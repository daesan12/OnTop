# 오목 브라우저 테스트

`backend/`에서 Java 21로 실행한다.

```powershell
.\gradlew.bat omokDemo
```

[흑 화면](http://127.0.0.1:18081/dev/omok)과 [백 화면](http://127.0.0.1:18081/dev/omok?role=white)을 각각 연다. 양쪽에서 **연결하기**를 누른 뒤 한쪽에서 **테스트 경기 생성**을 누른다. 자기 차례에 빈 교차점을 누르면 서버 판정 후 두 화면에 돌이 표시된다. [관전 화면](http://127.0.0.1:18081/dev/omok?role=viewer)도 별도 연결할 수 있다.

## 직접 확인할 흐름

- 흑과 백이 번갈아 착수한다. 잘못된 차례·이미 둔 칸·관전자 착수는 화면에서 차단한다. 서버도 기존 규칙을 다시 검사한다.
- **연결 끊기 → 다시 연결하기**: 같은 역할의 기존 판과 차례로 돌아온다. 턴 시간은 계속 흐르며 새로 30초를 주지 않는다. 살아 있는 같은 역할의 두 번째 연결은 거절된다.
- 한 수 30초를 실제로 기다리면 현재 차례가 시간패한다. 총시간 제한은 없다. 표시 시간은 서버 시각을 기준으로 계산하지만 승패는 서버 메시지로만 확정한다.
- 5개 이상 연결·시간패 등 종료 후 다시 **테스트 경기 생성**을 누른다. 진행 중에는 새 판 생성이 불가하다.
- **상태 재조회**로 현재 판을 다시 읽고, **최근 통신 기록**에서 보낸/받은 메시지 종류와 오류 코드를 확인한다. 재조회는 착수를 재전송하지 않는다.

## 테스트 도구의 범위

로그인 계정 매핑과 참가 확정·경기 생성만 테스트 대역이다. 실제 `OmokEngine`·기존 `/ws/tables`·복구/관전·30초 타이머를 사용한다. 대기 테이블 착석·준비·시작 차감·DB 정산을 이 화면에서 실행한 것으로 취급하지 않는다. 관전은 테스트 전용 채널과 테이블 중심 `(0,0)`에 위치 보고해 실제 20m 거리 검사를 통과한다. 실제 맵 좌표가 아니다.

브라우저의 **연결 끊기**는 정상 WebSocket 종료다. 브라우저가 자동 응답하는 Ping/Pong의 무응답 실험과는 다르며, 그 검증은 기존 `flowTest`가 담당한다.

`OmokDemoApplication`과 화면 리소스는 `src/test/`에만 있다. `omokDemo` 작업은 테스트 클래스패스로 별도 `127.0.0.1:18081` 서버를 실행하며 기존 8080 서버를 사용하지 않는다. 고정 테스트 역할은 흑101·백202·관전자505다. `demoRole`·`/dev/omok/games`는 이 테스트 실행에서만 사용하는 대역이며 정식 인증/API 명세나 Postman 일반 dev 연결에 추가할 값이 아니다. 운영 `bootJar`에는 이 클래스와 화면이 들어가지 않는다. 외부 공개·배포용으로 실행하지 않는다.

종료는 실행한 터미널에서 Ctrl+C다. 테스트 서버를 다시 실행하면 메모리 경기 이력은 초기화된다. 화면/스크립트 수정 시 `processTestResources`를 실행하고 브라우저를 새로고침한다. Java 수정은 테스트 서버를 재실행한다.

프론트 비동기 응답 회귀 검사는 `backend/`에서 `node --test src/test/js/omok.test.cjs`로 실행한다. 실제 화면 스크립트를 DOM/소켓 대역으로 실행해 관전자 복구 대기·새 판 전환 중 이전 응답·1008 종료 안내를 검사한다. 이 검사는 실제 브라우저 레이아웃/소켓 플레이를 대신하지 않는다.
