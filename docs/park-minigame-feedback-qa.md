# 공원·미니게임 피드백 통합 기록

작업 브랜치: `feat/park-minigame-feedback-20261031`. 시작 기준 `origin/dev@09880192`, 추가 효과음과 CI 수정까지 받은 통합 기준 `origin/dev@d8a571f0`. 최신 맵과 기존 미커밋 작업은 별도 작업 위치에서 보존했다.

게임 코드는 기존 `OMOK`, `ONE_CARD`, `DICE`, `DICE_LEDGER`, `LIAR_BRIDGE`를 유지한다. 새 인원 규칙·공통 통신 종류·DB CHECK는 없다. 오목만 서버가 한 번 추첨하며 흑돌이 선공이다. 공개 2.5초 동안 서버와 FE가 착수를 막고 첫 턴 30초는 공개 후 시작한다. 동일 경기 생성 재호출·재접속은 같은 결과를 사용한다.

공통 보상은 [미니게임 공통 일일 보상](minigame-shared-budget.md)을 따른다. 꼬치왕은 기존 10냥 이용료·보상 미지급을 유지한다. 신규 Flyway는 **없음**. 적용된 V131과 기존 다른 migration은 수정하지 않는다.

맵 `c05d8ada8b12d4e509f50c7e807949bd976811e1c69a628232520b88c15a0d07`, 18개 테이블·536개 이동 장애물·시설 좌표는 유지한다. VR 바닥 윗면을 포장면보다 높여 겹침을 없애고 기존 E 진입 위치에 시각 표시만 더했다. 점프맵 붕어빵은 착지면을 유지하며 몸체를 두껍게 했다. 승인된 점프맵 효과음 8개와 어댑터 해시는 최신 원격 값을 유지한다.

길 안내의 첫 워커·모듈 로딩과 경로 계산이 기존 5초 제한에 걸리는 회귀를 확인해 제한을 10초로 보완했다. 계산은 별도 워커에 유지하고 취소·오래된 응답·지도 버전 검증을 바꾸지 않는다.

## 독립 실행과 실제 서버 구분

frontend에서 다음 서버를 실행한다.

```text
node node_modules/vite/bin/vite.js --mode park-integration --host 127.0.0.1 --port 5283 --strictPort
```

- `/jumpmap-preview.html`: 실제 점프맵 HUD·결과·낙하 안내를 모의 이벤트로 독립 확인한다. 운영 지갑·랭킹에는 연결하지 않는다.
- 붕어빵: 기존 `dev:bungeoppang:v5` 모드는 지급 서비스를 모의 상태로 바꾸며 실제 엽전을 지급하지 않는다. 이번 진입 화면 검사는 `/park` contract fixture에서 실제 컴포넌트를 확인한다. 꼬치왕은 `/skewer.html`에서 공원을 거치지 않고 실행한다.
- `/park`: 최신 생성 맵에 통합된 진입·게임 선택·준비·진행·결과·공원 복귀·관전·채팅·입력 회귀를 브라우저 fixture로 확인한다. fixture를 실제 운영 HTTP/WS 연결 성공으로 보지 않는다.
- BE의 실제 규칙·시작 예약 계약·중복 actionId·expectedVersion·권한·기권·이탈·재접속·관전·정산은 Java 테스트로 확인한다. 지급 경쟁·원장·롤백·KST 자정·랭킹 SQL은 격리 MySQL 8.4에서 실제 서비스와 DB를 사용한다. 운영 DB와 배포 환경에는 접속하지 않았다. 진행 경기의 서버 재시작 복원은 추가 보장하지 않는다.

## 검증

- FE 전체 단위 검사: 1,704 통과, 기존 조건부 6건 제외. 길 안내 보완 후 관련 4건 재실행 통과.
- FE 소스·테스트 TypeScript 검사, 배포용 park 빌드, 맵·코스 생성물 일치 검사 통과.
- BE 전체 기본 검사: 2,599건 중 2,575건 실행, 환경 조건부 24건 제외. 하루 한도 API 설명의 기존 100냥 기대값 한 건을 500냥으로 수정한 후 해당 클래스 재실행 통과.
- 최신 실제 생성 맵을 입력한 6개 클래스 15건 모두 통과(제외 없음). 기본 검사에서 제외된 해당 15건을 별도로 실행했다.
- 격리 MySQL 8.4: 붕어빵 19건·점프맵 13건 모두 통과. 잔여 예산 2냥에서 실제 두 게임 정산을 동시에 실행하고 재시도해도 공통 500냥과 지갑 원장이 일치했다. 동점 1·1·3등과 먼저 도착한 순서, 이전 규칙·의심 기록 제외를 확인했다.
- 브라우저: 최신 맵, 1920×1080·1366×768·800×600·390×844에서 관련 화면을 확인했다. 신규 피드백 12개와 기존 공원·오목·잔해·점프맵 회귀를 합친 31개 시나리오를 확인했다. 첫 실행 제한에 걸린 길 안내는 10초 보완 후 2회 반복 통과했다. 붕어빵 에셋의 두께·착지면과 일곱 재질의 눌림·복원 실제 렌더도 확인했다. 캡처와 로컬 검사 결과는 저장소 밖 `output/feedback-v3/`에 보존한다.

공통 파일 변경과 게임 내부 변경은 위 표의 연결부를 기준으로 검토한다. 독립 UI 확인·fixture 통합·실제 BE/DB 검증은 완료했으며 운영 서버 배포 후 실제 사용자 동선 확인은 별도다.

## 병합 후 종료 수명 보완

MR !260 리뷰에서 추가된 동전 시각 맵의 보관 수명을 확인했다. 후속 `fix/omok-coin-toss-lifecycle-20261101`은 최신 dev `6c4d96d6`에서 시작하며, 기존 오목 collect 종료 연결점에서 해당 경기의 연출 시각만 제거한다. 정상 승리·턴 시간패·명시적 기권·재접속 유예 만료 모두 같은 종료 경로를 거친다. 종료 결과와 흑백 배정은 기존 경기 상태에서 복구한다. gameCode `OMOK`, 인원·FE 공개 필드의 선택성·공통 정산·Flyway는 바꾸지 않는다.

오목 엔진·라이프사이클·라우터·예약 시작 계약·시작 종료 처리의 5개 클래스 49건을 실행해 모두 통과했다(제외 없음). 네 종료 경로에서 연출 필드 제거와 종료 결과 복구, 종료 이벤트 한 번 발행을 확인했다.

성능 리뷰도 스키마로 확인했다. V131에는 `ix_jump_runs_reason_finish(end_reason, finish_ms)`, V4 원장에는 `ix_wallet_transactions_wallet_id(wallet_id, id)`가 있다. 규칙·코스·상태 복합 인덱스와 wallet_id·created_at 복합 인덱스는 현재 없다. 운영 데이터 규모와 EXPLAIN은 확인하지 않았으므로 고부하 조회 성능은 보장하지 않는다. 캐시나 추가 인덱스는 실제 실행 계획·부하 자료와 migration 번호 조율을 거친 별도 변경으로 다룬다.
