# AI·공지 Flyway 연결 기준

## 버전과 변경 범위

| 버전 | 용도 | 현재 기준 |
| --- | --- | --- |
| V166 | 두더지 랭킹 인덱스 | origin/dev 원문 유지 |
| V167 | 팀원 사용 | 사용자 확인, 실제 SQL 원문 dev 반영 대기 |
| V168 | 접속 안내 entry_news 테이블 | 기존 공지 로컬 커밋 원문 유지 |

최신 dev의 누락된 V157~V166 SQL은 원문 그대로 반영했다. 팀원 SQL과 기존 DB의 적용 이력은 바꾸지 않았다. 이번 예외 승인에 따라 우리 새 번호 파일을 구성했으며 과거 로컬 원문은 보존했다. V168·V169은 공지 브랜치와 같은 원문이며, AI 기능과 공지 기능의 실제 배포 여부는 SQL 존재만으로 판단하지 않는다.

## 기존 로컬 AI V166 보존

기존 db/migration/V166__create_joke_contest.sql은 backend/src/test/resources/db/ai-legacy/V166__create_joke_contest.sql로 원문 보존했다. 파일명·SQL 바이트·실제 DB의 Flyway 버전/체크섬은 변경하지 않는다. 새 V170는 새 SQL 버전이며 DDL 본문은 기존 원문과 같다. legacy 폴더는 공용/일반 테스트 Flyway 검색 위치에 포함하지 않는다.

JokeLocalDatabase는 마이그레이션 실행 전에 SELECT로 과거 AI V166 또는 이전 로컬 공지/AI V167~V169 이력(실패 포함)과 미완료 아재왕 테이블을 확인한다. 발견하면 연결을 닫고 새 로컬 DB 사용을 안내한다. 이전 V167~V169 원문은 db/ai-legacy/previous-v167-v169에 보존했다. 기존 DB를 repair하거나 outOfOrder로 우회하지 않으며, 기존 제출/참여권을 삭제하거나 새 DB로 자동 이관하지 않는다.

새 기본 미리보기 DB는 ontop_joke_local_preview_v170다. 기존 preview 이름을 명시해 열면 보존 차단 메시지가 나온다. 신규 DB에는 migration/minigame/shop 전체를 함께 적용해 낮은 버전 누락을 피한다. AI JSON 모드와 기존 JSON 자료는 이번 작업에서 변경하지 않는다.

## 팀 전달

> 기존 공통 V166은 두더지 랭킹으로 유지하고, 공지 V168·V169 다음 아재왕 테이블 신규 추가에 V170을 사용하려 합니다. 세 번호의 사용 가능 여부와 적용 순서 확인 부탁드립니다. 과거 로컬 AI V166 원문/DB는 보존했고 새 격리 DB에서만 검증합니다. 확인 전 푸시·병합·공용 DB 적용은 하지 않습니다.

공용 DB에 과거 AI V166이 적용됐다고 확인되면 이번 신규 적용 절차를 실행하지 말고 담당자와 별도 이관안을 결정한다. 이 문서는 공용 실행 승인이나 기존 이력 변경 절차가 아니다.

V167 팀원 SQL은 아직 origin/dev에 없다. 이번 격리 검사는 실제 존재하는 V166→V168→V169→V170의 계약만 확인하며 V167을 포함한 전체 통합 검증 완료로 보고하지 않는다. 팀원 원문을 임의로 만들지 않고 반영 뒤 새 DB에서 재검증한다. 사용자는 로컬 새 번호 구성·새 격리 DB 검증을 명시 승인했으며 기존 DB 이력 변경과 푸시는 승인 범위가 아니다.

## 2026-11-11 기능별 분리

사용자가 V168·V169·V170 팀 공유와 순서 확인 완료를 알렸고 네 기능별 Draft MR 생성을 승인했다. 이 아재왕 MR에는 V170과 과거 보존용 test resources만 포함한다. 현재 V168·V169 원문은 입장 공지 MR 소유로 두며 중복 복사하지 않는다. 독립 브랜치에서는 공지 부재를 허용하되 존재할 경우 기존 번호/역할 충돌 검사를 유지한다. 공용 DB 적용·repair·outOfOrder·기존 이력 수정은 수행하지 않는다.
