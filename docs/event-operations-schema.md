# 이벤트 운영 스키마 V163 (S15P31B105-379)

V163은 기존 V153~V162 결과를 유지하면서 후속 관리자 기능의 저장 구조만 만든다. 회차·응모권·당첨자를 생성하거나 확정하는 데이터 변경문은 없다.

## 테이블 계약

| 저장소 | 의미 | 중복 방지 |
| --- | --- | --- |
| `event_raffle_draws` | 응모권 추첨의 각 검토 시도, 실행자, 재추첨 사유와 후보 수 | 회차·시도 번호 유일; 회차별 현재 `REVIEW` 한 건과 `CONFIRMED` 한 건 이하 |
| `event_raffle_draw_picks` | 시도별 상품 슬롯·응모권·회원 후보 | 한 시도에서 슬롯·회원·응모권 중복 불가; 시도·슬롯의 회차와 응모권의 판매 회차·소유자 일치 |
| `event_minigame_configs` | 주차별 게임 회차에 사용할 표시명과 서버 랭킹 규칙 버전 | 회차당 한 건; `game_code`와 회차의 `event_type` 일치 |
| `event_prize_deliveries` | 경품을 전달한 관리자가 당첨 건별로 기록한 지급 완료 | 당첨 건당 한 건 |
| `personal_notifications.event_week_start_date` | 기존 개인 알림에 연결된 당첨 주차 | 회원·주차당 `EVENT_WINNER` 한 건 이하 |

`event_rounds`의 기존 `RAFFLE`, `BUNGEOPPANG`, `JUMPMAP`, `ASSET_VALUE` 코드는 유지한다. 새 미니게임 코드는 `MG_` 접두사를 붙인 최대 24자 ASCII 대문자 코드만 허용한다. 게임 설정 행만으로 게임을 활성화하지 않는다. 후속 API는 해당 코드에 맞는 **서버 검증 완료 기록과 랭킹 어댑터**가 등록됐는지 확인해야 한다. 회차 기간과 상품은 기존 `event_rounds`·`event_prize_slots`가 계속 소유한다. 이미 확정된 옛 게임 결과에는 설정 행을 자동 삽입하지 않는다.

## 후속 서비스가 지킬 규칙

추첨 서비스는 회차 행을 잠그고, 응모권 판매 마감·미확정 상태를 확인한 뒤 새 `REVIEW` 시도와 후보를 한 트랜잭션에 저장한다. GM도 정상 구매한 응모권으로 참여한다. 재추첨은 기존 시도를 `SUPERSEDED`로 바꾸고 사유가 있는 다음 시도를 만든다. 최종 확정 요청은 관리자가 검토한 시도 ID를 받아 현재 유효한 시도인지 확인한 뒤 `event_winners`에 기록한다. 확정된 회차와 과거 시도는 변경하지 않는다. DB의 복합 외래 키는 응모권의 소유·판매 회차와 상품 회차 일치를, 유일 제약은 동시 시도의 중복을 방어한다. 판매 마감·후보 수 일치 등은 서비스가 검증한다.

지급 완료는 경품을 실제 전달한 뒤 권한 있는 관리자가 `event_prize_deliveries`에 당첨 건별로 삽입한다. 전체 지급 여부는 같은 회원·주차의 당첨 건과 지급 행을 비교해 계산한다. 연락처 암호문, 제출·파기 기한은 기존 테이블과 서비스가 계속 관리한다.

당첨 알림은 발표된 회원·주차에 한 건 생성한다. 기존 소리함 답변·보상 알림은 주차 컬럼이 `NULL`이다. 읽음이나 팝업 닫기는 연락처 입력 가능 상태를 바꾸지 않는다. 모든 당첨 건이 지급 완료되면 후속 API가 새 입력·알림 동작을 중단한다.

## 배포 게이트

**운영 2026-11-02 회차는 아직 미확정이다.** V163 적용만으로 추첨하지 않는다. 응모권 자동 확정 스케줄러는 후속 API 작업에서 제거하고, DEV·PROD의 `RAFFLE_DRAW_ENABLED` 기본값도 `false`로 둔다. 이전 버전 앱이 배포돼 있는 동안에도 자동 확정되지 않도록 실제 운영 env의 값을 `false`로 고정해야 한다. 관리자 화면이 새 두 단계 API를 연결하고 DEV 종단 테스트가 끝나기 전에는 운영 추첨을 실행하지 않는다. 배포 전 백업, 회차 상태, 후보·GM 제외, 관리자 권한을 확인한 뒤 운영 담당자가 수동 추첨 → 결과 검토 → 최종 확정한다. 이미 확정된 DEV 2026-11-02 결과는 보존한다.

`EventOperationsMigrationMySqlTests`는 빈 MySQL 8.4 격리 DB에 V162까지 적용하고 기존 미확정 회차·게임 당첨·보상 알림을 만든 뒤 V163을 적용해 데이터 보존, 검토 시도 유일성, 재추첨 사유, 게임 코드 일치, 지급 중복, 주차별 당첨 알림 중복을 검증한다.
