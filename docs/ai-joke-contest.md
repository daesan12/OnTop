# 탑골 아재왕 — 로컬 검수

기획서 v1.0과 2026-11-09 사용자 결정(공개 검수 Jev, OPENAI_API_KEY가 있으면 성립 판단·채점 LLM, 정상 작품 리액션도 같은 LLM 호출에서 생성, 거절/미성립도 1회 차감)을 반영한 개인 로컬 구현이다. JSON과 V170 후보 MySQL 저장소를 지원한다. 공용 DB·기존 경기/엽전/제품 랭킹은 변경하지 않는다. 실제 배포용 API 활성화와 공용 DB 적용은 별도 작업이다.

## 실행과 화면

기존 `scripts/start-ai-park.cmd` 실행 후 `http://127.0.0.1:5211/ai-park.html`을 연다. 랭킹판 옆 **김부장**에게 2.5m 이내로 접근하면 기존 E 상호작용 선택에 `김부장과 대화`가 나온다. 현재 심사위원은 남색 재킷·노란 넥타이·안경의 기본 도형 임시 모델로 구분하며 팀원의 최종 모델로 교체할 예정이다. P1의 Utility AI 배회/초대 연출은 포함하지 않는다. 새 물리·충돌·서버 위치 스트림은 없다.

로컬 검수의 `심사위원 앞으로` 버튼으로 이동할 수도 있다. 이동 후 공원 캔버스를 누르고 E를 누른다. 문제 2~100자·정답 1~60자를 별도 입력하고 공개 안내에 동의한 후 제출한다. 닫기/Escape로 닫아도 접수한 심사는 계속되며 다시 열면 내 기록에서 확인한다. 랭킹 메뉴는 별도 조회 가능하다. 요청은 기존 인증된 서버 좌표를 검사하므로 멀리서 제출하면 거절한다.

최신 첨부 참고 이미지에 맞춰 화면 아래 짙은 갈색/금색 대화틀, 테두리 매듭·모서리 장식과 이름표, 왼쪽에 틀 위로 올라오는 캐릭터 상반신을 표시한다. 기존 `judge-portrait-v1.png`와 공원 명조 글꼴·실제 3D 배경을 유지한다. **별도 도전 입력창은 없다.** 인사→문제를 들려달라는 대사→같은 대화창 입력줄에서 문제 말하기→정답을 묻는 대사→같은 입력줄에서 정답 말하기→문제/정답 복기와 공개·차감 안내→명시적 동의 선택→심사·결과 대사로 이어진다.

말하기는 Enter/말하기 버튼, 줄바꿈은 Shift+Enter다. 한국어 IME 조합 중 Enter/229는 전송하지 않는다. 문제/정답 단계는 로컬 상태만 바꾸며 마지막 `공개에 동의하고 심사받기 · 1회` 버튼을 선택할 때만 제출 API를 호출한다. 확인 단계에서 Enter만 누르면 자동 제출하지 않는다. `문제 고치기`/`아니, 고칠게`는 입력을 보존하고 문제 단계로 돌아간다. 다시 도전은 새 문답을 시작하고 기회0이면 랭킹을 연다. 랭킹/내 기록은 대화창을 가리는 큰 중앙 두루마리 팝업에서 조회한다. 한지 바탕과 단청 녹색·목봉·장원 도장으로 꾸미고, 0.72초 동안 위아래 목봉과 종이가 함께 펼쳐진다. 모션 줄이기 설정에서는 연출을 생략한다. 오늘 순위/역대 아재왕/내 오늘 기록을 선택해 조회하며, 순위·닉네임/개그·점수를 고정 열로 정렬한다. 어제 우승자와 내 남은 기회/최고 점수는 별도 안내 영역에 표시한다(작은 폭에서는 하단에 남은 기회 유지). 목록만 내부 스크롤하며, 상단 닫기/ESC로 닫고 하단에서 도전으로 전환한다. 남은 횟수를 표시하고 0회면 도전 버튼을 비활성화한다(진행 중 심사는 확인 가능). 오늘 상위 5명만 정답 보기/접기를 제공하며 정답만 보여주고 심사 리액션은 반복 표시하지 않는다. 응답 캐시와 펼침 상태를 분리하고 항목별 진행 중 요청을 재사용해, 늦은 응답이 접은 답을 다시 펼치거나 오래된 실패가 새 요청을 덮지 않게 한다. 판정·참여권·DB 정책과 공개 범위는 바꾸지 않는다.

닫기/ESC는 화면만 닫고 접수한 심사는 취소하지 않는다. 최종 동의 전 닫기/수정은 도전 횟수를 사용하지 않는다. 심사 중 랭킹으로 재진입한 뒤 도전하기를 누르면 심사 대사로 돌아간다. Tab/Shift+Tab은 보이는 조작 요소 사이에서 순환하고 닫으면 이전 포커스로 돌아간다. 작은 화면에서 긴 대사·문답 복기·랭킹은 내부 스크롤로 확인할 수 있다. 초상화 출처와 프롬프트는 `frontend/public/art/ai-joke/SOURCE.md`에 보존한다.

Jev·MM 키가 있는 **같은 PowerShell**에서 LLM 키를 추가한다. 키 자체는 파일이나 채팅에 넣지 않는다.

```powershell
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'LLM API 키' -AsSecureString)).Password
$env:AI_LAB_LLM_MODEL = 'gpt-4.1-mini'
.\scripts\start-ai-park.cmd -Restart -LiveJev -LiveMattermost -NoBuild
```

LLM 모드의 채점·해석·리액션은 하나의 Chat Completions 구조화 출력 호출로 처리한다. 주민 대화/해설의 SpringAiText UTC100회 한도와 별개이며 기본 정책의 참여권 하루3회(ai-park JSON 연습 제외)/worker2개/대기16개와 요청10초·최대500출력토큰으로 제한한다. 기존 Jev 채점 모드로 복귀할 때만 별도 SpringAiText 리액션 호출과 해당 한도를 사용한다. 재시작 시 이 메모리 한도는 초기화되며 결제 금액 상한이 아니다. 키가 없거나 실패하면 안전한 고정 리액션을 사용한다. 외부 API를 끄려면 `-Offline`으로 실행한다. 대역 채점은 화면에 명시하며 실제 Jev 정확도나 실제 LLM 리액션으로 소개하지 않는다. 대역에서는 `검수거절`/`검수보류`/`심사장애`를 문제에, `모르겠`을 정답에 넣어 해당 흐름을 재현한다. 다른 대역 정상 작품은 시연용 82.3점이다.

## 판정과 참여권

- **ai-park 기본 JSON 로컬 테스트는 횟수 제한 없음**이다. 기존 제출 기록을 보존하며 세 번 사용한 계정도 계속 도전할 수 있다. me는 unlimitedAttempts=true/remaining=-1을 반환하고 화면은 제한 없음으로 표시한다. 같은 작품도 새 요청 키로 재제출 가능하며, 멱등키·2초 간격 제한은 유지한다. MySQL DB 검증 모드와 기본 저장소 생성자는 하루3회를 유지하며 V170 후보 스키마는 변경하지 않는다.
- 횟수 제한 모드에서는 Asia/Seoul 하루 최대3회. 접수 시 PENDING도 기회를 예약한다. JSON은 한 파일 작성자, MySQL은 사용자 행 락과 참여권 트랜잭션으로 동시 요청을 검사한다. 외부 API 호출은 DB 트랜잭션 밖의2개 worker에서 처리한다.
- `SCORED`, `REJECTED`, `INVALID_JOKE`, `REVIEW`는 각1회 소모한다. `FAILED`는 반환하며 랭킹에 나오지 않는다. JSON은 재시작 시 PENDING을 즉시 반환한다. **MySQL은 다른 인스턴스의 진행 중 심사를 보호하므로 재시작만으로 일괄 실패시키지 않고 60초 만료 후 조회/예약/완료 경로에서 반환**한다. 만료된 대기는 외부 호출을 시작하지 않고, 늦게 온 결과로 다시 확정하지 않는다.
- 같은 idempotencyKey와 같은 원문은 같은 제출을 반환한다. 같은 키의 다른 작품은 오류다. 확정 FAILED 뒤 명시 재도전은 새 키를 사용한다. JSON 모드에서는 같은 사용자도 새 요청 키로 동일 작품을 다시 제출할 수 있다. 기존 당일 상위10개·과거 날짜별1위와 겹치면 기존 독창성 감점으로 처리한다. JDBC 모드는 V170의 고유 제약 때문에 동일 작품 차단을 유지하며, 해당 DB 정책 변경은 별도 마이그레이션이 필요하다. 시도 간2초 제한도 있다.
- LLM 채점 모드에서 Jev `Noul` 3개는 공격/개인정보/공개 부적합만 검사한다. 위험 최댓값0.8 이상은 거절,0.35 이상은 공개 보류다. Jev의 개그 성립 여부/재미 점수는 호출하지 않는다. LLM이 한국어 발음·중의어·단어 분리의 연결을 먼저 해석하고 성립 여부와 점수를 판단한다. 썰렁함/익숙함만으로 미성립 처리하지 않도록 명시하고 특정 문제·정답의 정답표는 넣지 않는다.
- `LlmJokeJudge`는 strict JSON Schema로 SCORED/INVALID_JOKE, wordplayX10/witX10/originalityX10, 짧은 해석과 reaction을 한 번에 받는다. 정책은 joke-llm-v5-dialogue이며 채점 필드 다음에 그 해석에 근거한 반응을 작성하도록 지시한다. 항목별 x10 정수400/400/200 상한을 재검사하고 서버가 합산한다. 미성립이면 점수 모두0이어야 한다. 숫자 문자열/소수/범위 초과/출력 잘림/모델 거절/HTTP실패는 FAILED로 환불하고 Jev 점수로 조용히 대체하지 않는다. `judgeVersion`은 LLM 모델·정책·검수 공급자를 구분하며 기존 기록을 재채점하지 않는다.
- LLM 심사 시작 시 제출 날짜의 사용자별 최고 상위10개와 그보다 과거 날짜의 확정 우승작만 비교 자료로 읽는다. 과거 우승은 기존 다음 날00:05 이후 지연 확정 정책을 따르며, 실패/비공개/진행 중/과거2위 이하/당일11위 이하 작품은 포함하지 않는다. ID·문제·정답만 서버 내부에서 LLM에 보내고 닉네임·사용자ID는 보내지 않는다. 새 호출을 추가하지 않고 통합 응답에서 `similarity=NONE/SIMILAR`, `matchedId`를 받는다. 핵심 말장난·반전이 같은 표현 변형이면 SIMILAR, 주제나 답 단어만 같고 원리가 다르면 NONE이다. SIMILAR의 ID는 전달한 목록 안에 있어야 하며 모순·누락은 FAILED로 환불한다. 정규화된 문제·정답이 모두 같으면 LLM 판정과 관계없이 유사로 처리한다.
- 유사 작품은 말장난40점·재미40점을 유지하고 독창성20점만 **최대2점**으로 제한한다(원래2점 미만이면 올리지 않음). 감점 이유는 기존 `reason`, 조정된 독창성과 합계는 기존 점수 필드에 저장하므로 새 DB 마이그레이션은 없다. 기존 작품을 사후 재채점하지 않으며 동시에 진행 중인 제출끼리는 비교하지 않는다. 비교 범위 밖 작품이나 인터넷 전체 표절 검사가 아니고 LLM 유사 판정 정확도는 보장하지 않는다. Jev 채점/오프라인 대역 모드에서는 의미 유사 감점을 하지 않는다.
- 심사 대사는 공원의 나이 지긋한 김부장 페르소나를 공유한다. 호칭은 자네, 어미는 하게체(~했네/구먼/일세/보게)이며 상담원 존댓말·평가 보고서 말투를 피한다. 사용자에게 보이는 reaction은 구체적인 말장난 연결과 잘된 점 또는 아쉬운 점을 두세 문장·120자 이내로 설명하도록 요청한다. explanation도 같은 말투를 요청한다. 유사 감점은 서버가 “앞선 작품과 말장난이 닮았구먼. 새로움은 조금만 쳐주겠네.”를 안전한 고정 문구로 붙이고 마지막 점수는 서버 합계다. LLM 지시의 문체·품질을 문법 검사로 보장하는 것은 아니며, 기존 생성 실패 대체 정책을 유지한다. Jev 채점 모드의 별도 생성에도 같은 페르소나와 평가 근거를 전달한다.
- 통합 응답의 채점과 리액션은 실패를 분리한다. 전체 JSON 파싱 실패/채점 필드 오류/출력 잘림은 FAILED지만, 정상 채점에서 reaction 누락·null·비문자열·빈문장·길이 초과·숫자/점수 언급은 점수를 유지하고 고정 리액션으로 대체한다. 복구용 두 번째 LLM 호출은 하지 않는다. 정상 후보 반응만 Jev로 검사하며 검수 거절·예외도 고정 대사로 대체한다. 검증된 고정 대사는 다시 Jev에 보내지 않는다. 최종 `이번 개그는 82.3점일세!` 문장은 서버가 붙인다. 리액션만 실패해도 채점 성공과1회 소모는 유지한다.
- LLM 모드는 안전 Jev1요청(3질문)→LLM통합채점·리액션1요청→정상생성반응만 Jev안전1요청이다. 키가 없거나 `AI_LAB_JOKE_JUDGE=jev`면 기존 Jev7질문(개그성립0.65/Score0~4환산)으로 복귀한다. `-Offline`과 기본 benchmark에서는 키가 있어도 외부LLM이 켜지지 않으며 benchmark의 명시적LIVE_LLM opt-in만 허용한다. 실제 호출 비용/한국어 유머 정확도/점수 반복 안정성은 별도 실검수 결과만 근거로 한다.

최종 점수에 따라 대사 앞에 웃음 텍스트를 붙인다. 80점 이상 푸하하핫!!, 60~79.9점 허허허!, 40~59.9점 허허., 40점 미만 허허…이며 실제 사운드는 재생하지 않는다. 모델에게 웃음을 쓰지 않도록 요청하고 기존 생성 대사의 앞 웃음은 정리한다. 유사 감점 이후 합계를 기준으로 하며 비공개·미성립·실패에는 점수별 웃음을 붙이지 않는다. 제출 오류는 입력/2초 간격/거리 등 서버의 구체적인 안내를 표시한다. 아재왕 거리 거절(JOKE_OUT_OF_RANGE)은 로그인 종료로 처리하지 않는다.

## 랭킹과 공개

사용자별 당일 최고1건, 점수 내림차순·그 점수 작품의 심사 완료(확정) 시각 오름차순이다. 최종 동률은 생성 시각/ID로 안정 정렬한다. 목록 상위10명 중1~5위만 문제를 보내고, **모든 순위의 정답·리액션은 목록 응답에서 제외**한다. 정답 클릭 시 별도 reveal 경로가 당시 해당 일자 상위5위 여부를 다시 검사한다. 6~10위 작품/비공개 상태/다른 사람의 개인 제출 조회는 허용하지 않는다. 본인만 오늘 제출의 원문·실패/거절 결과를 본다.

지난 날짜는 다음 날00:05 이후 조회 시 우승작 스냅샷을 확정한다. 별도 스케줄러 없이 로컬 조회로 지연 확정한다. `어제의 아재왕`은 서울 날짜가 바뀌면 다음 날짜로 전환하고 우승 이력은 별도로 보존한다. 정답은 역대 우승작도 reveal 경로로 가져온다. 로컬 파일은 최대5000제출/16MiB 제한이며 운영 장기 보관용 저장소가 아니다.

## 저장 구조와 DB 반영 경계

기본 JSON 모드는 `backend/.gradle/ai-park/joke-contest/contest.json`을 원자 교체하고 `contest.lock`으로 중복 작성자를 막는다. MySQL 모드를 켜도 기존 JSON은 자동 이관/삭제하지 않는다. 두 저장소의 기록은 별개다. `me.storage`로 `JSON`/`MYSQL`을 확인할 수 있다.

`V170__create_joke_contest.sql` 후보는 제출·일일 참여권·일별 우승 스냅샷 테이블을 추가한다. 사용자/요청 키와 사용자/유효 작품 해시의 유일성, 점수·완료 상태·참여권 범위를 DB 제약으로 검사한다. 예약/환불은 `users` 행 → 참여권 순서로 잠그며, 중복 환불과 만료 후 성공 덮어쓰기를 막는다. 랭킹은 MySQL ROW_NUMBER로 사용자별 최고1건을 고른 뒤 상위10건을 조회한다. SQL에 기존 데이터 UPDATE/DELETE는 없다. 2026-11-11 사용자에게 V168·V169·V170의 팀 공유·적용 순서 확인 완료와 기능별 Draft MR 생성을 승인받았다. 공용 DB 적용·배포·병합은 수행하지 않는다.

### 로컬 MySQL 실행

MySQL 8.4.13 공식 Windows ZIP(`https://dev.mysql.com/downloads/mysql/8.4.html?os=3`)을 작업공간 `local-tools/joke-mysql/mysql-8.4.13-winx64`에 해제한 뒤 저장소 루트의 PowerShell에서 실행한다. 개발 PC에는 검증용 도구가 준비되어 있다.

```powershell
.\scripts\start-ai-park.cmd -Restart -JokeDb -Offline -NoBuild
```

`-JokeDb`가 같은 프로세스에서 DB 준비 스크립트를 호출하고 전용 `AI_LAB_JOKE_DB_*` 변수를 서버에 상속한다. 기존 cmd 진입점이 실행 정책 우회와 PowerShell 경로 선택을 처리하므로 사용자가 ps1을 따로 실행할 필요가 없다. 실제 Jev/MM은 `-Offline` 대신 기존 `-LiveJev -LiveMattermost`로 실행한다. 첫 빌드 전이거나 코드를 바꾼 뒤라면 `-NoBuild`를 뺀다. DB URL은 **127.0.0.1:19306/ontop_joke_local_*만** 허용하고 기존 DB_URL/DB_USERNAME/DB_PASSWORD는 읽지 않는다. 전체 로컬 선행 마이그레이션과 V170 후보를 새 전용 DB에 적용하고 로컬 fixture 회원3명만 준비한다. 이 어댑터의 자동 활성화는 테스트 클래스패스에만 있으며 제품 Spring DB 빈을 변경하지 않는다.

MySQL Windows 실행기의 한글 경로 재실행 문제 때문에 공식 바이너리를 `%TEMP%/ontop-joke-mysql-8.4.13`에 캐시하고 데이터는 `%TEMP%/ontop-joke-local-mysql-data-v1`에 보관한다. **임시 폴더가 지워지면 로컬 DB도 사라지므로 운영/장기 보관용이 아니다.** 전용 무작위 계정 정보는 Git에서 제외된 `backend/.gradle/ai-joke-db/credentials.json`에 보존하며 공유하지 않는다. MySQL은 Windows 서비스로 등록하지 않고 loopback에만 연다. 정상 종료는 `scripts/start-ai-joke-db.ps1 -Stop`이며 데이터는 삭제하지 않는다.

실제 DB 검사는 미리보기와 다른 전용 DB에서만 실행한다. 기존 테스트 DB의 아재왕 테이블3개만 비우므로 미리보기/공용 데이터에는 사용하지 않는다.

```powershell
.\scripts\start-ai-joke-db.ps1 -DatabaseName ontop_joke_local_test_20261109
cd backend
.\gradlew.bat mysqlTest --tests com.ssafy.ontop.ai.JokeContestMySqlTests --console=plain
```

## 검증

`LocalJokeContestTests`는 참여권/동시 예약/정규화/멱등/늦은 결과/환불/생성 실패/랭킹 개인정보/서울 날짜·재시작을 검사한다. `JevJokeJudgeTests`는 loopback API 대역으로7질문과 Score 환산/잘못된 응답을 검사한다. 실제 Jev 유머 판단의 정확도는 이 테스트로 증명하지 않는다.

```powershell
cd backend
.\gradlew.bat test --tests com.ssafy.ontop.ai.LocalJokeContestTests --tests com.ssafy.ontop.ai.JevJokeJudgeTests --console=plain
```

한국어 품질용30개 샘플은 `backend/src/test/resources/ai/joke-quality-cases.json`이다. 정상 농담·무관 대답·우회 욕설·합성 개인정보·명령 삽입·정상 유사어를 포함한다. 실제 호출은 기본으로 실행하지 않는다. 키가 있는 터미널에서 명시적으로 켜면 Jev만30회 호출하고 결과/지연을 `backend/build/joke-quality/`에 남긴다. 반복 비교는 `AI_JOKE_QUALITY_REPEAT=3`일 때90회다. 품질 관찰 완료가 각 표본 판정의 정답 일치나 전체 한국어 정확도 보장은 아니다.

## 호출 계측 (프로세스 메모리, 원문 없음)

`GET /local/ai/joke-contest/me`의 `metrics`는 전체 프로세스 누적 관측값이다. 본인의 제출 횟수와는 다르며 재시작하면 초기화된다.

- `provider.llm.calls`, `provider.llm.input_tokens/output_tokens`: 실제 HTTP 시도와 응답 usage. 토큰 없는 응답은 `usage_missing`에 기록한다. 실패·연결 중단으로 응답을 못 받은 호출의 실제 청구 토큰은 알 수 없다.
- `provider.original_guard`, `provider.llm.combined`, `provider.reaction_guard`: `.samples / .total_us / .max_us`. 요청 단계 경과시간이며 호출 완료 품질·정확도를 뜻하지 않는다.
- `provider.guard.jev.calls`: 실제 Jev HTTP 시도 수. 고정 대사를 쓰거나 원문에서 중단되면 정상 흐름의 2회보다 적다.
- `queue_wait / processing / end_to_end`: 작업 대기·작업자 처리·접수부터 완료까지의 관측 시간. `.total_us / .samples`로 관측 평균을 계산할 수 있으며 p95를 추정하지 않는다.
- `worker.result.*`, `reaction.fallbacks`: 작업자가 생성한 완료 결과의 상태별 기록과 채점 성공 후 대사 대체. 늦은 결과가 저장소에서 무시될 수 있으므로 확정 저장 상태의 통계와 구분한다. 재시작 전 이력과 저장소의 별도 만료 처리까지 재구성하는 영구 집계는 아니다.

정상 통합 심사는 LLM 1회 + Jev 2회, 로컬 검증에서 반응을 배제하면 LLM 1회 + Jev 1회다. 별도 대규모 계측 인프라와 새 DB 스키마는 추가하지 않는다.

역대 아재왕의 정답 보기 역시 오늘 상위 작품과 같은 reveal API를 호출하고, 목록 응답에는 정답을 추가하지 않는다. 버튼은 진녹색·금색 테두리·책/접힘 아이콘으로 표시하며 펼치면 한지 영역에 정답만 보여준다. 항목별 오류와 다시 불러오기, aria-expanded/aria-controls/hidden 영역을 제공하고, 이미 불러온 답은 캐시해 접었다 펼쳐도 다시 요청하지 않는다. 과거 요청의 늦은 응답은 현재 펼침 상태를 바꾸지 않으며 실패도 다른 항목에 전파하지 않는다. 날짜/닉네임/문제/점수의 시각 계층과 역대 장원 도장을 구분하고 내 기록의 심사 결과 버튼도 같은 색상으로 맞춘다.

## 2026-11-10 마이그레이션 번호 정리
공통 V166은 최신 dev의 두더지 랭킹 인덱스다. 아재왕 신규 SQL 후보는 V170이며, 공지 V168·V169 다음에 새 격리 DB에서 검증한다. 적용된 과거 AI V166 SQL은 test resources의 db/ai-legacy에 바이트 변경 없이 보존하고 공용 Flyway 검색에서 제외했다. 기존 AI V166/부분 적용 DB는 자동 갱신하지 않고 사전 차단한다. 기존 자료는 보존하며 repair/outOfOrder/이력 변경/자동 이관을 하지 않는다. 새 로컬 미리보기 기본 DB는 ontop_joke_local_preview_v170, 저장소 표시는 MYSQL로 버전과 분리했다. 팀 번호·적용 순서는 2026-11-11 사용자 확인 완료이며, 공용 DB 적용은 별도 작업으로 남긴다. 상세: [AI·공지 Flyway 연결 기준](ai-migration-compatibility.md).

2026-11-10 사용자 팀 확인·로컬 예외 승인: V167은 팀원 사용, 우리 공지 V168·V169 및 아재왕 V170으로 확정했다. 이전 로컬 V167~V169 원문은 test resources에 보존하고 기존 DB·Flyway 이력은 변경하지 않는다. 새 격리 DB에서만 검증하며 팀 V167 원문이 반영되면 전체 조합을 재검증한다. 당시 공용 DB에는 적용하지 않았고, 이후 2026-11-11 기능별 Draft MR 생성 승인을 받았다.

## 기능별 Draft MR 경계

이 MR은 선행 AI 공통 기반/주민 오목 위에 아재왕 부분만 추가한다. V168·V169 공지 SQL은 별도 공지 MR 소유이며 복사하지 않는다. 공지 SQL이 아직 없는 독립 브랜치에서는 V166/V170의 충돌·역할을 검사하고 공지 SQL이 합쳐진 뒤에는 V168/V169 역할도 검사한다. 공용 적용은 공지 MR과 팀 선행 버전을 먼저 확인한 뒤 V170 순서로 진행해야 한다. SQL 원문과 기존 DB 이력은 변경하지 않는다.

현재 대회 HTTP API와 NPC 상호작용 노출은 local/ai-park 검수 전용이다. 실제 서비스 API·운영 DataSource/회원 수명·프론트 기능 활성화와 실제 키/운영 DB 재검증 전에는 이 Draft를 병합/배포하지 않는다. 로컬 제어 API나 테스트 계정을 운영에 노출하는 방식으로 활성화하지 않는다.

LLM 설명은 기존 응답 길이를 검증한 뒤 저장용 reason을 유니코드 문자 100개 이내로 정규화한다. V170 VARCHAR(100)를 넘는 설명 때문에 JDBC 최종 저장이 실패하는 일을 방지하며 SQL은 수정하지 않는다.
