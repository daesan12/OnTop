## 공원 배경과 외형

- 소프트웨어 GPU에서 공원을 생략하던 분기와 450ms 캡처 포기 조건을 제거했다.
  현재 공원을 512px 큐브맵 6면으로 준비한 뒤 경기 화면을 공개한다. 한 면씩 GPU 완료를 확인한다.
  실패/시간 초과 시 오류를 표시하며 하늘만 있는 상태를 준비 완료로 보고하지 않는다.
- 경기 중에는 공원을 매 프레임 다시 렌더링하지 않는다. 큐브맵은 경기 진입 시의 정적인 배경이며
  공원의 다른 이용자 이동이나 경기 도중의 시간대 변화를 실시간으로 반영하는 용도는 아니다.
- 캐릭터 외형을 입장 시 `useState`로 고정하던 코드를 없앴다. 공원과 같은 공개 프로필·착용 정보·스킨 목록을 구독한다.
  아직 로드되지 않은 현재 의상도 공용 파일 캐시로 요청하며 전체 스킨과 부위별 의상을 지원한다.
  참가자의 실제 리그/경기용 재질이 준비된 후 GPU 준비를 시작한다. 공용 원본 리그/재질은 변경하지 않는다.
- 공원의 기존 의상 표시 정책을 따른다. 공개 착용 정보가 없는 경우에는 공원과 같이 제한 시간 후 기본 외형을 사용하며,
  늦게 도착한 정보는 이후에도 반영한다. 실패한 의상 파일을 정상 로드된 기본복으로 확정하지 않는다.

## 통신 최적화와 공통 연결부

- `HEX_AXIAL_V3`와 `arenaSize: 2 | 4 | 8` 계약에서 크기별 고정 좌표를 공유하고
  `tileMarks: [[id, breakAt, stepped(0|1)], ...]`만 보낸다. 같은 번호라도 경기장 크기에 따라 좌표가 다르므로
  시작 인원과 크기가 맞지 않거나 이전 버전인 응답은 거절한다. FE/BE는 함께 반영해야 한다.
  `slideX/Z`는 다이빙 시작 속도 벡터이며 FE는 방향 표시로 사용한다. 이동 거리로 해석하지 않는다.
  이미 사라진 발판도 포함한 현재까지의 전체 변경 목록이므로 이전 패킷 없이 재접속/늦은 관전을 복원한다.
  FE는 고정 보드와 표시 목록을 합쳐 기존 내부 `StoneState.tiles`를 만든다.
- 중복/범위 밖 id, 잘린 표시, 잘못된 타입·시각·버전은 거절한다. FE/BE는 함께 반영해야 하며 구버전 응답을 섞지 않는다.
- 8인 초기 공개 상태 2,559 bytes. 모든 발판이 변경된 epoch 시각 조건에서
  전체 좌표 방식 103,294 bytes → 표시 목록 방식 33,142 bytes, 약 67.9% 감소했다.
  최악 조건도 기존 64KiB 검증 한도 아래다. 수신자 간 상태 복사 보호는 유지한다.
- 게임 밖 공통 변경은 `VerifiedGameFinish`의 돌탑 `MATCH_TIME_LIMIT` 허용과
  `TabletLobby`의 돌탑 소개 문구 수정이다. 예약·지갑·정산 경로는 복제하지 않았다.

## 원격 반영 경계

기능 커밋과 이 기록을 작업 브랜치로 푸시한다. 공통 브랜치에 직접 푸시하지 않는다.
MR 생성·머지 요청은 없으므로 수행하지 않고 브랜치를 보존한다.
Jenkins 파이프라인은 기존 dev 기준이다. 관리 API 외부 조회가 막혀 있어 빌드 실행/성공은 확인하지 못했으며
로컬 빌드 성공을 Jenkins 성공으로 표시하지 않는다. 최종 푸시와 커밋 결과는 채팅 완료 보고에 남긴다.
