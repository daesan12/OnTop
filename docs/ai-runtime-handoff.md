# AI 운영 연결 인계

`AI_ENABLED`로 DEV와 운영의 AI 전체 활성화를 동일하게 관리한다. 기본값은 `false`이며 `dev,db`·`prod,db`·`production,db`에서 `true`를 설정하면 실제 TableHub 채팅과 커밋된 소리함 제보가 비동기 작업자로 전달된다. `AI_JEV_ENABLED`·`AI_MM_ENABLED`·`AI_POLICE_ENABLED`로 각 연결을 선택한다. 기존 소리함·관리자·DB 설정을 유지한다. `local,ai-park` 테스트 프로필이나 `/local/ai` 검수 API는 정식 서비스에 노출하지 않는다. 경찰은 서버가 선택한 공원 충돌 맵을 사용한다. 채팅은 기존 별표 필터만 적용하고 AI 판정으로 자동 가리지 않는다.

- `infra/app/ai.app.env.example`의 값을 기존 서버 app env에 추가한다. Jev/MM 활성화 전에 실제 키·전체 웹훅 URL을 비밀값으로 주입한다. OpenAI 키가 없으면 대사·요약은 고정 문구를 사용한다. 모델은 `AI_LLM_MODEL`, Jev는 `JEV_MODEL`로 선택한다. 기존 `AI_LAB_LLM_MODEL`·`AI_LAB_MM_WEBHOOK`은 호환용 대체 값이다.
- 정식 서비스는 기존 `DB_URL`·`DB_USERNAME`·`DB_PASSWORD`의 DataSource를 그대로 사용한다. 별도 AI DB 비밀번호·파일 디렉터리·쓰기 볼륨·`compose.ai.yaml`은 필요 없다. 기존 DB·인증·소리함 env와 Flyway 검색 경로는 유지한다.
- `AI_LLM_DAILY_CALLS`는 NPC/요약 공급자의 프로세스별 UTC 일일 호출 제한이다. 재시작으로 초기화되며 전체 조직 비용 상한이 아니다. Jev/MM 알림·아재왕 채점까지 제한한다고 해석하지 않는다.
- 새 env를 적용할 때 백엔드 컨테이너를 재생성한다. 이 MR 자체는 실제 서버 env 수정·공용 DB 적용·배포를 수행하지 않는다. 실제 키/운영 MM 전송은 단위 테스트 대역과 별도로 확인한다.

주민 대결·아재왕은 후속 기능 MR에서 별도 설정과 API를 연결한다. 현재 MR의 AI 공통 경계에는 로컬 검수용 범용 페르소나·오목 분석 인터페이스가 함께 포함되지만 주민 대결/아재왕을 자동으로 활성화하지 않는다.

## 채팅 위치 누락과 경찰 출동

전송된 채팅의 위치를 AI 전달 시점에 읽지 못해도 검수·개인 안내·MM 알림은 진행한다. 저장 메시지의 `positionMissing=true`는 좌표 미확인을 뜻하며 좌표 필드의 0을 실제 위치로 사용하지 않는다. 대화 묶음은 원래 채팅 수신자 정보를 우선 사용하고, 수신자 정보와 위치가 모두 없는 서로 다른 발화를 임의로 같은 장소로 묶지 않는다. 기존 저장 메시지에서 이 필드가 없으면 종전의 좌표 있는 입력으로 읽는다.

경찰 이동은 저장된 채팅 좌표 대신 매 tick의 같은 채널 최신 사용자 위치를 사용한다. 위치가 없으면 `WAITING_POSITION` 상태로 최대 5초 대기하고, 복구되면 최신 위치로 출동한다. 계속 없으면 개인 안내만 남기고 다음 출동 요청을 처리한다. 잘못된 0 좌표로 이동하거나 순간이동하지 않는다. 이동 중 대상 위치가 기존 경로 끝에서 2m 넘게 달라지면 기존 1초 경로 계획 주기에 맞춰 재계산한다. 보드게임 중에는 기존대로 개인 안내·MM만 처리하며 경찰은 이동하지 않는다.

## DB 적용과 복구

팀 공유·순서 확인된 V170을 원문 그대로 포함하고 V171에서 AI 전용 7개 테이블을 추가한다. `V170 → V171` 순서이며 기존 테이블·사용자·소리함 원본은 변경하지 않는다. V170은 후속 아재왕과 동일한 SQL이므로 이력 repair·번호 변경 없이 같은 파일로 유지한다. 공용 DB에 수동 적용하지 않으며 일반 배포의 Flyway 절차를 따른다.

채팅·판단·사건/발언 연결·소리함 AI 처리·MM outbox·요약 시각을 행 단위로 저장한다. 원문 모델은 각 행의 JSON payload로 보존하고 처리 상태·시각·멱등 키에는 검색 인덱스와 유일 제약을 둔다. 같은 시각의 채팅은 DB 수신 순번으로 순서를 보존한다. 원래 JSON의 누적 5,000건/2,000건/16MiB 제한은 정식 서비스에 적용되지 않는다. 완료 이력은 DB에 보존하고 자동 삭제하지 않는다.

작업자는 대기 채팅 최대 512건과 최근 표시용 기록·범위별 30초/5개 문맥만 조회한다. 이는 전체 저장 상한이 아니다. 사건·제보·알림도 처리할 작업 묶음만 읽으며 오래된 동일 메시지 ID/제보 요청 키는 DB에서 별도 조회해 중복 처리하지 않는다. 소리함 요약은 100건 및 번호·줄바꿈 포함 12,000자 이내에 실제 전달한 제보만 완료 처리하고 나머지는 다음 묶음에 남긴다. 파일을 DB 한 행에 통째로 넣거나 매 작업마다 전체 보관 이력을 불러오지 않는다.

단일 활성 AI 작업자가 기존 서비스 구조의 한 경찰/NPC와 외부 알림을 처리한다. MySQL 세션 락으로 같은 DB의 중복 작업자 시작을 거절한다. 세션 유지용 풀 연결 1개를 사용하므로 앱의 기존 DB 풀은 다른 서비스가 사용할 여유 연결을 포함해야 한다. 다중 활성 AI 인스턴스의 분산 소비는 지원하지 않는다. 종료·초기화 실패 시 소유권을 반환한다.

DB에 커밋된 미검수 채팅·미분류 제보·미발송 MM은 재시작 후 이어서 처리한다. 외부 Jev/LLM/MM 호출은 DB 트랜잭션 밖에서 실행한다. MM 전송 성공 직후 DB 결과 저장 전에 중단되면 재전송될 수 있는 at-least-once 방식이며 정확히 한 번 도착을 보장하지 않는다. DB 연결 상실 시 새 처리는 재시도 대기하고 소유권 회복을 위해 앱 재시작이 필요하다. DB 커밋 전 메모리 큐의 입력은 장애·재시작 시 유실될 수 있으며, 소리함 원본의 자동 재수집은 하지 않는다.

로컬 실험실/ai-park는 기존 JSON 대역과 한도를 유지한다. 기존 `state.json`은 자동 이관·삭제하지 않는다. 기존 테스트 알림을 운영 채널에 재발송하지 않도록 DB는 별도 새 기록으로 시작한다. 실제 Jev/MM 연결과 현재 맵 출동 검증은 로컬 MySQL 저장소 테스트와 구분한다.
