## 1. 개정 목표와 해석 기준

조리·재고·손님을 카트 앞에서 직접 관리하는 느낌을 강화한다. 기존 철판 조리의 3D 표현을 유지하고, 쟁반·손님·불꽃·쓰레기통을 차례로 3D로 전환한다. 숫자·주문·시간 같은 정보는 읽기 쉬운 UI로 함께 제공한다.

- **[확정]** 이번 사용자가 요청한 변경이다.
- **[유지]** 현재 v4의 승인된 정책을 이어가는 부분이다.
- **[설계안]** 작업을 구체화하기 위한 기본안이다. 사용자 확정 요구와 구분하며, 수치를 바꾸면 FE·BE 문서와 판별 설정을 함께 갱신한다.
- **[검증 후 조정]** 플레이테스트·화면 확인·성능 측정으로 조정할 항목이다.

| 항목 | 기존 v4 | v5 목표 | 구분 |
| --- | --- | --- | --- |
| 불 시작 | 소를 넣을 때 배정·가열 | 소 투입(FILL) 때 배정·가열 유지 | 2026-10-28 변경 확정 |
| 완성품 쟁반 | 전체 4개, 2D 중심 | 전체 10개, 2단에 각 5개인 3D 쟁반 | 확정 / 형태 해석은 설계안 |
| 손님 | 왼쪽 주문 창의 1명 | 카트 정면에 개인 전용 3D 손님 최대 3명 | 확정 |
| 손님 교체 | 현재 손님 납품 후 다음 1명 | 빈 자리에 새 손님이 들어올 수 있음 | 확정 |
| 실제 플레이 | 60초 | 120초, 마지막 30초 가속 | 2026-10-29 변경 확정 |
| 탄 빵 | 앞면에서도 뒤집을 수 있음 | 뒤집기 불가, 바로 쓰레기통으로 폐기 | 확정 |
| 화력 표현 | 불 표시·수치 UI 중심 | 철판 아래 가스버너형 3D 불꽃과 수치·문자 병행 | 확정 |

여기서 **철판**은 굽는 6칸, **쟁반/트레이**는 완성품을 보관하는 10개 공간이다. 불꽃은 보관 쟁반 아래가 아니라 **조리 철판 아래 버너 위치**에 배치한다. “2중, 한 칸에 5개”는 위·아래 선반 각각 5개를 나란히 놓는 형태로 해석한다. 빵을 5개 높이로 겹쳐 숨기는 형태는 기본안으로 사용하지 않는다.

## 2. 핵심 게임 규칙

**세 손님 주문 확인 → 재료 선택 → 반죽 → 소 투입부터 가열 → 불에 맞춰 뒤집기 → 10개 쟁반에 보관 → 선택한 손님에게 전달**하는 흐름이다.

| 항목 | 규칙 |
| --- | --- |
| 철판 | [유지] 2×3, 총 6칸 독립 사용 |
| 재료 | [유지] 반죽과 팥·슈크림·피자·초코 |
| 불 원본 | [유지] 서버 발급 85~115% 정수, 네 소에 같은 분포 |
| 배정 시점 | [확정] 성공한 소 투입(`FILL`)마다 다음 서버 불 사용 |
| 쟁반 | [확정] 전체 합계 10개. 재료별 10개가 아님 |
| 손님 | [확정] 같은 플레이어에게만 보이는 손님 최대 3명 |
| 개별 주문 | [유지] 손님마다 총 1~4개, 주문 전체를 한 번에 납품 |
| 주문 선택 | [설계안] 대기 중인 세 손님 중 원하는 손님을 선택해 먼저 처리 가능 |
| 시간 | [확정] 120,000ms, 카운트다운·시점 전환·결과는 별도 |
| 후반 가속 | [확정] 90,000ms부터 종료까지 30초 |
| 가속 폭 | [설계안: 기존 값 유지] 기준 불에서 한 면 8초 → 6초, 타이머는 실제 1초 속도 유지 |
| 점수 | [유지] 꺼낼 때 보관 점수만 기록, 납품 승인으로 총점 반영 |
| 보상 | [유지] 15점당 1냥, 일일 100냥 한도, 실제 지급은 서버 확정 |

손님 수를 3명으로 늘려도 손님 한 명의 주문 최대 수량을 10개로 늘리지 않는다. 세 주문의 합계가 10개를 넘을 수 있으며, 모든 주문을 동시에 완성해 둘 필요는 없다.

## 3. 한 판의 흐름

1. 공원 카트 앞에서 E로 진입한다. 기존 개인 조리 시점과 공원 입력 잠금을 적용한다.
2. 시작 안내에서 제한 시간, 10개 쟁반, 손님 선택, 반죽 → 소 투입부터 가열, 탄 빵 폐기를 설명한다. 새 판 목표는 2분이며 서버 발급 시간을 타이머에 표시한다.
3. 서버가 정한 시각에 기존 3.5초 카운트다운 후 플레이를 시작한다. 카운트다운 중에는 조리하지 못한다.
4. [확정] 시작 후 약 0.35초에 첫 손님 한 명이 입장하고, 평소 약 6초 간격으로 한 명씩 입장한다. 최대 3자리이며 첫 발급 주문은 기존처럼 팥 2개, 나머지 주문도 서버가 발급한다. 입장 전에는 말풍선과 주문 선택 UI를 표시하지 않는다.
5. 반죽만 부었을 때는 불이 꺼져 있다. 소를 넣는 순간 불을 배정하고 앞면이 익기 시작한다.
6. 타지 않은 빵은 뒤집고 꺼내 쟁반에 보관한다. 탄 빵은 뒤집지 않고 폐기한다.
7. 손님을 선택하고 필요한 재고가 있으면 R 또는 전달 버튼으로 납품한다. 여분 빵은 남는다.
8. 납품이 승인되면 그 손님이 떠난다. 서버가 발급한 다음 손님은 대기열에 들어가고, 평소에는 최소 2.5초 대기 후 다음 입장 차례에 같은 빈 자리로 들어온다. 다른 손님은 계속 기다린다.
9. 남은 33초부터 예고하고, 남은 30초부터 조리 속도를 높인다. 손님 최대 수는 계속 3명이며 서버가 발급한 대기 손님을 약 0.7초 간격으로 빈자리에 입장시킨다.
10. 새 판은 120초가 되면 새 입력·손님 입장을 종료하고 결과를 정산한다. 기존 3분 판은 원래 종료 시각을 유지한다. 유효 시간에 기록한 납품은 기존 제출 유예 안에서 서버가 검증한다.
11. 다시 하기 또는 공원 복귀를 선택한다. 개인 손님·불꽃·재고·입력 리스너를 정리하고 기존 자연스러운 아바타 복귀를 유지한다.

[유지] 탭 비활성·F1 도움말·그만두기 확인·통신 대기 중에도 서버 시간과 조리는 계속된다. 중도 포기는 무보상이다. F1 도움말에 게임 종료 버튼을 다시 넣지 않는다. 게임 자체 종료는 프로필 로그아웃 흐름을 사용한다.

## 4. 소 투입부터 익는 조리

### 상태와 불 소비

| 현재 상태 | 조작 | 결과 |
| --- | --- | --- |
| 빈 칸 | 반죽 붓기 | 반죽만 올림, 불·익힘·불 소비 없음 |
| 반죽 | 소 넣기 | 소 확정, 서버 불 1개 소비, 불꽃 켜짐, 앞면 since=t |
| 소가 있는 타지 않은 앞면 | 일반 조작 | 앞면 값 고정, 뒤집고 뒷면 조리 시작 |
| 타지 않은 뒷면 | 일반 조작 | 양면 판정 후 정상 완성품 보관 또는 기존 설익음 실패 처리 |
| 가열 중인 앞면/뒷면의 탄 빵 | 일반 조작 또는 폐기 조작 | 뒤집기 없이 폐기, 쓰레기통 이동 |
| 비어 있지 않은 칸 | 우클릭 / Shift+칸 키 | 직접 폐기, 쓰레기통 이동 |

- 소 투입(`FILL`) 시각부터 앞면을 계산한다. `POUR`는 반죽만 올리고 조리를 시작하지 않는다.
- 반죽만 두면 시간이 지나도 익거나 타지 않는다. 소를 넣은 뒤 탄 빵은 뒤집어 정상 빵으로 만들 수 없다.
- 소를 넣지 않은 반죽은 뒤집기·정상 꺼내기를 할 수 없다.
- 앞·뒷면은 같은 불을 사용한다. 성공한 소 투입만 다음 불을 소비한다. 가열 전 반죽 폐기는 불을 소비하지 않으며, 이미 사용한 불은 반환하지 않는다.
- 뒤집은 앞면은 더 익지 않는다. 현재 가열 중인 면만 시간이 흐른다.
- 탄 상태는 시간으로 판정하며 자동 폐기하지 않는다. 플레이어의 폐기 조작으로 칸을 비운다.

### 익힘 계산

[유지] 품질 구간과 점수는 변경하지 않는다. `h`는 서버 배정 불, `N`은 해당 면의 가속 전 조리 ms, `R`은 가속 후 조리 ms다. 새 2분 판의 경계는 90초, 기존 3분 판은 150초다.

```text
익힘 = floor(h × (N × 6000 + R × 8000) / (8000 × 6000))
```

구간별로 먼저 내림하지 않고 합계에 한 번 내림한다. 앞면의 시간 원점은 반죽 붓기, 뒷면의 원점은 뒤집기다.

| 정수 익힘 | 판정 | 면 점수 |
| --- | --- | ---: |
| 0~49 | RAW | 빵 전체 0 |
| 50~69 | GOOD | 2 |
| 70~90 | PERFECT | 5 |
| 91~99 | GOOD | 2 |
| 100 이상 | BURNT | 빵 전체 0 |

예: 반죽을 붓고 2초에 소를 넣으면 그때부터 불 100으로 익는다. 소 투입 후 6.4초인 8.4초에 뒤집으면 앞면 익힘은 80이다. 148~152초를 걸쳐 굽는 면은 익힘 58이다.

## 5. 쟁반 10개와 3D 카트

- 위·아래 2단에 각각 5개의 위치를 둔다. 총 10개 모두 종류와 수량을 식별할 수 있게 한다.
- [설계안] 보관 순서대로 아래 단 5개 → 위 단 5개를 채운다. 납품·폐기 뒤 남은 빵은 순서를 유지해 재배치한다.
- 화면 위치가 바뀌어도 서버의 안정적인 `breadId`는 바뀌지 않는다. 종류별 먼저 보관한 빵부터 납품하는 FIFO를 유지한다.
- 종류·양면 품질·보관 점수를 빵에 연결한다. 3D 소 표시와 보조 목록으로 같은 외형의 빵도 구분한다.
- 10개가 찬 상태에서 정상 꺼내기는 거부한다. 철판은 계속 익고, 자동 폐기·재고 덮어쓰기·11번째 저장은 하지 않는다.
- 탄 빵 폐기는 쟁반을 거치지 않으므로 쟁반이 가득 차도 가능하다.
- 쟁반에 저장한 정상 빵은 더 익지 않는다. 쟁반 재고도 선택해서 쓰레기통으로 버릴 수 있다.

카트는 현행 코드 모델인 `CodeFishBreadCart`·`fishCartGeometry`를 수정 대상으로 삼는다. 원본 GLB 교체가 필요하다고 가정하지 않는다. 2단 선반, 철판 아래 버너가 보이는 공간, 옆쪽 쓰레기통, 정면 손님 3자리를 위한 시야를 함께 설계한다. 공원 위치·접근 반경·기존 6칸 앵커를 유지하며, 외곽을 넓혀 충돌 변경이 필요하면 별도 월드 변경으로 검토한다.

## 6. 개인 전용 3D 손님

- 손님은 카트의 고객 측 정면에 좌·중·우 3자리로 배치한다. 조리자의 시점에서 얼굴과 주문이 보이고 철판·트레이 클릭을 가리지 않아야 한다.
- [설계안] 각 손님을 클릭하거나 전용 선택 UI로 대상을 고른다. R은 **선택한 손님 한 명**에게만 전달한다. 자동으로 다른 주문을 납품하지 않는다.
- 주문은 손님 입장 인사 → 도착 후 실제 주문 대사 → 맛별 붕어빵 그림·요구 수량의 구름 말풍선으로 표시한다. 입장하지 않은 손님은 말풍선과 주문 선택/전달 대상에서 제외한다. 준비된 주문의 전달 버튼 또는 선택한 주문의 R 키로 납품한다. 초록색 월드 팻말은 사용하지 않는다.
- 준비 수량 표시는 공유 재고를 기준으로 한다. 여러 손님에게 동시에 “준비 완료”가 보일 수 있지만 빵을 예약·복제하지 않는다. 한 명 납품 후 나머지 준비 상태를 즉시 재계산한다.
- 손님은 입장 → 대기 → 납품 확인 → 퇴장 연출을 갖는다. 재고·점수·빈자리 확정은 애니메이션이 아니라 서버 승인에 따른다.
- [확정] 서버가 승인한 주문만 FE 입장 대기열에 넣는다. 발급 즉시 입장시키지 않고 평소 약 6초, 마지막 30초에는 약 0.7초 간격으로 한 명씩 보여준다. 탭 비활성 중 밀린 입장을 복귀 시 한꺼번에 재생하지 않는다. 새 주문 생성·재추첨·정산 규칙은 서버 권한을 유지한다. 서버가 입장 시각 자체를 검증하는 계약은 이 FE 연출 변경에 추가하지 않는다.
- [유지] 손님 대기시간 제한·화남·이탈 벌점은 이번 개정에 추가하지 않는다.
- 손님은 플레이어의 로컬 장면에만 생성한다. 다른 플레이어·공개 월드 인원·충돌·네비게이션에 추가하지 않는다. 다른 플레이어에게는 기존 이용 상태 말풍선만 전달한다.

## 7. 버너 불꽃과 쓰레기통

### 불꽃

- 각 철판 칸 아래에 가스버너형 불꽃을 두고 어느 칸의 불인지 구분한다.
- 빈 칸은 꺼진 상태, 소 투입부터 꺼내기·폐기까지 켜진 상태다. 반죽만 있는 칸은 꺼져 있다. 탄 빵도 치우기 전까지 가열 상태를 유지한다.
- 불 세기는 서버 배정값을 사용한다. FE가 별도로 랜덤한 강도를 정하거나 불꽃 모양으로 판정을 계산하지 않는다.
- [설계안] 85%는 작고 낮게, 100%는 중간, 115%는 크고 높게 표현한다. 중간값은 연속 보간한다. 최소·중간·최대에서 차이를 쉽게 알아볼 수 있어야 한다.
- 마지막 30초의 공통 가속도 불꽃 강도와 “굽기 ×배율”에 반영한다. 배정 불 자체를 다시 뽑지는 않는다. 실제 속도 배율은 평소 `h/100`, 가속 중 `(h/100)×8/6`이다.
- 불 85/100/115% 수치와 약불/보통불/센불 문자도 함께 제공한다. 색만으로 강도를 구분하지 않는다. 모션 감소에서는 흔들림을 줄여도 강도 차이는 남긴다.

### 쓰레기통과 탄 빵

- 카트 옆, 조리 시점에서 클릭 가능한 위치에 3D 쓰레기통을 둔다.
- [설계안] 탄 칸을 누르면 폐기 동작 한 번으로 빵이 쓰레기통으로 이동한다. 들고 다시 클릭해야 하는 두 단계는 필수로 만들지 않는다.
- 일반 빵은 폐기 대상 선택 후 쓰레기통 클릭 또는 기존 우클릭/Shift+칸 키로 버린다. 쟁반 빵도 ID로 선택해 버린다.
- 쓰레기통 클릭에 유효한 대상이 없으면 안내만 표시한다. 모든 빵을 한 번에 버리거나 선택이 바뀐 다른 빵을 버리지 않는다.
- 폐기 성공 시만 이동·뚜껑 반응을 재생하고, 실패·거절·중복 입력에는 성공 연출을 만들지 않는다.
- 탄 빵은 뒤집기(`TURN`)로 보내지 않고 폐기(`DISCARD`)로 기록한다. 쟁반·납품으로 넘길 수 없고 점수·보상을 얻지 못한다.

## 8. 입력·카메라·정보 UI

| 입력 | 동작 |
| --- | --- |
| Space / 숫자열·숫자패드 1~4 | 반죽 / 팥·슈크림·피자·초코 선택 |
| 휠 아래·위 | 기존 순서의 다음·이전 재료, 양 끝에서 멈춤 |
| 좌클릭 / Q W E·A S D | 상태에 맞는 조리, 탄 칸이면 바로 폐기 |
| 우클릭 / Shift+칸 키 | 해당 철판 빵 직접 폐기 |
| 손님 클릭 / 손님 선택 UI | 납품 대상 선택 |
| R / 선택 손님 전달 버튼 | 준비된 선택 주문 전체 납품 |
| 빵 선택 후 쓰레기통 / 보조 폐기 버튼 | 해당 빵 한 개 폐기 |
| F1 | 도움말 열기·닫기, 게임 종료 버튼 없음 |

채팅·IME·입력창·도움말이 입력을 점유하면 조리 단축키·휠을 막는다. 카운트다운·정산 단계는 조리/납품 입력을 차단한다. 전체 50ms·같은 칸 300ms 입력 간격은 유지한다.

기존 조리 시점을 기반으로 철판 6칸·2단 쟁반·손님 3명·버너·쓰레기통이 한 화면에서 읽히도록 시점과 차양 가림을 조정한다. 카메라 수치는 화면 검수 후 정하며, 기존 진입/복귀 동작과 1·3인칭 복귀를 보존한다. 다른 실제 플레이어를 임의로 숨기지 않는다.

2026-10-28 요청에 따라 플레이 화면은 레퍼런스의 2.5D 구성으로 전환한다. 가운데 가까운 철판 2×3칸을 배치하고, 상단 왼쪽 분:초 타이머·오른쪽 점수/전달 손님 수, 오른쪽 콤보, 하단 왼쪽 재료 5개·가운데 2×5 보관함/폐기·오른쪽 F1 버튼을 제공한다. 불 세기 문자/%와 현재 면 익힘 게이지는 각 철판 칸 아래에 붙인다. 초록색 주문 팻말·별도 입체 계기판·입체 숫자 UI를 제거한다. 실제 철판/손님/조리 동작과 입체 질감의 음식 스프라이트를 결합하며, 버튼과 정보는 선명한 화면 UI로 제공한다. 시작·결과·도움말·종료 확인·통신 복구와 기존 키 조작은 유지한다. 실제 엽전은 서버 정산 후 결과에서 표시하며 플레이 중 가짜 지급액을 만들지 않는다.

## 9. 점수·결과·공정성

- 품질·콤보·특수 주문 20%·첫 주문 팥 2개 정책을 유지한다. 2026-11-02부터 새 판의 피자·초코 납품 보너스는 30%로 낮춘다. 기존 발급 판은 저장된 50%를 유지한다.
- 양면 황금 10점, 황금/GOOD 7점, GOOD/GOOD 4점. 한 면이라도 RAW/BURNT이면 0점이다.
- 양면 황금은 콤보 +1, 정상 혼합은 유지, 실패·폐기는 0으로 만든다. 3~5콤보 ×1.2, 6 이상 ×1.5, 정수 내림을 유지한다.
- 미납품·폐기·남은 철판은 점수가 없다. 특수 재료는 실제 납품한 빵에만 보너스를 준다.
- [설계안] 탄 빵 직접 폐기는 폐기 1회와 실패 1회로 집계하고, 완성·납품 개수는 늘리지 않는다. 두 지표는 중복 집계될 수 있는 다른 의미이므로 합산해 전체 빵 수로 표시하지 않는다.
- 실제 엽전은 기존처럼 최종 완료 시 한 번 지급한다. 2분 전환으로 환산율·일일 한도를 변경하지 않는다.
- 수익/분, 평균 완료 주문 수, 폐기율, 준비 재고와 마지막 30초 난도를 다시 측정한다. v4 점수를 3배 하여 v5 예상 수익으로 보고하지 않는다.

## 10. FE·BE 변경과 호환성

| FE | BE |
| --- | --- |
| 3D 카트·쟁반·개인 손님·버너·쓰레기통, 입력과 즉시 피드백 | 서버 시간·불 원본·최대 3건 주문·판별 규칙 관리 |
| 소 투입부터 계산하는 예상 조리, 선택 주문·재고 표시 | 동일 로그로 반죽·불·품질·쟁반·선택 주문 납품 재계산 |
| 서버 승인/거절·checkpoint 복구·재시도 | 멱등 납품·충원·정산, 저장·검증·실제 지급 |

[설계안] 의미가 바뀌는 규칙이므로 신규 `rulesVersion: v5`로 분리하고 기존 v2/v4 기록·영수증·진행 판을 그대로 유지한다. 같은 v4 설정을 덮어써 과거 기록을 새 규칙으로 해석하지 않는다. API 확장 예시는 BE 작업명세의 **제안 계약**이며 아직 구현된 API가 아니다.

이용 상태 말풍선은 해당 판의 카운트다운·플레이·종료 처리를 포함해 유지하고 완료·포기 시 해제한다. 2분 플레이에 맞춰 단순 120초 TTL로 줄이면 카운트다운 도중 시간이 소비되므로 고정 TTL을 추가하지 않는다. 개인 손님·주문·불 원본을 공개 월드에 보내지는 않는다.

## 11. 공동 완료 조건과 남은 조정

| 확인 항목 | 완료 기준 |
| --- | --- |
| 소 투입 가열 | 반죽만 있으면 불·익힘 없음, FILL에서 불 배정과 앞면 타이머 시작 |
| 10개 쟁반 | 2단×5개 표시, 10개까지 저장, 11번째 거절, 종류별 FIFO와 여분 유지 |
| 손님 3명 | 서로 다른 활성 주문 선택·납품·한 자리 충원, 다른 플레이어에게 NPC가 보이지 않음 |
| 2분·가속 | 87초 예고, 90초 가속, 120초 입력 마감, 경계 전후 익힘 FE·BE 일치. 기존 3분 판은 기존 스냅샷 유지 |

| 시각 전달 | 85/100/115%와 가속 강도가 읽히며 낮·밤·모션 감소에서도 인지 가능 |
| 복구·지급 | 응답 유실·거절·종료 경합에서도 빵·주문·충원·지급 중복 없음 |
| 기존 동작 | F1·채팅 입력 보호, 카메라 복귀, 공원·기존 버전 기능 유지 |
| 성능 | 동일 장면 전후 드로우콜·삼각형·프레임시간·메모리·전송량·자원 정리 확인 |

검증 기준은 **2단 배치, 입장한 손님 자유 선택, 첫 손님 1명부터 순차 입장, 납품 승인 후 대기열 충원, 마지막 30초 연속 입장과 기존 8→6초 조리 가속 폭**이다. 입장 간격은 FE 연출 값으로 두며 서버의 발급 주문만 사용한다. 추가 손님 이탈·벌점·재고 부패·랭킹은 이번 범위에 포함하지 않는다.
