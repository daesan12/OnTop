# 붕어빵 뒤집기 FE 작업명세 v5

> 2026-10-28 변경: 사용자 요청으로 가열 시작을 소 투입(FILL)으로 되돌렸습니다. 반죽만 있는 동안은 불·익힘·불 cursor가 진행되지 않습니다. BE 담당자에게는 사용자가 별도 전달했으며, BE 완료 후 최종 응답/fixture를 대조합니다. 이번 구현은 FE 변경입니다.

작성일: 2026-10-27 · 담당: FE 및 카트/캐릭터 시각 에셋 담당 · PC 웹

기준: [최종기획 v5](붕어빵_뒤집기_최종기획.md) · 연동: [BE 작업명세 v5](붕어빵_뒤집기_BE_작업명세_v5.md)

이 문서는 v5 작업 기준이다. 현재 저장소의 v4 코드 경로를 기준으로 작성했으며, **2026-10-27 FE 선행 구현 현황은 §11**에 구분해 기록한다. 기존 v4 계약은 유지하고 신규 v5 계약을 BE와 맞춘 뒤 실제 서버에 연결한다.

## 1. 목표와 책임

소 투입부터 익는 6칸 철판, 10개 쟁반, 카트 정면의 개인 손님 최대 3명, 서버 화력을 보여주는 불꽃, 직접 폐기하는 쓰레기통을 구현한다. 새 판 목표는 120초이며 마지막 30초만 빨라진다.

> 2026-10-29 개정: FE 기본·미리보기는 120초/90초 가속이며, 실서버는 판별 규칙 스냅샷을 따른다.
> 기존 180초/150초 가속 판도 계속 처리한다. 실제 새 판 전환과 배포는
> [BE 2분 변경 요청](BE_2분_플레이_변경요청_2026-10-29.md)에 정리했다. 뒤쪽 과거 구현 기록의 3분 표기는 당시 기준이다.

FE는 화면·입력·예상 재계산·응답 복구를 맡는다. 불·주문 원본·확정 점수·보상은 서버 권한이다. 개인 손님은 공개 월드 NPC가 아니며 FE 로컬 장면에서만 생성한다.

### 공통 수치

| 항목 | v5 값 |
| --- | --- |
| 철판 | 6칸, 기존 QWE/ASD |
| 쟁반 | 10개, 2단×각 5개 |
| 동시 손님 | 최대 3명, 각 주문 총 1~4개 |
| 플레이 | 새 판 `durationMs=120000`, 기존 판은 서버 스냅샷 유지 |
| 가속 | 새 판 `rushFromMs=90000`, 예고 87000ms |
| 가속 폭 | 설계안: 평소 한 면 8000ms, 가속 6000ms |
| 랜덤 불 | 서버 85~115 정수, 성공 FILL마다 소비 |
| 간격 | 전체 50ms, 같은 철판 칸 300ms |

품질·콤보·특수 보너스·엽전 환산·일일 한도는 기존 정책을 유지한다. API 수치와 원본은 서버의 판별 스냅샷을 사용한다. 로컬 상수만 바꿔 서버 v4에 전송하지 않는다.

경로는 저장소 루트 기준이다. 신규 컴포넌트 이름은 제안이며 공개 API 이름이 아니다.

## 3. FE-01 — 순수 조리 규칙

1. POUR는 반죽만 올린다. 빈 칸과 반죽 단계에서는 불을 소비하지 않고 불꽃·익힘을 표시하지 않는다.
2. 성공한 FILL에서 다음 서버 불을 소비하고 소·앞면 since=t를 저장한다. 그 시각부터 익힘과 불꽃을 표시한다.
3. 반죽만 있는 동안은 타지 않는다. 소 없는 반죽은 TURN을 할 수 없다.
4. 조작 순간 익힘을 다시 검사한다. 탄 앞면/뒷면에 대한 일반 클릭·칸 키는 TURN보다 우선해 DISCARD 한 번으로 처리한다.
5. 타지 않은 앞면은 뒤집고 뒷면의 새 원점을 기록한다. 이미 고정한 앞면은 더 익히지 않는다.
6. 정상 뒷면은 쟁반에 저장한다. 10개가 차면 거절하고 철판·로그·콤보·불 cursor를 유지한다. 탄 빵은 쟁반을 거치지 않는다.
7. 거절 입력은 로그에 추가하지 않는다. 표시 프레임과 클릭 사이에 타버린 경우 클릭 시점 판정을 따른다.

익힘은 최종 합계에 한 번 내림한다.

```text
N = 해당 면의 rushFromMs 이전 조리 시간 (새 판 90000ms)
R = 해당 면의 rushFromMs 이후 조리 시간 (기존 판은 서버 스냅샷 유지)
level = floor(h × (N×6000 + R×8000) / (8000×6000))
```

불 원본 소진 시 새 FILL을 막고 복구 안내를 한다. 이미 올린 빵의 시간은 계속 흐른다. FE 독립 추첨·불 값 재사용·v4로의 자동 폴백을 하지 않는다.

## 4. FE-02 — 10개 쟁반과 카트 에셋

### 제작물과 배치

- 현행 코드 카트에 위·아래 2단 선반을 마련하고 각 단 5개 위치를 정의한다.
- 제안 앵커: `tray_lower_0..4`, `tray_upper_0..4`, `burner_0..5`, `trash_drop`, `customer_0..2`. 코드 좌표 테이블이나 모델 노드로 동일하게 참조할 수 있다.
- 앵커는 카트 로컬 좌표로 정의하고 월드 변환을 한 곳에서 적용한다. 기존 6칸 철판·공원 상호작용 앵커는 유지한다.
- 하단 선반→상단 선반 순으로 채우고, 납품/폐기 후 남은 빵을 보관 순서대로 재배치하는 안을 사용한다.
- 한 개의 빵 표현을 재사용하고 재료 표시·품질 색을 인스턴스 데이터로 구분한다. 10개 모두 확인 가능해야 한다.
- 빵 선택·보관 점수·종류·폐기 버튼을 보조 목록으로도 제공한다. `n/10`과 가득 참 상태를 읽을 수 있게 한다.

### 재고 식별

3D 자리 번호는 렌더 위치다. 납품/폐기 대상은 `breadId`로 지정한다. 움직이는 빵·접히는 선반·재배치로 ID를 바꾸지 않는다. 폐기 애니메이션 중 남은 재고가 압축돼도 다른 빵이 삭제되면 안 된다.

정적 카트와 개인 재고를 분리한다. 공개 카트의 장식용 붕어빵이 실제 10개 재고처럼 보이거나 중복 렌더되지 않게 조리 모드에서 처리한다. 개인 재고는 다른 플레이어의 장면에 생성하지 않는다.

## 5. FE-03 — 개인 손님 3명과 주문 선택

- 카트 고객 측 정면에 3개의 대기 위치를 둔다. 조리자의 카메라에서 얼굴·주문을 볼 수 있게 배치한다.
- 손님은 가벼운 공유 캐릭터/재질을 재사용하되 서로 다른 옷·색상 등으로 구분한다. 실제 공원 이용자의 계정/외형을 복제하는 기능은 필요하지 않다.
- `orderId`와 `customerSlot`으로 손님을 식별한다. 화면 배열 index·이전 단일 `orderIndex`로 납품 대상을 정하지 않는다.
- 클릭/선택 UI로 활성 주문 하나를 선택한다. 처음에는 첫 자리, 선택 손님이 떠나면 아직 대기 중인 가장 오래된 주문을 선택하는 기본안을 적용한다.
- 2026-10-29 R 자동 전달: R 한 번에 입장·주문 발표를 마친 손님 한 명을 찾는다. 선택 손님이 준비됐으면 우선 전달하고, 아니면 준비된 주문 중 입장 시각이 가장 이른 손님을 고른다. 종류별 요구 수량 이상이면 가능하며 필요한 수량만 차감한다. 전달 중·응답 오류·인사 중·미입장·메뉴/채팅/종료창에서는 추가 전달하지 않는다. 전달 버튼 클릭은 해당 손님을 명시적으로 선택하는 기존 동작을 유지한다. 기존 DELIVER/orderId 계약을 사용하므로 이 조작 변경에 새 BE API는 필요 없다.
- 준비된 주문이 없으면 안내만 표시하고 납품 로그나 요청을 만들지 않는다. R을 누르지 않은 상태에서는 재고가 준비되어도 자동 납품하지 않는다.
- 손님 앞의 3D 주문표에는 붕어빵 모형·재료 이름·수량·준비 수량·선택/대기/전송 상태를 표시한다. 주문표에 지지대·클립·입체 조작 버튼을 둔다. 보너스 재료도 구분한다.
- 준비 수량은 공유 쟁반을 기준으로 계산하며 주문별로 재고를 예약하지 않는다. 한 주문 소비 후 다른 두 주문의 상태를 갱신한다.
- 서버가 승인한 새 주문만 빈자리에 배치한다. FE 애니메이션 완료나 로컬 타이머로 주문을 생성하지 않는다.
- 퇴장 손님은 잠깐 비상호작용 연출로 유지할 수 있지만, 같은 자리에 활성 주문/클릭 대상이 둘 생기면 안 된다. `orderId`와 수명 토큰으로 늦은 애니메이션 콜백을 차단한다.
- 2026-10-29 전달 후 감사 인사: 6종 손님마다 감사 문구 6개씩을 별도로 섞어 사용한다. 서버 전달 승인 전에는 기존 모델을 자리에 유지하고 감사 인사를 표시하지 않는다. 승인 후 약 0.45초의 수령 연출, 최소 2.6초의 감사 말풍선, 1.1초의 퇴장 순서로 진행한다. 긴 문장은 읽기 시간을 늘리고, 같은 종류 손님의 직전 인사는 반복하지 않는다. 교체 손님은 이전 손님이 퇴장할 때까지 같은 자리에 들어오지 않으며, 마지막 30초에도 이 겹침 방지는 유지한다. 실패 시 동일 요청 재시도/복구 흐름을 따르고, 게임 종료·재시작 시 로컬 연출 상태를 비운다. 기존 DELIVER 승인 응답을 사용하므로 BE 추가 API는 필요 없다.
- 지원 PC 화면에서 주문표 세 개를 3D 시야 안에 배치한다. 화면 읽기 도구용 숨김 DOM도 제공한다. 손님 메시가 철판이나 쓰레기통 클릭을 먼저 가로채지 않도록 raycast 대상을 구분한다.

다른 플레이어에게 손님 NPC·주문을 WebSocket으로 전송하지 않는다. 공개 아바타 이용 상태 말풍선은 기존 경로를 사용하며 판별 플레이와 카운트다운 동안 유지되는지 BE와 검증한다.

## 6. FE-04 — 서버 화력을 읽을 수 있는 불꽃

- 6개 칸 아래에 버너/불꽃을 연결한다. 위에서만 보이는 게이지가 아니라 카트 측면에서도 버너가 보일 공간을 만든다.
- 2.5D 조리 화면에서는 별도의 버너 창 없이 각 불판 양옆과 앞쪽 모서리에서 부드러운 파란 불꽃이 올라온다. 불꽃의 시작점은 불판 가장자리의 실제 3D 좌표를 화면으로 투영해 정하므로 화면 크기·원근이 바뀌어도 불판을 따른다. 앞뒤 여섯 칸 모두 같은 방식으로 표시하고, 기존 불꽃 수·화력 문자·백분율·익힘 게이지도 유지한다. 불꽃 높이는 서버 화력에 따라 커지고 흔들림은 빨라지며, 마지막 30초에는 동일 화력의 불꽃도 더 커진다. 실제 3D 버너는 해당 철판 아래에 두어 조리대 밖으로 불꽃이 노출되지 않게 한다.
- 불꽃은 슬롯의 서버 배정 `heat`와 현재 가속 구간을 입력으로 받는다. 흔들림용 시각 난수는 가능하지만 평균 강도·판정·열 배정을 바꾸지 않는다.
- 기본 강도 `heat/100`, 가속 강도 `(heat/100)×8/6`을 높이·폭·발광에 단조 증가로 대응시킨다. 구체 스케일은 시각 검수로 정한다.
- `85/100/115%`, 약불/보통불/센불, 현재 굽기 배율을 함께 표시한다. 가속 시 “마지막 30초” 안내를 보여준다.
- 소 투입부터 켜고 꺼내기/폐기 후 끈다. 탔다고 불을 임의로 꺼서 조리가 멈춘 것처럼 보이지 않게 한다.
- 낮·밤에서 크기 차이를 읽을 수 있게 하고 과한 빛으로 빵의 색·게이지가 가려지지 않게 한다.
- 6개 그림자 광원을 추가하는 방식은 기본안으로 사용하지 않는다. 재사용 메시/불꽃 재질·발광과 제한된 효과로 구현한다.
- 모션 감소에서 흔들림·파티클을 줄여도 정적인 크기·문자·배율로 강도를 알 수 있게 한다.

## 7. FE-05 — 쓰레기통과 즉시 폐기

- 쓰레기통은 조리 시야 안 옆쪽에 둔다. 클릭 영역과 선택 대상 표시를 제공한다.
- 탄 칸을 클릭하거나 칸 키를 누르면 `DISCARD`를 기록하고 뒤집기 없이 쓰레기통으로 보낸다. `TURN` 성공/뒤집기 효과를 재생하지 않는다.
- 타지 않은 철판 빵·쟁반 빵은 선택 후 쓰레기통 클릭 또는 기존 폐기 입력으로 버린다. 대상 선택 중에도 타이머·조리는 계속 흐른다.
- 철판은 `slot`과 현재 빵 수명, 쟁반은 `breadId`로 선택 대상을 고정한다. 선택 후 대상이 바뀌면 폐기를 취소한다.
- 대상이 없으면 안내만 표시한다. 폐기 입력 한 번이 여러 칸/빵을 처리하지 않게 한다.
- 논리 상태 변경과 애니메이션을 분리한다. 성공한 이벤트에만 이동·뚜껑·가벼운 피드백을 재생하고 중복 이벤트는 한 번만 보여준다.
- 폐기는 0점·콤보 초기화다. 탄 빵 폐기의 실패/폐기 지표는 BE와 같은 방식으로 계산한다.

## 8. FE-06 — 판별 시계·입력·복구 (새 판 2분)

### 시간과 UI

- 서버 `playStartsAt`·`playEndsAt`로 시계를 구성하고 모든 60000ms 고정 clamp·종료·예고 코드를 점검한다. `gameNow()`도 판별 duration을 읽게 한다.
- 새 판은 87초에 예고, 90초에 가속, 120초에 입력 종료. 기존 3분 판은 원래 스냅샷을 따른다. 카운트다운·정산 유예는 플레이 시간을 늘리지 않는다.
- 89.9초에 시작한 면은 구간별로 계산한다. 탭 복귀·도움말·납품 대기로 가속 경계를 다시 시작하지 않는다.
- 판별 종료 시각 후 들어온 과거 납품 응답은 결과 복구에 반영하되 새 손님·조리 입력을 활성화하지 않는다.
- 시간 표시는 해당 판의 서버 규칙을 따른다. 10개/손님 선택/소 투입 가열/탄 빵 폐기 안내는 유지하며 F1 종료 버튼은 추가하지 않는다.

### 납품과 checkpoint

- [설계안] 최초 구현에서는 납품 요청을 판당 한 번에 하나만 전송한다. 세 손님을 받는 것과 HTTP 납품을 병렬 처리하는 것은 구분한다.
- 납품 클릭 시 대상 `orderId`, `deliveryKey`, 로그 prefix를 고정한다. 재시도는 같은 키·같은 본문이다.
- v5 로그 정규화·prefix hash의 버전 seed를 BE와 맞추고 공통 해시 fixture를 검증한다. 기존 v4 seed나 직렬화를 무조건 재사용하지 않는다.
- 납품 대기 중에도 기존 조리·새 로그는 진행한다. 후속 로그는 별도 suffix로 유지하고 승인된 checkpoint 위에 재생한다.
- 승인 시 소비 재고·점수·전체 활성 주문·충원 결과를 하나의 revision으로 반영한다. 배열 하나만 부분 교체하지 않는다.
- 규칙 거절은 서버 checkpoint로 복구하고 아직 유효한 suffix만 재생한다. 충돌한 납품·없는 빵 폐기 등 재생 불가 입력은 임의 성공 처리하지 않는다.
- 통신 결과 불명은 같은 납품 영수증/세션 조회로 복구한다. 새 주문을 추첨하거나 다른 키로 재납품하지 않는다.
- 이전 revision·이전 판 응답으로 최신 세 주문을 덮어쓰지 않는다. 멱등 재생 응답이 과거 snapshot일 수 있으므로 필요하면 현재 세션을 다시 조회한다.

### 수명 정리

종료·포기·새 판·공원 복귀·언마운트에서 손님/빵/선택/불꽃/효과 큐/리스너를 정리한다. 공유 재질·geometry는 소유권에 맞게 해제하고 다른 공원 오브젝트에 영향을 주지 않는다. 기존 카메라 복귀와 아바타 페이드 동작을 유지한다.

## 9. 에셋·화면·성능 인수 조건

- 1280×720, 1440×900, 1920×1080에서 6칸·손님 3명·10개 쟁반·버너·쓰레기통을 확인한다. 태블릿 경로가 노출되는 경우 해당 레이아웃에서도 가림/클릭 회귀를 확인한다. 새 모바일 지원은 추가하지 않는다.
- 카트 근/원거리·낮/밤·최대 3손님·10개 빵·불꽃 6개를 모두 켠 장면과 비표시 장면을 측정한다.
- 드로우콜·삼각형·프레임시간 중앙값/p95·geometry/texture 메모리·전송량을 기존 v4와 같은 조건으로 비교한다. 기기/GPU·브라우저·해상도·품질·주변 인원을 기록한다.
- 공유 geometry/material·인스턴싱·LOD를 사용하고 정적 형상을 프레임마다 생성하지 않는다. 불꽃·좌표 갱신은 refs/프레임 루프를 사용하고 매 프레임 전체 React 상태를 갱신하지 않는다.
- 새 판 120초와 반복 진입/복귀 후 자원 잔류, 기존 180초 판 호환성을 확인한다. 근거 없이 FPS 보장이나 최적화 완료를 표기하지 않는다.
- 미니게임 외 공원의 카트 외형·컬링·충돌·접근 E 동작을 회귀 확인한다. 외곽이 기존 충돌을 벗어나면 월드 담당과 별도 조정한다.

### 실행과 BE 전환

frontend 폴더에서:

```powershell
pnpm dev:bungeoppang:v5
pnpm test:e2e:bungeoppang:v5
```

미리보기 모드는 개인 미니게임 발급·정산만 대역으로 실행한다. 공원 진입은 기존 로그인/월드 연결 환경을 사용하며, 자동 브라우저 테스트는 공원 계약 fixture를 사용한다.

**기본 개발/배포 서비스는 v4를 유지한다.** BE v5 계약 확정·배포 후 FE 빌드 설정 `VITE_BUNGEOPPANG_RULES_VERSION=v5`로 실제 서버 어댑터를 선택할 수 있다. BE가 v5를 지원하지 않으면 시작 오류를 표시한다. 이 설정은 BE 배포를 대신하지 않는다.

BE와 맞출 필드·해시 규격은 [BE 명세 §12](붕어빵_뒤집기_BE_작업명세_v5.md)에 정리했다. 특히 `heatAssignment=FILL`, `maxActiveOrders=3`, `activeOrders[].availableAfterSeq`를 확인한다. 제안 계약과 BE 최종 계약이 달라지면 어댑터·공통 fixture를 함께 갱신한다.

### 검증 범위와 남은 작업

FE 전체 단위 테스트 779개(신규 v5 33개), 테스트 포함 타입 검사와 프로덕션 빌드가 통과했다. 브라우저에서는 실제 180초 종료·마지막 30초 가속, 10개 보관, 실제 3D 클릭 폐기, 납품 후 다른 주문 유지와 빈자리 충원, F1 안내, 1280×720·1440×900·1920×1080을 확인했다. 기존 v4 브라우저 4개 시나리오도 통과했다. 세부 추가 검증은 실행 기록과 최종 인계 결과를 따른다.

Browser plugin not available: 기존 Playwright/Headless Edge/WebGL 2로 검증했다. 기존 큰 청크·Three.Clock·셰이더 정밀도 경고는 유지된다. 다른 GPU·브라우저·모바일 지원이나 실제 서버 지급 검증을 완료했다는 의미가 아니다.

추가 브라우저 검증: 밤·모션 감소에서 85/100/115% 불꽃 크기와 수치를 비교했고, 퇴장 시 개인 장면에서 추적한 geometry/material 전체의 dispose 이벤트를 확인했다. 인스턴싱 변경 후에도 실제 3D 빵 선택과 쓰레기통 클릭 폐기가 통과했다.

성능 참고 표본은 Windows/Headless Edge 156/WebGL 2/Intel Arc/Low/1920×1080/월드 fixture 4명/개인 손님 3명·재고 10개/밤, 90프레임이다. 장면 전체 드로우콜 중앙값 146, 삼각형 611,808, RAF 간격 중앙값 8.3ms/p95 9.5ms, 장면 geometry 버퍼 추정 약 42.6MB·texture 추정 약 121.5MB였다. 월드 전체와 넓어진 시점의 비용을 포함한다. 이전 v4와 시점·빛 조건이 같지 않아 이를 FPS 개선율이나 추가 기능만의 비용으로 해석하지 않는다. GPU 실행시간·다른 장비·장시간 부하는 별도 측정 대상이다.

**남은 BE 작업:** v5 규칙·세 주문·충원·저장·checkpoint·정산 구현, 공개 이용 상태의 120초 제한 조정, 실제 API/DB 배포. 이후 FE·BE 공통 fixture/해시·응답 유실·거절 복구·두 계정·실제 지급을 통합 검증한다. FE 미리보기 통과를 실제 v5 서버 연동 완료로 표시하지 않는다.

## 12. 레퍼런스 기반 시각 보강 — 2026-10-27

첨부 카트의 목재·붉은 천과 패널·금속 부속·진열장 구조를 기존 공원 스타일에 맞춰 반영했다. 화면 구성안에 남아 있는 60초/40초 규칙은 가져오지 않는다. v5의 180초/마지막 30초 가속을 유지한다.

- 카트: 붉은 패널, 목재 결, 모서리 철물·볼트, 말아 접은 금속 상판 모서리, 손잡이, 차양 봉제선과 구리색 조명. 기존 로컬 공원 재질·반사 맵을 재사용하며 추가 외부 에셋 요청은 없다.
- 철판/붕어빵: 공통 윤곽에 맞춘 오목한 주물 틀과 볼록한 빵, 눈·아가미·비늘·꼬리선, 경첩·체결부. 빵 양면 메시를 만들어 뒤집는 중에도 보인다. 반죽/앞면은 얇은 반죽 형상, 뒤집은 뒤는 입체 붕어빵 형상을 표시한다.
