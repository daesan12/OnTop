# 미니게임 v5 손님 런타임 적용

2026-10-28: 기존에 승인한 손님 6명 모두 사람형 뼈대와 대기·걷기 동작을 준비하고, 경량화한 실제 GLB를 미니게임 v5에 연결했습니다. 원본 생성물은 보존합니다.

## 게임에서의 동작

- 기존 단순 메시 대신 아이·대학생·귀마개 직장인·중년 손님·분홍 모자 아이·안경 쓴 여성이 등장합니다.
- 손님 3명의 표시와 선택, 주문 전달 후 퇴장, 빈 자리에 새 손님이 걸어와 대기하는 흐름을 연결했습니다. 공원 전체에 NPC를 생성하지 않고 플레이어의 조리 화면에만 표시합니다.
- 큰 주문 번호도 숫자 정밀도를 잃지 않고 외형을 선택합니다. 주문을 전달한 손님의 번호를 피드백에 보존해, 같은 자리에 새 손님이 들어와도 퇴장 중인 손님의 외형이 바뀌지 않습니다.
- 각 손님은 별도 뼈대·애니메이션 믹서를 사용합니다. 같은 외형은 한 방문 동안 형상과 텍스처를 공유하며, 교체·종료 시 재질·뼈대·텍스처·ImageBitmap을 해제합니다. 로딩 도중 나간 경우 늦은 응답도 해제합니다.
- 대기 자세를 평가한 뒤 원점과 높이를 보정해 리깅 전후의 위치 차이를 제거했습니다. 카메라와 주문표 위치를 맞춰 얼굴과 조리 칸을 함께 표시합니다. 아이의 카운터 높이와 분홍 모자 아이의 시선도 보정합니다.
- 모션 감소 설정에서는 이동과 반복 애니메이션을 생략하고 정적인 대기 자세를 표시합니다. 걷는 도중 설정을 켜도 즉시 대기 자세로 전환합니다.

## 모델과 경량화

파일: `frontend/public/art/bungeoppang/customers/runtime/<id>.glb`

| 손님 | 원본 동작 포함 bytes | 게임용 bytes | 게임용 triangles |
| --- | ---: | ---: | ---: |
| 활발한 아이 | 11,861,024 | 2,480,872 | 23,098 |
| 대학생 | 9,860,892 | 2,179,032 | 20,714 |
| 귀마개 직장인 | 11,024,228 | 2,253,000 | 19,999 |
| 중년 손님 | 11,041,104 | 2,201,384 | 20,246 |
| 분홍 모자 아이 | 13,003,360 | 2,490,928 | 22,590 |
| 안경 쓴 여성 | 8,683,088 | 1,907,728 | 20,000 |
| 합계 | 65,473,696 | 13,512,944 | 126,647 |

동작을 포함한 제공자 원본 대비 다운로드 용량 약 79.4% 감소입니다. 실제로 필요한 손님만 로드하며 6명 전체를 미리 다운로드하지 않습니다. 원본 GLB와 비교 자료는 별도 보존합니다.

- 65개 Mixamo 뼈대, `idle` 약 15.37초, 제자리 `walk` 약 2.37초, 반복·교차 전환
- meshoptimizer 형상 간소화: 목표 20,000 triangles, 상대 오차 상한 0.004. 관절·UV 경계 보존으로 일부 모델은 목표보다 조금 크며 모두 26,000 이하입니다.
- 남긴 정점의 위치·노멀·UV·관절·가중치 바이트 보존, Meshopt 압축 후 속성의 정확한 복원과 삼각형 winding/topology 확인
- PBR WebP: base color 2048, normal 1024, metallic/roughness 512. 데이터 맵은 lossless입니다.
- 별도 검사로 유한 좌표, 인덱스·관절 범위, 정규화 가중치, inverse bind matrix, 애니메이션 시간·대상 노드를 검증했습니다.

재현 명령은 frontend 디렉터리에서 실행합니다.

```powershell
node scripts/prepare-bungeoppang-customer.mjs <제공자-원본.glb> public/art/bungeoppang/customers/runtime/<id>.glb
node scripts/audit-bungeoppang-customers.mjs
```

개별 `.manifest.json`에 원본/결과 해시와 실제 수치가 있으며, 전체 검사는 `runtime-audit.json`에 기록합니다.

## 비용과 제작 기록

사용자 승인 상한 **295 credits**, 실제 청구 **295**, 최종 서버 확인 잔액 **255**, 동결 **0**입니다. 최초 모델 생성 비용 360 credits는 이전 단계 비용이며 이번 합계에 포함하지 않습니다.

| 단계 | 회수 | 단가 | 실제 청구 |
| --- | ---: | ---: | ---: |
| 최초 아이 v2.5 리깅 | 1 | 25 | 25 |
| v2.5 대기·걷기 실패 | 1 | 20 | 0 — 20 전액 환불 |
| 사람형 v3.0 리깅 | 6 | 25 | 150 |
| 대기 | 6 | 10 | 60 |
| 걷기 | 6 | 10 | 60 |
| 무료 rig-check | 각 작업 | 0 | 0 |
| 합계 | | | **295** |

설치된 스킬의 이전 v2.5 기본값으로 첫 작업을 시작했으나, 동작 요청은 제공자 오류 1004로 실패하고 환불됐습니다. 현행 공식 문서의 사람형 권장값 `v3.0-20260909`, `spec=mixamo`, `rig_type=biped`로 변경하고, 총 상한을 295로 올리는 별도 승인을 받은 뒤 6명을 다시 준비했습니다. 승인 이후 v3.0 작업 12개는 모두 성공했습니다. 승인하지 않은 유료 재시도나 모델 재생성은 없습니다.

모든 task ID·입력·청구·원본 기록 위치는 `billing.json`, 승인 계획은 `rig-animation-v3.plan.json`, 원본 모델과 제공자 task.json은 `v3/tripo-out/`에 있습니다.

참고: [공식 리깅 문서](https://developers.tripo3d.ai/en/docs/animations-rig), [동작 문서](https://developers.tripo3d.ai/en/docs/animations-retarget).

## 확인 방법과 적용 범위

- 6명 동작 미리보기: `http://127.0.0.1:5216/tests/bungeoppang-v5-e2e/customer-preview.html` — 손님 선택 후 대기/걷기 버튼 사용
- 기존 원본 비교: 같은 URL에 `?source=1&customer=<id>` 지정
- 실제 미니게임: frontend에서 `pnpm dev:bungeoppang:v5` 실행 후 공원에서 붕어빵 카트 이용
- 기존 v4 기본 설정은 유지됩니다. 운영에서 v5를 활성화하려면 기존 BE v5 계약 배포가 선행되어야 합니다. 이번 작업은 FE 에셋과 표시를 변경하며 BE 통신 규약을 변경하지 않습니다.

## 검증 결과

- 순수 규칙·세션·어댑터·서비스·큰 주문 번호·모델 풀 단위 테스트 36개 통과
- 실제 입력을 사용한 10개 보관, 선택 주문 전달, 쓰레기통, 도움말, 종료 흐름 통과
- 손님 6개 로딩, 뼈대 65개, 실제 포즈 변화, 걷기→대기, 클릭 선택, 종료 자원 해제 통과
- 개별 모델 6개의 대기/걷기 포즈 변화, 반복 교체 후 GPU 자원 수 유지, 390×844 미리보기 가로 넘침 없음, 앱 콘솔 오류 0
- 야간 불 세기·모션 감소 설정·종료 자원 해제 통과
- 960×540, 1280×720, 1920×1080 화면의 주문표/조리 칸 겹침 및 조작부 배치 검사 통과
- 테스트 포함 타입 검사, migration boundary 검사, 프로덕션 빌드 통과

로컬 Edge/Intel Arc, 4명 공원 fixture, 1920×1080, low 품질에서 측정한 전체 장면 프레임 간격은 median 9.3ms / p95 14.4ms였습니다. GPU 시간과 저사양 모바일 성능은 측정하지 않았으므로 보편적 성능 보장을 의미하지 않습니다. 기존 셰이더 precision 경고와 큰 청크 경고는 남아 있으나 앱 콘솔 오류는 없었습니다. 브라우저 플러그인이 없어 기존 Playwright + Edge 검증을 사용했습니다.

실제 운영 BE의 v5 응답·보상 연동은 이번 로컬 fixture 검증에 포함되지 않습니다.
