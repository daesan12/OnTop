# 붕어빵 v5 FE 작업 완료 내용과 BE 연동 요청

> 2026-10-28 변경: 사용자 요청으로 가열 시작을 소 투입(FILL)으로 되돌렸습니다. 반죽만 있는 동안은 불·익힘·불 cursor가 진행되지 않습니다. BE 담당자에게는 사용자가 별도 전달했으며, BE 완료 후 최종 응답/fixture를 대조합니다. 이번 구현은 FE 변경입니다.

확인일: 2026-10-28 · 최신 dev `165c155` 기반 FE 전용 브랜치 `feat/bungeoppang-v5-fe-polish`. BE 코드·테스트·DB는 변경하지 않았습니다. 담당자의 별도 작업 브랜치나 실제 개발 서버의 v5 배포 여부를 확인한 문서는 아닙니다. FE MR 머지 후 최신 dev를 받아 별도 BE 브랜치에서 진행해 주세요.

**이번 랜덤 대사·구름 주문표·순차 입장·야간 조명에는 새 BE 기능이 필요하지 않습니다.** 아래는 앞서 전달한 v5 작업의 연동 확인 목록입니다. 이미 작업 중이거나 완료한 항목은 중복 작업 없이 최종 계약·응답 예시·배포 결과만 공유해 주세요. 소 투입 후 가열 변경은 이미 별도로 전달했으며 BE 작업 완료 후 함께 대조할 항목입니다.

## 이번 손님 모델 작업에서 새로 필요한 BE 기능

**손님 6명의 3D 모델·경량화·대기/걷기·입장/퇴장 자체에는 새 API나 DB 컬럼이 필요하지 않습니다.** 손님은 게임 이용자에게만 보이는 FE 전용 연출입니다. 다른 사용자에게 손님 모델이나 좌표를 방송할 필요도 없습니다.

FE는 기존 v5 제안 응답의 `orderId`로 외형을 고르고 `customerSlot`으로 자리를 정합니다. 납품한 주문 번호를 FE 피드백에 보존해, 새 주문이 같은 자리에 들어와도 퇴장하는 손님이 바뀌지 않게 했습니다. `guestOrderId`는 FE 표시용 필드이며 서버 요청 DTO가 아닙니다.

## FE에서 완료한 내용

- 카트·조리 화면·손님·화력·쓰레기통 표시와 2.5D UI 개선
- Q/W/E/A/S/D 조리 조작 유지, 소 투입부터 가열, 쟁반 10개, 주문 3건 선택, 탄 빵 즉시 폐기
- 180초 진행과 마지막 30초 가속을 위한 FE 규칙·화면·제안 REST 어댑터
- 손님 6명 리깅·애니메이션·경량화·게임 연결, 클릭·입퇴장·자원 해제 검증
- 로컬 v5 미리보기와 공통 규칙 fixture/테스트
- 구름 말풍선: 등장하며 인사 → 실제 주문을 말함 → 맛별 이미지·수량 요약으로 전환. 복합 주문도 모든 맛의 이미지를 표시
- 캐릭터별 인사 6개·주문 표현 6개, 총 72개 대사. 방문마다 선택하고 직전 대사 반복 방지. 주문 종류·수량은 서버 승인값을 그대로 사용
- 첫 손님 1명부터 순차 입장, 평소 약 6초 간격. 교체 손님은 최소 2.5초 기다린 뒤 다음 차례에 입장하며 마지막 30초에는 약 0.7초 간격으로 빈자리 충원
- 손님 등장 전/빈자리의 말풍선 제거, 인사 중·대기 중인 손님 선택/납품 제한, 야간 조리 조명과 맛별 보관함 이미지

로컬 테스트는 실제 FE 게임 코드를 실행하지만 보상을 지급하지 않습니다. 서버 v5 배포 전에는 기본 v4 설정을 유지합니다.

최근 대사 작업은 관련 단위 검사 21개, 타입 검사·빌드·경계 검사와 브라우저 대사/재방문/순차 입장 검증을 통과했습니다. 이는 실제 v5 API·DB·지갑 지급의 통합 검증을 완료했다는 의미는 아닙니다.

## BE 담당자에게 계속 요청할 내용

이번 UI·손님 연출로 추가된 서버 요청이 아니라, **앞서 작성한 v5 밸런스/주문 계약의 구현 또는 완료 여부 확인 항목**입니다. 로컬 `BungeoppangV4Spec`은 60초·쟁반 4개이며, `MinigameService`는 최근 발급 주문 하나만 납품 대상으로 허용하는 경로를 확인했습니다. 별도 브랜치에서 완료했다면 결과를 공유해 주세요.

1. **v5 판 시작과 규칙 스냅샷**: 180000ms, 150000ms부터 가속, 쟁반 10개, 활성 주문 최대 3건. 기존 v4 판은 기존 규칙대로 처리해 주세요.
2. **소 투입부터 가열**: 반죽만 있을 때는 가열하지 않습니다. FILL에서 불 값을 소비하고 앞면 시작 시각을 저장합니다. 탄 빵의 FILL/TURN은 거절하고 DISCARD로 제거합니다.
3. **주문 3건·선택 납품·충원**: 서로 다른 `orderId`와 0..2 `customerSlot`을 제공합니다. 승인된 주문만 완료하고 빈 자리에 최대 한 건 충원하며, 나머지 두 주문 ID와 자리는 보존해 주세요.
4. **검증·멱등·복구**: 납품의 재고 소비·점수·완료·충원을 같은 트랜잭션으로 처리합니다. checkpoint에 전체 `activeOrders`, revision, 승인 prefix와 발급 순서(`availableAfterSeq` 제안)를 담고 재시도에서 중복 충원/지급하지 않도록 해주세요. BIGINT 주문 ID는 십진수 문자열로 보내주세요.
5. **180초에 맞춘 제한과 이용 상태**: heats/log/body/deadline 한도를 함께 확인해 주세요. 최신 dev에는 해당 이용 상태 BE 기능이 없으며, 이전 참고 구현의 120초 상한도 이번 MR에 가져오지 않았습니다. v5 구현 시 서버가 발급한 `playEndsAt`까지 유지하고 완료·포기·만료 시 해제와 커밋 후 방송을 처리해 주세요.

상세 규칙, DTO, 시간 계산, 오류·트랜잭션·테스트 조건은 [BE 작업명세 v5](붕어빵_뒤집기_BE_작업명세_v5.md)를 기준으로 합의하면 됩니다. 이용 상태 관련 기존 작업은 [말풍선 BE 전달 문서](../bungeoppang-activity-be-handoff.md)에 있습니다.

## 서버 주문 발급과 화면 입장은 구분해 주세요

**서버가 활성 주문 3건을 발급하는 것과 화면에 손님 3명이 동시에 등장하는 것은 다릅니다.**

현재 제안대로 시작 시 최대 3건의 활성 주문을 내려주면 FE가 한 명씩 입장시킵니다. 납품 응답에서 같은 자리에 교체 주문을 바로 발급해도 FE는 평소 입장 간격에 맞춰 기다렸다가 표시합니다. 마지막 30초에는 그 대기 간격을 줄입니다.

따라서 이번 연출을 위해 **BE가 6초/0.7초 타이머나 NPC 입장 이벤트를 추가할 필요는 없습니다.** FE는 승인된 활성 주문만 표시하며 서버가 아직 발급하지 않은 손님은 생성하지 않습니다. 주문 발급은 납품 트랜잭션에서 처리하고 애니메이션 완료나 GET 조회를 재발급 조건으로 사용하지 않습니다.

이 간격은 FE 연출·입력 제한입니다. 서버가 입장 시각 자체를 검증하는 규칙을 도입하려면 별도 계약 합의가 필요하며 이번 요청에는 포함하지 않습니다. 개인 손님·대사·주문·재고·불을 월드 WebSocket으로 방송할 필요도 없습니다.

## 함께 확정하고 싶은 사항

- v5 OpenAPI와 start/GET/delivery/complete/abandon 응답·오류 예시
- 세 주문의 초기 발급/충원 필드와 공통 replay·prefix hash fixture
- 최종 `rulesVersion`·`configVersion`, `heatAssignment=FILL`, 전체 `checkpoint.activeOrders[]`·revision·승인 로그. 발급 인과관계 필드는 FE 제안 `availableAfterSeq`와 맞추거나 다른 표현으로 합의
- 구현/진행/미착수 상태, 작업 브랜치 또는 MR, DB migration·멱등 처리 검증 결과
- 개발 서버 v5 배포 시점과 실제 지급 없는 FE/BE 통합 테스트 일정

계약 확정과 BE 배포 후 FE의 `VITE_BUNGEOPPANG_RULES_VERSION=v5`를 활성화하고 시작·납품·복구·종료를 통합 검증하겠습니다.

BE 완료 후 FE에서는 반죽만 있을 때 미가열, 소 투입 후 가열, 3분·마지막 30초 가속, 10개 보관, 선택 납품·충원, 통신 복구·포기·완료를 실제 개발 서버에서 확인합니다. 두 계정으로 공개 이용 상태를 확인하고 실제 DB의 중복 소비·충원·지급 여부는 BE와 함께 검증합니다.

## 전달할 짧은 글

붕어빵 FE 추가 작업을 마무리해서 최신 요청 문서를 공유드립니다.

손님 6종의 3D 모델과 입퇴장, 구름 주문표, 캐릭터별 랜덤 대사, 야간 조명을 적용했습니다. 처음에는 한 명부터 차례로 들어오고, 마지막 30초에는 빈자리가 빠르게 채워지도록 했습니다. 이 부분은 FE 연출이라 새 API나 NPC/대사 저장 기능은 필요하지 않습니다.

BE에서는 앞서 전달드린 v5 작업을 기준으로 아래 내용의 구현 또는 완료 여부 확인 부탁드립니다.

1. 3분 플레이·마지막 30초 가속·보관함 10개·활성 주문 최대 3건
2. 반죽만 있을 때는 가열하지 않고 소를 올린 뒤부터 가열하는 방식. 이전에 별도로 전달드린 변경 사항입니다.
3. 선택한 주문만 납품하고 그 자리에 새 주문을 충원하며 나머지 주문은 유지하는 처리
4. 재시도·재접속 때 재고/주문/보상이 중복 처리되지 않는 복구·정산
5. 다른 이용자에게 보이는 게임 이용 상태가 3분 플레이 도중 사라지지 않도록 유지 시간 확인

서버에서 활성 주문을 3건 내려주셔도 화면에서는 FE가 한 명씩 입장시키므로, 손님 입장 간격용 서버 타이머는 추가하지 않으셔도 됩니다.

이미 구현하신 항목은 중복 작업 없이 완료 여부만 알려주시면 됩니다. 최종 API 응답 예시와 개발 서버 배포 일정을 공유해 주시면 FE에서 실제 연동과 소 투입 가열 동작까지 함께 확인하겠습니다. 감사합니다!
