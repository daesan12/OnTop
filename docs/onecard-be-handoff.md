# 원카드 QA 반영 BE 확인·배포 요청

작성: 2026-10-29 KST. 상세 계약은 [원카드 BE 명세](onecard-ux-be-spec.md), 공통 경기 채팅은 [WebSocket 문서](websocket-api/10-game-spectator-events.md)를 참고한다.

## 이번 변경에 포함된 구현

| 항목 | 서버 동작 | FE 연동 |
| --- | --- | --- |
| 실제 손에 든 카드 한 장 지정 | REACH 요청의 `cardIndex`/`handVersion`을 쌍으로 검사. 공개 장수 범위·현재 버전 검증, 지정 효과는 `count=1` | 관전자가 실제 3D 카드 뒷면을 직접 선택. 비공개 카드 ID를 전송하지 않음 |
| 방어 접근 시간 | `resolveAt = serverNow + 3200ms`. 마감 전에 승인된 HIT와 마감 뒤집힘 중 하나만 확정 | 손이 천천히 다가오며 우클릭으로 망치를 들어 방어 |
| 오래된 대상 취소 | 같은 차례라도 대기 중 손패 버전이 바뀌면 CANCELLED | 옆 카드로 대체하지 않음. 선택·제출 중인 카드 보호 |
| 경기 전용 채팅 | 오목·원카드·주사위·라이어 브리지의 참가자와 승인 관전자만 전송/수신. 경기 중 WORLD 채팅 요청 거절 | 경기 전용 입력과 이력 사용, 관전/경기 해제 시 정리 |

BE 구현은 `OneCardPranks`, `TableProtocol`, `TableHub` 및 관련 테스트에 포함되어 있다. 아래 요청은 이미 포함한 동작의 계약 확인과 배포 설정·실계정 공동 검수에 관한 것이다.

## BE 담당자 확인 요청

1. `cardIndex`는 0 기반 공개 위치, `handVersion`은 화면의 `GAME_STATE.version`으로 사용한다. `cardIndex`/`handVersion` 중 하나만 있거나 범위/버전이 틀린 요청을 거절하고 횟수를 소비하지 않는지 확인해 주세요.
2. 방어 마감 3.2초를 적용하고, 중복 REACH 재확인이 최초 마감을 연장하지 않는지 확인해 주세요. 방어 성공 후 해당 관전자→대상만 3초 차단, 복구 후 대상 2.5초 면역은 유지합니다.
3. 공개 이벤트에 실제 카드 ID·무늬·숫자·비공개 손패가 섞이지 않는지 확인해 주세요. 대기 중 버전 변경·턴 전환·기권·관전 종료·접속 종료 시 취소 동작도 확인 부탁드립니다.
4. 네 게임의 경기 전용 채팅이 같은 경기에 있는 참가자/승인 관전자에게만 도착하고, 공원 채팅으로 우회되지 않는지 확인해 주세요.
5. 운영 환경에서 원카드 장난을 사용할 경우 아래 FE/BE 설정을 함께 적용하고 공동 배포해 주세요. 이 작업 자체는 운영 설정 변경이나 배포를 수행하지 않습니다.

| 구분 | 설정 |
| --- | --- |
| BE | 기존 원카드 활성화 + `ontop.games.onecard.pranks-enabled=true`, `ontop.games.onecard.defense-enabled=true` |
| FE | 최신 dev 기본 활성화 정책 유지. `VITE_ONECARD_PRANKS`/`VITE_ONECARD_PRANK_DEFENSE`를 false로 지정하지 않음(명시적 true도 가능) |

FE는 즉시 뒤집기 API로 대체하지 않습니다. BE 미지원/미설정이면 장난을 중지합니다. 기존 서버의 1.4초 응답을 FE가 임의로 3.2초로 늘리지 않으므로 시간 개선은 BE 반영이 필요합니다.

공동 검수: 참가자 4명과 관전자 2명 이상으로 실제 카드 한 장 선택 → 3.2초 접근 중 방어 → 방어하지 않은 시도의 한 장 뒤집기 → 한 번에 복구 → 면역/턴 제한, 네 게임의 채팅 격리·Esc 관전 종료를 확인해 주세요. 현재 자동 검증은 로컬 모의 서버와 BE 테스트를 사용하며 운영 다중 계정 검수를 대신하지 않습니다.

## 전달용 요청 글

안녕하세요. 원카드 추가 QA에 맞춘 BE 연동 확인과 공동 배포를 요청드립니다.

이번 변경에는 관전자 카드 한 장 지정(`cardIndex`, `handVersion`), 3.2초 방어 접근, 대기 중 버전 변경 취소, 네 게임의 경기 전용 채팅 격리가 포함되어 있습니다. BE 구현과 테스트도 변경에 포함했으니, 상세 명세를 기준으로 계약과 개인정보 노출 여부를 검토 부탁드립니다.

특히 FE는 즉시 뒤집기로 대체하지 않으므로 장난 기능을 사용할 환경에서는 BE 장난/방어 설정과 FE 플래그를 함께 활성화해야 합니다. 운영 설정 반영과 FE·BE 공동 배포 후, 4인 경기 및 복수 관전자로 카드 지정·망치 방어·복구 면역·경기 채팅 격리를 함께 확인 부탁드립니다.
