## Java 연결

`PreparedParkMap`은 기존 형상 외에 furniturePolicy/fountainPolicy/pavilionJumpSpeed/pavilionTunedJumpSpeed와 pavilions를 런타임 입력에 연결한다. `ParkMovementPolicy`는 정책 종류·숫자·높이·분수 hull 일치를 검사한다. 정책 없는 기존 맵은 기존 동작을 유지한다.

- 가구는 활성 table-N-top/table-N-chair-[0-3]의 로컬 XZ 좌표에서 반경을 한 번 더해 차단한다. 비활성 의자는 제외하며 회전은 기존 yaw를 사용한다.
- 분수는 반경6.588m·하단-1.1·상단2.5 원형 영역이다. 중심은 +Z로 내보낸다.
- 가구·분수의 상단/잔여 모서리를 지지면·안전 위치로 채택하지 않는다. 높은 곳에서 떨어지거나 내부에서 복구돼도 낙하를 계속한다. 승인된 착석/시설 hold 자세는 보정 대상에서 제외한다.
- Native 이동은 물리 갱신 뒤 보정하며, C 이동은 이미 승인된 서버 위치·관측 하강속도의 최대100ms 낙하 전망으로 필요한 수평 보정을 선행한다. 후보 좌표를 크게 보내는 예외를 만들지 않는다.
- 보정 목적지의 월드 경계·캡슐 여유와 다른 장애물의 경로를 검사한다. 막히면 기존 검증된 안전 위치로 복구한다. 검증 위치의 보정은 기존 motion.epoch를 새로 발급하며 과거 epoch 보고는 무시한다. 안전한 낙하 과정에서는 C를 영구 비활성화하지 않는다.
- 팔각정 바닥에서만 PARK_V1 jumpSpeed8.6, 일반 경로7.8을 사용한다. 일반 지면8/기존6.2·기존 중력·유한 높이 난간은 유지한다. 승인 보고의 상승속도와 native 인계도 발사 위치 정책을 따른다.

새 REST/WS 메시지나 클라이언트 보정 권한은 추가하지 않는다. WORLD_MAP_CONFIRM 불일치 차단과 기존 WORLD_STATE/motion.epoch 계약을 사용한다. 기존 점프맵 코스 파일·프로토콜·보상·DB는 변경하지 않는다. 점프맵 신규 서버 기능의 구현 완료를 뜻하지 않는다.
