## 문제와 변경

주변 테이블 상호작용은 HTTP 목록의 `joinable`에 따라 착석 또는 테이블 조회 중 하나만 제공했다. 정자 테이블에는 별도 벤치 관전 진입이 있지만 돌 테이블은 이 경로에 의존한다. 목록이 아직 대기 상태를 가리키면 착석만 안내되어 현재 진행 경기의 관전 정보에 접근하기 어려웠다.

`ParkInteractionHint.tsx`에 **테이블 정보 · 관전** 진입 버튼을 추가했다. 현재 착석 안내가 표시되는 주변 테이블에서 사용할 수 있고, 진행/만석 테이블은 기존 **테이블 경기 보기** 진입을 유지한다. 새 버튼은 직접 앉거나 경기 ID를 추측하지 않고 기존 `runtime.inspectTable`을 호출한다. 기존 E/클릭 착석은 유지한다. 안내 갱신 비교에 `label`도 포함하여 같은 테이블의 상태가 바뀌면 문구가 갱신된다.

공통 연결 순서는 다음과 같다.

1. 테이블 근처에서 **테이블 정보 · 관전** 또는 **테이블 경기 보기** 선택.
2. 기존 `TABLE_WATCH` 승인으로 현재 공개 테이블과 gameId 확인.
3. **경기 관전** 선택 후 기존 `GAME_WATCH` 승인으로 공개 게임 화면 진입.
4. 기존 경기 채팅·게임별 관전 상호작용 사용.
5. **관전 종료** 또는 Esc로 기존 구독 해제 및 공원 복귀.

관전 거절 시 로컬에서 관전을 허용하지 않으며, 공개 경기 ID가 없으면 **경기 관전**은 비활성이다. 서버가 승인한 공개 상태만 사용하는 기존 권한 검사는 변경하지 않았다.

공통 변경 파일은 `frontend/src/features/interactions/ParkInteractionHint.tsx`와 `interactions.css` 두 개다. CSS는 900px 이하에서 테이블 안내만 채팅 위로 올려 새 버튼이 가려지지 않도록 한다. 새로운 gameCode·경기 프로토콜·BE·DB·Flyway 변경은 없다. V133을 포함한 migration 번호를 사용하거나 예약하지 않았다.

## 독립 검증과 실행

`frontend`에서:

```powershell
node node_modules/vite/bin/vite.js --mode park-integration --host 127.0.0.1 --port 5227 --strictPort
node node_modules/@playwright/test/cli.js test --config playwright.stone-spectating.config.ts
```

개발 주소는 `http://127.0.0.1:5227/park`이며 정상 실행은 실제 로그인·서버가 필요하다. Playwright 명령은 서버를 직접 시작하고 종료 시 정리한다. 동일 lockfile의 기존 의존성을 junction으로 공유했다.
