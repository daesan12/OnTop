## 1. 채널 물리 스텝과 발판 준비 비용

지적을 확인했다. 기존 구현은 코스 진입 여부와 관계없이 서버 제어 액터마다 전체 `PhysicsSpace.update`를
실행했다. `prepare`도 178개 충돌체를 돌며 native 위치를 읽었다.

- 코스 미진입자들은 한 스텝을 공유한다. 진입자도 실제 충돌 상태가 같으면 같은 스텝을 공유한다.
  판 ID만 다른 동일한 상태는 분리하지 않는다. 캐릭터끼리의 충돌 마스크는 기존처럼 비활성이다.
- 연잎 소멸이나 두더지 높이가 다른 개인 상태는 여전히 격리한다. 각 캐릭터는 자기 상태의 그룹에서
  정확히 한 번 진행된다. 한 채널 틱 안에서는 공통 모션 시각도 동일하게 고정한다.
- 시작/종료로 발판 전체의 활성 여부가 바뀔 때만 전체 목록을 확인한다. 그 외에는 개인 접촉에 의해
  달라진 발판과 공통 비둘기 모션만 갱신한다. 이미 적용한 높이를 캐시해 native 위치 읽기를 제거하고,
  같은 상태·시각의 반복 prepare는 즉시 반환한다.
- 서버 이동에서 기하 쿼리가 필요하지 않은 루프는 불필요한 사용자별 prepare를 하지 않는다.
  복구·위치 검증에는 해당 사용자의 충돌 상태를 먼저 적용한다.

## 2. 첫 도전 플래그 타입

`Boolean.TRUE.equals`가 JDBC 숫자 `1`을 거짓으로 처리하는 문제를 확인했다.
Boolean 및 Number의 정확한 0/1을 명시적으로 읽고, 다른 값은 데이터 오류로 거절한다.
중복 시작 키는 이번 호출에서 계산한 값이 아니라 기존 행의 첫 판 플래그를 계속 반환한다.

실제 MySQL 8.4에서 `tinyInt1isBit=true`의 Boolean과 `false`의 Number 반환을 직접 확인한다.
각 옵션에서 첫 판=true, 같은 키 재시도=true, 다음 판=false를 검사한다.
기존 회원·지갑·게임 데이터 보존을 위해 검증용 MySQL 컨테이너에 새 전용 schema를 만들었으며,
기존 로컬 서비스 schema나 dev DB는 변경하지 않았다.

## 3. 잘못된 외부 코스 폴백

저장소의 레거시 코스 폴백은 제거했다. 설정한 코스 파일이 없거나 checksum이 다르면 원인 예외를 보존한
`IllegalStateException`으로 저장소·애플리케이션 컨텍스트 기동을 실패시킨다. 정상 기본 레거시 코스와
정상 새 공원 코스는 각각 유지한다.

원래도 `JumpmapActivation`이 설정 코스를 별도로 다시 읽어 오류 시 `INVALID_COURSE`로 끄므로,
정상 bean 경로에서 잘못된 7단계 코스가 곧바로 활성화되는 것은 아니었다.
이번 수정은 저장소와 활성화 계층의 코스 선택을 달리하는 폴백을 없애고 기동 단계에서 오류를 드러낸다.
V167은 허용 단계 CHECK를 확장하는 migration이며, 적용 사실만으로 메모리 코스가 선택되지는 않는다.
