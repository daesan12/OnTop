# 💬 백엔드 연동 전 팀 협의 목록

2026-10-22 기준. 확정된 사용자 결정과 남은 팀 협의를 구분합니다.

## 게임 정책

| 결정할 것 | 선택지 | 현재 처리 |
| --- | --- | --- |
| 원카드에서 기권한 사람의 남은 카드 | ① 이번 경기에서 제외 ② 뽑기 덱에 돌려 넣고 섞기 | 두 방식 모두 구현·검증. 기본값 없이 서버 설정 필수. 팀 결정 전 확정하지 않음 |
| 상점 의상 중복 구매 | ① 이미 보유하면 거절(REJECT) ② 수량 합산(STACK) | 두 방식 구현·검증. 기본값 없음. 미설정 의상 구매만 차감 전에 SHOP_POLICY_REQUIRED. 시연 REJECT는 팀 확정이 아님 |

## 실제 연동에 필요한 합의·자료

| 확인할 것 | 필요한 답 |
| --- | --- |
| 로그인과 WebSocket 인증 | 2026-10-21 사용자 승인: Access JWT → 30초1회용 접속권 → 연결. [확정 계약](websocket-authentication.md). 로그아웃·만료 시 열린 소켓 강제종료와 다중 서버 공유는 별도 |
| 참가·차감 확정 후 게임 시작 | [A 연결부](committed-game-start.md) 구현: 기존 GameStartGateway의 확정 경기 ID·테이블·게임·좌석 매핑, 같은 시도 재조회. 실제 DB Gateway와 커밋/영속 멱등성 통합 확인 |
| 주사위 시작 목표 전달 | 2026-10-22 사용자 확정: 첫 착석자가 GAME_SELECT의 targetScore로 2,000/4,000/6,000 중 선택. 목표 변경 시 전원 준비 해제, 시작 시 같은 옵션 고정 |
| 경기 종료 후 정산·다음 판 | 2026-10-22 사용자 확정: 종료 시 좌석 유지·전원 준비 해제 → SETTLING → 경기 전체 SETTLED 확인 후 WAITING → 다시 전원 준비해 새 경기 시작. 실제 DB 커밋 결과 통합 검증은 별도 |
| 실제 맵 테이블 배치 | tableId별 중심 X/Z 좌표. 채팅·관전 반경은 이미20m로 결정됨 |
| 상점과 공통 재화 처리 | [구매 계약](shop-inventory.md)의 같은 DB·지갑 잠금·예약금 의미·SHOP_PURCHASE 원장·최종 DDL 대조. V100은 선택적 위치이며 기존 DB에 자동 적용하지 않음 |
| 장착 후 3D 외형 반영 | image_key의 프론트 에셋 매핑과 WS 외형 필드 계약. 저장/본인 조회/내부 커밋 알림은 구현하며 신규 WS 형식은 임의 확정하지 않음 |

게임 시작·정산 연결의 기존 초안은 [시작 연동 계약](game-start-contract-draft.md)을 참고합니다. 새 메시지나 인증 방식을 이 목록에서 확정하지 않습니다.

이미 결정된 내용: 오목은 한 수30초 초과 시 시간패·총시간 제한 없음. 나머지 게임은30초 후 차례 넘김. 다리의 굴림/선언/각 판단은30초이며, 원카드 선언/신고의 별도3초 반응창은 차례 제한과 구분합니다.

결과2종(`GAME_RESULT_CHECK`, `GAME_RESULT`)의 실제 연결에는 정산 저장 담당의 `GameResultGateway`가 필요합니다. 확정 경기 ID·참가자별 결과/금액·종료 이유·PENDING/SETTLED 상태·단조 증가 버전의 매핑, 커밋 성공 뒤 `GameResultCommitted` 발행 시점을 함께 확인합니다. 현재 통신부·대역 검증은 완료지만 임의 금액이나 가짜 정산 완료를 만들지 않습니다.
