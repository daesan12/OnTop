# 💬 백엔드 연동 전 팀 협의 목록

## WebSocket 유입 제한 · 2026-10-29

기존 인증 코드를 감싸는 공통 제한기를 로컬 구현한다. 신규 DB/프록시 설정 변경 없음.
아래는 **미확정 협의 항목**이며 로컬 기본값을 운영 승인·수용량 실측으로 취급하지 않는다.

- 운영 메시지 rate/burst·JVM 전체/주소별 동시 연결 수: 로컬 기본120/s·240·200·100의 적정성.
- 인프라: X-Real-IP 덮어쓰기·직접 접속 차단·신뢰할 peer CIDR, 공유 NAT 사용자 한도.
- FE: 1013 종료 표시·재시도 간격/최대 backoff. 액션ID·멱등키·30초 유예/턴 마감 유지.
- 인프라/인증: Upgrade 전 연결·접속권 발급·재접속 폭주 제한, 다중 JVM 한도, ticket 로그 마스킹.
  현재는 Upgrade 후 추가 인증 재검사/Hub 등록·완성 텍스트 파싱 전의 단일 JVM 경계다.
- 제한만으로 계정 제재·즉시 기권을 추가하지 않는다. 변경 시 별도 합의한다.

상세 설정·종료 코드·검증 경계: [공통 유입 제한](websocket-ingress-limits.md).

## 경기 종료·이탈 연동 · 2026-10-23

- 2026-10-25 수동 기권: GAME_FORFEIT → GAME_FORFEIT_RESULT, 공통 이탈 사유 EXPLICIT_LEAVE. DB 담당은 기존 이탈·최종 종료 이벤트 경로만 소비한다. 새 스키마 없음.
- FE 확인 필요: 되돌림 없는 기권 버튼의 확인창·문구, 기권 후 화면을 결과/관전 중 어디로 전환할지. 현재 API는 소켓/채널과 기존 좌석 유지·전체 정산 후 대기 정책을 보존한다. 이 항목의 최종 UI 동작은 임의 확정하지 않았다.

- 게임 담당 구현: 공통 GameParticipantLeft/GameFinished, 모든 최초 참가자의 결과·이탈 사유·시각. 기존 게임별 이벤트/프론트 JSON 유지. DB 담당은 한 경로만 구독하고 eventId로 중복을 막는다. 실제 예약·정산 트랜잭션은 DB 담당 유지.
- 인증 담당 구현: Revoked.reason=LOGOUT만 ConnectionCloseReason.LOGOUT으로 전달. MEMBER_DEACTIVATED는 기존 회원 전체 전달 경로 재사용. REFRESH_REUSE_DETECTED/SESSION_REVOKED는 AUTH_SESSION_REVOKED로 유지하며 일괄 즉시 기권으로 분류하지 않는다. 게임 코드 변경 없이 기존 분기를 재사용하며 오프라인 유예/최초 원인 경합 제한은 session-invalidation.md에 기록한다.
- DB 담당 확인: 이벤트 LOGOUT/MEMBER_DEACTIVATED와 ERD의 EXPLICIT_LEAVE 매핑, 최초 참가자 전체 저장, 중도 탈락 시 예약금 유지 후 경기 최종 정산. 세부 계약은 game-result-api.md/game-reconnect.md.
