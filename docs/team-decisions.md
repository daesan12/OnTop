# 💬 백엔드 연동 전 팀 협의 목록

## 시설 점유 · 2026-10-25

- 구현 계약: [시설 WebSocket](world-facility-api.md). 현재 FE 배치 ID와 서버 맵 충돌체 94개를 대조했다.
- 2026-10-25 사용자 확정: 벤치·운동기구 3m / 망원경 2m, 기준 높이 +0.8m·오차 ±0.7m.
  채팅/관전20m와 별개다. 망원경 100ms·pitch[-1.35,1.15]는 현재 FE 설정에 따른 구현값이다.
- 2026-10-25 사용자 확정: 단절·인증 종료·채널 퇴장 즉시 점유 해제, 재접속 시 CHECK 후 재이용.
  시설 점유는 30초 보존하지 않으며 기존 경기 유예는 유지한다.
- FE 후속: 목업 포트를 USE/RELEASE/AIM/CHECK로 교체, 입장/재접속 CHECK 필수,
  mapVersion 대조와 leaseId·요청/연결 수명 확인, 승인 WORLD_STATE 위치·공통 startedAt 반영.
- 시설 중 감정표현 허용/취소는 미확정, 임의 추가 제한 없음. 확대/FOV는 FE 유지.
- 서버 단일 JVM 점유. 같은 채널을 여러 인스턴스로 나누려면 점유 공유·라우팅 정책 합의 필요.

2026-10-22 기준. 확정된 사용자 결정과 남은 팀 협의를 구분합니다.

## 실제 연동에 필요한 합의·자료

| 확인할 것 | 필요한 답 |

| 로그인과 WebSocket 인증 | 2026-10-21 사용자 승인: Access JWT → 30초1회용 접속권 → 연결. [확정 계약](websocket-authentication.md). 로그아웃·만료 시 열린 소켓 강제종료와 다중 서버 공유는 별도 |
| 참가·차감 확정 후 게임 시작 | [A 연결부](committed-game-start.md) 구현: 기존 GameStartGateway의 확정 경기 ID·테이블·게임·좌석 매핑, 같은 시도 재조회. 실제 DB Gateway와 커밋/영속 멱등성 통합 확인 |
| 주사위 시작 목표 전달 | 2026-10-22 사용자 확정: 첫 착석자가 GAME_SELECT의 targetScore로 2,000/4,000/6,000 중 선택. 목표 변경 시 전원 준비 해제, 시작 시 같은 옵션 고정 |
| 경기 종료 후 정산·다음 판 | 2026-10-22 사용자 확정: 종료 시 좌석 유지·전원 준비 해제 → SETTLING → 경기 전체 SETTLED 확인 후 WAITING → 다시 전원 준비해 새 경기 시작. 실제 DB 커밋 결과 통합 검증은 별도 |
| 실제 맵 테이블 배치 | tableId별 중심 X/Z 좌표. 채팅·관전 반경은 이미20m로 결정됨 |
| 상점과 공통 재화 처리 | 2026-10-22 사용자 확정: 구매·판돈·정산은 같은 지갑 행을 잠그고 순서대로 처리. 구매 쪽 FOR UPDATE는 구현됨. 남은 확인은 같은 DB·예약금 의미·SHOP_PURCHASE 원장·최종 DDL과 실제 공통 서비스의 동일 잠금 적용. V100은 기존 DB에 자동 적용하지 않음 |
| 장착 후 3D 외형 반영 | 서버 구현: 실제 REST 커밋 뒤 같은 채널 WORLD_STATE.payload.avatars[].equipment에 itemId/itemCode/equipSlot/imageKey 전파, CHANNEL_JOIN 시 복구. 프론트와 확인할 것: 이 추가 필드 수용과 null=기존 외형 유지/[]=장착 없음 처리, image_key→성별·부위별 실제 3D 에셋·기본 외형 매핑. 에셋 값이나 렌더링 완료를 임의 확정하지 않음 |

게임 시작·정산 연결의 기존 초안은 [시작 연동 계약](game-start-contract-draft.md)을 참고합니다. 새 메시지나 인증 방식을 이 목록에서 확정하지 않습니다.

이미 결정된 내용: 오목은 한 수30초 초과 시 시간패·총시간 제한 없음. 나머지 게임은30초 후 차례 넘김. 다리의 굴림/선언/각 판단은30초이며, 원카드 선언/신고의 별도3초 반응창은 차례 제한과 구분합니다.

결과2종(`GAME_RESULT_CHECK`, `GAME_RESULT`)의 실제 연결에는 정산 저장 담당의 `GameResultGateway`가 필요합니다. 확정 경기 ID·참가자별 결과/금액·종료 이유·PENDING/SETTLED 상태·단조 증가 버전의 매핑, 커밋 성공 뒤 `GameResultCommitted` 발행 시점을 함께 확인합니다. 현재 통신부·대역 검증은 완료지만 임의 금액이나 가짜 정산 완료를 만들지 않습니다.

## 경기 종료·이탈 연동 · 2026-10-23

- 게임 담당 구현: 공통 GameParticipantLeft/GameFinished, 모든 최초 참가자의 결과·이탈 사유·시각. 기존 게임별 이벤트/프론트 JSON 유지. DB 담당은 한 경로만 구독하고 eventId로 중복을 막는다. 실제 예약·정산 트랜잭션은 DB 담당 유지.
- 인증 담당 구현: Revoked.reason=LOGOUT만 ConnectionCloseReason.LOGOUT으로 전달. MEMBER_DEACTIVATED는 기존 회원 전체 전달 경로 재사용. REFRESH_REUSE_DETECTED/SESSION_REVOKED는 AUTH_SESSION_REVOKED로 유지하며 일괄 즉시 기권으로 분류하지 않는다. 게임 코드 변경 없이 기존 분기를 재사용하며 오프라인 유예/최초 원인 경합 제한은 session-invalidation.md에 기록한다.
- DB 담당 확인: 이벤트 LOGOUT/MEMBER_DEACTIVATED와 ERD의 EXPLICIT_LEAVE 매핑, 최초 참가자 전체 저장, 중도 탈락 시 예약금 유지 후 경기 최종 정산. 세부 계약은 game-result-api.md/game-reconnect.md.

- 2026-10-23 사용자 승인: 수신한 붕어빵 최종 기획·BE/FE v2 규칙으로 입력 기록을 서버에서 재생한다.
- 기존 3개당 2냥은 15점당 1냥·KST 하루 100냥으로 변경. 미완성·환산 잔여 점수는 버린다.
- 랭킹 제외, 탭 이동 중 타이머 진행, 가게/캐릭터 배치 미정. 배치 결정 없이 REST 구현 진행.
- 본인별 활성 판 하나, 새 판 시작 시 이전 판 포기, 10분 제출 기한. 상세 [미니게임 계약](minigame-api.md).
