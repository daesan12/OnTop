# 근거리 채팅·관전

사용자 확정(2026-10-20~21): **채팅·관전 반경 모두 기본 20m**, XZ 평면 거리로 계산하고 정확히 20m인 경계도 포함한다. Y 높이·회전은 거리에서 제외한다. 기존 Raw WebSocket 메시지 형식은 유지한다.

## 좌표와 서버 설정

`WORLD_MOVE`는 방향 입력만 전달한다. 서버가 맵 충돌·이동 속도를 계산한 `WORLD_STATE.position`의 x/z와 테이블 좌표를 사용하며 **1단위=1m**, Y축 위쪽이다. 위치는 캐릭터 충돌 캡슐 중심이다.

테이블 위치는 아직 미정이므로 기본 설정은 비어 있다. 실제 배치가 정해지면 `GET /api/v1/tables?channelId=...`로 확인한 서버 tableId를 아래 설정의 키로 넣는다. 임의 원점이나 예시 좌표를 실제 배치로 사용하지 않는다.

```yaml
ontop:
  world:
    proximity:
      chat-radius: 20
      watch-radius: 20
      tables:
        # 실제 tableId와 맵의 미터 좌표로 교체하는 설정 형식 예시
        "[실제-tableId]":
          x: 10.0
          z: 30.0
```

서버 시작 시 읽는다. 반경은 유한한 양수여야 하며 등록한 테이블은 x/z를 모두 지정해야 한다. 일부 누락을 0으로 처리하지 않는다. 설정되지 않은 테이블은 관전 불가다. 같은 위치라도 다른 채널의 테이블·사용자에게 접근할 수 없다. 채널 설정이 없는 구형 개발 모드도 관전은 허용하지 않는다.

## 채팅

- 채널 입장 시 서버 스폰 위치를 만든다. 입력 전에 채팅할 수 있으며 정상 입장 상태에 위치가 없으면 `WORLD_POSITION_REQUIRED`로 차단한다.
- 성공 시 본인에게 원 요청 ID의 `WORLD_CHAT_MESSAGE`, 같은 채널에서 발신자 반경 20m 안이고 위치가 확인된 타인에게 requestId=null의 같은 payload를 보낸다.
- 대기 착석자도 최신 서버 계산 위치를 기준으로 이용한다. 위치 미보고·다른 채널·범위 밖 타인에게는 보내지 않는다. 재입장은 서버 스폰으로 시작한다.
- 기존 텍스트 검증·전송 간격·메시지 ID·시각 규칙은 유지한다. [광장 계약](world-websocket-api.md) 참고. 감정표현·위치 상태 자체의 전달 범위는 이 변경 대상이 아니다.

## 테이블 보기와 경기 관전

- `TABLE_WATCH`는 현재 채널의 설정된 테이블 중심에서 20m 안일 때만 공개 대기 상태를 구독한다. 위치·설정이 없거나 범위 밖이면 `TABLE_OUT_OF_RANGE`다.
- `GAME_WATCH`와 `GAME_STATE_CHECK`의 SPECTATOR 상태도 같은 범위를 검사한다. `GameStateGateway`는 공개/개인 상태와 함께 **서버가 확인한 내부 tableId**를 `GameStateView`의 7번째 인자로 반환해야 한다. tableId는 `@JsonIgnore`이며 외부 JSON에는 추가되지 않는다. 기존 6인자 생성자는 null을 사용하므로 참가자 조회에는 쓸 수 있으나 관전은 거절된다.
- tableId만으로 권한이 생기지 않는다. 기존 인증·로비 사용 가능·미착석·Gateway의 관전 자격·SPECTATOR 역할·빈 privateState 검사와 함께 적용한다. 좌표/공개 JSON에서 tableId를 추측하지 않는다. 참가자의 본인 개인 상태는 기존 경기 복구 권한으로 검사한다.
- 최초·단건·자동 상태 모두 **응답을 큐에 넣기 직전** 현재 범위를 검사한다. 위치·테이블 연결 정보가 없거나 범위 밖인 경기 상태는 `GAME_STATE_ACCESS_DENIED`로 거절한다.
- 관전 중 서버가 계산한 이동으로 범위를 벗어나거나 채널을 나가거나 착석하면 성립한 구독은 `TABLE_WATCH_LEFT` / `GAME_WATCH_LEFT`로 해제한다. 최초 경기 조회 중 채널 퇴장·착석은 원 요청 ID의 오류로 완료한다. 이동 중 최초 조회가 끝나면 현재 위치로 재검사한다. 자동 재관전은 없다.
- 이미 송신 큐에 수락된 과거 메시지를 회수하지는 않는다. 테이블 배치/반경은 실행 중 변경하지 않는다. 향후 동적 설정을 도입하면 구독 재평가가 추가로 필요하다.

## 검증 범위

`WorldProximityTests`와 `WorldProximityWebSocketTests`는 실제 거리 서비스·Spring 설정 바인딩·실제 로컬 소켓으로 경계·채널 격리·미보고/미설정 차단·단건 조회 우회·이동/퇴장/착석·느린 조회의 범위 재검사를 확인한다. 인증·경기 상태는 테스트 대역이다. 정확한 19/20/21m 경계 검사는 `FrozenWorldFixture`에서 물리 시간을 정지하고 서버 내부 위치를 주입한다. 실제 입력·물리 틱은 별도 `WorldMovementWebSocketTests`가 확인한다. 기존 통신/복구 시나리오 일부는 거리 권한만 허용하는 `AllowedWatchFixture`를 사용하여 해당 기능을 별도 검증한다.

실제 3D 맵 배치·좌표 변환·경기 Gateway·운영 인증 연동 완료나 성능 개선을 뜻하지 않는다.
