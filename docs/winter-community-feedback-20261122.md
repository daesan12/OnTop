## 트리 편지와 장식

- E로 여는 화면 자체가 눈 덮인 가지·별·전구·붉은 리본·밑동의 선물로 이어지는 트리 형태다.
  전용 배경 2종을 built-in image_gen으로 생성했다. 기와·메모판·옆 패널을 사용하지 않으며,
  UI용 별도 Canvas도 추가하지 않는다. 출처·제작 브리프는 community/ui-art/README.md에 기록한다.
  첫 화면에서 가지에 매달린 양말·구슬·종·선물을 고르고 같은 트리 안에서 편지를 작성한다.
  다른 탭에서는 실제 저장된 편지를 읽는다. 이미지 안에 글자나 입력을 넣지 않고 실제 DOM을 사용한다.
  휴대폰은 별도 세로 아트, 낮은 가로 화면은 트리 비율을 유지한 스크롤 영역을 사용한다.
  공통 PaperPopup의
  Escape·포커스 복귀·Tab 순환을 유지하고 textarea·select를 순환 대상에 포함했다.
- 기존 양말·구슬·종·선물 중 하나를 먼저 고르고 300자 이내 편지를 쓴다.
  익명/내 닉네임을 선택하며 닉네임은 서버 값만 사용한다. 편지는 공원 전체에 공유된다.
- 누적 50개부터 별·전구의 발광 재질을 켜고 최초 점등 시각을 영구 저장한다.
  전체 편지는 12개씩 조회하고, 실제 트리에는 최근 50개 편지의 장식을 기존 72개
  Memo_Anchor에 중복 없이 표시한다. 광원을 추가하지 않는다.
- 기존 `feat/christmas-tripo-assets@6f31c87539253064ed4c9e95943d509d7bf397b2`의
  12m 트리와 같은 작업의 원본 장식을 재사용한다. 별도 1.8배 확대·선물 이동은 취소했다.
  최신 dev에는 아직 이전 절차형 트리가 있어 해당 12m 모델과 일치하는 트리 충돌만 이관했다.
  최신 dev에서 이미 적용한 산타·눈사람·썰매의 다른 Tripo 모델과 물리를 그대로 보존한다.
  !669 병합 후 생성 맵을 재생성하고 에셋 수명주기·모델 검사를 포함해 재검증했다.
- 모델·미리보기의 출처·이용 조건·SHA-256은 community/assets/manifest.json에 기록한다.
  `node scripts/verify-winter-community-assets.mjs`로 11개 파일과 GLB 5개의 해시,
  자체 포함 텍스처, 면 수, 앵커·발광 재질을 검증했다. 추가 유료 생성은 없다.
  game-dev CLI가 없는 환경으로 해당 도구의 canonical admission을 수행한 결과는 아니다.

## 공동 눈 굴리기와 눈사람

- 짧은 Q의 기존 눈싸움과 R 던지기를 유지하고 Q를 길게 누르면 눈을 굴린다.
  서버가 채널별 공동 굴리기·크기 상한(반지름 1.1m)·위치·다른 활동과의 충돌을 판단한다.
- 눈 세 덩이를 모아 광장 양옆 눈밭에서 E로 모자·목도리·표정·이름과 위치를 고른다.
  한 채널 최대 12개이며 완성 눈사람은 채널별 DB 기록과 충돌을 복원한다.
  제작 도중의 굴리는 눈은 임시 상태다. 머리·몸통은 동일한 jointInsetRatio=.45로
  겹쳐 연결하고 FE 표시와 BE 충돌 높이를 맞췄다.
- 요청 UUID와 작성자별 유일 키로 재시도를 멱등 처리한다. 동일 UUID로 다른 내용·장식을
  보내면 충돌로 거절하며 저장 성공을 확인하기 전 편집을 잠가 같은 요청을 재확인한다.

## 공통 연결·DB·맵 계약

게임 엔진이나 지갑·보상 계약은 변경하지 않는다. REST는 WinterCommunityController,
WS는 `WORLD_WINTER_TREE`(개수·점등·장식 종류와 ID), `WORLD_WINTER_COMMUNITY`
(채널별 굴리는 눈·완성 눈사람)을 기존 TableHub/WorldChannelRegistry로 전달한다.
공통 변경은 위치·활동 권한 확인, 동적 눈사람 충돌, worldClient/runtime 상태 전달과
공원 상호작용 진입 연결이다. 익명 편지의 작성자 키는 공개 상태에 포함하지 않는다.

- 신규 SQL 1개: `backend/src/main/resources/db/migration/V183__create_winter_community.sql`.
  편지·누적 점등과 채널별 눈사람 4개 테이블이다. 활성 기본 location인 db/migration을 사용한다.
- V183은 사용자가 지정했다. 생성 전 최신 dev(V182), 활성 원격 heads, 열린 MR의 source와
  로컬 worktree 전체 db/**/V*.sql을 확인하고 점유가 없음을 채팅에 공유했다.
  별도 팀 예약과 실제 dev DB 적용 이력은 확인하지 못했다. 기존 혼합 작업의 V190은
  보존하며 이 MR에 넣지 않았다. 이미 적용된 SQL을 수정한 작업이 아니다.
  푸시 전 재확인한 원격 heads 39개·로컬 worktree 262개에서 V183은 이 작업 파일만 발견했다.
- 생성 맵 `2405deab271ed73362a6e1f2e9a4bab96a95394cfbc9e59f245e0761602780b3`.
  12m 트리 충돌·눈사람 제작 영역·형상 계약을 반영했다. 썰매 경로는 최신 dev와 동일하다.
  배포 시 FE와 같은 server-map.json/manifest.json을 BE가 참조하도록 동시 반영해야 한다.
  인프라 파일·설정은 수정하지 않았다. 담당자 요청문은 채팅에 전달했다.

## 검증과 미확인 범위

- FE 관련 7개 파일 32개 테스트, TypeScript 검사 통과.
- BE 관련 7개 클래스 40개 테스트 통과. 기존 눈싸움·눈 줍기·던지기 회귀 포함.
- 최신 dev 통합·소리함 스타일 UI 수정 후 FE 9개 파일 38개 테스트와 BE 물리 관련 4개 클래스
  13개 테스트, 타입 검사, 프로덕션 빌드 통과. 기존 BE 서비스 코드는 이번 UI 수정에서 바꾸지 않았다.
- 최종 트리형 UI 재디자인 후 FE 38개·타입 검사·프로덕션 빌드와 동일 Chrome 흐름을 재검증했다.
  생성 아트 대비 실루엣, 별/가지/선물 비율, 녹색·금색 대비, 매달린 장식, 네이티브 글자/입력,
  휴대폰 비율과 낮은 가로 화면 접근성을 확인했다. 별도 UI Canvas는 제거했으며 맵/DB는 수정하지 않았다.
- park-integration 프로덕션 빌드와 에셋 무결성 검사 통과.
- Browser plugin 미제공으로 기존 Playwright/Chrome을 사용했다. 실제 React 화면과
  GLB를 렌더링하고 장식 선택 → 익명 편지 → 49개 소등/50개 점등을 확인했다.
  1280×850, 390×844, 844×390에서 스크롤·주요 버튼·Escape를 검증했으며 앱 오류는 없었다.
  검수용 게임 브라우저와 해당 서버는 검증 직후 종료했다.
- 이 화면 검수는 API/runtime fixture를 사용했다. 운영 OAuth·실서버 다인 공원 이동이나
  실제 MySQL 영구 저장을 검증한 것으로 해석하지 않는다. 테스트 계정 링크 요청은 없었다.
- 신규 WinterCommunityMySqlTests는 MySQL 8.4의 명시적인 빈 loopback 테스트 DB에서만
  V183 신규 적용·CHECK·동시 멱등 요청·재생성 복원을 검증한다. 이 환경에는 연결 정보가
  없어 컴파일만 확인했고 실제 실행은 하지 못했다. 담당자의 DB 준비 후 실행이 필요하다.
  기존 dev DB 순차 적용·실서버 재시작 복원은 미확인이다. 테스트용 파일 저장소 복원은 통과했다.

요청 범위는 MR 생성까지다. 머지·Jenkins 성공·배포는 확인하지 않았고 브랜치는 유지한다.
