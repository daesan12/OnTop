# 🛠️ Backend_Roles

온탑 백엔드 담당 분담표

백엔드 A는 실시간 월드·통신을, 백엔드 B는 계정·데이터·재화 정합성을 담당합니다. 게임별 규칙과 AI 행동은 게임 단위로 나누어 담당합니다.

## 담당 영역

| 구분 | 백엔드 A — 실시간 월드·통신 | 백엔드 B — 계정·데이터·재화 |
| --- | --- | --- |
| 핵심 책임 | 실시간 상태 관리와 메시지 전달 | 데이터 저장과 재화 정합성 |
| 명세 작성 | WebSocket 메시지·실시간 상태 전환 | HTTP API·ERD·저장 및 정산 규칙 |
| 사용자·연결 | 인증된 사용자와 WebSocket 연결 매핑·연결 정리 | 로그인·가입·탈퇴·7일 계정 복구 |
| 광장 | 이동·근거리 채팅·감정표현 동기화 | 사용자 프로필·닉네임 저장 및 조회 |
| 테이블 | 착석·퇴장·준비·관전 상태 관리 및 전송 | 게임 시작 시 참가 조건 검증·참가 기록 생성 |
| 게임 시작 | 참가자 목록으로 시작 처리 요청·성공 후 시작 알림 | 잔액 검증·판돈 차감·게임 기록 생성·중복 시작 방지 |
| 게임 진행 | 입력 전달·게임 실행 연결·공개/개인 상태 전송 | 필요한 게임 기록 저장·조회 |
| AI 대행·재접속 | 연결 종료 감지·AI 전환 연결·상태 재전송·조작권 반환 | 종료된 경기의 결과·정산·대행 이력 저장 및 조회 |
| 게임 종료 | 서버가 판정한 최종 결과 전달·종료 알림 | 결과 저장·정산 처리·중복 정산 방지 |
| 엽전·보상 | 실시간 잔액 변경 알림 | 지갑·원장·가입 지급·베팅·미니게임 보상·랭킹 |
| 검증 주제 | 전송 대상 최적화·재접속·비공개 정보 노출 방지 | 동시 참가·동시 차감·중복 지급·정산 재처리 |
| 측정 항목 | 전송량·메시지 지연·동시 접속 수 | 정합성 오류·처리량·응답 시간 |
| 게임별 규칙·AI 행동 | 담당 게임의 규칙·AI·테스트 | 담당 게임의 규칙·AI·테스트 |

## 담당 간 연결점

아래는 A와 B 사이의 내부 처리 경계입니다. 구체적인 메시지·API 형식은 각 명세에서 정의합니다.

| 시점 | A → B | B → A |
| --- | --- | --- |
| 게임 시작 | 테이블·게임 종류·참가자·판돈 정보 | 생성된 게임 ID·시작 처리 성공 또는 실패 |
| 추가 베팅 | 사용자·게임·베팅 요청 식별자·금액 | 처리 결과·확정된 베팅 내역 |
| 게임 종료 | 게임 ID·서버가 판정한 최종 결과·종료 사유 | 결과 저장·정산 상태·참가자별 지급액과 잔액 |
| 종료 후 재접속 | 사용자·게임 결과 조회 요청 | 저장된 경기 결과·정산 상태·대행 이력 |

## 처리 흐름

1. **게임 시작:** A가 참가자를 확정해 시작 처리를 요청합니다. B가 참가 조건·잔액을 확인하고 참가 기록과 판돈 차감을 반영합니다. A는 성공 결과를 받은 뒤 게임을 시작합니다.
2. **추가 베팅:** 게임 상태에서 베팅 허용 여부를 검증한 요청을 B에 전달합니다. B가 잔액과 중복 요청을 확인해 반영하고, A가 확정된 결과를 전송합니다.
3. **게임 종료:** 담당 게임의 서버 로직이 결과를 판정합니다. A가 최종 결과를 B에 전달하고, B는 결과를 저장하고 정산합니다. A는 경기 종료와 정산 완료를 구분해 전달합니다.
4. **재접속:** 진행 중인 경기는 A가 현재 상태와 조작권 복귀를 처리합니다. 종료된 경기는 B가 저장한 결과·정산 상태·대행 이력을 바탕으로 전달합니다.

## 게임별 분담 원칙

- 오목·주사위·원카드·거짓말 다리의 규칙과 AI 행동은 게임 단위로 나누어 담당합니다. 개별 게임 담당자는 게임별 작업에서 지정합니다.
- 담당자는 해당 게임의 규칙·AI 행동·테스트를 함께 책임집니다.
- 모든 게임은 A의 공통 실행·통신 구조와 B의 기록·정산 처리에 연결합니다.
- 연결 종료 시 AI 대행과 재접속 시 조작권 반환은 A의 공통 흐름에 연결하고, 실제 AI 행동 선택은 담당 게임에서 구현합니다.
- 전송 최적화와 동시성 검증은 측정 주제이며, 특정 최적화 기법이나 락 방식의 도입·개선 성과를 미리 확정하지 않습니다.
