# 원카드 플레이·관전 UX 추가 기획

작성: 2026-10-27 KST. 기존 [게임 규칙](onecard.md)에 추가한다. FE 구현과 BE 배포 완료를 구분한다.

2026-10-28 변경: 사용자 레퍼런스에 따라 어깨 너머 3인칭을 **테이블을 바라보는 1인칭 + 화면에 고정된 2D 손패·버튼**으로 변경한다. 아래 현재 플레이 기획을 우선한다.

## 플레이 경험

- 실제 시작 승인 이후 좌석 기준 1인칭으로 테이블을 본다. 내 화면의 내 캐릭터 몸·뒤통수는 숨기며 상대와 관전자에게는 기존 내 3D 캐릭터를 표시한다. 내 차례와 상대 차례에 같은 시점을 유지한다. 준비·결과 카메라는 선행 태블릿 흐름을 따른다.
- 테이블과 상대 캐릭터는 3D, 내 손패·버튼·안내는 원근·조명에 영향을 받지 않는 화면 좌표의 2D 인터페이스다. 손패는 얕은 부채꼴로 배치하고 겹침을 줄여 중앙의 짧은 능력명만 읽을 수 있게 한다. `+2 공격`, `방향 반전`처럼 표시하고 설명 문장은 생략한다. 앞면 왼쪽 위 숫자·무늬를 유지하며 낼 수 있는 카드는 테두리로 강조한다. 일반 카드에는 추가 문구를 넣지 않는다. 선택 카드는 위로 들어 올리고 별도 제출 버튼으로 낸다.
- 카드에는 아이보리 종이색·금색 안쪽 테두리·희미한 무늬 워터마크·오른쪽 아래 뒤집힌 숫자/무늬를 사용한다. 뒷면은 청록색 격자와 중앙 장식으로 통일한다. 원카드 게임판에는 청록 펠트·이중 금색 테두리·네 모서리 장식·중앙 네 무늬 메달리온·카드 더미 영역을 넣는다. 원카드 전용 재질과 CSS 안에서 구현해 다른 게임의 테이블 모델은 유지한다.
- 테이블의 공개 카드·덱은 기존 가로·세로의 80%로 줄인다. 상대 손패는 테이블에 놓인 소품 대신 캐릭터가 두 손으로 들고 있는 3D 부채꼴 뒷면으로 표현한다. 공개 카드 수와 표시 수를 정확히 일치시키며 10장 제한을 두지 않는다. 최대 54장까지 같은 손 안의 범위에서 펼치고, 아바타당 instanced mesh 하나로 처리한다. 2D 손패 크기는 줄이지 않는다.
- 중앙은 실제 테이블·공개 카드·캐릭터가 보이는 공간으로 남긴다. 현재 무늬·공격 정보와 좌상단 남은 시간만 간결하게 제공한다. `원카드 / 같은 무늬나 숫자…` 제목, `내 차례 / 시계 방향 / 덱 34장…` 안내, `나의 손패 / 강조된 카드를…` 안내, 하단 드로우 설명은 제거한다. 참가자 머리 위에 이름·공개 카드 수·현재 차례를 표시한다. 스크린리더에는 참가자 목록을 별도로 제공한다.
- 손패 왼쪽 위와 오른쪽 아래의 숫자·무늬는 같은 크기로 표시하고, 오른쪽 아래는 180도 회전한다. 남은 시간은 초 단위로 표시하며 5초 이하에서 색으로 강조한다. 시간 만료 시 0초를 유지하고 서버 입력 권한을 따른다.
- 우상단의 규칙·최신 확인·기권 도구를 기본 경기 화면에서 제거한다. 기권은 Esc → `기권하시겠습니까? / 배팅한 엽전은 모두 잃게 됩니다.` 확인 창 → `기권 확정`으로 처리한다. `계속 플레이` 또는 Esc로 취소할 수 있다. 채팅 입력·다른 대화상자의 Esc는 먼저 해당 UI에 양보한다. 기존 기권 API·중복 방지·응답 유실 시 같은 요청 확인은 유지하고 복구가 필요한 상태에서만 확인 버튼을 제공한다.
- 모든 게임의 시작 승인·진행 중에는 공원 지도를 비활성화한다. 버튼·M 단축키·지도 열기 함수 모두 같은 기준을 따르며 이미 열린 지도와 길 안내도 닫는다. 일반 공원에서는 기존 지도 이용을 유지한다.
- 남은 시간과 현재 공개 카드/무늬 정보를 확대한다. 카드·게임판의 금색 프레임·종이 음영·펠트 자수 장식을 보강한다. 채팅 입력란과 전송 아이콘은 같은 높이 변수로 크기를 맞춰 펼친/접힌 입력란과 모바일에서도 밖으로 나오지 않게 한다.
- 낼 카드가 있어도 **한 장 뽑고 차례를 넘기기**가 가능하다. 뽑은 카드는 같은 차례에 낼 수 없다. 공격 중에는 기존 공격 받기/방어 규칙을 유지한다. 합법 카드·드로우 권한은 서버 privateState를 따른다.
- 많은 손패는 데스크톱 8장, 좁은 화면 3장 단위 묶음으로 탐색한다. 현재 묶음과 전체 카드 수를 표시하며 모든 손패에 접근할 수 있다. 묶음 변경은 손패 순서·게임 상태를 바꾸지 않는다.
- 개인 손패는 하단 버튼 위치를 유지하면서 위로 띄운다. 데스크톱은 화면 높이에 따라 36~64px, 모바일은 36px 올려 테이블에 가까운 높이에서 보이게 한다. 손패 장수 규칙은 기존 기획과 서버 판정을 따른다.

## 관전자 장난: 손패 뒤집기

승인된 동일 경기 관전자만 현재 차례의 활성 플레이어를 대상으로 요청한다. 실제 손패·장수·규칙·타이머는 바뀌지 않는다. 다른 사용자에게 손패 앞면을 공개하지 않는다.

| 항목 | 첫 테스트 기준 |
| --- | --- |
| 뒤집는 장수 | 최대 2장, 적격 카드 1장일 때 1장 |
| 보호 | 선택 카드와 제출 중 카드는 제외. 보호 때문에 0장이면 효과를 즉시 복구 |
| 복구 | 뒤집힌 카드 아무거나 클릭 또는 ‘손패 정리’ 한 번으로 모든 묶음의 뒤집힌 카드 복구 |
| 연출 | 카드 Y축 회전 약 320ms, 동작 줄이기에서는 즉시 상태 전환 |
| 빈도 | 대상 플레이어의 한 차례에 1회. 관전자 전체가 한도를 공유 |
| 중첩 | 효과 중 재적용·장수 추가·시간 갱신 금지 |
| 면역 | 복구 직후 2500ms. 다음 차례로 넘어가도 남은 면역 유지 |
| 턴 전환·종료 | 가려진 카드는 즉시 복구. 효과로 턴 시간이 늘어나지 않음 |
| 재접속 | 과거 장난 재생 금지. 서버는 종료된/유실된 효과 정리 및 면역 유지 |

복구는 FE에서 즉시 처리한다. 서버 ACK를 기다려 카드를 가리지 않는다. 복구 통신 실패는 기존 효과를 다시 적용하지 않으며 자동 재요청하지 않는다. 제출 이후 도착한 장난은 이미 선택한 제출을 취소하거나 손패를 재정렬하지 않는다.

## 구현·연동 경계

기존 드로우·카드 제출 API는 유지한다. 장난은 일회성 표현 이벤트로 별도 어댑터에 둔다. BE 계약 확정 전 운영에서는 장난 전송을 기본 비활성화하고, FE의 뒤집기/복구/제한 로직은 제안 계약을 사용하는 테스트로 검증한다. UI에서 다른 플레이어에게 성공한 척하지 않는다.

기존 3D 캐릭터·테이블을 재사용한다. 이미지 시안은 구도 참조이며 실제 UI는 코드와 실시간 장면이다. [FE 명세](../frontend/docs/ONECARD_UX_FE_SPEC.md), [BE 명세](onecard-ux-be-spec.md), [동시 작업 규칙](../frontend/docs/GAME_MODULE_WORKFLOW.md)을 따른다.
