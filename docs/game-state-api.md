# 경기 공개·개인 상태 조회·자동 전송 연결부

OnTop v0.4의 **비공개 정보는 본인에게만 전송, 관전자는 공개 정보만 수신** 원칙을 위한 local 연결부다. 실제 로그인·경기 엔진·맵/거리 기반 관전 자격 판정은 미연결이다. `GameStateGateway` 구현이 없으면 성공 데이터 대신 명시적 오류를 반환한다.

2026-10-20 Notion에 [경기 통신 상세 7종](websocket-api/09-game-communication.md)을 반영하고 저장 내용을 재조회했다. 실제 게임의 필드와 엔진 연동은 여전히 대기 상태다. 기존 `TABLE_WATCH`는 대기 상태 구독이며 경기 관전 권한을 부여하지 않는다.

## 요청·응답

인증된 연결에서 다음을 보낸다. `gameId`는 조회 대상이며 접근 권한의 증명이 아니다. 사용자 ID·역할은 요청에 넣을 수 없다.

```json
{"requestId":"state-1","type":"GAME_STATE_CHECK","payload":{"gameId":"game-1"}}
```

```json
{
  "requestId":"state-1",
  "type":"GAME_STATE",
  "payload":{
    "gameId":"game-1",
    "version":8,
    "role":"PLAYER",
    "publicState":{"turnUserId":"101"},
    "privateState":{"hand":["example-card"]}
  }
}
```

상태 필드는 형식 설명용 예시다. `gameId`는 공백이 아닌 1~120자 문자열, `version`은 경기 담당의 0 이상 상태 버전이다. 같은 경기의 이전 버전을 화면에 덮어쓰지 않는다. 이 연결부가 턴·승패를 판정하지 않는다.

- `PLAYER`: 공개 정보와 해당 사용자 자신의 개인 정보만 포함한다. 응답 직전에도 기존 재접속 서비스의 해당 경기 복구 완료·조작 가능 여부를 확인한다. 복구 중·유예 만료 상태를 조회로 우회할 수 없다.
- `SPECTATOR`: `privateState`는 반드시 `{}`다. 비어 있지 않으면 상태 객체 생성 시 거절한다. 경기 담당이 현재 관전 자격을 검사한다.
- 응답은 요청한 연결에만 전송한다. 같은 채널·테이블·다른 계정에 방송하지 않는다. 서버 내부 검증용 `userId`는 응답 JSON에서 제외한다.
- 요청당 상태 하나를 조회한다. 참가자 자동 전송과 관전자 공개 상태 구독은 아래 별도 흐름이다. 종료/정산·재접속 유예 변경은 이번 범위에 없다.
- 같은 연결에서 조회 하나만 진행한다. 느린 조회는 Hub 잠금 밖에서 실행하며, 종료된 연결의 결과는 버린다. 동일 계정이 다시 연결해도 이전 응답을 넘기지 않는다.

## 오류

기존 `ERROR` 형식을 사용하며 요청 ID를 복사한다. 상태나 엔진 예외 내용은 오류 응답에 넣지 않는다.

| 코드 | 의미 |
| --- | --- |
| `INVALID_PAYLOAD` | gameId 누락·형식/길이 오류·허용되지 않은 필드 |
| `GAME_STATE_AUTH_REQUIRED` | dev 임시 사용자이며 인증 연결이 아님 |
| `GAME_STATE_NOT_CONFIGURED` | 경기 담당 Gateway 미등록 |
| `GAME_STATE_PENDING` | 같은 연결의 이전 조회 진행 중 |
| `GAME_STATE_ACCESS_DENIED` | 접근 자격 없음 또는 경기 없음. 두 경우를 구분해 노출하지 않음 |
| `GAME_STATE_INVALID` | 경기 담당이 다른 사용자·경기의 상태를 반환 |
| `GAME_STATE_UNAVAILABLE` | 경기 담당 조회/상태 생성 실패 |
| `GAME_STATE_STALE` | 변경 알림보다 오래되었거나 이미 전송한 참가자 상태보다 과거 버전 |
| `GAME_RECOVERY_REQUIRED` | 참가자의 해당 경기 복구가 완료되지 않음 |

## 경기 담당이 구현할 부분

`GameStateGateway.load(userId, gameId)`는 서버가 확인한 내부 계정 ID를 받는다. 참가/관전 자격 검사와 일관된 스냅샷 생성을 함께 수행하고, 자격이 없거나 경기가 없으면 `Optional.empty()`를 반환한다. 참가자 응답에는 본인 개인 정보만 넣고 관전자 응답에는 빈 개인 상태를 넣는다.

연결부는 사용자·경기 일치와 관전자 개인 상태를 검사하지만, 임의 JSON 필드가 실제 공개 정보인지 판별할 수는 없다. 손패 전체를 publicState에 넣는 실수를 엔진이 방지해야 한다. 실제 엔진에서 반환 객체와 권한을 함께 검증하는 테스트가 추가로 필요하다.

엔진의 DB/외부 호출에는 제한 시간을 설정해야 한다. 현재 연결부는 조회 중복을 막지만 별도 조회 타임아웃이나 강제 취소를 제공하지 않는다. 동기화 작업을 장시간 점유하는 구현을 연결하지 않는다.

검증은 테스트 소스의 인증·경기 대역으로 수행한다. 실제 경기 관전·운영 인증 연동 성공을 뜻하지 않는다.

## 진행 경기 참가자에게 자동 전송

사용자의 입력이 확정되면 같은 경기의 **현재 인증 연결·복구 완료 참가자**에게 자동 GAME_STATE를 보낸다. 입력자가 응답 전에 끊겨도 남은 참가자에게 전달한다. 별도 클라이언트 구독 요청은 없다. 자동 메시지는 기존 응답과 같은 payload이며 `requestId`만 `null`이다.

타이머·AI 등 다른 원인으로 상태가 바뀌면 경기 담당이 **변경 확정 후** Spring `ApplicationEventPublisher.publishEvent(new GameStateChanged(gameId, version))`를 호출한다. 이 이벤트에는 경기 ID와 확정 버전만 넣는다. WebSocket JSON 입력이나 사용자 지정 수신자 목록이 아니다. DB 트랜잭션을 붙일 때는 반드시 커밋 성공 뒤 발행하도록 연결해야 한다. 현재 메모리 이벤트는 재시작 복구·다중 서버 전달을 보장하지 않는다.

전송 순서는 다음과 같다.

1. 서버 재접속 상태에서 해당 경기의 조작권이 확인된 연결만 고른다. dev·다른 경기·관전자·복구 중 연결은 자동 대상에 넣지 않는다. TABLE_WATCH로 경기 개인 정보 수신 권한이 생기지 않는다.
2. 대상마다 `GameStateGateway.load(userId, gameId)`를 Hub 잠금 밖에서 따로 호출한다. 반환 사용자·경기·PLAYER 역할을 대조한다. 같은 직렬화 문자열을 전체 참가자에게 방송하지 않는다.
3. 전송 직전에도 원래 연결과 현재 경기 조작권을 확인한다. `publicState`와 **그 사용자 자신의** `privateState`를 함께 보내고, 내부 userId는 응답에서 제외한다. 공개 필드의 실제 내용과 개인 정보 필터링은 여전히 경기 담당이 책임진다.
4. 연결 하나의 자동 조회는 한 번에 하나다. 처리 중 변경 알림은 가장 큰 버전으로 합치고, 예전 조회 결과 대신 최신 상태를 다시 조회한다. 중간 프레임마다 한 번씩 보내는 이벤트 로그가 아니라 최신 상태 동기화다.
5. 동일/과거 버전 알림은 이미 보낸 상태를 다시 전송하지 않는다. 단건 조회도 이미 전달한 참가자 상태보다 낮으면 GAME_STATE_STALE 오류로 응답한다. 클라이언트는 기존 규칙대로 같은 경기의 낮은 버전을 무시한다.

권한이 사라졌거나 종료된 연결의 결과는 폐기한다. 개인별 조회 실패는 그 연결에만 requestId=null의 ERROR로 알리고 다른 참가자 전송은 계속한다. 최신 버전 조회가 실패/지연됐을 때 무한 재시도하지 않는다. 다음 변경 알림 또는 GAME_STATE_CHECK로 재확인한다. 별도 조회 제한 시간은 없으므로 엔진 호출 자체에 제한 시간이 필요하다.

참가자 자동 대상은 재접속 서비스의 `RESTORED` 상태에 있는 진행 경기 참가자다. FINISHED/ELIMINATED 상태로 전환된 연결의 종료·정산 통지는 별도 연결이 필요하다. 관전자는 아래 명시적 구독을 사용한다. 실제 엔진·정산 완료로 표시하지 않는다.

## 관전자 공개 상태 구독

기존 TABLE_WATCH는 대기 테이블 공개 상태만 구독한다. 경기 관전은 별도 GAME_WATCH로 요청하며, gameId만 안다고 관전 권한이 생기지 않는다.

```json
{"requestId":"watch-1","type":"GAME_WATCH","payload":{"gameId":"game-1"}}
```

현재 인증 계정이며 로비 사용이 가능한 연결에서 요청한다. 기존 경기 복구 중/참가 중 연결은 GAME_RECOVERY_REQUIRED다. `GameStateGateway.load(userId, gameId)`가 현재 관전 자격을 확인하고 SPECTATOR 역할·빈 privateState를 반환해야 구독이 성립한다. PLAYER 역할이나 다른 사용자/경기의 상태는 전송하지 않는다. 최초 GAME_STATE는 원래 requestId로 응답하고 이후 변경은 requestId=null로 자동 전송한다.

```json
{"requestId":"watch-1","type":"GAME_STATE","payload":{"gameId":"game-1","version":8,"role":"SPECTATOR","publicState":{"turnUserId":"101"},"privateState":{}}}
```

현재 연결 하나는 경기 하나만 구독한다. 조회 중인 요청도 자리를 차지하며, 다른 경기로 바꾸려면 먼저 GAME_UNWATCH한다. 중복 요청은 GAME_ALREADY_WATCHING으로 거절한다. 이는 현재 로컬 연결 계약이며 정식 UI의 관전 구역/거리/전환 정책을 확정한 것은 아니다.

```json
{"requestId":"unwatch-1","type":"GAME_UNWATCH","payload":{}}
```

```json
{"requestId":"unwatch-1","type":"GAME_WATCH_LEFT","payload":{"gameId":"game-1"}}
```

- 해제 후 도착한 자동 조회 결과는 폐기한다. 최초 확인 전 취소하면 이전 GAME_WATCH 요청에는 GAME_WATCH_CANCELLED 오류를, 해제 요청에는 GAME_WATCH_LEFT를 보낸다. 구독이 없으면 GAME_NOT_WATCHING이다.
- GameStateChanged마다 관전자 본인 계정으로 다시 조회해 권한을 확인한다. 공개 상태만 전송하며 다른 참가자의 조회 결과를 관전자에게 재사용하지 않는다. SPECTATOR의 privateState가 비어 있지 않으면 상태 객체 생성 단계에서도 거절한다.
- 조회 중 알림은 최신 버전으로 합친다. 최초 응답도 그 사이 관찰한 최신 버전 이상이어야 한다. 관전 권한 확인은 같은/과거 버전 알림에도 다시 수행하며, 조회 도중 새 알림이 오면 이전 권한 결과를 폐기하고 다시 조회한다. 상태 버전이 그대로면 권한 확인 뒤 중복 GAME_STATE는 보내지 않는다.
- 종료·해제·다른 구독으로 바뀌면 이전 조회 결과가 새 구독에 적용되지 않는다. 취소해도 이미 실행 중인 엔진 호출은 강제 종료하지 않으며, 새 자동 조회는 그 호출이 끝날 때까지 대기한다. 취소·재구독 반복으로 한 연결에 자동 조회가 중첩되지 않는다.
- 조회가 거절/실패하거나 역할·대상이 잘못됐으면 그 연결에 ERROR를 보내고 구독을 제거한다. 최초 오류는 요청 ID가 있고 이후 오류는 null이다. 프론트는 이 오류를 받으면 자동 구독 표시를 해제하고 필요시 다시 GAME_WATCH한다.
- 로비 사용 자격이 없어지거나 참가자 전송으로 바뀌면 최초 대기 요청에는 GAME_RECOVERY_REQUIRED 오류, 성립한 구독에는 requestId=null의 GAME_WATCH_LEFT로 종료를 알린다. 연결 종료는 별도 알림 없이 구독을 정리한다. 재접속 시 자동 재구독하지 않는다.
- 해제는 자기 연결의 관전 구독만 제거하며 참가자 입력·복구 상태·테이블 대기 구독은 바꾸지 않는다. 관전만으로 GAME_ACTION_SEND 조작권은 생기지 않는다.

경기 담당은 권한 회수 시에도 변경 이벤트를 발행해 다음 전송 전에 자격을 재검사하도록 연결해야 한다. 현재 전송 전에 검증하는 권한은 Gateway가 만든 스냅샷 기준이며, 실제 엔진이 권한 검사와 스냅샷 생성을 함께 보장해야 한다. 맵/거리 판정·관전자 수 제한·정산 정보 공개 정책은 구현하지 않았다.
