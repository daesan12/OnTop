## 흑백수사 (`DAVINCI_CODE`)

`DavinciEngine.forfeit`가 `match.forfeit`의 판정과 `GameLifecycle.left`에 서로 다른
`clock.instant()`를 사용했다. 마지막 상대가 기권하면 먼저 기록한 `endedAt`보다
`leftAt`이 늦어지고 `VerifiedGameFinish.validate`가 참가 판정을 거절한다.
게임 화면은 FINISHED지만 DB 결과 저장·정산은 진행되지 않을 수 있다.

기권 요청 안에서 시각을 한 번 읽어 이탈과 종료에 공유한다. 공통 검증을 완화하거나
클라이언트에서 정산 완료를 추정하지 않는다. 참가자·승자·기권 사유·중복 actionId 계약은 유지한다.
수정은 게임 전용 엔진에 한정하며 공통 종료/정산 구현과 FE/BE 프로토콜은 변경하지 않는다.

- 신규 `DavinciForfeitSettlementTests`: 2·3·4인, 호출마다 1ns/1ms 진행하는 시계로 총 6개.
- 수정 전 6개 모두 실제 공통 검증의 `경기 참가 판정을 확인하세요.` 오류 재현.
- 수정 후 엔진 → 공통 결과 저장 → 지갑 예약 해제·지급 → SETTLED를 검증한다.
  기권 재전송·결과 재수신·정산 재시도 시 원장과 지급이 중복되지 않는지도 확인한다.
- BE 6개 클래스 61개 통과, 실패·스킵 0. DB I/O만 mock이고 실제 MySQL/DEV 정산은 미검증이다.
- 이미 멈춘 DEV 경기의 저장 상태와 소급 복구 여부는 별도 로그/DB 확인이 필요하다.
  사용자에게 담당자 확인 요청을 전달했으며 직접 DB 수정·수동 지급은 하지 않았다.

## 눈싸움 HUD

`winter.css`의 오른쪽 고정 배치를 화면 중앙 하단 배치로 바꾸고 공통 HUD 축소 비율을 적용한다.
Q/R 버튼 글자·여백을 줄이며 수집·투척 입력과 최대 소지량은 유지한다.
작은 세로 화면은 채팅 공간을 고려해 높이를 조정하고 낮은 가로 화면은 하단 64px을 사용한다.
기존 스크롤바 숨김과 휠·키보드 스크롤은 유지한다.

- localhost:5559의 실제 WinterHud + 최신 생성 맵을 읽는 별도 UI fixture로 검증했다.
  인증·수집·투척 응답은 로컬 상태이며 실제 서버 연결/게임 전체 화면 검증은 아니다.
- Chrome/CUA로 Q 수집 2→3, R 투척 3→2를 버튼과 키보드에서 확인했다.
- 실제 CSS viewport 1707×1125, 390×843, 843×390, 320×567에서 중심 오차 1px 미만,
  화면 잘림 없음. 얼음 상태 표시도 확인했다. 페이지/오버레이/console 오류 없음.
- TypeScript `--noEmit`와 기존 FE 8개 파일 122개 테스트 통과.
- 검증 탭은 즉시 닫았고 viewport 복원·5559 서버 종료와 리스너 제거를 확인했다.
