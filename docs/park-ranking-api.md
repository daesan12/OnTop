# 공원 랭킹판 조회 계약

Jira S15P31B105-287·S15P31B105-308·S15P31B105-309. 총자산 기준은 일반 랭킹 `GET /api/v1/rankings`와 동일하다.
2026-11-16부터 7종을 4열+3열 두 페이지로 보여 준다. 기존 총자산·두더지·스피드 두더지·구구구 줄넘기에 점프맵·붕어빵·온탑 꼬치왕을 추가한다. GM은 목록에서 제외하지 않고 기존 표시 정책을 유지한다.

## 조회

`GET /api/v1/rankings/park`에 기존 회원 Access JWT를 보낸다. 응답은 `Cache-Control: no-store`다.

```json
{
  "balance": [{ "rank": 1, "userId": "101", "nickname": "온탑", "coinBalance": 300, "equipmentValue": 1000, "totalAssets": 1300 }],
  "mole": [{
    "rank": 1, "userId": "102", "nickname": "두더지왕", "score": 1380,
    "maxCombo": 24, "completedAt": "2026-11-10T05:30:00Z", "gameMaster": false
  }],
  "speedMole": [{
    "rank": 1, "userId": "103", "nickname": "스피드왕", "score": 132,
    "misses": 3, "completedAt": "2026-11-10T05:31:00Z", "gameMaster": false
  }],
  "jumpRope": [{
    "rank": 1, "userId": "104", "nickname": "줄넘기왕", "score": 1250,
    "misses": 1, "completedAt": "2026-11-16T05:31:00Z", "gameMaster": false
  }],
  "jumpmap": [], "bungeoppang": [], "skewer": [],
  "jumpRopeStartsAt": "2026-11-16T05:00:00Z", "jumpRopeEndsAtExclusive": "2026-11-18T15:00:00Z",
  "updatedAt": "2026-11-16T06:00:00Z"
}
```

- 보유량 목록은 10명 이하이며 기록이 없으면 빈 배열이다. 10위에서 동점이어도 11번째를 추가하지 않는다.
- 화면 이름은 **총자산 랭킹**이며 `balance` 배열 이름은 호환성을 위해 유지한다. 순위 숫자는 총자산으로 계산해 `1, 1, 3`을 유지한다. 동점 표시 순서는 지갑 마지막 변경 시각,
  사용자 ID 오름차순이다.
- 보유량은 예약된 엽전을 포함한 `wallets.balance`다. 예약만 변경되어도 지갑 마지막 변경 시각이 바뀔 수 있다.
- `coinBalance`는 실제 잔액, `equipmentValue`는 완전 보유 상품 가치, `totalAssets`는 둘의 합이다. 합산·비활성 기본값은 [일반 랭킹](rankings-api.md)과 [의상 뽑기](gacha-api.md)를 따른다. 기존 60초 스냅샷과 마지막 집계 시각을 유지한다.
- 두더지 잡기 랭킹은 10명 이하이며 `PARK_RANKING_STARTED_AT` 이후에 정산한 현재 규칙(3) 판만 대상으로 한다.
  게임 안 랭킹(`GET /api/v1/minigames/whack-a-mole/rankings`)과 같은 기준이다. 회원별 최고 기록을 먼저 선택하고
  점수 내림차순, 같은 점수는 최대 콤보 내림차순, 정산 시각과 판 ID 오름차순으로 최대 10명을 결정한다. 순위 숫자는
  점수와 최대 콤보만으로 계산해 공동 순위를 `1, 1, 3`으로 표시한다.
- 스피드 두더지 잡기 랭킹은 10명 이하이며 `PARK_RANKING_STARTED_AT` 이후에 확정한 현재 규칙(1) 판만 대상으로 한다.
  게임 안 랭킹(`GET /api/v1/minigames/speed-mole/rankings`)과 같은 기준이다. 점수 내림차순, 같은 점수는 실수 오름차순,
  완료 시각과 판 ID 오름차순이며 순위 숫자는 점수와 실수만으로 계산한다.
- 구구구 줄넘기는 KST **2026-11-16 14:00 이상 시작**, **2026-11-19 00:00 미만 완료**한 확정 기록만 포함한다. 종료일 11/18 23:59 전체 분을 포함하며 기존 기록은 삭제하지 않는다. 기간 조건은 개인 최고 선택 전에 적용한다. 게임 안 목록·참가자 수·내 순위도 동일하다. 현재 규칙은 기존 jump-rope-rules-version 설정을 따른다. 응답의 jumpRopeStartsAt/jumpRopeEndsAtExclusive는 UTC ISO-8601이다. 시작 전에는 집계 예정, 종료 후에는 확정 기간 결과를 계속 조회한다. 기간 메타데이터가 없는 구 서버의 줄넘기는 새 화면에서 기간 집계 준비 중으로 처리한다.
- 점프맵(jumpmap)은 기존 정상 완주·현재 코스/규칙·검증 허용 기준을 재사용한다. finishMs가 짧은 순, 동점은 먼저 완료한 순이며 개인 최고만 남긴다. 화면은 분:초.밀리초로 표시한다.
- 붕어빵(bungeoppang)은 기존 v5 2분 검증 완료 기록만 대상으로 점수·최대 콤보·정산 시각 순으로 개인 최고를 선택한다. 점프맵·붕어빵·꼬치는 기존 PARK_RANKING_STARTED_AT 이후 기록만 포함한다.
- 꼬치(skewer)는 PC·VR을 통합하고 역할과 무관하게 같은 두 회원의 최고 팀 기록 하나만 남긴다. 점수 내림차순, 동점은 먼저 완료한 기록/게임 ID 순이며 점수만 같은 팀은 공동 순위다. 기존 ranking_eligible·정상 4분 완료·현재 규칙·탈퇴 제외를 유지한다. 각 행은 chefUserId/chefNickname/serverUserId/serverNickname/score/playMode/completedAt/chefGameMaster/serverGameMaster를 제공한다. 선정 기록이 VR이면 두 닉네임 옆에 VR 배지를 표시한다. 명시적 PC·VR 게임 내 필터 API는 호환 유지하고 새 통합 창은 mode=ALL을 요청한다.
- 공원 보드의 구조·충돌 맵을 바꾸지 않고 표시 면만 페이지별로 배치한다. 8초 자동 전환과 줄어드는 진행 막대·현재 페이지를 표시한다. 페이지 전환은 추가 HTTP 요청을 만들지 않는다. E 상세창은 현재 보드 페이지에서 열리며 이전/다음·페이지 버튼·좌우키로 수동 이동한다. 상세창 또는 숨긴 탭에서는 자동 전환을 멈추고 다시 열 때 8초부터 시작한다.
- 모든 게임은 탈퇴 회원을 제외하고, 10번째 행에서 동점이어도 11번째를 추가하지 않는다. 완료 시각은 SQL에서 epoch
  millis로 변환해 JVM 기본 시간대와 DB 세션 시간대의 차이에 의존하지 않는다. 두 게임은 PROD 기준 시각(11/02) 뒤에
  출시되어(11/04·11/05) 운영에서는 게임 안 전체 기간 랭킹과 순위가 같다.
- 정상 기록이 없는 게임의 랭킹 필드는 빈 배열이다.
- `updatedAt`은 일곱 조회를 모두 성공적으로 계산한 뒤 교체한 시각이다. API 요청 시각이 아니다.
- 일곱 조회는 각각의 읽기 전용 트랜잭션에서 순서대로 실행된다. 데이터가 그 사이에 바뀌면 DB의 정확히 같은
  시점을 보장하지는 않는다. 일곱 결과의 공개는 원자적으로 이뤄져 API 응답 안에서 이전·새 스냅샷이 섞이지 않는다.

최초 집계 성공 전 또는 시작 시각이 설정되지 않은 DEV에서는 `503 RANKING_UNAVAILABLE`을 반환한다.
한 목록이라도 갱신에 실패하면 이전 정상 스냅샷과 `updatedAt`을 유지한다. 인증 실패에는 기존
Access JWT·회원·세션 정책의 401/403 응답을 사용한다.

## 공원판·상세창 표시

공원판과 E 상세창은 나무 테두리·한지·짙은 녹색·금색 표식 및 같은 종목 아이콘을 사용한다.
1~3위 강조는 행 순서가 아닌 서버의 실제 순위 값을 따르므로 공동 1위도 같은 표식으로 보인다.
긴 닉네임은 글자 크기를 줄이지 않고 말줄임하며, 꼬치의 두 이름과 VR 배지는 별도 공간에 배치한다.
Full HD에서는 10개 팀 기록을 한눈에 보여 주고 작은 화면에서는 목록 내부를 스크롤한다.
목록은 Tab으로 진입할 수 있고 위·아래/Home/End/PageUp/PageDown/Space로 이동한다.
좌우키는 기존 페이지 전환, Esc는 닫기로 유지하며 모션 축소 설정에서는 버튼 전환 효과를 줄인다.
표시 개선에 따른 API·집계·DB 변경은 없다.

## 운영 설정과 관찰

DEV 첫 적용 직전에 `/etc/ontop/dev-app/app.env`의 `PARK_RANKING_STARTED_AT`을 UTC ISO-8601 시각으로
정해 기록한다. 예: `2026-10-31T04:00:00Z`. 이 예시를 실제 값으로 복사하지 않는다. 앱 재생성 뒤에도 값을
유지해야 과거 기록이 다시 계산되지 않는다. 빈 값이면 랭킹판 집계만 대기하며 기존 앱은 기동한다.

PROD 기준은 `2026-11-02 09:00 Asia/Seoul` = `2026-11-02T00:00:00Z`로 고정한다.
운영 환경 예시 파일에 같은 값을 적었다. 시작 시각을 바꾸면 과거 순위의 기준이 바뀌므로 재배포 때 유지한다.

앱 인스턴스마다 메모리 스냅샷 하나를 보관하고 시작 직후와 이후 60초마다 갱신을 시도한다.
동시 갱신은 건너뛴다. 갱신 성공/실패 횟수는 `ontop.ranking.park.refresh`, 소요 시간은
`ontop.ranking.park.refresh.duration` Micrometer 지표로 집계한다. 현재 Actuator 웹 노출은 health만 허용하므로
외부에 지표를 공개하지 않는다. 앱 인스턴스를 여러 개로 늘릴 때는 공용 스냅샷과 단일 집계 주체가 필요하다.

격리된 MySQL 8.4.11의 소량 테스트 데이터에서 기존 보유량 조회는 약 8.7ms였다. `EXPLAIN FORMAT=TREE`는
활성 회원 스캔 → `uk_wallets_user` 조회 → 잔액 정렬/윈도우 집계를 보였다. 운영 데이터 규모의 성능 보장은
아니다. 붕어빵 우승자도 단일 정상 기록 fixture에서 JSON 방어 검증과 개인 최고 윈도우 집계를 포함해 약 6.9ms였고,
실행 계획은 회원별 세션 인덱스 조회와 세션 기본 키 기반 결과·라운드 조회 후 윈도우 정렬을 사용했다. 데이터가
쌓인 뒤 세 쿼리 시간과 실행 계획을 다시 측정하고, JSON 평가가 병목이 되면 검증된 콤보의 별도 컬럼·인덱스를
후속 마이그레이션으로 검토한다. V138은 1분 주기 조회의 상태·버전·시각 필터를 지원하는 붕어빵·점프맵
복합 인덱스를 추가한다. 두 쿼리는 유효 기록을 필터링하고 사용자별 최고 기록으로 축소한 뒤 공동 순위를
계산하며, 최종 정렬에 `LIMIT 10`을 적용한다.
2026-11-10 열 교체 뒤 미니게임 조회는 스피드 두더지의 기존 `ix_speed_mole_bests`와 V166의 `ix_mole_bests`를 사용한다.
위 붕어빵 측정·V138 설명은 이전 열의 기록으로 남긴다.
