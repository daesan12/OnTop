# 당첨 알림 연결 (S15P31B105-383)

회원이 알림함 첫 페이지를 조회하면 이미 확정되고 발표 시각이 지난 `event_winners`를 확인해 회원·주차당 `EVENT_WINNER` 알림 한 건을 연결한다. 커서로 이전 페이지를 넘길 때는 연결 조회를 생략하고, 첫 페이지에서도 누락된 알림이나 보관 기한 연장이 필요한 건이 있을 때만 쓰기 쿼리를 실행한다. V163의 `(user_id, event_week_start_date)` 유일키를 사용하므로 기존 발표 결과도 최초 조회 시 소급 연결되며, 반복 조회해도 알림이 늘지 않는다. 별도 마이그레이션은 없다.

발표 전 결과는 알림에 연결하거나 상세 응답에 포함하지 않는다. 같은 주차에 나중에 발표되는 부문이 있으면 기존 알림 상세의 `awards` 목록에 추가된다. 알림 목록에는 전화번호를 넣지 않는다. 상세에는 부문·등수·상품·지급 상태, 연락처 제출·수정 여부와 제출 가능 여부만 담는다. 읽음 여부는 알림의 `readAt`으로 관리하며, 창을 닫아도 목록에서 다시 열 수 있다.

회원 당첨 조회와 알림 상세의 `allPrizesDelivered`는 **발표된 해당 주차의 모든 경품**에 지급 완료 기록이 있을 때만 `true`다. 이때 `contactActionRequired`와 `contactEditable`은 `false`이며 연락처 제출 API도 `EVENT_CONTACT_ALREADY_DELIVERED`로 거절한다. 이후 같은 주차의 다른 경품이 발표되면 지급 상태를 다시 계산하므로 미지급 경품이 있는 동안 연락처 입력이 재개된다. 발표 전 당첨 여부는 이 응답에서 드러내지 않는다. 기존 알림은 지급 완료 후에도 보존 기한 안에서 조회할 수 있다. 연락처 원문은 기존 암호화 저장소와 관리자 전용 API에서만 다룬다.

현재 프론트엔드는 새 알림 유형을 파싱하고 당첨 내역을 읽을 수 있으며, 지급 완료 시 자동 연락처 창과 입력 폼을 숨긴다. 알림에서 연락처 입력 창으로 직접 이동하는 흐름은 후속 FE 작업 S15P31B105-387에서 연결한다.
