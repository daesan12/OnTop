# OnTop 효과음 제작 요청 작업명세서

작성일: 2026-10-31 · 버전: 1.0 · 대상: 효과음을 요청하는 게임 담당자와 제작 담당자

## 1. 이 문서를 사용하는 방법

필요한 효과음을 아래 회신 양식으로 정리해 제작 담당자에게 보내 주세요. **팀원은 한글로 원하는 소리와 사용 조건을 작성하면 됩니다. 영문 프롬프트나 오디오 전문 용어를 알 필요는 없습니다.** 제작 담당자가 회신 내용을 바탕으로 Suno 프롬프트를 만들고, 생성 결과를 선별·편집해 전달합니다.

1. 게임별로 필요한 효과음 목록을 적고 기존 소리로 대체할 수 있는지 확인합니다.
2. **소리 하나당 요청서 하나**를 작성합니다. 시작·성공·실패처럼 역할이 다르면 각각 작성합니다.
3. 제작 담당자가 요청을 확인하고 후보를 만든 뒤, 요청자가 실제 사용 상황에서 듣고 선택합니다.

아직 모르는 값은 `제작자 제안 요청`으로 적어 주세요. 제작자는 제안한 값과 확정된 값을 구분해 남깁니다. 다른 게임의 효과음까지 같은 스타일로 맞추거나 기존 소리를 교체하는 작업은 해당 담당자와 범위를 확인합니다.

## 2. 팀원 회신 양식

아래 블록을 복사해 작성합니다. **필수 항목은 모두 회신하되, 미정인 항목은 비워 두지 말고 제안을 요청합니다.** 선택 항목은 해당할 때 작성합니다. 여러 요청을 보낼 때는 같은 양식을 반복합니다.

```text
[효과음 제작 요청]

1. 담당자와 게임 또는 기능 [필수]
- 요청자:
- 게임/기능명:
- 연결 담당자: 요청자와 같음 / 이름 / 미정

2. 효과음 이름과 역할 [필수]
- 이름:
- 역할: 조작 피드백 / 재질감 / 성공·보상 / 실패·경고 / 환경음 / 기타
- 신규 제작 또는 기존 소리 수정:
- 기존 파일명 또는 기존 요청 ID: 없으면 없음

3. 정확히 언제 재생하는지 [필수]
- 재생 조건: 예) 내 캐릭터가 구름 발판에 착지하는 순간
- 재생하면 안 되는 조건: 예) 발판 위에 서 있거나 걸을 때
- 요청 시점과 확정 시점 중 어느 쪽인지: 해당 없으면 해당 없음

4. 원하는 소리 [필수]
- 무엇이 어떻게 움직이는 소리인지:
- 가장 중요하게 들려야 하는 질감:
- 소리의 순서: 예) 빠각 → 꾸욱 → 작게 뽁
- 느낌 또는 의성어:
- 피하고 싶은 소리: 예) 유리 깨짐, 씹는 소리, 날카로운 고음

5. 최종 길이와 시작 시점 [필수]
- 목표 파일 길이: ___초 / 제작자 제안 요청
- 허용 가능한 최대 길이: ___초 / 제작자 제안 요청
- 길이 기준: 정확히 맞춤 / 여운을 살리면 범위 조정 가능
- 사건 발생 후 재생 지연: 즉시 / ___초 뒤 / 제작자 제안 요청
- 맞춰야 할 애니메이션 순간: 없으면 없음

6. 반복 방식 [필수]
- 유형: 한 번 재생 / 누르는 동안 반복 / 계속 반복 / 기타
- 한 동작의 범위: 예) 누르기만 / 누르기와 떼기 / 떼기만
- 자주 발생하는 빈도: 예) 초당 1회 / 연속 클릭 가능 / 드물게 발생
- 새 소리가 나면 이전 소리: 겹쳐 재생 / 끊고 교체 / 연속 요청 생략 / 제안 요청
- 반복음이면: 반복 주기, 자연스럽게 이어져야 하는지, 멈출 때 여운

7. 우선순위와 일정 [필수]
- 우선순위: 필수 / 있으면 좋음
- 필요한 날짜: 날짜 또는 일정 협의

8. 듣는 사람과 공간 [선택]
- 누구에게 들리는지: 본인 / 같은 게임 참가자 / 관전자 포함 / 주변 사람
- 위치감: 화면 중앙 / 좌우 방향 / 월드 위치 / 제안 요청
- 주변 사람에게 들리는 최대 거리: ___m / 연결 담당자 결정
- 본인과 다른 사람의 소리 차이:

9. 참고 자료와 후보 수 [선택]
- 참고 링크 또는 화면·영상 설명:
- 영상에서 참고할 구간: 00:00~00:00
- 참고할 특징: 예) 눌릴 때의 말랑한 질감만 참고
- 처음 비교할 후보 수: 기본 A/B 2개 / 다른 수량
- 최종적으로 필요한 다른 버전 수: 기본 1개 / 반복용 ___개

10. 함께 들리는 소리와 검수 조건 [선택]
- 동시에 나오는 배경음·다른 효과음:
- 소리 크기: 주변 소리보다 작게 / 비슷하게 / 강조 / 제안 요청
- 반드시 확인할 조건: 예) 10회 연속 재생해도 귀가 피곤하지 않음
- 기타:
```

**A/B 후보 2개**는 방향을 비교하기 위한 두 선택지입니다. **반복용 변형 3개**는 게임에서 번갈아 쓸 서로 다른 파일 3개입니다. 두 수량을 구분해 적어 주세요. 위 수량은 이 문서의 작업 기본값 제안이며, 요청에 맞춰 조정합니다.

## 3. 작성 예시

아래는 점프맵 석탑 효과음을 요청하는 예시입니다. 허용 최대 길이와 일정 등은 실제 요청자가 정합니다.

```text
[효과음 제작 요청]

1. 담당자와 게임 또는 기능
- 요청자: 점프맵 담당자
- 게임/기능명: 점프맵 석탑 발판
- 연결 담당자: 점프맵 담당자

2. 효과음 이름과 역할
- 이름: 석탑 왁뿌볼 대표 ASMR
- 역할: 착지 재질감
- 신규 제작 또는 기존 소리 수정: 신규 제작
- 기존 파일명 또는 기존 요청 ID: 없음

3. 정확히 언제 재생하는지
- 재생 조건: 내 캐릭터가 석탑 발판에 착지할 때
- 재생하면 안 되는 조건: 서 있거나 발판 위를 걸을 때
- 요청 시점과 확정 시점: 보상과 무관한 착지 연출

4. 원하는 소리
- 무엇이 어떻게 움직이는 소리인지: 얇은 왁스 껍질이 있는 말랑이 공을 한 번 누름
- 가장 중요한 질감: 껍질이 깨진 다음 말랑한 속이 눌리는 질감
- 소리의 순서: 짧게 빠각 → 두툼하게 꾸욱 → 작게 뽁
- 느낌 또는 의성어: 바삭함과 말랑함이 함께 느껴짐
- 피하고 싶은 소리: 유리 파손, 폭발, 음식 씹기, 과도하게 날카로운 고음

5. 최종 길이와 시작 시점
- 목표 파일 길이: 0.35초
- 허용 가능한 최대 길이: 제작자 제안 요청
- 길이 기준: 말랑한 중간 소리가 잘리면 길이 조정안도 함께 비교
- 사건 발생 후 재생 지연: 착지 후 0.015초
- 맞춰야 할 애니메이션 순간: 첫 크랙과 표면 균열 시작

6. 반복 방식
- 유형: 한 번 재생
- 한 동작의 범위: 누르기와 짧은 풀림
- 발생 빈도: 연속 점프 중 약 0.5~1초마다 발생할 수 있음
- 새 소리가 나면 이전 소리: 연결 담당자가 기존 착지 중복 방지 규칙 적용
- 반복음: 해당 없음

7. 우선순위와 일정
- 우선순위: 필수
- 필요한 날짜: 일정 협의

8~10. 추가 조건
- 처음 비교할 후보: A/B 2개
- 최종 변형 수: 대표 소리 선택 후 결정
- 고유 돌 착지음이 별도로 겹칠 수 있으므로 추가 돌 충격음은 과하게 넣지 않음
- 검수: 빠각만 들리지 않고 꾸욱 눌리는 중간 질감이 분명히 들려야 함
```

## 4. 길이와 재생 시점을 적는 기준

**파일 길이, 재생 지연, 애니메이션 길이는 서로 다른 값입니다.** 아래처럼 각각 적습니다.

| 항목 | 뜻 | 예시 |
| --- | --- | --- |
| 최종 파일 길이 | 소리와 필요한 여운을 포함한 편집 후 길이 | 0.35초 |
| 재생 지연 | 게임 사건 이후 소리가 시작될 때까지의 간격 | 착지 후 0.015초 |
| 애니메이션 길이 | 눌림·복원 등 화면 연출 전체 시간 | 0.8초 |
| 동작 동기화 | 특정 시각 효과와 소리가 만나는 순간 | 착지 후 0.28초에 복원음 시작 |

- `100ms = 0.10초`, `15ms = 0.015초`, `280ms = 0.280초`입니다.
- 재생 지연은 게임 코드에서 적용합니다. **파일 앞에 지연 시간만큼 무음을 넣지 않습니다.**
- Suno 프롬프트에 적은 초는 생성 목표입니다. 생성된 원본 길이와 최종 편집 길이를 따로 기록합니다.
- 짧게 자르면 핵심 질감이 사라지는 경우, 목표 길이 버전과 자연스러운 여운 버전을 비교해 결정합니다. 시간을 맞추기 위해 임의로 빠르게 재생하지 않습니다.

아래 범위는 길이를 정하기 어려울 때 참고하는 **제작 시작값 제안**입니다. 게임 규칙이나 확정된 제한으로 취급하지 않습니다.

| 사용 상황 | 처음 비교할 길이 | 작성할 때 확인할 것 |
| --- | --- | --- |
| 버튼·키캡·작은 클릭 | 0.05~0.15초 | 짧은 클릭인지 누르기와 떼기 전체인지 |
| 착지·크런치·스퀴시 | 0.15~0.40초 | 충격 뒤 눌림이나 풀림이 필요한지 |
| 물방울·팝·작은 반응 | 0.10~0.25초 | 한 번의 소리인지 여러 방울인지 |
| 종·보상·짧은 알림 | 0.30~0.90초 | 여운이 다른 안내를 가리지 않는지 |
| 성공·실패 연출 | 0.5~2.0초 | 다음 조작이 언제 시작되는지 |
| 환경음·지속 조작음 | 요청별 결정 | 반복 주기와 시작·종료 동작 |

## 5. 요청을 Suno 프롬프트로 바꾸는 방법

이 절은 제작 담당자가 사용합니다. 요청자는 앞의 회신 양식까지만 작성해도 됩니다.

### 제작 전 확인

1. 소리의 대상, 동작, 핵심 질감, 최종 길이, 반복 방식을 확인합니다.
2. 기존 효과음을 재사용할 수 있으면 해당 파일과 차이를 먼저 확인합니다.
3. 별도 시점에 나오는 소리는 나눕니다. 예를 들어 `구름 착지 푸욱`과 `0.28초 뒤 복원 뿅`은 별도 파일입니다.
4. 한 파일에 이미 포함된 작은 팝이나 크랙을 다른 층에서 또 겹치지 않도록 구성 요소를 적습니다.

### One Shot 기본 프롬프트

아래는 제작자가 채우는 템플릿입니다. 실제로 Suno에 넣을 때는 대괄호를 모두 구체적인 문장으로 바꿉니다.

```text
Isolated close-miked game sound effect. One shot, one action.
Start immediately. Dry recording, no reverb, music, voices or background noise.
[Object or material] being [one physical action].
[Main texture and short sound sequence].
Emphasize [the most important audible detail].
Target audible duration: [seconds] seconds.
Avoid [specific unwanted sounds].
```

`no voices` 등은 일반 비음성 효과음의 기본 조건입니다. 대사·인사·군중 소리처럼 사람이 내는 소리 자체가 요청이면 관련 조건을 빼거나 바꿉니다. 공간 잔향도 요청된 경우에만 추가합니다.

### 점프맵 예시의 완성 프롬프트

공통 조건까지 포함했으므로 아래 블록 전체를 그대로 넣을 수 있습니다.

```text
Isolated close-miked ASMR game SFX. One shot, one action. Start immediately. Dry, no reverb, music, voices or background noise. Squeeze a wax-coated squishy stress ball once. A thin brittle shell gives a crisp crack, followed by a prominent thick soft squish as the yielding center compresses, ending in a tiny sticky release pop. Emphasize the squishy middle, not just the crack. No glass, explosion or chewing. Target audible duration: 0.35 seconds.
```

### 반복음 기본 프롬프트

```text
Isolated seamless game sound loop of [source and continuous action].
[Texture, intensity and pace]. Consistent sound with no sudden accents.
No distinct beginning or ending. No music, voices or unrelated ambience.
Target loop duration: [seconds] seconds.
Avoid [specific unwanted sounds].
```

반복음은 `Loop`로 제작하고, 경계에서 끊김이나 클릭이 나는지 따로 확인합니다. 시작음·종료음이 필요하면 별도 요청서로 받습니다.

현재 작업에서 확인한 Suno Sounds 설명란은 **500자 제한**이었습니다. 공통 문장을 포함한 전체 길이를 확인하고, 입력 제한이나 화면 구성이 바뀌면 실제 화면을 기준으로 조정합니다. 짧은 효과음은 `Sounds → One-Shot`, 계속 이어지는 음은 `Sounds → Loop`를 사용합니다.

## 6. 제작 결과 전달 기준

### 파일과 이력

- 원본 생성 파일과 편집본을 별도 폴더에 보존합니다. 원본을 덮어쓰지 않습니다.
- 후보에는 요청 ID와 A/B를 붙이고, 최종 선정본은 반복용 변형 번호와 수정 버전을 구분합니다.
- 요청별로 사용한 프롬프트, 생성 링크, 실제 원본 길이, 잘라낸 시작·끝, 최종 길이를 기록합니다.
- 작업 전달용 기본값은 **모노 48kHz 16bit PCM WAV**로 제안합니다. 스테레오·공간음·다른 규격은 연결 담당자와 정합니다.
- 원본이 MP3이면 그 사실을 기록합니다. WAV로 변환해도 원본의 압축 손실이 복구되지는 않습니다.
- 배포용 압축 파일과 프로젝트 저장 경로는 연결 담당자가 기존 구조에 맞춥니다. 기존 공통 효과음 설정과 오디오 출력을 재사용합니다.

파일명 제안:

```text
요청 ID: sfx_<game_or_feature>_<event>
후보:    sfx_<game_or_feature>_<event>_candidate_a.wav
변형:    sfx_<game_or_feature>_<event>_01_v1.wav
수정본:  sfx_<game_or_feature>_<event>_01_v2.wav

예: sfx_jumpmap_stone_land_candidate_a.wav
예: sfx_jumpmap_stone_land_01_v1.wav
```

### 완료를 구분하는 상태

| 상태 | 확인할 증거 |
| --- | --- |
| 요청 정리 | 재생 조건과 원하는 소리, 길이가 작성됨 |
| 후보 생성 | 후보를 재생할 수 있는 생성 결과가 있음 |
| 원본 확보 | 로컬 파일이 있고 정상적으로 디코딩·재생됨 |
| 편집 완료 | 길이·무음·끝 처리 등을 확인한 편집 파일이 있음 |
| 청취 확인 | 요청자가 실제 소리를 듣고 후보를 선택함 |
| 게임 적용 확인 | 담당자가 실제 장면에서 시점·음량·반복을 확인함 |

**생성 완료를 다운로드 완료나 게임 적용 완료로 보고하지 않습니다.** 다운로드 버튼을 누른 사실만으로 원본 확보 상태로 바꾸지 않습니다.

### 검수 체크리스트

- [ ] 원본과 최종 파일이 실제로 열리고 재생된다.
- [ ] 요청한 동작과 핵심 질감이 들린다. 파형 분석만으로 재질감을 합격 처리하지 않는다.
- [ ] 목표 길이와 허용 최대 길이를 만족하거나, 조정한 이유가 기록되어 있다.
- [ ] 앞 무음은 원칙적으로 0~0.005초를 목표로 정리했다.
- [ ] 끝은 약 0.005~0.015초 범위에서 필요한 만큼 페이드 처리해 클릭을 줄였다.
- [ ] 작은 클릭·종소리 등 소리의 공격감과 여운이 편집 때문에 훼손되지 않았다.
- [ ] 클리핑이 없고, 연속 재생해도 과하게 날카롭거나 피곤하지 않다.
- [ ] 다른 효과음·배경음과 함께 들어도 필요한 정보가 구분된다.
- [ ] 루프는 연결부와 종료가 자연스럽다. 단발음은 불필요한 반복이 없다.
- [ ] 공개 참고 자료는 질감 참고로 사용하고, 가져온 음원이 있으면 사용 조건과 출처를 기록했다.

일반 단발 효과음은 10회 이상 연속 재생해 비교합니다. 보상·정산음은 담당자가 서버 확정 이벤트 등 실제 의미에 맞는 시점에 연결합니다. 파일 제작과 게임 로직 변경은 별도 범위로 관리합니다.

## 7. 수정 요청을 보내는 방법

`더 좋게`, `좀 더 말랑하게`만 적으면 비교 기준이 달라질 수 있습니다. 후보 이름과 유지할 부분, 바꿀 부분을 함께 적어 주세요.

```text
[효과음 수정 요청]
- 요청 ID와 후보 또는 파일명:
- 유지할 부분:
- 바꿀 부분:
- 문제가 들리는 구간: ___초~___초 / 전체
- 길이 변경 여부:
- 원하는 변화: 예) 첫 빠각은 유지하고, 뒤쪽 꾸욱이 더 오래 들리게
- 확인할 기준: 예) 뽁 소리가 키보드 클릭처럼 날카롭게 들리지 않게
```

## 8. AI에게 요청 정리를 맡길 때 쓰는 프롬프트

팀원이 원하는 효과음을 편하게 설명한 뒤, 아래 프롬프트와 함께 보내면 요청서 형태로 정리할 수 있습니다.

```text
OnTop 효과음 제작 담당자에게 보낼 요청서를 정리해 줘.
내가 설명하는 효과음마다 별도 요청서를 만들고 아래 항목으로 작성해 줘.

필수 항목:
1. 담당자와 게임/기능
2. 효과음 이름, 역할, 신규 또는 수정 여부
3. 정확한 재생 조건과 재생하면 안 되는 조건
4. 소리의 대상과 동작, 핵심 질감, 소리 순서, 피할 소리
5. 최종 목표 길이, 허용 최대 길이, 사건 이후 재생 지연, 애니메이션 동기화
6. 단발/반복 방식, 한 동작의 범위, 발생 빈도, 겹침 처리
7. 우선순위와 필요한 날짜

선택 항목:
듣는 사람과 위치감, 참고 링크와 영상 구간, 비교 후보 수,
최종 변형 수, 함께 들리는 소리, 청취 합격 기준.

내가 말하지 않은 값은 확정하지 말고 '제작자 제안 요청'으로 표시해 줘.
중요한 재생 조건이나 원하는 재질이 불분명하면 필요한 질문만 최대 3개 해 줘.
파일 길이, 재생 지연, 애니메이션 길이를 구분하고 시간 단위는 초로 통일해 줘.
한 번 누르는 소리와 떼는 소리의 시점이 다르면 별도 파일이 필요한지 표시해 줘.
영문 생성 프롬프트나 게임 구현 코드는 아직 만들지 마.

내가 원하는 효과음:
[여기에 원하는 소리와 사용 상황을 자유롭게 작성]
```

제작 담당자는 회신받은 요청서를 다음 프롬프트와 함께 사용하면 됩니다.

```text
첨부한 효과음 요청서와 작업명세서를 기준으로 제작 목록을 만들어 줘.
1. 효과음별로 요청 ID, 재생 조건, 목표 길이, 최대 길이, 재생 지연,
   반복 방식, 비교 후보 수와 최종 변형 수를 표로 정리해 줘.
2. 요청에서 확정된 값과 네가 제안하는 값을 구분해 줘.
3. 각 소리의 Suno 입력용 영문 프롬프트를 별도 코드 블록으로 작성해 줘.
   공통 조건까지 포함하고, 대괄호나 별도 공통 문장을 남기지 마.
   현재 입력란의 글자 제한에 맞추고, 500자 제한 화면이면 전체를 500자 이내로 만들어 줘.
4. One-Shot과 Loop를 구분하고, 별도 시점에 재생할 구성 요소는 파일을 분리해 줘.
5. 게임에서 적용할 지연 시간을 파일 앞 무음으로 넣도록 요청하지 마.
6. 파일명, 필요한 편집 작업, 요청자가 확인할 청취 기준을 함께 적어 줘.
7. 생성 길이가 정확히 지켜진다고 보장하지 말고 최종 편집 길이로 구분해 줘.
아직 생성·다운로드·게시·게임 코드 변경은 실행하지 마.
```
