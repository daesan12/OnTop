# 구구구 줄넘기 API

세 경로 모두 `Authorization: Bearer <accessToken>`을 사용합니다. 서버는 인증된 사용자 ID로 라운드 소유권과 개인 기록을 확인합니다. 응답은 `Cache-Control: no-store`를 포함합니다. 응답의 `id`와 경로의 `roundId`는 숫자로 변환하지 않고 문자열로 보관합니다.

## `POST /api/v1/minigames/jump-rope/rounds`

요청 본문은 비워 두고 `Idempotency-Key` 헤더를 한 개 보냅니다. 키는 영문, 숫자, `_`, `-`로 이루어진 1~64자입니다. 네트워크 오류에는 같은 키를 재사용하고, 새 판을 시작할 때 새 키를 발급합니다. 같은 키로 활성 판을 다시 요청하면 새 `serverNow`와 기존 `startedAt`, `expiresAt`, `seed`, `id`를 받습니다. 새 판이 발급되면 이전 미확정 판의 제출은 `409 JUMP_ROPE_ROUND_SUPERSEDED`가 됩니다.

참가비는 0냥입니다.

`201 Created` 응답 예시입니다.

```json
{"id":"40901","seed":123456789,"rulesVersion":1,"serverNow":"2026-11-12T00:00:00Z","startedAt":"2026-11-12T00:00:03Z","expiresAt":"2026-11-12T00:01:38Z","durationMs":60000}
```

`startedAt`은 서버 발급 시각의 3초 후이고 `expiresAt`은 `startedAt`의 95초 후입니다. FE는 `startedAt`을 단조 증가하는 로컬 시계에 매핑해 카운트다운과 플레이 시작을 맞춥니다. 응답을 다시 받았을 때 3초를 새로 더하면 안 됩니다. 시드는 방해 연출 재현에 사용합니다.

`rulesVersion`은 서버 설정 `ontop.minigames.jump-rope-rules-version`(환경변수 `JUMP_ROPE_RULES_VERSION`, 기본 `1`)으로 정합니다. `2`이면 탑골 할아버지 난입과 숙이기 규칙을 적용하며, 시드로 할아버지 일정도 정합니다. 판은 시작할 때 저장한 버전으로 끝까지 판정합니다. 설정을 바꾼 뒤에도 같은 키 재시도는 기존 판과 버전을 그대로 돌려주고, 이미 시작한 판도 원래 버전으로 완료할 수 있습니다. FE는 응답의 `rulesVersion`에 맞는 규칙과 제출 형식을 사용해야 합니다.

## `POST /api/v1/minigames/jump-rope/rounds/{roundId}/complete`

`Content-Type: application/json`으로 수락된 점프만 시간순으로 보냅니다. 요청 예시입니다.

```json
{"jumpOffsetsUs":[728335,1723348]}
```

- 실제 플레이 시작을 0으로 두고, 카운트다운과 MISS로 정지한 구간을 제외합니다. 수락한 입력의 시각을 `Math.round(activeElapsedMs * 1000)`으로 변환합니다. 범위는 `0`~`59_999_999`, 최대 128개이며 엄격한 오름차순입니다. 빈 배열은 유효합니다.
- 랭킹 플레이의 판정에는 같은 정규화 입력을 사용합니다. `n`번째 줄 통과 시각은 실제 플레이 시간 기준 `Math.round(-300000 * Math.expm1(-n / 300) * 1000)`입니다. 60초 이후의 통과는 판정하지 않습니다. 같은 시각에서는 시간 만료, 줄 통과, 새 점프 순으로 처리합니다. MISS와 같은 마이크로초의 입력은 수락하지 않습니다.
- 판정은 준비 70ms, 체공 400ms, 정점 0.6m 기준입니다. 발 높이 0.082m 이상에서 입력 선행 시간이 220~320ms이면 PERFECT이고 그 외 성공은 GOOD입니다. MISS로 점프 상태를 초기화하기 전에는 직전 수락 입력부터 515ms가 지나야 재점프할 수 있습니다. 1·2번째 MISS 이후 자세 복귀와 1,350ms 연출 동안 실제 플레이 시계를 멈추고, 재개 시 점프 상태를 비운 채 기존 가속을 이어갑니다. 랭킹 모드는 개발용 수동 일시정지와 규칙 설정 변경을 차단해야 합니다.
- FE는 판이 끝난 뒤 로그를 제출합니다. 서버는 로그로 종료 사유와 점수를 재계산하고, `startedAt` 이후 해당 결과에 필요한 최소 실제 시간이 지난 경우에 정산합니다. 만료 전 같은 라운드에 같은 로그를 보내면 동일한 결과가 반환됩니다. 네트워크 장애나 `503`이면 같은 라운드 ID와 로그로 재시도합니다. `JUMP_ROPE_NOT_FINISHED`이면 잠시 뒤 동일 로그를 재시도할 수 있습니다. 다른 로그의 재제출은 `409 JUMP_ROPE_INPUT_CONFLICT`, 만료 이후 제출은 `409 JUMP_ROPE_ROUND_EXPIRED`입니다. 타인 소유이거나 존재하지 않는 판은 `404 JUMP_ROPE_ROUND_NOT_FOUND`입니다.

### `rulesVersion: 2` 판의 제출과 판정

v2 판은 점프 로그와 함께 숙이기(↓ 또는 S) 유지 구간을 보냅니다. 빈 배열도 유효하지만 필드는 생략할 수 없습니다. v1 판에 `duckSpansUs`를 보내거나 v2 판에 빠뜨리면 `400 JUMP_ROPE_INVALID_INPUTS`입니다. 두 필드의 순서는 상관없습니다. 형태 예시입니다(배열 일부 생략).

```text
{"jumpOffsetsUs":[728335,1723348,…,59314480],"duckSpansUs":[[19227904,19947904],[21092696,21812696],…]}
```

- 구간은 `[startUs, endUs]` 정수 쌍이며 점프 로그와 같은 실제 플레이 시계(`Math.round(activeElapsedMs * 1000)`)를 씁니다. 두 키 중 하나라도 눌려 있는 동안을 한 구간으로 기록합니다. 최대 64개이고 `0 ≤ startUs < endUs ≤ 60000000`이며, 앞 구간의 `endUs`보다 다음 `startUs`가 커야 합니다.
- MISS로 정지한 동안 키를 누르거나 떼면 그 MISS 통과 시각으로 기록합니다. 같은 마이크로초에 떼고 다시 누른 경우(정지 중 떼고 다시 누르기 포함)는 한 구간으로 합쳐 보냅니다. 길이가 0인 구간은 보내지 않습니다.
- 판이 끝날 때 누르고 있던 구간은 마지막 플레이 시각으로 닫습니다. 60초 완주면 `60000000`, MISS 3회 조기 종료면 3번째 MISS 통과 시각입니다. 조기 종료 판에서 이 시각보다 늦게 끝나는 구간은 `400`입니다.
- 숙이기를 누르고 있는 동안과 빗자루 스턴 중에는 Space를 점프로 수락하지 않습니다. 따라서 구간 안(`startUs ≤ 점프 ≤ endUs`, 경계 포함)의 점프와 스턴 중의 점프는 `400`입니다. FE는 떼는 시각과 같은 마이크로초의 Space를 무시하고, 수락한 점프와 같은 마이크로초의 숙이기는 다음 마이크로초로 기록합니다. 착지 전 숙이기는 착지 시각부터 시작하므로 판정 결과는 같습니다.

서버는 FE가 계산한 점수·MISS·스턴을 받지 않고, 위 로그와 판의 `seed`로 전부 다시 계산합니다.

- 할아버지 일정은 FE 프리뷰 `planGrandpaEvents`와 같은 배정밀도 계산으로 정합니다. 시드에서 `grandpaSeed`와 Mulberry32를 만들고 구간마다 난수를 한 번 뽑습니다. 15~30초 구간은 안전 1회와 위험 2회, 40~60초 구간은 위험 3회입니다. 스윙은 줄 통과 2회 간격입니다. 등장 2.2초부터 퇴장 1.65초까지가 구간 안에 들고, 마지막 위험 스윙 뒤 줄 통과가 60초 전에 있는 첫 스윙 후보 중 하나를 고릅니다.
- 위험 스윙 뒤 회전은 930ms보다 짧으면 부족한 만큼 늘립니다. 늘린 양은 `Math.ceil((930 - 그 회전의 v1 주기 ms) * 1000)`μs이고, 이후 통과 시각은 모두 그만큼 밀립니다. `n`번째 줄 통과는 v1 통과 시각에 이전 위험 스윙들의 늘린 양을 더한 정수 μs이며, 빗자루 충돌은 기준 통과 + 480,000μs입니다.
- 충돌 순간 숙이기가 끝나 있으면 회피, 아니면 피격입니다. 숙이기 완료 시각은 시작 + 60,000μs이고, 시작은 키를 누른 시각과 공중이던 직전 점프의 착지 시각(점프 + 470,000μs) 중 늦은 쪽입니다. 누르고 있는 동안 MISS가 나면 그 MISS 통과 시각부터 다시 시작합니다.
- 같은 마이크로초에서는 시간 만료, 줄 통과 또는 빗자루 충돌, 입력 순으로 처리합니다. 따라서 충돌과 같은 시각에 누르면 피격, 같은 시각에 떼면 회피입니다.
- 피격 1회는 다음 줄 통과 1회를 MISS로 만들고, 그 통과에서 스턴이 풀립니다. 이 MISS도 일반 MISS와 같이 점프 상태 초기화, 콤보 초기화, 실제 시계 정지(복귀 대기 + 1,350ms), 기회 차감을 적용합니다. 안전 스윙은 판정에 영향이 없습니다.
- 점수, 판정 경계, 최대 점수(1,965점), 50점당 1냥 보상, 일일 한도와 재시도 규칙은 v1과 같습니다. 같은 로그 재제출은 v2 전용 해시(버전, 점프 수, 점프, 구간 수, 구간 쌍의 int32 순서)로 비교합니다.

`200 OK`의 `reward`는 서버가 실제로 지급한 엽전의 정수 수량입니다. `endReason: "time"`인 60초 완주에만 서버 확정 점수 50점당 1냥을 지급하며 나머지는 버립니다. MISS가 1~2회여도 완주하면 지급 대상입니다. 미니게임 공통 일일 한도(한국 시간 자정 기준 1,000냥)의 남은 범위까지만 지급합니다. 조기 종료(`missLimit`), 50점 미만, 한도 소진, 보상 도입 전에 확정된 기록에는 `reward: 0`을 반환합니다. 만료 전 동일 로그 재시도는 최초 지급액을 그대로 반환합니다.

1,965점 완주 및 남은 한도가 충분할 때의 예시입니다.

```json
{"id":"40901","rulesVersion":1,"score":1965,"counts":{"perfect":66,"good":0,"miss":0},"endReason":"time","completedAt":"2026-11-12T00:01:03Z","reward":39}
```

FE는 완료 응답의 점수·판정 횟수와 함께 `reward`를 표시합니다. 지급액은 로컬 점수로 계산하지 않습니다. 실제 지급이 있으면 기존 지갑 조회 경로로 표시 잔액을 갱신할 수 있습니다.

## `GET /api/v1/minigames/jump-rope/rankings`

기본값은 `limit=10&offset=0`입니다. `limit`은 1~10, `offset`은 0~10,000입니다. KST 2026-11-16 14:00 이상 시작하고 11/19 00:00 미만 완료한 기록에서 신규 판 설정과 같은 규칙 버전(응답의 `rulesVersion`)의 확정 기록에서 사용자별 최고 기록을 골라 점수 내림차순, MISS 횟수 오름차순으로 매깁니다. 두 값이 같으면 공동 순위(`1, 1, 3`)이며 표시 순서는 완료 시각, 라운드 ID 순입니다. `me`는 페이지에 관계없이 전체 순위 기준의 개인 최고 기록입니다. 기록이 없으면 `null`입니다. FE는 목록의 배열 인덱스 대신 응답의 `rank`를 표시합니다.

```json
{"rulesVersion":1,"period":"EVENT","startsAt":"2026-11-16T05:00:00Z","endsAtExclusive":"2026-11-18T15:00:00Z","updatedAt":"2026-11-16T06:00:12Z","totalParticipants":1,"offset":0,"limit":10,"items":[{"rank":1,"nickname":"한강줄넘기","score":45}],"me":null,"hasMore":false}
```

오류 본문은 `{"code":"JUMP_ROPE_INVALID_INPUTS","message":"점프 기록의 시간과 순서를 확인해 주세요."}` 형태입니다. 버전이 다른 기록은 지우지 않고 보존하지만 순위에는 섞지 않습니다. 점프 판정 경계와 줄 통과 검산에는 [v1 공통 테스트 데이터](../../backend/src/test/resources/jump-rope/rules-v1.json)를 사용할 수 있습니다. v2의 할아버지 일정, 통과·충돌 시각, FE 엔진으로 플레이한 판의 로그와 결과는 [v2 공통 테스트 데이터](../../backend/src/test/resources/jump-rope/rules-v2.json)에 있습니다. 전체 응답 스키마는 [OpenAPI](openapi.yaml)에 있습니다.

기간 필터는 사용자별 최고 선택 전에 적용하며 목록·me·totalParticipants가 같은 범위를 사용한다. 11/18 23:59 전체 분 포함, 과거 데이터 삭제 없음. 시작 전에는 빈 목록이며 종료 후에도 이 이벤트 결과를 조회한다.
