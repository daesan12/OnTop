## 변경 내용

- 틀린그림찾기: 기존 2인 대결 엔진과 준비·점수·종료 계약을 유지한다. 공개 방 이름(최대 40자)과 참가 가능한 방 목록을 추가하고 코드 입력·복사를 화면에서 제거했다. 3초마다 목록을 갱신하며, 만석·종료·만료·방장 응답이 45초 이상 없는 방은 목록에서 제외하고 신규 참가도 거절한다.
- `GET /api/v1/minigames/spot-difference/duels`: 인증된 공개 목록 조회. 방 ID·이름·난이도·인원·정원만 반환하며 문제·정답·개인 상태는 반환하지 않는다. 생성 요청에는 선택적인 `title`을 추가했다. 참가·준비·점수·이탈은 기존 API를 재사용한다.
- 탈것: 첫 구간을 탑승 시 선결제한다. 자전거는 20초에 1냥, 킥보드는 10초에 1냥이며 구간마다 추가 결제한다. 결제 순번·영수증·취소 및 중복 결제 방어를 유지한다. PC·XR 요금 안내도 같은 단위로 바꿨다.
- 열기구: 기존 바닥·건물 조회로 현재 위치 및 진행 방향 1초 앞을 확인해 접근 경고를 표시한다. 화면 가장자리는 1초 주기로 밝아지고 안내 문구는 계속 보인다. 입력을 가로채지 않으며 동작 줄이기 설정에서는 깜박임을 없앤다. 승강장 복귀는 기존 수평/수직 속도 제한을 유지하고 경로의 장애물 높이를 확인하여 불필요한 54m 상승을 줄인다.

## 두 계정 로컬 확인

- FE: `http://127.0.0.1:5511/stone-rumble-park.html?role=1` 및 `?role=2`.
- BE: `http://127.0.0.1:19193`. 서로 다른 테스트 계정으로 자동 인증하고 `channel-1`에 입장한다. 두 계정의 로그인·진입과 이동을 확인했다. 로컬 테스트 계정/지갑은 메모리 대역이고, 공원 물리·채널·틀린그림찾기 대결·대여 결제 주기 및 열기구 탑승 계약은 실제 애플리케이션 코드다.
- 사격장으로 이동한 뒤 멀티플레이를 선택한다. 한 계정은 방 이름과 난이도를 선택해 생성하고 다른 계정은 목록의 참가하기를 누른다. 탑승 요금은 대여소 안내에서, 열기구 경고는 승강장 탑승 후 지면/건물에 접근하여 확인한다.
- 다른 작업의 5501/19191 서버는 보존했다. 이번 작업의 로컬 실행은 기존 Vite 환경변수와 테스트 실행 인수를 사용하며 설정 파일은 변경하지 않았다. 서버 PID·로그는 각 모듈의 무시되는 `.vite-cache/qa-feedback/`, `.gradle/qa-feedback/`에 있다.
- `StoneRumbleParkApplication`의 선택적인 `ontop.qa-feedback.enabled` 테스트 전용 fixture를 사용한다. 운영 JAR에는 포함되지 않는다. DB가 필요한 공지·랭킹 등 부가 API는 503을 반환할 수 있다.
- MR·머지·배포 및 작업 브랜치 삭제는 진행하지 않는다. 사용자 로컬 검수 후 명시적인 MR 생성 요청을 기다린다.
