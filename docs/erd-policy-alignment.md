# ERD 정책과 현재 구현의 연결 상태

2026-10-19 [Notion 1차 ERD 설계 정책](https://app.notion.com/p/1-ERD-3fe161842b868044a670e2b147f54079)과 브라우저의 [OnTop 초안 ERD](https://www.erdcloud.com/d/fb3woEfx3FLMCny9H)를 읽었다. MM 헤더는 앱 접근 오류·브라우저 미로그인으로 직접 확인하지 못했다. 열람한 ERD가 헤더의 링크와 동일한지는 확인이 필요하다.

## 사용자 정정

Notion의 “준비 버튼 없이 정원이 차면 시작” 대신 사용자가 직접 정정한 **정원 충족 + 전원 준비 → 카운트다운 → 시작 처리**를 적용한다. 외부 Notion 문구를 수정한 것은 아니다.

| 영역 | 최신 정책 | 현재 상태·남은 연결 |
| --- | --- | --- |
| 저장 | MySQL, UTC, TIMESTAMP(3), Enum + VARCHAR | 현재 local은 메모리. 엔티티·DB는 팀원 영역과 조율 |
| 인증 | SSAFY·네이버, 제공자/외부 ID 복합 UNIQUE | dev 임시 사용자에서 실제 계정 연결 필요 |
| 인원·베팅 | required_players=2 또는 4, 인당 동일 양수 베팅 | 현재 2석·검증용 고정 1. 정식 인원·금액 설정은 후속 |
| 시작 | 전원 준비 후 카운트다운, 취소·퇴장 시 취소 | 이번 local 검증에 구현. 기본 대기 모드는 유지 |
| 재화 | 착석 때 잔액 확인만, 시작 때 전원 재검증·예약·게임 기록을 한 트랜잭션으로 처리 | B의 정식 서비스 연결 필요. 대역은 실제 예약·차감 없음 |
| 종료 | 최종 종료 시 일괄 정산. 무승부·무효는 예약 해제 | 미구현 |
| 이탈 | AI 대행 제외, 2인 비정상 종료는 30초 유예 | 재접속·기권 처리는 후속 |

게임 시작 전 대기방·좌석은 메모리이며 실제 시작한 경기만 DB에 기록한다. 준비·카운트다운 때문에 DB 세션을 미리 생성하지 않는다.

## 스키마 대조 사항

Notion은 `user_id`, `coin_balance`, `reserved_coin_balance`, `profile_image_url`을 표기한다. 열람한 ERD는 사용자 PK `id`, 지갑 `balance`/`reserved_balance`, 사용자 `character_gender`를 사용한다. 의미 규칙과 물리 컬럼명을 구분하고 DB 담당자의 최종 DDL로 연결해야 한다. SQL 미리보기에는 한글 테이블명과 일부 제약 미포함이 보여 마이그레이션으로 실행하지 않았으며 ERD 원본도 수정하지 않았다.

사용자가 시작 초안 공유 완료를 알렸다. 공유 완료를 모든 항목의 합의 완료로 표시하지 않는다. [기존 초안](game-start-contract-draft.md)의 고정 1엽전·즉시 차감·AI 대행 가정은 최신 정책과 다르다. 정식 연결 전 예약 기반 입출력으로 갱신해야 하며, 이번에는 DB 스키마와 무관한 카운트다운·취소 경계부터 구현했다.
