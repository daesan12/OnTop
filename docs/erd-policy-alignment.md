# OnTop 제품 기준과 ERD 연결 상태

2026-10-19 [Notion 1차 ERD 설계 정책](https://app.notion.com/p/1-ERD-3fe161842b868044a670e2b147f54079)과 브라우저의 [OnTop 초안 ERD](https://www.erdcloud.com/d/fb3woEfx3FLMCny9H)를 읽었다. MM 헤더는 앱 접근 오류·브라우저 미로그인으로 직접 확인하지 못했다. 열람한 ERD가 헤더의 링크와 동일한지는 확인이 필요하다.

## 우선 적용할 제품 문서

사용자가 [OnTop 통합 기획서 v0.4](https://app.notion.com/p/OnTop_-_-154161842b868387b6ad0174db68ee71)를 앞으로의 제품 기준으로 지정했다. 부모 ‘기획 문서’의 오래된 v0.3 본문이나 별도 ‘1차 ERD 설계 정책 정리’와 구분한다.

OnTop의 ‘현재 프로토타입에서 확인한 UX’에는 **먼저 앉은 이용자가 게임을 고르고, 2명 이상 착석한 참가자가 모두 대국 준비를 누르면 시작**한다고 적혀 있다. 사용자의 직접 정정·기준 지정에 따라 별도 카운트다운 없이 전원 준비 후 시작 요청을 보낸다. 정원이 꽉 차야 한다는 문구는 없으며, 현재 local은 오목·주사위 2명, 원카드·거짓말 2~4명을 반영했으며 실제 엔진·DB 검증은 별도다. 외부 Notion 문구는 수정하지 않았다.

직전 구현의 ‘정원 충족 + 준비 + 카운트다운’은 서로 다른 문서를 잘못 합친 해석이었다. 타이머와 관련 상태·화면·설정·테스트를 제거하고 전원 준비 후 즉시 요청으로 수정했다. 기존 검증 이력은 당시 수행 사실로 보존한다.

| 영역 | 최신 정책 | 현재 상태·남은 연결 |
| --- | --- | --- |
| 저장 | MySQL, UTC, TIMESTAMP(3), Enum + VARCHAR | 현재 local은 메모리. 엔티티·DB는 팀원 영역과 조율 |
| 인증 | SSAFY·네이버, 제공자/외부 ID 복합 UNIQUE | dev 임시 사용자에서 실제 계정 연결 필요 |
| 인원·베팅 | OnTop은 2명 이상·전원 준비 및 기본 1엽전, ERD 문서는 필요 인원 2/4·인당 양수 설정 | 현재 게임별 2~4인·검증용 고정 1. 정식 DB·금액 연결은 후속이며 두 문서 내용을 자동 병합하지 않음 |
| 시작 | 사용자 지정 OnTop 기준: 전원 준비 후 즉시 시작 요청 | 카운트다운 제거. 실제 경기·DB 성공과 local 검증 결과를 구분 |
| 재화 | 착석 때 잔액 확인만, 시작 때 전원 재검증·예약·게임 기록을 한 트랜잭션으로 처리 | B의 정식 서비스 연결 필요. 대역은 실제 예약·차감 없음 |
| 종료 | 최종 종료 시 일괄 정산. 무승부·무효는 예약 해제 | 미구현 |
| 이탈 | AI 대행 제외, 2인 비정상 종료는 30초 유예 | 재접속·기권 처리는 후속 |

게임 시작 전 대기방·좌석은 메모리다. DB 담당자 연결 없이 실제 게임 세션을 임의 생성하지 않는다. 재화·스키마 행은 ERD 참고 정책이며 제품 기준과 다른 내용까지 일괄 확정한 뜻은 아니다.

## 스키마 대조 사항

Notion은 `user_id`, `coin_balance`, `reserved_coin_balance`, `profile_image_url`을 표기한다. 열람한 ERD는 사용자 PK `id`, 지갑 `balance`/`reserved_balance`, 사용자 `character_gender`를 사용한다. 의미 규칙과 물리 컬럼명을 구분하고 DB 담당자의 최종 DDL로 연결해야 한다. SQL 미리보기에는 한글 테이블명과 일부 제약 미포함이 보여 마이그레이션으로 실행하지 않았으며 ERD 원본도 수정하지 않았다.

사용자가 시작 초안 공유 완료를 알렸다. 공유 완료를 모든 항목의 합의 완료로 표시하지 않는다. [기존 초안](game-start-contract-draft.md)의 시작 시 재화 처리·AI 대행 가정과 ERD 예약 정책은 정식 연결 전 대조가 필요하다. DB 스키마와 무관한 전원 준비 후 시작 경계를 OnTop 기준으로 수정했다.

후속으로 [첫 착석자의 게임 선택](websocket-api/07-game-select.md)을 local에 연결했다. 선택 코드는 실제 DB 게임 ID가 아니며, 선택자 이탈 시 남은 참가자에게 권한을 넘기는 규칙은 2026-10-19 사용자 확인으로 보완했다. 게임별 2~4인 착석·전원 준비를 연결했고 게임별 세부 설정·실제 경기는 미구현이다.

## 2026-10-26 참가비 확정

기존 selector가 GAME_SELECT에서 양수 betAmountPerPlayer를 게임과 함께 설정한다. 서버 시작 스냅샷을 DB에 고정하여 예약·정산에 사용한다. 기존 표의 검증용 1코인 가정은 [가변 참가비 계약](game-settlement.md)으로 대체한다. 별도 방장/테이블 생성 API는 추가하지 않는다.
