# 알까기 비밀 카드·아이템8종 로컬 계약

2026-10-31 · S15P31B105-294 · 로컬 데모 계약. 제품 WebSocket·회원 인증·판돈·DB와 아직 연결하지 않았다.

## 구현 경계

2026-11-02 공원 UI: F1에서 알까기 설명서를 열 수 있다. 비책은 카드 선택 뒤 대상 클릭으로 바로 제출한다. 교환은 두 번째 알, 재배치는 대상 알을 고른 뒤 목적지 클릭으로 제출한다. 벽은 유효한 빈 위치 클릭으로 미리보기를 고정하고 둥근 손잡이를 드래그해 회전한 뒤 ‘벽 설치’로 제출한다. Q/E·휠 회전과 위치 다시 고르기도 지원한다. 추가 발사는 카드 클릭 즉시 제출한다. 같은 카드 재클릭·Esc·우클릭으로 미확정 선택을 취소한다. 잘못된 대상·겹침은 소모 없이 막고 최종 판정·소모는 서버 승인을 따른다. 아래 독립 물리 데모의 확정 버튼은 별도 로컬 검수 도구 동작이다.

- 실제 경기 객체는 빈 손패로 생성된다. 보유 장수 제한 없이 누적하며 카드 ID/종류는 소유자에게만 전달한다.
- 아이템8종과 손실 기반 지급 모두 로컬에서 사용할 수 있다. 미정 수치·수명은 `AlkkagiItemRules`, 추첨은 `AlkkagiCardRules`의 임시 설정이며 운영 합의가 아니다. 밸런스 확정은 [미정 목록](alkkagi-decisions.md)에 남긴다.
- `receiveCard`는 신뢰된 서버 지급 경계다. 제품 클라이언트에 원하는 종류 지급 요청을 노출하지 않는다.
- 로컬 테스트 클래스패스의 `TEST_CARDS`는 홍팀이 시작 전에 `cards` 배열(1~2종)을 골라 양쪽에 지급하는 연습 도구다. 생략 시 SWAP/EXTRA_SHOT이다. 실제 손실 기반 지급·중복 허용·확률 정책을 대신하지 않는다.
- 물리값30/60/1·종류별 프로필·120Hz 물리·20Hz 공개 스냅샷·100ms 화면 버퍼는 유지한다.

## 정상 플레이의 카드 지급

초기0장. 양쪽 각자의 누적 손실3/6/9/12/15마다 후보3장 중1장을 선택한다. 열세/동수/우세와 관계없다. 물리 안정화 후 손실을 확정하며 경기 종료가 우선하면 새 선택을 열지 않는다. 같은 이정표/재접속은 후보를 다시 추첨하지 않는다.

선택은 서버 기준10초이며 만료하면 현재 후보 중 서버 RNG로 한 장만 확정한다. 정상 설정에서는 서로 다른3종을 가중 추첨한다. 로컬 가중치 설정이3종 미만만 허용하면 가능한 종류를 반복해3개의 서로 다른 optionId를 만든다. 벽3회 소진 제외/보유종류 중복 허용 설정은 유지한다. RNG/시드는 전송하지 않는다.

CHOOSING 중에는 양쪽 발사/아이템 사용을 막고 턴 시간을 정지한다. 각자 동시에 선택 가능하며 한쪽이 골라도 상대의 원래 기한은 바뀌지 않는다. 같은 발사에 여러 손실 이정표를 넘으면 각자 순서대로10초씩 선택한다. 전원 선택 완료 후 다음 턴30초를 시작하거나, 추가 발사 중이었다면 원래 남은 시간만 이어간다. 늦게 tick/조회해도 자동선택의 원래 deadline을 재개 기준으로 사용해 시간을 더 주지 않는다. 전체 경기12분은 기존대로 계속 흐르며 전체 기한/기권 확정 시 대기 후보를 폐기한다.

사용자 확정: 손패 장수 한도를 없애고 이정표마다 계속 선택·획득한다. 이미2장 이상 있어도 건너뛰거나 기존 카드를 버리지 않는다. 실제로 사용한 카드만 제거하며 재접속은 전체 손패를 복원한다. 화면은 장수를 표시하고 여러 장은 줄바꿈/스크롤로 보여준다.

소유자 PRIVATE_STATE에는 cards/awards와 choice:{id,losses,deadline,options:[{id,type}]} 또는 null이 있다. 공개 STATE에는 stage=CHOOSING, cardChoices:[{actor,deadline}], pausedTurnMillis만 추가한다. 상대/관전자에게 후보 종류·ID·선택 이력은 보내지 않는다. options ID는 보유 cardId가 아니며 선택 후 새 손패 ID가 발급된다.

CARD_CHOOSE는 gameId/actionId/expectedVersion/choiceId/optionId를 보낸다. 공통 GAME_ACTION_SEND input은 type=CARD_CHOOSE/choiceId/optionId이며 외부 경기/action/version은 기존 envelope를 쓴다. 후보 소유자·ID·기한을 검증하므로 양쪽 동시 선택으로 public version이 변해도 본인 유효 후보는 고를 수 있다. 같은 actionId/같은 선택은 최초 결과 재확인, 다른 선택은 ACTION_ID_CONFLICT. 만료/종료된 후보 CHOICE_NOT_ACTIVE, 틀린 option CHOICE_OPTION_INVALID, 미지 필드 INVALID_ACTION. 성공 로컬 ACK는 CARD_CHOSEN이며 공개/개인 상태의 같은 버전 송신 경계를 유지한다.

## 사용 규칙

공통: 본인 차례 AIMING 단계의 첫 발사 전에만, 턴당 최대1장. gameId/expectedVersion/actionId/소유권/대상을 서버가 검증한 후 효과와 소모를 함께 확정한다. 잘못된 요청·확정 전 취소는 소모하지 않는다. 같은 actionId/같은 입력은 최초 승인 version을 반환하고, 다른 입력은 ACTION_ID_CONFLICT다. 발사와 아이템은 같은 중복 요청 공간을 사용한다.

SWAP은 양팀의 생존 알 두 개를 지정한다. 교환 후 각각의 실제 반지름으로 다른 생존 알·회전 벽과 겹치는지 검사한다. 동일 알·탈락한 알·겹침은 거절한다.

EXTRA_SHOT은 첫 발사 정지 후 같은 사용자의 두 번째 발사를 허용한다. **원래30초 마감은 유지**한다. 첫 발사 중 마감이 지나면 물리 종료 후 다음 차례로 넘기고, 승패/전체 시간 종료가 우선한다. 첫 발사가 있으면 추가 발사를 쓰지 않아도 AFK가 아니다. 카드만 쓰고 첫 발사를 하지 않으면 기존 미발사로 처리한다.

| 종류 | 로컬 동작 | 임시 설정/만료 |

| WALL | 빈 판의 위치·회전 선택, 서버 직사각형 정적 충돌체 설치. 알·판 가장자리 겹침 거절 | 길이1.6/두께.18/가장자리 여백.12, 알과.02 여백. 개인당 최대3개·전체 최대6개. 경기 종료까지 유지 (`expiresAfterTurn: null`) |

확대·축소·방어·힘 강화·벽은 경기 끝까지 지속한다. 턴 종료에 크기/질량을 원복하지 않는다. 크기/방어는 알별 기존 modifier 중첩을 거절하고, 힘 강화는 별도 pieces[].powerUp으로 여러 알에 각각 적용한다. 힘 강화와 크기/방어는 함께 유지할 수 있다. EXTRA_SHOT만 사용 턴에 추가1회이며 다음 턴에는 해제된다. 새 경기는 새 Match로 기본 상태를 생성한다.

크기/방어로 질량이 달라도 같은 조준의 출발속도는 유지하도록 현재 질량으로 충격량을 계산한다. 충돌 시 운동량·버티는 정도가 달라진다. 힘 강화 배율은 출발속도에 적용하며 별도 질량 강화가 아니다. 평상시 물리30/60/1은 바꾸지 않는다.

임시 수치 근거: 확대1.25/축소.8은 전달된 초기 검토값, 나머지는 원작 측정이나 팀 합의가 없는 로컬 검수 시작값이다. 벽 길이.5~3/두께.1~.5/여백.02~.4, 재배치.5~3, 힘1.05~2, 확대1.05~1.5/축소.5~.95, 방어1.1~4, 지속 턴 설정은 폐기하고 effectOpponentTurns=0(경기 지속)을 사용한다. 홍팀의 ‘아이템 수치 조절’은 `TUNE_ITEMS(gameId/expectedVersion/rules)`로 검증된 **새 판**만 생성한다. 현재 시뮬레이션 계수를 중간에 바꾸거나 파일/환경변수를 저장하지 않는다. 잘못된 값은 기존 판 보존, 청팀/관전자 변경 거절. 일반 새 판/물리 조절은 현재 아이템 설정을 유지하고 서버 재시작은 기본 임시값으로 돌아간다.

## 로컬 요청·응답

`ws://127.0.0.1:19183/dev/alkkagi-ws?role=red|green|viewer`

role 쿼리는 로컬 테스트 역할이며 인증이 아니다. 이 데모 핸들러는 운영 JAR에 포함되지 않는다.

```json
{
  "type": "ITEM_USE",
  "gameId": "현재 STATE의 gameId",
  "actionId": "고유 요청 ID",
  "expectedVersion": 5,
  "cardId": "내 PRIVATE_STATE의 카드 ID",
  "targetPieceIds": ["p11", "p12"]
}
```

EXTRA_SHOT/WALL의 targetPieceIds는 빈 배열, SWAP은2개, 나머지는1개다. WALL/RELOCATE만 `placement: {"x": 0, "y": 0, "angle": 0}`를 추가한다. XY는 판 평면, angle은 라디안(-π~π)이며 RELOCATE는 회전 없이 이동만 한다. 서버는 유한수치와 실제 형상·거리·소유권을 검사한다. 클라이언트가 카드 종류·효과 수치·교환 좌표를 지정하지 않는다. 미지 필드·2개 초과 대상·문자열 아닌 대상·잘못된 version은 거절한다. 실제 입력 파서는 `AlkkagiInputs`로 로컬 소켓과 공통 엔진이 함께 사용한다.

성공은 ITEM_ACCEPTED(actionId/version), 실패는 ERROR(code)다. 주요 코드는 PLAYER_REQUIRED, STALE_GAME, STALE_VERSION, NOT_AIMING, NOT_YOUR_TURN, CARD_NOT_OWNED, INVALID_TARGETS, NOT_YOUR_PIECE, ITEM_OVERLAP, ITEM_ALREADY_USED_OR_SHOT, ACTION_ID_CONFLICT다. 추가 코드는 INVALID_PLACEMENT, ITEM_OUTSIDE_BOARD, ITEM_OVERLAP_OR_OUTSIDE, RELOCATE_TOO_FAR, WALL_LIMIT, MODIFIER_ACTIVE, POWER_ALREADY_ACTIVE, INVALID_ITEM_RULES다.

매 공개 STATE와 같은 seq/gameId/version의 PRIVATE_STATE를 본인에게만 보낸다.

```json
{
  "type": "PRIVATE_STATE",
  "seq": 42,
  "state": {
    "gameId": "현재 경기",
    "version": 5,
    "cards": [{ "id": "소유자 전용 ID", "type": "SWAP" }]
  }
}
```

상대·관전자에게 미사용 종류/ID는 보내지 않는다. 공개 STATE에는 itemUsedThisTurn, extraShotsRemaining(추가분0/1), lastItemEffect(version/turnNumber/actor/type/targets), walls[](소유자/위치/길이/두께/각도/expiresAfterTurn:null), wall(호환용 첫 벽 또는 null), wallsUsed, boostedPieceId(호환 필드, 항상 null), itemRules가 있다. 알별 radius/mass/launchSpeed/modifier/powerUp/restorePending(항상 false)도 서버 현재값이다. lastItemEffect는 최신 확정 효과를 설명하는 상태이며 일회성 연출 이벤트가 아니다. 재접속 시 이를 새 연출로 재생하면 안 된다.

공개/개인 JSON을 물리 소유 스레드에서 같은 발행 묶음으로 만들고 AtomicReference 하나로 송신 스레드에 넘긴다. 최신 상태 교체 중에도 서로 다른 버전의 손패가 짝지어지지 않는다. 소켓 쓰기는 기존대로 별도 sender에서 수행한다. 연결 복구는 현재 손패/상태를 재조회하며 타이머를 초기화하지 않는다. 서버 프로세스 재시작은 데모 판을 초기화한다.

물리 진행 중 version도6스텝마다 갱신한다. 같은 version을 재전송하지 않는 기존 공통 상태 전송 경로에서도20Hz 물리 변화가 전달되도록 하기 위함이다. actionId의 최초 승인 version은 별도로 보존되어 이후 물리 version이 올라도 같은 요청의 최초 결과를 반환한다. FE `AlkkagiInbox`는 승인된 최소 version보다 낮은 프레임, 역순 seq, 공개와 짝이 다른 개인 손패를 무시한다.

## 로컬 관전·기권·복구

STATE.social은 채팅·커서·훈수만 포함한다. CHAT은 gameId/actionId/text(공백 제외1~200 code point), CURSOR는 gameId/x/y, ADVICE는 gameId/actionId/expectedVersion/pieceId/dx/dy/power를 받는다. sender/역할은 연결에서 가져오고 입력으로 바꿀 수 없다. 채팅은 React 텍스트로 표시해 HTML로 실행하지 않는다.

임시 제한: 채팅600ms, 커서80ms/2초 유효, 훈수600ms/4초 유효·관전자당 최신1개·전체 최신3개. 채팅은 최근50개를 보관하되 공개 프레임에는 보수적인 UTF-8/JSON 예산8KB 안의 최신 부분만 포함한다. 훈수는 관전자만, 현재 AIMING의 현재 턴 생존 알만 허용하고 방향/힘/버전을 검증한다. 실제 발사·물리·턴·승패를 변경하지 않는다. 훈수는 턴 변경·발사 시작·새 판·연결 종료에서 정리한다. 커서는2초 만료·새 판·연결 종료에서 정리하며 턴 전환만으로 지우지 않는다. 새 판은 채팅도 비운다. 이 로컬 통신은 제품의 기존 관전 거리·인증·채팅 권한을 대체하지 않는다.

FORFEIT(gameId/actionId)은 자신의 명시적 기권이다. 같은 actionId는 최초 결과 재확인, 다른 동작에 사용한 actionId는 충돌 거절. 즉시 물리를 멈추고 상대 승리로 확정하며, 이미 끝난 결과를 덮지 않는다. 로컬에서는 같은 역할의 마지막 연결이 사라진 뒤30초 유예를 주고, 그 안에 복귀하면 같은 판/기한/손패/확정 효과를 유지한다. 유예 만료는 DISCONNECT_TIMEOUT. 로컬 역할 URL은 실제 회원/다중 로그인 세션 검증이 아니다.

## 기존 게임 인터페이스와 연결할 경계

`AlkkagiEngine`은 기존 GameEngine/Router의 입력·상태·기권·복구를 구현하고 `startCommitted(command,result)`에서 ALKKAGI·2명·전원 예약 커밋 계약을 확인한다. 실제 예약/차감 요청이나 DB 저장을 만들지 않는다. 공개 gameId는 서버의 외부 경기 ID, players는 참가자 순서의 회원 ID 문자열이며 내부 actor0/1과 매핑한다. publicState는 gameCode/status/tableId/turnUserId/winnerUserId와 공개 판, privateState는 해당 회원 손패만 담는다. 복구 state는 기존 원카드와 같은 publicState/privateState 객체다. 알까기 시간 필드는 epoch ms다.

공통 요청은 기존 GAME_ACTION_SEND payload 안의 gameId/actionId/expectedVersion/input을 사용한다. input은 로컬 SHOT/ITEM_USE/CARD_CHOOSE에서 type과 행동 필드만 남긴 형태다. 기권은 기존 GAME_FORFEIT, 상태는 기존 GAME_STATE_CHECK/관전 경로를 재사용할 수 있다. 이 어댑터는 local에서 명시적으로 활성화하는 Configuration과 공원 연결 경로를 추가했다. dev/prod의 기본 등록은 하지 않았으며 검수 서버에서는 예약 완료 계약 대역을 사용한다. 새 인증을 만들거나 팀원 DB 예약·정산 코드를 수정하지 않았다.

**실제 공원/DB 활성화는 완료가 아니다.** CommittedGameStartService 지원과 DEV 명시 플래그의 게임 선택 카탈로그는 연결했다. DB 종료 검증 VerifiedGameFinish.REASONS 등 실제 DB 계약은 아직 ALKKAGI를 지원하지 않는다. DB의 게임 종류 등록, 시작 호출 연결, 종료 사유/무승부/물리 실패 무효·환급 계약을 담당자와 함께 반영해야 한다. 현재 어댑터의 GameFinished를 기존 DB 소비자에 바로 연결하면 거절된다. SIMULATION_INVALID/LIMIT는 로컬 검증 종료이며 금전 결과로 사용하면 안 된다. DB 구현·Flyway·스키마는 변경하지 않았다. 공통 시작 서비스는 엔진 존재 확인/예약 확정 후 호출만 추가했다.

## 화면·검증

홍팀 로컬 화면에서 새 판 → 연습 카드2종 선택 → 연습 카드 받기(로컬) → 테스트 시작. 카드 선택 → 대상 알/빈 판 위치 선택 → 미리보기 → 아이템 확정. 벽은 각도 슬라이더로 회전한다. 취소/Esc/우클릭은 미확정 선택만 지운다. 일반 발사는 **처음 누른 채 바로 드래그하고 놓는 한 동작**이며 클릭/미세 흔들림은 발사하지 않는다. 추가 발사는 첫 정지 후 같은 남은 시간 안에 한 번 더 발사한다. 턴/판/승인 버전이 바뀌면 미확정 UI를 취소한다.

검증: 기존 아이템/물리 검사에 Completion(실제 손실 지급/자연 종료/안전 종료), Engine(예약 계약·격리·동시 기권·다음 판/복구 경쟁), Social(권한/중복/한도), LocalReconnect(가상 시계+소켓 대역의30초 유예), 실제 소켓·Chrome 일반 한 판/8종/벽고스트/관전/기권/복구 검사를 연결했다. 로컬 검증·DB 계약 대역을 실서버·실DB·운영 완료로 표시하지 않는다. 필요한 효과음·이미지는 [전달 목록](alkkagi-assets.md)을 따른다.

공용 화면 `frontend/src/game/alkkagi/AlkkagiBoard.tsx`는 승인 snapshot/replay/actor와 명령 callback으로 동작한다. 로컬 역할 URL·소켓·물리값 조절/연습 지급은 `alkkagi-preview/main.tsx`에 분리했다. 실제 공원 화면에서는 인증된 사용자/기존 GAME_ACTION_SEND와 상태 수신을 공급해야 하며 로컬 테스트 연결을 그대로 운영 인증으로 사용하지 않는다.

## 2026-10-31 사용자 검수 반영: 연출·아이템 범위·중심 경계
- SWAP/RELOCATE/GROW/SHRINK는 내 알·상대 알 모두 대상이다. POWER_UP/DEFEND는 내 알만, 발사도 여전히 내 알만이다. 턴/손패/생존/중복·소모 검증은 유지한다.
- 변형·재배치·교환의 판 경계는 생존과 같은 중심 좌표 기준이다. 반경이 밖으로 걸쳐도 중심이 판 안이면 허용한다. 다른 생존 알 또는 회전 벽과 실제 반경이 겹치는 배치/확대는 거절한다. 벽 자체는 판 전체 안/여백·알 겹침 검증을 유지한다.
- 공개 pieces[].exit는 최초 장외 순간의 {x,y,vx,vy,at} 또는 null이다. 안정화 후 본체 속도가0이 돼도 변경하지 않는다. 화면은 새 alive→false만 해당 속도로 수평 진행+중력 낙하·축소 소멸하며, 복구 시 이미 탈락한 알은 과거 연출을 재생하지 않는다. 시각 효과는 서버의 탈락/충돌/승패를 변경하지 않는다.
- 공격 강화는 주황 궤도/화살, 방어는 파란 구형 막, 확대는 보라·축소는 청록 화살로 지속 표시한다. 실제 승인 modifier/powerUp에 연결하며 해당 알 탈락/경기 화면 종료까지 유지한다. 외부 이미지/모델 없이 Geometry로 렌더한다.
- AIMING의 서버 기준 턴 마감10초부터 판 중앙에 남은 초를 표시한다. 경고는 입력을 막지 않으며 새 판/턴 종료에 제거한다.

장외 연출 검수 보완: 수평 속도와 회전은 v0·exp(-6t) 형태로 감속하고 적분 이동량으로 재생한다. 수직 낙하/소멸 시간과 서버 장외 판정은 유지한다. 이는 공중 시각 연출 계수이며 판 위 물리의 감속60과 별개다.

## 2026-10-31 지속 효과·아이템 미리보기
대상 선택은 맥동하는 테두리로 표시한다. 확대/축소는 변경 반경, 방어/힘 강화는 효과를 사전 표시한다. 벽과 재배치는 포인터를 따라 녹색(가능)/빨강(불가) 고스트를 표시하고 클릭으로 위치를 고정한 뒤 확정한다. 교환은 두 알의 변경 위치·반경을 반투명으로 표시한다. 취소/Esc/우클릭/차례·승인 버전 변경 시 미확정 표시를 지운다. 미리보기는 실제 물리·소모를 변경하지 않으며 최종 서버 검증을 유지한다. 공원 집중 카메라의 렌더 레이어를 매 UI 렌더에 새 메시까지 적용한다.

## 벽 개인별 설치 한도 (2026-10-31 확정)
각 플레이어는 벽을 최대3개 설치한다. 양쪽 합쳐 최대6개, 모든 벽은 경기 끝까지 유지하고 새 경기에는 남기지 않는다. 개인별 설치 성공 횟수 wallsUsed[actor]가3이면 그 사람의 이후 후보 생성에서 WALL을 무조건 제외한다(구버전 excludeExhaustedWalls=false도 true로 정규화). 상대의 설치 횟수는 본인 후보에 영향을 주지 않는다. 이미 보유한 벽 카드는 삭제하지 않지만 한도에 도달하면 사용 버튼을 비활성화하고 서버도 WALL_LIMIT로 소모 없이 거절한다. 미리 보유한 벽 카드가 후보로 다시 나오는 것은 별개의 allowDuplicates 규칙을 따른다.
서버/클라이언트는 모든 회전 벽과 알/확대/재배치/교환의 겹침을 검사한다. 벽끼리는 회전 직사각형의 네 분리축(SAT)으로 교차/겹침을 검사하며 맞닿는 것은 허용한다. 설치 실패/같은 actionId 재확인은 벽 수·카드를 중복 증가/소모하지 않는다. 공개 walls 배열이 전체 상태이며 프론트는 이를 우선한다. legacy wall은 첫 벽 하나만 담으므로 다중 벽 표시에는 사용하지 않는다.

## 인게임 기권·버튼 UI (2026-10-31)
알까기는 기존 공통 기권 요청/응답·재확인 로직을 그대로 사용하며 중앙 한지 확인창만 별도로 제공한다. 계속 플레이를 기본 포커스로 두고 Esc/닫기/취소는 요청 없이 닫고 원래 버튼으로 돌아간다. 확인창 중에는 알 발사·아이템 입력을 막되 서버 턴 시간은 계속 흐른다. 기권 pending/uncertain/approved에서도 기존 forfeitBlocksInput을 입력 가능 조건에 반영하며 거절 후에는 기존 권한을 다시 평가한다. 주변 보기·기권 버튼과 아이템 사용하기/취소 버튼의 디자인만 알까기 범위에서 통일한다. 결과·좌석·정산 정책을 변경하지 않는다.

### 기권 종료 연출 수신·상대 퇴장 회귀 (2026-10-31)
서버가 보내는 WORLD_PARK_DEBRIS_STATE.items[].gameCode=ALKKAGI를 프론트도 허용하며, 파편 표시에서 목재판과 알을 사용한다. 알까기는 오목용 stone-* 부품을 허용하지 않고 기존 board/coin-* 검증과 개수·중복 제한을 유지한다. 기권 뒤 GAME_CONNECTION_STATE FINISHED와 SETTLED 결과·WAITING을 정상 수신하면 기존 결과 확인→대기실 복귀→퇴장 흐름을 따른다. 임의로 busy/uncertain이나 서버 정산 제한을 해제하지 않는다.

### 기권 응답 순서와 다음 판 회귀
기권 승인 응답보다 WAITING 방송이 먼저 도착하면 활성 경기 ID가 비워질 수 있다. 동일 completedGameId의 기권 응답도 처리해 요청 pending을 정리하며, 새 경기 ID가 활성화된 경우 과거 응답으로 새 요청을 해제하지 않는다. 회귀 검증은 양쪽 퇴장→재착석→방장 수동 시작→새 경기 ID·알32개·빈 손패/벽→첫 발사까지 포함한다. 로컬 공원 검수는 메모리 예약·정산 대역이며 실제 DB 지급 검증이 아니다.

### 게임 중 새로고침 복구
초기 GAME_CONNECTION_STATE는 좌석보다 먼저 도착해도 채널·테이블 목록 로딩까지 보관하고 좌석을 먼저 적용한다. 서버는 현재 세션의 RESTORED 게임 제어권과 보존 좌석이 확인된 참가자에게 원래 테이블 채널의 CHANNEL_JOIN만 허용한다. 다른 채널·일반 이동에 대한 경기 복구 제한은 유지한다. 새로고침은 턴 제한 시간을 초기화하지 않는다. 집중 카메라는 평면 장기판 외에 알 윗면의 높이와 가장자리 여백을 포함해 양쪽 좌석 방향에서 맞춘다.
복구 후 원래 채널에 다시 들어온 참가자는 WORLD_FACILITY_CATALOG·WORLD_FACILITY_CHECK·WORLD_FOLLOW_CHECK 초기 조회도 허용한다. 보존 좌석·현재 연결의 해당 경기 제어권·원래 채널 가입을 모두 확인하며, 시설 사용/따라가기 시작·종료/이동 등 행동은 기존 제한을 유지한다. 양쪽 재접속에도 원래 턴 기한은 유지한다.
