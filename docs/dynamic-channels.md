# 운영 유동 채널 (S15P31B105-117)

## 정책

- PROD는 백엔드 프로세스 안에 공원 채널 하나를 만들고 시작한다. 채널당 정원은 20명이다.
- 열린 모든 채널의 인원이 18명 이상이면 빈 채널 하나를 미리 만든다. 새 채널의 테이블 16개와 맵 앵커를 등록한 뒤 목록에 공개한다.
- 채널 입장 시 서버가 다시 정원을 검사한다. 목록의 `joinable`은 조회 시점의 안내값이다.
- 최소 한 채널을 유지한다. 다른 채널은 인원 0명이 5분 지속되고 테이블 좌석·관전·진행 중 경기·재접속 대기·시설 점유·따라가기 연결이 없을 때만 정리한다. 남은 사용자를 다른 채널로 이동시키지 않는다.
- 실행 중 생성되는 채널은 UUID 기반 ID를 사용한다. 화면 이름은 `운영 공원 2`, `운영 공원 3`처럼 증가한다. 빈 번호를 다시 쓰지 않는다.
- 최대 채널 수 기본값 2는 임시 안전 한도다. 서버 전체 한도와 적정 최대치는 [S15P31B105-119](https://ssafy.atlassian.net/browse/S15P31B105-119) 부하·브라우저 측정 후 결정한다. 최대치에서 모든 채널이 찼으면 입장은 `CHANNEL_FULL`로 거절한다.

## 설정

운영 앱의 `/etc/ontop/prod-app/app.env`에 아래 값을 넣고 앱을 재생성해야 한다. 저장소의 `infra/app/prod.app.env.example`은 예시 파일이며 실제 서버 설정을 바꾸지 않는다.

```dotenv
WORLD_DYNAMIC_CHANNELS_ENABLED=true
WORLD_CHANNEL_CAPACITY=20
WORLD_CHANNEL_SPAWN_AT=18
WORLD_MAX_CHANNELS=2
WORLD_CHANNEL_IDLE_TIMEOUT=5m
```

DEV는 `WORLD_DYNAMIC_CHANNELS_ENABLED=false`를 유지하고 기존 설정 채널 하나를 사용한다. 유동 채널 동작은 별도 시험 설정에서 검증한다. 채널 및 테이블 상태는 현재 백엔드 프로세스 메모리에 있으므로, 여러 앱 인스턴스 사이에서 공유되지 않는다. 배포 중 진행 중 게임 보호와 구·신 버전 전환은 [S15P31B105-118](https://ssafy.atlassian.net/browse/S15P31B105-118)에서 다룬다.

## 확인 순서

1. 로그인 후 `GET /api/v1/channels`에서 초기 채널 하나, 정원 20명, 실제 인원, `joinable`을 확인한다.
2. 입장 후 `GET /api/v1/tables?channelId=...`에서 테이블 16개와 각각의 `anchorId`를 확인한다. 프론트는 이 값을 실제 3D 맵의 테이블 배치에 사용한다.
3. 시험 설정에서 18명 이상을 입장시켜 빈 채널이 하나 추가되는지 확인한다. 20명 동시 입장 경합에도 한 채널 정원이 넘지 않아야 한다.
4. 첫 채널의 인원이 18명 미만으로 내려온 뒤 추가 채널의 인원을 0명으로 만들고, 게임·재접속·좌석·시설 점유가 없는 상태로 5분 기다려 추가 채널이 사라지는지 확인한다.
5. 진행 중 경기가 있거나 재접속 대기가 있으면 빈 채널이어도 유지되는지 확인한다. DEV 일반 배포의 채널 수가 계속 하나인지 확인한다.

20명일 때의 브라우저 FPS와 서버 수용량은 아직 검증되지 않았다. 운영 활성화와 최대 채널 수 증가는 부하 시험 결과를 보고 결정한다.
