- 2026-11-25 사용자의 개발 진행 지시에 따라 기존 테이블에 연결된 `STONE_RUMBLE` 게임 내부를 수정했다.

## 레퍼런스와 구현

레퍼런스는 폴가이즈의 **Hex-A-Gone(바닥 떨어져유)**다. 밟은 육각 발판을 소모하며
아래층의 남은 착지점을 살피는 흐름과, 캐릭터를 따라가는 마우스 조작 카메라를 반영했다.
원작 내부 카메라 수치를 가져온 것은 아니며 현재 캐릭터 크기·서버 이동 속도에 맞춰 조정했다.
사용자가 제공한 유튜브 링크는 직접 재생하지 못했으며 별도 검색 자료를 사용했다.

- [발판 소멸 지연을 설명하는 원작 레벨 디자이너 인터뷰](https://www.washingtonpost.com/video-games/2020/09/04/fall-guys-lore-crunch-levels/)
- [PC 카메라·이동 조작 참고 영상](https://www.youtube.com/watch?v=Wo-5IMuiDOE)
- [사용자가 제공한 영상](https://youtu.be/gwvH7f7uad0)

### 카메라·조작

- 화면 클릭으로 마우스 시점을 잡고, 마우스로 좌우·상하 회전한다. 최초 클릭은 공격하지 않는다.
- Esc로 마우스 시점을 해제한다. 채팅·안내·기권창·탈락·종료·컴포넌트 정리 시에도 해제한다.
- 우클릭 드래그와 터치 드래그를 제공해 pointer lock을 사용할 수 없는 환경에서도 시점을 조절한다.
- WASD/방향키는 **현재 화면**을 기준으로 이동한다. 키를 누른 채 카메라를 돌려도 같은 기준을 따른다.
  이동만으로 카메라를 자동 회전시키던 동작은 제거했다.
- 카메라는 거리 10.5m, 기본 고도각 0.46rad, 시야각 55도로 시작한다.
  고도각 범위는 0.18~1.35rad이며 휠로 거리를 조절한다. 캐릭터와 카메라 회전은 별도로 보간한다.
- 비둘기는 카메라의 수평 방향으로 발사한다. 점프·Shift 다이빙·E/클릭 발사·채팅·관전 전환은 유지한다.

### 발판·서버 계약

- `frontend/src/game/stone-rumble/layout.ts`와 BE의 `StoneHexGrid`가 같은 pointy-top axial 좌표를 사용한다.
- 이웃 발판 중심 간 거리는 2.6m다. `x=2.6*(q+r/2)`, `z=2.6*sqrt(3)*r/2`이며 cube rounding으로 착지를 판정한다.
- 육각 거리 `max(abs(q), abs(r), abs(q+r))`를 경기장 경계·외곽 붕괴에 사용한다.
- 아래층부터 반경 8/7/6, 발판 217/169/127개로 총 **513개**다. 층 높이는 0/12/24m다.
- 밟은 발판은 1초 후 사라진다. 황토색·줄어드는 육각 테두리·마지막 0.3초의 붉은색으로 구분한다.
- 카운트다운 중 경기장 밖 이동도 육각 경계로 제한한다. 출발점·층간 낙하·충돌과 화면의 발판 좌표가 일치한다.
- `publicState.tileLayout`에 `HEX_AXIAL_V1`을 추가했다. FE는 옛 사각 배치 응답, 누락·중복·경계 밖 발판을 거절한다.
  FE와 BE를 함께 반영해야 한다. `gameCode`, 공통 액션·지갑·정산 계약은 유지한다.
- 층마다 하나의 instanced mesh를 사용하고, 변경한 발판의 마크만 GPU에 전송한다.
  실제 엔진에서 생성한 8인 fixture도 새 계약으로 갱신했다.

## 작업 위치와 검증 방법

- FE 담당: `frontend/src/game/stone-rumble/`, 관련 `frontend/tests/local-unit/stone*`.
- BE 담당: `backend/src/main/java/com/ssafy/ontop/game/stonerumble/`, 대응 테스트.
- 로컬 공원 검증: 기존 `stone-rumble-park.html`, FE 5517 / BE 19217.
- 게임 독립 검증: 기존 `preview.tsx`를 Playwright 임시 HTML에 마운트, FE 5236 / BE 19186의
  기존 `stoneRumbleDemo`를 사용했다. 검증 도구가 `/dev/stone-rumble/**` 요청을 해당 BE로 전달했다.
  게임 상태·입력·충돌·승패는 실제 Java 엔진이 처리하며 회원·재화·채팅 기록은 로컬 fixture다.
- 브라우저 스크립트와 스크린샷은 저장소 밖 `OnTop/output/stone-hex-qa-20261125/`에 보관했다.
  스크립트는 `try/finally`에서 브라우저를 닫는다. 다른 작업의 서버·브라우저는 종료하지 않는다.

## 검증 기록

- FE 앱 타입 검사 통과.
- FE 돌탑 관련 단위 테스트 14개 파일, 95개 통과. 육각 경계·계약·현재 시점 이동·카메라 고도각·보간·관전·입력 큐·사운드를 포함한다.
- BE 돌탑 도메인·엔진·로비·단독 서버·공원 fixture·시작·종료·정산 연결 테스트 88개와
  공원 복귀 회귀 테스트 2개, 총 90개 통과.
- 최신 공원용 프로덕션 빌드 통과. 기존 번들 크기·Three CJS 사용 경고가 있다.
- 실제 단독 서버 2인 경기에서 발판 렌더링, 좌우·상하 카메라, 점프·이동, 마우스 잠금,
  채팅 시 잠금 해제, 층간 낙하, 승패·순위 표시를 확인했다. 실행·셰이더 오류 0건.
- 1440×900, 390×844, 800×600 화면을 확인했다. 좁은 화면의 안내와 터치 버튼 겹침을 수정했다.
- 최신 공원에서 두 계정이 눈사람을 우회해 기존 `table-17`의 입구까지 실제 이동한 뒤 참가했다.
  로비 인원 확정·준비·시작, `HEX_AXIAL_V1` 513개 발판 수신, 마우스 잠금·상하 회전,
  채팅 시 잠금 해제, 경기 종료와 `SETTLED` 결과 수신, `공원으로 나가기` 후 입구 복귀를 확인했다.
  공동 1위 15냥씩의 로컬 정산과 공원 복귀 후 `mapStatus=verified`, `tableId=''`를 확인했다.
- 브라우저의 실행·셰이더 오류는 없었다. 공원 통합 fixture에서 공지·당첨 내역·알림·랭킹·진입 소식·
  응모·겨울 트리 상태 API는 DB 미연결로 503을 반환했다. 해당 기능을 성공으로 표시하거나 설정을 우회하지 않았다.
- 전체 FE 테스트 타입 검사는 기존 `tests/unit/tableGathering.test.ts:87`의 루미큐브 fixture에서
  `firstUserId`, `openingDraws`, `finalTurnUserIds`가 누락돼 실패한다. 해당 파일은 변경하지 않았다.
- 맵 전수 탐색 및 자전거·킥보드 주행 테스트는 실행하거나 추가하지 않았다.

## 원격 반영 경계

- 커밋 전과 푸시 전에 최신 `origin/dev`와 중복·충돌을 다시 확인한다.
- MR 생성·머지는 사용자 명시 요청 전까지 보류하며 작업 브랜치는 삭제하지 않는다.
- 현재 저장소 Jenkins 파이프라인은 `dev` 전용이다. 관리 API의 외부 조회는 HTTP 403으로 차단되어
  Jenkins 결과를 확인하지 못했다. 로컬 테스트·빌드 성공을 Jenkins 성공으로 표시하지 않는다.
