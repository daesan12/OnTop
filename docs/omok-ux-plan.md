# 오목 플레이·관전 참여 UX 기획

작성: 2026-10-27 KST. 상태: 사용자 요구사항 반영 / 구현 전.

관련 문서: [기존 오목 규칙](omok.md), [공통 진입·에셋 기획](../frontend/docs/BOARDGAME_PRESENTATION_PLAN.md), [FE 작업 명세](../frontend/docs/OMOK_UX_FE_SPEC.md), [BE 작업 명세](omok-ux-be-spec.md).

## 목적과 선행 작업

오목판에 집중하면서도 관전자의 채팅과 위치 추천으로 훈수를 주고받는다. 내 턴과 상대 턴마다 카메라가 움직이는 문제를 없앤다. 주변 관중까지 보이는 넓은 탑뷰는 이번 채택안이 아니다.

게임 진입→선택→준비→수동 시작은 아직 머지되지 않은 [태블릿 선행 작업](../frontend/docs/TABLET_LOBBY_HANDOFF.md)을 따른다. 충돌 시 선행 작업을 유지하고 이 후속 작업을 수정한다. 선택 승인 시 빈 판·돌통을 표시하되 준비 시점은 유지하고, 서버의 실제 시작 확정 후 아래 경기 화면으로 들어간다. 선행 작업 머지 후 전체 흐름을 다시 검증한다.

## 확정한 플레이어 화면

| 항목 | 요구사항 |
| --- | --- |
| 시점 | 현재의 오목판 확대 탑뷰를 양쪽 플레이어에게 유지한다. 내 턴·상대 턴이 바뀌어도 위치·회전·줌을 바꾸지 않는다. |
| 판 방향 | 좌석별 판 방향은 유지할 수 있으나, 한 경기 중 턴을 따라 회전하지 않는다. 화면 방향과 서버 좌표를 구분한다. |
| 착수 | 고정 시점이어도 본인 차례에만 기존 서버 계약으로 착수한다. |
| 경기 정보 | 내 닉네임·흑/백, 상대 닉네임·흑/백, 현재 차례와 남은 한 수 시간을 쉽게 읽을 수 있게 표시한다. 총시간으로 오인시키지 않는다. |
| 정보 위치 | 차례·타이머·참가자 정보는 판의 교차점 밖에 둔다. HUD 공간을 제외한 나머지 영역에 판 전체가 보이도록 계산한다. |
| 채팅 | 플레이어의 좌하단 기존 채팅창·입력창·기록을 제거한다. 플레이어는 우선 관전자 채팅을 받기만 하며 경기 중 채팅을 보내지 않는다. |
| 공통 메뉴 | 플레이어 경기 화면의 오른쪽 옷장·지도·감정표현·설명서 등 공통 메뉴 열을 숨긴다. 주변 둘러보기로 카메라를 바꾸는 버튼도 제공하지 않는다. |
| 필요한 경기 기능 | 독립 게임 설명 버튼, 기존 기권·오류/복구 확인·키보드 착수 경로는 판을 가리지 않게 제공한다. |
| F1 | 독립 게임 설명 버튼과 F1 키로 기존 설명서를 연다. "설명서를 읽는 동안에도 게임 시간은 계속 흐릅니다."를 표시한다. 열기·닫기·턴 변경으로 경기 시간을 멈추거나 카메라를 바꾸지 않는다. |

종료 후에는 기존 결과·정산 흐름으로 연결한다. 고정 시점·채팅창 숨김·메뉴 숨김은 오목 플레이어의 경기 중 화면에 한정한다. 다른 게임·준비 화면·공원을 일괄 변경하지 않는다.

## 관전자 채팅

- 해당 경기를 실제로 관전 중인 사용자가 보낸 채팅을 두 플레이어에게 표시한다. 근처 다른 경기나 일반 공원 채팅을 섞지 않는다.
- 채팅은 좌하단 기록창 대신 화면 곳곳에 반투명하게 나타난 후 빠르게 사라진다. 위치는 메시지 생성 때 정하고 표시 중 돌아다니게 하지 않는다.
- 판 위에도 나타날 수 있으나 큰 배경 패널을 만들지 않는다. 타이머·이름·필수 버튼 및 메시지끼리의 겹침을 피한다. 클릭을 가로채지 않아 착수를 막지 않는다.
- 플레이어는 수신 전용이다. 숨겨진 채팅 입력창이 Enter/Z로 열리거나 포커스를 가져가지 않게 한다.
- 관전자는 공원 전체 채팅과 구분되는 해당 경기 채팅 입력 경로를 사용한다. 기존 관전 입력 UI를 재사용할 수 있다.
- 관전자끼리도 같은 경기 채팅을 받는 것은 작업 명세의 기본 제안이다. 사용자 확정 수신 범위인 두 플레이어는 필수다.

## 관전자 핑

- 승인된 관전자가 관전 중인 오목판의 교차점을 클릭하면 위치 추천 핑을 보낸다. 별도 훈수 모드 전환 없이 판 클릭으로 동작한다.
- 핑은 두 플레이어와 해당 경기의 관전자 모두에게 보인다. 돌과 구별되는 링·파동 형태로 잠깐 나타난 뒤 사라진다.
- 관전자 클릭은 핑, 플레이어 클릭은 기존 착수로 역할에 따라 분리한다. 핑 수신은 실제 돌 배치·선택·승패·차례·버전·마감·정산을 바꾸지 않는다.
- 좌석별 판 방향이 달라도 같은 서버 판 좌표를 가리킨다. 월드 좌표나 화면 픽셀 좌표를 통신 규격으로 사용하지 않는다.

## 조정 가능한 초기값 제안

아래는 구현 착수를 위한 기본 제안이며 사용자 확정 수치가 아니다. 화면 검수와 BE 계약 합의에 따라 조정한다.

| 항목 | 초기 제안 |
| --- | --- |
| 채팅 표시 | 약 3초, 마지막 0.5초 페이드아웃, 동시 최대 3개, 글자 불투명도 약 0.55~0.7 |
| 채팅 배치 | 닉네임+본문 최대 2줄, 슬롯 기반 분산 위치. 긴 대기열 없이 오래된 표시를 교체 |
| 핑 표시 | 약 2초, 동시 최대 5개, 관전자 1명당 최신 1개. 얇은 링·짧은 파동 |
| 핑 대상 | 0~14의 모든 교차점. 돌이 있는 위치도 링으로 표현하고 돌을 가리지 않음 |
| 전송 제한 | 채팅·핑 각각 사용자당 최소 1초 간격. BE 설정값으로 관리 |
| 가독성 | PC 기준 본문 16px 이상, 주요 타이머 28px 이상을 출발점으로 검수 |

F1을 읽는 동안 채팅·핑이 설명서를 덮지 않는다. 이벤트 수명은 계속 흐르며 닫은 뒤 만료된 내용을 한꺼번에 재생하지 않는다. 동작 줄이기 설정에서는 파동·이동 대신 짧은 정적 표시와 사라짐을 제공한다.

## 현재 구현과의 차이

확인 기준: `frontend-tablet-flow` HEAD `15fd3df`와 이 작업의 기획 수정본.

- `CameraRig.tsx`의 `boardFocus`, `OmokBoard.tsx`의 `focused`가 본인 차례 여부를 사용한다. 카메라·판 전용 레이어 조건을 함께 변경해야 한다.
- `OmokPanel.tsx`의 차례 표시가 판 위에 있고 `Enter · 채팅`, 주변 둘러보기 버튼이 남아 있다.
- `ParkPage.tsx`에서 `ParkChat`과 공통 메뉴가 경기 중에도 표시된다. 상위 공원 UI를 통째로 숨기면 같은 영역의 `GamePanel`까지 사라질 수 있으므로 표시 범위를 나눈다.
- 기존 `WORLD_CHAT_MESSAGE`에는 경기 ID·관전자 역할이 없다. 근거리 채팅의 표시만 바꿔서는 동일 경기 관전자 전용 전달을 보장하지 못한다.
- 기존 오목 입력은 참가자의 착수만 지원한다. 관전자 핑·경기별 관전 채팅은 새 연동이 필요하다.

이 문서는 기존 턴별 카메라 전환과 관전자끼리만 훈수를 공유하던 과거 시안보다 우선하는 오목 후속 기획이다. 기존 렌주·30초·기권·복구·결과 규칙은 별도 요청이 없는 한 유지한다.
