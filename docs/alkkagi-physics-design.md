# 알까기 물리 모델 분리 설계

2026-10-31 · 사용자 플레이 검수가 남은 실험 후보. 모든 새 계수는 원작 실측이 아니다.

## 선택한 흐름

```text
드래그 거리 → 입력 p(0..1) → 부드러운 응답 f(p)
 → 알 종류의 최대 출발속도 × 로컬 배율 × f(p)
 → J = 충돌질량 × 목표속도
 → dyn4j 원형 충돌 → 공통 바닥감속
 → 저속 정지 → 안정화/탈락/턴 → 공개 스냅샷 → 기존 보간 재생
```

`AlkkagiPhysics`가 입력 응답과 `Profile(radius,mass,maximumSpeed)`를 관리한다. `AlkkagiSettings`는 경기 시간·판 크기·감속·반발·안정화 설정이다. `AlkkagiMatch`는 권한과 단계 및 dyn4j 수명주기를 관리한다. 종류마다 별도의 충돌 예외나 강제 밀기 코드를 넣지 않았다.

## 조작과 출발속도

입력 요청 power는 기존 거리/2.5를 유지한다. 서버 응답 곡선은 `f(p)=p(1+.5(1-p))`다. 원점에서0이며 기울기가유한1.5, p=1에서1이다. sqrt는 이동거리 선형화에 가깝지만 아주 작은 입력의 기울기가 커서 정밀 조작에 불리해 기각했다. 선택 곡선도 거리를 완전히 선형으로 만들지는 않는다.

| 종류 | 반지름 | 충돌 질량 | 기본 최대 출발속도 |
| --- | ---: | ---: | ---: |
| 사·병·졸 | .24 | .8 | 12 |
| 차·마·상·포 | .32 | 2.4 | 11 |
| 왕 | .43 | 6.4 | 10 |

`vTarget=vType·(maximumImpulse/12)·f(p)`, `J=m·vTarget`로 계산한다. `maximumImpulse`라는 로컬 TUNE 필드는 기존 도구 호환을 위해 남겼지만 현재 의미는 **종류별 속도 배율**이다. 12가 배율1이며 UI에 이를 설명한다. 정확한 단위의 충격량은 실제 J 계산 결과다.

왕이 무겁다는 이유로 졸과 같은 최대속도를 강제하지 않는다. 기본 최대힘의 에너지는 졸57.6/왕320으로 차이는 남지만 기존24배 대신약5.56배다. 질량도1:3:8로 줄였다. 이것은 면적/부피 법칙이나 원작 공식이 아닌, 약한 졸의 왕 공격과 왕의 과도한 연쇄 타격을 함께 완화하기 위한 게임 밸런스 가설이다.

같은 충격량 모델은 왕의 최대 자유이동이약.004칸, 같은 에너지 모델은약.144칸으로 너무 짧았다. 종류별 속도만 줄이고 질량24를 남기는 후보도 비교했다. 최종 후보는 한 계수 변경의 효과가 아니라 입력·충돌·속도를 명시적으로 분리한 조합이다. 비교표에서 개별 변경 후보와 최종 조합을 구분한다.

## 충돌과 바닥

충돌은 계속 dyn4j가 계산한다. 반발.55는 .9보다 큰/작은 알의 과도한 튕김을 줄이는 가설이다. 고정 회전·원형 충돌·접촉마찰.15·bullet·maximumTranslation2는 유지한다. 새 속도 상한은 **발사 입력의 상한**이며 충돌 후 속도를 임의로 잘라 운동량을 없애는 후처리가 아니다.

바닥은 일정 감속18을 모든 종류에 동일하게 적용한다. 작은 알의 자유 최대거리약4칸, 최대속도12를 목표로 `a≈v²/(2D)=18`을 먼저 정했다. 왕의 큰 충돌 에너지를 감추려고 감속을 더 높이지 않았다. 실제 고정스텝 결과와 해석식 사이에는 스텝 오차가 있다.

속도 비례 감쇠(lambda6)도 비교했으나 저속 꼬리와 임계값 의존성이 커 일정 감속을 유지했다. 새 모델은 속력이 stopSpeed보다 작아지면0으로 두고24스텝 안정화를 확인한다. 자동 sleep은 꺼 정지 결정을 하나로 관리한다. 기준선에는 원래 없던 저속 clamp를 섞지 않는다.

## 조준 표시와 재생

SHOT 요청 필드는 그대로다. 로컬 STATE에 `modelId`, `inputCurveBoost`, 알별 `launchSpeed`를 더한다. UI는 서버가 준 상한과 곡선을 사용해 입력%·예상 출발속도를 표시하고 화살표 길이에도 같은 응답을 적용한다. 충돌 후 거리 예측선은 아니다.

20Hz/100ms는 유지한다. `AlkkagiReplay(delayMs)`로 다른 버퍼를 비교할 수 있지만 화면에 새 튜닝 메뉴나 운영 설정은 추가하지 않았다. 40Hz는 무지터 위치 오차를 줄였으나 합성 지터에서는 항상 낫지 않고 전송량이 증가했다. 발사단위 전체 궤적을 미리 전달하는 프로토콜은 이번 범위에서 필요성이 확인되지 않아 추가하지 않았다.

로컬 전송은 독립50ms 타이머 대신 physics의6스텝마다 최신 스냅샷을 만든 뒤 단일 sender executor에 전송을 예약한다. AtomicBoolean으로 작업을 합쳐 느린 수신자 때문에 무한 큐가 쌓이지 않게 하고, 송신 완료 시 새 최신 상태가 있으면 다시 깨운다. 물리 스레드는 socket I/O를 하지 않는다. 오류 스냅샷도 같은 경로로 보낸다. fixed-rate 타이머만으로 바꿨던 중간 시도는 기각했다.

## 부작용·후속 판단

- 졸→왕 밀림은 .024→.120칸으로 늘었다. “왕은 거의 안 움직임”과 극단적 질량비 제거 사이의 절충이며 사용자 확인이 필요하다.
- 왕의 약한 당김 거리는 이전보다 약간 길어졌다. 입력 반응을 살린 결과이며 완벽한 개선으로 표현하지 않는다.
- 작은 알의 최대 자유거리는3.69→3.95칸으로 조금 증가했다. 모든 이동을 짧게 만든 설계가 아니다.
- 물리 정지까지 시간이 더 길어진 경우가 있다. 왕의 폭발적 충돌을 줄이는 것과 경기 템포는 별도 기준이다.
- 기존 아이템8종은 아직 구현 전이다. 향후 크기/질량 효과가 최대 출발속도를 자동으로 바꾸지 않도록 Profile의 역할을 유지해야 한다. 아이템 호환성 완료라고 표시하지 않는다.
- 최종 손맛은 같은 당김·같은 배치의 실제 사용자 검수가 필요하다. 새 수치가 정답이라는 의미는 아니다.
