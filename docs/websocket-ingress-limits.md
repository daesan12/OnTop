# WebSocket 공통 유입 제한

2026-10-29 로컬 구현. 팀원 인증 코드·DB·프록시 설정은 변경하지 않았다.

## 적용 경계

기존 구체 Handler 주입 타입을 유지하는 Spring 클래스 프록시로 공개 수명 메서드만 감싼다.
인증·Origin·접속권·회원 중복 연결 판정은 기존 Handler에 위임한다.

- HTTP Upgrade **이후**, 추가 회원 재검사/Hub 등록 전에 JVM 전체·주소별 동시 연결 수를 원자적으로 검사한다.
- 완성 텍스트의 UTF-8 크기·토큰 버킷을 JSON 파싱/Hub 잠금 전에 검사한다. 정상/오류/조회/중복/알 수 없는
  타입을 모두 센다. Pong은 기존 heartbeat로 전달한다. 초과 연결만 닫고 다른 연결은 유지한다.
- 종료/인증 거절은 슬롯을 한 번만 반환한다. 전송 오류 중 아직 열린 연결은 실제 종료까지 보유한다.
  누락된 종료 콜백은 10초마다 또는 다음 접속 때 닫힌 소켓만 회수한다. 종료한 주소 집계도 제거한다.

## 설정

**로컬 검증 기본값이며 승인된 운영 한도·실측 수용량이 아니다.** `ontop.websocket.limits`로 조정한다.
0/음수·비정상적으로 큰 값은 시작 오류다. 비활성화 플래그는 없다.

| 설정 | 로컬 기본값 | 의미 |
| --- | --- | --- |
| messages-per-second | 120 | 연결별 초당 보충 토큰 |
| burst | 240 | 최대 누적·순간 허용 토큰 |
| max-connections | 200 | 인증 진행 중을 포함한 JVM별 Upgrade 연결 수 |
| max-connections-per-address | 100 | 판정 주소별 동시 연결 수 |
| trusted-proxy-cidrs | 빈 목록 | X-Real-IP를 신뢰할 실제 직전 프록시 IP/CIDR |

단조 증가 시계로 보충하고 유휴 시간에도 burst를 넘지 않는다. 새 연결은 새 버킷으로 시작하므로
**재접속 빈도 제한은 아니다**. 수치의 적정성은 배포 전에 [협의 목록](team-decisions.md)에서 확인한다.
신뢰 프록시가 없으면 소켓 peer만 사용한다. 명시한 CIDR의 peer에서만 단일 숫자 X-Real-IP를 사용하며,
호스트 이름·복수 헤더·쉼표 목록·잘못된 주소는 peer로 묶는다. DNS나 X-Forwarded-For 목록을 조회하지 않는다.
공유 프록시/NAT 사용자가 한 주소로 묶일 수 있으므로 CIDR·헤더 덮어쓰기·주소 상한을 함께 조율한다.

## FE 계약·지표

새 요청 타입·정상 JSON·REST API는 없다. 기존 `/ws/tables`에서 다음 Close Code를 받을 수 있다.
Upgrade 단계에서 접속권이 이미 소비될 수 있으므로 상한 거절 후 재시도도 반드시 새 접속권을 발급받는다.

| 상황 | Code / reason | 처리 |
| --- | --- | --- |
| 새 연결 상한 초과 | 1013 / WS_CONNECTION_LIMIT | 기존 연결 유지, 즉시 반복하지 말고 지연 재시도 |
| 메시지 빈도 초과 | 1013 / WS_RATE_LIMITED | 전송 중지 후 기존 새 접속권·복구 경로로 지연 재연결 |
| UTF-8 16KiB 초과 | 1009 / WS_MESSAGE_TOO_LARGE 또는 컨테이너 크기 오류 | 본문 축소, 파싱 전 종료에는 JSON 응답 없음 |

제한을 로그아웃·고의 기권·부정행위로 분류하지 않는다. 종료는 기존 네트워크 단절 경로를 따르며
30초 유예·턴 마감·동일 actionId/멱등키 재확인은 유지한다. 응답 유실 시 새 키로 행동/보상을 재실행하지 않는다.
FE 표시·재시도 간격은 미확정이다.

`ontop.websocket.ingress.connections`는 현재 보유 연결 수,
`ontop.websocket.ingress.rejected{reason=GLOBAL_CONNECTIONS|ADDRESS_CONNECTIONS|RATE|SIZE}`는
고정 사유별 거절 횟수다. 차단 뒤 텍스트마다 계수를 반복하지 않는다. IP·회원/세션 ID·ticket·JWT·본문·손패·
눈은 새 로그·태그에 넣지 않는다. 기존 관리 엔드포인트 인증도 유지한다.

## 검증과 남은 범위

로컬 TCP로 정상 요청/1013/다른 연결 유지/슬롯 반환/재연결, 인증 중복1008·폐기4401 뒤 반환,
16KiB 분할 요청/1바이트 초과1009·멀티바이트 초과를 검사한다. 회원 DB 조회는 기존 경계의 대역이다.
공용 DB·운영 부하·서버 적용은 검증하지 않았다. Upgrade 전 TCP/TLS·Origin/접속권 검사·로그인 DB 조회,
접속권 발급·재접속 빈도, 다중 JVM 한도·프록시 limit_req/limit_conn·ticket 로그 마스킹은 별도 조율한다.
