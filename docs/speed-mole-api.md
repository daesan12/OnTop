# 스피드 두더지 잡기 기록·랭킹 API

구현 계약이며 배포·공용 DB 적용 완료를 뜻하지 않는다. 격리 MySQL 검증과 팀 V151 번호 사용·V150 다음 적용 순서 확인을 완료했다. MR 병합·배포는 아직 남아 있다. 기존 두더지·붕어빵·공원 랭킹판은 변경하지 않는다. 사용자 후속 승인으로 기존 지갑·보상 원장을 재사용해 5점당 1냥(처음 40점에서 사용자 요청으로 조정)을 공통 일일 상한 안에서 지급한다. 추가 스키마 변경은 없다.

## 규칙

- 위 RTYU / 아래 FGHJ, 8구멍 중 4마리 유지. 잡은 구멍은 제외한 기존 빈 구멍으로 즉시 교체한다.
- 준비 3초 뒤 플레이 60초. 성공 +1, 빈 구멍 −3, 매 입력 직후 0점 하한. 등장 모션은 판정 지연이 아니다.
- 서버가 발급한 unsigned 32-bit seed와 규칙 버전 1의 LCG를 양쪽이 사용한다. `state=(state*1664525+1013904223) mod 2^32`, 선택 인덱스는 `floor(state*length/2^32)`다.
- 서버는 타격 순서로 목표를 재생하고 점수·성공·실수를 직접 계산한다. 요청에 클라이언트 점수를 받지 않는다. 인간의 직접 조작이나 봇 부재까지 증명하는 방식은 아니다.
- 입력은 최대 6000개, hole 0~7 정수, at은 준비 시간을 제외한 시작 기준 0~59999ms 정수·비감소 순서다. 잘못된 기록은 전체 거절한다.
- 서버의 60초 마감 전 제출은 거절한다. 마감 뒤 30초까지 제출할 수 있다. 단말 시계나 클라이언트가 주장한 종료 시각으로 마감을 바꾸지 않는다.
- 중도 종료·새로고침한 미확정 판은 랭킹에 포함하지 않는다. 미완료 행은 ACTIVE로 남으며 새 판이 생긴 이전 판은 완료할 수 없다. 자동 정리 정책은 이번 범위에 포함하지 않는다.
- 정상 확정 기록 중 개인 최고 하나를 선택한다. 점수 내림차순 → 실수 오름차순. 두 값이 같으면 공동 순위(RANK: 1,1,3), 먼저 확정한 시각·기록 ID 순서로 노출한다. 탈퇴 회원·다른 규칙 버전은 제외한다.

## 공통

Bearer 인증과 기존 허용 Origin 정책을 따른다. 응답은 `Cache-Control: no-store`다. 기존 회원 지갑이 필요하며 관리자 권한은 필요 없다. `ontop.minigames.enabled=true`와 DB 프로필, V151 테이블이 필요하다. 프론트는 다른 오락기 게임처럼 개발·운영 공원의 게임 목록에서 노출하며 호스트명·Vite 개발 모드로 진입을 제한하지 않는다. 백엔드는 기존 `prod,db` 또는 `production,db` 프로필과 `MINIGAMES_ENABLED=true`를 사용한다. 목록 노출만으로 서버 미활성·DB 미적용을 우회하지 않으며 시작·완료·보상·랭킹은 기존 인증된 서버 API로 처리한다.

## 시작

`POST /api/v1/minigames/speed-mole/rounds`, `Idempotency-Key: <1~64 ASCII letters/digits/_/->`, body 없음.

```json
{"id":"7","seed":1,"rulesVersion":1,"serverNow":"2030-01-01T00:00:00Z","startedAt":"2030-01-01T00:00:03Z","durationMs":60000}
```

201. 같은 회원·키 재전송은 같은 판·seed·시각을 반환한다. 완료했거나 만료한 시작 키는 409이므로 다음 시작은 새 키를 사용한다. 다른 새 키로 판을 열면 이전 미완료 판은 더 이상 완료·보상할 수 없다. 같은 회원의 시작·완료는 지갑을 먼저 잠가 순서를 정한다. 클라이언트는 서버 응답이 확인되기 전에는 로컬 판을 시작하지 않는다.

## 완료

`POST /api/v1/minigames/speed-mole/rounds/7/complete`

```json
{"taps":[{"hole":1,"at":0},{"hole":3,"at":100}]}
```

```json
{"id":"7","rulesVersion":1,"score":2,"hits":2,"misses":0,"completedAt":"2030-01-01T00:01:03Z","calculatedReward":0,"reward":0,"todayEarned":0,"dailyCap":500}
```

200. 회원 ID는 인증 주체에서만 읽는다. 완료 행을 잠그고 한 번만 확정한다. 동일 판의 재시도·동시 완료·서로 다른 재전송 본문에도 먼저 확정된 결과를 반환하며 다시 계산하거나 중복 저장하지 않는다. 원래 요청이 성공했는지 불확실하면 같은 판·같은 타격 기록으로 재확인한다. 프론트는 확인 전 성공/랭킹 반영을 표시하지 않는다. 5점당 1냥(서버 `SpeedMoleRules.POINTS_PER_COIN`, 기존 두더지와 별도)을 미니게임 공통 KST 하루 500냥 상한 안에서 지급한다. 지갑 잠금→경기 잠금→서버 재계산→공통 예산 확인→지갑·원장·경기 확정을 같은 트랜잭션으로 처리한다. 원장 분류는 기존 두더지 계열 MOLE_REWARD이고 멱등 키는 mole:reward:speed:<roundId>라 기존 두더지 키와 충돌하지 않는다. 중복 완료는 원래 지급액만 반환한다. 예전 랭킹 전용 확정 기록은 재요청해도 소급 지급하지 않는다.

## 전체 랭킹·내 최고

`GET /api/v1/minigames/speed-mole/rankings?limit=20&offset=0`

```json
{"rulesVersion":1,"period":"ALL_TIME","updatedAt":"2030-01-01T00:01:04Z","totalParticipants":1,"offset":0,"limit":20,"items":[{"rank":1,"userId":"101","nickname":"테스트 회원","score":2,"hits":2,"misses":0,"completedAt":"2030-01-01T00:01:03Z"}],"me":{"rank":1,"userId":"101","nickname":"테스트 회원","score":2,"hits":2,"misses":0,"completedAt":"2030-01-01T00:01:03Z"},"hasMore":false}
```

200. limit 1~100(기본20), offset 0~10000(기본0). 내 기록이 없으면 me=null. 현재 페이지 밖이어도 내 최고 기록을 별도로 제공한다. 목록·참가자 수·내 기록은 같은 읽기 트랜잭션 스냅샷이다. 페이지를 새로 조회하면 그 사이의 새 기록으로 순서가 바뀔 수 있다. 공원 전체 랭킹판에는 추가하지 않는다.

## 오류와 적용 순서

- 400: `SPEED_MOLE_INVALID_KEY`, `SPEED_MOLE_INVALID_REQUEST`, `SPEED_MOLE_INVALID_TAPS`, `SPEED_MOLE_INVALID_PAGE`.
- 401/403: 기존 로그인·Origin 정책. 타인 판·없는 판은 404 `SPEED_MOLE_ROUND_NOT_FOUND`.
- 409: `SPEED_MOLE_NOT_FINISHED`, `SPEED_MOLE_ROUND_EXPIRED`, `SPEED_MOLE_ROUND_FINISHED`, `SPEED_MOLE_ROUND_SUPERSEDED`, `WALLET_NOT_READY`.
- 503: `SPEED_MOLE_UNAVAILABLE`. 미활성·테이블 미적용·DB 장애 시 로컬 결과나 가짜 랭킹으로 대체하지 않는다.

팀 번호·순서 확인 및 격리 DB에서 V151/동시성/랭킹 검증 완료 → SQL 포함 MR → 사용자 병합 → 기존 배포 파이프라인에서 DB·BE → FE → 로그인 계정으로 시작·완료·랭킹·재시도 검수. 스키마는 새 테이블만 추가하며 기존 데이터·SQL 수정/repair/outOfOrder는 사용하지 않는다.

## 로컬 검증 범위 (2026-11-05)

격리 MySQL에서 V151 적용, 같은 시작 키의 동시 요청, 동시 완료의 단일 확정, 개인 최고·공동 순위·버전/탈퇴 제외를 4개 검사로 확인했다. 관련 백엔드94개와 프론트88개 검사, TypeScript 및 park build를 통과했다. 실제 로컬 공원에서2점 완료→격리 DB 저장→내 최고2점·전체 랭킹 재조회를 확인했다. 계정/인증은 테스트 대역이며 개발 서버 로그인·배포 검수는 아니다. 백엔드 전체 검사는 Windows 클래스패스 탐색 지연으로 완료하지 못했다.

보상 연결 후 추가 검증: 관련BE95/95·FE82/82·격리MySQL7/7 통과. 실제 로컬 UI40점→1냥→잔액100에서101냥, 두 게임의 공통 일일1/500냥 표시를 확인했다. 지연 완료 응답에서 결과 UI가 닫혀도 같은 계정의 공원 잔액 재조회가 유지된다. 계정/공원은대역이며 지갑·원장·두더지/스피드저장은실제격리DB다. 신규스키마/V151수정은없다.
