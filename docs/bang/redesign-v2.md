# 탑골 총잡이 화면 개편

- 작업 브랜치: `feat/bang-table`, 작업 위치: `OnTop/bang-20261121`.
- 작업 시작 시 전체 원격 브랜치를 가져왔고 최신 `origin/dev` `2aecab6531b06ec3c919726baf41cf75e31a059c`가 현재 이력에 포함된 것을 확인했다. 기존 작업과 공유 브랜치 이력을 보존한다.
- 변경 범위: 게임 UI·한국어 표시 문구·로비/설명서 이름·UI 삽화. 공원 지형/좌표/시설/좌석/충돌/카메라 및 인프라 설정은 변경하지 않는다.
- 기존 공개/개인 상태와 gameCode·카드 kind·인물 식별자는 호환성을 유지한다. DB 구조 변경이 없어 신규 migration은 필요하지 않으며 V187도 수정하지 않는다.

## 사용자 요청과 해결

1. 고객에게 보이는 게임명은 **탑골 총잡이**다. 게임 화면·로비·결과에 사용하는 게임명·설명서·페이지 제목·서버 안내 문구를 맞췄다.
2. 내 정보는 별도 한지 영역에 역할, 승리 목표, 공개 인물, 능력 전체 문장, 하트와 현재/최대 생명력, 무기 이름, 공격 사거리, 기타 장비를 표시한다. 장착 무기가 없을 때도 ‘기본 권총’과 사거리 1을 명시한다.
3. 상대 정보는 공개 범위에서만 표시한다. 인물/능력/무기/생명력/손패 수/거리를 보여주고, 보안관·탈락자 외의 역할은 비공개로 유지한다. 작은 화면에서도 능력 문장을 숨기거나 잘라내지 않는다.
4. 카드 이름은 사격·회피·맥주·결투·보급 마차·잡화점·강탈·장비 파괴·연발 권총 등 한국어로 정리했다. 3D 카드의 실제 이름도 같은 표시 사전을 사용한다.
5. 카드 위에 마우스를 올리거나 키보드로 포커스하면 종류·효과·사용 조건·예외를 담은 설명창을 표시한다. 터치로도 설명을 확인할 수 있으며 Esc·스크롤·포커스 이탈로 닫힌다. 비활성 손패도 설명을 읽을 수 있지만 실제 사용은 차단한다. 공개 장비와 판정 카드에도 설명을 제공한다.
6. 카드 선택 후 오른쪽 설명 영역에서 효과를 다시 확인하고 사용한다. 모바일에는 ‘내 손패’ 바로가기를 제공한다. 모든 스크롤바는 숨기면서 휠·터치·키보드 스크롤을 유지한다.
7. 옛 이름과 영어 카드명이 이미지에 들어갈 수 있던 로비/설명서 썸네일을 글자 없는 새 삽화로 교체했다. 이름과 효과 문구는 HTML/Canvas로 표시한다.

## 화면 기준과 에셋

- 디자인 기준: `redesign-v2.png` — 내장 Image Gen으로 생성한 전체 화면 콘셉트.
- 색: 짙은 녹색 헤더/주 버튼, 먹색 글자, 크림색 한지, 황동 테두리. 기존 한지 원본을 사용하고 장식 대비를 낮춰 내용과 겹치지 않도록 한다.
- 구조: 좌측 내 정보+기록/채팅, 우측 상대 3열×2행, 하단 손패+설명/행동. 작은 화면은 내 정보를 먼저 보여주고 상대·손패는 좌우 스크롤, 전체는 세로 스크롤한다.
- 글자: 제목은 기존 명조, 본문은 시스템 고딕. 역할·생명력·능력·무기/사거리는 명시적인 라벨을 사용한다.
- 삽화: `frontend/public/art/bang/portraits-v1.webp`와 `cover-v2.webp`는 새로 생성한 글자 없는 독자적인 이미지다. 기존 카드 삽화는 재사용한다. 생성 프롬프트와 출처는 해당 폴더의 `SOURCE.md`에 기록했다.

## 검수 경로

- 독립 화면: `http://127.0.0.1:5267/topgol-preview.html?count=7`. UI fixture이며 실제 경기/지갑/정산은 실행하지 않는다.
- 전체 카드 검수: 위 URL에 `&cards=all`을 붙이면 카드 22종을 모두 확인할 수 있다.
- 실제 공원: `http://127.0.0.1:5267/topgol-park.html?account=101`, `account=202`. 4인 시작에는 303/404 계정을 추가한다. 서로 독립된 브라우저 프로필을 사용하고 같은 채널을 선택한다.
- 기존 개발용 URL도 새 한국어 화면을 표시하도록 유지한다.
- FE 5267 / BE 19187은 기존 실행 방식을 재사용한다. 인증/지갑/예약/정산은 로컬 memory fixture이며 공원·게임·WS는 실제 로컬 코드다. 운영 DB와 외부 인증에는 연결하지 않는다.

## 검증과 제약

- Browser 플러그인이 없어 일반 Playwright + 설치된 Chrome으로 검사했다.
- 콘셉트와 실제 화면을 view_image로 대조했다. 내 정보 위계, 상대 정보 공개 범위, 한국어 카드 제목/종류, 한지 대비, 설명창/행동 영역, 모바일 접근성 6개 항목을 확인했다. 실제 화면은 동적인 경기 데이터를 표시하고, 글자는 코드로 렌더링한다. 모바일에서는 정보를 숨기지 않고 스크롤로 제공한다.
- 카드 설명 22종 전체의 낮은 가로 화면(844×390) 범위와 터치 설명, 손패 이동을 검사했다. 데스크톱 1536×1024와 모바일 390×844·800×480에서도 핵심 정보와 카드 사용을 확인했다. 헤더 버튼 hover 대비와 데스크톱 기록·채팅 확대/닫기도 확인했다.
- FE 타입 검사와 표시/개인 정보 보호/설명서/테이블 관련 32개 테스트, 기존 BE 규칙·시작·종료 25개 테스트가 통과했다. 최신 공원 모드 Vite 빌드도 맵 생성기를 실행하지 않는 직접 명령으로 통과했다.
- 실제 로컬 공원에서 독립 세션 4개가 채널 1에 입장해 중앙 테이블 2에서 준비/시작했다. 장거리 권총 사용 후 서버 상태와 화면 사거리가 2로 바뀌는 것, 비활성 회피 카드 설명, 채팅, 기권/결과/다음 판 준비/퇴장을 확인했다. HMR 후 진행 중 경기 복구도 확인했다. 관련 브라우저 오류는 없었다.
- 계정 101/202는 경기 후 같은 공원에 복귀하여 WS 연결·mapCompatible·좌석 해제를 확인하고 실제 이동에 따른 좌표 변화를 확인했다. 두 링크는 독립 프로필에서 사용한다. 검수 배너가 모바일 행동 버튼을 가리던 문제는 배너의 레이어와 포인터 처리로 수정했다.
- 화면 증거: [7인 UI fixture](redesign-v2-screen.webp), [실제 로컬 4인 경기](redesign-v2-live.webp). 7인 fixture 검증을 실제 7인 동시 접속 성공으로 해석하지 않는다.
- 기존 large-chunk/Three.js 경고와 공원 상세 geometry cache 경고는 남아 있으며 이 작업에서 맵 생성기를 실행하거나 인프라 설정을 변경하지 않는다.
- 실제 MySQL 8.4 적용·운영 정산·외부 OAuth와 7인 동시 공원 접속 제약은 이전 기록과 같다. 새 DB/인프라 변경 요청은 없다.
- MR/머지는 명시적 요청 전까지 보류한다. Jenkins 연결 정보/조회 권한은 확인하지 못했으며 로컬 빌드 통과를 Jenkins 성공으로 표시하지 않는다.
