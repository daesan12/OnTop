# 오목 관전 채팅·핑 BE 작업 명세

작성: 2026-10-27 KST. 상태: 구현 전 / 신규 통신 계약 제안. [기획](omok-ux-plan.md)과 [FE 명세](../frontend/docs/OMOK_UX_FE_SPEC.md)를 함께 사용한다.

> **2026-10-27 BE 확정(S15P31B105-236)**: 최종 메시지·필드·오류·정책은 [관전자 채팅·핑 계약](websocket-api/10-game-spectator-events.md)이 우선한다. 아래 본문은 협의 당시 제안 기록이다.
>
> 제안과 다른 점:
> - `sentAt`·`expiresAt`·`serverNow`는 ISO 문자열이 아닌 **Unix ms 숫자**다.
> - 관전자끼리도 채팅을 받는다.
> - 경기별 상한(채팅 3건/3초, 핑 5건/2초)이 있다.
> - 다른 수신자 전달은 큐 포화·만료 시 폐기될 수 있는 비필수 이벤트다.
> - 플레이어 발신 거절은 `GAME_SPECTATOR_ACCESS_DENIED`다.
> - 오류 코드 10종을 확정했다.
>
> 서버 로컬 통합 검사까지 완료했으며 개발 서버 배포와 FE 공동 검수는 별도다.

담당자에게 전달할 요청 글은 [오목 관전자 채팅·핑 BE 연동 요청서](../frontend/docs/OMOK_UX_BE_REQUEST.md)를 사용한다. 기존 문제, FE에서 완료한 기획·미리보기와 후속 구현 범위, BE 요청사항을 구분해 작성했다. 아래는 계약 협의와 구현 검증을 위한 상세 명세다.

## 선행 의존성과 작업 범위

기존 진입·선택·준비·수동 시작·정산을 선행 기준으로 사용한다. 충돌하면 선행 작업을 유지하고 후속 구현을 맞춘다. 카메라·HUD·메뉴 숨김은 FE 작업이다. BE 추가 범위는 승인된 관전자의 오목 경기별 채팅·핑 전달과 권한·수명·중복·빈도 처리다. 기존 착수·시간·승패·정산 계약을 다시 정의하지 않는다.

사용자 확정: 플레이어는 관전 채팅을 받기만 한다. 핑은 두 플레이어와 해당 경기 관전자 모두에게 전달한다. 관전자끼리도 동일 경기 채팅을 받는 것은 이 명세의 기본 제안이다.

## BE-01: 기존 경로 확장과 권한

- 기존 인증 `/ws/tables`, `TableWebSocketHandler`→`TableHub` 경로를 사용한다. `TableProtocol` 검증·디스패치와 관전 구독 처리를 확장한다. 별도 소켓이나 무인증 전송 API를 만들지 않는다.
- 실제 `GAME_WATCH`가 승인되고 같은 경기 공개 상태를 읽을 수 있는 관전자만 발신할 수 있다. `TABLE_WATCH`나 근처에 서 있다는 사실만으로 발신 권한이 생기지 않는다.
- 발신자 계정·역할·채널·경기 상태는 서버 연결에서 판별한다. 클라이언트 userId/role 주입을 허용하지 않는다. 플레이어는 채팅·핑 발신을 거절하고 수신만 허용한다.
- 관전자 발신과 수신 대상 선정 때 기존 같은 채널·테이블 중심 20m 자격을 검사한다. 참가자는 해당 경기의 실제 참가 권한을 검사한다. 다른 경기·채널·일반 근처 사용자에게 전달하지 않는다.
- 관전 승인 전/취소 중/해제·거리 이탈·채널 변경·연결 종료·경기 종료 후에는 발신과 새 전달을 차단한다. 관전자→플레이어 전환 등은 기존 구독 종료 수명주기를 따른다.
- 플레이어 수신은 인증·복구가 완료된 해당 경기 참가자 경로로 연결한다. 로비용 `GAME_RECOVERY_REQUIRED` 게이트를 통째로 우회하지 않는다.
- 기존 `WORLD_CHAT_SEND`는 발신자 중심 20m 채팅이며 경기 ID가 없다. 일반 공원 채팅을 참가자에게 무조건 중계하지 않는다. 텍스트 검증은 재사용하되 경기별 이벤트로 구분한다.

## BE-02: 신규 통신 계약 제안

아래 메시지명·필드는 아직 서버에서 지원하지 않는다. 선행 계약과 대조한 뒤 BE가 최종 스키마를 확정하고 FE와 함께 갱신한다. 기존 최상위 requestId와 ERROR envelope를 사용한다.

| 방향 | 제안 메시지 | payload |
| --- | --- | --- |
| C→S | `GAME_SPECTATOR_CHAT_SEND` | `{gameId,eventId,text}` |
| S→C | `GAME_SPECTATOR_CHAT_MESSAGE` | `{gameId,eventId,senderUserId,text,sentAt,expiresAt,serverNow}` |
| C→S | `OMOK_SPECTATOR_PING_SEND` | `{gameId,eventId,basedOnVersion,x,y}` |
| S→C | `OMOK_SPECTATOR_PING` | `{gameId,eventId,senderUserId,basedOnVersion,x,y,sentAt,expiresAt,serverNow}` |

- gameId는 기존 경기 ID 형식, eventId는 클라이언트 발급 UUID로 수명 내 중복 판별용이다. senderUserId와 시각·만료는 서버가 설정한다. sentAt/expiresAt/serverNow는 UTC ISO-8601이다.
- basedOnVersion은 발신 당시 공개 경기 버전의 0 이상 정수, x/y는 0~14 정수의 판 좌표다. 추가 필드·NaN·소수·화면/월드 좌표를 받지 않는다.
- 채팅 text는 기존 `ChatText`의 1~200 Unicode 코드포인트, 공백·제어문자·잘못된 surrogate 검증을 재사용한다. 서버는 원문을 전달하고 FE가 안전한 텍스트로 표시한다.

채팅 요청 예시:

```json
{"requestId":"spectator-chat-1","type":"GAME_SPECTATOR_CHAT_SEND","payload":{"gameId":"omok-game-1","eventId":"2d895dfa-3ffb-4bd8-92ca-5c9e3bf8921b","text":"가운데 쪽을 막아봐요!"}}
```

핑 요청 예시:

```json
{"requestId":"spectator-ping-1","type":"OMOK_SPECTATOR_PING_SEND","payload":{"gameId":"omok-game-1","eventId":"ee46b20f-e2b9-40ee-9a73-7a86c59e65a2","basedOnVersion":8,"x":7,"y":7}}
```

핑 전달 예시(시간과 ID는 예시):

```json
{"requestId":null,"type":"OMOK_SPECTATOR_PING","payload":{"gameId":"omok-game-1","eventId":"ee46b20f-e2b9-40ee-9a73-7a86c59e65a2","senderUserId":"505","basedOnVersion":8,"x":7,"y":7,"sentAt":"2026-10-27T01:00:00Z","expiresAt":"2026-10-27T01:00:02Z","serverNow":"2026-10-27T01:00:00Z"}}
```

## BE-03: 승인 응답·중복·버전 정합성

- 승인 이벤트를 발신자에게 원래 requestId로, 나머지 수신자에게 requestId=null로 전달하는 방식을 제안한다. FE는 발신자도 서버 이벤트 수신 후 한 번만 표시한다. 거절은 해당 요청의 ERROR로 응답한다.
- 동일 계정·경기·eventId와 동일 내용은 유효 시간 내 기존 승인 결과만 발신자에게 돌려주고 전체 재방송하지 않는다. 다른 내용은 충돌로 거절하고 만료 이벤트를 다시 살리지 않는다. FE 자동 재시도는 하지 않는다.
- 중복 캐시는 경기·사용자별 크기와 TTL을 제한한다. 일회성 이벤트를 영구 이력이나 복구 GAME_STATE에 추가하지 않는다.
- 핑 승인 시 공개 경기 버전과 basedOnVersion의 일치를 검사한다. 실제 착수와 경쟁하면 동일 경기 읽기/직렬화 경계에서 버전을 확인하고 오래된 핑은 거절한다.
- 모든 교차점 핑을 기본 제안으로 하며 실제 돌이 있는 위치도 허용한다. 금수는 착수 규칙이므로 핑 때문에 금수 판정이나 게임 행동을 실행하지 않는다.
- 핑 승인 직후 실제 수가 진행되면 FE가 다른 버전 핑을 제거한다. 핑이 상태보다 먼저 도착할 수도 있으므로 이벤트를 착수 ACK나 경기 상태 전송 순서에 결합하지 않는다.
- 채팅·핑은 판·차례·turnDeadline·moveCount·경기 version·승패·정산을 변경하거나 GAME_ACTION_RESULT를 만들지 않는다. 연출이 끝날 때까지 다음 수·시간 만료를 지연시키지 않는다.

## BE-04: 수명·빈도·정리

- 초기 제안: 채팅 TTL 3초, 핑 TTL 2초, 사용자당 종류별 최소 전송 간격 1초. 최종 정책은 설정값으로 합의한다. 거절된 요청으로 정상 이벤트의 수명이나 쿨다운을 연장하지 않는다.
- 현재 코드가 OMOK+PLAYING인 경우에만 지원한다. 메시지 이름을 공통으로 제안했더라도 다른 게임에 자동 적용하지 않는다.
- 관전 종료·경기 종료·연결 종료 때 관련 이벤트·캐시를 정리하고, 늦게 도착한 이벤트가 다음 경기로 전달되지 않게 한다. 재관전·재접속 시 과거 채팅·핑을 재생하지 않는다.
- 기존 peer 전송 큐 정책과 이벤트별 상한을 확인한다. 무제한 대기열을 만들지 않고 만료 이벤트는 큐에서도 폐기한다. 느린 수신자가 경기 상태 전송을 막지 않게 한다.
- serverNow와 기존 서버 시각 동기화 계약으로 FE의 초기 수명 계산을 지원한다. 전송 지연을 수명에서 제외해 항상 TTL 전체를 새로 주지 않도록 시각 보정 계약을 FE와 합의한다.
- 화면 위치·불투명도·모션·링 색은 FE 책임이다. 서버는 화면 좌표·카메라를 지정하지 않는다.
- 오류 구분: 기존 INVALID_PAYLOAD, 관전 권한 없음, 미지원/종료 경기, 핑 버전 만료, 빈도 초과, eventId 충돌. 신규 오류 코드 문자열은 스키마 확정 시 명시한다.

## BE 인수 조건

| 검수 | 통과 기준 |
| --- | --- |
| 역할 | 승인 관전자만 발신, 플레이어 수신만. role/userId 주입 거절 |
| 전달 범위 | 두 플레이어+승인된 전체 관전자 핑 수신, 다른 경기·테이블·채널 유입 없음 |
| 해제 경쟁 | 승인 전·취소·거리 이탈·해제·재접속·종료 후 발신/새 전달 차단 |
| 좌표/버전 | 0/14 경계 허용, 범위 밖/소수/이전 버전 거절, 착수와 핑 경쟁 정합성 |
| 불변 | 채팅/핑 전후 판·version·차례·마감·승패·정산 동일 |
| 중복/폭주 | 같은 eventId 재방송 없음, 내용 충돌·TTL·캐시/큐 상한·사용자별 빈도 정상 |
| 시간 | F1과 무관하게 기존 30초 만료·시간패, 채팅/핑으로 마감 연장 없음 |
| 실제 연동 | 인증된 두 참가자+관전자 2명 이상으로 채팅·핑·턴 변경·관전 해제·종료 공동 검증 |

선행 BE 머지 후 메시지명·필드·오류 코드를 확정하고 FE 어댑터를 연결한다. 명세 작성이나 대역 검사만으로 서버 지원/배포 완료를 선언하지 않는다.
