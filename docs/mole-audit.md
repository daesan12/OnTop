# 두더지 운영 관측

`/admin`의 **게임 매크로 분석**에서 **두더지 잡기** 또는 **스피드 두더지 잡기** 메뉴를 고른다.
닉네임 전체, 회원 ID, 판 ID, 한국 날짜를 조합해 최근 40판을 조회한다. 목록에는 회원, 시작 시각,
확정 점수, 관측 수가 표시되고, 판을 선택하면 같은 회원의 최근 판과 타임라인을 볼 수 있다.
상단 **매크로 의심 회원**은 해당 게임의 최근 30일간 함정 표적과 타이밍 신호를 자동 조회한다.
같은 회원의 신호를 한 행에 모으고, 각 유형의 판 수와 가장 최근 근거 판을 표시한다.

- 클라이언트는 판 중 타격을 약 350ms 단위로 묶어 `POST /api/v1/minigames/{game}/rounds/{id}/observations`로 보낸다.
  `game`은 `whack-a-mole` 또는 `speed-mole`이다. 회원은 인증 주체에서 읽고 판 소유권은 서버에서 검사한다.
  요청은 점수·엽전·랭킹 API와 독립적이다. 수신 시각은 서버가 붙이며, 표적 등장·입력 시간과 적중 결과는 클라이언트 보고값이다.
- 타격 묶음과 완료 제출의 더미 신호는 기존 행동 로그에 각각 `MOLE_TAP_BATCH`, `MOLE_ROUND_HONEYPOT`으로 기록된다.
  판 중 더미 건수와 완료 제출 더미 건수는 별도로 표시한다. 정상 입력에 사용한 표적 ID 원문은 저장하지 않는다.
  배포 환경에서 기존 행동 로그가 활성화돼 있어야 새 기록이 저장된다. 큐 초과나 전송 실패로 관측 기록이 빠질 수 있다.
- `GET /api/v1/admin/macro-analysis/mole?game=…&nickname=…&userId=…&roundId=…&date=YYYY-MM-DD`는 목록을 반환한다.
  닉네임·회원 ID·판·날짜 중 최소 하나를 지정한다. 닉네임은 현재 회원 닉네임과 전체 일치로 조회하며, 다른 필터와 함께 지정하면 모두 적용된다.
  `GET /api/v1/admin/macro-analysis/mole/{id}?game=…&input=…`는 판 상세를 반환한다.
  `input`은 `KEYBOARD`, `POINTER`, `TOUCH` 중 하나이며, 두 조회는 기존 `ADMIN_READ` 권한을 적용한다.
- `GET /api/v1/admin/macro-analysis/mole/detections?game=…`도 `ADMIN_READ` 조회다. 서버가 두더지 판 소유자와 일치하는
  행동 로그에서 확인한 더미 신호만 포함한다. 같은 판에 판 중 및 종료 제출 신호가 모두 있어도 전체 적발 판은 한 번만 센다.
  적발 판 수, 최근 적발 순으로 최대 100명을 반환한다. 적발 신호는 운영 검토용이며 자동 제재나 내부 집계 제외로 이어지지 않는다.
  서버 인스턴스는 게임별 집계 결과를 30초 동안 재사용하며 같은 게임의 동시 집계 요청을 하나로 묶는다.
  응답의 조회 기준 시각은 실제로 집계한 시각이다.
- 비교는 선택한 판의 한국 날짜·게임·규칙 버전에서, 선택한 입력 방식만 관측된 판을 사용한다.
  비교 표본은 다른 회원의 정산 판 중 더미 신호가 없는 최근 판 최대 40개다. 첫 적중과 일반 두더지의 헬멧 연타 간격은
  중앙값·10/90백분위·표본 수로 표시한다. 비교 결과는 운영 검토용이며 기존 내부 집계 판정 절차는 [분석 안내](../analytics/README.md)를 따른다.

## 타이밍 신호 (S15P31B105-449)

화면을 보고 조작하는 매크로는 정상 표적 ID를 보내므로 함정 표적에 걸리지 않는다. 대신 판 확정 때 타격 시각을 분석해
`mole_timing_audits`(V181)에 판마다 한 줄을 남긴다. 두더지가 나온 시각은 클라이언트 보고값이 아니라 서버가 시드로 다시 만든
출현 순서에서 얻고, 숨은 표적 타격은 빼고 계산한다. 기록은 확정 트랜잭션이 커밋된 뒤 전용 스레드에서 저장하며
판정·점수·엽전·랭킹과 무관하다. 초고속 반응과 구간 내 일정한 타이밍 기준은 실측 전 추정치다(`MoleTimingSignals`).

| 게임 | 항목 | 기준 |
| --- | --- | --- |
| 두더지 잡기 | 초고속 반응 | 두더지(치면 안 되는 친구 제외)가 나온 뒤 그 구멍을 처음 친 반응 시간의 판 전체 중앙값이 150ms 미만, 20건 이상 |
| 두더지 잡기 | 구간 내 일정한 반응 | 반응 시간 표본이 8건 이상이고 흔들림이 12ms 미만인 30초 구간이 2개 이상 |
| 스피드 두더지 잡기 | 초고속 반응 | 판 중 새로 나온 두더지(처음 4마리 제외)를 친 반응 시간의 중앙값이 150ms 미만, 20건 이상 |
| 스피드 두더지 잡기 | 구간 내 일정한 간격 | 연속 타격 간격 표본이 10건 이상이고 흔들림이 8ms 미만인 20초 구간이 2개 이상 |
| 스피드 두더지 잡기 | 지속 고속 적중 | 20초 구간 3개 모두 적중 140건 이상, 적중률 97% 이상, 같은 구간 연속 입력 간격 90백분위 180ms 이하 |
| 두 게임 | 반복 초단기 반응 | 반응 표본 16건 이상인 구간 중 초단기 반응이 절반 이상인 구간이 2개 이상. 일반 두더지는 50ms 이하, 스피드 두더지는 100ms 이하 |

- 흔들림은 중앙값 절대 편차 × 1.4826(정규 분포의 표준편차에 해당)이다. 구간을 나누는 이유는 난이도가 바뀌면 사람의 반응도 바뀌기
  때문이며, 구간마다 지연을 바꾸는 매크로도 구간 안에서는 일정하게 드러난다.
- 스피드 두더지는 두더지 4마리가 늘 떠 있어 사람도 오래된 두더지를 치므로, 흔들림은 반응 시간이 아니라 타격 간격으로 잰다.
- 지속 고속 적중은 판 확정의 서버 리플레이로 적중과 실수를 세고, 제출된 입력 시각으로 간격을 계산한다. 이 신호의 적중 수에는 첫 4마리도 포함한다.
- 90백분위는 구간 내에서 연속 입력 간격을 정렬한 뒤 표본 수의 90% 위치를 올림해 읽는다. 구간을 가로지르는 간격은 여기서 제외한다.
- 지속 고속 적중 기준은 2026-11-15 운영 의심 판 1개와 같은 날 키보드 비교 판 6개로 예비 점검했다. 기준을 정한 뒤 다음 날 키보드 관측 판 16개에 적용했으며 새 신호는 0건이었다. 입력 주체가 확인된 표본을 확보하면 오탐률을 별도로 평가할 수 있다.
- 기존 타이밍 행은 새 신호가 배포되기 전에 저장되어 상세 화면에 지속 고속 적중 지표가 없다. 새 기준은 배포 후 확정되는 스피드 두더지 판부터 계산한다.
- 반복 초단기 반응은 출현 시각이 포함된 구간에서 센다. 판 전체 중앙값이 높더라도 여러 구간에서 초단기 반응이 일반적인 입력과 섞여 반복되면 운영 검토 신호를 남긴다.
  스피드 두더지의 첫 4마리와 일반 두더지의 고슴도치는 비교 표본에서 제외한다. 기존 타이밍 판에는 새 반응 지표가 없다.
- 일반 두더지는 점수 판정에서 제외되는 이른 입력도 조사에 포함한다. 기존 운영 관측을 재구성한 예비 표본에서 반응 수가 충분했던 일반 17판과 스피드 22판이 새 기준에 해당하지 않았다. 관측값을 사용한 비교이며, 제출 원본의 서버 리플레이나 확인된 정상 대조군 검증과는 범위가 다르다.
- `GET /api/v1/admin/macro-analysis/mole/timing?game=…`(`ADMIN_READ`)는 최근 30일 동안 신호가 한 번이라도 난 회원을
  적발 판 수, 최근 적발 순으로 최대 100명 반환하며 30초 동안 재사용한다. 판 상세 응답의 `timing`에는 그 판의 구간별 중앙값과
  흔들림과 스피드 두더지의 구간별 적중·입력 수, 입력 간격 90백분위가 담기며, 타이밍 기능 배포 전 판이나 확정되지 않은 판은 `null`이다.
