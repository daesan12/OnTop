# WebSocket 연결 생존 확인

서버가 **10초마다 Ping**, 클라이언트가 **10초 안에 동일 내용의 Pong**을 보내는 방식이다. 응답이 없으면 기존 연결을 정리하고, 인증 사용자는 그 감지 시점부터 기존 **30초 경기 재접속 유예**로 이어진다. 턴 시간은 계속 흐른다.

JSON 메시지를 새로 만들지 않고 WebSocket 제어 프레임을 쓴다. 표준 브라우저는 Pong을 자동 처리하므로 프론트 JavaScript에 HEARTBEAT/PONG 요청을 추가하지 않는다. 직접 만든 클라이언트는 Ping의 바이트를 그대로 Pong에 담아야 한다. [RFC 6455 Ping/Pong](https://www.rfc-editor.org/rfc/rfc6455.html#section-5.5.2) 기준이다.

## 처리 흐름

1. `TableHub`가 100ms 간격으로 현재 연결들을 검사한다. `WebSocketHeartbeat`는 벽시계 대신 `System.nanoTime()`으로 주기·마감을 판단한다.
2. `TablePeer`의 기존 송신 큐에 Ping을 넣는다. 텍스트와 같은 송신자에서 처리하므로 동시에 sendMessage를 호출하지 않는다.
3. 실제 전송을 시작할 때 Pong 대기를 시작한다. 전송 큐에서 응답 제한 시간만큼 대기한 경우도 끊는다. 전송 자체가 멈춰 있어도 타이머는 기다리지 않는다.
4. `TableWebSocketHandler.handlePongMessage()` → Hub → 해당 연결의 heartbeat 순으로 검사한다. 현재 보낸 Ping의 응답만 인정한다. 잘못된·전송 전·지난 Ping·마감 후 Pong, 일반 텍스트는 제한을 늘리지 않는다.
5. 만료되면 Hub의 기존 `disconnect()`가 연결 권한을 제거한다. 대기 좌석은 비우고, 인증 사용자는 `GameReconnectService.disconnected()`로 유예를 시작한다. 네트워크 close는 잠금 밖에서 시도한다. 늦은 close·Pong이 다시 와도 정리는 중복 적용하지 않는다.

유예 안에 같은 계정이 돌아오면 현재 경기 상태를 조회하고, 유예를 넘기면 기존 기권·탈락 경계로 간다. [재접속 계약](game-reconnect.md)을 따른다. 실제 로그인·경기 엔진 구현체가 필요한 상태는 그대로다.

## 설정과 한계

`local`에서 연결마다 자동 활성화하며 dev 사용자도 검사한다. 인증 여부나 테이블 착석 여부와 무관하게 연결이 살아 있는지 확인한다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `ontop.websocket.heartbeat.interval` | `10s` | 연결 시점 또는 정상 Pong 이후 다음 Ping까지 대기 |
| `ontop.websocket.heartbeat.timeout` | `10s` | Ping의 전송 큐 대기 제한 / 전송 시작 후 Pong 응답 제한 |

0·음수 설정은 앱 시작 시 거절한다. 두 값은 연결 관리 구현값이며 기획서에 새 제품 유예를 추가한 것이 아니다. 실제 테스트는 200ms/1s로 줄여 같은 전송 경로를 확인하고, 기본 10초 경계는 단조 시간을 직접 움직여 검사한다.

보통 마지막 정상 응답 이후 약 20초 뒤 감지하지만 검사 주기·송신 큐·서버 부하에 따라 늦어질 수 있다. 물리적 단절 시점부터 정확히 20초를 보장하지 않는다. 만료 시 기존 세션의 서버 권한을 먼저 없애므로 소켓 close가 지연돼도 새 연결을 막지 않는다. 유예 시각은 계속 서버의 정리 시점이며, 재시작/다중 서버 복구·운영 부하 검증은 아직 없다.

## 테스트에서 확인하는 것

- `WebSocketHeartbeatTests`: 기본 주기·정확한 만료 경계·현재 응답만 인정·송신 지연/정지·비동기 종료·잘못된 설정.
- `HeartbeatWebSocketTests`: 실제 TCP/WebSocket 프레임의 정상 Pong 유지, 무응답/잘못된 Pong 감지, 대기 좌석 정리, 감지 후 29초 복귀/30초 만료.

프레임을 직접 다루는 클라이언트와 인증·경기 대역은 테스트 소스에만 있다. 운영용 게임이나 새 인증 방식은 추가하지 않았다.
