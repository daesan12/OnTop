# AI 로컬 검수 실행 안내

팀 협의 전 개인 검수를 위한 실험 브랜치다. 운영 앱에 기능을 자동 등록하지 않으며 공용 DB·Jira·Notion·Postman 웹·MR·배포와 연결하지 않는다. 기존 인증과 실제 재화를 사용하지 않는다.

이 문서의 파일 저장소와 한도는 로컬 실험실/ai-park 대역에 해당한다. 정식 DEV·운영 서비스의 env 및 DB 저장소는 [AI 운영 연결 인계](ai-runtime-handoff.md)를 따른다.

## 현재 공원에서 NPC·오목 테스트하기

아재왕 대회는 [로컬 대회 안내](ai-joke-contest.md)를 따른다. 랭킹판 옆 심사위원 접근→E→문제/정답 제출, Jev 검수·채점→LLM 리액션+서버 확정 점수, 서울 날짜 하루3회·상위10/정답별도공개를 제공한다. 기존 제품 DB/엽전은 변경하지 않는다.

`scripts/start-ai-park.cmd`의 실제 공원 화면 `http://127.0.0.1:5211/ai-park.html`에 연결했다. 별도 실험실의 도형 공원과 구분한다. 채널마다 한순경과 오목 주민 세 명(강잼민·윤한수·박영감)이 돌아다닌다. 강잼민은 작은 키·빨간 목도리, 윤한수은 안경·검은 코트, 박영감은 수염·모자·지팡이로 구분한다. 붕어빵 손님의 기존 GLB와 idle/walk 관절 애니메이션을 재사용하며, 한순경은 복제한 모델에서 일반인 외투·청바지·귀마개를 제거하고 관절을 따라 움직이는 남색 제복·장비 벨트·구두로 교체했다. 얼굴·손과 애니메이션은 유지하고, 머리에 맞춘 경찰 모자·가슴 표식·오른손 곤봉을 사용한다. 원본 GLB와 붕어빵 손님은 변경하지 않는다. 각 주민 한 몸이 산책·관전·대결을 선택하며 이동은 실제 서버 맵 경로를 사용한다. 일반 NPC 자유대화는 제공하지 않으며, 대화형 입력은 김부장 아재왕에만 제공한다. 고정 대사를 우선하고 LLM은 일부 문장만 작성하며 착수·금수·승패를 결정하지 않는다.

1. `오목 테이블 앞으로`로 이동해 테이블에 앉고 오목을 선택한다. 실제 게임 태블릿에서는 참가비를 `0`으로 입력하고 설정한다.
2. 혼자 오목을 선택한 상태로30초 기다리면 보통 난이도의 윤한수을 부른다. 2번 빈자리의 `+`를 누르면 `강잼민(쉬움) / 윤한수(보통) / 박영감(어려움)`을 선택해 바로 부를 수 있다. 기존 주민과 두기 창에서도 같은 선택을 지원한다. 초대는 자리를 예약하는 단계다. 선택한 주민이 산책/관전을 멈추고 뛰어와 테이블 옆에 도착한 뒤 빈자리에 앉으면 대결이 시작한다. 이동 중에는 착수와 차례 제한을 시작하지 않는다. 참가비는 서버에서0엽전으로 확정한다.
3. 사람은 흑, NPC는 백이다. 대결 서버는 로컬 NPC전으로 유지하고, 화면은 사람끼리 쓰는 공원 3D 오목판·탑뷰 카메라·차례/시간 HUD를 그대로 사용한다. 별도 격자판은 사용하지 않는다. 실제 `OmokMatch/OmokBoard`의 15×15 렌주·흑 금수·차례별 30초·승패 규칙을 사용하며 기존 재화 예약/지갑/정산 저장소는 호출하지 않는다. 빈 NPC 좌석은 실제 TableRoom에 예약해 사람의 중복 참가와 기존 경기 시작을 막는다.
4. 기존 오목 화면의 무르기/무승부 제안은 NPC 서버가 거절한다. 기권과 주민 보내기는 같은 화면의 게임 메뉴에서 선택한다. 판이 가득 차 자연 무승부가 되는 규칙은 유지한다. `기권`은 판을 끝내고, `대결 마치고 주민 보내기`는 자리를 돌려준다. 도착 전에는 `주민 호출 취소`가 가능하다. 결과는 최대30초 보여준 뒤 주민이 일어나며, 직접 보내면 해당 좌석 설정에서는 자동 초대를 쉬고 수동 호출이나 재착석으로 다시 시작한다. 연결 종료·현재 좌석 불일치에도 예약을 해제한다.90초 동안 도착하지 못하면 호출을 취소하고 개인 대화창에 안내한다.
5. 채널당 각 종류의 주민은 한 명이며 같은 주민을 두 테이블에 동시에 부를 수 없다. 서로 다른 난이도의 세 주민은 각각 대결할 수 있다. 윤한수이 대결 중이면 다른 테이블의30초 자동 초대는 기다리고 수동으로 다른 난이도를 선택할 수 있다. 다른 채널의 갱신은 계속한다. 관전 주민은 테이블당 최대2명이며 대결 중인 몸은 관전에 배정하지 않는다. 남는 주민은 산책하고, 기존 관전 배정은 경기가 끝나거나 대결에 불릴 때까지 유지한다.
6. 쉬움은 로컬 전술 선택, 보통은 Rapfi 추천과 일부 전술 선택 혼합, 어려움은 Rapfi 추천을 우선한다. 모든 난이도가 즉시 승리/상대 즉시 승리를 우선 확인한다. 보장된 승률이나 검증된 Elo 난이도가 아니다. 엔진이 없거나 실패해도 합법적인 로컬 전술 수로 대체한다.
7. 사람끼리 오목도 이 로컬 실행에서는0엽전으로 시작할 수 있다(A/B/C 테스트 계정). 기존 태블릿의 준비/방장 시작 흐름을 사용한다. 실제 OmokEngine 국면과 착수 이력을 서버에서 읽고, 배정된 주민 최대2명이 서로 다른 테이블 옆 지점으로 뛰어와 해설한다. 사람 경기의 한 엔진 분석을 관전자들이 공유하며 별도 제한된 큐에서 NPC 응수 작업을 우선한다. NPC 연습판을 구경하는 주민은 새 현재 국면 평가가 없으면 응원/판세 미확인 대사를 한다. 이전 NPC 착수 전 평가를 현재 우세로 재사용하지 않는다.
8. 판세 지표는 흑 기준 엔진 평가이며 사람의 실제 승률이 아니다. NPC전 지표는 직전 NPC 착수 전 국면이다. 지연 해설은 버전이 바뀌면 반영하지 않는다. 사람 경기 해설에는 추천 좌표를 공개하지 않는다. 고정 대사는 인사·응수·판세·종료마다 주민별 여러 말투를 순환하며 판세 미확인은 그대로 말한다. 대사는 각 주민 이름/actorId로 채팅과 머리 위에 표시한다. 사람 경기 채팅은 승인된 참가/관전 범위와 같은 국면만 반영하고, NPC 연습판의 발화도 참가자와 승인된 현재 테이블 관전자만 받는 전용 경기 채팅으로 보낸다.

### 보드게임 중 채팅 안내

경기 채팅도 기존 욕설 규칙/Jev 검사를 적용하지만, 감지 시 발언한 사용자에게만 8초 동안 ‘함께 즐기는 게임이에요. 서로 존중하는 표현을 사용해주세요.’ 안내를 표시한다. 확인 버튼으로 닫을 수 있다. 경찰은 출동하지 않고 경기 채팅/공개 말풍선에도 안내 대사를 넣지 않는다. 경기와 기존 필터는 유지하며, MM에는 닉네임·원문과 경기 개인 안내 사실을 보낸다. 사건 상태는 NOTIFIED다. NPC 오목의 참가자·승인 관전자도 서버의 공개 프로필에서 발언 당시 닉네임을 가져와 MM에 표시한다. 프로필이 없을 때만 사용자 ID로 대체하며, 같은 발언 재전송이나 이후 닉네임 변경은 이미 저장한 발언자 표시를 바꾸지 않는다. 오목 확대 화면에서도 안내가 보이고 다른 경기로 이동하면 이전 경기 안내를 숨긴다. 공원 채팅의 경찰 출동은 유지한다.

### NPC 모델 미리보기

로컬 실행 중 `http://127.0.0.1:5211/npc-models.html`에서 네 주민을 회전하며 걷기·착석·점프 자세를 확인할 수 있다. DEV/loopback 전용이며 API/채팅/알림을 보내지 않는다. 실제 공원에도 같은 ParkNpcModel을 쓴다. 채널 변경 시 모델별 관절/재질과 소품을 정리하고 기존 공유 에셋은 참조 수로 관리한다. 서버 재시작 없이 새로고침하면 모델 변경을 반영한다.

### NPC 배회와 화면 이동

경찰 이름은 `한순경`이다. 한순경·강잼민·윤한수·박영감은 평상시 주민별 고정 대사5개를 순환한다. 최초8~16초 뒤부터25~40초 간격으로6초간 머리 위에만 표시하며, 출동·복귀·대결·관전 중에는 혼잣말을 멈춘다. actor snapshot의 ambient 필드만 쓰므로 사용자 채팅 기록·Jev 검사·MM 알림·LLM 호출을 만들지 않는다. 경찰 주의와 오목 해설은 기존 사건/경기 발화 흐름을 유지한다. NPC 머리 위에는 유저와 같은 크기·형태의 닉네임표를 표시하며, NPC는 민트색 글자와 짙은 초록 배경으로 구분한다. 별도 파란/갈색 상태 표시판은 사용하지 않는다. 경찰의 현장 안내와 박영감의 공개 해설은 채팅 기록과 이름 위 말풍선에 함께 표시한다. 말풍선은 유저와 같은 스타일로 실제 NPC를 따라가며 최대10초 표시하고, 경찰은 현장 안내 동작이 끝나면 말풍선만 숨긴다. 김부장 아재왕 결과는 전용 대화창에 표시한다. 화면 밖·먼 거리·오목 탑다운 화면에는 머리 위 표시를 숨긴다.

욕설 감지 시 개인 안내는 “욕설 표현이 감지됐어요. 서로 존중하는 말을 사용해주세요.”로 표시한다. 경찰의 내부 대기열이나 방문 순번은 안내하지 않는다. 도착하면 개인 팝업을 지우고 현장 대사를 보여주며, 접근이 어려운 위치에서는 짧은 안내 후 기존 순간이동 정책으로 처리한다.

경찰은 공원 전체에서, 오목 주민 세 명은 중앙광장과 오목 테이블 주변(x -32~32, z -24~64)에서 무작위 목적지를 고른다. 고정 지점을 반복하는 순찰은 없앴다. 목적지는 이동 중 유지하며 장애물을 피하는 지상 경로로 걷고,8~18초 보행 뒤4~11초 쉬거나 도착 후 쉰다. 경로를 찾지 못하면 잠시 기다린 뒤 다시 선택한다. 광장 범위 제한은 평상시 배회에 적용하며 경기 관전·대결에는 해당 테이블로 간다.

NpcUtility는 가능한 행동의 점수(순찰10·휴식35·관전70·대결90·출동100) 중 높은 행동을 선택한다. 무작위 목적지 선정과 지상 경로 탐색은 별도 NpcWander/ParkNavigation이 맡는다. 학습 모델이나 LLM으로 이동을 결정하지 않는다. 오목 NPC의 상태에는 선택한 action과 utilities를 표시한다.

서버 이동 갱신은 약 100ms 간격이며 실제 경과 시간으로 진행한다. 오목 NPC 위치도 WORLD_AI_COMPANIONS 소켓으로 보내고 HTTP는 대결·대화 상태 조회에 사용한다. 버전이 오래된 HTTP 위치는 최신 소켓 위치를 덮지 않는다. 화면은 150ms 버퍼 사이를 보간하고, 가속·감속·회전 완화와 실제 이동 속도에 맞춘 보행 모션을 사용한다. 착석·경찰 순간이동은 보간 경로를 초기화한다. 네트워크가 멎으면 최대100ms만 예측하고 멈춘다.

최종 실제 로컬 소켓 검수는 배회·휴식·광장 범위·소켓 수신·세 난이도 주민·도착 전 착수 차단·도착 후 대결·30초 자동 호출·연습판 관전 대사 수신·사람 경기 두 관전자까지52항목을 확인했다. 아래 과거4Hz/두NPC 부하 측정은 현재10Hz/네NPC 방식의 성능 근거로 재사용하지 않는다. 운영 동시 접속 부하는 별도 확인 대상이다.

### LLM 키만 추가하기

키 없이도 위 기능은 주민별 여러 고정 대사로 실행된다. 키를 넣으면 박영감의 일반 질문과 주민 대결의 여섯 수마다 일부 해설에 기존 Spring AI 어댑터를 연결한다. 사람 경기의 생성 해설은 여섯 수마다 관전 배정된 주민 한 명의 말투를 선택하고 다른 주민은 고정 소감을 말하므로 같은 국면에 각자 LLM을 호출하지 않는다. 인사·규칙·엽전·소리함·게임 추천은 고정 대사다. 입력에는 현재 채널의 실제 대기 수와 확인된 국면만 넣고 다른 채널의 상황을 섞지 않는다.

```powershell
cd "C:\Users\SSAFY\Desktop\자율\S15P31B105"
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'LLM API 키' -AsSecureString)).Password
.\scripts\start-ai-park.cmd -Restart -AutoLive -NoBuild
```

`-AutoLive`는 해당 창의 JEV_API_KEY와 AI_LAB_MM_WEBHOOK 존재 여부로 Jev/MM을 켠다. 없으면 해당 기능만 대역/로컬 알림으로 실행하며 LLM 키만 넣어도 NPC·오목을 확인할 수 있다. 기존 키/웹훅은 각자의 환경변수로 상속하며 URL·키를 문서나 Git에 저장하지 않는다. OPENAI_API_KEY는 ChatGPT 로그인/구독과 다른 API 키다.

CMD 실행기는 PATH의 pwsh, 이 PC의 기존 Codex PowerShell, 기본 Windows PowerShell 순서로 선택하고 프로필/실행 정책 문제를 이 프로세스에서만 우회한다. 시스템 실행 정책이나 설치 프로그램을 바꾸지 않는다. 기본 Windows PowerShell에서도 한글 경로의 UTF-8 클래스패스를 읽어 실제 기동을 검증했다. `-Restart`는 스크립트가 기록하고 저장소/명령줄이 일치하는 프로세스만 종료한다. 외부 호출 없이 확인하려면 `.\scripts\start-ai-park.cmd -Restart -Offline -NoBuild`, 종료만 하려면 `.\scripts\start-ai-park.cmd -Stop`이다. Offline과 실제 연결 옵션은 함께 쓰지 않는다.

기본 모델은 기존 어댑터와 호환되는 `gpt-4.1-mini`이며 `AI_LAB_LLM_MODEL`로 변경한다. [공식 모델 안내](https://developers.openai.com/api/docs/models/gpt-4.1-mini)를 확인했다. 호출 실패·빈 응답·8초 타임아웃·예산 소진에는 고정 대사로 돌아간다. 기본은 프로세스당 UTC 하루100회이며 `AI_LAB_LLM_DAILY_CALLS`로 조절한다. 재시작하면 이 메모리 카운터는 초기화되므로 계정 전체의 결제 상한은 아니다. 개인 대화는10초 간격이고 마지막 답변만 유지한다. 대화 이력 전체 기억 기능은 없다.

`GET /local/ai/companions/status`에는 FIXED/SPRING_AI, RAPFI/LOCAL_TACTICAL, LLM 호출·실패 수, 답변 공급자, 경기·해설 버전이 표시된다. 실제 키가 없는 이번 검수는 LLM 유료 응답 품질 검증을 포함하지 않는다. 지연/실패 대역으로 다음 착수·기권·시간 종료 뒤 오래된 답변이 덮어쓰거나 대사 대기를 계속 막지 않는 경계는 별도로 검증한다. API 키가 있는 일반 공원에서는 별도 Live LLM 옵션 없이 활성화되며, 비교 검증 서버는 명시적 별도 설정이 없는 한 LLM을 끈다.

재현 검증: `node scripts/test-ai-companions.mjs <새 결과 폴더>`는 전용 loopback19192에서 실제 소켓·Rapfi·30초 대기/차례 제한·자리 반환·사람 경기 국면 해설을 확인하고 종료한다. Jev/MM/LLM 외부 호출은 꺼져 있다. 공원 UI와 NPC 연습 상태는 메모리이며 서버 재시작/연결 종료 뒤 경기를 복구하지 않는다. 운영 배포용 계정·영속 저장·실재화 연동은 포함하지 않는다.

## 현행 정책: 표시 필터와 거친 언행 안내

AI 전체 메시지 가림이나 자동 mute/kick은 하지 않는다. 기존 팀원 filterChat의 단어만 화면에서 **로 치환한다. 목록과 정규화/경계 규칙은 바꾸지 않고 frontend/src/features/chat/filterRules.json 한 사전을 공유한다. backend processResources가 이 JSON만 ai/filterRules.json으로 복사하고 ChatWarningRules는 같은 NFKC/초성/띄어쓰기/기호 규칙으로 확인한다. 따라서 화면에서 마스킹되는 표현은 경찰·MM 안내 대상이다. 인용 안의 단어도 기존 필터가 마스킹하면 같은 규칙을 적용한다. 시발점/시발역 같은 기존 예외는 유지한다.

새 메시지 최대10개 또는 첫 대기10초마다 검사한다. 규칙 감지는 먼저 저장·출동/알림 요청하고 Jev가 느리거나 실패해도 진행한다. 마스킹되지 않은 새 발화는 최근30초·같은 대화 범위의 닉네임/이전 문맥 최대5개와 함께 Jev가 각각 판단한다. 한 명의 '아 ㅈ같네' 같은 거친 불평·적대적 비난도 대상이며 서로 싸우는 두 사람을 요구하지 않는다. 단순 아쉬움·정상 비판/의견·인용/신고는 구별하도록 질문한다. Jev negative-advisory-v5는 욕설 없는 인격 비하·비꼼(그렇게 살지마, 가정교육 못 받으심?)도 대상으로 명시한다. 걱정에서 나온 조언·중립적인 가정교육 언급·인용 신고는 제외하며, 존댓말/의문문/따옴표 자체는 비하를 면제하지 않는다. 또한 발음대로 쓰기·모음 늘이기·띄어쓰기 변형도 문맥에서 해석하도록 질문하며 정상 유사어/인용 제외는 유지한다. 기본기준0.5 이상(경계값 포함)의 잠정 모델 판단이며 정확도 보장이 아니다. NEGATIVE_SPEECH는 문장을 가리지 않고 해당 새 발화 작성자에게만 부드러운 안내를 요청한다. 정상인 문맥 작성자를 함께 경고하지 않는다.

새 위반이 있는 검사 묶음마다 MM 알림을 만든다. 카드의 감지된 발언에는 해당 사건 메시지 ID에 속하는 닉네임: 원문만 표시한다. 여러 명이면 한 줄씩 나누며 정상 문맥은 넣지 않는다. 코드 블록으로 표시해 욕설/이모지 표기를 유지하고, 멘션과 줄바꿈·제어문자만 알림용으로 정리한다. 저장 원문과 화면의 기존 ** 필터는 바꾸지 않는다. 동일 작성자/유형60초 억제와 사건 합침은 제거했다. 같은 입력ID의 재시도만 중복 경고하지 않으며, Jev 재시도 사이 새 욕설이 들어와도 이전에 처리한 규칙ID는 다시 포함하지 않는다. 새 위반 없는 빈 주기에는 알림을 보내지 않는다. 소리함의 기존 접수 멱등/긴급 알림/일반 요약은 유지한다.

MM 거친 언행 카드의 색상은 저장한 모델 응답값으로 구분한다. 0.50 이상 0.70 미만은 노랑 ‘안내’, 0.70 이상 0.85 미만은 주황 ‘주의’, 0.85 이상은 빨강 ‘우선 확인’이다. 검토 단계와 ‘모델 판단 점수 · 묶음 최댓값’을 함께 표시하며, 실제 위험 확률이나 개별 발언의 확률로 해석하지 않는다. 모델 점수를 소수 둘째 자리로 반올림해 표시 구간이 달라 보이게 하지 않고 원래 값을 표시한다. 점수 없는 이전 알림은 회색 ‘점수 없음’이다. 욕설 규칙 카드는 주황과 ‘모델 점수 없음’을 사용하고, 긴급 소리함은 빨강·일반 소리함은 파랑을 유지한다. 원문 안의 숫자는 색상에 영향을 주지 않는다. optional Notice.modelScore를 JSON에 보존하여 재시작·재시도·전송 완료 때도 값을 유지하며 기존 JSON에 필드가 없으면 null로 읽는다. DB 마이그레이션과 기존 게시물 수정·SENT 재전송은 없다.

소리함은 Jev가 BUG/OTHER·분야·긴급도(P0 전체 핵심 장애/P1 핵심 이용 차단/P2 일반 오류/P3 의견)를 분류한다. 명백한 로그인·이동·턴 차단 문구는 기존 보조 규칙으로 최소 P1을 보장한다. P0/P1은 즉시 빨강 MM 알림을 요청하고, P2/P3은 서울 09/12/15/18시의 새 요약 구간 또는 관리자 수동 요약에서 모은다. 공원 `LocalWorldAiConfiguration`은 `AiParkApplication`의 AiText 빈을 주입해 일반 제보 요약에 사용하며, 빈이 없거나 키가 없으면 고정 안내로 대체한다. LLM 요약은 제보의 핵심 불편·요청을 주제별 한국어 3~5줄로 정리하도록 요청하고 원문에 없는 원인·해결 완료·긴급도를 생성하지 않도록 지시한다. LLM 미설정·실패·일일 생성 한도에서는 기존 고정 안내를 유지한다. `status.feedbackSummaryProvider`와 worker의 `feedback_summary.requests/generated/fallback`, 시간 계측으로 선택된 공급자와 실제 생성/대체 결과를 구분한다. 공급자 설정만으로 실제 생성 성공을 표시하지 않는다. 요약의 @는 전각으로 바꿔 멘션을 막고, 요약에 배정된 제보는 다음 요약에서 제외한다.

한순경은 한 몸으로 요청을 차례로 처리한다. 순찰은1.6m/s, 출동은8m/s이다. 접근 가능한 같은 지상3.5m 이내에서6초 안내한다. 높은 곳/길을 찾지 못하는 곳은5초 지속 확인 후 출동 순간이동·3초 안내를 하고, 현지 순찰 또는 보행·점프·낙하로 지상 복귀한다. 복귀 순간이동은 하지 않는다. 주민은 산책 속도를 유지하지만 대결 호출·관전 이동은4.5m/s까지 가속해 뛴다. 현재4NPC 방식의 운영 부하는 별도 미검증이다.

사람 경기는 기존 전용 경기 채팅을 쓰며, 초기 상태 구독 전에도 확정 참가자를 격리한다. 승인된 관전자만 같은 경기에 말할 수 있고 바깥 공원 채팅은 참가자·관전자에게 전달하지 않는다. NPC 연습판도 좌석 임대에 gameId를 연결해 참가자와 현재20m 테이블 관전자만 전용 채팅/주민 대사를 받는다. 바깥 사람의 추측 gameId 송신은 거절한다. 연습판을 마치면 공원 채팅으로 돌아오며 사람 경기도 정산 후 계속 착석한 다음 판 대기자는 다시 공원 채팅을 쓴다. private NPC 대사는 바깥 기록/말풍선에 넣지 않는다.

관전 주민 최대2명은 사람 경기의 한 엔진 분석 결과를 공유한다. 주민마다 엔진을 따로 호출하지 않으며 고정 소감의 말투만 다르게 만든다. 일부6수 생성 해설도 배정된 한 주민만 LLM을 호출한다. NPC 상대의 착수용 분석과 다른 테이블의 분석은 제한된 공통 작업 큐를 사용한다.

진단 모드는 CHAT_FILTER_NEGATIVE이며 A 전용 GET /local/ai/conflicts(호환 경로명)의 policyVersion=negative-advisory-v5에서 새 발화별 판단을 확인한다. 소리함은 기존 Jev 긴급/일반 분류를 유지하고 LLM 키는 필요 없다. 키 없는 실행은 OFFLINE_RULE_FIXTURE/LOCAL이며 실제 Jev의 한국어 판단 품질이나 실제 웹훅 전달을 검증한 결과로 표현하지 않는다.

실제 검증은 backend에서 ./gradlew.bat aiLabClasspath를 빌드한 뒤 키와 웹훅이 있는 PowerShell에서 다음 명령으로 실행한다.

```powershell
$aiInterventionDir = '.\backend\.gradle\ai-park-benchmark\live-interventions-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
node .\scripts\test-ai-interventions.mjs $aiInterventionDir --live-jev --live-mm
```

키는 JEV_API_KEY, 웹훅은 AI_LAB_MM_WEBHOOK 환경변수로만 상속한다. 기존 앱 재시작 없이 loopback19192·새 데이터에서 실행하며 실제 MM 테스트 알림은 욕설/거친 언행/소리함 카드로 전송된다. 별도 API 검증기는 정상/마스킹 욕설/60초 안 반복 욕설/단독 거친 표현/미마스킹 인용를 31초 간격으로 격리하고, 강제 배치 점검과 같은 사건의 NPC 도착·알림 SENT·소리함 접수를 확인한다. 이 검사는 일반 배치 지연 성능 측정이 아니다. 잘못된 입력이나 이전 사건의 늦은 도착을 성공으로 집계하지 않는다.

이하에는 기존 실행 안내와 과거 가림·모델 임계값 실험 이력이 함께 남아 있다. 현재 동작은 위 정책을 우선한다.

## 시작과 종료

기존 Java 21, Node 24, frontend 의존성이 설치된 Windows PowerShell에서 저장소 루트를 기준으로 실행한다.

```powershell
./scripts/start-ai-lab.ps1
```

- 화면: [AI 로컬 공원](http://127.0.0.1:5210/ai-lab.html)
- 백엔드: `127.0.0.1:19190`, 로컬 Raw WebSocket: `/dev/ai/ws`
- 데이터·프로세스 ID·실행 로그: `backend/.gradle/ai-lab/` (Git 제외)
- 재실행은 저장한 채팅·소리함·알림 작업을 복구한다. 오목판·NPC 순간 위치는 새로 시작한다.
- 이미 포트를 쓰는 프로세스는 종료하지 않고 시작을 거절한다.
- 창을 열지 않는 백그라운드 실행이다. 브라우저에서 위 링크를 직접 연다.

```powershell
./scripts/start-ai-lab.ps1 -Stop
```

종료는 기록된 PID와 저장소·명령줄을 대조해 이 스크립트가 실행한 프로세스만 대상으로 한다. 데이터는 삭제하지 않는다. 새 데이터로 검수하려면 별도의 빈 `AI_LAB_DATA_DIR` 경로를 지정한다. 다른 프로세스의 데이터 디렉터리를 공유하지 않는다.

이 환경의 전역 pnpm은 프로젝트 지정 버전을 자동 다운로드하다 네트워크 제한으로 대기할 수 있다. 실행 스크립트는 설치된 Vite를 Node로 직접 실행하며 패키지 관리자 설정을 바꾸지 않는다.

## API 키 없이 확인할 기능

실험실 기본 모드는 `CHAT_RULES+CONFLICT_FIXTURE+FIXED`, 알림은 `LOCAL_CAPTURE`다. 갈등 대역은 제한된 규칙이며 실제 한국어 Jev 정확도나 LLM 품질을 의미하지 않는다. 화면은 독립 3D 검수 공원과 전환 가능한 2D 지도다. 실제 공원 연결은 아래 별도 공원 실행 안내를 따른다.

1. **두 사용자 채팅:** 두 번째 사용자 창을 열고 공원1에서 대화한다. `씨발` 등 명백한 욕설은 원문을 유지하면서 규칙 안내 사건을 만든다. “지금 검사”는 갈등 배치의 대기 시간을 건너뛴다. 공원2·오목 경기 채팅은 분리된다.
2. **갈등:** 사용자 A의 “너 나가”와 B의 “왜 시비 걸어”를 최근 묶음에 입력한다. 본문은 유지하고 채팅 검토·알림함에서 CONFLICT_SUSPECTED를 확인한다. 혼자 한 발언은 갈등 질문을 호출하지 않는다.
3. **경찰:** 욕설 규칙이나 갈등 의심 사건에 경찰이 고정 안내·중재 대사를 말한다. 출동과 별개로 MM 안내 요청을 처리한다.
4. **소리함:** “전체 접속 불가입니다”는 P0 긴급, “캐릭터가 안 움직여요”는 P1 후보, “의상을 더 추가해주세요”는 P3 대역이다. 긴급은 분류 후 알림함에, 일반은 요약 실행 뒤 알림함에 표시된다.
5. **정기 보고:** 한국시간 09·12·15·18시. 빈 보고는 생략한다. 야간 제보는 다음 시각에 포함하고 재실행 시 지난 슬롯을 따라잡는다. 수동 버튼으로 기다리지 않고 같은 흐름을 확인할 수 있다.
6. **장애 복구:** 분류 실패·알림 실패를 켜고 접수한다. 미처리 상태가 보존되는지 확인하고 실패를 끈 뒤 재시도한다. 알림은 최대 5회 자동 시도 후 FAILED가 되며 수동 재시도가 가능하다. 분류 실패 중에도 기존 알림 전송은 독립적으로 진행한다.
7. **과거 가림 기록:** 예전 실험의 숨김·복원 진단은 남아 있지만 새 채팅은 자동 가리지 않는다. 이 화면의 관리자는 모두 로컬 검수자이며 제품 관리자 권한을 대체하지 않는다.
8. **NPC 대화:** NPC 선택 후 질문한다. 고정 안내·인사·오목 규칙은 외부 호출을 생략한다. 대화 취소 후 지연된 응답은 행동 세대가 다르면 폐기한다.
9. **오목:** 새 경기에서 흑백을 번갈아 둔다. 실제 `OmokBoard`의 15×15 렌주·흑 금수를 적용한다. 두 수 무르기와 흑 우세 예제를 제공한다. 실제 종료 총평 발화 후 약12초 뒤 순찰로 복귀한다. 참여할 구경 NPC가 없으면 종료 후60초 상한으로 복귀한다.

## 실제 Rapfi 분석

현재 PC에는 공식 250615 배포를 저장소 밖의 `자율/local-tools/ai-lab/rapfi-250615/`에 설치했다. Windows AVX2 실행 파일이 있으면 실행 스크립트가 자동으로 연결한다. 다른 PC는 호환되는 바이너리·가중치·config를 함께 설치하고 절대경로를 지정한다.

```powershell
$env:AI_LAB_RAPFI_PATH = 'C:\absolute\rapfi\pbrain-rapfi-windows-avx2.exe'
./scripts/start-ai-lab.ps1
```

- 1스레드, 해시16MiB, 목표 탐색300ms·최대깊이16, 프로세스 응답 마감5초를 적용한다. 해시 크기는 전체 프로세스 메모리 상한이 아니다.

- `INFO WINRATE`는 엔진 평가 환산 지표이며 사람의 실제 승률이 아니다. 얕은 분석은 판단을 보류한다.

- “로컬 연습용 추천 수”는 기본 꺼짐이다. 제품 경기에서 정답을 공개하는 기능을 구현한 것은 아니다.
- 경기 버전이 바뀐 과거 분석은 폐기하고, 대기 중 요청은 최신 국면으로 합친다. NPC 도착·발화 쿨다운을 기다렸다가 최신 판세를 국면당 한 번 전달한다.

공식 다운로드: [Rapfi 250615](https://github.com/dotb1ue/rapfi/releases/tag/250615). 내려받은 `Rapfi-engine.7z` SHA256은 `1A3E24024062A153AC079060EE9589A37C6BDD1ECC54FED3908793C519594E05`다. 바이너리·가중치는 Git에 넣지 않는다. 엔진은 GPLv3이며 향후 배포 시 라이선스·해당 소스 제공·가중치 조건을 확인한다. 소스는 [Rapfi](https://github.com/dotb1ue/rapfi)에서 확인한다.

## 나중에 실제 API 연결

키를 채팅이나 Git에 넣지 않고 현재 PowerShell 환경에 설정한다. 아래 변수명만 안내하며 실제 비밀값 예시는 포함하지 않는다.

| 변수 | 역할 |
| --- | --- |
| `JEV_API_KEY` | 지원받는 Jev 키 |
| `JEV_MODEL` | 기본 `jev-1.14.0` |
| `OPENAI_API_KEY` | 생성형 API 키 |
| `AI_LAB_LLM_MODEL` | 선정한 Chat Completions 호환 모델명, 필수 |
| `AI_LAB_LLM_DAILY_CALLS` | 생성 최대 시도 횟수, 기본300/UTC 하루 |
| `AI_LAB_MM_WEBHOOK` | 실제 MM Incoming Webhook |

```powershell
./scripts/start-ai-lab.ps1 -Live
# 실제 채널 전송이 필요한 경우에만 별도 지정
./scripts/start-ai-lab.ps1 -Live -LiveMattermost
```

기본 실행은 상속된 키가 있어도 외부 호출을 끈다. `-Live`는 Jev와 LLM을 함께 켜며 MM은 여전히 로컬 캡처다. `-LiveMattermost`를 명시해야 실제 알림이 나간다. 실제 Jev 합성 채팅 검수는 아래 결과와 같으며 LLM·MM 실채널은 미검수다.

### Jev만 연결하기

PowerShell에서 저장소 루트로 이동한 뒤 아래를 실행한다. 키는 입력창에 붙여 넣으며 화면·명령 기록에 키 자체를 쓰지 않는다. `.env`·소스·채팅에 넣을 필요가 없다. 환경변수는 해당 터미널과 실행한 서버에서 사용하며 서버를 종료해야 서버의 키 사용도 끝난다.

```powershell
$env:JEV_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host 'Jev API 키' -AsSecureString)).Password
./scripts/start-ai-lab.ps1 -Stop
./scripts/start-ai-lab.ps1 -LiveJev
```

`-LiveJev`는 채팅 검사·소리함 분류·NPC 질문 의도에 실제 Jev 어댑터를 선택하고, LLM 생성은 고정 문구·MM은 로컬 캡처로 유지한다. OpenAI 키나 모델명은 필요 없다. 화면 상단은 `LIVE_JEV + FIXED`가 된다. 이는 공급자 선택 표시이고 인증·응답 성공의 보장은 아니다. 키를 넣은 후 새 채팅을 보내 실제 처리와 오류 표시를 확인한다. 과거 대화 전체를 자동 일괄 재검사하지는 않으며, 새 발화의 최근10개 문맥에 포함된 완료 메시지는 재판정될 수 있다.

이 모드의 실행 설정·누락 키 거절은 대역 키로 검증했고 실제 키로 Jev 응답과 화면 가림도 확인했다. 선정한 합성 사례의 관찰이며 판정 품질 전체의 검증은 아니다. 외부 호출이 실패하면 미처리 상태를 보존하고 운영 작업대에 오류를 표시한다.

2026-11-08 실제 키로 합성 욕설2개가 가려지는 것은 확인했지만, 다른 모욕 표현은 유지되는 사례도 관찰했다. 이후 질문에 명시적인 true/false 기준을 넣고, 최종 연속 발화 버전을 실제 Chrome에서 검수했다. 확인 범위와 누락은 아래와 같으며 전체 품질 검증으로 보지 않는다.

최근 Jev 검사256건은 관리자 조회의 `moderationAssessments`에 메시지 ID별 provider·응답값·가림 기준·모델 판정·검사 시각을 보관한다. 원문과 키는 넣지 않고 메모리에만 남긴다. 메시지 아래에도 이 값을 표시한다. `UNCERTAIN`은 현재 모델의 불확실 판정이며 저장된 가림 상태와 별개다. 새로 가리지는 않지만 기존 가림을 자동 복원하지도 않는다. `검사 완료`를 정상 판정으로 해석하지 않는다. 현재 로컬 기본 기준은 발화0.85·구성0.95이며 운영 데이터로 보정된 값은 아니다. 모델의 응답값은 욕설 강도나 측정 정확도가 아니다. 과거 점수는 복원할 수 없고 재실행 시 기록이 사라진다.

### 최신10개와 연속 발화

같은 대화·상호 수신 범위에서 최근 최대10개를 시간순으로 전달한다. 각 항목은 `messageId`, `nickname`, `text`, `sentAt`이며 로컬 닉네임은 산책자 A/B다. 원래 메시지 ID는 유지한다. 같은 닉네임이 연속해서10초 이내 보낸 메시지의 공백 포함/제거 결합 후보도 함께 제공한다. 다른 닉네임이나 긴 시간 간격에서는 후보를 끊는다. 결합 후보 전체를 일괄 가리는 방식은 아니다.

Jev는 후보 발화의 모욕 여부와 각 메시지가 그 모욕을 구성하는지 별도로 답한다. 발화 값이0.85 이상이고 해당 메시지 구성 값이0.95 이상일 때만 그 ID를 가린다. 화면은 각 값과 각 기준을 따로 표시한다. 두 응답값의 최솟값도 진단에 남지만 단일 가림 기준과 비교하거나 결합 확률로 해석하지 않는다. 최대21개 질문(발화10+메시지10+갈등1)이다.

다음 조각이 도착하면 이전 검사 완료 조각도 다시 해석해 가릴 수 있다. 기존 가림은 모델이 정상으로 바꿔도 자동 복원하지 않고, 관리자가 직접 복원한 메시지는 재검사로 다시 가리지 않는다. 새로 가려진 ID에서 모욕 사건을 만들고 갈등 단독 판정도 별도 사건을 만든다. 경찰 반응은 사건 단위로 중복을 억제한다. 이미 들었던 사용자에게만 가림 결과가 보인다.

미처리 입력이10개를 넘으면 오래된 대기부터 처리해 버리지 않는다. 첫 창 뒤에는 신규 최대5개와 이전 문맥을 겹쳐 최대10개를 만든다. 과부하 시 모든 입력을 한 번에 처리하는 보장은 아니며 임의 길이의 모든 분할 패턴 검출을 보장하지 않는다. API 실패 시 대기를 유지한다. 이미 완료된 과거 대화 전체를 일괄 재검사하는 작업은 아니다.

실제 Chrome·Jev `utterance-v2` 검수에서 `너 / 미친 / 놈이야`는 세 ID 모두 가려졌다. `너`를 먼저 정상 검사한 뒤 `진짜 / 쓰레기야`를 보내자 앞의 `너`와 뒤의 `쓰레기야`가 가려졌고 부사 `진짜`는 유지됐다. 다른 닉네임의 인사·신고 인용·욕설 금지 안내·칭찬도 유지됐다. 원래10개 묶음과 ID별 결과를 화면에서 확인했다.

v2의 `님 / 도 / 라이세요?`는 합쳐 보내도 발화 응답이 약0.3~0.53으로 낮아 가리지 못했다. 이후 표기 후보·어휘 뜻·모욕 질문과 구성 판정의 의미를 보완한 v3에서는 가림에 성공했으나 반복 시 발화 값0.88로 다시 누락됐다. 이를 보고 v4에서 발화와 구성 기준을 분리했다. 대역 회귀·실제 API 관찰·일반 정확도는 구분한다.

### 변형 표기 복원 후보

`utterance-v3-spelling`은 원문·닉네임·ID를 유지하면서 NFKC 정규화, 공백·기호·숨은 문자 제거, 한글 초성의 기본소리→된소리 단일 치환 후보를 추가한다. 욕설 목록을 검색하거나 후보 문자열만으로 숨기지 않는다. 정상 단어에도 후보가 생길 수 있으며 원래 문맥에서 자연스러운 복원이고 사람을 모욕하는 경우에만 Jev가 참으로 판단하도록 질문한다. 인용 신고·금지 안내·칭찬·이름·사물 설명은 제외한다. 후보는 원문 결합 길이160자 이하에서 최대8개이며 그보다 긴 발화는 원문으로 판단한다. 모든 변형을 복원하는 기능은 아니다.

발화/구성 질문은 영어로 간단하게 작성하고 실제 한국어 대상 객체를 직접 지정한다. 코드는 변형 후보만 만들고 최종 가림은 여전히 두 Jev 응답값으로 결정한다. v3의 동일0.95 기준에서 v4의 발화0.85·구성0.95 기준으로 분리했다. 진단에 후보 수와 검수 질문 보완 해시를 추가한다.

반복 재시작 없이 질문을 비교할 수 있도록 로컬 테스트 실행기에서만 `.gradle/ai-lab/moderation-guidance.txt`의 추가 설명을 매 검사 읽는다. UTF-8 최대4KiB·1200자이며 파일이 없으면 코드의 기본 지침을 사용한다. 기본 지침에는 사람을 향한 모욕 질문의 기준과 한국어 은어 뜻, 정상 문맥의 예외가 들어 있다. 키를 넣는 파일이 아니고 Git에서 제외된다. 잘못된 파일·범위 초과는 외부 호출 전에 실패하며 대기를 보존한다. 가림 임계값이나 프로그램 코드를 바꾸는 기능은 아니다. 일반 앱 런처에는 연결하지 않는다.

v3 실제 Chrome 검수에서 기호·숨은문자·공손한 종결의 변형 모욕과 별도 모욕 질문은 가려졌고, 유사 정상 문장8개는 유지됐다. 다만 같은 분할 표현을 반복하면 발화0.88·구성0.98로 동일0.95 기준을 넘지 못했다. v4의 특정 지침에서 같은 분할 표현을 새 메시지로3회 반복해 가림을 확인했고 정상8문장은 유지됐다. 이후 추가 변형2개 누락과 지침 확장 시 기존 표현 재누락도 관찰했다. 최신 추가 지침의 전체 회귀는 아직 완료되지 않았다. 이 작은 합성 집합을 전체 정확도로 해석하지 않는다.

Spring AI 1.1.8은 테스트 클래스패스에서만 수동 생성하고 bootJar에 포함하지 않는다. 생성 모델의 `max_tokens=200` 호환 여부는 모델 선정 시 확인한다. 응답 실패·일일 횟수 초과에는 고정 문구로 돌아간다. 호출 제한은 금액 보장이 아니며 실제 토큰으로 예산을 확인해야 한다.

## 저장과 남은 제품 연결

### LLM 없이 Jev·경찰·Mattermost 연결

기존 MM의 `메뉴 → 통합 → Incoming Webhooks → 추가`에서 알림 수신 채널을 선택하고 생성한 URL을 사용한다. 메뉴가 없으면 서버 관리자가 Incoming Webhook 사용·생성 권한을 활성화해야 한다. URL은 비밀정보이며 소스·Git·채팅에 넣지 않는다. Jev 키를 설정한 동일 PowerShell에서 마스킹 입력한다.

```powershell
$env:AI_LAB_MM_WEBHOOK = [System.Net.NetworkCredential]::new('', (Read-Host 'MM Webhook URL' -AsSecureString)).Password
& $aiLabPowerShell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-ai-lab.ps1 -Stop
& $aiLabPowerShell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-ai-lab.ps1 -LiveJev -LiveMattermost -NoBuild
```

`$aiLabPowerShell`은 이 PC에서 확인한 PowerShell7 실행 파일 경로다. 다른 PC는 설치된 PowerShell7 경로를 사용한다. 위 명령은 빌드 완료 후 사용한다. `JEV_API_KEY`, `AI_LAB_MM_WEBHOOK`만 필요하며 `OPENAI_API_KEY`·LLM 모델명은 필요 없다. MM 옵션을 생략하면 실제 전송 없이 `LOCAL_CAPTURE`로 검증한다. 실제 MM을 켜면 저장된 미전송 알림도 재시도한다. 이미 `SENT`인 로컬 캡처 내역을 실제 채널로 재전송하지 않는다.

#### 사건과 경찰 요청

- `ABUSE`: 새로 가린 메시지가 있을 때만 생성하고 관련 ID를 저장한다. 경찰·MM은 사건당 한 번 요청한다.
- `CONFLICT`: 서로 다른 작성자가 있는 문맥에서 모델이 갈등으로 판정하면 생성한다. 갈등 자체로 메시지를 가리지 않는다.
- `ABUSE_AND_CONFLICT`: 같은 검사에서 두 조건을 만족하면 사건·경찰 요청·MM 알림을 하나씩 생성한다.
- 사건 ID·유형·범위·관련 작성자 후보·전송 당시 위치·경찰 요청 상태를 저장한다. 갈등은 모델이 개별 참가자를 반환하지 않으므로 해당 문맥 작성자들을 후보로 기록하며 가해자·피해자로 확정하지 않는다. 출동 위치는 관련 메시지의 마지막 위치를 사용한다.
- 같은 범위·관련 작성자 집합·유형은 기본60초간 병합한다. 동시 사건 뒤 모욕/갈등 단독 반복도 병합한다. 갈등에서 모욕 동반으로 악화되거나 별도 작성자/유형이면 새 사건을 허용한다. 이 억제는 새 메시지의 가림을 막지 않는다. `AI_LAB_INCIDENT_COOLDOWN_SECONDS`로1~300초 범위에서 조정한다.
- 경찰 요청은 가림과 함께 저장하고 별도 단계에서 전달한다. 실패는 최대5회 자동 재시도하고, 작업대의 `실패 알림·경찰 요청 다시 시도`로 재개할 수 있다. 재시작 시 미처리 요청을 복구한다. 기존 저장 파일의 구형 사건은 `LEGACY`이며 재출동하지 않는다.
- NPC는 사건 ID를 메모리에서 최대64개 중복 억제하고 유형별 고정 대사를 사용한다. `DISPATCHED`는 NPC 이동 요청을 수락했다는 뜻이며 도착 완료가 아니다. 현재 단일 공통 NPC 시뮬레이션에서는 새 사건이 이전 목적지를 바꿀 수 있다. 모든 사건의 방문 완료를 보장하는 큐는 아니다.
- Jev·경찰·MM 단계의 실패는 서로의 확정 조치를 되돌리지 않는다. MM에는 원문 없이 한글 사건명·사건 발생 시각·장소·작성자 후보·최초 가림 조치·출동 요청 사실을 보낸다. 전체 사건 ID와 판단 공급자는 로컬 사건에서 확인한다. 같은 사건 병합 후의 최신 내역은 관리자 검토 목록에서 확인한다. 작성자/범위의 MM 멘션·서식 문자는 무해화한다.
- MM 수신 후 응답 유실·전송 후 저장 실패에는 같은 알림이 재전송될 수 있다. Incoming Webhook의 정확히 한 번 전달을 보장하지 않으며 알림 ID로 중복을 식별한다.

공식 Webhook 생성 안내: [Mattermost Incoming Webhooks](https://docs.mattermost.com/developers/integrate/webhooks/incoming).

제품 WebSocket 계약은 변경하지 않았다. 로컬 `/dev/ai/ws`의 기존 스냅샷을 재사용하고 관리자 HTTP 조회의 `incidents`에 사건/경찰 상태 필드를 추가했다. 실제 회원 인증·제품 공원별 경찰 actor·공용 DB와의 통합은 별도다. 이전 Jev 사건2건의 POST 성공 응답에 이어 새 OnTop 운영 알림 채널에서 모욕/갈등 카드·소리함 긴급 제보·일반 요약의 실제 수신 표시를 확인했다. 어댑터의 JSON/실패 검사는 HTTP 클라이언트 대역이며 실채널 성공을 뜻하지 않는다.

`LocalAiStore`는 단일 writer 잠금·임시 파일 force·원자 교체를 사용한다. 최대 파일16MiB, 메시지5000·소리함2000·알림4000·사건2000건의 로컬 한도가 있으며 넘으면 새 입력을 거절한다. 현재 로컬 파일은 자동 보관 만료·탈퇴 연계가 없고 직접 쓴 테스트 데이터만 보관한다. 정상 문맥도 이 검수 파일에 남으므로 실제 사용자나 민감한 내용으로 사용하지 않는다.

팀 협의 뒤 연결할 항목은 실제 공원 NPC actor·충돌·접근 거리, 기존 채팅 수신 연결별 가림 이벤트, 기존 소리함 DB·관리자 읽기/쓰기 권한, 실제 경기 사건과 종료 총평, 데이터 보관·탈퇴 처리, 모델 품질·임계값·MM 수신 검수다. 현재 장면은 경유지 기반의 개인 3D 검수 공원이며 제품 공원 통합 완료로 보고하지 않는다.

신규 SQL은 작성하지 않았다. 제품 DB 연결 때 최신 Flyway 번호·목적·영향·팀원 전달 문구와 적용 순서를 확인한다. 이 브랜치의 AI 커밋만 최신 팀 기준에 옮겨 검토할 수 있으며 Jira·MR·푸시는 팀 협의 후 별도 진행한다.

브라우저 네 번째 시나리오는 실제 Rapfi 설치를 전제로 NPC 판세 발화·종료 총평·순찰 복귀까지 검증합니다.

## 3D 검수 장면

기본 화면은 도형으로 직접 구성한 영감·경찰, 나무·벤치·소리함·실제 착수가 표시되는 오목판이다. 기존 제품 캐릭터·리깅이나 외부 모델 파일을 사용하지 않는다. 서버 NPC 좌표를 보간하고 걷기·대화 동작을 표시한다. 개인 검수용 모습이며 최종 캐릭터 디자인은 아니다.

사용자 A/B도 간단한 도형 캐릭터로 표시한다. 산책로 클릭이나 `소리함으로`·`오목판 앞으로`·`동쪽 산책`·`남쪽 산책` 버튼으로 이동하고 `이동 중지`로 멈춘다. 서버가 직사각형 산책로의 짧은 방향을 골라 이동한다. 잔디·시설 통과는 거절한다. NPC도 사건/오목 목적지를 바꿀 때 산책로의 짧은 방향을 선택한다.

채팅의 발신 좌표와 수신자 A/B를 전송 시점에 저장한다. 공원 채팅은 20m 이내, 오목 채팅은 같은 경기 참가자 대역 전체가 수신한다. 사용자가 이동해도 과거 수신 내역은 유지하고, 처음 듣지 못했던 채팅은 새로 표시하지 않는다. 후처리 가림·복원도 이 수신자 기준으로 조회한다. 예전 저장 파일의 수신자 없는 메시지는 기존 공개 검수 내역으로 유지한다.

`두 번째 사용자 창`을 연 뒤 A를 동쪽/남쪽으로 보내면 거리별 전달을 확인할 수 있다. 사용자 위치는 재실행 시 초기화되고 메시지의 당시 수신자는 파일에 남는다. 공원1/2는 사용자 위치·채팅을 나누는 로컬 대역이며 NPC/오목 시뮬레이션과 운영 작업대는 공통이다. 실제 회원별 권한이나 제품 물리는 아직 연결하지 않았다.

드래그로 회전하고 휠로 확대한다. 전체 보기·선택 NPC 따라보기·오목판 보기 프리셋이 있다. NPC 모델·이름표를 누르면 대화 대상을 선택하며, 오목판·소리함을 누르면 해당 입력 영역으로 이동한다. 말풍선은 서버의 speechUntil에 맞춰 사라진다.

2D 지도 버튼은 WebGL을 지원하지 않는 환경에서도 사용할 수 있다. 3D 모듈 로딩 실패와 WebGL 장면 실패는 분리해서 격리하며 채팅·소리함·운영 검수는 유지한다. 3D 코드는 별도 청크로 불러오고 외부 모델·텍스처 다운로드나 API 키를 요구하지 않는다.

### v5 갈등 문맥 보완과 실제 연동 관찰

실제 Chrome·Jev·MM 모드에서 정상8개는 모두 유지되고 사건/알림은 늘지 않았다. 명확한 모욕1개는 가려지고 경찰이 좌표4,4에 도착해 고정 대사를 발화했다. 상호 언쟁2개는 가리지 않고 갈등 사건·경찰 갈등 대사·MM 성공 응답을 확인했다. 실제2개 알림은 `SENT`, 시도1회다. MM 클라이언트는 최소화돼 채널 수신 화면은 확인하지 못했으며, 서버 성공 응답과 사람에게 보이는 수신을 구분한다.

다만 일방 모욕에 과거/중립 작성자까지 참고해 동시 모욕·갈등으로 과잉 분류된 사례가 있었다. `utterance-v5-conflict`는 모욕용 최대10개는 유지하고 갈등 질문에만 최신 메시지 기준 최근30초의 별도 문맥을 제공한다. 서로 다른2명이 각자 적대적으로 답하고 신규 메시지가 관련될 때만 참이며, 일방 모욕·인용신고·말림·평범한 반대·경쟁·장난은 거짓으로 명시했다. 최근 문맥 작성자가2명 미만이면 높은 모델 응답이어도 서버가 갈등을 거절한다. 질문 수는 최대21개로 유지한다. 최근2명이 존재한다는 사실만으로 상호 적대를 확정하지는 않는다.

새 질문의 대역 요청/응답 회귀와 관련 빌드는 통과했다. 실제 Jev의 v5 판정은 새 서버 적용 뒤 재검수해야 하며 이전 v4 성공 화면을 새 질문의 품질 근거로 쓰지 않는다.

### 전용 MM 채널과 카드 알림

추천 채널은 비공개 `OnTop AI 운영 알림`(URL 이름 `ontop-ai-alerts`), 설명은 `채팅 검수·갈등 감지·경찰 NPC 처리 알림을 확인하는 운영 채널`이다. 개발 검수 전용은 `OnTop AI 검수`/`ontop-ai-dev`로 분리할 수 있다. 현재 개인 검수 단계에서는 검수 채널만 만들어도 된다.

1. Mattermost 채널 목록의 `+` 또는 `채널 추가 → 새 채널 만들기`를 선택한다.
2. 표시 이름·채널 주소 이름을 지정하고 비공개로 만든다. 확인할 사람만 초대한다.
3. `메뉴 → 통합 → Incoming Webhooks`에서 본인이 관리하는 기존 웹훅을 편집해 새 수신 채널을 선택한다. 편집이 제공되지 않으면 새 채널용 웹훅을 생성한다. 비공개 채널에는 웹훅 생성자가 참여해야 한다. `이 채널로 잠금`을 제공하면 목적 채널을 확인하고 선택한다.
4. 기존 웹훅의 채널만 변경하고 URL이 같다면 서버 환경변수는 그대로다. 새 웹훅 URL을 받으면 기존과 동일한 마스킹 입력 명령으로 `AI_LAB_MM_WEBHOOK`을 다시 설정한다. URL을 채팅/Git에 넣지 않는다.
5. 새 코드 또는 URL을 적용할 때 동일 PowerShell에서 `-Stop`, `-LiveJev -LiveMattermost -NoBuild`로 재시작한다. 코드는 채널명을 강제하지 않고 웹훅에 설정된 채널로 보낸다. 기존 채널의 게시물을 옮기거나 재전송하지 않는다.

신규 채팅 사건 알림은 Incoming Webhook의 최상위 `attachments` 카드로 전송한다. 모욕/동시는 빨간색, 갈등은 주황색이며 한글 제목·조치 요약·공원명·KST 시각·작성자 후보를 보여준다. 사건 번호·알림 ID는 표시하지 않고 알림 ID를 메타데이터와 서버 기록에 보존한다. 전체 사건 ID는 로컬 `notice.key=case:<ID>`와 사건 레코드에 유지한다. 소리함 긴급 제보도 한글 분야·우선순위·미확인 안내 카드로, 정기 요약은 건수·요약·소리함 안내 카드로 보낸다. 배치 ID는 표시하지 않고 내부 묶음 연결에만 사용한다. 이미 발송한 과거 게시물이나 저장 알림 본문은 수정하지 않는다. 새 코드 적용 후 새로 생성한 사건부터 요약 형식이 적용된다. 실제 MM 데스크톱에서 빨간 모욕 카드와 주황 갈등 카드 표시를 확인했다. 시각은 커스텀 이모지 치환을 피하도록 인라인 코드로 감싼다. 재시작 후 실제 MM 데스크톱에서 시각이 이모지로 치환되지 않고 표시되는 것을 확인했다.

공식 안내: [채널 만들기](https://docs.mattermost.com/end-user-guide/collaborate/create-channels), [Incoming Webhooks](https://docs.mattermost.com/integrations-guide/incoming-webhooks), [Message attachments](https://docs.mattermost.com/developers/integrate/reference/message-attachments).

### 내부 식별자를 숨긴 운영 알림

알림 ID는 전송/재시도 추적 번호, 배치 ID는 여러 제보의 요약 묶음 번호다. `notice.id`, `notice.key`, `report.digestId`, 사건 레코드는 유지하며 MM의 표시 본문·footer에서는 알림/배치/사건 ID를 제거했다. 전송 payload의 사용자 정의 `props.ontop_notice_id`에는 전체 알림 ID를 남긴다. Incoming Webhook의 최상위 attachments와 별도 메타데이터 props를 사용한다. 메타데이터는 카드에 표시되지 않으며 전송을 정확히 한 번 보장하는 기능은 아니다.

- 채팅: 한글 사건명, 가림/채팅 유지, 출동 요청, 장소·시각, 관련 작성자 후보.
- 소리함 긴급: `소리함 · 빠른 확인 필요`, 로그인·접속/캐릭터 이동/게임 진행/기타 분야, 즉시 확인/우선 확인, 실제 장애 여부 확인 안내.
- 소리함 요약: `소리함 · 제보 요약`, 새로운 제보 건수, 요약과 소리함 확인 안내. 요약 모델 입력에도 내부 제보 UUID 대신 순번만 전달한다.

기존 저장 내역·이미 게시된 메시지는 수정하지 않는다. 새 서버 적용 뒤 새로 생성한 알림부터 적용된다. 실제 MM 채널에서 모욕·소리함 긴급2건·일반 요약 카드 총4건을 확인했으며 표시용 내부 번호가 없고 시각도 정상이다.

## 실제 공원 연결 로컬 검수

별도 실험실 화면 대신 실제 `ParkPage`·Raw WebSocket·소리함 작성 창을 사용하는 진입점을 추가했다. DB·실제 계정 없이 테스트 계정 A(101)/B(202)/C(505)로 실행한다. 공원/맵/채팅/소리함 서비스는 실제 구현이며 인증·회원·소리함 repository/transaction manager만 테스트 대역이다. 소리함 원본 repository는 메모리라 재시작 시 비워지고 AI 검수·알림 내역은 `backend/.gradle/ai-park`에 보존한다. 기존 AI 실험실 데이터와 분리한다.

저장소 루트 PowerShell:

```powershell
.\scripts\start-ai-park.ps1
# 화면 http://127.0.0.1:5211/ai-park.html?role=red
# B/C는 위쪽 검수 도구의 링크로 별도 탭에서 연다.
```

기존 키와 웹훅이 들어 있는 PowerShell에서 실제 공급자를 연결하려면:

```powershell
.\scripts\start-ai-park.ps1 -Stop
.\scripts\start-ai-park.ps1 -LiveJev -LiveMattermost -NoBuild
```

실행 정책 때문에 스크립트를 직접 실행할 수 없으면 기존 `$aiLabPowerShell`로 `-NoProfile -ExecutionPolicy Bypass -File .\scripts\start-ai-park.ps1`를 실행한다. 키 이름은 `JEV_API_KEY`, 웹훅은 `AI_LAB_MM_WEBHOOK` 그대로다. LLM 키는 필요 없다. 옵션을 생략하면 규칙 기반 검수 대역과 로컬 알림 기록만 사용한다. A 화면 위쪽 검수 도구에 실제 검수/전송 모드가 표시된다. `-NoBuild`는 이 변경의 빌드가 준비된 경우에만 사용한다.

확인 순서:

1. A/B 공원에서 정상 채팅과 욕설 규칙 대상 채팅을 보낸다. 수신 화면도 원문을 유지한다. Jev에는 새 10개+이전 5개 이내와 안정적인 회원 ID·닉네임을 전달하며 동명이인은 ID로 구분한다.
2. 욕설 규칙은 안내 사건을 만들고, 갈등은 새 대상 10개 또는 첫 대기 10초 후 Jev로 점검한다. A의 `지금 검수`는 배치 점검을 앞당긴다. 두 흐름 모두 원문을 가리지 않는다. 상호 갈등 의심은 중재 요청이며 가해자를 확정하지 않는다.
3. 채널마다 같은 경찰 NPC가 평소 순찰하고 사건 시 사용자에게 달려간다. 일반 점프 중에는 지상 경로로 접근하고 착지하면 순간이동 후보를 취소한다. 접근 불가/높은 곳/남은 거리80m 초과가 지속되면 NPC만 순간이동해3초 안내한다. 안내 후에는 순간이동하지 않고 걷기·점프·낙하 경로로 지상에 내려와 현지 순찰로 이어진다. 자세한 경계와 검증 범위는 아래 순간이동 경고 절을 따른다.
4. `소리함 앞으로`를 누른 뒤 실제 `소리함에 의견 쓰기`를 연다. 실제 회원·위치·내용·15초 작성 간격·중복 요청 검사와 영수증을 사용한다. 신규 저장의 커밋 이후에만 AI 분류 대기열로 넘긴다. 재시도 영수증에는 중복 알림을 만들지 않는다.
5. 광범위 장애/핵심 이용 차단(P0/P1)은 즉시 알림, 일반 의견은 정기 요약(09/12/15/18시 KST) 또는 A의 `일반 제보 요약`으로 확인한다. 신변 위협 등을 포괄하는 별도 긴급 정책은 아직 포함하지 않는다.

구현 경계: `TableHub → WorldAiBridge → LocalWorldAi → AiOperations`이며 외부 API와 JSON 저장은 단일 작업 스레드에서 실행한다. 원본 ID·작성 시각·서버 좌표·원래 수신자를 보존한다. 현행 advisory 경로는 가림 패킷을 발행하지 않으며 경찰 대사 `WORLD_AI_POLICE`와 상시 NPC 상태 `WORLD_AI_NPCS`를 사용한다. 욕설 규칙 개인 안내는 해당 작성자에게, 갈등 중재 대사는 원래 사건 수신자에게 보낸다. NPC 상태는 채널 공개 정보다. 과거 가림 패킷의 프론트 수신 호환 코드는 남아 있다.

설정은 명시적인 `local,ai-park` 프로필에서만 켜지며 `dev/prod/production`에서는 등록되지 않는다. loopback 바인딩도 필수다. `local,db,ai-park` 구성에서는 실제 소리함 저장 서비스의 커밋 이벤트를 받도록 연결되어 있지만 이번 검수에서 실제 DB 접수/재시작 복구는 실행하지 않았다. 로컬 JSON 저장소와 메모리 입력 대기열은 공용 운영용 outbox가 아니다. 큐 초과/프로세스 강제 종료 사이의 신규 입력을 운영 수준으로 보장하려면 별도 영속 outbox 설계가 필요하다. 데이터 초기화·Flyway 추가·공용 DB 적용은 하지 않았다.

로컬 HTTP 조작(`/local/ai/*`)과 테스트 계정 발급은 test classpath 실행부에만 있다. A만 강제 검수/요약·상태 조회가 가능하다. 상태 조회는 원문 없이 모드·큐·거절 수·가림 수·알림 상태를 반환한다. 포트 충돌 시 기존 프로세스를 종료하지 않으며 `-Stop`은 기록된 명령행이 일치하는 자체 프로세스만 종료한다.

## 접근 불가 위치: 순간이동 경고

경찰은 사용자의 지상 투영 위치로 경로를 찾아 달려간다. 일반 점프의 높이 변화만으로 즉시 접근 불가 안내를 하지 않는다. 지면과 높이차0.35m 초과 또는 남은 수평거리80m 초과가 연속5초 유지되거나 지상 경로 탐색이5초 연속 실패할 때 NPC만 근처로 순간이동한다. 착지·거리 회복·경로 복구 시 해당 후보를 취소한다. 점프맵 진행 플래그 자체만으로 접근 불가로 보지 않는다. 같은 지상에서3.5m 이내이며 사이가 막히지 않으면 도착으로 보고6초 안내한다. 순간이동 경고는3초이며 복귀 순간이동은 사용하지 않는다. 현재 위치에서 지상 보행이 가능하면 그대로 현지 순찰을 시작한다. 옥상·지붕·점프맵에서는 NpcDescent가 실제 지지 표면·캡슐 충돌·점프 속도·중력을 확인해 걷기/점프/낙하 경로를 만든다. 각 이동 구간은 시간에 따라 진행하고 공중에서는 점프 자세를 표시한다. 한 번의 탐색은 반경32m/최대384표면 노드로 제한하며 경로를 못 찾으면 현재 위치에서 RETURN_WAIT 상태로2초 뒤 다시 찾는다. 복귀가 끝나기 전에는 다음 사건으로 이동하지 않는다. 플레이어 위치·진행 상태는 바꾸지 않는다. NPC는 충돌체 없는 시각적 경고라 공중에서도 잠깐 나타날 수 있으며 정적 구조물에 겹치지 않는 주변 위치를 확인한다. 안전한 위치를 못 찾으면 재시도하고 전체90초 한도에서 개인 안내 후 종료한다.

NPC snapshot의 warp 번호는 출동 순간이동 때만 증가한다. 복귀의 RETURN/RETURN_JUMP 좌표는 일반 이동처럼 보간한다. 일반 순찰/달리기는 기존 프레임 보간을 유지한다. 입구 대기 좌표 설정과 ONTOP_AI_POLICE_WAITING_FILE은 더 이상 사용하지 않는다.

## 반복 위반과 여러 작성자

새로 가려진 메시지가 있으면 같은 사람의 쿨타임 안 위반도 새 사건·경찰 요청·개인 경고를 만든다. 중복 억제는 같은 scope/종류/관련 작성자 후보 집합의 MM 알림에만 적용한다. 실제 알림이 만들어진 사건의 시각을 기준으로60초를 계산하므로 지속 위반이 쿨타임을 무한 연장하지 않는다. 똑같은 사건의 전송 재시도는 별도 재경고로 보지 않는다.

한 문맥에서 여러 명의 메시지가 위반이면 새로 숨긴 메시지 작성자별로 개인 경고를 보내고 같은 경찰이 FIFO로 한 명씩 확인한다. 문맥에 함께 있는 정상 작성자는 경고 대상으로 넣지 않는다. 모욕/갈등 복합 사건의 actors는 검토 후보이고 경찰 경고 대상은 newly-hidden 메시지의 실제 작성자다. 동시 욕설만으로 상호 싸움이라고 단정하지 않으며 상호 적대 문맥은 별도 갈등 판정을 따른다. 갈등만 있는 경우 메시지 가림 없이 중재한다.

현재 제재는 메시지 가림·개인 경고·NPC 재출동이다. 자동 채팅 금지/강퇴/계정 제재 정책은 추가하지 않았다. 큐가 있으면 개인 경고는 즉시 전달하고 NPC는 순서대로 처리한다.

## 공원 채팅 경고 경로와 계측 (2026-11-10)

실제 공원 advisory 모드에서 소켓 전송은 그대로 유지한다. AI 입력은 최대512개 별도 큐에 넣고, 외부 API 없는 `world-chat-ingress`가50ms 주기로 저장과 명백한 욕설 사건/경찰 요청을 처리한다. 같은 메시지 ID는 재경고하지 않으며 새 메시지의 연속 욕설은 각각 안내한다. 경찰 한 몸의 기존 FIFO·복귀/접근 로직은 유지한다. 게임 중에는 같은 개인 안내만 보내고 몸체는 출동하지 않는다.
