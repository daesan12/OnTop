# 본인 이동 예측과 서버 위치 보정

2026-10-29 로컬 구현 계약. `WORLD_MOVE` 입력 형식과 서버의 최종 이동·충돌 판정은 유지한다. 본인 화면에는 입력을 먼저 반영하고 상대는 서버 tick 스냅샷 버퍼를 사용한다. 개발 서버 배포·실제 두 계정 검수는 별도다. 원인 분석·설계 선택·측정 범위는 [이동 분석](world-movement-analysis.md)을 참고한다.

## 서버 응답

`WORLD_STATE.payload.avatars[].motion`은 선택 필드다. `position.lastInputSeq`는 수락한 입력 순번이고 `motion.appliedInputSeq`는 실제 물리 스텝에 반영한 순번이다. 입력 수락 직후 응답은 직전 물리 계산 결과일 수 있다.

```json
{
  "epoch": 0,
  "tick": 30,
  "appliedInputSeq": 11,
  "inputAgeMs": 33.333333,
  "velocityY": 0,
  "grounded": true,
  "inputActive": true
}
```

| 필드 | 의미 |
| --- | --- |
| epoch | 강제 위치 이동·시설 고정/해제·오류 복구 시 바뀌는 보정 세대 |
| tick | 서버 물리 계산 순번. 같은 세대의 과거 tick은 재적용하지 않음 |
| appliedInputSeq | 완료한 물리 스텝이 사용한 입력 순번 |
| inputAgeMs | 그 스텝에서 해당 입력을 받은 뒤 경과한 서버 시간, 0~250ms |
| velocityY | 해당 스텝의 실제 수직 이동 속도(m/s), 접지 상태는 0 |
| grounded | 해당 스텝의 접지 여부 |
| inputActive | 입력이 서버의 250ms 유효 기간 안에 있는지 여부 |

클라이언트는 시각·dt·최종 좌표를 보내지 않는다. 메타데이터만 바뀌었다고 정지 아바타 방송을 추가하지 않는다.

## 본인 화면

- 같은 맵 버전에서 Rapier 0.21.0과 공통 맵 충돌 설정으로 본인 캡슐을 계산한다. 공개 `WORLD_STATE.tables`의 anchorId/chairCount로 의자 활성 상태를 반영한다.
- 방향키·Shift·키 해제·이동 중 카메라 회전은 이벤트 시점에 로컬 이동 의도를 갱신한다. 렌더링은 다음 프레임에 반영한다. 기존 60ms 전송 큐를 유지하고 서버로 좌표를 보내지 않는다. 오래된 요청 실패는 이미 대기 중인 새 방향·점프를 지우지 않는다.
- 실제 처리한 순번의 서버 위치에서 남은 로컬 입력을 재생한다. 입력 기록은 최대128개, 보정 지표는 최대256개다.
- 마지막 서버 확인 후 최대250ms만 예측한다. 오래 정지한 경우 확인된 정지 위치에서 한 번 시작할 수 있지만 미확인 상태의 정지·재시작 반복으로 기한을 연장하지 못한다.
- 같은 세대의 보정 잔차는80ms 동안 줄이는 것을 목표로 하되 아래 표시 이동 상한이 우선한다. 따라서 큰 오차의 실제 수렴은80ms보다 오래 걸릴 수 있다. 오차 크기만으로 모델을 즉시 초기화하지 않으며 서버가 명시한 세대 변경만 즉시 위치를 바꾼다. 공식 좌표와 물리 기준의 서버 응답 반영은 즉시 유지한다.
- 표시 위치는 물리 예측과 분리한다. 연속 프레임의 수평 이동은 `달리기 속도 + 걷기 속도의 절반`(현재12.125m/s), 수직 이동은 최대 낙하 속력(현재20m/s)으로 제한한다. 이는 표시 보정의 추격 한계이며 실제 이동 속도·서버 거리 판정은 바꾸지 않는다.
- 이동·충돌은 예측 물리와 서버 물리에서 계산한다. 표시 위치를 수렴시키는 보정 경로에는 별도 충돌 검사를 하지 않는다. 잘못 예측해 발판 아래에 있는 표시 모델이 서버가 확정한 발판 위로 복원되는 것을 다시 막으면 안 된다. 보정 중 모델의 일시적 겹침은 가능하지만 물리 캡슐·공식 좌표·거리/접근 권한은 바뀌지 않는다.
- 입력 수락과 점프 실행을 구분한다. 실제 전송 입력에 점프 시각을 연결하고, 물리 완료 순번이 확인한 점프만 재생에서 소비한다. 점프 이전 스냅샷을 받으면 미처리 점프를 다시 예측하며 명시적으로 거절된 점프는 제외한다. 처리 순번을 찾지 못하면 이전 물리 tick의 시계를 이어 사용한다.
- 본인 회전 표시는 기존 NETWORK.interpolationMs(120ms) 동안 최단 각도로 보간한다. 방향을 다시 바꾸면 현재 보이는 각도에서 이어가며 위치 반응은 늦추지 않는다. 일반 서버 ACK는 회전을 다시 시작하지 않고, 강제 위치 보정·접속/활동 초기화는 회전도 즉시 새 기준으로 맞춘다.
- 연결/채널/맵 변경, 본인 누락, 시설·테이블·따라가기·공개 활동 상태에서 예측을 중단한다. motion 없는 구서버나 WASM 초기화 실패는 기존 서버 보간을 사용한다.
- 예측 위치·애니메이션은 표시 전용이다. authoritativePose, 공식 current 좌표, 시설 접근·채팅·관전 거리는 계속 서버 위치를 사용한다.
- `localMovement.metrics()`는 최근 RTT16개·보정 진단64개·반응/보정 표본256개와 강제 보정 카운터를 제공한다. 인증정보·사용자 ID는 담지 않는다. RTT는 매칭 입력의0~500ms 표본만 보관하고 보정 진단에는 최근 최솟값을 넣는다. 장기 지연/전체 RTT 분포로 해석하지 않는다. RTT는 진단용이며 절반 RTT를 물리 시각으로 단정해 재생 시계를 변경하지 않는다.

Java Bullet과 Rapier는 다른 엔진이므로 완전히 같은 궤적을 보장하지 않는다. 초기 WASM 다운로드·충돌 월드 구성 비용과 다양한 기기/지형/지연에서의 보정 체감은 추가 확인이 필요하다. 서버 맵 변경 때 FE 충돌 데이터도 함께 맞춰야 한다.

## 다른 사용자 표시

`remoteMovement`는 사용자별 최대16개 스냅샷을 서버 motion.tick 순으로 정렬하고 중복 tick·과거 epoch를 제외한다. 최초 epoch는 즉시 표시하고, 이후180ms 지연한 서버 시각에서 위치와 이동·달리기·수영 플래그를 함께 보간한다. 기존 도착 시각 기반120ms 보간보다 표시 지연이60ms 늘어난다. 이 값은100ms 방송 주기와 로컬 비교의0~60ms 지터를 고려한 초기값이지 운영 최적값이 아니다.

수신이 끊기면 마지막 좌표를 유지하고 외삽하지 않는다. 재개 시 표시 이동 상한으로 따라잡으며 epoch 변경은 리스폰/강제 이동으로 구분한다. 서버가 긴 정지 후 catch-up tick을 버릴 수 있으므로 최근16개·2초 시계 표본으로 위상을 재조정하고 표시 tick은 역행시키지 않는다. 재위상 조정 중 잠시 멈출 수 있다. 착석·시설·맵/채널 변경·사용자 삭제 시 기록을 비운다. motion 없는 구서버는 기존 보간으로 돌아간다. 캐릭터와 수영 물결은 같은 표시 좌표를 사용한다.

## 이동 입력 빈도

`ontop.world.movement.minimum-interval`은 기본50ms당1개(평균 초당20개) 예산을 충전하고 연속4개까지 일시 수락한다. 몰려 도착한 정상 입력을 허용하되 초과한 새 순번은 기존 MOVE_TOO_FREQUENT로 거절하고 순번을 소비하지 않는다. 중복/과거 순번은 예산 소비·입력 유효 기간 갱신을 하지 않는다.

서버는30Hz 고정 스텝이므로 입력을 몰아 보내도 실제 이동 시간이 늘지 않는다. 공통 소켓 유입 제한은 유지한다. FE의 반복적인 이동 간격 안내만 상태 표시에서 숨기고 진단 상태·다른 오류 안내는 유지한다.

## 호환과 검증

테스트 전용 `ClientPositionPrototypeTests`는 별도의 client-driven 위치 검증 가능성을 살펴보는 오프라인 초안이다. 제품 프로토콜은 여전히 방향 입력 방식이며 좌표 제출 API가 추가된 것이 아니다. 사용자 B 선호와 초안의 통과/미검증 범위는 `world-movement-analysis.md`8절을 참고한다.

BE 먼저 반영 후 FE를 반영할 수 있다. 구FE는 추가 motion을 무시하고 신FE는 motion 없는 구BE에서 기존 표시를 사용한다. 인증·DB 스키마·게임 규칙 변경은 없다.

MovementPredictionContractTests는 수락/물리 완료 구분, 버스트·충전·중복 순번, 속도와 의자 안전 이동의 세대 동기화를 검사한다. FE 단위 검사는 예측·재생·정지·방향 전환·기한·재접속/활동 중단·실제 Rapier 충돌을 확인한다. 선택 실행 MovementPredictionFrontendTests와 movement-prediction.spec.ts는 같은 Bullet 궤적의 제어된 리플레이를 비교한다. 합성 로그인/전송과 준비된 충돌 월드의 로컬 비교이며 운영 지연 측정·실제 로그인 연동 검수와 구분한다.

선택 Bullet 비교는 직진·경계·직선 달리기·걷기에서Shift전환·20ms 간격 입력/80ms 좌우 반전·60ms 전송·점프·실제 공원 점프 발판·발판 낙하·계단을 RTT0/50/100/200ms의36조건으로 재생한다. cc86867 당시 결과는7종28조건이며 후속 진단에서 장애물 없는(-10,42) 구간의 달리기2종을 추가했다. ACK 동일 시각의 표시 불연속, 프레임 이동량, 정지 후 서버 위치 수렴을 함께 검사한다. movement-continuity.spec.ts는 이 중100ms RTT의5조건과, 잘못된 발판 아래 표시를 서버 확정 착지로 복원하는 분기를 실제 Three.js 화면에서도 검사한다. 후자는 합성된 보정 분기이며 실제 서버 점프 궤적으로 주장하지 않는다. 이 검사는 인간의 키보드 체감·다중 사용자 개발 서버 검수를 대신하지 않는다.

원인 분리용 `tests/diagnostics/movementAblation.ts`는 제품 코드에서 참조하지 않는 테스트 모듈이다. baseline/A(offset만제거)/B(A+같은epoch물리재설정·재생생략)를 동일 입력·스냅샷으로 비교한다. A↔B 비교로 reset/replay의 기여를 분리한다. B는 서버와의 정합성을 만족하는 새 이동 구현이 아니며 운영에 적용하지 않는다. 단위 선택 검사는 MOVEMENT_AB_DIR에 Bullet결과 폴더를 지정해 movementAblation.test.ts를 실행하고, 실제 렌더 비교는 movement-ablation.spec.ts를 실행한다. 개발전용movementPanel도 자동으로 앱에 연결되지 않으며 loopback에서만 수동 로딩한다. 마지막 서버 확인 기한과 epoch/활동 전환은 유지하고, 모드 전환 때 입력·예측을 초기화한다.
