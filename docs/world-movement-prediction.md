# 본인 이동 예측과 서버 위치 보정

2026-10-30 구현 계약. dev는 아래 C 방식으로 클라이언트가 먼저 물리를 계산하고 서버가 승인 위치를 검증한다. local의 명시적 C 활성화와 기존 WORLD_MOVE 경로도 유지하며 prod는 기존 방식이다. 상대는 서버 tick 스냅샷 버퍼를 사용한다. 개발 서버 배포·실제 두 계정 검수는 별도다. 원인 분석·설계 선택·측정 범위는 [이동 분석](world-movement-analysis.md)을 참고한다.

## 서버 응답

`WORLD_STATE.payload.avatars[].motion`은 선택 필드다. `position.lastInputSeq`는 수락한 입력 순번이고 `motion.appliedInputSeq`는 실제 물리 스텝에 반영한 순번이다. 입력 수락 직후 응답은 직전 물리 계산 결과일 수 있다.

```json
{
  "epoch": 0,
  "tick": 30,
  "appliedInputSeq": 11,
  "inputAgeMs": 33.333333,
  "velocityY": 0,
  "grounded": true,
  "inputActive": true
}
```

| 필드 | 의미 |
| --- | --- |
| epoch | 강제 위치 이동·시설 고정/해제·오류 복구 시 바뀌는 보정 세대 |
| tick | 서버 물리 계산 순번. 같은 세대의 과거 tick은 재적용하지 않음 |
| appliedInputSeq | 완료한 물리 스텝이 사용한 입력 순번 |
| inputAgeMs | 그 스텝에서 해당 입력을 받은 뒤 경과한 서버 시간, 0~250ms |
| velocityY | 해당 스텝의 실제 수직 이동 속도(m/s), 접지 상태는 0 |
| grounded | 해당 스텝의 접지 여부 |
| inputActive | 입력이 서버의 250ms 유효 기간 안에 있는지 여부 |

클라이언트는 시각·dt·최종 좌표를 보내지 않는다. 메타데이터만 바뀌었다고 정지 아바타 방송을 추가하지 않는다.

## 본인 화면

- 같은 맵 버전에서 Rapier 0.21.0과 공통 맵 충돌 설정으로 본인 캡슐을 계산한다. 공개 `WORLD_STATE.tables`의 anchorId/chairCount로 의자 활성 상태를 반영한다.
- 방향키·Shift·키 해제·이동 중 카메라 회전은 이벤트 시점에 로컬 이동 의도를 갱신한다. 렌더링은 다음 프레임에 반영한다. 기존 60ms 전송 큐를 유지하고 서버로 좌표를 보내지 않는다. 오래된 요청 실패는 이미 대기 중인 새 방향·점프를 지우지 않는다.
- 실제 처리한 순번의 서버 위치에서 남은 로컬 입력을 재생한다. 입력 기록은 최대128개, 보정 지표는 최대256개다.
- 마지막 서버 확인 후 최대250ms만 예측한다. 오래 정지한 경우 확인된 정지 위치에서 한 번 시작할 수 있지만 미확인 상태의 정지·재시작 반복으로 기한을 연장하지 못한다.
- 같은 세대의 보정 잔차는80ms 동안 줄이는 것을 목표로 하되 아래 표시 이동 상한이 우선한다. 따라서 큰 오차의 실제 수렴은80ms보다 오래 걸릴 수 있다. 오차 크기만으로 모델을 즉시 초기화하지 않으며 서버가 명시한 세대 변경만 즉시 위치를 바꾼다. 공식 좌표와 물리 기준의 서버 응답 반영은 즉시 유지한다.
- 표시 위치는 물리 예측과 분리한다. 연속 프레임의 수평 이동은 `달리기 속도 + 걷기 속도의 절반`(현재12.125m/s), 수직 이동은 최대 낙하 속력(현재20m/s)으로 제한한다. 이는 표시 보정의 추격 한계이며 실제 이동 속도·서버 거리 판정은 바꾸지 않는다.
- 이동·충돌은 예측 물리와 서버 물리에서 계산한다. 표시 위치를 수렴시키는 보정 경로에는 별도 충돌 검사를 하지 않는다. 잘못 예측해 발판 아래에 있는 표시 모델이 서버가 확정한 발판 위로 복원되는 것을 다시 막으면 안 된다. 보정 중 모델의 일시적 겹침은 가능하지만 물리 캡슐·공식 좌표·거리/접근 권한은 바뀌지 않는다.
- 입력 수락과 점프 실행을 구분한다. 실제 전송 입력에 점프 시각을 연결하고, 물리 완료 순번이 확인한 점프만 재생에서 소비한다. 점프 이전 스냅샷을 받으면 미처리 점프를 다시 예측하며 명시적으로 거절된 점프는 제외한다. 처리 순번을 찾지 못하면 이전 물리 tick의 시계를 이어 사용한다.
- 본인 회전 표시는 기존 NETWORK.interpolationMs(120ms) 동안 최단 각도로 보간한다. 방향을 다시 바꾸면 현재 보이는 각도에서 이어가며 위치 반응은 늦추지 않는다. 일반 서버 ACK는 회전을 다시 시작하지 않고, 강제 위치 보정·접속/활동 초기화는 회전도 즉시 새 기준으로 맞춘다.
- 연결/채널/맵 변경, 본인 누락, 시설·테이블·따라가기·공개 활동 상태에서 예측을 중단한다. motion 없는 구서버나 WASM 초기화 실패는 기존 서버 보간을 사용한다.
- 예측 위치·애니메이션은 표시 전용이다. authoritativePose, 공식 current 좌표, 시설 접근·채팅·관전 거리는 계속 서버 위치를 사용한다.
- `localMovement.metrics()`는 최근 RTT16개·보정 진단64개·반응/보정 표본256개와 강제 보정 카운터를 제공한다. 인증정보·사용자 ID는 담지 않는다. RTT는 매칭 입력의0~500ms 표본만 보관하고 보정 진단에는 최근 최솟값을 넣는다. 장기 지연/전체 RTT 분포로 해석하지 않는다. RTT는 진단용이며 절반 RTT를 물리 시각으로 단정해 재생 시계를 변경하지 않는다.

Java Bullet과 Rapier는 다른 엔진이므로 완전히 같은 궤적을 보장하지 않는다. 초기 WASM 다운로드·충돌 월드 구성 비용과 다양한 기기/지형/지연에서의 보정 체감은 추가 확인이 필요하다. 서버 맵 변경 때 FE 충돌 데이터도 함께 맞춰야 한다.

## 다른 사용자 표시

`remoteMovement`는 사용자별 최대16개 스냅샷을 서버 motion.tick 순으로 정렬하고 중복 tick·과거 epoch를 제외한다. 최초 epoch는 즉시 표시하고, 이후180ms 지연한 서버 시각에서 위치와 이동·달리기·수영 플래그를 함께 보간한다. 기존 도착 시각 기반120ms 보간보다 표시 지연이60ms 늘어난다. 이 값은100ms 방송 주기와 로컬 비교의0~60ms 지터를 고려한 초기값이지 운영 최적값이 아니다.

수신이 끊기면 마지막 좌표를 유지하고 외삽하지 않는다. 재개 시 표시 이동 상한으로 따라잡으며 epoch 변경은 리스폰/강제 이동으로 구분한다. 서버가 긴 정지 후 catch-up tick을 버릴 수 있으므로 최근16개·2초 시계 표본으로 위상을 재조정하고 표시 tick은 역행시키지 않는다. 재위상 조정 중 잠시 멈출 수 있다. 착석·시설·맵/채널 변경·사용자 삭제 시 기록을 비운다. motion 없는 구서버는 기존 보간으로 돌아간다. 캐릭터와 수영 물결은 같은 표시 좌표를 사용한다.

## 이동 입력 빈도

`ontop.world.movement.minimum-interval`은 기본50ms당1개(평균 초당20개) 예산을 충전하고 연속4개까지 일시 수락한다. 몰려 도착한 정상 입력을 허용하되 초과한 새 순번은 기존 MOVE_TOO_FREQUENT로 거절하고 순번을 소비하지 않는다. 중복/과거 순번은 예산 소비·입력 유효 기간 갱신을 하지 않는다.

서버는30Hz 고정 스텝이므로 입력을 몰아 보내도 실제 이동 시간이 늘지 않는다. 공통 소켓 유입 제한은 유지한다. FE의 반복적인 이동 간격 안내만 상태 표시에서 숨기고 진단 상태·다른 오류 안내는 유지한다.

## 호환과 검증

테스트 전용 `ClientPositionPrototypeTests`는 별도의 client-driven 위치 검증 가능성을 살펴보는 오프라인 초안이다. 초안 자체는 제품 API가 아니며, 아래 C 구현은 별도로 제품 프로토콜에 연결했다. 사용자 B 선호와 초안의 통과/미검증 범위는 `world-movement-analysis.md`8절을 참고한다.

### C 좌표 검증 이동 계약 (dev·운영 DB 기본 적용)

`application-dev.yml`은 `ontop.world.movement.client-position: true`를 기본 적용한다. `application.yml`의 운영 DB 전용 설정도 같은 값을 적용하므로 dev,db 및 prod,db(또는 production,db)는 별도 환경변수 추가 없이 C를 사용한다. local은 명시적으로 true를 지정할 때 사용한다. DB 없는 운영·local/dev와 운영을 섞은 프로필에서는 활성화를 거절한다. 이때 `WORLD_STATE.avatars[].motion.authority`가 `CLIENT_VALIDATED`인 본인만 아래 메시지를 기존60ms 큐에서 전송한다. 구서버/기본 서버/권위 필드가 없는 actor는 기존 `WORLD_MOVE`다.

```json
{
  "requestId": "position-1",
  "type": "WORLD_POSITION",
  "payload": { "seq": 1, "epoch": 1, "x": -2.0, "y": 0.84, "z": 34.0, "yaw": 0.0, "run": false, "jump": false }
}
```

응답은 기존 `WORLD_STATE`다. seq는 보고 순번, epoch는 직전 서버 세대를 사용하며 x/y/z/yaw는 실제 로컬 물리 표본이다. client timestamp/dt/grounded/userId 필드는 허용하지 않는다. 정상 승인에 appliedInputSeq가 증가하면 확인 기한을 갱신하고 물리는 되감지 않는다. 과거 승인 재방송은 기한을 늘리지 않는다. 새 epoch가 오면 이전 보고를 버리고 서버 위치에서 다시 시작한다.

위치·속도·충돌 검증 거절이나500ms 보고 만료는 마지막 승인 좌표에서 서버 모드로 복귀하고 authority를 생략한다. 이 입장 중 좌표 모드 자동 재시도는 없다. 잘못된 공통 필드는 INVALID_PAYLOAD, 기능 OFF는 UNSUPPORTED_MESSAGE_TYPE, 채널 미입장은 NOT_IN_CHANNEL, 활동 차단은 기존 TABLE_BUSY/FACILITY_BUSY 또는 ACTIVITY_BUSY, 과다 요청은 MOVE_TOO_FREQUENT다. 인증/게임 복구/맵 확인은 공통 게이트다. 수영·전망대·따라가기에서 서버 모드로 전환하는 정상 경계와 실패 fallback은 구분한다. 상세는 분석서9절을 참고한다. 개발 서버에서는 이 계약을 사용하며 운영 서버 적용과는 구분한다.

첫 보고 전에는 승인 스폰을 유지해 WASM/모델 로딩 시간 때문에 실패 복귀하지 않는다. 클라이언트 준비 완료 시 로딩 시간을 이동으로 재생하지 않는다. 준비 실패는 `WORLD_POSITION_FALLBACK`에 `{"epoch":현재세대}`를 보내 명시적으로 서버 이동으로 복귀한다. 옛 세대 요청/중복 요청은 추가 세대 변경 없이 현재 WORLD_STATE를 돌려준다. 준비 중에는 WORLD_MOVE를 보내지 않으며 준비 실패 후 서버 권위 응답을 받은 뒤 기존 입력으로 이동한다.

BE와 FE를 함께 배포하고 기존 탭은 새로고침해 C를 사용한다. 배포 중 구FE가 첫 좌표 보고 전에 WORLD_MOVE를 보내면 해당 입장만 기존 서버 이동으로 복귀해 이동 중단을 방지한다. 이미 좌표 보고를 시작한 actor의 늦은 방향 입력은 무시해 권위 전환을 반복하지 않는다. 신FE는 motion 없는 구BE에서 기존 표시를 사용한다. 인증·DB 스키마·게임 규칙 변경은 없다.

MovementPredictionContractTests는 수락/물리 완료 구분, 버스트·충전·중복 순번, 속도와 의자 안전 이동의 세대 동기화를 검사한다. FE 단위 검사는 예측·재생·정지·방향 전환·기한·재접속/활동 중단·실제 Rapier 충돌을 확인한다. 선택 실행 MovementPredictionFrontendTests와 movement-prediction.spec.ts는 같은 Bullet 궤적의 제어된 리플레이를 비교한다. 합성 로그인/전송과 준비된 충돌 월드의 로컬 비교이며 운영 지연 측정·실제 로그인 연동 검수와 구분한다.

선택 Bullet 비교는 직진·경계·직선 달리기·걷기에서Shift전환·20ms 간격 입력/80ms 좌우 반전·60ms 전송·점프·실제 공원 점프 발판·발판 낙하·계단을 RTT0/50/100/200ms의36조건으로 재생한다. cc86867 당시 결과는7종28조건이며 후속 진단에서 장애물 없는(-10,42) 구간의 달리기2종을 추가했다. ACK 동일 시각의 표시 불연속, 프레임 이동량, 정지 후 서버 위치 수렴을 함께 검사한다. movement-continuity.spec.ts는 이 중100ms RTT의5조건과, 잘못된 발판 아래 표시를 서버 확정 착지로 복원하는 분기를 실제 Three.js 화면에서도 검사한다. 후자는 합성된 보정 분기이며 실제 서버 점프 궤적으로 주장하지 않는다. 이 검사는 인간의 키보드 체감·다중 사용자 개발 서버 검수를 대신하지 않는다.

원인 분리용 `tests/diagnostics/movementAblation.ts`는 제품 코드에서 참조하지 않는 테스트 모듈이다. baseline/A(offset만제거)/B(A+같은epoch물리재설정·재생생략)를 동일 입력·스냅샷으로 비교한다. A↔B 비교로 reset/replay의 기여를 분리한다. B는 서버와의 정합성을 만족하는 새 이동 구현이 아니며 운영에 적용하지 않는다. 단위 선택 검사는 MOVEMENT_AB_DIR에 Bullet결과 폴더를 지정해 movementAblation.test.ts를 실행하고, 실제 렌더 비교는 movement-ablation.spec.ts를 실행한다. 개발전용movementPanel도 자동으로 앱에 연결되지 않으며 loopback에서만 수동 로딩한다. 마지막 서버 확인 기한과 epoch/활동 전환은 유지하고, 모드 전환 때 입력·예측을 초기화한다.


## 개발·운영 공통 확정 이동 프로필 (PARK_V1)

최종 로컬 비교에서 사용자가 걷기6m/s·달리기8m/s·점프 초기8m/s·중력30m/s²·최대 낙하78.4m/s·달리기 점프 추가속도0을 선택했다. MR에는 조절 패널·브라우저 설정 저장소·로컬 실험 플래그를 포함하지 않는다. `ParkMotion`이 이 고정값으로 지상 가속/제동·공중 관성과50ms 수직 항력(.98)을 계산하며, 기존 Rapier 캡슐·자동 단차0.22m·최소폭0.15m·접지스냅0.15m를 사용한다.

서버가 `motion.profile = "PARK_V1"`를 보내면 프론트가 해당 계산을 선택한다. request의 WORLD_POSITION 필드나 지도 버전은 바꾸지 않는다. 구서버가 profile을 보내지 않으면 기존 물리 경로를 사용한다. dev & !prod & !production 및 (prod | production) & db & !local & !dev 설정은 client-position/tuned-profile을 기본 true로 둔다. Registry는 같은 제품 프로필 조건으로 두 설정을 허용한다. 프론트가 임의 위치나 profile을 요청으로 지정해서 서버 정책을 바꿀 수 없다. FE/BE 배포 순서가 달라도 표식 없는 구서버에서 새 물리를 먼저 사용하지 않는다.

운영 반영 시에는 위 두 속성을 false로 덮어쓰는 외부 설정이 없는지 확인하고, 이 코드를 포함한 BE 이미지를 재배포한다. 최신 FE와 실행 서버의 맵 버전도 일치해야 한다. 접속 후 본인의 `motion.authority = "CLIENT_VALIDATED"`, `motion.profile = "PARK_V1"`를 확인한다. 운영 Spring 프로필은 그대로 유지하며 DB 스키마·맵 파일·인증 설정은 변경하지 않는다. 속도·경계·수직 이동·벽 관통·순번/세대 검증도 유지한다. 운영에서 실제 달리기·점프·충돌·재접속 검수는 배포 후 별도로 확인해야 하며, 로컬 프로필 검사를 실서버 검수 완료로 취급하지 않는다. 되돌릴 때는 서버 외부 설정에서 두 속성을 함께 false로 지정하고 재기동한다.

두 속성은 최종 주입이 끝난 뒤 `validateMovementConfiguration`에서 함께 검사한다. `client-position=false`, `tuned-profile=true`는 PARK_V1 표식과 좌표 검증 권한이 어긋나므로 기동을 거절한다. 둘 다 true인 정상 설정, 둘 다 false인 롤백, 기존 client-position=true/tuned-profile=false 모드는 유지한다. 착석·시설·자동 따라가기 중 잠시 authority가 해제되는 정상 런타임 상태는 이 기동 설정 검사와 구분한다. 저장소의 application-prod.yml과 Compose에는 현재 이 속성을 덮어쓰는 항목이 없지만, 외부 프로필 파일·환경변수는 기본값보다 우선하므로 배포 때 실제 설정을 확인해야 한다.

예시(기존 WORLD_STATE.avatars[].motion에 선택 필드만 추가):

```json
{
  "epoch": 123,
  "tick": 30,
  "appliedInputSeq": 16,
  "inputAgeMs": 0,
  "velocityY": 0,
  "grounded": true,
  "inputActive": true,
  "authority": "CLIENT_VALIDATED",
  "profile": "PARK_V1"
}
```

C 정상 확인은 현재 로컬 몸체에 과거 좌표를 다시 덮거나 입력을 재생하지 않는다. 서버 확인 기한은2초, 렌더 정지 뒤 물리 catch-up은 한 번에 최대100ms다. PARK_V1은 수영·전망대·따라가기와 검증 거절에서도 CLIENT_VALIDATED를 유지한다. 물의 부력·전망대 경사·따라가기 방향은 같은 로컬 물리의 환경 입력으로 처리한다. 거절 시 새 epoch의 서버 승인 위치로 복구하고 같은 조작계로 재개한다. native Bullet의 연속 중력과50ms 항력이 완전히 같은 궤적이라고 가정하지 않는다.

서버는 기존 인증·활동·순번·세대·자기 단조 시계·경계·전체 캡슐 충돌 검사를 유지한다. 수평 예산은350ms까지만 쌓이고 초기0.9m, 선택 걷기/달리기의15% 전달 여유를 둔다. 로컬 실험의2초 이동 예산과 중심 ray 검사는 제품에 사용하지 않는다. 점프는 서버 지지 상태와 jump 신호로 시작하고 출발 높이에서 최대1.45m(선택 궤적 최고점 약1.21m + 계산 여유)로 제한한다. 신호 없는 공중 상승과 높은 플랫폼 순간이동을 거절한다. 프레임마다 정확한 포물선 일치를 요구하는 대신 큰 수직 변화·지속 공중정체도 검사한다. 검증한 서버 좌표로 시설/테이블/관전 등 거리를 판정하는 경계는 유지한다.

실제 평지 접촉은 이동량이 조금 줄었다는 이유만으로 벽으로 판단하지 않는다. Rapier의 world-space 장애물 법선과 기존 최대 통행 경사각으로 벽을 구분하고, 벽 안으로 향하는 수평 속도 성분만 제거한다. 정상 계단 상승은 관성을 유지한다. 실제 몸체의 이동 경로는 계속 Rapier가 제한한다.

기존 회귀는 실제 생성맵 계단·평지 속도·벽/낮은 장애물·점프 상한·구서버 호환을 포함한다. 아래 통합 검사는 PARK_V1의 구역/오류 경계와 동일 물리 유지 정책을 추가한다. 임시 로컬 실행 런처·합성 로그인 어댑터는 MR 밖에서 검수에만 사용하며 실회원/WAN 검수와 구분한다.
점프 보고는 최초 jump=true 요청이 빈도 제한으로 거절돼도 승인 순번 ACK를 받을 때까지 새 보고에 유지한다. 로컬 물리의 점프는 한 번만 소비하며 재전송 때문에 추가 점프하지 않는다. 세대 전환·활동 중단 때 대기 표식을 정리한다.

연속 계단에서는 둥근 캡슐의 모서리 접촉만 따라가면 발이 발판 안으로 들어간 중간 좌표를 보고할 수 있다. PredictionPhysics.stairTop은 기존 계단 박스 안에서만 상단을 구하고, 접지 상태의 비점프 이동에서 기존0.22m 이내 높이를 먼저 요청한다. 최종 이동은 Rapier 충돌 결과를 사용한다. 서버 침투 허용치를 늘리지 않으며 실제 침투 좌표 거절/정상 상단 좌표 승인 회귀를 유지한다.

### 벽 접촉 중 미세 좌표 보고

PARK_V1에서 지상·비점프·진행 중 Flight 없음·출발/도착 모두 서버 지지 조건을 충족하고, 충돌 검사에 걸린 목표가 마지막 승인점에서 XYZ 거리1mm 이내라면 이동 좌표는 채택하지 않는다. 마지막 안전 위치를 그대로 유지하고 순번/확인 시각만 갱신한다. 같은 보고를 반복해도 벽으로 조금씩 이동할 수 없다. 1mm 초과·공중·점프·기본 프로필의 충돌 거절은 유지한다. 공개 요청/응답 필드와 오류 계약은 바뀌지 않는다.

### 5174 기준 보행 표시와 착지 접촉

본인의 PARK_V1 아바타도 다른 사용자와 같은 authored 대기·걷기·달리기 클립을 사용한다(S15P31B105-305, 이동 담당자 협의). 5174에서 쓰던 절차형 걷기·달리기 표시는 본인 화면과 다른 사용자 화면의 모습이 달라지고 멈췄을 때 대기 동작이 없어 되돌렸다. 위치 계산의 고정값은 위와 같고, 시설·착석·수영·감정표현의 우선순위는 유지한다.

공통 PositionCollision은 기본 sweep 실패 후 하강 중이고 도착점이 서버의 이용 가능한 지지면 위일 때만 착지 접촉을 다시 검사한다. 보행 가능한 법선(y≥0.6)의 충돌면에서 끝점까지 남은 법선 방향 거리가 5mm 이내인 경우만 접촉 여유로 처리한다. Rapier 착지와 Bullet contact skin의 미세 차이가 정상 착지를 충돌로 바꾸는 것을 막는다. 이 기하 판정은 기본 프로필에도 공통 적용된다. 벽·천장·깊은 겹침·경로 중간의 바닥 횡단, 속도·시간·순번·최대 높이 검사는 유지한다. 맵·요청/응답 필드는 바꾸지 않는다.

## PARK_V1 구역·오류 경계 통합 (2026-10-30, 로컬 검증)

이 절은 위의 초기 C/legacy 설명 중 PARK_V1 인계·실패 fallback 정책을 대체한다. 일반 WORLD_MOVE/구프로필은 변경하지 않는다. 실제 배포 여부와 구분하며 FE/BE를 함께 반영해야 한다.

- 선택값 걷기6·달리기8·점프8·중력30·최대낙하78.4·sprintJumpBoost0, 기존 자동 단차0.22m를 유지한다. 수영은 기존 맵의 수영 속도·부력, 전망대는 동일 Rapier 충돌/경사로 처리한다.
- 검증 거절은 마지막 승인 위치와 새 epoch를 방송한다. 권위는 CLIENT_VALIDATED, 프로필은 PARK_V1이다. 이동 예산·승인 순번·진행 중 점프·공중 정체 시계는 거절 때문에 초기화하지 않는다. 오래된 epoch/순번은 무시한다. 계속 누르고 있는 방향은 새 기준에서 재개하지만 점프는 재발사하지 않는다.
- 유효 보고가2초 넘게 없으면 지지면 아래로 안전 복구한 후 새 세대에서 재개한다. 수영 중이면 물 위 승인 위치를 유지한다. 연결 해제는 기존 heartbeat/재접속 정책을 따른다.
- WASM 준비 실패 시 PARK_V1을 다른 물리로 조용히 전환하지 않는다. 이동 불가 안내와 새로고침으로 복구한다. 구프로필의 WORLD_POSITION_FALLBACK 호환은 유지한다.
- 따라가기 관계·거리·해제 권한과 자동 이동은 서버가 판정한다. 브라우저 최소화로 프레임/위치 보고가 멈춰도 서버 30Hz 틱에서 자동 이동한다. 자동 따라가기 동안 profile=PARK_V1은 유지하고 authority는 생략한다. FE는 기존 서버 좌표 보간을 사용하며 WORLD_POSITION을 보내지 않는다. 2.2m 이내 정지, 5m 이내 걷기6/초과 달리기8과 기존 장애물 충돌을 사용한다. 직접 방향/점프 WORLD_MOVE 또는 종료 요청이 관계를 해제하며, 다음 틱에 현재 승인 좌표·수직속도로 CLIENT_VALIDATED에 복귀한다. 일반 직접 조작의 6/8/8/30·단차0.22m는 유지한다.

WORLD_POSITION의 선택 필드 `manual:boolean`은 직접 이동/점프 의도이면 true, 자동 따라가기·정지 보고이면 false다. 생략하면 이전 클라이언트와 같이 true로 처리한다. 이는 서버 검증이나 접근 권한을 우회하는 플래그가 아니다.

### 울타리 경계와 보고 사이의 착지·재점프 경로 (2026-11-05)

PARK_V1의 WORLD_POSITION은 선택 필드 `path`를 받는다. 각 점은 `{x, y, z, jump}`이며 1~64개, 마지막 점의 좌표는 보고의 최종 `x/y/z`와 정확히 같아야 한다. `jump`는 키 누름 대신 해당 물리 구간에서 실제로 발동한 점프다. 점프 버퍼가 착지 직후 발동해도 기록한다. 클라이언트 시각·구간 시간·접지 주장은 받지 않는다.

FE는 표시 보정 전 실제 물리 경로를 기록한다. 착지·이륙·굽은 구간은 보존하고 같은 지지 상태의 직선은 합친다. 합칠 때의 위치 오차는 0.5mm 이내이며, 합친 구간도 서버가 다시 충돌 검사한다. 2026-11-06부터 송신 콜백이 밀려 경로가 64점에 도달하면 다음 물리 단계 전에 추가 예측을 보류한다. 기존 경로와 실제 예측 위치를 유지한 채 최대 64점을 그대로 보내며 끝점 보고로 대체하지 않는다. 직선으로 압축되는 긴 미전송 구간도 서버의 기존 이동 예산을 넘지 않도록 미전송 물리 진행을 100ms로 제한한다. 보고를 만들면 경로 보관 한도를 다시 열고 다음 프레임부터 재개하며, 보류 중 경과한 시간을 몰아서 따라가지 않는다. 예측이 한 단계도 진행되지 않은 PARK_V1 보고도 현재 위치의 jump=false 한 점을 보내 실제로 발동하지 않은 키 입력을 점프로 판정하지 않게 한다. 세대 변경·물리 reset·입력 소유권 중지는 이전 경로를 버린다.

서버는 각 구간에 기존 충돌·지지면·점프 검증을 적용한다. 보고 사이의 짧은 착지도 실제 서버 지지면으로 확인하므로 정상 재점프가 이전 비행의 높이 제한을 잘못 이어받지 않는다. 모든 점은 같은 서버 수신 시각을 쓰며 경로 전체의 수평 거리에서 기존 이동 예산을 소비한다. 보고 전체의 수직 한도도 유지한다. 한 점이라도 실패하면 위치·순번·예산·비행/공중 체류 상태 전체를 이전 값으로 복구하고 기존 보정 절차를 따른다. 중간점은 별도 월드 방송·게임 진행·보상 이벤트를 만들지 않으며 최종 승인 좌표만 기존 흐름에 전달한다.

2026-11-06 수직 상승 일괄 검사 보완: 수신 간격이 짧아진 배치가 공중에서 시작해도, 구간 검증을 통과하고 서버 지지 출발점에서 새 Flight를 만든 착지·재점프는 그 출발 높이와 실제 선택된 점프 속도로 전체 상승 상한을 계산한다. 서버가 출발점 또는 착지점의 지지를 확인해야 하며 공중 jump 표식이나 미검증 발판은 상한을 늘리지 않는다. 전체 낙하 한도는 구간 검사 전에 유지하고 전체 상승 검사는 구간 검사 후 커밋 전에 수행한다. 마지막 일괄 검사에서 실패해도 동일한 체크포인트로 모든 상태를 복구한다. 경로 생략·구프로필·64점 제한·수평 예산·충돌 검사는 유지한다.

`path` 생략 시 기존 계약을 유지한다. 구프로필은 경로 보고를 승인하지 않는다. 새 FE를 배포하기 전에 이 필드를 지원하는 BE를 먼저 반영해야 하며, 롤백은 FE를 먼저 되돌린다. DB·Flyway·기존 게임 규칙·맵·보상 변경은 없다. 관련 재현/검증은 `docs/integration/fence-movement-path-20261105.md`에 기록한다.

경로 보존을 위한 예측 보류는 전송 정체 동안 잠깐 서 있는 것으로 보일 수 있다. 실제 연결 유실·보고 2초 만료·잘못된 위치의 서버 안전 복구는 유지하며, 모든 네트워크 장애에서 이동이 끊기지 않는다는 보장은 아니다. 64점 처리 보완의 검증은 `docs/integration/movement-backpressure-20261106.md`에 기록한다.

### 최소화 중 자동 따라가기 보완 (로컬 검증)

WORLD_FOLLOW_START/STOP/CHECK·WORLD_FOLLOW_STATE의 요청/응답 필드는 유지한다. 자동 이동은 브라우저의 타이머·가시성 이벤트가 아니라 서버 물리 틱에 종속된다. 살아 있는 소켓의 heartbeat 응답은 계속 필요하며 실제 단절이면 기존대로 관계를 해제한다. 재접속은 자동 따라가기 복원이 아닌 CHECK로 관계를 다시 확인한다.

따라가기 중 오래된 WORLD_POSITION은 승인 위치/순번을 바꾸지 않는다. 직접 WORLD_MOVE를 서버가 수락하면 관계를 해제하고 현재 위치에서 수동 프로필로 돌아온다. 점프로 해제할 때 서버가 승인한 점프 속도를 새 세대와 검증기의 Flight에 함께 넘기며, 자동→수동 전환마다 무료 이동 예산을 주지 않는다. WORLD_STATE의 기존 authority 생략/CLIENT_VALIDATED 처리를 그대로 사용하므로 새 메시지·환경변수·DB 변경이 없다.

BackgroundFollowTests는 30초간 위치 보고 없이 이동 대상 추적·정지/재개, 실제 장애물 차단, 점프 인계·추가 이동 예산 차단을 검사한다. UnifiedMovementFlowTests는 실제 RawWS로 시작→서버 자동 이동→수동/명시 종료→새 C 세대·heartbeat 단절·재접속을 검사한다. 루프백 무보고 재현은 브라우저/OS가 소켓까지 완전히 중지한 경우를 보장하는 검사는 아니다.
### 2026-10-31 울타리·관전자 벤치의 접촉 보정

여러 렌더 프레임에 걸쳐 둥근 캡슐이 모서리를 올라가거나 가장자리에서 내려오는 경로는, 두 위치 보고 사이의 직선과 다르다. 실제 Rapier 궤적의 끝점이 안전해도 직선 sweep만으로는 벤치 등받이·난간 모서리를 관통한 것으로 판정할 수 있었다. 이때 새 epoch의 마지막 승인 위치로 복귀하면서 접촉 부근의 되돌림이 생긴다.

### 작은 표면 오차의 고정 허용 폭 (2026-10-31, 로컬 검증)

PARK_V1은 위의 원래 캡슐/안전한 모서리 경로 검사와 1mm CONTACT_HELD가 실패한 경우 `PositionCollision.clearContact`를 추가로 확인한다. 원래 캡슐의 바깥 3cm만 접촉 오차로 두고, 반지름을 3cm 줄인 내부 캡슐의 **시작점·끝점 비침투와 전체 이동 선분 sweep**를 모두 통과해야 한다. 수영 경로에서도 기존 수면·속도 검사를 통과한 후에만 같은 오차 검사를 사용할 수 있다. strict 프로필과 서버 자동 따라가기 물리는 바꾸지 않는다.

승인한 작은 접촉에서는 새 epoch를 만들지 않으므로 프론트의 물리 위치·수직속도를 초기화하지 않는다. 시설·테이블·거리 제한 기능은 기존처럼 서버 승인 좌표를 사용한다. 외곽 3cm 이내에서는 원래 캡슐이 표면과 약간 겹칠 수 있다는 제한을 허용하며, 추가 native 조회 비용은 측정하지 않았다. 메시지·FE 제품 코드·물리 선택값·맵·DB 스키마 변경은 없다.

### 연속 점프의 착지 구분과 울타리 옆면 접지 (2026-10-31, 로컬 검증)

연속 점프에서는 이전 Flight가 끝나기 전에 새 착지·점프가 한 보고에 담길 수 있다. PARK_V1 검증은 새 jump 표식과 서버가 확인한 시작점 지지 또는 내려오는 끝점 지지가 있고, 이전 상승 점프가150ms를 넘겼을 때 새 Flight를 만든다. 수동 낙하 기록(speed=0)과 Flight가 없는 경우도 서버 지지가 필요하다. 새 착지는 이전 점프의 높이 상한을 재사용하거나 그 점프의 착지 처리로 지우지 않는다. 공중의 jump 표식만으로 상한을 재충전하지 않으며, 올라가는 목적지에만 높은 발판이 있다는 주장도 새 점프의 근거로 삼지 않는다.

Rapier의 computedGrounded가 true여도 접촉 법선이 거의 수평인 울타리 옆면만 닿은 경우가 있었다. PredictionPhysics.stepTuned는 실제 보행 가능한 접촉/계단이 없고 옆면 접촉만 있는 경우 발밑의 짧은 ray로 지지면을 확인한다. 이때 실제 바닥이 없으면 접지를 해제해 옆면에서 추가 점프하거나 중력이 초기화되는 것을 막는다. 벽과 바닥에 함께 닿은 정상 이동·기존 자동 단차0.22m·조작 선택값은 유지한다. 조건부 ray 조회 비용은 미측정이다.

새 메시지/필드·맵·DB 변경은 없다. 기존 jump는 계속 점프 입력 표식이며 새 프로토콜을 추가하지 않는다. 실제 Rapier 연속 입력 궤적(전진/역전·계단 방향·울타리/벤치·서로 다른 점프 입력 주기)을 기존 선택 검사로 서버에 전달하고, 공중 재점프·높은 발판 주장·기존 충돌 회귀도 검사한다. 로컬 검증은 개발 서버 배포나 사용자 체감 재검수와 구분한다.

### 계단 진입 점프와 거절 후 복구 (2026-10-31, 로컬 검증)

양끝이 실제 지지면에 있고 기존 상승 Flight가150ms를 넘겼으며 지상 이동이 그 점프의 높이 상한을 넘기는 경우, 계단의 지지 이동은 이전 점프가 계속되는 것으로 보지 않는다. 상승 중 다음 발판 가까이를 스치기만 한 경우에는 진행 중인 점프를 지우지 않는다. 원래 지상 이동 높이/경로 검사는 그대로 적용한다. 착지 직전 승인한 jump 표식은 서버 시간으로150ms만 보관하며, 다음 보고에서 서버 시작 지지가 있고 지지면을 떠나는 상승에 한 번만 사용할 수 있다. 만료·보정 epoch 변경 때 폐기하며, 거절된 보고는 새 입력 시간을 저장하지 않는다.

마지막 계단에서 팔각정으로 넘어가는 보고는 마지막 승인 위치의 일반 점프8과 실제 출발 지점의 팔각정 점프8.6이 다를 수 있다. `PositionCollision.jumpSpeed(from,to)`는 시작 지지, 목적지 아래의 실제 서버 지지면, 수평 이동+.22m 이내 상승/최대.17m 하강, 해당 지지면까지의 검증된 캡슐 경로를 모두 확인할 때만 기존 팔각정 부스트를 선택한다. 점프 원점 높이는 그대로이며 클라이언트 속도/지지 주장이나 새 맵 값을 받지 않는다. 이동 예산·최종 점프 상한·관통 검사는 유지한다.

HOVER 거절에서 같은 공중 위치로만 매번 reset하면 낙하가 진행되지 못하고 거절이 반복될 수 있었다. 이때 기존 보고 만료와 같은 서버 지지면/검증된 대체 위치로 한 번 복구하고, 새 검증기의 무료 이동 예산을0으로 둔다. CLIENT_VALIDATED/PARK_V1은 유지한다. 일반적인 작은 충돌 거절에서 안전 지면으로 보내는 정책을 추가한 것은 아니다.

선택 궤적 검사는 기존44경로 외에 양쪽 계단 진입/왕복·점프 입력 주기/위상24경로를 추가한다. `TunedMovementValidatorTests`는 지지 계단 상승·착지 전 입력의1회 사용·만료/epoch 폐기, `UnifiedMovementTests`는 HOVER 복구 후 정상 이동과 무료 이동 차단을 검사한다. 키보드/마우스룩 단축키는 변경하지 않는다.
