## 규칙과 계약

숫자 104개 + 조커 2개. 타일마다 유일 ID. 첫 등록 30점이며 조커 역할값 포함. 등록 턴에는 기존 묶음 변경 금지.
공개 판의 모든 타일을 보존하고 손패에서 최소 1개 사용해야 한다. 서버는 전체 제안 판을 검증한 뒤 원자적으로 확정한다.
조커 역할은 `{id,color,number}`로 명시하며 회수 시 같은 색·숫자 손패 타일과 다른 묶음 내 즉시 재사용을 검증한다.

- `GAME_ACTION_SEND` input: `{kind:'draw'}` 또는 `{kind:'play',melds:Placed[][]}`.
- 공개: 조합·차례·시간·더미 수·각 손패 개수·등록·기권·최종 점수. 개인: 본인 `userId`, `tiles`.
- 서버 실패 시 확정 판은 보존. 초안은 클라이언트에만 존재한다. 새 버전·차례·경기 변경 시 초안 폐기.
- 게임 점수와 엽전은 분리. 공통 GameLifecycle/GameFinished/예약·정산 경로 재사용.
- 관전 핑은 기존 관전 권한/1초 간격/중복 이벤트 정책을 사용한다. `RUMMIKUB_SPECTATOR_PING_SEND`는 `gameId`, `eventId`, `basedOnVersion`, `meldIndex`(0~34)를 보낸다. 공개 조합 번호만 공유하며 서버 상태를 바꾸지 않는다.
- 선공: 1개씩 자동 추첨해 최고 숫자(조커는 14 취급)가 시작한다. 최고값 동점자는 무작위 선정. 추첨 타일을 모두 돌려놓고 다시 섞어 14개씩 배분한다. 추첨 결과를 공개하며 실물 타일 ID는 노출하지 않는다.
- 기본값: 60초, 시간 초과 시 미확정 초안 폐기·기존 판 유지·벌칙 3개 뽑기(더미 부족 시 남은 수만 지급). 정상 뽑기는 1개이다.
- 더미를 소진시킨 차례 뒤, 활동 참가자마다 한 차례씩 더 진행한다. 마지막 차례 중 타일을 내더라도 남은 차례를 초기화하지 않는다. 손패를 먼저 비우면 즉시 승리하며, 전원 마지막 차례 완료 시 최저 벌점 승리(동점 공동).
- 조커 최초 등록 허용, 잔여 조커 벌점 30. 하우스 룰 옵션은 이번 범위에 포함하지 않는다.
- 재접속은 같은 프로세스 메모리 판 복구. 종료 처리 후 30분까지 종료 판·중복 요청을 보관하고 이후 메모리 복구 기록을 제거한다. 영속 결과·정산은 공통 경로로 분리되며 서버 재시작 복원은 보장하지 않는다.

## 실행 및 사용자 확인

작업 위치는 `OnTop/rummikub-20261121`이다. 새 의존성 없이 동일 lockfile의 기존 node_modules를 개발용으로 연결했다.

프론트: `frontend/`에서 PowerShell로 실행한다.

```powershell
$env:API_PROXY_TARGET='http://127.0.0.1:19464'
pnpm exec vite --mode park-renewal-integration --host 127.0.0.1 --port 5544 --strictPort
```

백엔드: `backend/`에서 `./gradlew.bat aiLabClasspath --offline`로 test classpath를 만든다.
실행 중 검수 서버는 `java @build/rummikub-park.args`이며, 이 build 파일은 classpath와
`com.ssafy.ontop.demo.RummikubParkApplication`을 지정한다. 운영 JAR에 이 fixture는 포함되지 않는다.
서버 포트는 19464, 필요 시 Java 시스템 속성 `-Drummikub.port=포트`로 실행 시 지정한다.
기존 서버·포트·환경 설정 파일을 수정하지 않았다.

- A: `http://127.0.0.1:5544/rummikub-park.html?role=red`
- B: `http://127.0.0.1:5544/rummikub-park.html?role=green`
- 관전: 같은 경로의 `role=viewer`.
- 독립 UI: `http://127.0.0.1:5544/rummikub-preview.html` (로컬 상태만 사용).

각 계정은 별도 브라우저 프로필/시크릿 세션을 권장한다. 링크의 role로 로컬 fixture에 로그인하며 비밀번호·토큰은 URL에 포함하지 않는다.
두 계정 모두 자동으로 channel-1에 입장한다. `1번 테이블로 이동` → E로 착석 → 수패마루/인원/판돈 확정 → 각자 금액 확인/준비 → 방장 시작.
관전은 테이블 앞에서 E로 진입한다. 실제 운영 로그인·운영 DB를 사용하는 링크가 아니다.

## 수패마루 테이블 표시·기권 잔해 보완
