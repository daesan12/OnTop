# 외부 서비스 정보

온탑(`on-top.world`)의 실행·배포에 사용하는 외부 서비스와 가입·설정 정보를 정리합니다.

## 1. Secret 작성 원칙

**이 문서와 Git 저장소에는 실제 Secret을 작성하지 않습니다.**

- 금지: API Key, OAuth Client Secret, JWT·암호화 키, DB 비밀번호, Vercel·Docker Hub 토큰, Mattermost Webhook 전체 URL, PEM 개인키
- 허용: 공개 도메인, Redirect URI, 리전, 환경변수 이름, 발급·설정 절차
- 실제 값은 평가 담당자에게 별도 보안 채널로 전달하고, 임시 토큰은 평가 후 폐기합니다.
- 프론트 `VITE_*` 값은 번들에서 누구나 볼 수 있으므로 Secret을 넣지 않습니다.

## 3. OAuth

### 3.1 SSAFY OAuth

| 항목 | 값 |
| --- | --- |
| 발급처 | `https://project.ssafy.com` 오픈 API(OAuth) 신청 |
| 인가 | `https://project.ssafy.com/oauth/sso-check` |
| 토큰 | `https://project.ssafy.com/ssafy/oauth2/token` |
| 프로필 | `https://project.ssafy.com/ssafy/resources/userInfo` |
| 운영 Redirect URI | `https://www.on-top.world/api/v1/auth/ssafy/callback` |
| DEV Redirect URI | `https://dev.on-top.world/api/v1/auth/ssafy/callback` |
| 로컬 Redirect URI | `http://localhost:8080/api/v1/auth/ssafy/callback` |

```dotenv
SSAFY_CLIENT_ID=<별도 전달>
SSAFY_CLIENT_SECRET=<별도 전달>
SSAFY_REDIRECT_URI=<환경별 Redirect URI>
```

### 3.2 네이버 로그인

네이버 개발자센터(`https://developers.naver.com`)에서 애플리케이션을 등록하고 네이버 로그인을 활성화합니다.

```dotenv
NAVER_CLIENT_ID=<별도 전달>
NAVER_CLIENT_SECRET=<별도 전달>
NAVER_REDIRECT_URI=<환경별 Redirect URI>
```

공급자에 등록한 Redirect URI와 서버 값은 글자 하나까지 같아야 합니다. 로그인 시작과 콜백은 같은 FE 호스트의 `/api` 경로를 사용해야 OAuth state 세션이 유지됩니다.

## 4. AI·알림

### 4.1 OpenAI API

- 가입·키 발급: `https://platform.openai.com`
- ChatGPT 구독과 API 사용량 결제는 별개입니다.
- 키는 백엔드 `app.env` 또는 로컬 프로세스 환경에만 넣습니다.

```dotenv
AI_ENABLED=true
OPENAI_API_KEY=<별도 전달>
AI_LLM_MODEL=<승인 모델명>
AI_JOKE_LLM_MODEL=<아재개그 전용 승인 모델명>
```

### 4.2 Jev

지원받은 Jev API Key와 승인 모델명을 사용합니다. 실제 키가 없으면 해당 어댑터를 끄고 규칙 기반 대체 동작으로 검수합니다.

```dotenv
AI_JEV_ENABLED=true
JEV_API_KEY=<별도 전달>
JEV_MODEL=jev-1.14.0
```

### 4.3 Mattermost Webhook

Mattermost 채널의 Integration에서 Incoming Webhook을 발급합니다. 전체 URL은 토큰이므로 Git·Jira·채팅에 복사하지 않습니다.

```dotenv
AI_MM_ENABLED=true
AI_MM_WEBHOOK=<별도 전달>
```

### 4.4 Rapfi

Rapfi는 외부 API가 아니라 서버에 설치하는 로컬 오목 엔진입니다. 검증한 Linux 릴리스를 호스트에 두고 `infra/app/compose.rapfi.yaml`로 read-only 마운트합니다.

```dotenv
# deploy.env
RAPFI_HOST_DIR=/opt/ontop/rapfi/<검증 버전>
```

컨테이너의 `AI_RAPFI_PATH`는 Compose 오버레이가 설정합니다.

## 5. AWS

리전은 서울(`ap-northeast-2`)입니다.

### 5.1 EC2

| 서버 | 역할 |
| --- | --- |
| PROD-APP | Spring Boot + Nginx, `api.on-top.world` |
| PROD-DB | MySQL + 암호화 EBS, WireGuard 내부 3306 |
| DEV-CI | Jenkins + DEV Spring Boot/Nginx/MySQL |

키 페어의 `.pem`은 저장소 밖에 보관합니다. SSH 22는 관리자 IP만, 서비스는 80/443만 허용하며 PROD-DB의 3306은 공개하지 않습니다.

### 5.2 S3 운영 DB 백업

- 비공개 버킷, 퍼블릭 액세스 차단, SSE-S3 암호화, 버전 관리
- PROD-DB EC2 IAM 역할에 백업 prefix의 Put/Get/List 최소 권한만 부여
- `/etc/ontop/prod-db/compose.env`의 `BACKUP_S3_URI=s3://<별도 전달>/ontop/prod-db`
- 매일 03:00 KST에 gzip 덤프와 SHA-256 업로드

### 5.3 S3 + CloudFront 스킨·공지 이미지

환경별 비공개 S3 버킷과 CloudFront OAC를 사용합니다. 브라우저 업로드는 5분 Presigned PUT, 공개 조회는 CloudFront의 `published/` 경로만 허용합니다.

```dotenv
SKIN_ASSET_BUCKET=<환경별 별도 전달>
SKIN_ASSET_REGION=ap-northeast-2
SKIN_ASSET_CDN_BASE_URL=<환경별 CloudFront URL>
SKIN_UPLOAD_URL_TTL_SECONDS=300
```

공지 이미지는 `ENTRY_NEWS_ASSET_*`가 없으면 같은 스킨 저장소 설정을 재사용합니다. AWS 장기 Access Key를 프론트에 넣지 않으며 백엔드는 EC2 IAM 역할의 기본 자격 증명 체인을 사용합니다.

## 6. Vercel

| 환경 | 프로젝트 | 도메인 | 설정 파일 |
| --- | --- | --- | --- |
| PROD | `ontop-frontend` | `www.on-top.world` | `frontend/vercel.json` |
| DEV | `ontop-frontend-dev` | `dev.on-top.world` | `frontend/vercel.dev.json` |

빌드는 Node 24, pnpm 11.25.0, `pnpm run build:park`, 출력 `dist-park`입니다.

```dotenv
VERCEL_TOKEN=<별도 전달>
VERCEL_ORG_ID=<별도 전달>
VERCEL_PROJECT_ID=<환경별 별도 전달>
```

## 7. Docker Hub

- 비공개 저장소: `wooaw/ontop-backend`
- Jenkins: Read & Write PAT
- 서버: Read-only PAT
- PAT는 Docker 자격 증명 저장소에만 보관하고 문서에 기록하지 않습니다.

Docker Hub 사용이 불가능한 경우 동일 SHA의 이미지를 `docker save`로 내보내 SSH 전송 후 `docker load`하며 digest를 기록합니다.

## 8. 도메인·HTTPS

| 레코드 | 대상 |
| --- | --- |
| `@`, `www` | Vercel PROD |
| `dev` | Vercel DEV |
| `api` | PROD-APP |
| `dev-api`, `ci` | DEV-CI |

가비아 DNS 관리툴을 사용합니다. API와 CI 인증서는 Certbot webroot 방식의 Let's Encrypt 인증서이며 자동 갱신 훅이 Nginx에 반영합니다.

| 서비스 | 용도 | 실행 필수 여부 |

에셋 출처와 라이선스는 `frontend/docs/ASSET_CREDITS.md`를 확인합니다.

실제 Secret 없이도 키가 필요 없는 기능과 로컬 대체 모드로 기본 빌드·UI 검수는 가능합니다. 외부 연동 기능은 실행 환경에 필요한 값을 주입한 뒤 앱 컨테이너 또는 프론트 번들을 새로 빌드·배포해야 합니다.
