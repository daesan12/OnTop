# OnTop 포팅 매뉴얼

## 1. 시스템 개요

OnTop은 React 기반 3D 공원 프론트엔드와 Spring Boot 기반 REST·WebSocket 백엔드, MySQL로 구성됩니다. 프론트는 Vercel, 백엔드는 AWS EC2의 Docker Compose, 운영 DB는 별도 EC2에서 실행됩니다.

| 환경 | 공개 주소 | 역할 |
| --- | --- | --- |
| PROD FE | `https://www.on-top.world` | Vercel 운영 프론트 |
| PROD API | `https://api.on-top.world` | Nginx → Spring Boot |
| DEV FE | `https://dev.on-top.world` | Vercel 개발 프론트 |
| DEV API | `https://dev-api.on-top.world` | Nginx → Spring Boot |
| Jenkins | `https://ci.on-top.world` | 빌드·테스트·DEV 배포 |

운영 DB의 3306 포트와 앱의 8080 포트는 인터넷에 공개하지 않습니다. PROD-APP은 WireGuard 내부 주소로 PROD-DB에 접속합니다.

## 4. 소스 클론 및 로컬 빌드

```bash
git clone https://lab.ssafy.com/s15-final/S15P31B105.git
cd S15P31B105
```

### 4.1 백엔드

Linux/macOS:

```bash
cd backend
chmod +x gradlew
./gradlew test
./gradlew bootJar
```

Windows PowerShell:

```powershell
cd backend
.\gradlew.bat test
.\gradlew.bat bootJar
```

Docker 이미지:

```bash
docker build -t ontop-backend:local backend
```

런타임 이미지는 `eclipse-temurin:21-jre-jammy`이며 Bullet/Rapfi 네이티브 실행에 필요한 `libstdc++6`, `libatomic1`을 포함합니다.

### 4.2 프론트엔드

```bash
corepack enable
cd frontend
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm test
pnpm run build:park
```

결과물은 `frontend/dist-park/`에 생성됩니다. `build:park`는 공원 맵·점프맵 코스·룰북을 다시 생성하므로 생성 파일 차이가 남는지 확인합니다.

## 5. 환경변수와 Secret

실제 환경 파일은 Git 밖에 둡니다.

| 환경 | 앱 설정 | 배포 설정 |
| --- | --- | --- |
| DEV | `/etc/ontop/dev-app/app.env` | `/etc/ontop/dev-app/deploy.env` |
| PROD | `/etc/ontop/prod-app/app.env` | `/etc/ontop/prod-app/deploy.env` |

템플릿은 다음 파일을 사용합니다.

- 공통 로컬: `.env.example`, `frontend/.env.example`
- DEV: `infra/app/dev.app.env.example`, `infra/app/dev.deploy.env.example`
- PROD: `infra/app/prod.app.env.example`, `infra/app/prod.deploy.env.example`
- AI: `infra/app/ai.app.env.example`
- 모니터링: `infra/monitoring/{dev,prod}/.env.example`

### 5.1 반드시 별도 전달할 Secret

| 값 | 용도 |
| --- | --- |
| `AUTH_JWT_SECRET_BASE64` | Access/Refresh JWT 서명 |
| `SSAFY_CLIENT_SECRET`, `NAVER_CLIENT_SECRET` | OAuth |
| `OPENAI_API_KEY`, `JEV_API_KEY` | AI 공급자 호출 |
| `AI_MM_WEBHOOK` | 운영 알림 채널 |
| `NOTES_PRIVACY_SECRET`, `EVENT_CONTACT_KEYS` | 개인정보 암호화 |
| DB 비밀번호 파일 | MySQL 앱·관리 계정 |
| `VERCEL_TOKEN` | Vercel 배포 |
| Docker Hub PAT | 이미지 push/pull |
| PEM 개인키 | EC2 SSH |

문서나 `.env.example`에는 실제 값을 넣지 않습니다. `VITE_*`는 브라우저 번들에 공개되므로 비밀값을 절대 사용하지 않습니다.

### 5.2 주요 비밀이 아닌 설정

| 변수 | 설명 |
| --- | --- |
| `DB_URL`, `DB_USERNAME` | DB 주소·사용자 |
| `AUTH_ALLOWED_ORIGINS` | FE 허용 Origin |
| `AUTH_FRONTEND_CALLBACK_URI` | 로그인 완료 FE 주소 |
| `WORLD_MAP_SOURCE`, `WORLD_MAP_*_PATH`, `WORLD_MAP_REQUIRE_MATCH` | 서버 맵과 버전 검사 |
| `PARK_MAP_HOST_DIR` | 호스트에 스테이징한 불변 맵 디렉터리 |
| `RAPFI_HOST_DIR` | Rapfi 배포 디렉터리 |
| `*_ENABLED` | 게임·상점·AI·운영 기능 플래그 |
| `ADMIN_*_IDS` | 내부 회원 ID 기반 관리자 범위 |
| `SKIN_ASSET_BUCKET`, `SKIN_ASSET_REGION`, `SKIN_ASSET_CDN_BASE_URL` | 스킨 저장소·CDN |

## 6. DB 구성과 복원

### 6.1 접속 정보

| 환경 | DB / 사용자 | 접속 경로 |
| --- | --- | --- |
| DEV | `ontop_dev` / `ontop_dev` | Compose 내부 `mysql:3306`; 외부는 SSH 터널만 사용 |
| PROD | `ontop` / `ontop_app` | PROD-APP에서 WireGuard `10.77.0.1:3306`; 공개 3306 없음 |

비밀번호는 Compose secret 파일로 공급합니다. DataGrip도 서버 3306을 공개하지 않고 SSH 터널을 통해 접속합니다.

### 6.2 덤프 검증

```bash
cd exec/db-dumps
sha256sum -c ontop-dev-20261118T043852Z.sql.gz.sha256
sha256sum -c ontop-prod-20261118T043911Z.sql.gz.sha256
gzip -t ontop-dev-20261118T043852Z.sql.gz
gzip -t ontop-prod-20261118T043911Z.sql.gz
```

체크섬 파일에는 생성 서버의 절대 경로가 함께 기록될 수 있으므로, 다른 경로에서는 첫 번째 해시 값과 `sha256sum <파일>` 결과를 비교해도 됩니다.

### 6.3 로컬 MySQL 복원 예시

기존 공용 DB를 덮어쓰지 말고 격리된 MySQL에 복원합니다.

```bash
docker run -d --name ontop-restore \
  -e MYSQL_ROOT_PASSWORD='<별도 전달>' \
  -p 127.0.0.1:13306:3306 mysql:8.4.11

gzip -dc exec/db-dumps/ontop-dev-20261118T043852Z.sql.gz \
  | mysql -h 127.0.0.1 -P 13306 -u root -p
```

PROD 파일은 `ontop`, DEV 파일은 `ontop_dev` 데이터베이스를 포함합니다.

### 6.4 Flyway·ERD 관련 파일

- 공통 마이그레이션: `backend/src/main/resources/db/migration/`
- 미니게임: `backend/src/main/resources/db/minigame/`
- 상점·스킨: `backend/src/main/resources/db/shop/`
- JPA Entity: `backend/src/main/java/com/ssafy/ontop/**/domain/`
- 연결 설정: `backend/src/main/resources/application.yml`, `application-dev.yml`, `application-prod.yml`
- Compose 계정·DB명: `infra/app/compose.dev.yaml`, `infra/prod-db/compose.yaml`

Flyway 이력이 있는 DB에서는 기존 SQL을 수정하거나 `repair`, `outOfOrder`, 볼륨 초기화를 임의 실행하지 않습니다.

## 7. 서버 배포

### 7.1 DEV 백엔드

```bash
sudo docker compose \
  --env-file /etc/ontop/dev-app/deploy.env \
  -f infra/app/compose.dev.yaml \
  -f infra/app/compose.generated-map.yaml \
  -f infra/app/compose.rapfi.yaml \
  config --quiet

sudo docker compose \
  --env-file /etc/ontop/dev-app/deploy.env \
  -f infra/app/compose.dev.yaml \
  -f infra/app/compose.generated-map.yaml \
  -f infra/app/compose.rapfi.yaml \
  up -d --force-recreate app nginx
```

협동 꼬치왕·모니터링 등 환경별 오버레이는 실제 서버에서 사용 중인 파일을 기존 명령에 추가하고 누락하지 않습니다.

### 7.2 PROD 백엔드

1. DB 덤프·체크섬과 현재 이미지·환경 파일을 백업합니다.
2. 승인된 동일 Git SHA로 이미지를 빌드합니다.
3. `deploy.env`의 불변 이미지 태그, `PARK_MAP_HOST_DIR`, `RAPFI_HOST_DIR`를 확인합니다.
4. 운영에서 사용 중인 모든 Compose 파일을 유지해 앱을 재생성합니다.
5. 앱 `healthy` 확인 후 Nginx를 재생성하고 외부 health를 확인합니다.

```bash
sudo docker compose \
  --env-file /etc/ontop/prod-app/deploy.env \
  -f infra/app/compose.prod.yaml \
  -f infra/app/compose.generated-map.yaml \
  -f infra/app/compose.rapfi.yaml \
  config --quiet
```

환경변수 변경은 `docker compose restart`가 아니라 `up -d --force-recreate app`으로 반영합니다. Docker Hub를 사용할 수 없을 때는 승인 이미지를 `docker save` → SSH 전송 → `docker load`로 옮기되 digest를 기록합니다.

### 7.3 프론트엔드

- DEV Vercel 프로젝트: `ontop-frontend-dev`, 설정 `frontend/vercel.dev.json`
- PROD Vercel 프로젝트: `ontop-frontend`, 설정 `frontend/vercel.json`
- Node 24, pnpm 11.25.0, `pnpm run build:park`, 출력 `dist-park`

Vercel Production 환경변수 변경 후에는 기존 번들이 바뀌지 않으므로 새 빌드·배포가 필요합니다. 백엔드와 동일 Git SHA의 프론트를 게시합니다.

## 8. 배포 시 특이사항

1. **맵 원자성:** `server-map.json`과 `manifest.json`을 같은 커밋·같은 `mapVersion` 세트로 스테이징합니다. FE·BE `mapId`, `schemaVersion`, `mapVersion`이 모두 일치해야 합니다.
2. **Windows 압축 금지:** Windows `tar`가 한글 자산 경로를 누락한 이력이 있으므로 Linux 빌드 산출물 또는 Git checkout 기반 빌드를 사용합니다.
3. **CRLF:** 셸 스크립트는 LF를 유지합니다. `gradlew`는 Dockerfile에서 CRLF를 제거하지만 다른 `.sh`는 별도 확인합니다.
4. **네이티브 라이브러리:** 앱은 read-only 컨테이너이며 Bullet은 실행 가능한 `/run/ontop-native` tmpfs가 필요합니다.
5. **Rapfi:** 서버 OS와 맞는 검증 바이너리를 호스트에 설치하고 `compose.rapfi.yaml`로 read-only 마운트합니다.
6. **DB:** 배포 전 백업, Flyway 성공 이력 확인, 운영 중 `down -v` 금지.
7. **로그·자원:** 배포 후 컨테이너 재시작 횟수, CPU·메모리, Nginx 4xx/5xx, WebSocket 연결을 확인합니다.

```bash

```

- OAuth 로그인·갱신·로그아웃
- 공원 입장, `WORLD_MAP_CONFIRM`, 이동·재접속
- WebSocket 연결과 채널 입장
- 테이블 착석·준비·게임 시작·종료·정산
- 미니게임·랭킹·상점·뽑기·옷장·마이룸
- 관리자 기능과 행동 로그
- FE·BE 맵 버전 및 Flyway 성공 이력

문제 발생 시 직전 정상 이미지·프론트 배포·환경 파일·맵 세트를 함께 되돌립니다. DB 마이그레이션은 임의로 되돌리지 않고 백업과 별도 복구 절차를 사용합니다.
