# 태블릿 실제 서버 검수 순서

2026-10-27 · 실제 서버의 다중 계정 검수는 사용자가 직접 진행한다. 아래 항목은 추가 BE 개발 요청이 아니라 확정 명세에 대한 공동 확인 항목이다. 일반 실행·빌드에서 착석 시 태블릿을 기본 표시한다.

## 접속

```powershell
# 프로젝트 frontend 폴더에서 실행한다.
# BE가 기본 http://127.0.0.1:8080 이외의 주소라면 기존 주소를 지정한다.
$env:API_PROXY_TARGET = 'https://<테스트 BE 주소>'
pnpm dev
```

기본 로컬 BE를 사용한다면 환경변수 지정 없이 `pnpm dev`를 실행한다. 터미널에 표시된 localhost 주소(기본 `http://localhost:5173/park`)에서 기존 로그인으로 접속한다. 서로 다른 계정은 별도 브라우저 프로필/브라우저를 사용한다. 기존 소셜 로그인·API·RawWS `/ws/tables` 연결을 그대로 사용하며 가짜 로그인이나 지급 기능을 추가하지 않았다. 이전 검수 주소가 필요하면 `pnpm dev:tablet`의 `http://localhost:5203/park`도 계속 사용할 수 있다.

로그인 콜백이 다른 포트로 이동하거나 인증 origin이 거절되면 현재 BE의 허용 origin 및 프론트 콜백 주소를 담당자에게 확인한다. FE에서 인증을 우회하거나 BE 환경변수를 변경하지 않는다. 기존 환경에 `VITE_TABLET_LOBBY=false`가 지정되어 있으면 AUTO 호환 UI가 선택되므로, 태블릿 검수 환경에서는 해당 설정을 해제한다.

## 확인 항목

| 순서 | 조작 | 기대 결과 |
|---|---|---|
| 1 | 빈 테이블에 첫 계정 착석 | 태블릿 전원이 켜지고 첫 착석자가 방장. 설정 전 의자 두 개 |
| 2 | 오목/주사위 2인, 원카드/다리 2·3·4인을 각각 설정 | 설정한 게임·정원·판돈이 다른 계정에도 같음. 의자가 승인 정원에 맞게 표시됨 |
| 3 | 주사위 목표 2000/4000/6000을 각각 설정 | 준비 화면과 시작된 경기의 목표가 일치함 |
| 4 | 각 계정이 판돈 확인 후 준비 | 선택 정원이 채워지고 전원 준비해야 방장의 시작 버튼 활성화. 준비만으로 자동 시작하지 않음 |
| 5 | 전원 준비 후 한 계정 준비 취소 | 시작 버튼 비활성화, 서버 시간 취소 반영. 다시 전원 준비하면 새 2분 |
| 6 | 방장이 시작 | 서버 승인 이후 태블릿이 꺼지고 기존 게임 화면 연결. 중복 클릭으로 경기 중복 생성 없음 |
| 7 | 전원 준비 후 방장이 2분간 시작하지 않음 | 서버가 방장 좌석만 해제하고 남은 착석자 중 새 방장 선정. 공원/로그인 연결 유지, 남은 준비 해제, 선택 정원 유지 |
| 8 | 제한시간 중 새로고침/잠시 연결 끊김 후 복귀 | 동일 로그인 세션의 30초 유예 내 복귀는 서버 상태를 따름. 만료 시각이 매번 2분으로 연장되지 않음 |
| 9 | 시작 응답이 불명확할 때 상태 확인 버튼 사용 | 조회로 승인 여부를 확인. 자동으로 새 시작 명령을 반복하지 않음 |
| 10 | 경기 종료 | 한지 결과 팝업에 실제 승패/참가자/정산 상태 표시. 정산 전 다음 판 진행 불가 |
| 11 | 정산 완료 후 다음 판 | 서버가 승자에게 방장 승계. 공동 승리/무승부는 남은 해당 후보 중 추첨. 다음 판에서 승계된 계정만 시작 가능 |
| 12 | 결과 확인 후 일어나기, 붕어빵 종료 | 실제 퇴장 승인 후 좌석 해제. 붕어빵 결과 팝업의 실제 지급/지갑 재조회 기능 유지 |

무효 경기·승자 부재·승자 이탈 시 방장 선정은 확정된 [BE 명세](../../docs/tablet-lobby-api.md)를 따른다. FE는 추첨·좌석 해제·잔액·정산 완료를 직접 만들지 않는다.

## 문제가 생기면

게임/정원/목표/판돈, 계정별 방장·준비 여부, 발생 시각(KST), 기대 결과와 실제 화면을 함께 기록한다. 개발자 도구에서 관련 메시지 이름과 오류 코드·`tableId`·`tableVersion`·`epoch`·`revision`을 확인할 수 있으면 첨부한다. 비밀번호·토큰·쿠키·접속권은 공유하지 않는다.

FE 표시/버튼/동기화 문제는 FE에서 보완한다. 서버 명령 거절·실제 120초 타이머·추첨·예약금/정산 문제는 확정 명세와 비교한 뒤 BE 담당자에게 전달하고, 이 브랜치에서 BE/DB/인프라를 수정하지 않는다.
