# 전망대 온탑 메모함 — FE 구현 및 BE 연동 요청

2026-10-28 작성 / 2026-10-29 정리. 이번 작업은 **frontend 경로만 수정**한다. BE 코드·DB·마이그레이션·인프라는 수정하지 않는다.

BE 담당자가 바로 진행할 항목만 모은 문서는 [소리함·메모함 BE 요청서](./handoff/TRADITIONAL_MAILBOX_BE_REQUEST_2026-10-29.md), 복사해 전달할 글은 [전달 메시지](./handoff/TRADITIONAL_MAILBOX_BE_MESSAGE_2026-10-29.md)를 참고한다.

## FE 완료 범위

- 기존 정상 좌표·E 대상·1.30 × 0.96 × 1.72m 충돌 영역을 유지한 기와 게시판, 등불, 꽃, 안내판, 지붕 위 새 에셋.
- E 진입 시 게시판이 확대되는 목록 화면. 전체/응원/일상/고민/추천/자유 필터, 페이지당 12장, 최근 120장.
- 별도 작성 화면, 원문 **300자** 제한, 한글 조합·붙여넣기·줄바꿈을 보존하는 실제 textarea와 커서를 따라가는 만년필.
- 저장 성공 응답 이후에만 종이를 접어 게시판에 붙이는 연출 → 완료 화면 → 메모함 복귀. 실패 시 원문·주제·재시도 키 보존.
- 2초 폴링 삭제. 가까이 접근 시 한 번 권한이 있는 GET으로 에셋용 메모를 조회하고 E 진입은 진행 중인 조회나 미사용 접근 조회 결과를 공유한다. 이후 다시 열기/사용자의 새로고침에서 조회한다. 본인 작성 성공은 POST 응답을 목록과 에셋에 병합하므로 추가 GET 없이 바로 갱신한다.
- 월드 에셋에는 실제 조회·작성 성공한 글 중 최신 6장만 표시한다. 예시 문구·기본 샘플 게시물은 없다. 에셋의 긴 문장은 최대 5줄 말줄임으로 보여주고 작성 화면 목록은 원문을 유지한다.
- `watchNotes()`는 서비스 생성 알림이 있을 때만 조회를 예약한다. 현재 운영 REST의 `subscribe()`는 기존대로 no-op이다. 다른 사용자의 새 글을 실시간으로 반영하려면 아래 BE 알림 계약 합의와 후속 FE 연결이 필요하다.
- 로컬 `pnpm dev:notes` → `http://127.0.0.1:5205/notes-preview.html`. 명시적 개발 모드의 메모리 목업이며 인증 HTTP/WS 전송·실제 저장은 없다.

## 1. 주제 저장·조회 요청

현재 BE의 `NoteSubmissionRequest`/`NoteResponse`에는 주제가 없다. 본문에 접두사를 끼워 넣거나 길이를 줄이지 않고, FE 도메인에 선택적 `category`를 준비했다.

제안하는 값:

| 값 | 표시 |
| --- | --- |
| `daily` | 일상 |
| `cheer` | 응원 |
| `worry` | 고민 |
| `recommend` | 추천 |
| `free` | 자유 |

POST `/api/v1/notes` 확장 예시:

```json
{"operationId":"1761436800000_0123456789abcdef","channelId":"channel-1","text":"오늘도 좋은 하루 보내세요!","category":"cheer"}
```

GET 목록의 각 메모와 POST 성공 응답의 `note`에 같은 `category`를 반환해주세요. 메모 필드는 `id`, `text`, `createdAt`, `category`로 제한하고 작성자 정보는 포함하지 않습니다. 기존 글/기존 클라이언트의 생략된 값은 `free`로 취급해주세요. 본문 1~300자, 정규화, 최신 120장, 작성 간격, 서버 근접·높이·활동 검증과 인증 정책은 유지해주세요.

멱등성 본문 digest와 동일 요청 충돌 검증에 category도 포함해주세요. 같은 operationId로 주제가 달라지면 충돌이며, 같은 본문·주제 재시도는 기존 접수 응답을 반환해야 합니다. FE는 주제가 바뀌면 새 요청 키를 발급합니다.

**호환성:** `VITE_NOTES_CATEGORIES` 기본값은 꺼짐입니다. 현 서버에는 기존 세 필드만 전송하고 선택 컨트롤은 준비 안내와 함께 비활성화합니다. 선택적 응답 category는 검증 후 읽을 수 있으며, 기존 글은 자유로 표시합니다. 로컬 목업에서는 모든 주제 동작을 확인할 수 있습니다. BE 구현·계약 검수 후 FE 빌드 환경에 `VITE_NOTES_CATEGORIES=true`를 설정하면 category 전송과 선택이 활성화됩니다. 활성화 시 POST ACK의 category가 요청과 일치해야 성공 연출을 시작합니다.

## 2. 다른 사용자의 작성 시점 갱신 알림 요청

정기 폴링을 다시 넣지 않고 **저장 커밋 성공 시점에만** 메모 목록 변경 알림을 보내주세요. 이벤트 이름·전달 채널은 BE와 합의가 필요하며 현재 FE는 임의의 WS 명령을 보내지 않습니다.

권장 최소 payload 예시(합의 전 제안):

```json
{"type":"NOTES_CHANGED","payload":{"revision":"1234"}}
```

- 메모 본문·작성자 ID·닉네임·IP·사용자 추적값을 이벤트에 담지 않습니다.
- 현재 전 채널 공용 게시판 범위에 맞춰 알림 범위를 정하고, 여러 서버 간에도 저장된 새 글을 구독자에게 알립니다.
- 같은 operationId의 ACK 재조회가 새로운 글 생성 이벤트를 반복 발생시키지 않도록 해주세요.
- FE 후속 연결: 합의된 이벤트를 `notesService.subscribe()`에 연결 → 열린 방문에서만 1초 조회 간격을 지켜 합쳐서 GET → 닫기/단절/거리 이탈 시 구독 해제. 작성 중인 원문·선택·커서를 유지하고 기존 메모 DOM은 지우지 않습니다.
- 연결 전 현재 동작: 본인 메모 즉시 반영, 다른 사용자의 글은 메모함 다시 열기/새로고침으로 반영. 실시간 다중 사용자 갱신이 구현되었다고 간주하지 않습니다.

## BE 담당자 전달용 요청 글

전망대 익명 메모함의 FE 디자인과 작성 연출을 반영했습니다. 2초 주기 폴링은 제거했고 본인 작성 결과는 성공 응답으로 즉시 목록에 반영합니다. 주제별 저장을 위해 기존 메모 POST·GET·작성 ACK에 `category(daily/cheer/worry/recommend/free)`를 추가하고, 기존 글은 free로 처리 부탁드립니다. 주제도 멱등성 비교에 포함해주세요. 다른 사용자가 메모를 작성한 순간에만 목록을 갱신할 수 있도록, 저장 커밋 이후 본문·작성자 정보 없는 변경 알림 이벤트도 부탁드립니다. 이벤트 명칭과 전달 경로를 합의하면 FE의 기존 구독 포트에 연결하겠습니다. FE 주제 전송은 현재 호환성을 위해 꺼두었으며, BE 검수 완료 후 `VITE_NOTES_CATEGORIES=true`로 활성화할 예정입니다. 자세한 요청·검수 항목은 이 문서를 확인해주세요.

## 함께 확인할 항목

1. 주제별 작성 → 재조회/새 세션/다른 사용자에서도 같은 주제 유지, 본문 300자 전체 사용 가능.
2. 기존 글과 기존 클라이언트의 free 기본값, 잘못된 주제의 업무 오류, 주제만 바뀐 동일 키의 충돌.
3. 저장 실패에는 생성 알림 없음, 응답 유실 후 같은 요청 재시도에는 중복 글·중복 생성 알림 없음.
4. 두 사용자가 목록을 열어도 유휴 GET 없음. 한 사용자가 작성하면 본인은 ACK 병합, 다른 사용자는 생성 이벤트로 목록 갱신.
5. 조회/작성 제한·인증·거리/높이 검사·익명 필드 제한·닫힌 방문 취소 유지.

로컬 자동 검증은 목업 및 HTTP 계약 대역 기반이며 실제 개발 BE 저장·이벤트 전파 검증을 대체하지 않습니다.
