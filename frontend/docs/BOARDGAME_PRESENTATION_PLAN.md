# 보드게임 판·에셋 표시와 시작 시점 기획

2026-10-27 KST 사용자 추가 요구사항. 기획 반영이며 런타임 구현 완료를 의미하지 않는다.

이번 오목 후속 구현에서는 선택 승인 시 빈 오목판·돌통 표시와 실제 시작 확정 후 고정 탑뷰 진입을 반영했다. 나머지 세 게임의 선택 후 에셋 표시 변경은 이 작업 범위에 포함하지 않는다.

원카드 후속 작업(2026-10-27): [원카드 UX 기획](../../docs/onecard-ux-plan.md)에 따라 원카드 선택 승인 후 매트·준비용 카드 뒷면 소품을 표시한다. 실제 손패·첫 바닥 카드는 시작 승인과 실제 GAME_STATE 이후에만 표시하며 준비 카메라를 유지한다. 원카드 모듈 외 게임의 위 범위는 유지한다.

## 선행 작업과 변경 우선순위

이 후속 작업은 아직 머지되지 않은 게임 진입·게임 선택·준비·수동 시작 선행 작업에 의존한다. 기준 흐름은 [태블릿 준비·결과 인계](TABLET_LOBBY_HANDOFF.md)의 사용자 확정 흐름이다.

- 선행 작업의 테이블 바인딩, 승인된 게임 선택, 참가 인원, 준비 상태, 방장 시작 권한과 실제 시작 확정을 사용한다.
- 선행 작업과 충돌하면 선행 작업을 유지하고 이 후속 작업의 코드·기획 연결을 선행 작업에 맞춘다. 이 요구사항 때문에 준비·시작 계약을 별도로 다시 만들지 않는다.
- 선행 문서의 "시작 확정 뒤 플레이 화면 표시"와 이번 "선택 후 판·소품 표시"는 구분한다. 준비 UI와 판·소품은 함께 존재할 수 있으며, 게임 조작과 플레이어 카메라 진입은 실제 시작 확정에 연결한다.
- 선행 작업 머지 후 선택→준비→수동 시작→플레이 전체 흐름을 다시 검증한다.

## 사용자 확정 요구사항

1. 사용자가 게임을 선택하고 해당 선택이 승인되면, 시작 버튼을 누르기 전부터 그 게임의 판과 소품이 해당 테이블 위에 나타난다. 경기 생성이나 최초 GAME_STATE 수신까지 기다리지 않는다.
2. 선택 요청 중이거나 거절된 선택은 표시 확정으로 취급하지 않는다. 승인된 선택이 바뀌면 이전 게임의 판·소품을 제거하고 새 게임의 판·소품으로 바꾼다.
3. 준비 중에는 선행 작업의 준비 화면·시점을 유지한다. 판·소품을 표시했다는 이유로 플레이어 시점으로 이동하거나 경기 조작을 활성화하지 않는다.
4. 방장이 시작을 누르고 서버가 실제 게임 시작을 확정하면, 선행 작업의 태블릿 종료 전환에 맞춰 해당 게임의 플레이어 시점으로 이동한다. 요청 중·거절·실패만으로 플레이어 시점에 진입하지 않는다.
5. 준비 중의 판·소품은 화면 표현이다. 이를 표시하기 위해 경기·손패·주사위 결과를 임의 생성하거나, 게임 시작·재화 예약·정산 명령을 추가 전송하지 않는다.

| 게임 | 선택 승인 후 테이블 표시 | 시작 확정 후 연결 |
| --- | --- | --- |
| 오목 | 빈 오목판과 돌통 등 게임 소품 | 실제 판·돌 배치·착수 입력, 게임별 플레이어 카메라 |
| 주사위 한 판 | 트레이·컵·주사위 소품. 준비용 배치는 실제 굴림 결과가 아님 | 실제 주사위 상태와 굴림·선택·확정 조작, 게임별 플레이어 카메라 |
| 원카드 | 매트·카드 뒷면 등 준비용 소품. 실제 손패·첫 바닥 카드를 미리 배분하지 않음 | 서버의 공개 카드·본인 손패·진행 상태, 게임별 플레이어 카메라 |
| 거짓말 다리 | 다리 게임판과 말 등 소품. 비밀 주사위 눈은 표시하지 않음 | 실제 말 위치·굴림·선언·판단 상태, 게임별 플레이어 카메라 |

게임별 카메라 구도·이동 경로·모션의 상세 수치는 이후 각 게임 기획에서 정한다. 이번 기획은 선택 시 표시와 시작 시 시점 전환의 경계를 확정한다.

## 현재 구현과의 차이

확인 기준: 로컬 `frontend-tablet-flow`, HEAD `15fd3df`의 프런트 소스.

- `src/game/bridge/BridgeBoard.tsx`: `game.bridge`가 없으면 반환하므로 선택·준비 단계에서 GLB 보드·말이 표시되지 않는다. 사용자가 확인한 "시작 후에야 나타남"과 일치하는 표시 조건이다.
- `src/game/onecard/OneCardBoard.tsx`: `game.onecard`가 없으면 반환한다. 경기 전 소품 표시가 별도로 필요하다.
- `src/game/OmokBoard.tsx`, `src/game/farkle/FarkleTable.tsx`: 일반 모드는 승인 선택으로 판을 표시할 수 있으나, `TABLET_ENABLED && !relevant` 조건은 경기 전 표시를 막는다.
- 표시용 준비 상태와 실제 경기 상태를 구분하여 연결해야 한다. 가짜 경기 스냅샷을 주입해서 판을 보이게 하지 않는다.

## 후속 구현·검수 항목

- FE: 승인된 테이블 선택으로 준비용 판·소품을 표시하고, 실제 경기 시작 시 같은 게임의 경기 표시·입력·카메라로 연결한다. GLB가 필요한 게임은 선택 단계에서 로딩을 시작하며 로딩 완료 때문에 준비 상태나 카메라가 바뀌면 안 된다.
- BE 연동: 선행 작업에서 확정한 테이블 선택·시작 상태를 사용한다. 추가 필드가 필요한지는 선행 계약과 대조한 뒤 정하며, 이번 문서에서 새 메시지나 API를 확정하지 않는다.
- 검수: 네 게임 각각 선택 승인→판·소품 표시→준비 중 시점 유지→수동 시작 요청→실제 시작 확정→플레이어 시점과 실제 경기 상태 연결을 확인한다.
- 선택 변경·거절, 시작 실패, 선택된 테이블의 상태 재수신, 에셋 로딩 지연에서도 잘못된 게임 소품이나 조기 시점 전환이 없는지 확인한다.
- 준비 중 실제 손패·비밀 눈을 생성·노출하지 않고, 시작 후 기존 공개/개인 정보와 서버 결과를 유지하는지 확인한다.
