수영 상태·속도·부력·높이와 충돌 계산은 계속 BE 승인 값이다. FE가 좌표를 예측하거나 이동 권한을 새로 만들지 않는다. 기존 착석/운동기구/망원경 고정 자세를 보존한다. 제안했던 좌표 이력과 그 전용 복구 임계값은 최종 코드에 포함하지 않는다.

### 한국 시간 계산 규칙

- 기준 시간대는 브라우저/기기의 로컬 설정과 무관하게 `Asia/Seoul`로 고정한다. 기준 시각은 한국 시간 2026-01-01 00:00이며 Unix ms로는 `1767193200000`이다(동일한 순간의 표기는 `2025-12-31T15:00:00Z`).
- 현재 시각과 서버 동기화 값은 동일한 순간을 나타내는 Unix ms를 사용한다. `Date.now()`나 서버 타임스탬프에 9시간을 더하지 않는다. 한국 시간 오프셋은 기준 시각의 `+09:00`에 이미 반영돼 있다.
- 위상은 `(현재 시각 - 한국 시간 기준 시각) mod 30분`으로 계산한다. 게임의 24시간이 실제 30분에 해당하며, 실제 한국 시각 12시에 반드시 게임 정오가 되는 24시간 실시간 주기로 바꾸는 작업은 아니다.
- 기존 기준과 한국 자정 기준의 차이 9시간은 30분 주기의 정확히 18배다. 따라서 이 시간대 명시·기준 시각 변경만으로 기존 낮밤 위상이 9시간 이동하지 않는다. 접속 시점 차이를 없앤 공통 타임라인은 유지된다.

## BE 요청과 실서버에서 남은 검수

1. 한국 시간 `Asia/Seoul` 기준 공통 월드 시각·기준 epoch·낮밤 주기와 재동기화 계약 필요. FE의 공통 KST 기준 보완은 기기 시계가 맞는 사용자 사이에서 입장 시점 차이를 제거한다. 기기 시계 오차·서버별 설정 변경까지 일치시키는 서버 동기화 완료를 뜻하지 않는다. 서버 현재 시각/epoch는 Unix ms로 전달하고 9시간을 중복 가산하지 않는다. 미정 메시지명/필드를 FE 운영 계약으로 추가하지 않았다.
2. 좌표 생성 시각 또는 물리 tick 식별자를 승인 WORLD_STATE에 제공할 수 있는지 협의. 현재 FE는 수신 시각으로 표시를 시작하므로 패킷 지연/묶음 전달을 완전히 복원할 수 없다. 실서버 기록에서 이력 보간 역효과를 확인해 기본 보간은 원본으로 유지했다. lastInputSeq는 수락한 입력 번호이며 물리 계산 완료 시각으로 쓰지 않는다.
3. 실제 서버에서 최소 입력 간격 50ms·입력 만료 250ms, 물리 30Hz·방송 약 100ms 설정을 확인하고 RTT/jitter/부하와 수신 간격·오류·물리 스텝 시간을 함께 측정해달라. FE 응답 대기는 제거했지만 TCP 묶음 전달에 따른 MOVE_TOO_FREQUENT나 BE 지연까지 해결했다고 주장하지 않는다. 값 확대나 물리 속도 변경은 이번에 요청하지 않는다.
4. 실제 개발 서버의 기존 배포본에서 한 계정으로 걷기·달리기 6회/입력 273개를 확인했다. 첫 이동의 rAF 공백 최대 358.2ms, FE Long Task 최대 340ms, 입력 공백 최대 432.4ms와 이동키 유지 중 moving=false가 관측됐다. 최종 FE 배포 후 동일 경로 검수와 두 계정·수영·점프·시설·고지연/부하 검수는 남아 있다. rAF FPS는 GPU 실행 시간/렌더 완료 FPS와 구분한다. FE 긴 작업과 BE 입력 만료/물리 로그를 함께 확인해야 한다.
5. 점프 수신/실행 시 접지 판정에 따른 입력 폐기 여부와 접지 보정 필요성을 확인해달라. 코요테 타임·착지 전 점프 버퍼는 프로토타입에서 확인된 기존 기능이 아닌 추가 개선 제안이며, 도입 여부·유예 시간·초기화 조건은 BE와 합의해야 한다. [점프 요청 상세](handoff/점프_입력지연_FE수정_BE요청_2026-10-26.md)를 따른다.
