# M07 — 지상 소리함 분리

## 2026-10-25 · 기존 인증 REST 연결

`feat/frontend-public-profiles`의 M03·M04 커밋을 유지하고 M07만 후속 연결한다.
BE 계약은 저장소 `docs/feedback-api.md` 기준이다. 일반 모드의 미연결 포트를
`POST /api/v1/feedback`으로 교체하며, `facility-preview`의 명시적 목업은 유지한다.

- 기존 Access JWT·401 갱신·요청 취소 경로를 재사용한다. payload에는
  `operationId`, `channelId`, 정규화 `text`만 넣고 FE 내부 userId/좌표는 보내지 않는다.
- 영수증의 ISO 시각을 ms로 변환해 표시한다. 유효한 접수 응답을 받기 전에는
  원문·동일 키·채널·요청 내용을 보존한다. 응답 유실 후 재시도로 새 키를 만들지 않는다.
- `429 FEEDBACK_COOLDOWN`의 서버 `nextAllowedAt`을 반영한다. 닫기·단절·재접속의
  취소/원문 보존과 인증 종료 시 삭제를 유지하고 늦은 응답은 무시한다.
- 공통 REST 허용 경로에 의견 POST만 추가한다. `403 FEEDBACK_OUT_OF_RANGE`는
  업무 거절로 표시하며 로그인 종료로 취급하지 않는다. 다른 경로와 인증/권한 오류의
  기존 종료 처리는 유지한다.
- 관리자 조회·공개 방송·브라우저 영구 저장·자동 재전송은 추가하지 않는다.
  미설정/저장 실패/거리/중복 키 충돌은 실패로 표시하며 목업 접수로 대체하지 않는다.
- FE 연결·로컬 계약 응답 검증과 실제 BE 배포·공유 DB 저장 검수는 구분한다.
  V120 등 Flyway 적용·활성화·관리자 설정은 FE 작업에서 변경하지 않는다.

검증: 앱/테스트 타입·빌드·경계 검사, 단위 342개 통과. Edge 1920×1080/390×844에서
일반 모드 19개 시나리오와 기존 미리보기 4개를 확인했다. 초기 붕어빵 회귀 검사는
슬롯 상태 조회에서 실패했으나, M07 이전 비교본과 최종 코드 모두 새 서버에서 한 판·정산을 통과했다.
붕어빵 소스/테스트는 변경하지 않았으며, 초기 실행 전체가 무실패였다는 뜻은 아니다.
인증 REST·영수증·중복 복구 검증은 로컬 계약 응답 기반이며 실제 공유 DB 저장 검수는 남아 있다.

이하 내용은 **2026-10-24 초기 분리 당시 기록**이다. 당시 “BE API 없음/일반 모드 전송 불가”는
현재 상태가 아니며, 위 REST 연결 내용이 우선한다. 실제 DB 저장 완료를 뜻하지 않는다.

## 2026-10-24 초기 분리 기록

2026-10-24. 기준 커밋 `f93e858`의 M00~M06 프론트에 소리함 작성·검증·요청 수명만 추가한다. 원본 혼합 작업은 보존하고 같은 `feat/frontend-m00-foundation` 브랜치에 별도 커밋으로 쌓는다. 머지·배포·M08은 진행하지 않는다.

## 작성과 요청 수명

기존 `TraditionalMailbox`와 `MAILBOX` 좌표·2.6m 반경을 사용한다. 지상 높이 0.8m ±0.7m에서 기존 공통 E 안내/버튼으로 연다. 시설·경기·수영·다른 패널 이용 중에는 진입하지 않는다. 작성창 안에서 포커스를 순환하고 한글 입력·줄바꿈을 유지하며 이동·점프·G·채팅·카메라 드래그/휠 입력을 차단한다. Esc/×/바깥 클릭으로 닫고 기존 입력으로 돌아간다.

원문 600자 상한 → NFC → 제어/서식 문자 제거 → trim → 5~600자 순으로 검증한다. 길이는 JavaScript 문자열 길이 기준이며 줄바꿈·탭은 유지한다. 실패 시 원문을 바꾸지 않는다.

제출 중 중복 클릭·편집을 막고 확인 응답 후에만 원문을 비운다. 실패·10초 타임아웃·응답 유실에는 원문과 동일 요청 키를 보존해 명시적으로 재시도한다. 정규화 본문을 바꾸면 새 요청 키를 사용한다. 닫기·원거리/높이 이동·맵 불일치·단절은 창과 대기를 정리하며 늦은 응답이 새 작성 내용을 지우지 못하게 한다.

같은 사용자·같은 채널의 자동 재접속에서는 원문/재시도 키를 보존한다. 명시적 채널 변경·공원 종료·인증 종료·다른 사용자 연결에서는 삭제한다. 현재 페이지 메모리에만 보관하며 새로고침·브라우저 종료 후 복원하지 않는다.

## BE 연결과 목업 경계

확인한 Java BE 코드에는 소리함 제출·관리자 조회 API가 없다. `features/feedback/contracts.ts`는 FE 내부 포트이며 REST 경로·WS 명령·관리자 권한을 추정하지 않는다.

- 일반 개발/운영 환경: 실제 작성 UI를 표시하고 전송 버튼은 비활성화한다. 서버 연결 준비 안내를 표시한다.
- `facility-preview`: 현재 페이지에 한정한 `MockFeedbackService`로 제출을 검수한다. 실제 관리자 전달·영구 저장이 아님을 화면과 완료 안내에 표시한다.
- 목업은 접수 메타데이터와 본문 SHA-256을 비공개 필드로 보관한다. 동일 사용자/요청 키와 같은 정규화 본문은 같은 접수 번호를 반환하며, 같은 키의 본문 변경은 거절한다. 성공 후 15초 제한은 개발용 정책이다.
- 의견 본문을 공개 세션·아바타·채팅·월드 메시지로 보내지 않는다. 목록/관리자 화면·공유 비밀번호를 이관하지 않는다. 운영 빌드에서 목업 구현 제외를 검사한다.

BE 연결 시 인증 사용자 귀속·서버 근접/활동 검증·정규화/길이 정책·저장 확인/거절·재시도 키의 원자성과 보존·제출 간격을 합의해야 한다. 관리자 인증/조회 권한·보존/삭제 정책도 필요하다. 현재 페이지 목업은 실제 서버의 영구 저장·다중 서버 중복 방지·관리자 권한 검수를 대신하지 않는다.

## 다른 작업 보존

공통 런타임·월드에는 소리함의 인증/채널/위치 변화 정리 훅만 추가한다. 기존 인증/API 오류 처리·프로필·RawWS·이동 형식/주기/보간·본인 제거 시 입력 차단·M04 코드 매핑과 손 인사/박수 목업 금지를 유지한다. M01~M06 시설 서비스·모델·카메라·입력 구현은 그대로 사용한다.

백엔드·인프라·맵/버전·배포 JSON·자산·의존성·잠금파일·Vite 설정·지갑·다른 M 변경은 포함하지 않는다. 원본 144개 변경/미추적 파일의 SHA-256·경로 집합·HEAD를 전후 비교한다.

## 검증

Browser plugin not available. 기존 Playwright/Edge 및 테스트 전용 HTTP/RawWS 계약 대역을 사용한다. `facility-preview`는 5196, 일반 모드는 외부 QA 설정으로 5198에서 실행하며 기존 개발 서버는 유지한다. 화면 증빙은 저장소 밖 `m07-isolated/`에 저장한다.

```sh
pnpm typecheck
pnpm typecheck:tests
pnpm test
pnpm build
pnpm check:migration
pnpm test:e2e:facilities
pnpm exec playwright test tests/e2e/park.spec.ts tests/e2e/omok.spec.ts tests/e2e/fitness-boundary.spec.ts tests/e2e/telescope-boundary.spec.ts tests/e2e/feedback-boundary.spec.ts
```

브라우저 검수는 기존 공원 → E 작성창 → 길이/입력 격리 → 실패 원문 보존 → 동일 키 재시도 → 접수 확인 후 비우기 → 이동 복구를 따른다. 응답 유실 시 같은 접수 번호 재사용, 닫기/단절 취소·재접속 원문 복원·인증 종료 삭제, 다른 페이지에 본문 미노출, 일반 모드 전송 차단을 확인한다. 데스크톱 1920×1080 및 작성창 390×844를 검사한다.

이 검증은 프론트 계약 대역·개발 목업 검증이며 실제 개발 서버 배포/BE 연동 완료를 의미하지 않는다. 기존 Three.Clock/ANGLE·큰 3D 청크 경고와 전체 HUD 모바일 재배치는 남아 있다.
