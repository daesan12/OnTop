## 동작

협동 요리사 VR의 인사 이벤트에서 제자리에서 한 바퀴 돌면 기존 `GREET`를 전송한다. 시계/반시계 방향 모두 인정한다. 전송 확인에 실패한 경우만 완료한 회전을 보존하고 카드의 트리거 선택으로 재시도할 수 있다. PC 요리사와 서빙 담당의 기존 G/버튼 인사는 유지한다. VR 요리사는 회전을 완료하기 전에 트리거·마우스·G로 회전 요구를 우회하지 않는다.

WebXR animation frame의 `getViewerPose(referenceSpace)` 자세를 사용한다. 가상 카메라나 스틱으로 돌린 각도를 사용하지 않는다. 헤드셋의 수평 방향을 연속적으로 풀어 순 회전량을 측정하며, 반대 방향으로 되돌아보면 차감한다. 단순 고개 좌우 흔들기나 위아래 보기로 완료되지 않는다. 별도 신체 추적기는 사용하지 않으므로 몸통 자체의 관절 회전을 측정하는 기능은 아니다.

진행률과 남은 인사 시간을 기존 인사 그림 패널에 표시하고, 실제 몰입형 세션에서는 패널을 시야 앞에 유지한다. 서버의 기존 5초 인사 제한·팀 점수·보상·타임아웃·실패 그림은 변경하지 않는다. 헤드셋에서 제자리 회전을 수행할 실제 공간과 착용 상태를 확인해야 한다.

일시정지, 입력 차단, 가이드, 숨겨진 세션, 추적 소실, reference-space reset, 긴 프레임 공백, 비정상 자세 점프는 진행 중 측정을 초기화한다. 같은 이벤트에서 완료한 인사는 자세가 다시 잡혀도 중복 전송하지 않는다. 이벤트/라운드 변경·세션 종료 시 측정을 분리하고 reset/visibility 리스너를 정리한다.

- 게임 코드: `SKEWER_COOP`. VR 대상은 요리사다. 신규 서빙 VR을 만들거나 점프맵의 조작을 변경하지 않았다.
- MR !437 반영: 역할/기기별 원래 일러스트, 서빙 준비 화면의 실제 게임 이미지, 준비 화면 하단 규격, 강조된 X와 중복 나가기 제거, 입구 문구 정리. MOVE/행동 직렬 전송·E 직전 정지 보존·복구 후 입력 재검사·방향 전환 및 ResizeObserver 보완도 기존 게임 경로에 함께 반영했다.

- 서버가 이미 제공하는 `greeting.index`, `greeting.remaining`을 내부 ChefView로 전달한다. FE/BE 메시지 구조와 BE 제품 코드는 변경하지 않는다.
- 공통 공원 맵·인증·카메라·WS 인프라·DB/Flyway 변경 없음. 신규 migration 없음.

## VR 일시정지 조작

- 협동 요리사 VR에서 오른손 B를 한 번 누르면 기존 서버 PAUSE 요청으로 게임을 함께 멈춘다. 다시 B를 누르거나 시야 앞 한지 패널의 계속하기를 검지 트리거로 선택하면 자신의 일시정지를 해제한다. 친구가 별도로 멈춘 상태는 유지한다.
- 주방의 ‘일시정지 · B’ 3D 버튼도 트리거로 선택할 수 있다. 계속하기·나가기·실패 시 일시정지 다시 시도를 헤드셋 안에서 선택한다. XR 중에는 DOM 확인 모달로 포커스를 이동하지 않는다.
- 요청 확인 전에는 ‘요청을 확인하고 있어요’로 표시하고 버튼·요리 입력을 차단한다. 실패하면 오류를 패널에 남겨 재시도하거나 계속하기를 선택할 수 있게 한다. 나가기는 기존 서버 기권/퇴장을 사용하며 중복 퇴장 실행을 막는다.
- B는 XR 표준 오른손 게임패드의 버튼 5를 사용한다. 계속 누르기는 반복 요청을 만들지 않으며 세션 진입·추적/포커스 복구·컨트롤러 교체 후에는 B를 놓은 다음 다시 눌러야 한다.
- 일시정지 중 인사 회전은 누적하지 않고 잡고 있던 재료와 꼬치를 정리한다. 기존 360도 인사·재시작·세션 종료 시 공원 복귀 계약을 유지한다.
- 좌/우 Touch 컨트롤러 도식은 1 검지 트리거, 2 옆면 그립, 3 오른손 B를 실제 위치와 연결선으로 표시한다. 주방 안내 이미지는 현재 요리대 이미지로 교체했다.
