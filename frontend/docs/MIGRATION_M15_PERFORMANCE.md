# M15 품질·성능 UI

## 범위와 원본 비교

- `feat/frontend-m15-manual-rulebooks`의 지도 커밋 `babd55e9a8588ae5e3ef2cdc4842acd3f178caf4` 다음 변경이다. 품질·성능 UI와 관련 프론트 연결·테스트·문서만 별도 커밋으로 분리해 같은 브랜치에 푸시하는 범위이며, MR·머지·배포는 포함하지 않는다.
- 원본 `topgoal/apps/web/src/App.tsx`의 F1 설명서 유틸리티 행을 이관했다. 기존 종이/두루마리 안에 현재 채널·인원, Low/Medium/High 선택, 나가기를 표시한다. 기존 OnTop 채널 응답과 로그아웃 콜백을 연결한다.
- 원본 최신 소스와 `MASTER_SPEC.md`의 2026-10-20 HUD 간소화 기록에서는 성능 패널을 제거하고 내부 측정기는 유지했다. 이번에는 **기존 OnTop 기능 유지 요청**에 맞춰 기존 `그래픽 · 성능` 버튼/필요할 때 여는 패널을 유지하고, 원본 F1 품질 조작을 추가했다. 전체 HUD를 원본처럼 제거하는 작업은 하지 않는다.
- 원본 `performance/metrics.ts`, `PerformanceProbe.tsx`, `AdaptiveResolution.tsx`, `resolutionBudget.ts`와 현재 소스의 동작은 이미 같아 재복사하거나 렌더 루프를 교체하지 않았다. 기존 프로브를 읽는 UI만 분리했다.
- 성능 패널에도 기존 설명서의 녹색·크림 종이 색을 적용했다. 첫 브라우저 검사에서 넓어진 패널이 상단 버튼 위치를 밀어 지도 버튼과 겹치는 문제를 발견해, 패널을 버튼 아래 독립 배치로 수정했다.

## 조작과 측정값

- F1 → 설명서 상단에서 품질 변경/채널 인원 확인/나가기. 품질은 공원 `그래픽 · 성능` 패널과 같은 React 상태를 사용한다. 초기값은 기존 Low이며 영구 저장 기능은 추가하지 않는다.
- 성능 패널에는 FPS, 프레임 간격 p95/p99/최대, 초기화 이후 프레임 수·50ms 초과 수, 드로우콜·삼각형 수, 형상·텍스처 **개수**, 실제 렌더 버퍼 해상도·DPR을 표시한다. 접힌 설명에는 기존 프로브가 제공한 GPU 이름과 측정 기준을 표시한다.
- FPS/분위수는 기존 최근 최대 600프레임 표본, 프레임 수/50ms 초과 수는 초기화 이후 누적이다. CPU/GPU 실행시간, 전체 메모리 사용량, RTT로 표기하지 않는다. 표본이 없으면 수집 중/대시를 표시한다.
- 품질 변경과 `측정 초기화`는 기존 프레임 표본을 비운다. 기존 렌더러 정보·현재 자원 수치를 초기화로 지우거나 실제 GPU 자원을 다시 만들지 않는다.
- UI는 열린 동안 1초마다 갱신하며 닫으면 타이머·visibility 리스너를 해제한다. 숨긴 탭에서는 UI 표본을 읽지 않고 일시 정지를 표시하며, 기존 `frameloop=never`/복귀 처리를 유지한다. 네트워크 소켓은 끊지 않는다.
- 설명서의 닫기/Tab 포커스, 채팅 초안·복귀, 지도 길 안내, 경기 중 F1, 기존 상단 나가기는 유지한다. 설명서 나가기는 동일한 `POST /api/v1/auth/logout` 흐름을 호출한다. 실패 표시는 기존 App 콜백/화면을 따른다.

## 유지한 렌더·통신 경계

| 품질 | 기존 최대 렌더 픽셀 예산 | DPR 상한 | 그림자 / shadow map |
| --- | --- | --- | --- |
| Low | 1280×720 | 1 | 끔 / 기존 512 설정 유지 |
| Medium | 1600×900 | 1 | 켬 / 1024 |
| High | 1920×1080 | 1 | 켬 / 1536 |

- 창 해상도/기기 DPR와 기존 자동 해상도 조절에 따라 실제 렌더 버퍼가 예산보다 작아질 수 있다. 정책·카메라·충돌/맵·그림자 주기·지형·LOD를 바꾸지 않았다.
- 클라이언트 개인 렌더 설정/진단이므로 새 REST·WS·서버 저장·운영 목업을 추가하지 않는다. 인증, 월드 이동 전송 간격, 테이블·게임·지갑 코드, BE/DB/Flyway/배포 설정은 변경하지 않는다.
- 새로운 이미지·GLB·폰트·텍스처·의존성은 없다. DOM/CSS UI여서 메시 병합·인스턴싱·LOD·KTX2/Meshopt 적용 대상이 아니며 기존 월드 자원의 정책을 유지한다. UI의 React 상태는 프레임 루프에서 갱신하지 않는다.

## 검증

- 앱/테스트 타입 검사, 배포용 빌드, migration boundary 검사 통과. 단위 검사 34파일/294개 통과. 표본 창/누적 값 구분, 리셋 시 기존 렌더 정보 보존, 기존 DPR 예산·자동 해상도 경계를 포함한다.
- 첫 전체 단위 실행에서 기존 `movement.test.ts`의 엄격한 실수 비교가 `0.999999999999999`와 `1` 차이로 1회 실패했다. 해당 기존 파일을 수정하지 않고 단독 9개와 전체 294개를 재실행해 통과했다.
- Browser plugin not available: 기존 프로젝트 Playwright/Edge, WebGL 2를 사용한다. HTTP/RawWS는 기존 계약 fixture이며 실제 개발 서버/다인원 DB 검증을 뜻하지 않는다.
- 최종 브라우저 회귀 23개(기존 설명서 9·지도 9·품질/성능 5) 모두 통과했다. 실제 프리셋 해상도/그림자 전환, 동일 카메라/소켓 유지, F1 품질 값 공유·채널 응답 인원 표시·채팅 초안/포커스 복귀·로그아웃, 오목 경기/기존 4종 게임 설명서, 지도 길 안내, 숨긴 탭 복귀, 반복 열기/닫기 시 UI 타이머 해제를 확인했다.
- 별도 시각 검수 1개와 실제 배포용 빌드 검수 1개도 통과했다. `/park`/OnTop 제목·실제 월드 렌더·오류 오버레이 부재·새 앱 오류 0, Low↔Medium 실제 버퍼 변경, F1 설정과 기존 로그아웃 요청→로그인 화면/소켓 종료를 확인했다. 개발 서버 배포는 하지 않았다.
- 1920×1080, 1280×720, 1000×700 PC 화면에서 버튼/설정 접근·Tab·설명서 유틸리티·긴 GPU 설명 스크롤, 실제 낮(daylight=1)/밤(night=1) 상태에서 가독성과 기존 월드 표시를 확인했다. 시각 검수 시계는 QA 파일 안에서만 고정하며 앱 시간 코드는 변경하지 않았다.

## UI 비용 관측

2026-10-25, Core Ultra 9 185H / Intel Arc 내장 GPU, Edge 156.0.4314.42/WebGL 2, Low, 1920×1080(렌더 버퍼 1280×720), 기존 계약 fixture 8명, 같은 카메라·정지 위치에서 각 2.5초를 관측했다. UI만 열고 닫으며 품질은 변경하지 않았다. QA 고정 시각에서 동영상 광고 슬롯을 피해 다른 자원 변동을 줄였다.

- 배포 산출물은 메인 JS 560.31→565.04kB(gzip 173.27→174.86kB), CSS 70.69→72.45kB(gzip 15.63→15.96kB)다. 표시 UI/설명 추가 비용이며 성능 최적화 달성을 의미하지 않는다. 기존 지도 worker는 같은 49.91kB/해시를 유지한다. 신규 시각 에셋 다운로드는 없다.

## 실행과 제한

`frontend`에서 `pnpm dev` → 기존 로그인/채널 입장 → 상단 `그래픽 · 성능` 또는 F1 설명서 → 품질 변경. 검사 명령은 `pnpm test`, `pnpm typecheck:tests`, `pnpm build`, `pnpm check:migration`, `pnpm test:e2e tests/e2e/performance.spec.ts tests/e2e/manual.spec.ts tests/e2e/navigation.spec.ts`다.

QA 스크립트·JSON·화면은 Git 밖 `m15-performance` 폴더에 보관한다. 외장 GPU·다른 브라우저·WebGPU·실제 개발 서버 배포는 이번 로컬 UI 확인에 포함하지 않는다. 기존 큰 청크/Three.Clock/Intel 셰이더 경고는 남아 있다. M15 전체 자산 최적화/전수 성능·시각 검수와 다음 M은 별도 작업이며 시작하지 않는다.
