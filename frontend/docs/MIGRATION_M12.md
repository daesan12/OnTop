# M12 원카드 이관

2026-10-24 원본 시각 보완: 원본 매트·덱 장식·탁자별 높이·카드 스타일/가로 손패를 현재 BE 계약과 패널에 적용했다. 변경·검수는 [M12 시각 보완](M12_VISUAL.md)을 따른다.

기준: 2026-10-24, M11 커밋 `d3d626d` 위의 FE 작업. 같은 `feat/frontend-m09-table-lobby` 브랜치에서 기존 로그인·인증·Spring HTTP/RawWS·이동·채팅·오목·Farkle·공통 로비/관전/결과를 유지한다. BE·인프라·맵·패키지/잠금파일은 수정하지 않는다. M13은 진행하지 않는다.

## 화면과 조작

- 공통 로비에서 ONE_CARD 선택·준비 활성화. 2~4인 공개 참가자·차례·장수·탈락/기권·방향·덱 장수·바닥 카드·유효 무늬·누적 공격·K 추가 행동을 표시한다.
- 본인 패만 별도 HUD로 표시하고 서버 `playableCardIds`에 있는 카드를 선택·제출한다. 패의 가능 여부·특수 효과를 FE 규칙 엔진으로 재판정하지 않는다.
- 일반 한 장 뽑고 넘기기, 누적 공격 수락, 7/조커 무늬 선택, 원카드 선언·다른 활성 참가자 신고를 기존 API로 연결한다. 대상은 좌석 숫자가 아닌 서버 `userId`다.
- 한 차례 전체 30초, 선언/신고 반응창은 별도 3초. 시간 경계에서 버튼을 막지만 로컬에서 드로우·벌칙·턴 변경·승패를 확정하지 않는다. K·무늬 선택·조회·재접속으로 서버 마감을 연장하지 않는다.
- 관전자는 공개 판과 장수만 보고 기존 공개 판/테이블 시점을 사용한다. 손패·개인 정산·제출·뽑기·선언/신고·기권 권한을 얻지 않는다.
- 결과·정산 조회와 서버 WAITING 후 다음 판/퇴장은 M09 공통 흐름을 유지한다. 정산 응답의 표시만 하며 잔액이나 지급을 FE에서 만들지 않는다.

## 실제 BE 연결

프로토타입의 세 파일 `OneCardPanel.tsx`, `OneCardBoard.tsx`, `presentation.ts`를 화면/연출 참고 자료로 사용한다. 통신과 실제 판정은 현 프로젝트 `docs/onecard.md`, `OneCardEngine`, `OneCardMatch`의 계약을 따른다. Colyseus·기존 프로토타입 서버·셔플 코드를 이식하지 않는다.

모든 행동은 기존 소켓 하나의 `GAME_ACTION_SEND {gameId,actionId,expectedVersion,input}`로 보낸다.

| 기능 | input |
| --- | --- |
| 제출 | `{kind:'play',cardId}` |
| 한 장 뽑기 | `{kind:'draw'}` |
| 공격 수락 | `{kind:'accept-attack'}` |
| 무늬 선택 | `{kind:'select-suit',suit:'hearts'|'diamonds'|'clubs'|'spades'}` |
| 선언 | `{kind:'declare-one'}` |
| 신고 | `{kind:'catch-one',targetUserId}` |

`GAME_STATE`의 공개/개인 상태는 **같은 version의 단일 응답**이다. 개인 상태에 별도 버전 필드를 임의로 요구하지 않는다. PLAYER는 `privateState.userId === 현재 사용자` 및 공개 `cardCount`와 패 길이 일치를 검사하며 알려진 필드만 복사한다. 소유하지 않은 `playableCardIds`, 중복 카드, 잘못된 카드 ID, 타인의 개인 상태를 거절한다. SPECTATOR는 privateState가 빈 객체일 때만 수용하며 손패를 보관하지 않는다.

복구 응답은 기존 오목/DICE의 평면 상태와 달리 `{publicState,privateState}`를 포함한다. 이 ONE_CARD 래퍼만 별도로 파싱해 서버에서 받은 본인 패·원래 차례·무늬 선택·마감을 복원한다. 재배분하지 않는다. 재접속 중·응답 불명·오류 형식·최신 버전 미수신 시 손패 표시/행동을 중지한다. 카드 선택도 사용자·채널·gameId·version이 바뀌면 무효다.

확인 응답 `GAME_ACTION_RESULT`만 먼저 오면 새로운 패를 추정하지 않고, GAME_STATE가 승인 버전까지 도착할 때까지 입력을 막는다. 거절/응답 소실 후 자동 재전송하지 않으며 기존 재조회/복구 버튼을 사용한다. FINISHED·ELIMINATED·비활성 참가자는 행동할 수 없다.

기존 단위 테스트의 미지원 게임 예시는 이제 지원하는 ONE_CARD에서 LIAR_BRIDGE로 바꿨다. 공통 로비 E2E도 원카드 준비 활성화와 아직 미지원인 다리 준비 차단을 각각 확인한다. 기존 오목/Farkle 판정과 결과는 바꾸지 않는다.

## 미구현 경계와 목업

원카드 제출·뽑기·공격·무늬·선언/신고·공개 판·개인 패·복구·결과 API는 이미 구현되어 있으므로 **원카드 목업 엔진·가짜 패·로컬 셔플·가짜 정산을 제품에 추가하지 않는다.**

- 수동 기권 공개 API는 아직 없으므로 M10의 공통 의사 확인 포트를 재사용한다. `DEV && MODE === 'facility-preview'`에서만 의사 확인 목업이며 실제 경기·좌석·지급을 바꾸지 않는다. 일반 개발/운영에서는 비활성 안내다. BE의 내부 graceExpired/기권 테스트 명령을 제품 API로 호출하지 않는다.
- 관전 가능한 공개 gameId 공급은 M09의 전용 개발 미리보기 포트만 재사용한다. GAME_WATCH 권한·거리·공개 스냅샷은 실제 기존 WS를 사용한다. 개발 서버 관전 거리 오류는 보류 범위로 유지하며 우회하지 않는다.
- ONE_CARD 서버 엔진 활성 설정과 정식 참가 차감·DB 정산·배포 상태는 BE/배포 환경의 책임이다. 소스의 기능 존재를 현재 개발 서버 설정 완료로 해석하지 않는다.

## 검증

Browser plugin not available. 기존 Playwright/Edge로 `/park` → 착석·원카드 선택·준비 → 승인 패/판 → 제출·무늬·K·뽑기·공격 수락·선언/신고 → 결과·다음 판을 조작한다. 1920×1080, 패널 390×844를 확인한다. 좁은 화면의 기존 전체 HUD 겹침은 모바일 서비스 지원 보장 범위에 포함하지 않는다.

```sh
pnpm typecheck:tests
pnpm test
pnpm build
pnpm check:migration
pnpm exec playwright test tests/e2e/onecard.spec.ts
pnpm test:e2e:facilities
```

검사 항목은 2/3/4인 UI, 서버의 카드/무늬/턴/장수 반영, 반응창 3초와 턴 30초 경계, pending/ACK/버전 차단, 최신 조회, 복구, 잘못된 타인 패 거절, 관전자 입력·손패 차단, 결과/다음 판, 기존 M01~M11 회귀다. 테스트 계약 응답은 명시적으로 지정하며 제품에 목업 게임 엔진을 넣지 않는다.

BE 수정 없이 Java 21에서 기존 `./gradlew test --tests '*OneCard*' --rerun-tasks` 24개(설정 2·엔진 5·규칙 2·도메인 14·실제 소켓 1)가 통과했다. 셔플·특수 카드·선언 경합·타임아웃·개인 패/공개 관전·복구 계약을 기존 BE 테스트로 확인한다.

실제 FE+Java 연동은 기존 테스트 클래스패스의 `gamesDemo`와 독립된 참가자101/202·관전자505 브라우저로 실행했다. 서버 셔플로 받은 서로 다른 본인 패, 공개 판 일치, 페이지 재접속 후 원래 패/마감 복구를 확인하고, 실제 UI로 142개 행동을 보내 124번째 차례의 참가자101 EMPTY_HAND 승리를 세 화면에서 동일하게 확인했다. 마지막 ♦K가 즉시 승리하며 추가 행동을 만들지 않는 것도 서버 결과 그대로 표시했다.

테스트 로그인/프로필/목록·내부 경기 생성만 대역이며 경기 입력·서버 셔플/판정·공개/개인 WS·복구는 실제 Java 코드다. 관전 참조는 기존 M09 미리보기 포트다. 실제 OAuth·참가 차감·DB 정산·개발 서버 배포를 확인했다는 의미는 아니다. 테스트 서버의 `AUTH_ALLOWED_ORIGINS`에 정확한 FE 검증 주소를 설정해야 한다. 재접속의 기존 복구 게이트가 PENDING을 표시하면 화면의 “경기 복구 다시 확인”으로 본인 상태를 확인한 뒤 계속한다. 공통 월드 채널의 자동 재입장까지 이번 범위에서 보장하지 않는다.

## 렌더링 자원

공개 바닥 카드만 로컬 CanvasTexture로 그린다. 본인/타인의 손패 앞면이나 덱 순서를 3D 장면·공유 재질·아바타 상태에 전달하지 않는다. 상대 카드 뒷면은 최대 12장씩/4인 48개 인스턴스로 표시하고 정확한 장수는 HUD로 표시한다. 도형과 공용 재질을 공유하며 프레임 연출은 ref만 갱신한다. 바닥 카드 교체/화면 종료 시 해당 텍스처·재질과 인스턴스 버퍼를 해제하고 공용 geometry/material은 보존한다.

새 파일형 에셋이나 상업 카드 이미지를 추가하지 않았다. 카드는 자체 Canvas 그림이므로 KTX2/Meshopt 변환·외부 다운로드를 추가하지 않는다. 기존 테이블 스케일·카메라·주야간·공원 자산은 유지한다. 동일 16인/착석 시점에서 미배치/배치 대조 결과를 별도로 기록하며 단일 장비 측정으로 성능 보장을 주장하지 않는다.

1920×1080 화면/Low(내부 렌더 1280×720)·Edge156.0.4314.42·Core Ultra9 185H/Intel Arc(ANGLE D3D11)·WebGL2에서 동일 착석 1인칭·16인·낮밤을 대조했다. 네트워크는 로컬 계약 대역이며 자산 계측 시 다른 브라우저 검사는 종료했다. 워밍업 뒤 각 230프레임 이상을 기록했다.

| 장면 | 낮 draw calls / triangles | 밤 draw calls / triangles | geometry buffer 추정 | 텍스처 메모리 추정 |
| --- | --- | --- | --- | --- |
| 카드 자산 없음 | 360 / 1,651,402 | 361 / 1,652,682 | 43,817,200 B | 211,435,520 B |
| 4인 공개 카드(뒷면28장) | 365 / 1,651,766 | 366 / 1,653,046 | 43,818,180 B | 211,959,808 B |

증가는 5 draw calls·364 triangles·geometry 980B·동적 이미지 추정 524,288B다. geometry 추정에는 인스턴스 행렬 용량 3,072B를 포함하지 않는다. 관측 p95 프레임 간격은 낮 8.7→12.0ms, 밤 8.8→11.4ms, 관측 FPS는 약120이다. GPU timer는 가용했으며 3회 표본을 원본에 남겼지만 정밀 CPU/GPU 프로파일이나 전체 장비 FPS 보장은 아니다.

카드 교체→다음 판에서 개별 텍스처2·재질2·인스턴스1 해제, 공유 자산 해제0을 확인했다. 최종 자산 검사 1개 통과. 주야간 캡처·환경·프레임 분포·GPU 표본·자원 해제 기록은 Git 밖 `m12/asset-metrics.json`에 보관한다.
