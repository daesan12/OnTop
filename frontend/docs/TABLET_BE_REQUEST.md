# BE 전달: 태블릿 게임 준비 흐름 연결 요청

2026-10-26 KST · 확인 기준: dev `bde4bce` · FE 브랜치 `feat/frontend-tablet-lobby`

## 어떤 흐름을 만들려는지

착석 → 방장이 게임·정원·목표 점수·판돈 확정 → 참가자가 금액을 확인하고 준비 → 전원 준비 시 방장이 시작 → 서버 시작 승인 후 기존 게임 화면 → 서버 정산 결과 → 다음 판 준비.

원카드·주사위·거짓말 다리 이미지 수정은 FE에 반영했으며, 이미지 관련 BE 작업은 없다. 실제 다리 규칙도 기존의 `1·2·3·4·X·X`를 유지한다.

## 이미 구현되어 있어 유지할 부분

- 최신 dev의 참가자 이탈 저장, INVALID 결과의 nullable 판정, 예약금 해제, 결과 outbox/재전달, 정산 후 WAITING 복구를 그대로 사용한다.
- FE는 `GAME_RESULT`의 결과·참가비·종료 사유·정산 버전을 표시하고, SETTLED와 WAITING을 모두 확인한 뒤 다음 판으로 이동한다.
- INVALID 예약금 해제는 추가 보상 지급이 아니다. 서버의 잔액 변화 0과 예약 해제 완료를 표시한다.
- 기존 인증·WS·지갑 검증·게임 엔진·좌석 ID·재접속 처리는 유지한다.

## BE에서 추가로 필요한 작업

| 우선순위 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 준비와 실제 시작 분리 | 현재 `TableHub.ready()`의 `beginStartIfReady(room)` 자동 시작을 새 흐름에서 분리. 전원 준비해도 기다리고 방장 시작 명령을 받아야 경기 생성. 기존 클라이언트와의 호환/전환 방법도 합의 |
| 2 | 이번 방의 정확한 정원 저장·공개 | 게임 최대 정원과 선택 정원을 구분. 원카드/다리 2·3·4인, 오목/주사위 2인. 선택 정원이 모두 착석하고 준비해야 시작 가능. 전체/인접 관찰 및 재접속 상태에도 같은 값 제공 |
| 3 | 게임 설정 일괄 확정 | 게임·정원·주사위 목표(2000/4000/6000)·1인 판돈을 같은 버전으로 저장/방송. 설정 변경 시 동의·준비 초기화. 이미 착석한 수보다 정원을 줄이면 거절 |
| 4 | 다음 방장 결정 | 첫 판은 최초 착석자. 이후 승자, 무승부는 무승부 참가자 중 서버 추첨. `selectorUserId`로 방송. 공동 승리·무효·기권·승자 이탈 시 정책 확정 |

현재 `TableRoom.snapshot()`은 도착 순서의 첫 유저를 selector로 쓰고, capacity는 게임 최대 정원이다. 따라서 2·3인 방 확정과 결과에 따른 방장 승계는 별도 처리가 필요하다.

시작 명령은 서버에서 방장 권한·설정 버전·선택 정원 충족·전원 준비·판돈 동의·지갑 상태를 다시 검사하고, 동시/중복 요청으로 경기가 두 번 생성되지 않게 해주세요. 시작 도중 취소/퇴장/연결 종료와 실패 복구도 기존 시작 파이프라인에서 처리해야 한다.

## FE에 전달해주실 명세

1. 설정 확정 명령 및 공개 상태 필드: 정확한 정원, 설정 버전, 게임/목표/판돈.
2. 방장 시작 명령의 WS 이름·payload·승인/거절·중복 요청/응답 유실 재확인 방식. `GAME_START_CHECK`는 기존 조회로 유지한다.
3. 방장 승계 시점과 예외 정책, `TABLE_STATE`/`GAME_START_STATE` 방송 순서 및 복구 규칙.
4. 자동 시작이 분리된 테스트 서버와 공동 검수 일정.

`TablePreparationPort`는 FE 내부 연결 지점이며 새 WS 명세가 아니다. 계약이 확정되면 FE가 `selectedPlayers`·`configure`·`start`를 실제 runtime에 바인딩한다. 서버 계약을 받기 전에 FE에서 임의의 메시지명으로 호출하지 않는다.

## 공동 검수와 현재 제한

동시 준비·준비 취소·퇴장·판돈 변경·중복 시작·응답 유실·2/3/4인 정원·승자/무승부 승계·재접속·INVALID 예약금 해제·SETTLED/WAITING 순서 뒤바뀜을 검수한다. 최종 WS/API 명세와 실제 서버 검증 전까지 운영 적용 완료로 보지 않는다.

현재 기본 `dev/build`는 기존 흐름이다. 새 UI는 `pnpm dev:tablet` 또는 tablet 빌드로 확인한다. 현행 서버는 마지막 준비 시 자동 시작하므로 새 모드에서 준비=true와 시작은 비활성화되어 있다. BE 수동 시작 계약을 연결하고 공동 검수한 뒤 전환해야 한다.

## 채팅에 복사할 전달 문구

> 태블릿 선택·준비 UI와 기존 게임 연결, 결과 팝업은 FE 작업을 완료했고 최신 dev의 정산·무효 경기·복구 기능도 유지했습니다. BE에서는 ① 전원 준비 후에도 자동 시작하지 않고 방장 버튼으로 시작하는 계약 ② 이번 방의 정확한 정원(2/3/4)과 게임·목표·판돈 일괄 저장/방송 ③ 승자에게 다음 방장 승계, 무승부 참가자 중 서버 추첨이 필요합니다. 명령/payload와 공개 상태를 확정해주시면 FE 어댑터를 연결하겠습니다. 기존 결과·정산 기능은 재개발 요청이 아니고, 변경된 썸네일 3개도 추가 BE 작업이 없습니다. 현재 태블릿 모드는 검수용이며 실제 서버에서 동시 요청·재접속까지 함께 확인한 후 전환하면 됩니다.
