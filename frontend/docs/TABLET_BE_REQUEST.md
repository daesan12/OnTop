# 태블릿 BE 요청 기록 및 연결 상태

## 2026-10-27 연결 상태

BE의 확정 명세 [tablet-lobby-api.md](../../docs/tablet-lobby-api.md)를 반영했다. `TabletLobbyClient`가 운영 RawWS 연결에서 TABLE_CONFIGURE/TABLE_START/TABLE_HOST_WAIT_CHECK와 시간 상태/만료 알림을 처리한다. startMode=MANUAL/selectedPlayers를 검증하며 AUTO 테이블에서 준비=true로 자동 시작하지 않도록 새 태블릿 준비를 차단한다. 시작 응답 유실 시 같은 actionId를 보존하고 명시적인 GAME_START_CHECK로 확인하며 자동 재전송하지 않는다. 테이블 epoch·revision·tableVersion·사용자/채널을 비교해 과거 시간 상태를 적용하지 않는다.

기존 기본 dev/build는 AUTO UI를 유지하고, `dev:tablet`/`build:tablet`은 실제 BE 수동 시작 어댑터가 연결된 새 UI다. 현재 브랜치는 코드·WS fixture 검증이며 배포된 BE/실제 DB를 사용한 다중 계정 공동 검수 완료를 의미하지 않는다.

**아래 내용은 10/26 당시 요청·미연결 상태의 기록이다. 현재 메시지와 정책의 기준은 위 확정 명세다.** 서버 재시작 시 대기석/타이머는 비우고, MANUAL 대기석의 일반 재접속은 서버의 30초 유예와 기존 절대 만료 시각을 따른다. 결과 승계 예외는 BE가 확정한 WIN/DRAW 후보 및 INVALID/승자 부재 시 남은 인원 추첨 정책을 사용한다.

2026-10-26 KST · 확인 기준: dev `bde4bce` · FE 브랜치 `feat/frontend-tablet-lobby`

## 어떤 흐름을 만들려는지

착석 → 방장이 게임·정원·목표 점수·판돈 확정 → 참가자가 금액을 확인하고 준비 → 전원 준비 시 방장이 시작 → 서버 시작 승인 후 기존 게임 화면 → 서버 정산 결과 → 다음 판 준비.

원카드·주사위·거짓말 다리 이미지 수정은 FE에 반영했으며, 이미지 관련 BE 작업은 없다. 실제 다리 규칙도 기존의 `1·2·3·4·X·X`를 유지한다.

## 이미 구현되어 있어 유지할 부분

- 최신 dev의 참가자 이탈 저장, INVALID 결과의 nullable 판정, 예약금 해제, 결과 outbox/재전달, 정산 후 WAITING 복구를 그대로 사용한다.
- FE는 `GAME_RESULT`의 결과·참가비·종료 사유·정산 버전을 표시하고, SETTLED와 WAITING을 모두 확인한 뒤 다음 판으로 이동한다.
- INVALID 예약금 해제는 추가 보상 지급이 아니다. 서버의 잔액 변화 0과 예약 해제 완료를 표시한다.
- 기존 인증·WS·지갑 검증·게임 엔진·좌석 ID·재접속 처리는 유지한다.

## BE에서 추가로 필요한 작업

| 우선순위 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 준비와 실제 시작 분리 | 현재 `TableHub.ready()`의 `beginStartIfReady(room)` 자동 시작을 새 흐름에서 분리. 전원 준비해도 기다리고 방장 시작 명령을 받아야 경기 생성. 기존 클라이언트와의 호환/전환 방법도 합의 |
| 2 | 이번 방의 정확한 정원 저장·공개 | 게임 최대 정원과 선택 정원을 구분. 원카드/다리 2·3·4인, 오목/주사위 2인. 선택 정원이 모두 착석하고 준비해야 시작 가능. 전체/인접 관찰 및 재접속 상태에도 같은 값 제공 |
| 3 | 게임 설정 일괄 확정 | 게임·정원·주사위 목표(2000/4000/6000)·1인 판돈을 같은 버전으로 저장/방송. 설정 변경 시 동의·준비 초기화. 이미 착석한 수보다 정원을 줄이면 거절 |
| 4 | 다음 방장 결정 | 첫 판은 최초 착석자. 이후 승자, 무승부는 무승부 참가자 중 서버 추첨. `selectorUserId`로 방송. 공동 승리·무효·기권·승자 이탈 시 정책 확정 |
| 5 | 전원 준비 후 방장 시작 제한 120초 | 서버 타이머 만료 시 기존 방장을 테이블에서 퇴장시키고, 남은 착석자 중 서버 무작위 추첨으로 새 방장 지정. 상세 조건과 FE 연결 지점은 아래 항목 참조 |

현재 `TableRoom.snapshot()`은 도착 순서의 첫 유저를 selector로 쓰고, capacity는 게임 최대 정원이다. 따라서 2·3인 방 확정과 결과에 따른 방장 승계는 별도 처리가 필요하다.

시작 명령은 서버에서 방장 권한·설정 버전·선택 정원 충족·전원 준비·판돈 동의·지갑 상태를 다시 검사하고, 동시/중복 요청으로 경기가 두 번 생성되지 않게 해주세요. 시작 도중 취소/퇴장/연결 종료와 실패 복구도 기존 시작 파이프라인에서 처리해야 한다.

## FE에 전달해주실 명세

1. 설정 확정 명령 및 공개 상태 필드: 정확한 정원, 설정 버전, 게임/목표/판돈.
2. 방장 시작 명령의 WS 이름·payload·승인/거절·중복 요청/응답 유실 재확인 방식. `GAME_START_CHECK`는 기존 조회로 유지한다.
3. 방장 승계 시점과 예외 정책, `TABLE_STATE`/`GAME_START_STATE` 방송 순서 및 복구 규칙.
4. 자동 시작이 분리된 테스트 서버와 공동 검수 일정.
5. 120초 만료 시각·타이머 취소·시간 초과 확정 사유 및 새 방장 정보의 공개 상태/이벤트 명세.

## 추가 BE 작업: 방장 시작 대기시간 2분

사용자 확정 요구: **선택한 참가 인원이 모두 착석하고 준비 완료한 뒤 120초 동안 방장이 시작하지 않으면, 방장을 테이블에서 자동 퇴장시키고 남은 착석자 중 서버 무작위 추첨으로 방장을 넘긴다.** 초기 설정은 120초다. 계정 로그아웃·채널 퇴장이 아니라 테이블 좌석만 해제한다.

### 서버 처리 및 권장 세부 정책

- 기존 마지막 READY_SET 자동 시작을 분리한 뒤 연결한다. 서버가 정확한 선택 정원·전원 준비·판돈 동의를 확인한 시점에 타이머를 한 번 시작한다. 단순 중복 준비/상태 조회/새로고침으로 만료 시각을 연장하지 않는다.
- 준비 취소·입퇴장·게임/정원/목표/판돈 변경·방장 변경 시 취소한다. 다시 시작 요건을 충족하면 새 120초를 부여한다. 이 취소/초기화 정책은 FE 제안이며 BE 명세에서 확정해달라.
- 시작 명령을 수락하면 타이머를 취소한다. STARTING/CONFIRMED/PLAYING 중에는 시간 초과 퇴장 처리하지 않는다. 실패 후 WAITING으로 돌아갈 때는 서버가 재개/새 타이머 정책과 시각을 명시한다.
- 만료 시점에도 같은 대기 세대·방장·정원 충족·전원 준비인지 검사한다. 시작 요청·퇴장·타임아웃이 같은 시점에 와도 서버의 동일 동기화/트랜잭션 경계에서 한 번만 확정한다. 예전 예약 작업이 새 판의 방장을 내보내면 안 된다.
- 서버에서 기존 방장 좌석·착석 상태·방장 권한을 해제하고 남은 착석자 중 무작위로 한 명을 선정한다. 남은 사람이 한 명이면 그 사람이 방장, 아무도 없으면 방장 없이 빈 테이블이다.
- 남은 인원 준비를 초기화하고 선택 정원은 유지하는 방식을 권장한다. 인원이 채워지고 다시 전원 준비하기 전에는 타이머를 시작하지 않는다. 정원 자동 축소나 연속 퇴장을 하지 않는다.
- 일반 테이블 퇴장/준비 초기화 경로와 지갑 예약 해제 정책을 재사용한다. FE가 잔액·예약금을 계산하거나 차감하지 않는다.
- 재접속 시 같은 타이머의 실제 만료 시각을 재전달한다. 서버 재시작 복구도 만료된 작업이 새 방장을 추방하지 않도록 대기 세대 식별자를 유지하거나 복구 정책을 합의한다.

### FE 완료 범위와 연결 입력

FE에는 2:00 카운트다운, 방장/참가자별 안내, 30초 이하 강조, 0초 때 시작 버튼 차단 및 서버 처리 확인 문구를 추가했다. 서버 퇴장 승인과 시간 초과 확정 통지가 확인되면 기존 방장에게 일어남 안내, 남은 인원에게 새 방장 안내를 표시한다. 0초만으로 TABLE_LEAVE를 전송하거나 selector/좌석을 수정하지 않는다. 서버 계약이 없을 때 임의 카운트다운은 시작하지 않고 시간 확인 대기를 표시한다.

`src/features/tableLobby/hostStartWait.ts`의 다음 타입은 **FE 내부 어댑터 입력**이며, WS 메시지 이름/payload를 확정한 것이 아니다. 기존 `TablePreparationPort`와 함께 실제 runtime 어댑터를 연결해야 한다.

```ts
const feed = bindHostStartWait({ userId, channelId, tableId })
feed.update({
  revision, tableVersion, hostUserId,
  serverNow, // 서버 Unix milliseconds, 어댑터가 유효한 서버 시각으로 정규화
  expiresAt, // 서버 Unix milliseconds. 취소 시 null
})
feed.timeout({
  eventId, revision, tableVersion,
  previousHostUserId, nextHostUserId, // 남은 사람이 없으면 nextHostUserId: null
})
feed.dispose()
```

- `revision`은 update/timeout이 공유하는 같은 테이블 대기 스트림에서 증가하는 값이다. 각각 중복·이전 버전을 무시하고, 더 최신 시간 상태 이후 도착한 과거 timeout이나 timeout 이전 시간 상태도 적용하지 않는다. 재시작으로 버전을 초기화한다면 스트림 세대도 전달하고 어댑터를 새로 바인딩한다.
- `tableVersion`은 해당 TABLE_STATE 버전이다. FE는 현재 방장·정원·준비·버전이 맞을 때만 타이머를 보여준다. 준비 상태 등으로 TABLE_STATE 버전이 바뀌면 같은 절대 expiresAt을 새 상태 버전에 맞춰 보내야 하며 120초를 재설정하면 안 된다.
- FE는 서버 시각 + performance.now 경과로 표시하므로 PC 시계 오차/변경에 의존하지 않는다. 탭이 다시 보이면 절대 만료 시각 기준으로 재계산한다.
- `timeout`은 단순 타이머 만료 예상이 아니라 서버가 퇴장·승계를 확정했다는 사유 통지다. 일반 퇴장/승리 후 승계를 시간 초과로 추정하지 않는다. 구체적인 reason 필드/이벤트 이름은 BE에서 확정해달라.
- 기존 방장에게는 TABLE_LEFT 또는 자기 좌석이 제거된 TABLE_STATE를, 남은 인원에게는 새 selectorUserId·이전 방장 좌석 제거·준비 초기화가 담긴 TABLE_STATE를 전송한다. 통지가 먼저 와도 실제 좌석 변경 전에는 FE 알림을 표시하지 않는다.
- 바인딩은 인증 사용자/채널/테이블 방문 범위다. 재접속·계정/채널/다른 테이블 전환에는 폐기 후 복원 상태로 재바인딩한다. 자동 퇴장 시에는 사유 통지를 받아 좌석 해제 후 알림을 표시할 때까지 바인딩을 유지하고, 알림 확인 후 dispose한다. 늦은 통지는 기존 feed로 받아야 하며 새 테이블에 적용하지 않는다.

### 추가 공동 검수

전원 준비 후 정확히 한 번 시작, 새로고침/재접속 시 남은 시간 유지, 준비 취소 후 재준비, 2초 남긴 시작, 만료와 시작 동시 요청, 이전 타이머 지연 실행, 중복 통지, 2인→방장 퇴장→1인 대기, 3/4인 중 무작위 승계, 무인 테이블, 시작 처리 중 타임아웃 방지, 예약금 정합성을 함께 확인한다.

`TablePreparationPort`는 FE 내부 연결 지점이며 새 WS 명세가 아니다. 계약이 확정되면 FE가 `selectedPlayers`·`configure`·`start`를 실제 runtime에 바인딩한다. 서버 계약을 받기 전에 FE에서 임의의 메시지명으로 호출하지 않는다.

## 공동 검수와 현재 제한

동시 준비·준비 취소·퇴장·판돈 변경·중복 시작·응답 유실·2/3/4인 정원·승자/무승부 승계·재접속·INVALID 예약금 해제·SETTLED/WAITING 순서 뒤바뀜을 검수한다. 최종 WS/API 명세와 실제 서버 검증 전까지 운영 적용 완료로 보지 않는다.

현재 기본 `dev/build`는 기존 흐름이다. 새 UI는 `pnpm dev:tablet` 또는 tablet 빌드로 확인한다. 현행 서버는 마지막 준비 시 자동 시작하므로 새 모드에서 준비=true와 시작은 비활성화되어 있다. BE 수동 시작 계약을 연결하고 공동 검수한 뒤 전환해야 한다.

## 채팅에 복사할 전달 문구

> 태블릿 선택·준비 UI와 기존 게임 연결, 결과 팝업은 FE 작업을 완료했고 최신 dev의 정산·무효 경기·복구 기능도 유지했습니다. BE에서는 ① 전원 준비 후에도 자동 시작하지 않고 방장 버튼으로 시작하는 계약 ② 이번 방의 정확한 정원(2/3/4)과 게임·목표·판돈 일괄 저장/방송 ③ 승자에게 다음 방장 승계, 무승부 참가자 중 서버 추첨이 필요합니다. 명령/payload와 공개 상태를 확정해주시면 FE 어댑터를 연결하겠습니다. 기존 결과·정산 기능은 재개발 요청이 아니고, 변경된 썸네일 3개도 추가 BE 작업이 없습니다. 현재 태블릿 모드는 검수용이며 실제 서버에서 동시 요청·재접속까지 함께 확인한 후 전환하면 됩니다.
