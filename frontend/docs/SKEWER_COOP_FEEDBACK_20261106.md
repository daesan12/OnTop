# 꼬치왕 협동 피드백 반영 — 2026-11-06

이 문서는 기존 VR 전용 랭킹·세척 중 추가 투입 금지 설명보다 우선한다.
게임 코드는 `SKEWER_COOP`, 작업 브랜치는 `feat/quest-vr`다.

## 동작

- 서빙 속도를 3.75 → 5.0 world units/초로 약 33% 올린다. 서버 충돌·상호작용 판정은 유지한다.
- 홀과 요리사 창문에서 보이는 동료의 위치·회전·걷기 전환을 보간한다. PC 렌더링의 격 프레임 생략을 제거한다. 보간은 화면 전용이며 서버 위치나 입력 권한을 바꾸지 않는다.
- 재료 이름표와 슬롯 번호를 제작대 뒤쪽의 높은 위치로 옮긴다. 꽂힌 음식과 이름표가 겹치지 않게 하며, 기존 음식 선택·VR 집기 영역은 유지한다.
- 세척기는 최대 두 **테이블분 묶음**을 받는다. 세척 중에도 빈 칸에 추가 투입할 수 있다. 남은 칸보다 운반 묶음이 많으면 들어갈 만큼만 넣고 나머지는 유지한다.
- 마지막 추가 투입부터 8초를 새로 센다. 새로 투입된 묶음당 3점만 확정한다. 가득 찼을 때 재시도하거나 이미 넣은 식기는 점수·식기를 복제하지 않는다.
- 음식·식기 동시 운반 금지와 식기 운반 중 주문 접수·전달 금지는 유지한다.

## PC·VR 랭킹과 계약

- 두 사람의 준비가 완료되면 요리사의 방식으로 `rankingMode=PC|VR`을 고정한다. 두 방식 모두 정상 종료 시 해당 랭킹에 등록된다.
- 경기 중 PC↔VR 전환 시 그 경기의 자격은 제외 상태로 유지한다. 원래 방식으로 돌아가거나 공동 재시작해도 복구하지 않는다.
- 공통 인증 REST를 유지한다. `GET /api/v1/minigames/skewer/coop/rankings?mode=PC|VR`, 생략 시 기존 호환용 VR이다. 응답에 `playMode`를 포함한다. 랭킹 탭을 빠르게 바꾸면 마지막 요청의 응답만 표시한다.
- 공개 상태의 `rankingMode` 외에 개인 주문 공개 범위는 바꾸지 않는다. 결과 저널에 확정 방식을 함께 저장한다.
- 엽전은 기존 팀 점수 20점당 각자 1냥, 모든 미니게임 합산 하루 500냥 한도를 그대로 사용한다.
- 공통 변경은 `SpringParkRuntime`의 인증 API 허용 목록에 정확한 PC·VR 쿼리만 추가한 것이다. 임의 쿼리·중복 mode는 허용하지 않는다.

## DB·배포

- 사용자 승인 번호 **V156**, `backend/src/main/resources/db/minigame/V156__add_skewer_coop_play_mode.sql` 한 개다. 결과의 `play_mode`와 방식별 랭킹 인덱스를 추가한다. 기존 V145는 수정하지 않는다.
- 처음 V154는 새 이벤트 V154와 겹쳐 V155로 변경했다. 이후 수상자 연락처 작업이 별도로 V155를 사용해 사용자가 꼬치왕 V156을 승인했다. OnTop 전체·등록된 117 worktree·원격 브랜치에서 V156 파일이 없는 것을 확인한 뒤 미배포 소스 한 개만 재지정했다. 공유 DB·기존 적용 이력은 변경하지 않았다.
- 기존 행의 기본값은 VR이다. 과거 PC·전환으로 제외된 경기는 소급 등록하지 않는다. 기존 결과·지갑·지급 영수증을 변경하지 않는다.
- 이전 저널의 mode 누락은 legacy VR로 읽고, 구 record의 해시 입력을 그대로 보존한다. 재시도 시 동일 경기의 정산 충돌·중복 지급을 방지한다.
- 새 백엔드는 V156의 `play_mode`가 없으면 기동을 거절한다. `dev,db`의 기존 `db/minigame` Flyway location에서 V156을 정상 적용한 뒤 배포 상태를 확인한다. V156을 건너뛴 공유 DB에는 임의 outOfOrder·repair·초기화를 하지 않는다.
- 기존 `verify-skewer-coop-db.sh`는 **V145와 두 테이블만** 확인한다. 이 검사 성공은 V156 적용 증거가 아니다. 승인된 DB 조회 경로에서 다음 읽기 전용 조회도 확인한다.

```sql
SELECT version, description, success FROM flyway_schema_history WHERE version = '156';
SELECT column_name, column_type FROM information_schema.columns
WHERE table_schema = DATABASE() AND table_name = 'skewer_coop_results' AND column_name = 'play_mode';
```

- 실제 DEV 방 생성 성공과 2인 역할 선택·진행은 앞선 사용자 조작 화면으로 확인했지만, 이번 변경의 공유 DEV 배포·두 물리 노트북 플레이·Quest 실기기 검수는 수행하지 않았다. FPS 개선 수치는 측정하지 않았으며 실제 기기 GPU 부하 검수가 남아 있다.

- 기존 큰 번들·Three.js 셰이더 정밀도 경고가 남아 있다. 공유 서버 변경·머지·배포·브랜치 삭제는 별도다.
