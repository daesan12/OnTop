# M02 — 이동 입력·점프·수영 표시 분리

2026-10-24. M01 커밋 `f7a1e9e` 위에 M02만 추가한다. GitLab dev 기준은 `69a9d19`이며, 같은 작업 브랜치에 별도 커밋으로 쌓고 병합·배포하지 않는다. 원본 미커밋 작업본은 보존한다.

## 기존 BE 연결과 변경 범위

`docs/world-websocket-api.md`, `backend/src/main/java/com/ssafy/ontop/world/movement/MoveInput.java`, `WorldPhysics.java`를 확인했다. 걷기·달리기·점프·충돌·수영·부력·징검다리 오르기·전망대 전용 점프는 기존 서버 처리 경로를 사용한다. 새 이동 API나 운영용 이동 목업을 만들지 않는다.

| 프론트 파일 | M02 변경 |
| --- | --- |
| `network/movementInput.ts` | 카메라 기준 방향·대각선 정규화·유한값/범위 검사·60ms 입력 병합 |
| `park/runtime/SpringParkRuntime.ts` | 전송 직전 연결·채널·맵·본인 아바타·착석/경기 상태를 재검사하고 세션 수명이 바뀌면 대기 입력 폐기 |
| `world/input.ts` | 기존 WASD/방향키·Shift·Space를 입력 함수에 연결, 기존 단발 Space와 M01 입력 소유권 유지 |
| `world/movementPresentation.ts`, `network/worldClient.ts` | 기존 120ms·최단 yaw 보간 유지, 동일 위치의 반복 ACK가 보간을 계속 지연시키는 현상 방지 |
| `world/SwimmingRipples.tsx` | 연결된 수영 아바타의 보간 위치로 물결 표시, 인스턴스 용량 제한 |
| `world/cameraCollision.ts`, `world/CameraRig.tsx` | 보간 후 실제 카메라가 지형 아래로 내려가지 않게 보정, 가림 기준을 표시 아바타에 연결 |

이동 전송은 기존 `WORLD_MOVE`와 `seq/dx/dz/run/jump`만 사용한다. 순번은 실제 전송 시 증가한다. 빠른 입력 변경은 기존 60ms 간격 안에서 병합하고, 대기 점프는 한 번 보존하며 명시적 정지로 취소한다. 현재 BE 기본 최소 입력 간격은 50ms다. 해당 운영 설정이 바뀌면 FE 주기도 함께 확인해야 한다.

서버 최종 위치·회전·속도·dt·사용자 ID를 입력에 추가하지 않는다. 점프 높이·접지·수영 여부·충돌은 BE 판단을 따른다. 서버 승인 `position.swimming`으로 기존 수영 자세를 표시하고, 물 색이나 지형으로 수영 상태를 만들지 않는다. 클라이언트 예측·외삽·물리 시뮬레이션도 추가하지 않는다. 현재 DTO에 없는 grounded·수직속도·정교한 점프/착지 클립을 가짜로 추가하지 않는다.

## 입력 수명과 회귀 보강

맵 불일치·테이블 착석·채널 이탈·로그아웃·단절·재접속 시 이전 입력이 나중에 재생되지 않게 한다. M01 벤치 이용/대기 중에는 일반 이동을 막고 기존 정지 메시지를 허용한다.

추가 런타임 검증에서 본인 아바타가 서버 월드에서 제거된 동안 새 입력이 대기열에 들어갈 수 있는 경우를 확인했다. M02 범위에서 본인 아바타 유무를 입력/전송 조건에 추가하고 제거 시 눌린 키를 정리했다. 아바타가 돌아와도 이전 키·점프가 재생되지 않는지 단위·브라우저 테스트로 확인한다.

## 목업·후속 단계와 분리

기존 로그인·OAuth·인증/세션·채팅·채널·테이블·오목 연결과 M01 벤치 목업을 유지한다. 이 커밋에는 M03 리그·보행 모션, M04 G 휠·감정표현, M05 운동기구, M06 망원경, M07 소리함을 추가하지 않는다. `Avatars.tsx`와 `CharacterRig.ts`는 변경하지 않는다.

백엔드·인프라·맵/버전·맵 생성·이동 설정 수치·에셋·Vite·의존성/잠금파일·인증/API 오류 처리·지갑·미니게임·로컬 플레이 변경도 제외한다. M00/M01 파일 전체를 후속 작업본으로 덮어쓰지 않았다.

`tests/fixtures/movementScenarios.ts`는 승인 위치·수영/이동 상태의 FE 검수 샘플이다. `manualMovement` 테스트 모드는 입력만으로 좌표를 계산하지 않는다. 명시적으로 주입한 승인 샘플의 점프 높이·물결·돌 위 전환을 표시한다. 운영용 이동 목업이나 Java 물리 검증 결과가 아니며 앱 진입 코드에서 테스트 파일을 import하지 않는다.

## 검증

```sh

pnpm check:migration
pnpm exec playwright test tests/e2e/m02.spec.ts tests/e2e/m01.spec.ts tests/e2e/park.spec.ts tests/e2e/omok.spec.ts
```

Browser plugin not available. 기존 Playwright/Edge와 저장소의 HTTP/RawWS 계약 대역을 사용한다. 기존 작업 서버와 분리한 `http://127.0.0.1:5198`에서 검증하고, 화면 증빙은 저장소 외부 QA 폴더에 저장한다.

검수 흐름은 기존 로그인/공원 → 걷기·달리기·대각선·단발 Space → blur·본인 제거·재접속 후 입력 정리 → 승인 점프 높이·수영·물결·돌 위 전환 표시다. M01 벤치와 기존 공원·오목·로그인 회귀도 함께 확인한다.

수영 화면에서는 본인과 테스트 원격 아바타의 물결이 보간 위치를 따르는지, 돌 위 승인 상태에서는 수영 자세·물결이 해제되는지 확인했다. 이 결과는 명시적 승인 샘플을 사용하는 FE 계약 대역 검증이다.

실제 개발 BE 두 계정 플레이·속도·충돌·부력·전망대/징검다리 물리 동등성·운영 부하 검증은 별도다. 기존 큰 3D 청크·Three.Clock/ANGLE 경고는 남아 있다.
