# M11 주사위 한 판(Farkle) 이관

기준: 2026-10-24. M10 커밋 `566fef7` 위의 FE 작업이다. 기존 로그인·Spring HTTP/RawWS·채널·월드·이동·오목·M09 로비/관전/결과 흐름을 유지한다. BE·인프라·맵·패키지/잠금 파일은 수정하지 않으며 M12·M13 게임 화면은 시작하지 않는다.

## 화면과 조작

- 공통 로비에서 DICE 선택, 기존 목표 2000/4000/6000 선택과 준비를 활성화했다. M09의 기존 초기 목표 선택값은 유지하고 경기 화면에는 서버 승인 targetScore만 표시한다. 아직 화면이 없는 원카드·다리는 준비할 수 없다.
- `game/farkle/`에 참가자/공개 관전자 패널, 주사위 점수판, 선택·예상 점수, 굴림/재굴림·Bank, BUST/HOT DICE·30초 마감·승패/정산 안내를 분리했다.
- R 굴리기/재굴림, Q Bank, T 점수표를 지원한다. 채팅·텍스트 입력·다른 입력 소유 패널·점수표가 열렸을 때 경기 단축키는 실행하지 않는다. 점수표는 T/Esc/닫기로 닫고 Tab 포커스를 내부에 유지한다.
- 실제 3D 컵을 잡아 판 위로 움직이고 방향을 바꿔 충분히 흔든 뒤 놓으면 굴림을 요청한다. 흔들기 부족·Esc·blur/탭 전환·pointercancel·상태/차례/버전 변경은 취소하며 굴리지 않는다. 화면 좌표는 테이블 로컬 평면에 투영하므로 반대 좌석과 테이블 스케일에도 대응한다.
- 기존 착석 1인칭을 기본으로 유지하고 명시적 “주사위 판 보기/착석 시점” 보조 시점을 제공한다. 관전자는 M09 공개 판/테이블 시점을 사용하며 선택·굴림·Bank·개인 정산 권한을 얻지 않는다.
- 판 위의 주사위 선택은 선택한 돌출 높이로 표시하고 접근성 버튼과 같은 선택 상태/명령을 사용한다. 이미 보관한 주사위는 다시 선택하거나 새 조합에 합칠 수 없다.

## 실제 BE 계약 연결

프로토타입의 Colyseus·FarkleState·서버 RNG를 복사하지 않는다. 현 프로젝트의 `docs/farkle.md`, `FarkleMatch`, `FarkleEngine`을 기준으로 기존 인증 소켓 하나를 사용한다.

| 기능 | 기존 연결 | FE 처리 |
| --- | --- | --- |
| 선택·준비 | `GAME_SELECT {gameCode:'DICE',targetScore}`, `READY_SET` | 기존 서버 좌석·방장·시작 승인 유지 |
| 첫 굴림 | `GAME_ACTION_SEND`의 `input:{kind:'roll',selectedIds:[]}` | gameId·새 actionId·최신 expectedVersion 포함 |
| 보관 후 재굴림 | 같은 입력의 `kind:'roll', selectedIds:[...]` | 득점 선택 ID만 전송. 눈·점수·시간·승자를 전송하지 않음 |
| Bank | 같은 입력의 `kind:'bank',selectedIds:[...]` | 이번 턴 누적+선택 반영은 BE가 확정 |
| 처리/공개 상태 | `GAME_ACTION_RESULT`, `GAME_STATE`, `GAME_STATE_CHECK` | 확인 응답을 새 눈으로 취급하지 않음. 상태 버전이 따라오기 전 입력 차단 |
| 복구 | `GAME_RECONNECT_CHECK` / `GAME_CONNECTION_STATE` | 기존 판·점수·차례·원래 마감 복원 |
| 관전 | `GAME_WATCH` / `GAME_STATE` / `GAME_UNWATCH` | 기존 공개 참조·서버 권한 검사. privateState는 빈 객체만 수용 |
| 종료/정산 | `GAME_RESULT_CHECK` / `GAME_RESULT` | DICE 결과 읽기만 지원. 지급/잔액·SETTLED 생성 없음 |

`Game` 표시 상태를 OMOK/DICE 구분 타입으로 확장했다. 오목 필드는 오목 렌더러만, DICE 필드는 주사위 렌더러만 사용한다. 기존 오목 단위 검사의 세 곳은 이 구분에 맞는 타입 단언만 추가했으며 검증값과 규칙은 바꾸지 않았다. 미지원 게임·다른 경기/사용자·낮은 버전·비공개 데이터는 기존 수신 경계에서 차단한다.

`scoring.ts`는 서버 공개 눈에 대한 **선택 가능/예상 점수 표시용 순수 함수**다. 선택 전체를 득점 조합으로 나눈 최대합을 구하며 임의 총점·턴 점수·승패·BUST를 확정하지 않는다. 최종 검증과 점수 반영은 Java 엔진이 다시 수행한다. 브라우저에 주사위 난수 생성기는 없다.

## 현 BE와 프로토타입의 차이

- 현 BE는 **한 차례 전체 30초**다. 재굴림·거절·조회·재접속으로 마감을 연장하지 않는다. 0초에는 입력만 중지하고 다음 차례·점수 소멸은 서버 상태를 기다린다. 단순한 시간 만료를 패배로 표시하지 않는다.
- 서버 단계는 AWAITING_ROLL/SELECTING/FINISHED이며 별도 ROLLING/BUST 대기 단계가 없다. 확정된 rollId 변경 후 로컬 900ms 연출을 재생하고 최종 윗면을 서버 value에 맞춘다. 복구/새 관전의 최초 스냅샷을 이전 굴림처럼 재생하지 않는다.
- BUST·Bank·차례 시간 만료 후에는 BE가 즉시 다음 차례/빈 dice 배열을 보낸다. 특히 BUST 실패 눈은 현재 상태에 남지 않는다. 없는 실패 눈을 임의 생성하지 않고 BUST 문구와 새 차례를 표시한다. 실패 굴림의 정확한 눈까지 재현하려면 BE가 승인한 공개 최근 굴림 필드/이벤트 계약이 추가로 필요하다.
- Bank로 총점이 목표 이상이 되면 즉시 승리하며 상대 추가 차례를 만들지 않는다. 결과 뒤 좌석 유지·WAITING·다시 준비는 M09의 기존 서버 흐름을 따른다.

## BE 미구현 부분과 목업

굴림·재굴림·Bank·공개 상태·복구·결과 API는 이미 있어 **M11용 목업 엔진/가짜 난수/가짜 정산은 추가하지 않았다.**

- 수동 기권에는 아직 공개 API가 없다. M10의 공통 기권 의사 확인 포트를 재사용한다. `DEV && MODE === 'facility-preview'`에서만 목업 안내·확인/취소를 검수하며 실제 게임/좌석/점수/지갑을 바꾸지 않는다. 일반 개발·운영에서는 연결 준비 안내와 비활성 버튼이다.
- 관전 가능한 공개 gameId 공급은 M09의 미연결 경계를 유지한다. 전용 개발 모드의 공개 참조 공급만 목업이며 기존 GAME_WATCH와 공개 스냅샷·권한을 목업 성공으로 바꾸지 않는다.
- 개발 서버 TABLE_OUT_OF_RANGE 확인은 보류 상태다. 거리 검사나 BE 설정을 우회하지 않는다. DB 저장·차감·지급을 FE에서 대신하지 않는다.

## 검증 방법과 범위

일반 실행은 `pnpm dev`, 미구현 기권/공개 참조 의사 확인은 `pnpm dev:facilities`다. 기존 로그인 화면과 서버 연결이 필요하며 별도 목업 입장 화면은 만들지 않는다.

Browser plugin not available. 기존 Playwright/Edge로 `/park` → 착석/주사위 선택/준비 → 승인 경기 → 굴림/보관/재굴림/HOT DICE/Bank → 승리/정산/다음 판을 조작한다. 컵 미달/흔들기/취소·채팅 R/Q 격리·점수표 T/Esc/Tab·응답 불명/중복 차단·재조회·복구·BUST/시간 만료·관전자 입력 차단·최종 3D 눈·자원 해제도 확인한다.

```sh
pnpm typecheck:tests
pnpm test
pnpm build
pnpm check:migration
pnpm exec playwright test tests/e2e/farkle.spec.ts tests/e2e/omok.spec.ts tests/e2e/omok-migration.spec.ts tests/e2e/table-lobby.spec.ts tests/e2e/park.spec.ts
pnpm test:e2e:facilities
```

BE 수정 없이 Java 21에서 기존 `./gradlew test --tests '*Farkle*'`도 실행한다. 실제 FE 연동에는 기존 테스트 클래스패스의 `gamesDemo`를 127.0.0.1:18082로 실행하고, 독립된 참가자101/202·관전자505의 새 React 화면을 실제 Java RNG·규칙·RawWS에 연결했다. 20회 입력 검사 루프 안에 재굴림·Bank를 거쳐 1,450 대 2,200점, 참가자202의 TARGET_REACHED 종료를 세 화면에서 동일하게 확인했다. 관전자는 입력하지 않으며 실제 입력에는 kind/selectedIds 외의 눈·점수 필드가 없다.

이 검증에서 로그인/프로필·목록·내부 경기 생성은 테스트 대역, 공개 관전 참조는 기존 미리보기 포트다. 실제 OAuth·준비에 따른 참가 차감·DB 정산·개발 서버 배포를 확인했다는 의미가 아니다. 테스트 인증/생성 코드는 제품이나 BE에 추가하지 않았다. 어댑터·스크린샷·기록은 Git 밖 QA 디렉터리에 보관하며 이번에 실행한 Java 테스트 서버만 종료했다.

데스크톱 1920×1080/1280×720과 주사위 패널 390×844를 확인한다. 좁은 화면의 전체 기존 HUD·3D 컵 조작을 모바일 서비스 지원으로 보장하지 않는다. 기존 Three.Clock/ANGLE 경고와 큰 3D 청크 경고는 남아 있다.

2026-10-24 검증 결과:

- FE 타입·단위 25개 파일/185개, 일반 모드 회귀 24개, M01~M11 전용 미리보기 29개 통과.
- 기존 Java Farkle 점수/엔진/소켓 12개, 실제 React+Java 3세션 경기 1개 통과.
- 채팅 R/Q 격리·T/Tab·응답 소실 검사를 보강한 M11 3개를 재실행했고, 이후 개별 GPU 자원 정리를 보완한 최종 M11 3개도 통과했다. 다음 판 전환에서 인스턴스 6개 해제·공유 자산 해제 0개를 확인했다.
- 운영 빌드·목업 제외·프로토타입 의존성 경계·공백 검사 통과. 이 결과는 명시한 검증 집합이며 저장소 모든 E2E나 배포 검수를 뜻하지 않는다.
- 최초 단위 실행에서 기존 M02의 실수 정확 비교가 0.999999999999999/1 차이로 한 차례 실패했다. M02 코드/테스트는 수정하지 않았고 이후 전체 단위 검사를 반복해 185개 통과했다.
- 일반 회귀의 기존 5198 포트가 사용 중이어서 해당 프로세스를 종료하지 않고 5208 검증 포트를 사용했다.

## 렌더링 자원

주사위 body/pip geometry와 재질, 트레이와 컵 geometry를 공유한다. 주사위 여섯 개의 126개 점은 여섯 instancedMesh로 표시하며 눈마다 텍스처를 다운로드하지 않는다. 매 프레임 React 상태를 갱신하지 않고 위치·회전·컵 투영 scratch 객체를 재사용한다. 주사위가 사라질 때 개별 인스턴스 GPU 버퍼만 해제하고 공유 geometry/material은 유지한다.

파일형 에셋/텍스처를 새로 추가하지 않았으므로 KTX2·Meshopt 변환은 적용하지 않는다. 프레임 타이밍·GPU·메모리 수치는 환경에 따른 검수 값이며 이관 완료를 다인원/iGPU FPS 보장이나 모든 최적화 완료로 해석하지 않는다.

동일 16인 공원·착석 1인칭·Low·1920×1080·Edge 156.0.4314.42·WebGL2에서 주야간 대조를 실행했다. 하드웨어는 Core Ultra 9 185H/Intel Arc(ANGLE D3D11), 네트워크는 로컬 HTTP/WS 계약 대역이며 외부 지연은 없다. 자산 없음 → 빈 트레이/컵 → 확정 주사위 6개의 순서로 각각 워밍업 후 120프레임 이상을 기록했다.

| 장면 | 낮 draw calls / triangles | 밤 draw calls / triangles | geometry buffer 추정 |
| --- | --- | --- | --- |
| 주사위 자산 없음 | 360 / 1,651,402 | 361 / 1,652,682 | 43,817,200 B |
| 빈 트레이·컵 | 362 / 1,651,638 | 363 / 1,652,918 | 43,823,736 B |
| 주사위 6개 포함 | 374 / 1,652,718 | 375 / 1,653,998 | 43,824,944 B |

새 자산 전체는 같은 장면 대비 14 draw calls·1,316 triangles를 더한다. geometry buffer 추정은 instanceMatrix를 제외하며 점 인스턴스 6개는 별도 8,064 B의 행렬 배열을 사용한다. 이미지 텍스처 메모리 추정은 약 211.4 MB로 동일하다. 관측 p95 프레임 간격은 낮 9.1→8.8→10.9ms, 밤 8.9→8.8→10.4ms였고, 이 한 환경의 계측만으로 FPS 개선을 주장하지 않는다. CPU/GPU 정밀 프로파일·네트워크 배포·다른 저사양 장비의 최적화 완료는 남아 있다. 주야간 캡처와 GPU timer 가용성/샘플 원본은 Git 밖 `m11/asset-metrics.json`에 보관한다.

최종 범위는 M11 관련 프론트 29개 파일이다. 원본 혼합 작업 폴더의 144개 변경 파일·HEAD·변경 목록 보존을 확인한다. 이 단계는 로컬 이관/검증이며 새 커밋·푸시·머지·배포는 하지 않는다.
