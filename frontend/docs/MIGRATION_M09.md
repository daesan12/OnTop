# M09 공통 테이블 로비·관전·결과 이관

기준: 2026-10-24, `dev`의 MR !47 머지 커밋 `73e95a6b`에서 분기한 `feat/frontend-m09-table-lobby`.

## 범위와 기존 기능

기존 로그인·프로필·채널·RawWS·이동·시설·소리함·익명 메모를 보존하면서 테이블 로비를 공통 화면으로 분리했다. 기존 가구·좌석 앵커·오목판·서버 권한을 사용하며 새 에셋이나 게임 규칙을 추가하지 않는다. M10~M14의 게임별 이관은 시작하지 않았다.

- 서버의 `seatNumber`는 1부터, 아바타의 `seatIndex`는 0부터 사용한다. 기존 `seatNumber - 1` 매핑을 유지한다.
- 방장은 서버 `selectorUserId`로 표시한다. 1번 좌석이나 본인이라는 이유로 선택 권한을 만들지 않는다. 방장 승계도 새 `TABLE_STATE`로 반영한다.
- 네 게임의 로비 선택과 주사위 목표 2000/4000/6000을 기존 `GAME_SELECT`에 연결했다. `cards` 미리보기 메뉴는 추가하지 않는다.
- 기존 오목은 선택·준비·경기·결과 흐름을 유지한다. 다른 세 게임은 로비 설정만 가능하며, 플레이 화면 이관 전에는 준비를 비활성화하여 표시할 수 없는 경기를 새로 시작하지 않는다.
- 좌석·준비·정원·결과·엽전은 로컬에서 승인하거나 계산하지 않는다. 공개 정보와 본인 결과만 검증 후 표시한다.

## 실제 사용하는 기존 BE 계약

| 기능 | 기존 계약 | FE 처리 |
| --- | --- | --- |
| 테이블 목록 | `GET /api/v1/tables?channelId=...` | 입장과 정보 열기 시 현재 목록·입장 가능 상태 재조회 |
| 공개 대기 상태 | `TABLE_WATCH` / `TABLE_WATCH_STATE`, `TABLE_UNWATCH` / `TABLE_WATCH_LEFT` | 로딩·거절·재시도·구독 정리, 좌석·선택 상태 표시 |
| 착석·퇴장 | `TABLE_JOIN` / `TABLE_STATE`, `TABLE_LEAVE` / `TABLE_LEFT` | 승인 시에만 본인 좌석 전환, 명시적 퇴장 후 시점 복구 |
| 게임·목표 | `GAME_SELECT {gameCode, targetScore?}` | 방장만 선택, DICE만 목표 포함, 서버 정원·준비 초기화 반영 |
| 준비 | `READY_SET {ready}` | 기존 오목 경로 유지, 최소 인원·서버 시작 대기·진행/정산 잠금 |
| 경기 복구·공개 상태 | `GAME_START_CHECK`, `GAME_RECONNECT_CHECK`, `GAME_STATE_CHECK` | 승인된 경기 ID·버전·본인 참가 범위 유지 |
| 결과 | `GAME_RESULT_CHECK` / `GAME_RESULT` | PENDING/SETTLED 구분, 본인 증감 표시만, 지급·지갑 변경 없음 |
| 실제 경기 관전 | `GAME_WATCH` / `GAME_STATE`, `GAME_UNWATCH` / `GAME_WATCH_LEFT` | 승인된 공개 경기 참조가 있을 때만 요청. 개인 패나 역할을 요청에 넣지 않음 |

`GameControls`의 오목 호환 함수 `selectOmok()`는 유지하며 일반 선택 포트 `selectGame()`을 추가했다. 프로토타입의 예약 토큰·Colyseus·운영에 없는 DTO를 이식하지 않는다.

## 결과와 다음 판: 현재 BE 흐름에 맞춘 차이

프로토타입은 방장의 수동 다음 판 요청이 있지만 현재 Spring BE 계약은 다음과 같다.

1. 경기 종료 시 좌석 유지, 전원 준비 해제, `SETTLING`.
2. 실제 정산 커밋 확인 후 서버가 `WAITING` 전환.
3. 좌석·게임 선택·주사위 목표를 유지하고 다시 전원 준비해야 새 경기 시작.

FE의 “다음 판 준비/대기실로 돌아가기”는 서버가 WAITING을 승인한 뒤 지난 결과 표시를 정리하는 로컬 UI 동작이다. 새 경기·정산·좌석 초기화 요청을 만들지 않으며 자동 준비도 하지 않는다. 실제 새 경기는 기존 READY_SET과 서버의 새 경기 ID로만 시작한다.

정산 결과와 WAITING의 수신 순서가 달라도 직전 본인 결과를 표시할 수 있도록 완료 경기 ID를 기억한다. 새 경기 승인·본인 퇴장·채널/계정/연결 초기화 시 지운다. 이전 경기의 늦은 결과로 새 판이 바뀌지 않고, 이미 닫은 결과의 같은/낮은 버전이 다시 열리지 않는다.

## 카메라·입력·요청 수명

- 기존 착석 1인칭과 본인 차례 오목판 보기 유지. 우클릭 드래그로 좌우 둘러보기, “정면 보기”로 복귀한다. 마우스 이동은 ref로 처리하며 프레임마다 React 상태를 갱신하지 않는다.
- 관전자는 자신의 좌석을 얻지 않고 공개 판 탑뷰/테이블 둘러보기를 선택한다. 돌 놓기와 개인 결과 요청은 불가하다. 관전 종료 후 원래 로밍 카메라로 복귀한다.
- 미준비 + 서버 WAITING + 연결 정상 + 텍스트/모달 미사용일 때만 이동키가 기존 `TABLE_LEAVE`를 요청한다. 키를 눌렀다고 로컬에서 좌석을 해제하지 않는다. 준비·진행·정산 상태나 지연 키로 기권 요청을 만들지 않는다.
- 서버 관전 거절은 실패 상태와 재시도 버튼으로 표시한다. 캐시가 없다는 이유로 영구히 “상태 확인 중”을 표시하지 않는다. BE 거절을 목업 성공으로 바꾸지 않는다.
- 닫은 조회의 늦은 응답은 로비를 다시 열지 않으며, 아직 요청 수명이 유효하면 늦게 승인된 구독을 반납한다. 타임아웃 이후 승인도 화면 상태로 수락하지 않는다.
- 계정·채널·접속 초기화 시 요청 표시, 카메라 선택, 결과·목업 공개 참조를 정리한다.

## BE 미구현·미확정 경계

### 공개 경기 ID 공급

현재 `TABLE_STATE`와 테이블 REST 요약에는 관전 가능한 공개 `gameId`가 없다. `GAME_WATCH` 자체는 이미 있으므로 이를 새 API로 분류하거나 목업 소켓으로 대체하지 않는다.

`features/tableLobby/publicMatch.ts`는 FE 내부 정보 공급 포트다. 일반 개발/운영에서는 `unavailable`이며 “경기 관전” 버튼을 비활성화한다. BE가 승인한 공개 경기 참조의 조회/갱신 계약을 제공하면 해당 포트를 실제 어댑터로 교체한다. tableId를 gameId로 추측하거나 임의 입력하는 UI는 만들지 않는다.

`DEV && MODE === 'facility-preview'`에서만 `MockPublicMatchService`를 사용한다. 초기 참조는 비어 있으며 명시적 테스트 시나리오가 채널·테이블·공개 경기 ID를 제공한다. 이 포트는 공개 참조만 모사한다. 경기 관전 승인·공개 판·역할·관전 종료는 그대로 기존 WS를 사용하므로 서버 거절은 계속 거절이다. 실제 BE에 임의 목업 경기 ID를 보내 성공한 것처럼 표시하지 않는다. 테스트의 HTTP/WS 계약 대역은 제품 목업과 구분한다.

### 보류한 개발 서버 오류와 수동 기권

- 기존 개발 서버의 TABLE_OUT_OF_RANGE/관전 좌표 설정 문제는 보류 상태다. 이번 FE 이관으로 서버 설정을 고치거나 거리 검사를 우회하지 않았다. 실패 표시만 개선했다.
- 수동 기권은 프로토타입에 있지만 현재 공개 TableProtocol에는 별도 사용자 기권 명령이 없다. 내부 단절 처리용 FORFEIT와 구분하며, 새 명령·퇴장 우회·접속 종료로 기권을 구현하지 않는다. 필요한 요청·취소·수락 규칙은 BE 계약 협의 후 후속 연결한다.
- 공개 경기 참조가 연결되더라도 실제 게임 관전은 서버의 채널·위치·거리·공개 상태 권한을 다시 통과해야 한다.

## 검증과 한계

Browser plugin not available. 기존 Playwright/Edge로 로컬 Vite 화면을 조작하며 HTTP/RawWS 계약 대역을 사용한다. 실제 개발 서버의 두 참가자+관전자, DB 정산·지갑 지급·배포 완료 검증을 뜻하지 않는다.

주요 검수는 4석/2석 전환·방장 승계·목표 옵션·게임별 준비 차단, 조회 거절/재시도·닫은 요청의 늦은 승인, 결과→정산→좌석 유지→다음 판 표시→미준비 이동키 퇴장, 공개 참조 목업→기존 GAME_WATCH 거절/승인→공개 탑뷰→시점 전환→관전 종료, 우클릭 둘러보기/정면 복원이다. 기존 공원·오목·이동·캐릭터·M01~M08 시설 경계도 함께 회귀 검사한다.

2026-10-24 검증 결과:

- 타입 검사와 단위 테스트 23개 파일·165개 통과.
- 일반 모드 공원/오목/재접속·이동/외형·M06~M08 경계·M09 로비 18개 통과.
- 전용 시설 미리보기 M01~M09 26개 통과.
- 이후 관전자 차례 문구·실패 안내·관전 중 E 상호작용을 보완하고, 영향받는 오목/로비 5개와 M09 관전 1개를 재검증해 통과.
- 데스크톱 1920×1080/1280×720과 로비 390×844, 공개 관전 탑뷰/테이블 시점 화면 확인.
- 릴리스 빌드와 `check:migration` 통과. 공개 경기 참조 목업과 목업 안내가 운영 번들에 포함되지 않음.
- 최초 브라우저 실행 중 소스 갱신으로 기존 재접속 시나리오 한 건이 중단되었으나, 제품 코드 고정 후 해당 시나리오와 관련 전체 18개를 다시 실행해 통과.

기존 M05 일반 모드 테스트의 채팅 선택자 중복은 이번에 수정하지 않았다. 위 결과는 명시한 검증 집합이며 저장소의 모든 E2E를 한 번에 실행한 결과라는 뜻은 아니다.
