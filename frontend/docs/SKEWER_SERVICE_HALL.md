## 이번 구현 범위

**독립 PC 동선·조작 프리뷰**다. 2인 온라인 게임이나 공원 통합 완료가 아니다.

- 오버쿡드식 높은 고정 정투영 시점(약 50도), 낮은 벽, 가로 20 × 세로 11.4의 절개형 무대. 정면 매장 일러스트 구도를 폐기했다.
- 1인 원형 테이블 3개 + 2인 사각 테이블 3개, 실제 의자 9개. 중앙과 가로 통로를 열어 주문 전달/수령과 냉장고 방문을 묶어 이동할 수 있다.
- 고객 그림 말풍선: 실제 꼬치 조합 그림, 사케 병 수. 청소/주방 전달 대기/조리/수령 가능은 별도 상태 아이콘이다. 손님 대사는 없다.
- WASD/방향키 이동, 가구 충돌, 바닥·시설·테이블 클릭 시 길 찾기. 클릭은 이동만 하며 행동은 가까이 가서 E로 한다.
- 주문표 최대 2장, 접시 최대 2개, 사케 최대 2병. 테이블에 맞는 메뉴만 전달한다.
- 청소는 E 1.5초 유지. 키를 놓거나 이동하면 진행을 취소한다. 음식 운반 중 청소도 가능하다.
- 12초마다 입구 대기팀을 비어 있는 호환 테이블로 배치한다. 1인 우선 좌석/2인석 규칙을 적용한다. 이 프리뷰에서는 입장·퇴장 보행 연출 없이 좌석 상태를 전환한다.
- 도움말을 열거나 창이 비활성화되면 조작/프리뷰 시간이 멈춘다. CSS는 `.service-hall` 안으로 한정했다.

시작 상태는 동선 검토용 fixture다. 1·4번은 주문 대기, 2번은 청소 필요, 3번은 빈자리, 5번은 식사 중, 6번은 미리 완성된 접시 2개가 있다. 이 접시는 연결되지 않은 요리사가 자동 조리한 결과가 아니다. 주문을 주방에 넘기면 조리 대기 목록에 들어가며, 아직 온라인 요리사 제작을 흉내 내어 자동 완성하지 않는다.

빠른 확인: 2번 청소 → 1번 주문 접수/뒤쪽 전달 → 음식 수령대의 6번 접시 2개 수령 → 냉장고 사케 2병 → 6번 서빙 → 식사 후 청소.

**이번에 연결하지 않은 것:** 역할 선택/준비/경기 시작, 요리사 화면의 새 주문 큐, VR 입력, 두 컴퓨터 동기화, 영업 종료/결과/인사 이벤트, 점수/랭킹/엽전, 공원 진입·복귀·관전. 기존 단독 게임의 결제/보상 흐름은 변경하지 않았다. 새 버전이 무료라는 확정 기획과 기존 공원 구현은 아직 다르다. DB 파일 및 Flyway는 추가·수정하지 않았고, 팀원 사용 예정 V133을 점유하지 않았다.

현재 카탈로그의 기존 solo game ID는 `skewer`다. **새 co-op 서버 gameCode/등록을 추가하지 않았다.** 다음 단계에서 최신 공통 GameEngine/WS와 로비 흐름을 확인하고 인원 2명, 역할, 준비, 종료 사유와 DB CHECK를 함께 맞춘다. 게임 통신을 별도 서버나 공통 프레임워크로 복제하지 않는다.

서버 연결 시 필요한 게임별 입력은 접수·주방 전달·조립/제출·수령·사케 수령·서빙·청소 시작/취소·인사 응답·기권이다. 기존 actionId/expectedVersion 검증과 공통 권한 검사를 재사용한다. 서버는 위치/거리, 테이블 주문 ID, 메뉴 일치와 용량, 청소 유지 시간, 종료와 중복 정산을 판정해야 한다. 클라이언트 프리뷰의 이동·시간·점수는 권한 있는 결과가 될 수 없다.

- 공개 상태: 남은 시간, 팀 점수, 테이블 상태, 입구 대기, 운반/전달대 수량, 인사/연결 상태.
- PC 개인 상태: 손님 주문 그림, 받은 주문표와 테이블별 메뉴/진행.
- 요리사 개인 상태: PC가 전달한 작업만, 앞면 2장과 비공개 대기 순서. 미접수 주문을 publicState/렌더 말풍선에 섞지 않는다.
- 재접속: 역할·완료 메뉴·운반·큐·VR 자격 제외 플래그·일시정지 시계를 서버 스냅샷으로 복원. 서버 재시작 복원은 별도 구현/검증 전 보장하지 않는다.
- 공원 통합: 기존 VR 존 진입 등록, 공동 준비/결과, 무료 입장, 공유 일일 보상 한도, 공원 복귀, 채팅/입력 잠금, 관전 채팅/핑과 연결한다. 이번에는 공통 파일을 바꾸지 않았다.

## 시각 기준과 에셋

사용자 추가 지시: 첨부 이미지에서는 **음식 그림 말풍선만 참고**, 공간은 오버쿡드식 높은 고정 시점/이동 동선으로 구성. 초기 정면 매장 콘셉트는 공간 기준에서 제외했다. [Team17 공식 Overcooked! 2 자료](https://www.team17.com/games/overcooked-2)를 공간 참고로 확인했으며 게임 이미지/로고/캐릭터를 가져와 런타임에 사용하지 않았다.

보조 콘셉트: built-in image_gen, `exec-cb019003-ea94-4092-85d5-822638f6e4bf.png`. 새 고정 시점 방향을 검토하기 위한 이미지이며 사용자가 승인한 최종 도면이라고 간주하지 않는다. 생성 이미지의 장식/추가 테이블은 가져오지 않고 확정된 6개 테이블 규칙과 플레이 가능한 바닥을 우선한다. 실제 화면을 이미지 한 장으로 덮지 않았다.

- 배경 `#173d3c`, 목재 `#a76f43`/`#bd8651`, 짙은 녹색 `#214c35`, 말풍선 `#fff2d8`, 금빛 테두리 `#bf944c`.
- 제목은 프로젝트의 부산단디명조, 조작/수량은 읽기 쉬운 시스템 한글 고딕. 조작 키·음식/주문 슬롯·말풍선에 같은 크림/녹색 계열 적용.
- 식당: 이번 모듈에서 조립한 실제 3D 가구·번호판·식기·냉장고. 게임 소유 prop/post 헬퍼는 기존 로컬 꼬치 작업의 `RestaurantSet`/`RestaurantPost`를 복사해 독립 경로에 두었다. 이전 화면 배치나 배경 이미지는 공간 기준으로 사용하지 않았다.
- 음식: 최신 기준의 기존 `foodModels.ts`와 조합 규칙을 재사용. 같은 실제 3D 음식으로 말풍선용 600×200 PNG를 런타임 생성/캐시하므로 조합 그림과 접시 내용이 대응한다.
