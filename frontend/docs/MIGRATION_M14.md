# M14 붕어빵 이관

2026-10-24, `origin/dev`의 `ab4d7484cccfc10c92eaf70fff61c3563183ecba`에서 만든 `feat/frontend-m14-bungeoppang`의 FE 작업이다. 기존 혼합 작업 체크아웃은 보존한다. M15와 BE·Flyway·인프라·의존성·운영 에셋 파일은 변경하지 않는다.

## 원본 화면과 조작

원본 `features/bungeoppang`의 HUD/CSS·개인 철판·v2 표시 규칙·카메라 배치를 현재 프로젝트에 맞게 옮겼다. 기존 `fish-bread-cart.glb`를 재사용하며 Colyseus, 원본 서버, 브라우저 저장 기반 정산 서비스는 가져오지 않는다.

- 카트 인근에서 E → 시작 안내 → 3.5초 카운트다운 → 실제 60초 조리 → 결과 → 다시 하기/공원 복귀.
- 6칸 Q/W/E·A/S/D 또는 마우스 클릭. Space/휠 위는 반죽, 1/휠 아래는 팥. 우클릭·Shift+칸 키·Shift+클릭은 버리기.
- 익힘색·게이지·김/연기·재료 붓기·팥 넣기·뒤집기·꺼내기·잘못된 도구 흔들림, 판정 팝업, 콤보, 37초 예고/40초 손님 몰림을 유지한다.
- F1은 붕어빵 조작 안내다. 설명서·채팅·나가기 확인 중에는 조리 입력을 막지만 시간이 흐른다. 공통 설명서/지도 M15를 진행한 것은 아니다.
- 개인 철판과 카메라만 바뀐다. 카트 독점·대기열을 추가하지 않는다. 카메라를 가리는 간판과 주변 아바타는 이 클라이언트에서만 잠시 숨기고 복귀한다.
- 착석·관전·경기·다른 시설·채널 전환 중이거나 접근 거리/높이 밖이면 열지 않는다. 조리 중 이동·점프·다른 시설 진입을 막고 기존 월드 소켓과 정지 전송을 유지한다.

## 기존 BE 연결

이관 초안 이후 현재 BE에 MINI-01~04와 DB 정산이 구현되어 있다. `docs/minigame-api.md`, `MinigameController`, `MinigameService`, `BungeoppangRules`를 기준으로 연결했다.

| 시점 | 요청 | 반영 |
|---|---|---|
| 입장·명시적 재조회 | GET `/api/v1/minigames/sessions` | 오늘 누적·일일 상한·첫 판·확인한 팁·규칙 버전 |
| 시작 | POST 같은 경로, `{minigameType:"BUNGEOPPANG"}`, `Idempotency-Key` | 서버 발급 세션·64개 불 세기·v2 규칙 |
| 시작 영수증 확인 | GET `/api/v1/minigames/sessions/{id}` | 현재도 PLAYING인 본인 판인지 확인 |
| 완료 | POST `/{id}/complete`, `{log,seenTips,clientScore}` | 서버가 확정한 점수·개수·보상·누적만 결과로 반영 |
| 중단 | POST `/{id}/abandon`, `{}` | 승인 후에만 조리 화면에서 복귀 |
| 입장·정산 후 | GET `/api/v1/wallets/me` | HUD 잔액 재조회. FE에서 보상을 더하지 않음 |

기존 `ParkRuntime`의 Bearer 인증·401 갱신·로그인 종료 처리를 재사용하는 허용 경로 제한 REST 포트를 추가했다. 타임아웃·이전 공원 연결의 취소 신호도 전달한다. 사용자 ID·난수·확정 점수·지급량을 클라이언트가 결정해 전송하지 않는다.

진행 중 점수는 미리보기다. 서버 발급 불 세기로 표시를 계산하고 최대 1,200개의 정수 밀리초 조리 기록만 보낸다. 같은 칸 300ms/전체 50ms 간격을 지킨다. 하루 100냥 및 KST 날짜 경계는 서버 응답을 따른다.

응답 유실 시 시작 키와 완료 로그를 해당 방문 동안 보존해 수동 재시도한다. 정산 결과가 불명확하면 새 판을 막는다. 다른 방문의 늦은 응답은 적용하지 않는다. 새로고침·나가기 이후의 영구 재시도 보관과 자동 재전송은 제공하지 않는다. 확인되지 않은 결과에서 나갈 때는 기록 손실을 안내한다.

### 목업과 남은 경계

핵심 조리·정산·지갑은 실제 API만 사용한다. HTTP/WS 응답 대역은 `tests/e2e/bungeoppangFixture.ts`, 서비스 대역은 단위 테스트에만 있다. 404/503·인증 실패를 브라우저 정산으로 바꾸지 않는다. 운영 소스에 목업 로그인·localStorage 보상·가짜 성공을 추가하지 않았다.

타인의 원격 **‘붕어빵 굽는 중’** 상태를 알리는 월드 이벤트는 확인한 BE 계약에 없다. 원본에도 미연결로 남았던 신규 계약 항목이므로 임의 WS 코드를 만들거나 타인의 상태를 추측해 표시하지 않는다. 필요하면 입장/중단/완료/단절 때의 공개 상태 전달 계약을 BE와 확정해야 한다. 개인 로그·불 세기·지갑을 공개 이벤트로 보내면 안 된다.

현재 BE 활성 조건은 `(local | dev) & db & !prod & !production` 및 `ontop.minigames.enabled=true`다. dev 설정의 기본값과 지갑 존재 여부는 배포 환경에서 확인한다. 이번 FE 작업에서 프로필·DB·설정·마이그레이션 버전을 바꾸지 않았다.

## 철판 최적화와 검수

원본 윤곽·익힘색·연출은 유지하고 빵/반죽/팥/강조 테두리도 인스턴싱했다. 칸별 클릭 판정은 분리하고 2.2m의 로컬 바운드로 짧은 흔들림·뒤집기·꺼내기를 포함한다. 맵 전체 병합이나 프러스텀 컬링 해제는 하지 않는다. 개인 근접 화면에서만 생기는 작은 철판이므로 별도 원거리 LOD를 추가하지 않았다.

형상 6개를 공유하고 재질은 18→9개다. 철판의 형상·인스턴스 버퍼 추정은 26,768→28,760B다. 인스턴스 행렬/색 버퍼 때문에 1,992B 늘어난다. 마운트 해제 시 개인 형상·재질·인스턴스 자원을 정리하며 공유 카트 리소스는 해제하지 않는다. 신규 이미지/GLB 다운로드는 0B다. 작은 절차 형상에는 Meshopt/KTX2 재인코딩을 적용하지 않았다. 기존 카트의 Meshopt/WebP/거리 스트리밍·LOD를 유지한다. 추가 실시간 그림자·후처리는 없다.

측정: Core Ultra 9 185H/Intel Arc ANGLE D3D11, Edge156/WebGL2, 1920×1080 Low(내부1280×720), 같은 카메라·16인 정지 장면·HTTP/WS 응답 대역. 낮 phase .6/심야 .05의 실제 조명값을 검사했다. 프레임 표본 약300개와 GPU timer12개씩이다. CPU 렌더 단계만 분리한 측정은 없으며 프레임 분포로 기록한다.

관측한 전체 형상 버퍼 추정은 철판 있음43,843,200B/없음43,817,200B, 텍스처 RGBA8+mipmap 추정211,435,520B로 같다. 이 전체 형상 집계에는 인스턴스 버퍼가 빠져 있어 위의 철판 별도 집계를 함께 기록했다. 드라이버의 실제 GPU 메모리 측정은 아니다. 3회 철판 생성/해제 후 형상229개·텍스처32개로 복귀했다. 재생성 구간의 최대 프레임은116.2ms로 별도 컴파일/마운트 지연이 남으며 평상시 프레임 개선과 혼동하지 않는다.

## 동작 검증과 한계

- FE 단위 테스트30개 파일/263개, 소스·테스트 타입 검사, 프로덕션 빌드와 이관 경계 검사가 통과했다.
- M14 브라우저2개: 실제60초, 클릭/6키·도구·휠·버리기·F1, 시작 응답 유실 후 같은 키, 완료 응답 유실 후 같은 로그, 서버 형식 결과·지갑 표시, 재시작, 중단 거절 후 재시도, 아바타/HUD/이동 복귀, BE503에서 가짜 정산 미사용을 확인했다.
- 추가 브라우저1개에서 실제60초 조리 기록을 변경하지 않은 BE `BungeoppangRules` Java 클래스에 직접 재생했다. 양면 황금6개·점수71·최고 콤보6이 FE 미리보기와 일치했다. 이 검증의 HTTP·월드·인증·지갑 저장은 대역이며 DB 정산 검증은 아니다.
- 기존 이동·공통 테이블·오목·주사위·원카드·다리의 참가자/관전자 회귀28개를 확인했다. 첫 실행의 주사위1개는 검사 도중 주석 파일 갱신으로 Vite가 페이지를 재시작해 실패했다. 소스 동작을 바꾸지 않고 해당1개를 재실행해 통과했다.
- 기존 BE의 규칙·서비스·인증 HTTP·dev CORS·production 제외 테스트53개가 통과했다. 서비스 테스트의 저장소/트랜잭션은 테스트 대역이다.
- 브라우저의 완료 응답/지갑은 HTTP 계약 대역이므로 실제 DB 지급 검수가 아니다. 실제 DB의 판 소유·동시 정산·자정 상한·지갑 지급은 배포 후 확인 대상이다. OAuth와 운영 배포는 실행하지 않았다.
- Browser plugin이 없어 기존 Playwright/Edge를 사용했다. 페이지 오류와 Vite 오류 오버레이가 없음을 확인했다. 기존 Three.Clock/ANGLE 정밀도·큰 WorldCanvas 청크 경고가 남는다.

원시 JSON·스크린샷·비교용 스크립트는 Git 밖 QA에 보관한다. 이 문서는 구현 기록이며 BE 담당자 전달용 문서를 Git에 추가한 것은 아니다.
