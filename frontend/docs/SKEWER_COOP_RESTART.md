## 흐름

1. COUNTDOWN/PLAYING에서 연결된 참가자 한 명이 ‘다시 시작 요청’을 누르면 요청자의 동의로 간주한다. 기존 일시정지/다른 재시작 요청 중에는 새 요청을 받지 않는다.
2. 서버가 요청 번호·요청자·15초 만료 시각을 공개한다. 두 사람의 영업/인사/세척/이동을 잠시 멈춘다. 응답 제한과 연결 끊김 제한은 실제 시각으로 계속 계산한다.
3. 상대방만 동의 또는 거절할 수 있다. 요청자 자기 승인, 비참가자, 이전 요청 번호, 만료 뒤 승인, 연결 끊긴 참가자의 승인은 거절한다.
4. 동의하면 같은 경기와 역할을 유지하고 점수·영업시간·주문·트레이·보관대·전달대·식기·세척·제작 수·인사 이벤트·손님/대기열·서빙 위치를 초기화한다. 두 화면 모두 3·2·1부터 시작한다.
5. 거절/15초 무응답이면 현재 경기의 점수·음식·주문을 보존해 재개한다. Esc는 수신자의 거절로 처리한다. 요청자 화면은 서버의 응답/만료를 기다린다.
6. 연결이 끊기면 요청을 취소하고 기존 공동 일시정지/30초 재접속 만료 종료를 유지한다. 종료/기권 시 남은 요청도 제거한다.

## 통신 계약과 안전성

- 요청: `{type:'RESTART_REQUEST'}`
- 응답: `{type:'RESTART_REPLY',requestId:string,accept:boolean}`
- 공개 상태: `round`(0부터 증가), `restart:null | {id,requestedBy,expiresAt}`. `pauseReason:'RESTART_CONFIRM'` 및 `paused:true`로 입력을 막는다. 주문 원본은 기존 개인 상태에만 둔다.
- 서버의 actionId 멱등성과 actionVersion 검증을 유지한다. 재시작에도 경기 버전·행동 버전·접시 ID·요청 번호를 되돌리지 않는다. FE도 이전 round의 대기 입력과 stale-version 재전송을 새 판에 보내지 않는다.
- 중간에 버린 판은 종료/보상 이벤트를 발행하지 않는다. 최종 종료된 판만 기존 정산을 따른다. PC 전환 등으로 잃은 랭킹 자격은 같은 경기에서 복구하지 않는다.
- 진행 상태와 동의 요청은 기존 경기와 같은 서버 메모리에 존재한다. 서버 프로세스 재시작 시 경기/동의 요청 복구를 새로 보장하지 않는다. 정산 저널과 별개다.
