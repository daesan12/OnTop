## 조작과 상태

가까운 사용자를 바라보면 기존 상호작용 안내에 `E · ○○ 님 들기`가 표시된다. 시설과 캐릭터는 같은 시선·거리 선택 경로를 사용한다. 수평 거리 2.6m, 높이 차이 2m 이내에서 서버가 들기를 승인한다. 양쪽 모두 일반 달리기·점프 도중에도 들고 던질 수 있다. 점프 입력 대기 중인 운반자의 점프는 유지하고, 잡힌 사용자의 이전 이동·점프·위치 검증 상태는 기존 `hold` 경로로 정리한다. 수평 거리는 기존과 같고 높이 허용 범위는 점프를 잡기 위해 0.8m에서 2m로 늘렸다. 서버 충돌체가 두 사용자 사이를 가리거나 머리 위 공간이 막히면 승인하지 않는다.

들고 있는 동안에는 기존 시설 대신 `E · 캐릭터 방향으로 던지기`와 `Esc · 내려놓기`를 표시한다. 들린 사용자는 A·D를 번갈아 6회(ADADAD 또는 DADADA) 눌러 탈출한다. 화면에는 작은 `A ↔ D` 두 키만 표시하고, 두 키가 번갈아 내려갔다 올라오며 눌린 키의 색이 바뀌는 반복 모션으로 연타를 안내한다. 횟수·탈출 설명 문구는 화면에서 빼고 스크린리더용 이름으로 유지한다. 모션 감소 환경에서는 반복 모션을 멈추고 두 키와 화살표를 정적으로 표시한다. E·Esc·내려오기 버튼으로 즉시 탈출하지 않는다. 자동 키 반복은 세지 않으며 같은 키를 다시 누르거나 1초 이상 쉬면 새 시도로 시작한다. 창·텍스트 포커스·연결/운반 관계 변경 뒤 이전 입력 횟수를 이어받지 않는다. 마지막 입력에서 기존 `WORLD_CARRY_RELEASE`를 한 번 요청하며 실패하면 재시도할 수 있다. 운반 시간 제한은 없으며, 막힌 공간·접속 종료·채널 퇴장·다른 활동 시작 때의 안전 해제와 운반자의 내려놓기는 유지한다. 들고 걷는 동작은 유지한다.

## 행동 충돌 방지

들기와 던지기는 본인과 상대방 모두를 검사한다.

- 보드게임 참가·테이블 착석, 미니게임 진행, 경기 관전.
- 벤치·운동기구·망원경 사용, 수영, 감정표현, 따라가기 관계, 돌탑 도전.
- 채팅·상점·옷장·설명서·지도 등 다른 창이 키 입력을 점유하는 상태.
- 이미 운반·비행 중이거나 접속이 끊긴 대상. 일반 달리기·점프는 허용하며 돌탑 점프맵 도전은 기존 다른 활동 제한을 따른다.

서버 게임·시설 상태는 클라이언트 선언과 독립적으로 검사한다. 창 점유는 창 종류·본문을 노출하지 않는 `interactionBusy` 값만 공유한다. 클라이언트는 약 100ms마다 변화를 확인하고, 값이 바뀔 때만 전송한다. 창을 열면 던지는 대신 운반을 해제한다. 점유 해제 패킷으로 서버의 게임·시설 제한을 해제할 수 없다.

일반 창 점유 변경은 요청자에게 `{channelId, busy}` 확인 응답만 보낸다. 다른 사용자에게는 기존 10Hz 월드 틱에서 여러 변경을 합쳐 전달하며, 플래그만 바뀐 경우 전체 플레이어의 물리 좌표를 다시 읽지 않는다. 실제 운반·비행 해제가 발생할 때만 즉시 `WORLD_STATE`를 방송한다. 운반 참여자만 창 점유를 보내도록 제한하지 않아, 창을 열고 있던 일반 사용자도 들기 대상에서 보호한다.

채팅·팝업의 E와 Esc는 기존 입력 소유권을 따른다. 운반 도중 테이블·시설·따라가기·감정표현 진입도 서버에서 차단한다. 중복·늦은 던지기 및 해제는 관계별 `carryId`로 거절한다. 한 사용자는 운반 관계 하나만 가질 수 있다.

## FE/BE 공개 계약

모든 요청은 기존 인증 Raw WebSocket과 TableHub 잠금을 사용한다. 요청 사용자 ID는 인증된 연결에서 가져온다.

| 요청 | payload | 성공 응답 |
| --- | --- | --- |
| `WORLD_CARRY_PICKUP` | `{targetId}` | `WORLD_STATE` |
| `WORLD_CARRY_THROW` | `{carryId, dx, dy, dz}` | `WORLD_STATE` |
| `WORLD_CARRY_RELEASE` | `{carryId}` | `WORLD_STATE` |
| `WORLD_INTERACTION_SET` | `{busy}` | `WORLD_INTERACTION_STATE` (`{channelId, busy}`) |

`WORLD_STATE.avatars[].carry`는 `null` 또는 `{carryId, partnerId, role}`이다. role은 `CARRIER`, `CARRIED`, `THROWN`이다. 같은 채널만 수신한다. 창 점유 중에는 `interactionBusy: true`를 추가한다. 새 서버는 `carry: null`도 명시하며, 구 서버가 이 필드를 생략하면 FE는 들기 안내와 창 점유 전송을 활성화하지 않는다.

주요 오류는 `CARRY_TARGET_UNAVAILABLE`, `CARRY_ACTIVITY_CONFLICT`, `CARRY_OUT_OF_RANGE`, `CARRY_UNAVAILABLE`, `CARRY_LINK_MISMATCH`, `INVALID_PAYLOAD`이다. 관계·비행은 채널 물리 인스턴스의 일시적 상태이며 서버 재시작 복구를 보장하지 않는다. 지갑·정산·게임 엔진 계약은 변경하지 않는다.

## 리뷰 반영: 공간 검사와 내려놓기

`canOccupy`는 기존 충돌 마스크에 더해 접촉 콜백에서도 상대 객체의 충돌 그룹이 지형 그룹 2인지 검사한다. 캐리어와 다른 플레이어는 공간 차단 대상으로 보지 않으며, 정적 벽·천장은 계속 검사한다.

운반 중 캐리어가 접지한 상태로 20cm 이상 이동하면 검증된 내려놓기 위치를 갱신한다. 해제 시에는 현재 발밑 → 4m 이내의 최근 검증 위치 → 현재 높이 주변의 안전한 지지면 순서로 확인한다. 근처 지지면이 없어도 현재 공중 위치에 충돌이 없으면 그곳에서 자연스럽게 떨어지게 한다. 현재 위치가 막히고 주변 탐색도 실패한 예외에만 아래 지형 및 기존 공원 복구 경로를 사용한다. 캐시에 저장한 좌표도 해제 시 다시 검증한다.

추가 회귀는 다음을 확인한다.
