# 새 공원 맵의 소리함·메모함 FE 연동

기존 메모 주제·작성 알림 커밋 `846aae7f`에 최신 dev `56a31e75`의 생성 맵을 병합했습니다. 소켓 런타임 충돌은 새 맵 입장 확인과 이동 입력 승인 처리를 유지하면서 메모 알림 처리를 함께 보존하는 방식으로 해결했습니다. 직접 수정한 범위는 frontend입니다.

## 적용 경로

- 개발 배포의 기존 `build:park` 경로(`park-integration` 모드)를 사용합니다. Jenkinsfile과 vercel.dev.json의 새 맵 빌드 설정은 변경하지 않았습니다. 로컬 실행은 `pnpm dev:park`, 빌드는 `pnpm build:park`입니다.
- 소리함 위치는 `[-18,0,18]`, 메모함 모델 위치는 `[60.5,18.12,54.5]`, 메모함 접근 기준은 `[60.5,18.92,54.5]`입니다. 위치·접근 판정은 기존 mapConfig의 선택 맵 데이터를 사용합니다. 모델은 최신 dev의 맵 어댑터 배치를 유지합니다.
- 승인 맵은 schemaVersion 2, mapVersion `cac3cb040a43630b0b40201ab089a4b328146c03211867b2a155d2b3614acc81`입니다. 맵 확인을 통과한 기존 소켓에서만 메모 알림을 처리하며, 구맵 서버나 맵 정보 누락은 기존대로 입장을 거절합니다. 버전 검사를 우회하거나 맵 형상·해시·BE 리소스를 변경하지 않습니다.
- 메모 주제 5종과 300자, 소리함 600자를 유지합니다. 다른 사용자의 작성 알림 갱신, 작성 중 원문·주제·커서 보존, 중복 revision 무시, 창 닫기와 다시 열기, 월드 에셋의 실제 메모 표시를 새 맵에서 검증합니다.

## 검증

생성 산출물 일치 검사, FE/테스트 타입 검사, 새 맵 production build와 FE 경계 검사를 통과했습니다. 전체 단위는 1,451개 통과·4개 기존 제외이며, 이후 추가된 dev의 붕어빵 랭킹 변경 검사 7개도 별도로 통과했습니다. 무거운 형상 검사를 위해 실행 명령에만 `--maxWorkers=4 --testTimeout=20000`을 사용했습니다. Windows의 일시적 파일 잠금은 기존 파일을 삭제하지 않는 제한된 rename 재시도로 복구하고, 영구 오류·다른 오류는 그대로 실패합니다. 생성/감시 검사와 복구 로직 검사도 통과했습니다.

브라우저는 새 맵 5개 시나리오(소리함 전송·메모 작성/알림·기본 공원 흐름·구맵/누락 정보 거절)와 기존 맵 알림 3개 시나리오를 통과했습니다. 초기 로딩 제한과 예전 임시 테이블 ID 기대값은 최신 맵 로딩·바인딩 기준으로 수정해 재실행했습니다. 로컬 HTTP/WS fixture 검증이며 실제 개발 DB 저장·배포 완료와 구분합니다.

## BE 담당자 전달용

새 공원 맵 기준으로 소리함·메모함 FE 연동을 반영했습니다. 위 맵 버전과 배치가 적용된 서버에서 메모 category와 NOTES_CHANGED, 소리함 비공개 접수 API가 활성화되어 있는지 확인해주세요. V129 적용과 NOTES_ENABLED/기존 privacy-secret 설정, 배포 커밋·환경을 공유해주시면 실제 두 사용자 저장·알림을 공동 검수할 수 있습니다. 비밀값을 전달하실 필요는 없습니다.

메모함 충돌은 활성 맵의 형상·통로 정책에 맞춰 BE와 확정해야 합니다. 과거 확대 요청서의 단일 상자 수치를 새 맵에 임의로 복사하지 않았습니다. 새 맵에서 필요한 최종 충돌 정의와 변경 후 mapVersion을 공유해주세요. FE가 맵 버전이나 물리 정의를 독자적으로 바꾸지 않았습니다.
