# 팀 BE 로컬 실접속 검증 준비

2026-10-22 사용자에게 전달받은 팀원의 안내를 FE 실행 설정에 반영한다. 안내문과 실제 소스/실행 상태를 구분하며 BE 소스나 환경 파일을 수정하지 않는다.

## FE 실행

frontend에서 pnpm dev:frontend-test 실행. localhost:5173 고정·포트 점유 시 실패하며 다른 서버를 덮어쓰지 않는다. 이 Vite 개발 모드에서만 public/park-bindings.frontend-test.json을 읽는다. 일반 실행/production build는 기존 park-bindings.json을 유지한다. 테스트 파일은 임의 계정이나 로그인 우회 경로가 아니라 승인받은 공개 테이블 ID의 배치 대응이다.

기존 Vite의 /api/v1 및 /ws/tables 프록시를 사용하며 기본 BE 대상은 http://127.0.0.1:8080이다. 소켓 생성자는 기존 ParkRuntime 한 곳뿐이다. 전달된 안내의 “WebSocket 프록시 없음”은 현재 FE와 다르므로 별도 직접 연결/두 번째 소켓을 추가하지 않는다. 실제 BE에 연결되면 접속권 발급과 WS 핸드셰이크의 Origin 일치를 확인해야 한다.

테스트 모드의 channel-1/2와 table-1/2(좌표 -10/0/18, 10/0/18)만 매핑한다. 요청에는 서버 UUID tableId를 사용하고 실제 REST 목록에 있는 ID만 허용한다. 나머지 장식 테이블을 임의로 개방하지 않는다. mapVersion은 기존 지문 검사를 유지하며 팀의 기계 판독 배치 파일을 받은 뒤 재대조한다.

## 현재 확인한 상태

- http://localhost:8080/actuator/health는 연결 거부였다. 실제 BE 미실행이며 건강 상태 UP을 확인한 결과가 아니다.
- 사용자가 지정한 BE 폴더에서 scripts/start-frontend-test.ps1, application-frontend-test 프로필, .env.frontend-test 및 frontend-test-layout.json을 찾지 못했다.
- 조사 시점 GitLab dev93649cf에도 안내한 테스트 파일이 없다. 원격에 별도 frontend-test 브랜치도 확인되지 않았다. 로컬 ZIP에는 Git 메타데이터가 없어 임의 git pull하지 않는다.
- 5173에는 기존 Node 개발 프로세스가 있어 종료하거나 다른 앱으로 교체하지 않았다.
- 실제 계정·OAuth·MySQL·WS·두 계정 이동/채팅/착석/재접속은 아직 검증하지 못했다. FE 배치 데이터·모드 분리 검사는 실접속 검증을 대신하지 않는다.

## 준비된 뒤 확인할 순서

1. 안내한 테스트 파일이 포함된 소스 버전과 필요한 로컬 DB/OAuth 설정을 확인한다. 실행기의 -Check 통과 뒤 BE를 실행하고 health UP을 확인한다.
2. localhost:5173에서 두 실제 회원을 서로 다른 브라우저/독립 세션으로 로그인한다. OAuth 인증 조작은 사용자가 직접 수행한다.
3. 각각 새 접속권·소켓 하나, channel-1 선택, 실제 목록과 테이블 ID 일치를 확인한다.
4. 두 계정의 이동/위치 공유·20m 근접 채팅·동일 테이블 착석·게임 선택/준비·대기 중 단절과 재입장을 검증한다.
5. 인증 종료·중복 계정 연결 거절·Origin/프로필/소스 커밋을 구분해 기록한다. 토큰/접속권/쿠키를 검증 보고서에 남기지 않는다.

팀 안내에 따르면 이 프로필은 실제 DB 판돈 차감·경기 시작·종료 정산을 연결하지 않는다. 전원 준비 성공을 실제 오목 시작/정산 성공으로 표시하지 않는다. 경기 중30초 복귀도 대기 중 재접속과 별도이며 해당 기능을 활성화한 실행 환경이 필요하다.
