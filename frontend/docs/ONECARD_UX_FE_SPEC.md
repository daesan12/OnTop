## 상태·권한

게임 상태와 표현 상태를 분리한다. `useGame`의 version·hand·playableCardIds·canDraw는 변경하지 않는다. 뒤집힌 카드의 DOM에는 앞면 텍스트·aria-label을 남기지 않는다. 선택/제출은 cardId로 유지하며 뒤집힌 카드를 클릭하면 제출 대신 전체 복구한다.

선택은 gameId/userId/version 범위로 관리한다. 요청 중에도 보호할 cardId를 유지한다. 서버 상태 갱신 후 이전 선택이 표시되지 않게 한다. 관전자에게는 privateState를 요구하지 않는다.

장난 transport는 `VITE_ONECARD_PRANKS=true`일 때만 활성화한다. 기본값 false. 이는 BE 지원 여부 자동 탐지가 아니다. 운영 활성화는 BE 계약 확정·서버 배포·다중 계정 검수 이후에 한다. 미지원/권한 오류는 장난만 비활성화하고 카드 게임 입력·복구 오류와 섞지 않는다.

## UX 검수

1920×1080·1280×720·390×844에서 손패·제출·드로우·정리 접근을 확인한다. 전 좌석 카메라 수치는 단위 테스트하며 실제 장면에서 상대/테이블 가림을 검수한다. reduced-motion에서는 회전·들어올림 전환을 제거한다. 54장 탐색, 마지막 한 장, 무늬 선택, 공격 누적, 기권·복구·오래된 버전 차단을 확인한다.

## 4인 화면과 관전자 개입 추가 검수

사용자 요청에 따라 `onecard-four-player.spec.ts`를 추가했다. P1 정자의 네 좌석에 도윤(7장)·민지(5장)·준(4장)·하늘(3장)을 배치하고, 별도 브라우저 컨텍스트의 구경꾼(505)이 벤치에 앉아 동일 경기를 관전한다. 네 참가자의 실제 렌더 모델·좌석 번호·머리 위 닉네임을 확인한다. 플레이어 1명과 관전자 1명의 두 창을 조작하며, 나머지 세 참가자의 경기·월드 상태는 모의 서버가 제공한다.

공유 모의 이벤트 중계를 통해 관전자 버튼 클릭 → 플레이어 창의 비선택 카드 2장 뒤집힘 → 선택한 하트 J 및 제출 가능 상태 유지 → 손패 정리 한 번 → 양쪽 창에 복구 반영을 검증했다. 관전자는 private hand=null을 유지하며 같은 차례에 재사용할 수 없다. 관전 UI에는 요청 중·개입 적용·복구 완료를 구분하는 상태 문구를 추가했다.

1920×1080에서 플레이·관전자 개입 전/후·플레이어 뒤집힘/복구 화면을 캡처하고 `view_image`로 직접 확인했다. Browser 플러그인이 없어 기존 Playwright/Edge 경로를 사용했다. 이 검수는 신규 BE 장난 계약의 실제 서버 배포나 실제 다섯 계정의 공동 접속 검증을 의미하지 않는다.

재현: `node node_modules/@playwright/test/cli.js test --config playwright.onecard.config.ts onecard-four-player.spec.ts`. 기본 장난 비활성 설정은 유지하며 테스트 서버에서만 `VITE_ONECARD_PRANKS=true`를 적용한다.

## 2026-10-28: 1인칭과 3D 공간의 2D 인터페이스

이번 사용자 수정 요청은 초기 어깨 너머 구도보다 우선한다. 실제 PLAYER 경기에서는 자기 좌석의 중심선에서 테이블을 보는 1인칭을 사용하고, 로컬의 자기 캐릭터를 숨긴다. 상대·관전자 화면의 내 캐릭터는 유지한다. 별도 3D 손패·월드 공간 버튼은 만들지 않으며 기존 DOM 손패와 버튼을 화면 좌표에 고정한다.

첨부 카드 레퍼런스의 크림색 앞면·모서리 숫자·무늬·가운데 정렬된 능력 문구를 적용했다. 특수 카드에는 능력명과 짧은 설명을 표시하고 일반 카드에는 추가 문구를 넣지 않는다. 글자가 가려지지 않도록 얕은 부채꼴·적은 겹침과 데스크톱 8장/좁은 화면 3장 묶음을 사용한다. 뒤집힌 카드에는 설명 DOM·aria-description도 남기지 않는다.

공개 바닥 카드·덱·뒷면 소품은 X/Z 크기를 80%로 줄이고 테이블 높이·배치는 유지한다. 테이블 스케일은 X/Z에만 적용되므로 눈높이와 바라보는 높이를 확대 정자 배율로 올리지 않는다. 준비/결과·다른 게임의 시점과 기존 입력 권한은 유지한다.

검수 대상은 4인 좌석·자기 모델 숨김·상대 모델/이름표 유지·2D 카드 설명 가독성·일반 카드 설명 생략·공개 카드 축소·선택/드로우·관전자 뒤집기/전체 복구와 1920×1080·1536×1024·1280×720·390×844 레이아웃이다. Browser 플러그인이 없어 기존 Playwright/Edge 검증 경로를 사용한다.

최종 검증: TypeScript 앱/테스트 타입 검사, 관련 단위 테스트 5개 파일 41건, 원카드 E2E 7건, Vite 프로덕션 빌드 통과. 4인 플레이·관전자 개입 전후와 데스크톱/모바일 캡처를 확인했다. 빌드는 기존 대용량 청크 경고가 남는다. 관전자 개입 E2E는 위 공유 mock 전송 계층을 사용하며 실제 BE 연동 완료를 의미하지 않는다.

### 후속 카드·게임판 스타일 수정

사용자 요청에 따라 설명 문장과 `cardDescription`을 제거하고 기존 `cardEffect`의 짧은 능력명만 표시한다. 일반 카드에는 문구를 넣지 않는다. 아이보리 그라데이션·금색 내부 테두리·희미한 워터마크·하단 반전 숫자/무늬로 앞면을 다듬고, 뒤집기 뒷면은 청록 격자·금색 중앙 장식으로 통일한다. 공개 카드도 같은 팔레트를 쓴다.

`game/onecard/artwork.ts`는 CanvasTexture로 펠트 질감·이중 금색 외곽선·모서리 장식·네 무늬 메달리온·카드 더미 영역을 만든다. 정적 펠트/뒷면은 원카드 최초 표시 시 한 번 생성해 재사용하고, 공개 앞면은 카드 변경/해제 시 기존 수명 관리대로 정리한다. 비공개 손패는 3D 재질에 포함하지 않는다. 공용 테이블·카메라·서버 계약은 이번 수정에서 바꾸지 않는다.

검증 환경: `http://127.0.0.1:5213/park`, headless Edge/Playwright. Browser plugin not available. 1920×1080·1536×1024·1280×720·390×844를 캡처했다. `/park` → 원카드 착석/준비 → J 선택 → 관전자 뒤집기 → 손패 정리로 두 장 복구, 그리고 낼 카드가 있어도 드로우 → 다음 차례 전환·모바일 손패 탐색을 확인했다. 페이지 제목·실제 경기 내용·오류 overlay 부재·console error 부재·스크린샷·상호작용 검증이 통과했다. 기존 THREE.Clock 폐기 예정/셰이더 정밀도 경고는 남는다.

원카드 단위 테스트 21건, E2E 전체 7건, 마지막 간격 수정 후 UI E2E 3건 재검증, TypeScript 앱/테스트 타입 검사와 Vite 빌드가 통과했다. 실행은 기존 `playwright.onecard.config.ts`와 직접 Node CLI를 사용했다. 시안과 최종 4인/모바일 캡처를 `view_image`로 대조했다. 이번 검증은 mock 서버 계약을 사용하며 실제 BE 관전자 이벤트와 다른 브라우저의 공동 접속 검증은 포함하지 않는다.

### 상대가 든 손패와 간결한 HUD

`OneCardHeldHand`는 아바타의 양손 뼈 중간 위치를 추적해 공개 카드 수 기반의 뒷면 fan을 표시한다. 실제 카드 앞면·ID·무늬는 구독하지 않으며 양면 모두 공용 뒷면이다. 후속 요청에 따라 10장 제한을 제거하고 최대 54장까지 실제 공개 카드 수와 같은 수를 아바타별 instanced mesh 하나로 표시한다. 정규화된 fan 좌표로 장수가 많아져도 손 안의 범위를 벗어나지 않는다. 테이블에 누워 있던 손패 소품은 제거한다. 자신의 아바타는 본인 1인칭 화면에서 숨겨지고 관전자에게는 동일한 손패 소품이 보인다. 비활성·손패 0장·경기 종료·다른 테이블에서는 표시하지 않는다.

원카드 자세는 `heldHand.ts` 안에 둔다. 공용 `avatarMotion`에는 선택적인 앉은 자세 콜백만 추가하고, 원카드 경기 참여자에게만 주입한다. 이모트/패배 반응은 기존 우선순위를 유지하며 종료/퇴장/다른 게임에서는 기본 자세로 돌아간다. 공용 캐릭터 모델·재질을 수정하지 않는다.

좌상단 제목·규칙 한 줄, 손패 제목·강조 카드 안내, 드로우 설명, 차례·회전 방향·덱/턴 수·시간 부연 문구를 DOM에서 제거한다. 좌상단에는 `남은 시간 / N초` 타이머만 표시하고 5초 이하에서 강조한다. 서버 마감 시각을 따르며 0초에서는 기존 행동 차단을 유지한다. 무늬 선택 버튼·원카드 선언/신고·공격·복구/오류·결과/승리 등 실제 행동과 필수 상태는 유지한다.

손패의 숫자·무늬는 왼쪽 위와 오른쪽 아래를 동일 크기로 맞추고 아래는 180도 회전한다. 화면 테스트는 제목/손패/드로우 안내 부재, 아래 숫자와 회전, 남은 시간/만료 시 입력 차단, 4인 공개 장수 기반 손패와 관전자 비공개 손패 차단을 확인한다. 실제 남녀 캐릭터 리그로 얼굴 아래 손패 높이와 원카드 종료 후 기본 자세 복원을 단위 검증한다.

검증: 관련 단위 테스트 4파일 35건, 원카드 E2E 7건, 최종 손패 높이 조정 후 UI E2E 3건, 앱/테스트 타입 검사·프로덕션 빌드 통과. Browser plugin not available이므로 기존 로컬 `127.0.0.1:5213/park`의 Playwright/Edge 경로를 사용했다. 페이지 제목·경기 내용·오류 overlay/console error 부재, 선택·드로우·무늬 선택·선언/신고·0초 입력 차단·관전자 뒤집기/전체 복구를 검증했다. 4인 플레이·관전자·390×844 모바일을 캡처하고 최종 화면을 직접 확인했다. 기존 THREE.Clock/셰이더 정밀도·대용량 청크 경고는 남으며 실제 서버 관전자 계약과 다른 브라우저 공동 접속 검증은 범위 밖이다.

### 정확한 장수·공통 지도 차단·Esc 기권·마감 다듬기

- 상대 손패의 실제 인스턴스 수가 공개 장수와 같도록 10장 상한을 제거했다. 1·7·17·54장 fan이 같은 손 범위에 들어오는 단위 검증과 두 창에서 17→1→5장 증감을 확인하는 E2E를 추가했다. privateState는 계속 2D 개인 손패만 사용한다.
- `navigation/mapAccess.ts`에 네 게임에 공통인 지도 차단 정책을 둔다. `ParkMap`의 버튼·M 입력과 `openParkMap`의 직접 호출에 같은 정책을 적용하고, 게임 시작 시 지도/길 안내를 닫는다. 정상 공원 지도와 이동 경로 선택 기능은 유지한다.
- 채팅 입력란 높이를 `--chat-composer-height`로 공유한다. 접힌 전송 아이콘과 열린 입력란의 전송/닫기 버튼은 내부 높이에 맞추고 최소 크기·줄바꿈 때문에 밖으로 밀리지 않게 한다. 일반 공원은 52px, 게임의 작은 입력란은 36px다.
- 정상 플레이의 우상단 규칙/새로고침/기권 도구는 제거했다. 관전 종료·시점 변경과 오류/복구·결과 확인은 필요한 상태에만 별도 컨트롤로 유지한다. `OneCardForfeitDialog`는 body portal의 native dialog로 Esc 입력을 받고 기존 `canStartForfeit`/`canRetryForfeit`와 runtime 계약을 사용한다. 최초 포커스는 `계속 플레이`에 두고 Esc 취소 후 이전 카드 포커스를 복원한다. 채팅·IME·다른 대화상자는 Esc를 먼저 처리하며 기권은 최종 확인 클릭에서만 요청한다. 응답 유실·3인/4인 탈락 후에도 같은 actionId의 명시적 확인 경로를 제공한다. 다른 게임 기권 UI는 유지한다.
- 남은 시간 글자는 데스크톱 42px/모바일 34px로, 공개 카드 요약은 68×96px/56×80px로 확대했다. 무늬 글자도 확대하고 카드 종이 음영·금색 이중 프레임·펠트 자수/모서리 곡선과 카드 더미 영역을 다듬었다. 기존 디자인 시스템 안의 코드 재질/CSS 수정으로 구현하며 새 배경 에셋은 추가하지 않는다.

검증 흐름: 일반 공원 지도 열기/닫기 → 게임 입장 → 지도 버튼/M/직접 호출 차단 → 채팅 접힘/펼침 아이콘 경계 검사 → 채팅 Esc는 입력만 닫기 → 카드 선택 → Esc 기권 창/기본 취소 포커스 → Esc 취소/선택 보존 → 확정 두 번 클릭에도 한 번 요청 → 서버 결과 반영. 별도로 3인 원카드 기권 승인 후 receipt 유실 → 같은 요청 확인으로 추가 적용 없이 복구를 확인한다. 브라우저 테스트는 기존 mock 계약을 사용하므로 실제 관전자 BE 배포 완료를 의미하지 않는다.

최종 검증 결과: 관련 단위 테스트 7파일 86건, 고유 E2E 18건(원카드 기존 7·신규 컨트롤 2·네 게임 기권/지도 및 중도 탈락 8·일반 공원 지도 1), 앱/테스트 타입 검사·프로덕션 빌드 통과. Esc 창 초기 포커스 문제를 수정한 뒤 신규 컨트롤 2건을 재검증했다. 오목은 `omokFocus` 화면에서 지도 컴포넌트 자체가 없으므로 DOM 부재 및 M/직접 열기 차단을 검증하고 다른 게임은 비활성 버튼을 검증한다. 로컬 Edge의 1920×1080·1536×1024·1280×720·390×844와 두 창의 플레이어/관전자 흐름을 확인했으며, 4인/17장/모바일/기권 확인 창 캡처를 직접 검수했다. 기존 THREE.Clock·셰이더 정밀도·대용량 청크 경고는 남는다.

### 개인 손패 높이 조정

후속 요청에 따라 손패 영역의 높이를 데스크톱 `clamp(36px, 6dvh, 64px)`, 모바일 36px 늘려 카드와 묶음 탐색을 위로 올린다. 하단 제출·드로우·정리 버튼은 기존 위치를 유지한다. 선택·hover의 추가 들어올림과 카드 뒤집기는 기존 변환을 유지한다. 손패 장수 규칙은 기존 기획/서버 판정을 유지하며 이번 변경은 원카드 전용 CSS 배치만 조정한다.

검증: 로컬 Playwright/Edge에서 4인·선택/드로우·뒤집기/복구·관전자 E2E 3건과 Vite 빌드가 통과했다. 1920×1080·1536×1024·1280×720·390×844를 캡처하고 데스크톱·낮은 화면·모바일의 최종 배치를 직접 확인했다. 카드·버튼의 겹침이나 잘림은 없고 기존 페이지/콘솔 오류 검증도 통과했다.
