# 180m 공원 기본 배치 시안

## 광장 건물 연결부 보강 (2026-10-29)

상점·응모부스·포토부스는 각각 `procedural/plaza-shop`, `procedural/plaza-drink`, `procedural/plaza-photo` 에셋으로 관리한다. 기존 `layout-shop/drink/photo` 시설 ID·위치·회전·크기·공사 안내 계약은 유지한다. 지붕과 목재 사이의 틈은 실제 기와 메시를 샘플링한 목재 받침으로 연결하며 로우 폴리 지붕의 면도 따른다. 건물별 재질 배치와 안내문을 같은 에셋 루트 안에서 함께 이동한다.

상점은 선반·커튼봉·간판·진열대·등 받침을 연결한다. 포토부스는 옆 창살을 양쪽 목재 띠장에 연결하고 벤치 등받이 지주와 등/안내판 받침을 보강한다. 응모부스는 간판 지지대와 전구/풍선의 연결선을 로우 폴리에서도 유지한다. 세 공사 안내판은 넓은 계단 위의 공통 받침과 두 지주를 사용한다.

앱/테스트 타입 검사, 건물 외곽의 잔디 영역 유지 검사와 맵 배치 체크포인트를 검증한다. 브라우저에서 실제 지붕 연결부·안내판 지주·기단을 레이캐스트하고 세 건물의 공사 안내 및 렌더 예산을 확인했다. 이번 작업은 외형 보강으로 생성 데이터와 맵 버전은 변경하지 않는다. BE·인프라 수정은 없다.

현재 새 맵에는 외곽 광고 화면·영상·패널 프레임·옥상 지지대, 공원 A형 광고판 3개, 광고 풍선/현수막/줄을 표시하지 않는다. 외곽 6동과 일반 건물·도로·신호등·담장은 유지한다. 광고 리소스 공급자와 이미지/영상 미리 불러오기도 새 맵에서 해제한다. 아래 광고 배치 설명은 이전 검토 이력이다.

## 분수 진입 경사·원형 벤치 쉼터 (2026-10-28)

- 분수광장 위로 지나가던 평평한 포장 삼각형을 원형 경계에서 잘라냈다. 분수 바닥의 동일한 128각 외곽선에 맞추며, 길 끝과 바닥 사이의 낙차를 없앤다. 경사면의 마지막 1.2m는 평지 높이로 부드럽게 잇는다. 잔디 구멍과 외곽선의 분할 차이로 생기는 틈은 4cm 포장 여유로 덮는다. 분수 본체·깊이·주변 식재는 유지한다.
- 기존 지형 샘플러는 분수 경계에서도 높이가 음수인 경우가 있어, 걷기 높이도 경계에서 약 7cm 튀었다. 공통 `fountainHeight.ts`의 경계 보정을 미리보기와 서버 전달용 지형 생성에 함께 적용했다. 시설·충돌 ID는 바꾸지 않고 생성 JSON·manifest·FE 버전을 갱신한다. BE 소스는 수정하지 않는다. 실제 서비스 전환 시 새 생성 세트를 함께 사용해야 한다.
- 운동마당의 큰 나무는 geometry·재질·배치를 그대로 유지한다. 주변 벤치는 첨부 이미지의 원형 수목 벤치를 참고해 방사형 목재 좌판 48개, 어두운 받침과 다리, 12cm 좌판 두께로 표현한다. 이전 세로 등받이는 제거하고 좌판 상단 0.62m와 네 방향 통행 틈을 유지한다. 로우 폴리 색상과 정적 재질별 배치를 사용한다.
- `bench-fitness-ring-0`~`3`의 두 좌석씩 총 8자리와 바깥을 향하는 이용 방향·안전한 퇴장 위치는 기존 공통 데이터를 사용한다. 서비스 FE의 시설 이용 요청도 같은 ID를 사용한다.
- 미리보기에서 **운동마당 선택 → 원형 벤치 체험 → 1/2번 좌석에 앉기**로 체험한다. 가까이 걸어간 뒤 E키로 앉고 일어날 수도 있다. 앉은 동안 이동은 멈추고 드래그 시점은 유지하며, 일어나면 공통 퇴장 위치로 돌아간다. 미리보기 착석은 로컬 상태이며 실제 서버 점유 요청은 보내지 않는다.

검증은 실제 포장 메시의 네 진입 방향을 10cm 간격으로 레이캐스트하여 빈 곳·갑작스러운 높이 변화가 없는지 확인한다. 공통 걷기 높이도 함께 검사하고 8개 좌석에서 실제 좌판 높이 0.62m와 퇴장 가능 여부를 확인한다. 브라우저에서는 두 자리의 버튼/E키 착석·이탈, 착석 중 이동 정지, 모바일 이용 패널을 검사한다. 서비스 계약 fixture에는 네 원형 벤치의 이용 요청·해제·퇴장 좌표 검증을 추가한다. 실제 BE 접속 검증은 별도다.

## 성능 우선 로우 폴리 표현 (2026-10-28)

이 절이 현재 그래픽 기준이다. 아래의 실사 재질·기와 낱장·나무 세부 표현 설명은 이전 검토 이력이다. 시설 배치와 공유 물리 설정은 유지하고, `layout-preview`와 `park-integration` 모드의 표현을 `src/world/art/mapRenderProfile.ts`에서 단순화한다. 기본 MVP 모드의 그래픽 정책과 캐릭터 에셋은 유지한다.

- 팔각정은 경량 지붕·기둥 모델을 사용한다. 건물 처마는 적은 면으로 만들고 낱장 기와, 미세 곡선·금속 부품, 돌탑 부조와 과도한 모서리 곡면을 줄인다. 테이블·좌석·벤치는 단순 상자와 공유 도형으로 표현한다.
- 나무는 이전 서비스의 가지/수관 덩어리/원뿔 모델 계열과 색상을 유지한다. 줄기는 4각, 수관은 icosahedron detail=0으로 줄이고 식재 그룹별 인스턴싱을 적용한다. 화단 관목과 꽃도 단순 도형을 사용하며 작은 장식 꽃의 표시 밀도를 줄인다. 실제 수목 배치·수·충돌은 바꾸지 않는다.
- 지면·돌·목재의 색상/노멀/거칠기 이미지 맵과 미세 표면 셰이더를 제외한다. 광장 타일 격자와 분수의 개별 포장 조각도 생략하고 단색 면으로 표현한다. 안내문·시설 간판·광고·게임판·캐릭터에 필요한 이미지는 유지한다.
- 외곽 건물은 상자와 넓은 창 패널, 기와 담장은 공유 경량 지붕으로 표현한다. 도로/담장의 둥근 모서리, 출입구, 신호등과 외곽 건물 위치는 유지한다.
- 구름 36개 덩어리는 하나의 저면수 구와 재질을 공유해 한 번에 그린다. 전체 화면 구름 노이즈/반사 환경맵과 수면 다중 파동 셰이더 대신 단색 하늘·안개·반투명 수면을 사용한다. 낮/밤 상태, 남산 배경, 수영·물고기·비둘기·점프맵의 동작은 유지한다.
- 그림자는 끄고 DPR은 최대 1, 내부 렌더 픽셀 수는 최대 1280×720 상당으로 제한한다. 서비스의 자동 해상도 조절도 이 상한을 따른다. UI 해상도는 낮추지 않는다.

공통 시설 ID, 테이블 16개/좌석 앵커 64개, 바닥 높이·충돌 설정은 그대로다. 빈 테이블의 의자 2개 표시/4인 게임의 의자 추가 표시 정책도 유지한다. 외부 돌 테이블은 기존 의자 간격 1.8m를 유지한다. 생성 데이터 검사에서 파일 갱신 없이 맵 identity `2739365b0310f478662fc87884688f4c97af60359070a6c5747e9541e4a8944f`가 유효함을 확인했다. BE·인프라·배포 설정은 수정하지 않았다.

## 이전 서비스 맵의 실제 로우 폴리 나무 모델 적용 (2026-10-28)

이전 절의 단일 수관 나무는 180m 미리보기용 임시 형태였다. 사용자 요청에 따라 기존 서비스 SimpleParkTrees의 buildParkTreeParts와 동일한 나뭇가지·수관 덩어리·원뿔 수관 모델을 재사용한다. 줄기 geometry(6각), 수관 geometry(icosahedron detail=1), 원뿔 geometry(8각), flatShading/roughness 0.94 재질을 FacetedParkTreeInstances에서 공유하며 기존 서비스의 기본 식재와 생성 부품은 유지한다.

추가한 VR·광장·정자 식재뿐 아니라 일반 숲·담장 안쪽 수목·수변·운동마당 중앙 나무에도 같은 모델 계열을 적용한다. 일반 식재는 기존 위치·예약된 수관 폭 안에 맞게 기존 활엽수/가느다란 나무/정원수/침엽수 모델의 배율을 조절한다. 운동마당의 큰 나무는 기존 활엽수 모델을 확대하며 중앙 벤치와 화단은 유지한다.

입구 비우기, 포토부스 위치, 모든 수목 위치와 수, 공통 좌표·물리 형상·좌석을 바꾸지 않았다. map:check로 생성물과 identity가 그대로 유효함을 확인한다. 브라우저 검사는 여섯 식재 그룹의 mesh와 material이 기존 서비스와 같은 공유 객체인지 확인한다. 앱/테스트 타입 검사, 단위 검사 892개(Windows 파일 교체 잠금이 발생한 감시 검사는 단독 재검사 통과), 배치 브라우저 검사, 기존/새 맵 빌드와 map:check를 통과했다. BE·인프라·배포·커밋·푸시는 수행하지 않았다. 아래 단일 수관/줄기 설명은 이전 검토 이력이다.

## 부스 입구 비우기·측후면 식재·기존 나무 스타일 통일 (2026-10-28)

상점·응모부스·포토부스의 각 yaw를 기준으로 전면을 판별한다. 공통 planting.ts의 inKioskEntrance는 입구와 접근 공간을 비우며, 새 전용 수목뿐 아니라 기존 일반 숲과 수변 장식 수목에도 적용한다. 나무 후보는 부스의 옆/뒤 격자에서 먼저 선택하고, 길·원형 광장·건물·정자 뜰과 겹치거나 서로 2.35m 이내인 후보를 제외한다. 광장/부스 수목은 총 52그루이며 건물 12m 이내의 전용 수목은 상점 7그루·응모부스 7그루·포토부스 9그루다.

포토부스는 입구 방향으로 약 1m 당겨 (30,35.6)에 두고 두 접근길도 맞췄다. 실제 처마·받침·계단을 포함하는 외곽 검사로 잔디 경계를 다시 검증한다. 새 뒤 공간은 위 식재 후보에 포함한다. 메인 옆 정자 주변은 24그루로 보강했으며, X=±18.5의 사이 공간에는 각 8그루가 있다. 기존 정자 위치와 로컬 좌석은 유지한다.

최근 추가했던 VR/광장/정자 나무의 가지 곡선과 잎 클러스터 렌더를 제거했다. 기존 숲과 같은 7각 기둥 줄기, 단일 icosahedron(detail=1) 수관, 기존 녹색/분홍 팔레트와 높이·폭 범위를 사용한다. 정적 인스턴스로 묶으며 실사화는 적용하지 않는다. 생성 JSON·manifest·FE 버전은 함께 갱신하며 BE·인프라 코드는 변경하지 않는다.

동심원 인레이·팔방 꽃 문양·화단 4개·곡선 벤치를 추가했다. 정문에서 광장까지도 같은 블록 색·줄눈·완성 높이로 연결했다.
기존 시설 ID/모델을 유지하며 야외 돌 테이블 네 세트는 중앙 문양을 둘러싸도록 재배치한다. 새 통로를 확보하기 위해 소리함은 X -18m로, A2 광고판은 Z -13m로 길 옆에 옮겼다.
화단·벤치의 고체 영역도 미리보기 이동 검사에 반영한다. 외곽 배경 건물에는 이동/충돌 데이터를 추가하지 않는다.
상점/응모부스는 광장 서쪽 가장자리에, 포토부스는 맞은편 동쪽 가장자리에 배치한다. 건물은 기존 시안의 65~75% 크기다. 상점은 남동쪽 45도, 응모부스는 남쪽, 포토부스는 남서쪽 45도를 향한다.

## VR 구역과 호수 보완

체험관의 파란 바닥을 제거하고 기존 한옥 형상을 재사용한 VR 체험관/민속놀이 존 2동을 동향(+X)으로 배치했다. 뜰 전체에는 같은 타일 마감을 사용한다.
동쪽에는 기존 VR 석탑을 다시 배치했다. `SITES.vr`, `folk`, `vrPagoda`가 시안 위치를 지정한다.
전망대 동서남 접근로와 분수광장의 남·동·서쪽 직선 진입로, 북서 숲 연결로를 추가했다.
VR 북쪽 출입구에서 분수광장으로 이어지는 길과 서쪽 출입구를 추가했다.

분수는 기존 `ParkFountain`의 수조·물줄기·화단·동심원 석재 포장을 그대로 사용하며, 기존 `groundHeight`로 낮은 분수광장 지형을 재현한다.
외곽 배경 바닥이 공원 밑을 덮던 부분을 제거해 낮은 분수 수조와 수중 물고기를 가리지 않게 했다.
기존 `EnvironmentScene`의 하늘, `DistantLandscape`의 산 능선과 남산타워, 기존 `PlannedCity`·`CityStreets`·`ParkBoundary`를 직접 재사용한다.
기존 광고 건물 6동과 일반 건물의 모델·배치 순서·높이·화면, 도로·신호등·보도·가로등, 기와 담장의 석재·기와·막새 디테일을 유지한다.
공원 확장분에 맞춰 외곽을 10m 바깥으로 옮기고 도로/담장 길이를 180m에 맞췄다. 정문 5.2m 개구부를 제외하고 담장을 연결한다. 기본 서비스의 160m 설정은 그대로다.
시안에서만 `cornerRadius=6`을 지정한다. 외곽 도로·보도·차선은 같은 중심을 공유한 곡선 링이며, 담장 모서리는 기존 석재·기와·막새 지오메트리를 곡선에 맞춰 휘어 연속 연결한다.
내부 외곽 산책로도 반경 7m로 코너를 둥글게 잇고, 보행 경계와 담장 식재는 둥근 모서리를 따른다.
도로·건물 범위 약 316m 바깥의 먼 산/지평선도 배경이며 이동할 수 없다.

`lakeLayout.ts`의 `CROSSINGS`는 북쪽(Z -26m) 돌다리와 남쪽(Z +9m) 목교의 위치·폭을 지정한다.
`SHORE_RUNS`는 두 횡단로·낚시 데크·서/동 수영 진입부를 비운 호수 울타리이며 렌더링과 충돌 검사가 같은 구간을 쓴다.
기존 `LAKE_ROCKS` 배치를 호수 크기에 맞춰 변환하고, 바위의 회전/변형을 포함한 전체 반경에 여유를 더해 난간 안쪽으로 옮긴다. 접근로와 겹치는 바위는 제외한다.
다리 양끝은 해당 Z의 타원형 물가와 0.55~0.65m만 겹치도록 계산한다. 목교는 낮은 양끝에서 중앙이 1.85m 올라오는 아치이며, 판재·난간·곡선 하부 보와 보행 높이가 같은 프로파일을 따른다.
징검돌은 약 0.62m 두께의 비정형 석재로, 깎인 가장자리·작은 깨짐·석재 질감을 표현한다.
기존 `LakeFish` 모델/애니메이션을 새 호수 좌표로 변환해 재사용하며 연잎·연꽃·갈대와 수변 수목을 추가했다.
`layout-shore-trees` 그룹은 `plannedSpecies: willow`를 표시한 별도 수변 수목 배치다. 현재는 기본 나무이며 추후 버드나무 모델로 교체할 수 있다.
담장 안쪽 X/Z ±87.6m에는 남쪽 정문을 비우고 공원 한 바퀴에 별도의 나무 열을 추가했다.
일반 숲 식재 간격은 3.15m로 줄이고 나무별 수관 크기를 조절했다. 길·뜰·시설·광장 안에는 새 나무를 심지 않는다.

## 이동과 적용 범위

미리보기의 `canWalk`는 공원 경계, 기본 시설 박스와 호수, 횡단 동선, 울타리와 광장 가구를 검사한다.
`walkHeight`는 배치 검수를 위한 높이를 제공한다. 깊은 물에서는 기존 `SWIMMING` 설정의 수영 속도/깊이 기준/부유 높이를 사용하고 수면 시점과 잔물결 및 수영 상태를 표시한다.
두 다리와 낚시 데크에서는 수영 상태를 해제한다. 미리보기는 1인칭 이동(점프맵 체험 포함)이며 캐릭터 GLB/실서버 애니메이션·멀티플레이·착석·전망대 등반 전체를 재현하지 않는다.
실제 Java 서버의 충돌/거리 판정을 대체하거나 버전 검사를 해제하지 않는다.

BE 코드·리소스와 배포/CI는 수정하지 않았다. 새 좌표/충돌 전달 자동화와 실서버 반영은 배치 검토 후 별도 작업이다.

## 기획서 기반 점프맵 FE 체험

- VR 돌 탁자를 table-17/18 게임 앵커로 등록한다. 기존 앞뒤 의자 위치는 유지하고 양옆을 보강해 4석을 제공한다. 16개 기존 테이블은 변경하지 않는다.
- 분수 벤치 bench-76~79는 기존 좌석·물리 프록시 위치와 수평 배율에 맞춰 공유 ReferenceBench를 렌더한다. 미리보기 수조의 2D 충돌을 실제 원형에 맞춰 기존 퇴장 위치로 일어날 수 있게 한다. 서버 3D 수조 형상은 유지한다.
- 숲 벤치 3곳은 공통 설정에서 렌더·두 좌석·방향·퇴장·충돌을 함께 계산한다. 수목·쉼터를 선택하면 각 벤치 체험 버튼, 분수를 선택하면 분수 벤치 체험 버튼을 제공한다.
- 상점·응모부스·포토부스에 공사 중 표지판과 로컬 안내창을 둔다. 미리보기 시설 정보의 공사 안내 보기/건물 클릭, 산책 중 입구에서 E키로 확인한다. 서비스는 동일한 입구 거리·높이 검사 후 E/클릭으로 안내만 열며 기능 API는 호출하지 않는다. 포토부스 내부 촬영 벤치는 장식으로 유지한다.
