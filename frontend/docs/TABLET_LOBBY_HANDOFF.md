# 테이블 태블릿 · 경기/미니게임 결과 FE 인계

## 직접 착석 진입 (2026-10-27)

- 기본 흐름을 `의자 근처 E/테이블 클릭 → TABLE_JOIN → 서버 TABLE_STATE 착석 승인 → 태블릿`으로 연결했다. 기본 상호작용에서 `inspectTable`/TABLE_WATCH와 중간 2D 정보창을 거치지 않는다. `테이블 정보·관전` 보조 버튼과 벤치 관전의 기존 공개 조회 경로는 유지한다. false를 명시한 AUTO 호환 UI는 이전 진입을 유지한다.
- `joinTable(anchorId?)`의 인자는 FE 내부 배치 ID다. 기존 binding으로 서버 tableId를 찾으며 wire payload는 기존 `{tableId}`만 전송한다. 좌석 번호·사용자 ID·위치를 FE가 보내거나 선점하지 않고 기존 서버가 좌석을 배정한다. 클릭한 의자의 좌석 번호를 지정하는 기능은 추가하지 않았다.
- 요청 중 안내·중복 요청 차단·이동 입력 정리를 추가했다. 승인 전에는 태블릿/좌석을 만들지 않는다. 만석/진행 중/타임아웃에는 서 있는 상태와 오류 안내를 유지하고 자동 재전송·자동 관전을 하지 않는다. 가까운 E 상호작용과 3D 클릭에 기존 테이블 거리/높이 조건을 공통 적용한다. 세대/계정/채널이 바뀐 후 늦은 요청 정리는 새 요청 상태를 덮지 않는다.
- 기존 BE 입장·권한·정원·경기 상태 검사를 그대로 사용하며 BE/DB/인프라 수정은 없다.
- 최신 dev `71d92f8`의 오목 UX·카메라·관전 채팅/핑을 충돌 없이 통합했다. 이 작업의 변경은 FE에만 한정하며 기존 작업 폴더의 미커밋 문서 10개는 보존한다.
- 검증: FE/테스트 TypeScript, 단위 77파일/767개, 기본·tablet 빌드, migration boundary 통과. 일반 실행 태블릿 23개와 기존 조작·벤치·망원경 호환 7개를 확인했고, 최신 dev 통합 후 직접 착석·오목 태블릿 6개 및 오목 UX·관전 3개를 재검증했다. 중복 시나리오가 있으므로 합산 수치가 아니다.
- Playwright/Edge와 실제 운영 FE 어댑터의 WS fixture로 승인 대기·중복 입력·거절·명시적 재시도·일어나기/카메라 복귀·재착석·수동 시작을 검증했다. 실제 BE/DB 다중 계정 검수는 사용자가 진행한다. 실행 중인 배포 사이트에는 새 FE 빌드 배포가 필요하다.

## 기본 착석 화면 활성화 정정 (2026-10-27)

이전 머지는 `TABLET_ENABLED`를 별도 tablet 모드/true 환경변수로 제한해 일반 실행과 production에서 태블릿 및 서버 어댑터가 꺼져 있었다. 착석하면 바로 태블릿이 나와야 한다는 요구를 기본 실행에 적용하지 못한 FE 활성화 누락이다.

- 일반 `pnpm dev`/`pnpm build`/실서버 FE 검수 모드는 태블릿을 기본 활성화한다. 기능 표시와 `TabletLobbyClient` 바인딩이 같은 조건을 사용하므로 둘을 함께 활성화한다. `VITE_TABLET_LOBBY=false`를 명시한 환경만 기존 AUTO UI를 유지한다.
- 시설/붕어빵 에셋 미리보기는 기존 화면을 보존하며 true를 명시하면 태블릿을 선택할 수 있다. 기존 `dev:tablet`/`build:tablet` 명령도 유지한다.
- 별도 모드 없이 동작하는 `playwright.tablet-default.config.ts`와 `test:e2e:tablet:default`를 추가한다. 기존 AUTO 테스트 서버는 false를 명시해 호환 시나리오를 계속 검증한다. BE/DB/인프라 코드는 변경하지 않는다.
- 검증: FE/테스트 TypeScript, 단위 75파일/754개, 기본·tablet 빌드, migration boundary 통과. 일반 Vite 개발 서버(`--mode tablet` 없이, true 플래그 없이)에서 착석/4종 게임/준비 취소/120초/결과/모바일 시나리오 18개, false를 명시한 AUTO 호환 5개가 통과했다. Playwright/Edge의 `/park`에서 앱 내용·오류 오버레이·페이지 오류·스크린샷·조작을 확인했다. 실제 BE/DB 다중 계정 검수는 사용자 진행 범위로 유지한다.

- 새 태블릿 결과 팝업도 INVALID와 nullable 참가자 판정을 표시한다. 엔진 스냅샷이 PLAYING이거나 없는 복구 상태에서도 본인 경기의 결과를 다시 조회할 수 있다. 무효 경기를 승리/무승부로 표시하지 않으며, 예약금 해제 대기와 확정 후 잔액 변화 0을 구분한다.
- 원카드·일반 주사위·거짓말 다리 썸네일 3개 반영 유지. 다리 이미지는 `1·2·3·4·X·X` 특수 주사위 기준이며 이미지 때문에 추가 BE 작업은 필요하지 않다.
- 남은 BE 작업은 **전원 준비와 수동 시작 분리**, **정확한 선택 정원 저장·방송**, **승자/무승부 방장 승계**다. 아직 운영 어댑터를 바인딩하지 않았다.

최신 통합 재검증:

- FE/테스트 TypeScript 검사, 단위 57파일/557개 통과.
- 태블릿 브라우저 10개 통과. 무효 결과가 PLAYING 엔진을 덮는 경우, 엔진 없는 WAITING 이후 재조회, 지연된 PENDING 중복 수신, 예약 해제 후 다음 판 전환을 추가 검증했다.
- 기본 모드 브라우저 33개 통과: `game-forfeit.spec.ts`, `prototype-table-ui.spec.ts`, `table-lobby.spec.ts`. 4종 게임 연결·기권·재접속·무효 결과·예약 반환·로비·1280/1000px 조작을 확인했다.
- 기본/태블릿 production build와 migration boundary 통과. 충돌 마커·공백 오류 없음. BE 코드와 기존 정산/복구 문서는 최신 dev 원본과 동일하다. 썸네일 3개의 바이너리도 기존 수정 커밋 그대로 유지했다.
- 브라우저 플러그인이 없어 기존 Playwright/Edge를 사용했다. 검수 화면은 `tablet-sync-qa`에 저장해 직접 확인했다. 기존 Three.Clock/Intel 셰이더 정밀도/큰 번들 경고는 유지되며 새로운 앱 오류는 없었다. 실제 BE/DB 및 다중 계정 동시 요청은 아직 공동 검수 대상이다.

## 실행·배포 경계

기존 자동 시작 서버에서 실제 게임을 막지 않도록 **기본 `dev/build`는 기존 테이블 로비와 결과 경로를 유지**한다. 신규 태블릿·경기 결과는 명시적인 모드로 검수한다. 붕어빵 결과 팝업은 양쪽 모드에 적용한다.

```sh
pnpm dev:tablet
# http://localhost:5203/park — 기존 로그인/REST/WS 그대로 사용
pnpm build:tablet
# dist-tablet/ — 기본 dist/와 별도 산출물
pnpm test:e2e:tablet
```

BE 주소가 필요하면 기존 `API_PROXY_TARGET`을 지정한다. 신규 모드에 가짜 로그인/로컬 게임 서버/클라이언트 지급 기능을 추가하지 않았다. `VITE_TABLET_LOBBY=true`도 같은 UI를 선택하지만 BE 어댑터 바인딩까지 있어야 수동 시작할 수 있다. 운영 전환은 BE 계약·테스트 서버 공동 검수 후 진행한다.

## 사용자 확정 흐름

1. 처음에는 의자 두 개. 실제 착석 승인 후 목재 태블릿 화면을 켠다.
2. 방장이 게임·참가 인원·주사위 목표 점수·1인 판돈을 정하고 '선택하고 준비하기'를 누른다.
3. 서버가 승인한 인원에 맞춰 의자를 표시한다. 태블릿에 실제 참가자와 준비 상태가 나타난다.
4. 각 참가자가 판돈을 확인하고 준비 완료/준비 취소/일어나기를 선택한다.
5. 선택 인원이 모두 착석하고 전원 준비했을 때 방장만 게임 시작을 누른다.
6. 서버가 실제 경기를 확정하면 태블릿 화면을 끄고 프레임을 내려 기존 게임 플레이 화면을 표시한다.
7. 종료 시 한지 팝업에 승패·참가자·정산 상태를 표시한다. 실제 정산 완료와 WAITING 승인 후 다음 판 준비가 가능하다.
8. 첫 착석자가 최초 방장, 이후 승자가 다음 방장. 무승부면 해당 인원 중 서버가 무작위로 정한다.

오목·주사위는 현재 엔진 계약대로 2인, 원카드·거짓말 다리는 2/3/4인 선택 UI다. 주사위 목표는 기존 2000/4000/6000을 유지한다. 이미지 예시의 20냥은 고정 판돈이 아니며 실제 입력·서버 승인값을 사용한다.

## 완료한 FE 범위

- `TableTablet3D`: 실제 테이블 좌표·기존 목재 재질의 프레임/베젤/받침. 현재 좌석을 향한다. 입장 때 올라오고 시작 승인 후 전원을 끄며 내려간다.
- `tabletProjection`: 화면의 3D 네 모서리를 CSS 좌표로 투영한다. HTML 글자·버튼·숫자 입력은 스크린샷이 아니며 마우스/키보드로 조작한다. 작은 화면은 읽을 수 있는 스크롤 태블릿 배치로 전환한다.
- `TabletLobby`: 게임 썸네일, 인원·주사위 목표, 방장 판돈 입력, 금액 확인, 서버 좌석/준비 표시, 일어나기, 상태 확인. 참가자 초상은 기존 남녀 GLB를 재사용한다. 장착 의상 에셋이 없는 기존 한계는 유지한다.
- 기본 의자 2개, 승인된 정원/좌석에 따라 3/4개. 승인된 사람이 앉은 의자를 숨기지 않는다. 좌석 ID·순서·서버 충돌체는 변경하지 않는다.
- 기존 Omok/Farkle/OneCard/Bridge HUD·입력·공개/개인 정보·기권·복구 경로를 유지한다.
- 경기 결과는 서버 결과/승자/정산 데이터만 표시한다. 닫기와 다시 보기 제공. 닫기만으로 퇴장·정산·다음 판 전환을 하지 않는다.
- 현재 dev의 실제 미니게임인 붕어빵 결과를 같은 한지 팝업으로 변경한다. 점수·완성·실수·확정 보상·일일 상한·기존 동일 결과 재확인·공원 복귀를 유지한다.
- `PaperPopup`은 후속 미니게임 결과에도 재사용할 수 있다. 별도 점프맵 작업 브랜치의 미리보기 엔진/보상 코드를 dev로 복사하지 않는다.

## BE에 필요한 변경 — 현재 서버 기능과 구분

### 1. 준비와 시작 분리: 필수

현재 `TableHub`는 마지막 `READY_SET` 뒤 시작을 시도한다. `GAME_START_CHECK`는 조회이지 시작 명령이 아니다. 사용자의 확정 요구는 **전원 준비 후 방장 수동 시작**이다.

- `READY_SET`은 준비 상태만 바꾸도록 분리해야 한다. 동시 준비 요청으로 자동 시작하면 안 된다.
- 방장 전용 실제 시작 명령, 승인/거절 응답, 중복 시작 방지, 요청 유실 후 조회/동일 요청 재확인 계약을 제공해달라. 최종 WS 이름/payload는 BE 명세로 확정한다.
- 시작할 때 서버가 방장·채널·테이블 버전·선택 게임·인원 충족·전원 준비·판돈 동의·현재 지갑/예약금을 원자적으로 재검사한다.
- 시작 요청과 동시에 퇴장/준비 취소/설정 변경/연결 종료가 발생할 때의 처리와 STARTING/CONFIRMED/PLAYING 실패 복구를 정의한다.
- 기존 `GAME_START_STATE`·실제 `gameId`·게임 복구·정산 흐름을 재사용한다. 조회 응답만으로 FE가 게임을 만들지 않는다.

**현행 서버에서는 새 태블릿의 준비=true와 게임 시작을 비활성화한다.** 마지막 준비만 막는 방식은 두 사용자의 동시 요청 경쟁에서 자동 시작을 방지할 수 없으므로 사용하지 않는다. 준비 취소와 정상 대기 중 일어나기는 기존 명령을 사용한다. 기존 `GAME_SELECT`가 지원하는 최대 인원 설정은 연결돼 있다. 이 제한을 제거하려고 FE에 서버 가짜 승인·로컬 방장/준비·시작 엔진을 넣지 않는다.

### 2. 선택 인원·설정 확정

- 게임 최대 인원과 **이번 방에서 선택한 정확한 정원**을 구분한 공개 상태가 필요하다. 원카드·다리 2/3/4, 오목·주사위 2.
- 게임/목표/정원/판돈을 한 번에 저장하는 명세가 필요하다. 현재 GAME_SELECT는 gameCode, DICE targetScore, betAmountPerPlayer만 지원한다.
- '선택하고 준비하기'는 설정 확정이다. 사용자 준비=true와 구분한다. 첫 착석만으로 실제 테이블 좌석을 받으며 FE가 새 방 ID를 만들지 않는다.
- 정원보다 이미 착석한 사람이 많으면 거절한다. 강제 퇴장·자리 재정렬·임의 위치 변경을 하지 않는다.
- 게임/목표/정원/판돈 변경 시 전원 준비·동의를 초기화하고 방송한다. 입퇴장 때도 준비를 초기화할지, 정원 유지/축소 여부를 합의한다.
- 전체/인접 관찰자도 승인된 정원과 좌석을 받아 의자 개수를 일치시킬 수 있어야 한다. FE의 의자 표시만 바뀌므로 서버 충돌체 변경·생성 데이터와의 정합성은 BE가 처리한다.
- 서버 재접속/재기동 뒤 같은 선택 정원과 준비 상태를 복원한다. 공개 필드 위치와 버전 규칙을 알려달라.

### 3. 방장 승계

- 최초 첫 착석자 정책은 기존 `selectorUserId`를 사용한다. FE가 좌석 1번을 방장으로 추정하지 않는다.
- 종료/정산 이후 승자에게 방장 승계. 무승부 참여자 중 서버 무작위 추첨. FE의 Math.random으로 결정하지 않는다.
- 공동 승리/기권/무효/승자가 이미 퇴장/현재 방장 연결 종료/승자 재접속의 우선순위를 정해달라. 당첨된 사람이 아직 테이블에 있는지 검사해야 한다.
- 기존 `TABLE_STATE.selectorUserId`와 함께 방송하면 새 태블릿도 즉시 권한과 버튼을 반영한다. 승자 타이틀만으로 버튼 권한을 바꾸지 않는다.

### 4. 판돈·퇴장·결과의 경계

- 준비는 현재 판돈을 확인한 `expectedVersion`/금액으로 기존 검증을 유지한다. 단순 타인 준비 갱신은 UI 체크를 지우지 않지만 설정이 바뀌면 체크를 지운다.
- WAITING 중 준비 상태인 사람도 '일어나기'를 사용할 수 있는지 확인해달라. 서버 승인이 도착한 후에만 아바타·좌석을 해제한다.
- 결과 승패는 GAME_STATE/저장 결과, 지급 완료는 GAME_RESULT의 SETTLED를 따른다. 보상 확인 중에 임의 금액·가짜 순위를 만들지 않는다.
- 다음 판은 SETTLED + 실제 WAITING 모두 수신 후만 허용한다. DB 확정 지연/응답 순서 뒤바뀜/정산 실패도 공동 검수한다.

## 연결 지점

`src/features/tableLobby/tabletModel.ts`의 `TablePreparationPort`는 **FE 내부 포트이며 미확정 WS/API 명세가 아니다.** BE 계약을 받은 뒤 기존 Spring runtime에서 어댑터를 바인딩한다.

- `manualStart: true`: 서버가 자동 시작을 하지 않는 계약이 확인된 뒤만 설정.
- `selectedPlayers(table)`: 서버 승인 상태에서 정확한 선택 정원을 읽는다.
- `configure(context, selection)`: 사용자/채널/테이블/현재 버전과 선택 내용을 서버로 보낸다. 성공 상태는 기존 TABLE_STATE 수신으로 반영한다.
- `start(context)`: 방장 시작 명령 어댑터. 허용 여부와 결과는 서버가 다시 검사한다.

현재 운영 runtime에는 바인딩하지 않았다. 테스트 파일의 바인딩은 계약 대역이며 운영 번들에 포함되지 않는다. 포트가 없는 상태에서 3인 등 현행 GAME_SELECT로 표현하지 못하는 선택은 적용을 차단한다.

## 타 작업자 전달 문구

> FE 태블릿 선택/준비 UI와 4종 기존 게임 연결, 경기·붕어빵 결과 팝업을 작업했습니다. 신규 흐름은 마지막 준비 자동 시작 대신 전원 준비 후 방장 수동 시작이 필요합니다. 정확한 선택 정원(2/3/4), 게임·목표·판돈·정원 원자적 설정, 방장 시작/중복 방지 명세와 공개 상태를 부탁드립니다. 다음 방장은 승자, 무승부는 해당 인원 중 서버 추첨 후 기존 selectorUserId로 방송해주세요. FE는 미확정 WS를 임의 전송하지 않고 연결 포트를 준비했으며, 현행 자동 시작 서버에서는 준비=true와 시작을 안전하게 비활성화합니다. 준비된 테스트 서버에서 동시 준비/취소/퇴장, 정산·승계·재접속을 함께 검수하면 됩니다.

## 검증·병합

브라우저 플러그인이 없어 기존 Playwright/Edge를 사용한다. 태블릿 전용 설정은 `playwright.tablet.config.ts`이고 기본 e2e에서는 해당 파일을 제외한다. 화면·버튼·전환 검증은 HTTP/RawWS fixture와 FE 포트 대역이며 실제 BE 배포/DB·동시 다중 계정 검증을 대신하지 않는다.

코드 변경은 frontend만. backend/DB/CI/맵 좌표/좌석 ID/게임 규칙을 수정하지 않는다. 커밋 전 원격 dev 갱신·diff 확인, 커밋 후 merge-tree로 최신 dev 병합 충돌을 검사하고 전용 브랜치로 푸시한다. 다른 작업 브랜치의 미병합 변경까지 자동 반영/머지하지 않는다.

최초 구현 시 로컬 검증 (`e92d3ad`, 아래 수치는 최신 통합 재검증 수치가 아님):

- 태블릿 모드 브라우저 9개 통과. 2/3/4인, 전원 준비 전 시작 차단, 기존 4종 경기 연결, 결과 pending/SETTLED/WAITING, 닫기/다시 보기, 서버 방장 갱신, 붕어빵 결과, 모바일, 원본 1672×941 팔각정 배치 포함. 결과 카메라/HUD 보완 뒤 해당 2개 재검증도 통과.
