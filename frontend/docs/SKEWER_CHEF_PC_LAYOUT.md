## 2026-11-03 PC 영수증·제작대 변경 — 현재 기준

- PC 화면은 큰 꼬치 그림이 있는 영수증 두 장과 중앙 상단 남은 시간·팀 점수·요리 완료 수를 표시한다. 요리 완료는 정확도와 무관하게 전달대 제출에 성공한 꼬치 수다.
- 좌상단 제목, PC/VR 전환 탭, 오른쪽 시간·전달대 패널, 하단 재료·순서·제출 바는 PC에서 제거한다. 간단한 키 안내와 오류/행동 메시지만 남긴다.
- 숫자 1~6은 왼쪽부터 현재 재료 위치에 대응한다. Space로 꽂고 Backspace로 끝 재료를 뺀다. **R로 완성 및 즉시 전달대 제출**, Enter는 사용하지 않는다.
- PC 제출 성공마다 재료·이름표·클릭 영역을 함께 재배치한다. 같은 순서가 반복되지 않게 하며 실제 헤드셋 요리 중에는 배치를 섞지 않는다. 수량 초과·잘못된 큐브 간격·빈 꼬치·전달대 가득 참으로 거절되면 제작 수와 배치는 유지된다.
- 치즈·베이컨은 종류별 0개 또는 2~3개. 같은 큐브의 각 인접한 출현 사이에는 다른 재료가 정확히 한 개 있어야 한다. 치즈–피망–치즈는 가능, 치즈–치즈와 치즈–피망–새우–치즈는 불가능하다. 조립 중 단일 큐브는 허용하지만 그 상태로 제출할 수 없다.
- 여섯 주문 레시피를 FE/BE에서 동일하게 수정했고, 실제 레시피로 960×340 주문 그림을 다시 렌더링했다. 손님 말풍선·요리사 주문서·접시에서 같은 recipe 키를 사용한다.
- 레시피와 다르게 만든 꼬치도 조립 규칙을 충족하면 제출할 수 있다. 전달대·서빙 트레이에는 실제 제작 재료를 표시한다. 손님에게 전달했을 때 잘못된 꼬치는 소모하고 접시당 10점 감점(0점 하한), 원래 주문을 주방에 다시 보낸다. 단순 다른 테이블 오배송의 기존 음식 보존 규칙은 유지한다.
- 서버 privateState.chef에 pantry(현재 슬롯 순서), completed(제작 완료 수)를 추가한다. SUBMIT 액션과 기존 actionId/expectedVersion 처리를 재사용한다. 원본 주문과 실제 제작 접시를 분리해 올바른 음식만 점수를 받는다.
- 새 DB 변경 없음. V144 수정 없음. 로컬 전용, 커밋·푸시·MR·배포 없음.
