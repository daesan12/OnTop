# BE 전달: 오목 화면 개편에 따른 관전자 채팅·핑 연동 요청

작성일: 2026-10-27 KST

**진행 상태 갱신:** BE 구현 완료 회신과 [최종 계약](../../docs/websocket-api/10-game-spectator-events.md)을 수령했고, 별도 FE 브랜치 `feat/frontend-omok-ux`에서 실제 화면·통신 구현을 반영했다. 아래 최초 요청은 전달 이력이다. 신규 통신의 기준은 최종 계약이며 ISO 시각·관전자 채팅 수신 범위 등 초안 제안보다 우선한다. 개발 서버 배포와 실제 계정 공동 검수 완료를 뜻하지 않는다.

현재 FE에는 고정 탑뷰·판 밖 HUD·플레이어 채팅/공통 메뉴 제거·F1 유지, 승인 관전자 전용 채팅·보드 클릭 핑, Unix ms 잔여 수명·버전 검사·중복/만료 폐기·해제 정리가 구현되어 있다. 선행 태블릿 선택·준비·수동 시작 계약과 기존 착수·기권·복구·결과·정산 흐름을 재사용한다. 상세 검증 범위는 [FE 명세](OMOK_UX_FE_SPEC.md)를 따른다.

**추가 BE 요청 여부:** 현재 확정한 오목 기능에는 추가 API·메시지·DB 변경 요청이 없다. 기존 구현의 개발 서버 배포와 다중 계정 공동 검수만 남아 있다. 공동 검수에서 확인되는 계약 불일치나 결함은 재현 내용과 함께 별도 요청한다.

오목의 잦은 시점 전환을 없애고 게임판에 집중할 수 있도록 플레이 화면을 개편하려고 합니다. 확대된 판만 보더라도 관전자가 훈수로 참여하는 재미를 유지할 수 있도록, 해당 경기의 관전자 채팅과 위치 추천 핑을 전달하는 BE 연동을 요청드립니다.

## 1. 기존 화면에서 확인한 문제

- 내 차례에는 판을 확대하고 상대 차례에는 착석 시점으로 돌아가므로, 턴 교대가 빠른 오목에서 화면이 자주 움직입니다.
- 관중까지 보이는 넓은 시점은 주변 반응을 확인할 수 있지만, 게임판에 집중하기 어렵다는 문제가 있습니다.
- 좌하단 채팅창과 오른쪽 공통 메뉴가 경기 화면을 차지하고, 차례·시간 안내가 판을 가립니다. 내 돌 색과 상대 정보도 작아 대국 상황을 읽기 어렵습니다.
- 확대된 판을 계속 보여주면 주변 관중의 반응을 보기 어려워지므로, 관전자 채팅과 판 위 추천 핑으로 참여를 연결하려고 합니다.
- 기존 채팅은 발신자 기준 근거리 전달이며 메시지에 경기 ID가 없습니다. 이번 요구사항에 필요한 '같은 경기 관전자만 발신 → 해당 경기 참가자에게 전달'을 구분하는 기능과 관전자 핑 전달 기능이 추가로 필요합니다.

## 2. 최초 요청 당시 FE 진행 상태

최초 요청 당시에는 **기획·FE/BE 작업 명세 작성과 독립적인 핑 연출 미리보기 검증**까지 진행했습니다. 이후 실제 FE 구현을 완료했으며, 최신 상태는 문서 상단과 FE 명세를 따릅니다.

| 현재 진행한 작업 | 결과 |
| --- | --- |
| 오목 플레이·관전 참여 기획 보완 | 턴과 관계없는 확대 탑뷰, 판 밖 경기 정보, 관전자 채팅·핑 방식 정리 |
| FE/BE 작업 분리 | 화면 연출은 FE, 경기별 전달·관전 권한 검사는 BE로 구분 |
| 핑 연출 미리보기 | 교차점에 관전자 이름·얇은 링·파동을 표시하고 약 2초 후 사라지는 연출 확인 |
| 미리보기 동작 검증 | 클릭 위치 매핑·소멸·반복 재생·키보드·작은 화면·동작 줄이기 확인. 실제 게임/서버 연동 검증과는 별도 |

## 3. FE가 반영한 구현

1. 경기 시작 확정 후 양쪽 플레이어의 확대 오목판 탑뷰를 유지하고, 턴 변경에 따른 카메라 이동을 제거했습니다.
2. 플레이어 좌하단 채팅창과 오른쪽 공통 메뉴를 제거하고, 내 돌 색·상대 정보·차례·한 수 남은 시간을 판 밖에 배치했습니다.
3. 해당 경기 관전자 채팅을 화면 여러 위치에 반투명하게 잠깐 표시합니다. 플레이어는 수신만 합니다.
4. 관전자 판 클릭은 좌표 핑으로 전송하고, 서버가 승인한 이벤트를 두 플레이어와 전체 관전자의 같은 교차점에 표시합니다. 플레이어 클릭은 기존 착수 경로를 사용합니다.
5. 오버레이·핑은 클릭을 가로채지 않고, 중복·만료·다른 경기 이벤트와 현재 판보다 낮은 버전의 핑을 폐기합니다.
6. 독립 게임 설명 버튼과 F1을 유지했습니다. 설명서를 읽는 동안에도 경기 시간이 흐른다는 기존 안내를 표시합니다.

확정 메시지·필드·오류 계약을 기존 인증 소켓과 FE 런타임에 연결했습니다. 로컬 계약 fixture 검증과 실제 개발 서버 공동 검수는 구분합니다.

## 4. BE 구현 완료 항목(최초 요청 기준)

### A. 해당 경기 관전자 채팅 전달

- 실제로 해당 오목 경기의 관전이 승인된 사용자만 경기 관전 채팅을 보낼 수 있도록 처리해주세요.
- 승인한 메시지를 해당 경기의 두 플레이어에게 전달해주세요. 플레이어는 이 기능으로 채팅을 보내지 않고 수신만 합니다.
- 경기 ID와 발신자·이벤트 식별자를 함께 전달하여 다른 경기/일반 공원 채팅이 섞이지 않게 해주세요. 발신자와 역할은 서버 연결에서 확인해주세요.
- 최종 확정: 두 플레이어와 해당 경기의 승인 관전자 전체가 같은 경기 채팅을 받습니다.

### B. 관전자 위치 추천 핑 전달

- 해당 경기의 승인된 관전자가 보낸 오목판 좌표를 검사한 뒤, **두 플레이어와 해당 경기의 승인된 관전자 모두**에게 전달해주세요.
- 좌표는 화면/월드 위치가 아닌 오목판의 `x=열`, `y=행`, 각각 `0~14` 정수로 사용하려고 합니다.
- 좌표와 함께 경기 ID·발신자·이벤트 ID·기준 판 버전·발생/만료 시각을 전달하는 계약을 제안드립니다. 최종 필드는 기존 상태/시각 계약과 맞춰 확정해주세요.
- 핑은 위치 추천이며 착수가 아닙니다. 기존 착수 명령과 분리하고 판·차례·경기 버전·마감·승패·정산을 변경하지 않게 해주세요.

### C. 공통 처리와 정리

- 기존 인증 소켓과 관전 구독·채널·거리 검사 경로를 활용해주세요. 테이블 정보 조회만 했거나 단순히 근처에 있는 사용자는 관전자 발신자로 인정하지 않습니다.
- 다른 경기·채널, 관전 종료·거리 이탈·연결 종료·경기 종료 상태에서는 발신과 새 전달을 차단해주세요.
- 중복 이벤트의 재방송, 오래된 판 버전의 핑, 과도한 전송을 처리하고 재접속 시 과거 채팅·핑을 다시 보내지 않게 해주세요.
- 새 기능으로 기존 착수·30초 타이머·시간패·금수·기권·복구·정산 처리에 영향을 주지 않게 해주세요. F1을 열어도 서버 시간은 기존대로 진행합니다.

## 5. 선행 작업과 연동 순서

이 작업은 아직 머지되지 않은 **게임 진입→게임 선택→준비→방장 수동 시작** 작업 이후 동작하는 후속 기능입니다. 선행 작업의 승인 상태와 실제 게임 ID를 사용합니다.

선행 작업과 충돌하면 선행 작업을 유지하고 이번 후속 작업을 맞추겠습니다. 준비/시작 계약을 이번 요청에 맞춰 다시 변경하는 것은 요청 범위가 아닙니다.

BE 최종 계약에 FE 표시를 연결한 로컬 구현을 반영했습니다. 최종 선행 작업 머지·개발 서버 배포 후 실제 계정으로 공동 검수합니다.

## 6. 수령한 최종 계약

1. 메시지명·요청 payload는 FE 초안을 유지하며 시각 3종은 Unix milliseconds 숫자입니다.
2. 첫 GAME_STATE까지 받은 인증 관전자만 발신하고, 두 플레이어와 승인 관전자 전체가 수신합니다.
3. 채팅 TTL 3초·핑 TTL 2초, 사용자별 각각 1초 간격, 경기별 채팅 3건/3초·핑 5건/2초입니다.
4. 발신자는 원래 requestId 승인 이벤트, 다른 수신자는 requestId=null입니다. ACK는 승인·전달 시도 확인이며 모든 화면 도착을 보장하지 않습니다.
5. FE는 현재 판 버전과 같은 핑만 표시하며 낮은 버전·만료·중복을 버립니다. 높은 버전은 만료 이내에서만 제한적으로 기다립니다. 자동 재시도·과거 이력 재생은 하지 않습니다.

정확한 JSON·오류 코드·권한·큐 포화 정책은 [최종 WebSocket 계약](../../docs/websocket-api/10-game-spectator-events.md)을 따릅니다. 최초 요청의 제안 문구보다 이 확정 계약이 우선합니다.

## 7. 공동 검수 완료 기준

- 두 플레이어와 관전자 2명 이상이 같은 경기에 참여하여 채팅·핑을 확인합니다.
- 관전자 채팅·핑 모두 두 플레이어와 전체 승인 관전자에게 전달되어야 합니다.
- 양쪽 플레이어의 판 방향이 달라도 동일 교차점에 핑이 표시되어야 합니다.
- 다른 경기 유입·중복·버전 지연·관전 해제·종료 이후 전달이 차단되어야 합니다.
- 채팅·핑 사용 중에도 기존 착수·시간 만료·기권·결과/정산이 정상 동작해야 합니다.
