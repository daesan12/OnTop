# M04 — 감정표현·G 휠 분리

2026-10-24. M03 커밋 `b727cef` 위에 M04만 추가한다. 최신 GitLab dev 기준은 `69a9d19`이며, 같은 작업 브랜치에 독립 커밋으로 쌓는다. 원본 작업본을 보존하고 병합·배포하지 않는다.

## 사용자 조작

- G를 누른 채 마우스로 선택하고 놓아 실행한다. 중앙·빈 칸에서 놓으면 취소한다.
- 버튼 클릭 후 표현을 클릭하거나 방향키·Enter/Space로 선택한다. Tab/Shift+Tab은 휠 내부 버튼을 순환한다.
- Esc·우클릭·blur·탭 비활성·화면 크기 변경·포커스 이탈·연결/맵 변경 시 닫는다.
- 채팅·지도·설명서·미니게임 입력 소유권을 유지하고 휠 안의 이동/점프/E·Enter가 공원에 새지 않게 한다. 후속 공통 설명서를 위해 F1은 소비하지 않는다.
- 다섯 표현과 빈 세 칸을 유지한다. 악수·판 엎기를 임의로 채우지 않는다.
- 기존 테이블 정보창이 열리면 휠을 닫고 버튼을 숨긴다. 정보창 위에서 G로 다시 열리지 않게 한다.
- 작은 화면에서는 휠을 축소한다. 기존 로그인·HUD·채팅·벤치·테이블 UI를 재사용한다.

## 기존 BE와 목업 경계

기준 BE의 `WorldEmoteService.java`, `WorldEmoteProperties.java`, `TableHub.java`, `application-visual-test.yml`을 확인했다. 기존 `WORLD_EMOTE_SEND {emoteCode}`와 `WORLD_EMOTE_EVENT`를 사용한다. 본인 응답은 원래 requestId, 다른 시청자 방송은 null requestId다. 서버는 등록 코드와 최소 간격을 검사한다.

검증 설정에 WAVE·CLAP이 있지만 운영 기본 코드 목록은 비어 있다. 이를 최종 운영 카탈로그로 확정하지 않는다. 환경별 기존 park-bindings JSON의 선택적 `emotes` 매핑이 있는 경우에만 해당 코드를 기존 소켓으로 전송한다. 새 카탈로그 API·WS 명령·DTO를 만들지 않는다.

| 표현 | 실제 연결 | 미연결일 때 |
| --- | --- | --- |
| 손 인사·박수 | 매핑된 기존 BE 코드 사용 | 미연결/비활성, 목업 대체 없음 |
| 박수 부탁·에잉 쯧쯧·방귀 | 승인된 매핑이 있으면 기존 BE 코드 사용 | `DEV && MODE === facility-preview`에서만 현재 화면 목업, 운영 비활성 |
| 판 엎기·악수 | 이번 커밋에 자동 발동·선택 기능 없음 | 기권 승인/발동 대상·상대 지정·수락 등의 계약 검수 대기 |

facility-preview에서 배치 JSON의 `emotes`가 아예 없을 때만 WAVE·CLAP 검증용 기본 매핑을 제공한다. 명시적인 빈 배열은 해당 매핑을 비활성화한다. 실제 BE가 해당 코드를 등록하지 않았거나 요청을 거절하면 오류를 표시하고 목업 성공으로 전환하지 않는다. 이 모드도 기존 실제 로그인·월드 연결이 필요하다.

배치 설정 예시는 다음과 같다. 기존 `bindings`는 유지한다. 운영에서는 BE 담당자가 등록한 코드와 모션 의미를 확인한 뒤 환경별 파일에 설정한다. 이번 커밋에서는 실제 배치 JSON을 바꾸지 않았다.

```json
{
  "bindings": [],
  "emotes": [
    { "motion": "EMOTE_WAVE", "code": "WAVE" },
    { "motion": "EMOTE_CLAP", "code": "CLAP" }
  ]
}
```

목업은 세 미연결 표현의 비동기 승인 모양만 재현하고 현재 화면의 본인에게만 표시한다. 다른 창/사용자에게 방송하거나 계정·지갑·경기를 대체하지 않는다. 릴리스에서는 목업 호출 분기가 제거되고 `check:migration`이 서비스 식별 문자열 유입을 검사한다.

## 승인·재생·취소

SharedSocket의 선택적 콜백으로 전송 전에 requestId를 기록한다. 기존 호출 방식과 wire 형식은 유지한다. 본인은 정확한 대기 요청의 승인 뒤에 재생하고, 타인은 같은 채널의 알려진 아바타·명시적으로 매핑한 코드만 표시한다.

시작 시각은 승인 `sentAt`이다. eventId 중복·오래된 순서·종료된 표현·다른 채널·알 수 없는 사용자를 무시한다. 중복 이력은 재접속에도 잠시 유지하고 2,048건/10초로 제한한다. 스냅샷을 새 재생 요청으로 해석하지 않는다.

이동/점프 의도, 승인 이동·수영·높이 변화, 착석 전환·본인 아바타 제거는 표시/대기 표현을 취소한다. 0 방향 정지·heartbeat는 취소하지 않는다. 늦은 승인으로 재생이 살아나지 않게 하되 이미 승인된 쿨다운은 유지한다. 타임아웃/채널 변경 뒤에는 이전 요청을 되살리거나 자동 재전송하지 않는다. 본인 제거 후 복귀의 늦은 승인도 별도 회귀 검사한다.

박수 약 4.867초·손 인사 2.6초·각 쿨다운 5초와 나머지 기존 표시 시간/쿨다운은 FE 표시 설정이다. BE 기본 최소 간격 1초를 제품의 5초 규칙으로 바꾸었다고 주장하지 않는다. 서버와의 큰 시계 오차·상태별 허용/취소 정책은 공동 검수가 필요하다.

## 검증 실행

```sh
pnpm typecheck:tests
pnpm test
pnpm build
pnpm check:migration
pnpm test:e2e:facilities
pnpm exec playwright test tests/e2e/park.spec.ts tests/e2e/omok.spec.ts
```

`playwright.facilities.config.ts`는 명시적인 facility-preview 서버에서 M01~M04를 실행한다. 일반 `playwright.config.ts`에서는 개발 목업 전용 M04 시나리오를 제외한다. 이를 통해 일반 개발/운영과 개발 전용 목업 검증을 구분한다.

Browser plugin not available. 기존 Playwright/Edge와 테스트 전용 HTTP/WS 계약 대역을 사용한다. preview는 `127.0.0.1:5196`, 일반 모드 회귀는 별도 QA 설정의 `127.0.0.1:5198`에서 확인한다. 데스크톱 1920×1080·오목 1280×720·모바일 휠/로그인 390×844를 확인하고 화면은 저장소 외부 QA 폴더에 저장한다.

두 시청자 검증은 두 페이지에 같은 승인 이벤트를 전달해 시각·중복·재접속 처리를 확인한다. 실제 Java 서버 방송·운영 코드 등록·시설 상태별 정책 검증은 별도다. 기존 Three.Clock/ANGLE 정밀도·큰 3D 청크 경고는 남아 있다.
