# 상점·보유 아이템 FE 연결

2026-10-25, `feat/frontend-shop-integration`. 기준 dev `271f6f1`에서 FE만 변경한다.
BE 계약은 저장소 `docs/shop-inventory.md`, `docs/world-websocket-api.md` 기준이다.

## 진입·요청

공원 오른쪽 계정 영역의 **상점 · 옷장**에서 상품 목록·보유 아이템을 연다.
현재 서버 상품·가격만 표시하며 정식 상품·가격·의상 모델을 FE가 만들지 않는다.
기존 Access JWT·401 갱신·실패 종료·요청 취소 경로를 재사용한다.

| 기능 | 기존 API | FE 본문·헤더 |
|---|---|---|
| 상품 | GET `/api/v1/shop/items` | 본문 없음 |
| 구매 | POST `/api/v1/shop/purchases` | `Idempotency-Key`, `{itemId,quantity}` |
| 보유 | GET `/api/v1/users/me/items` | 본문 없음 |
| 장착 | PATCH `/api/v1/users/me/equipment` | `{userItemId}` |

- 구매 선택 → 수량 확인(의상은 1) → 명시적 구매 확정. 연타·중복 동시 구매를 차단한다.
- 승인받기 전 임의 차감·보유 지급·장착 변경을 하지 않는다. 소비·장착 해제 API/UI는 추가하지 않는다.
- 의상 중복 구매는 REJECT 계약을 따르며 기보유 의상 선택을 막고 서버의 `ITEM_ALREADY_OWNED`도 처리한다.
- 실패는 빈 상품/구매 성공/목업으로 바꾸지 않는다. 미설정·잔액 부족·지갑 미준비·동일 키 충돌을 구분한다.
- 구매 영수증의 `balanceAfter`는 과거 잔액이다. 구매/장착 승인 후 목록과 GET `/api/v1/wallets/me`를 새로 읽고, 현재 지갑 GET만 HUD에 반영한다. 예약금을 구매 가능 잔액으로 더하지 않는다.

## 구매 재시도와 수명

- 같은 구매의 미확정 상태에서는 키·itemId·quantity를 고정한다. 네트워크/5xx/응답 형식 오류는 새 키로 재구매하지 않고 **같은 구매 다시 확인**으로 재요청한다.
- 401 갱신 재요청도 동일 헤더·본문을 유지한다. 확정 거절 또는 영수증 확인 후에만 해당 미확정 요청을 정리한다. 충돌은 확인이 필요하므로 새 키로 자동 대체하지 않는다.
- 닫기·연결/채널 전환은 진행 요청을 취소하고 늦은 UI 응답을 무시한다. 같은 계정의 미확정 구매는 유지하며 자동 POST 재전송은 없다.
- 탭 새로고침 복구를 위해 미확정 키·상품 ID·수량·이름만 해당 계정의 `sessionStorage`에 보관한다. JWT·잔액·보유 목록을 저장하지 않는다. 승인·확정 거절·로그아웃/공원 언마운트 시 삭제한다. 저장소 접근이 막히면 현재 화면의 메모리 재시도만 유지한다.
- 다른 계정의 응답·미확정 구매는 사용하지 않는다. 최신 읽기 요청이 이전 목록·잔액 응답에 덮이지 않게 한다.

## 월드 장착 정보와 외형 한계

- `WORLD_STATE.payload.avatars[].equipment`의 공개 4필드(`itemId,itemCode,equipSlot,imageKey`)만 수신한다. 최대 5개·부위당 하나를 검사한다.
- `null`/누락은 비동기 조회 대기·실패이므로 기존 승인 외형을 유지한다. `[]`는 성공한 장착 없음으로 비운다.
- 이전 버전·다른 채널의 상태를 무시하고, 퇴장·채널 전환·재접속에서는 이전 장착 캐시를 정리한다.
- 같은 정보의 이동 tick은 장착 배열 참조를 유지한다. 변경은 해당 아바타 렌더러에 전달하며 현재 남녀 리그·스켈레톤·모션·LOD를 교체하지 않는다.
- **사용자가 상품별 에셋 매핑 자료가 아직 없음을 확인했다.** 현재 수신 정보는 아바타 렌더러의 `userData.equipment`까지 전달하며, 의상별 메시/텍스처 변경은 수행하지 않는다. 보유 UI에도 외형 준비 중을 표시한다. 이것을 상품별 실제 3D 외형 반영 완료로 보고하지 않는다.
- `imageKey`는 불투명 키이며 URL/색상/기본 캐릭터 선택값으로 추측하지 않는다. 실제 itemCode/imageKey → 남녀 리그별 자산 매핑이 제공되면 후속 렌더링을 연결한다.

## 입력과 실행 검증

네이티브 모달·포커스 순환과 공통 입력 잠금으로 이동/점프·E/G/M·채팅 Enter 충돌을 막는다. 닫기 후 로밍 입력을 복구한다. F1은 상점을 닫고 기존 설명서를 연다.

Browser plugin not available: 기존 Playwright/Edge를 사용한다. 계약 테스트의 상품·영수증·HTTP/WS 대역은 테스트 폴더에만 존재하며, 실제 공유 DB 차감·장착·다중 계정 검증과 구분한다.

검사: `pnpm typecheck:tests`, `pnpm test`, `pnpm build`, `pnpm check:migration`, `pnpm exec playwright test tests/e2e/shop.spec.ts` 및 관련 기존 회귀.
스크린샷·실행 산출물은 저장소 밖 `shop-integration`에 보관한다.

최종 로컬 검증: 타입·빌드·경계 검사, 단위 42파일/381개 통과. Edge의 1920×1080 및 390×844에서
상점 6개 시나리오와 기존 프로필·감정표현·시설·설명서·지도·공원 회귀 36개, 총 42개 통과.
상점 검사는 구매/동일 키·본문 재시도, 응답 유실 후 닫기·새로고침 복구, 과거 영수증 잔액과 현재 잔액 구분,
401 갱신·거절, 소유 의상 교체·승인 WS 대기·null 유지/빈 배열 제거, 모달 입력·F1·모바일 포커스와 로그아웃 정리를 포함한다.
초기 검사에서는 기대 잔액/포커스 전제의 테스트 오류 2개와 모바일 상점 버튼/F1 겹침 1개를 발견했다.
테스트 전제를 수정하고 실제 버튼 배치를 보완한 뒤 최종 전체 상점 검사를 통과했다. 기존 Three.Clock·Intel 셰이더·큰 청크 경고는 남아 있다.
실제 계정 DB 구매·차감·의상 외형 변경이 성공한 것으로 확대하지 않는다.

## BE 준비 후 실서버 검수

BE가 개발 서버 배포·활성화·CORS 준비 완료를 알리면 실제 계정으로 상품 → 구매 → 같은 키 재확인 → 최신 지갑 → 보유 → 장착 → 본인/다른 계정 WORLD_STATE → 재접속을 검증한다.
정식 의상 자산이 없으면 장착 데이터 전달과 실제 의상 렌더링 검증을 분리한다.

BE·인증 코드·DB·상품 데이터·CORS/배포 설정·Flyway V100은 변경하지 않는다. V100 적용 이력과 버전 순서·기존 locations 보존은 팀의 Flyway 정책에 따라 BE가 확인한다.
