# 오목판·돌 최적화 상태

2026-10-22. **제한된 비교는 수행했지만 전체 13.6 게이트는 미완료**다. 새 GLB·이미지·폰트 없이 절차 형상을 사용한다. 원본 프로토타입의 고급 나무판/바둑통 장식 전체를 이관한 것은 아니며 이번 범위는 게임 조작 준비다.

## 적용

- 판: 단순 Box 하나, 격자: LineSegments 하나. 흑/백 돌은 공유 SphereGeometry 하나·각각 공유 재질·InstancedMesh 두 개다. 돌당 mesh/material을 만들지 않는다.
- 비교 기준은 원본 오목 돌과 같은 16×10 구 분할(288삼각형/돌), 최종은 12×8(168삼각형/돌)이다. 75돌의 삼각형 21,600→12,600. 메시·돌 좌표·클릭/턴 규칙은 바꾸지 않는다.
- 선택된/확인된 테이블에만 게임판 컴포넌트를 생성한다. 판의 정적 재질/돌 geometry는 앱 수명 동안 공유하며 격자 geometry는 해제한다. 아바타·시설·전체 맵을 합치지 않는다. 돌은 인스턴스 경계 구를 재계산해 프러스텀 컬링한다.
- 작은 근접 조작판은 추가 돌 LOD 대신 간소화 형상과 인스턴싱을 사용한다. 원거리/여러 테이블 동시 사용의 LOD 전수 검토는 남는다.
- 이 자산에는 텍스처가 없어 해상도 축소·KTX2·라이트맵은 적용 대상이 아니다. GLB 전송도 없어 Meshopt 파일 압축은 적용 대상이 아니다. 공원 전체의 기존 텍스처/스트리밍 미완료 상태를 해결한 것은 아니다. 새 그림자 광원·후처리를 추가하지 않는다.

## 맞춘 조건과 결과

Core Ultra 9 185H / Intel Arc 내장 GPU(ANGLE D3D11), Windows, Edge 155.0.4283.62 headless, WebGL 2, Low. 뷰포트1920×1080 / 실제 Canvas1280×720. 16명 표시(본인 착석으로 본인 mesh는 숨김), 정지 아바타, 동일 착석 카메라 (-10,1.35,19.25). 낮 phase .6 / 밤 .05, 로컬 HTTP/RawWS 계약 대역·WAN 지연 미주입. 75돌은 **합법 수순/실제 경기 테스트가 아닌 서버 공개 판 모양의 렌더 부하 자료**다.

각 조건 60프레임 이상 워밍업 뒤 180프레임 이상 측정, GPU는 EXT_disjoint_timer_query_webgl2 유효8표본 평균이다. 스크린샷은 표본 뒤에 수집했다. CPU 작업별 분리는 미측정이며 아래는 전체 프레임 분포다. 낮/밤 각각 no-board는 게임 선택 전 게임판 미마운트 기준선이다. 전체 JS/앱 캐시까지 제거한 힙 기준선은 아니다.

추가 외부 GLB/이미지 요청은 없고 형상 코드는 JS 청크에 포함된다. 자산 단독 JS 전송량 분리는 미측정이다. **프레임/FPS/GPU 개선은 입증하지 않았다.** 75돌 GPU 평균은 두 조건 모두 소폭 증가했으며 작은 단일 비교 표본으로 원인을 단정하지 않는다.

## 확인과 남은 범위

3D 정확한 좌표 클릭·드래그 방지·시점 전환·원격 전신·화면 판 표시를 기능 회귀로 검증한다. 낮/밤 Low의 간소화 전후 모습도 수집했다. 모든 돌 배치/가림/High 그림자·외장 GPU·다른 브라우저/WebGPU·장시간 생성/해제·상한225돌·여러 경기판·실제 WAN·CPU/GPU 반복 교차 측정은 미완료다. 전체 최적화나 목표 FPS 달성을 선언하지 않는다.

재현: RUN_OMOK_ASSET_QA=1로 tests/e2e/omok-assets.spec.ts 실행. ASSET_QA_LABEL로 비교 실행을 구분한다. 기준 비교는 최종 소스의 SphereGeometry 분할만 임시로16×10으로 바꾸어 실행하고 원복한 뒤12×8을 실행했다. 원시 JSON/스크린샷은 프로젝트 밖 로컬 QA 산출물이며 커밋하지 않는다.
