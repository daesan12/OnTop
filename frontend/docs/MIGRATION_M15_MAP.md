# M15 지도·개인 길 안내

## 작업 경계

- 도움말·룰북을 먼저 `61910ad80aaa1831daca3b3ed947e04b0bcbedc1`로 커밋해 GitLab `feat/frontend-m15-manual-rulebooks`에 푸시했다. 원격 SHA 일치를 확인한 뒤 같은 브랜치에서 지도 작업을 시작했다.
- 이 문서는 그 다음 지도 변경에 대한 기록이다. 지도 변경만 별도 커밋으로 분리해 같은 브랜치에 푸시하는 범위이며, 머지·배포는 포함하지 않는다.
- 원본 `topgoal/apps/web/src/features/ParkMap.tsx`, `features/navigation/`, `styles.css`의 녹색 지도·장소 번호/목록·위치 마커·청록 경로·화살표 HUD를 이관했다. 현재 OnTop 시설 상수를 사용하고 원본 코드/파일은 수정하지 않았다.
- 신규 REST/WS 계약·인증·자동 이동·재화 처리를 추가하지 않는다. 기존 로그인·채널·월드 이동·테이블/시설·게임·지갑 연결을 유지한다. BE·DB·Flyway·배포 설정 변경은 없다. 지도는 FE 개인 표시 기능이므로 새 운영 목업이 필요하지 않다.

## 화면과 조작

- M 또는 상단 지도 버튼으로 열고 M·Esc·닫기 버튼으로 닫는다. native dialog로 배경 입력을 막고 Tab을 지도 안에서 순환시키며 닫은 후 이전 포커스로 돌아간다.
- 장소 번호·목록·지도 지점 클릭으로 목적지를 고른다. 안내는 **직접 WASD로 이동**하면서 방향 화살표·남은 경로 거리·지도 경로를 확인하는 방식이다. ×로 취소하고 도착 표시는 3초 후 정리한다.
- 서버가 승인한 기존 월드 위치를 사용한다. 지도 위치는 500ms, 안내 방향/거리는 200ms 간격으로 갱신한다. 그림의 다른 이용자 마커가 혼잡하면 실제 좌표에서 연결선을 유지하며 표시만 옮긴다. 인원 마커·연결선이 목적지 클릭을 가리지 않도록 분리했다.
- F1은 지도를 닫고 기존 공통 도움말을 연다. 채팅·IME·수정키·G 휠·다른 대화상자·미니게임 중 M이 입력을 가로채지 않는다. 열고 닫을 때 held movement/drag를 지우며 서버의 이동 전송 간격은 변경하지 않는다.
- 착석·게임·벤치·운동기구·망원경·붕어빵·설명서/작성 패널 중에는 안내를 숨기고 산책 복귀 시 이어간다. 그래픽 설정을 열 때 안내 HUD가 설정을 가리지 않게 숨긴다. 현재 성능 UI 자체는 유지했다.
- 목적지는 메모리에만 보관하며 계정·채널 변경/공원 종료 시 정리한다. 브라우저별로 독립이고 저장소나 서버로 공유하지 않는다. 서버 맵 버전 확인에 실패하면 지도에 경고를 표시하고 길 안내 선택을 막는다.

## 경로와 현재 맵

- 기존 0.75m 정적 격자 A*, 공간 인덱스·정적 연결 캐시·산책로/목교 우선 비용을 재사용한다. 현재 `WORLD_COLLIDERS`, 회전 가구의 이동 footprint, 지형, 팔각정 바닥/계단, 캐릭터 반경·stepHeight를 기준으로 연결 구간을 약 0.16m 간격으로 검사한다.
- 주요 장소 11곳의 접근 지점을 현재 시설 상수에서 계산한다. 장소 중심이 가구/물/다층 구조라면 걷기 가능한 입구/주변을 목적지로 사용한다. 전망대는 지상 입구까지이며 상층에서는 지상 복귀 안내를 표시한다.
- 호수 내부·맵 밖·비정상 좌표는 거부한다. 도달하지 못하면 실패를 표시하며 직선이나 이동 명령으로 대체하지 않는다. 장애물 지점은 약 3m 이내의 접근 가능한 주변 지점으로 보정할 수 있다.
- 승인 legacy 맵 fingerprint는 분수·돌 좌석 충돌 보정본 `ae833248d2dd356c6603af72b2b865f9051a866e9cfa7d2b9c9abe890579944d`로 2026-10-27 갱신했다. 미터/Y-up, 시설 위치·이동 권한은 유지하며 BE `world/park.json`·시설 카탈로그와 같은 버전을 사용한다. 180m 생성 맵 전환은 포함하지 않는다.
- 층간 전망대 길찾기, 디딤돌 점프 경로, 다른 플레이어의 동적 회피는 범위 밖이다. 물리 엔진의 최종 이동 승인을 그대로 따른다.

## 입력 응답과 자원 수명

- 장거리 탐색에서 주 스레드 계산 약 0.26초를 관측해, 계산을 별도 module Worker로 옮겼다. 워커는 목적지 선택 시 만들고 현재 목적지의 재탐색 동안 격자 캐시를 공유한다. 취소·도착 정리·계정/채널/목적지 변경·공원 해제 시 종료해 캐시를 해제한다.
- 같은 목적지에는 한 요청만 진행하며 reply ID·맵 버전·계정/채널·목적지 소유권을 검사한다. 지난 응답은 현재 안내를 덮어쓰지 못한다. 로드 오류·5초 초과는 실패로 표시하고 새 목적지 선택으로 재시도한다. 주 스레드의 무거운 계산이나 가짜 경로로 대체하지 않는다.
- 2026-10-25 Edge 156/WebGL2 검증에서 워커 계산 314.5ms, 시작/왕복 포함 383.4ms 동안 10ms UI 타이머가 37회 동작하고 기존 WORLD_MOVE 전송이 유지됐다. 계산 자체가 빨라졌다는 뜻이 아니라 UI/이동 타이머와 분리됐음을 확인한 것이다.
- 배포 워커 `navigation.worker-DOdv6Htr.js`는 49,910B이며 첫 목적지 선택 시 로드한다. 배포 빌드에서 실제 해시 파일 로드와 취소 후 worker 종료를 확인했다. 새로운 래스터/GLB/텍스처 요청은 추가하지 않는다.

## 지도 최적화·시각 검수

- 원본의 sampled edge별 SVG line을 현재 산책로별 polyline으로 묶고, 변하지 않는 지도 배경을 React.memo로 분리했다. 같은 창에서 원본 선분 표현을 QA DOM으로 재구성한 경우 SVG 요소 1,137개(숨긴 최적화 polyline 포함), 최적화 표현 528개를 관측했다. 원본 색·시설·나무·호수·벤치 표시를 유지한다.
- PC 내장 Intel Arc / Core Ultra 9 185H, Edge 156.0.4314.42, Low, 1920×1080(3D 버퍼 1280×720), 동일 카메라·8명 계약 fixture 장면에서 측정했다. 별도 Browser plugin이 없어 기존 Playwright/Edge를 사용했다.

- 장면 geometry buffer 추정 41,350,374B, texture 픽셀 추정 약 175,084,885B는 동일했다. 브라우저 DOM/워커의 전체 메모리를 측정한 것은 아니다. 약 2.5초 프레임 표본이며 GPU query/전체 CPU 작업 시간·네트워크 지연을 측정하지 않았다. FPS 향상을 보장하지 않는다.
- 지도는 HTML/SVG여서 3D LOD·그림자·Meshopt·KTX2·메시 병합은 대상이 아니다. 지도 닫힘 시 SVG 노드를 제거하고, 방향/거리 갱신은 렌더 프레임 루프와 분리한다. 낮/밤·반복 열기/닫기·1280×720 PC 화면·포커스/입력 복귀를 확인했다. 기존 월드의 광고/조명 자원 변동은 지도 비용과 구분한다.
