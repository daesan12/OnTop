# 새 공원 돌탑 점프맵 BE 추가 요청

작성·최신 동기화일: 2026-10-30. 기준: GitLab origin/dev `28f95f6ad794f5bb4374e9b4636cfbf605712461`.

작업 재개 시 GitLab을 fetch해 기존 FE 변경을 최신 dev에 다시 적용했고, 검증 중 추가로 병합된 Jenkins 새 맵 배포 수정도 fast-forward로 받았습니다. 최신 광장·정문·게임 화면 및 새 맵 배포 수정이 포함된 기준입니다. 직접 작성한 변경은 FE 파일뿐이며 BE 소스, Jenkinsfile, infra 파일은 수정하지 않았습니다. 최신 dev에서도 아래 맵 충돌 버전과 코스 좌표는 동일합니다.

> 2026-10-30 광장 최종 후보에 맞춰 기본 mapVersion과 전달 JSON checksum을 갱신했다. 코스 좌표·규칙은 동일하며, 최초 통합 기준 기록과 별도로 [공동 전환 요청문](../../../docs/integration/park-180/plaza-infra-request.md)의 커밋·생성물을 사용한다.

## 전달 목적과 현재 상태

새 180m 공원에 이미 제작한 점프맵 모델·좌표를 그대로 재사용해 FE 서비스 경로에 통합했습니다. 새로운 모델을 만들거나 기존 맵을 재배치하지 않았습니다. 이 문서의 API·이벤트는 **이번 FE 구현의 연동 제안**이며, 기존 BE에서 구현·합의됐다는 뜻은 아닙니다. 원본 기획의 규칙은 유지하되 현재 Spring Raw WebSocket envelope와 `/api/v1` 체계로 옮겼습니다.

현재 BE에는 점프맵 서비스, 3D 발판 충돌, 보상·기록 이벤트가 없습니다. 따라서 운영 사용 준비가 끝나기 전에는 `enabled:false`를 유지해 주세요. API가 없거나 버전이 다르면 FE는 공원 이동을 유지하면서 출발 자리에서 준비 중으로 안내합니다. 브라우저 검증은 테스트용 REST/WS 응답으로 진행했으며 실제 지급·서버 물리 검증은 BE 연동 후 필요합니다.

## 1. 우선 요청: 새 코스 충돌과 이동 검증

함께 전달하는 `course.generated.json`, `course.generated.sha256`을 사용해 주세요. 과거 `c1-fe-draft1` 임시 코스나 10/28 맵 전환 자료의 좌표를 적용하지 않습니다.

JSON SHA256은 `30ce531d815411476616d5144aa9649ecdb98db55415139c5d3f515989077e57`입니다. JSON과 SHA 파일은 Git checkout 시에도 LF를 유지하도록 고정했습니다. 전달받은 JSON의 실제 바이트로 checksum을 확인해 주세요.

| 항목 | 이번 FE 기준 |
| --- | --- |
| mapVersion | `e4c6e290be56dfb333a7b2fafd286664a5dd7f5e19ede0acfff859f6f6144200` |
| courseVersion | `park180-jump-v1` (이번 연동용 식별자 제안) |
| rulesVersion | `v2` |
| 일반 발판 / 중간 문 | 107개 / 6개, 총 113개 충돌체 |
| block | JSON `pads` 배열 순서의 0~112 정수. `id` 문자열도 FE 수신 가능 |
| stage / gate | stage는 1~7, 중간 gate는 1~6. gate 7은 마지막 연잎 이후 호수 다이빙 판정 |
| 좌표 | 미터, Y 위쪽. `top`은 윗면 높이. 중심은 `top - thickness/2` |
| shape | box는 `half` 반크기, cylinder는 `radius`와 `half[1]` 반높이 |
| yaw | 내보낸 collider yaw 적용. 방패연 box는 축 정렬, 모델의 회전과 구분 |
| 두께 | **현재 기존 방패연은 0.05m**. 원본 문서 0.12m와 다르므로 임의 확대 없이 JSON 기준 |
| 캐릭터끼리 | 서로 통과, 밀기·캐릭터 발판 타기 없음 |

기본 맵 생성기는 현재 `jump-course-3d-landing`을 제외합니다. 기본 `server-map.json`을 다시 받는 것만으로 이 발판이 추가되지 않습니다. 별도 코스 충돌을 Java 물리와 위치 검증 양쪽에 추가해야 합니다. FE도 기본 맵 mapVersion을 바꾸지 않고, matching status를 받은 뒤 별도 충돌을 활성화합니다. 코스 변경 시 courseVersion을 올리고 JSON을 다시 내보내 주세요.

`backend/.../world/movement/WorldPhysics.java`에는 `CLIENT_VALIDATED` 경로가 있습니다. 클라이언트 위치 보고를 그대로 착지·보상 근거로 사용하지 말아 주세요. 서버 시뮬레이션으로 코스 위치를 검증하거나, 기존 위치 검증기에 발판 support/sweep·속도·점프 높이·순서·최소 도달 시간 검사를 추가한 뒤 보상을 켜야 합니다. 얇은 발판을 초속 20m로 내려올 때 관통하지 않는지도 서버 물리에서 확인해야 합니다. FE Rapier 검사만 통과한 상태입니다.

### 이동 보조 규칙

원본 v2의 코요테 100ms = 30Hz 3틱, 버퍼는 원본 BE 의사코드 기준 4틱 = 약 133.33ms로 구현했습니다. 기획의 표기 150ms와 양자화 값이 다르므로 **서버도 4틱을 사용할지, 정확한 150ms로 바꿀지 확인이 필요**합니다. FE는 `jumpGrace.ts`에서 조절할 수 있습니다.

FE 예측은 기존 60Hz를 유지하면서 위 시간 창을 적용합니다. 활성화된 점프맵의 v2 규칙은 코스 밖 공원 이동에도 적용되므로 BE도 동일하게 적용해 주세요. 재조정 시 남은 창을 복원하도록 자신의 `WORLD_STATE.avatars[].motion`에 다음 선택 필드를 연결했습니다. 서버에서 반드시 내려주면 도약 직전 재조정이 버퍼를 지우는 문제를 줄일 수 있습니다.

```json
{ "jumpGrace": { "coyoteTicks": 3, "jumpBufferTicks": 4 } }
```

범위는 각각 0~3 / 0~4입니다. 점프 소비 후 모두 0, 텔레포트·착석·이동 epoch 변경 시 초기화합니다. 기존 motion의 epoch/tick/appliedInputSeq/grounded/velocityY 등은 그대로 유지합니다.

## 2. REST 계약

인증·오류·쿠키/토큰 정책은 기존 공원 API와 같습니다. status는 현재 접속 채널을 명시해 여러 탭의 채널이 섞이지 않게 합니다.

### GET `/api/v1/minigames/jumpmap/status?channelId={channelId}`

```json
{
  "channelId": "channel-1",
  "mapVersion": "e4c6e290be56dfb333a7b2fafd286664a5dd7f5e19ede0acfff859f6f6144200",
  "revision": 12,
  "enabled": true,
  "courseVersion": "park180-jump-v1",
  "rulesVersion": "v2",
  "isFirstRun": false,
  "seenTips": ["START_SPOT", "RUN_STARTED"],
  "activeRunId": "run-example",
  "activeRun": {
    "runId": "run-example", "elapsedMs": 32000, "gatesPassed": 2,
    "finalReached": false, "maxHeight": 27.5, "runCoins": 6
  },
  "todayEarned": 6, "dailyCap": 100, "earningsDate": "2026-10-30",
  "bestFinishMs": null
}
```

진행 중이 아니면 activeRunId와 activeRun은 null입니다. 진행 중에는 **activeRun 전체를 반환**해 새로고침·재접속 후 진행/타이머를 복원해 주세요. activeRunId만 오면 FE는 복구 중으로 표시합니다. 최초 서버 준비 확인 후, 30초마다 다시 조회합니다. 실패하면 엽전 수입은 `—`, 기존 진행은 유지하며 30초 후 재시도합니다.

### POST `/api/v1/minigames/jumpmap/tips` → 204

```json
{ "tips": ["FIRST_GATE"] }
```

허용 키: START_SPOT, RUN_STARTED, FIRST_GATE, FIRST_FALL, FINAL_PAD. 인증 사용자별 set으로 중복 안전하게 저장합니다. FE는 세션 내 즉시 중복 방지하고 POST 실패 시 재시도합니다. 채널 이동·로그아웃 후 다른 사용자에게 기록을 섞지 않습니다.

## 3. WebSocket 계약

기존 `/ws/tables` 연결을 재사용합니다. 새 소켓·STOMP 구독은 필요 없습니다. envelope는 다음과 같습니다.

```json
{ "requestId": null, "type": "JUMPMAP_STARTED", "payload": {} }
```

아래 표의 payload 공통 약칭:

- **scope**: channelId, mapVersion. 서버가 검증한 현재 채널·맵입니다.
- **ordered**: scope + runId(string) + revision(0 이상 정수).
- **earnings**: todayEarned(0~100 정수), dailyCap(항상100), earningsDate(`YYYY-MM-DD`, Asia/Seoul).

**revision은 인증 사용자 + 채널 범위에서 새 run·늦은 정산·REST 사이에도 계속 증가**해야 합니다. 판마다 0으로 초기화하면 FE가 새 이벤트를 이전 것으로 판단합니다. 같은 상태는 같은 revision으로 재전송하고, REST는 원자적 스냅샷과 그 revision을 반환해 주세요. scope 내 사용자 계정의 이벤트만 private로 보내며 runId는 재사용하지 않습니다.

| type | payload 추가 필드 | 수신 범위 |
| --- | --- | --- |
| JUMPMAP_STARTED | ordered + earnings + rulesVersion, courseVersion, serverTime(epoch ms 정수) | 본인 |
| JUMPMAP_GATE | ordered + earnings + gate(1~7), elapsedMs, coinsCalculated(해당 문 기준 보상), coinsGranted(확정 정수 또는 pending일 때 null), pending(boolean), runCoins(확정 누계) | 본인 |
| JUMPMAP_GATE_SETTLED | ordered + earnings + gate, coinsGranted, **runCoins(확정 누계)** | 본인 |
| JUMPMAP_FINAL_PAD | ordered | 본인 |
| JUMPMAP_ENDED | ordered + earnings + reason, gatesPassed(0~7), maxHeight(미터), runCoins, elapsedMs | 본인 |
| JUMPMAP_STEP | scope + playerId(string), block(0~112 또는 canonical id) | 주변 사람 |

reason: FINISH, FALL, LAKE, DISCONNECT, TIMEOUT, RESET, LEFT. FINISH는 gatesPassed=7이며 finishMs(정수), bestFinishMs(정수 또는 null), newBest(boolean)를 추가합니다. 동점의 newBest 의미는 BE가 확정해 주세요. FE가 로컬 시간으로 최고 기록을 결정하지 않습니다.

`runCoins`, `todayEarned`는 **서버 누계**입니다. FE는 coinsGranted를 누계에 더하지 않습니다. pending 알림 후 확정 이벤트를 보내고, 판이 끝난 뒤에도 늦은 정산을 전달해 주세요. 같은 문 지급은 `userId + runId + gate` 등으로 멱등 처리합니다. 종료 후 늦은 지급은 마지막 결과 및 지갑 조회를 갱신하며, 다음 판의 runCoins를 덮지 않습니다. 한국 날짜가 바뀌면 earningsDate와 todayEarned를 함께 갱신해 주세요.

FE는 시작·문 통과·완주·보상 요청을 전송하지 않습니다. 일반 WORLD_MOVE / WORLD_POSITION 이동 채널만 사용합니다. 착지·떠남 미리보기는 시각/청각 효과일 뿐, 서버 판정·엽전 지급을 만들지 않습니다.

### 보상과 종료 판정

원본 최종 기획의 규칙을 적용해 주세요: 구간 순서, 문별 2·4·7·11·16·24·36냥, KST 일일 100냥, 낙하 시 기지급 보존, 7구간 마지막 연잎 후 정상 호수 진입만 완주, 그 외 낙하/호수 종료, 세이브·자동 복귀 없음. 초기/종료 발판과 호수 다이빙 좌표는 JSON start/finish/pads를 기준으로 판정 조건을 확정해 주세요. 기존 명세의 최소 시간·타임아웃·높이 및 거리 검증, 지급 실패 재시도, DB 기록·개인 최고 기록 저장도 필요합니다.

## 4. 인프라 확인

- 기존 `/api/v1` 프록시와 `/ws/tables`를 사용하므로 새 포트·별도 WebSocket 경로·새 에셋 CDN은 필요하지 않습니다.
- BE 코스 JSON은 서버 배포 산출물에 포함하고 FE와 같은 mapVersion/courseVersion/rulesVersion 및 SHA256인지 확인합니다.
- 새 맵 서비스 빌드는 `pnpm build:park` → `dist-park`입니다. 일반 `pnpm build`는 기존 맵을 유지하는 저장소 정책이므로 배포 대상 디렉터리를 확인해 주세요.
- 개발 `pnpm dev:park`도 새 맵 모드입니다. FE 코드만 배포하고 status를 true로 강제하지 않습니다. 서버 충돌·검증·지갑·저장 준비 후 true로 전환합니다.
- 최신 dev의 Jenkins는 `--local-config vercel.dev.json`을 사용하고, 이 설정은 dev bindings로 `build:park` → `dist-park`를 지정합니다. 배포 전에는 서버의 generated 맵 identity가 일치하는지 검사합니다. 해당 수정은 GitLab에서 받은 내용이며 이번 점프맵 작업에서 Jenkins/인프라 설정을 직접 수정하지 않았습니다. 실제 배포 및 서버 컨테이너 검사는 이 로컬 작업에서 실행하지 않았습니다.
- 실제 지갑 지급 재시도·일일 경계·중복 이벤트·끊김 복구를 스테이징에서 공동 검증합니다.
