# 돌탑 점프맵 FE 통합 및 검증

> 아래는 최초 통합의 검증 기록이다. 2026-10-30 광장 후보의 최신 기본 맵 버전은 `a0f4df03ce302cfc8a82d2c9c933ae1a8d58dfaea307640e1191a7ab4556a620`, 코스 JSON SHA-256은 `a492d99adbdb58fcde5b340a36ba4ee3ac084cbc0b09da478928e43ddf1e4fcc`다. 코스 좌표·규칙을 바꾸지 않고 생성물의 기본 맵 참조와 source fingerprint를 동기화했다. 현재 전달본은 [공동 전환 요청문](../../../docs/integration/park-180/plaza-infra-request.md)을 따른다.

통합 기준은 dev `28f95f6ad794f5bb4374e9b4636cfbf605712461`, 검증일은 2026-10-30입니다. 변경 범위는 frontend의 점프맵 구현·테스트·코스 전달 자료이며 BE·Jenkins·infra 파일은 수정하지 않았습니다. 실제 병합 및 배포 상태는 GitLab MR과 Jenkins 결과를 확인해 주세요.

최신 광장·정문 모델과 오목·원카드 화면 수정이 반영된 상태입니다. 현재 충돌 mapVersion은 `cac3cb040a43630b0b40201ab089a4b328146c03211867b2a155d2b3614acc81`로 유지됐고, 최신 accepted visual checkpoint도 함께 검증합니다. 코스는 새로 재구성하지 않고 이 버전의 기존 에셋을 직접 참조합니다.

## 반영한 기능

- 새 맵의 `layout-preview/jumpCourse.ts`, `jumpGeometry.ts`를 직접 참조해 7종 테마, 107개 일반 발판과 6개 문을 재사용합니다. 출발 자리와 호수 다이빙 엽전도 기존 모델입니다. 원본 모델·배치·미리보기 소스와 기본 맵 hash는 바꾸지 않았습니다.
- 새 맵 서비스 `WorldCanvas`에 전용 렌더러를 연결했습니다. 높은 발판의 단계적 디더링, 카메라와 아바타 사이 발판 흐림, 점유 발판 최소 가시성, 착지 변형·파티클과 겹친 다른 아바타 40% 표시를 처리합니다.
- 기존 로컬 이동 예측에 코스 충돌을 추가했습니다. API에서 맵·코스·규칙 버전이 맞고 enabled true여야 플랫폼 렌더링과 충돌을 함께 켭니다. 얇은 방패연 두께는 기존 0.05m 그대로입니다.
- 3틱 코요테 / 4틱 버퍼를 조건부 적용하고 서버 motion.jumpGrace 재조정 정보를 받을 수 있게 했습니다. 기획의 버퍼 150ms 표기와 BE 의사코드 4틱의 차이는 BE 요청 문서에 명시했습니다.
- 상태 조회, 재접속 도전 복구, 채널·사용자·맵 분리, 단조 revision에 따른 중복/역순 응답 무시를 연결했습니다. 실패 시 30초 재조회, KST 날짜 변경 시 일일 수입 재확인을 처리합니다.
- 도전 단계·현재 높이·경과 시간·일일 수입·보상 예상/정산 중/확정·낙하/완주 결과·개인 최고 기록을 표시합니다. 받은 엽전은 로컬에서 더하지 않고 기존 지갑 조회를 갱신합니다. 종료 후 늦은 정산도 지원합니다.
- 지도 목적지와 결과의 돌탑 길 안내, F1 설명서, 최초 안내 말풍선과 seenTips 저장을 연결했습니다. 길 안내는 직접 걷는 경로만 표시합니다.
- 기존 합성음 설계를 서비스 효과음 버스에 옮겨 전역 음소거/음량을 따릅니다. 본인 3겹, 다른 사람은 15m 안에서 ②만 감쇠·좌우 배치하며 합성음 동시 6개로 제한합니다. 방패연 떠남은 본인에게만 재생합니다. 숨은 탭에서는 신규 점프맵 소리를 재생하지 않습니다.
- 일반 기존 맵 빌드는 점프맵 코스·API·설명서 항목을 활성화하지 않습니다.
- 작업 복원 시 Git의 CRLF 변환으로 전달 JSON의 checksum이 달라지는 문제를 재현해 JSON/SHA 파일을 LF로 고정했습니다. 내보낸 실제 바이트 checksum과 최신 소스·맵·충돌 데이터를 검사하는 테스트를 추가했습니다.

## 실행과 전달

새 맵 개발 실행: frontend에서 `pnpm dev:park`. 새 맵 배포 산출물: `pnpm build:park` → `dist-park`.

코스 전달 자료 재생성: `pnpm jumpmap:export`. 변경 없이 일치 검사: `pnpm jumpmap:check`.

BE에 같은 폴더의 다음 3개 파일을 전달하면 됩니다.

1. `BE_추가요청_2026-10-30.md`
2. `course.generated.json`
3. `course.generated.sha256`

이번 JSON은 기본 맵 충돌 handoff와 별개입니다. 서버가 기본 맵만 갱신했다고 발판 충돌까지 적용되는 것은 아닙니다.

## 검증

- 최신 dev 기준 전체 Vitest: 155개 파일 통과, 1,347개 테스트 통과, 기존 2개 파일/4개 테스트 skip. Windows 샌드박스의 임시 파일 rename 제한을 피하고, 무거운 기존 에셋 검사의 CPU 경합을 줄이기 위해 일반 권한 실행에서 `--maxWorkers=4`로 확인했습니다. 점프맵·물리·설명서·예측 이동·맵 계약·최신 원본 에셋 보존 검사를 포함합니다.
- 타입 검사: 앱과 테스트 포함 `tsconfig.tests.json` 통과.
- `pnpm build:park`, 일반 `pnpm build`, `pnpm check:migration` 통과. 기본 맵 생성 산출물 변경 0개, 기본 mapVersion 유지.
- 최종 `28f95f6a` 반영 후에는 새 dev 배포 설정과 같은 `VITE_PARK_BINDINGS_URL=/park-bindings.generated.dev.json` 조건의 `build:park`도 통과했습니다. 실제 Vercel 배포와 서버 컨테이너 preflight는 실행하지 않았습니다.
- `pnpm map:check`, `pnpm jumpmap:check` 통과. 생성 코스 SHA256: `2467bae726f84075a65ce389530ef209d2c5d27e66d89ae0e94e81288fa2d9ae`.
- 실제 Rapier 검사: 5cm 방패연에 초속 20m 낙하 시 착지, 비활성화 시 충돌 제거 확인.
- Edge Playwright 점프맵: 시작/진행/지연 정산 중복 방지/F1, 낙하/늦은 정산/복귀 길 안내, 740×900 재접속 복구/완주 기록, BE 미구현 시 공원 유지/지도 안내, 오래된 코스·다른 서버 맵 차단의 5개 시나리오 통과. 세션 버전과 실제 렌더된 service-map의 identity를 함께 확인합니다. 1920×1080과 740×900 화면을 캡처 후 직접 확인했습니다.
- 최신 오목·원카드 회귀 Playwright: 화면 크기별 보기, 카드 끌기, 기권 취소, 정산 후 다음 판·나가기, 키보드 오목, 좁은 화면 채팅, 카드 선택·무늬·공격·선언·거절 복구의 9개 시나리오 통과. 처음 발견한 일반 테스트 서버의 jumpmap/status 404는 비활성 응답 fixture를 추가해 해결했습니다. 점프맵 자체의 실제 404 처리 시나리오는 별도로 유지합니다.
- 브라우저 plugin이 제공되지 않아 저장소의 Playwright + 설치된 Edge를 사용했습니다. React/페이지 예외와 WebGL shader 오류는 없었습니다. 기존 THREE.Clock 경고 및 ANGLE의 부동소수 정밀도 경고는 남아 있습니다.

테스트용 REST/WS 응답은 `tests/park-integration` 안에만 있습니다. 운영 앱에 가짜 시작·보상 버튼이나 우회 로그인·테스트 소켓을 추가하지 않았습니다.

## 아직 서비스 완료로 볼 수 없는 부분

**FE 통합 구현과 브라우저 검증은 완료했지만, 실제 BE 물리·보상·기록 연동 검증은 남아 있습니다.** 현재 서버에 점프맵 API와 충돌/이벤트 구현이 없으면 준비 중 상태로 표시하는 것이 정상입니다.

BE 담당자가 113개 충돌, 위치 검증, 시작/순서/낙하/다이빙 판정, 멱등 지급·일일 상한·늦은 정산, 복구 status·revision·기록을 구현해야 실제 플레이와 지급을 열 수 있습니다. 서버 물리로 전체 코스 완주, 여러 사람 착지와 겹침, 한국 자정 경계, 지연·재접속 시나리오를 스테이징에서 함께 확인해야 합니다.

새로운 최종 녹음 ASMR 파일이나 콘텐츠 제작은 하지 않았습니다. 기존 합성음과 모델을 재사용한 범위이며, 실제 다중 사용자 청취·믹싱 평가는 별도 플레이테스트가 필요합니다.
