# 공원 기능 BE 후속 요청 — 2026-10-29

## 전달 범위

이번 FE 변경과 별도로 BE 담당자가 구현할 내용만 정리한 요청서다. FE 소스와 테스트는 함께 MR로 올리며, BE 소스·물리 맵·맵 생성기는 수정하지 않았다. FE를 먼저 머지해도 아래 두 기능의 서버 동작까지 완료되는 것은 아니다.

| 항목 | FE에 포함한 작업 | BE에 요청하는 작업 |
| --- | --- | --- |
| 의자 | 이미 받은 승인 인원수에 맞춰 주변 사용자에게도 2·3·4개 의자 표시 | 채널·테이블별 실제 의자 충돌 활성화와 공개 상태 갱신 |
| 활동 말풍선 | 기존 공개 activity 필드의 GAME/SHOP 수신·표시, 본인 경기·상점 상태 연결 | 실제 활동 승인·해제·채널 방송, 추후 상점 진입·종료 계약 |

PICKUS 팝업, 테스트 광고·온탑 영상 삭제, 도착 반경 확대, 엽전 새로고침 UI 제거에는 이번 요청에 해당하는 BE 구현이 없다.

## 1. 보이지 않는 의자에 막히는 문제

### 원하는 결과

보이지 않는 의자 자리는 걸어서 지나갈 수 있어야 한다. 현재 서버는 정적 맵의 의자 네 개를 항상 충돌체로 등록하므로, 모델만 숨겨진 좌석 3·4에서도 이동이 막힌다.

| 서버 승인 상태 | 활성 의자 충돌 | 통과 가능한 의자 자리 |
| --- | --- | --- |
| 미설정 / 2인 | 좌석 1·2 | 좌석 3·4 |
| 3인 | 좌석 1·2·3 | 좌석 4 |
| 4인 | 좌석 1·2·3·4 | 없음 |

### BE 작업

1. `ParkScene` / `WorldPhysics`의 의자 등록 경로를 확인하고, 채널·테이블의 **서버 승인 설정**으로 충돌을 활성화·해제해 주세요. 정적 의자와 동적 의자를 중복 등록하지 않아야 합니다.
2. 기본 2개 이상을 유지하되, 승인 인원수와 현재 점유된 가장 큰 좌석 번호를 함께 고려해 주세요. 설정 초기화·게임 종료·마지막 퇴장에도 갱신하고, 점유 중인 의자를 임의로 없애지 않아야 합니다.
3. 의자가 생길 자리에 산책자가 이미 있을 때 고립되거나 튕기지 않도록 서버의 안전한 위치 처리도 적용해 주세요.
4. 공개 테이블 조회 응답의 승인 상태를 맞추고, 주변 산책자와 늦게 입장한 사용자도 최신 의자 수를 받도록 공개 갱신 계약을 전달해 주세요. 새 메시지가 필요하면 channelId, tableId, 순서/버전, 인원수, 초기화 규칙을 명시해 주세요.
5. tableId와 장면 anchorId는 기존 binding으로 연결해 주세요. 충돌 박스 접미사는 0-based, 공개 좌석은 1-based이므로 번호를 그대로 혼용하지 않아야 합니다.
6. 맵 구조/지문을 바꾸면 FE에서 함께 반영할 맵 버전과 자료를 전달해 주세요. 현재 FE는 서버 정적 맵과의 검증을 유지하고 있습니다.

### 완료 확인

2→3→4→2 전환 시 의자 표시와 실제 통과 여부가 일치해야 합니다. 서로 다른 두 채널의 설정이 섞이지 않고, 테이블·기둥 등 기존 충돌은 유지되어야 합니다. 설정 초기화, 점유된 4번 좌석, 의자 생성 위치의 산책자, 늦은 입장과 재접속도 확인 부탁드립니다.

## 2. 게임·상점 이용 활동 말풍선

### 원하는 결과

기존 붕어빵처럼 다른 사용자가 상대방의 활동을 머리 위 말풍선으로 알 수 있어야 한다. 본인 브라우저에서 만든 표시는 다른 사람에게 전달되지 않으므로 서버 공개 상태가 필요하다.

기존 `WORLD_STATE.avatars[].activity` 필드를 사용해 주세요.

| 값 | FE 표시 | BE 기준 |
| --- | --- | --- |
| `BUNGEOPPANG` | 붕어빵 뒤집는 중 | 기존 규칙 유지 |
| `GAME` | 게임 중 | 실제 보드게임 참가자의 경기 시작이 승인된 동안 |
| `SHOP` | 상점 이용중 | 추후 상점 진입이 승인된 동안 |
| `null` | 활동 말풍선 해제 | 활동 종료 확정 |

### BE 작업

1. 보드게임의 실제 참가자만 경기 시작 승인 시 `GAME`으로 방송해 주세요. 착석·게임 선택·대기·준비·관전은 제외해 주세요.
2. 정산 진입·경기 종료·무효·기권/탈락 확정·참가 종료 시 해당 사용자의 활동을 해제해 주세요. 다른 참가자의 진행 표시는 유지해야 합니다.
3. 같은 채널의 산책자가 참가/관전 요청 없이도 상태를 받아야 합니다. 늦은 입장·재접속에는 현재 상태를 전달하고, 오래된 시작/종료 이벤트가 새 활동을 덮어쓰지 않도록 처리해 주세요.
4. 기존 `BUNGEOPPANG` 활동과 채널 정리 동작은 유지해 주세요. 비공개 게임 정보나 자유 텍스트는 전달할 필요가 없습니다.
5. **상점은 추후 도입 시** 진입·종료 승인 계약을 먼저 공유해 주세요. 인증 사용자/채널 범위, 요청·응답, 멱등성 또는 lease 식별, 닫기·연결 종료·재접속·만료 규칙이 필요합니다. 목록 GET·지갑 GET이나 옷장 이용으로 상점 열림을 추정하지 않아야 합니다.

### 완료 확인

두 브라우저에서 A의 실제 경기 시작/종료에 따라 B에게 '게임 중'이 나타나고 사라져야 합니다. 대기자·관전자에게는 표시하지 않고, 채팅 말풍선 만료와 관계없이 활동이 유지되어야 합니다. 상점 도입 후에는 진입 승인·닫기·연결 종료·만료 시 '상점 이용중'도 확인해 주세요.

## BE 완료 후 FE에 전달할 내용

- 반영 브랜치/MR과 테스트 가능한 서버 환경
- 공개 의자 상태 갱신 계약 및 샘플 메시지
- 맵 변경 시 새 버전과 대응 자료
- GAME/SHOP 공개 상태 예시와 시작·해제 조건
- 추후 상점 진입·종료 계약

현재 FE는 새로운 의자 WS 메시지나 상점 API 이름을 추정해서 호출하지 않습니다. **공개 의자 갱신/맵 변경/상점 계약이 새로 확정되면 그 부분의 FE 연동은 후속 작업으로 진행합니다.** 기존 activity 필드의 GAME/SHOP 수신 준비와 실제 서버 전체 동작 검증은 구분해 주세요.
