# 수영·낮밤·이동·점프 관련 BE 확인 및 작업 요청

작성일: 2026-10-26 KST. 검토 기준: dev `2310dae`, FE 작업 브랜치 `fix/frontend-motion-clock`.

안녕하세요. 공원에서 수영 모션 이상, 사용자마다 다른 낮밤, 이동 끊김, 점프 반응 지연이 있어 FE에서 원인을 확인하고 수정했습니다. 서버의 시간 제공·이동 처리·접지 판정이 필요한 부분은 아래와 같이 확인 및 작업을 요청드립니다.

## 1. 사용자마다 낮과 밤이 다르게 보이는 문제

**기존 문제**

사용자가 접속한 시점을 기준으로 낮밤이 시작돼 같은 공원에서도 서로 다른 시간대로 보일 수 있었습니다. 서버의 공통 시간과 동기화하는 FE 연결 경로도 없었습니다.

**FE에서 진행한 작업**

접속 시점과 무관하게 한국 시간 `Asia/Seoul`의 공통 기준 시각으로 낮밤을 계산하도록 수정했습니다. 기존 게임 낮밤 한 주기 30분은 유지합니다. 다만 기기 시계가 틀린 사용자까지 일치시키려면 서버 기준 시간이 필요합니다.

**BE 요청**

모든 사용자에게 서버 현재 시각·공통 기준 시각·낮밤 주기를 제공할 계약과 입장/재접속/탭 복귀 시 재동기화 방법을 확정해주세요. 계약이 정해지면 FE에서 연결하겠습니다. 기준은 `2026-01-01T00:00:00+09:00`(Unix ms `1767193200000`), 주기는 30분입니다. 서버 재시작·채널/인스턴스가 달라도 동일하게 유지하고, 타임스탬프는 Unix ms로 전송해 9시간을 중복 가산하지 않도록 부탁드립니다.

## 2. 이동 중 뚝뚝 끊기거나 잠깐 멈추는 문제

**기존 문제**

FE가 이동 입력을 보낸 뒤 서버 응답을 기다리고, 응답 후 60ms를 더 기다렸습니다. 응답이 늦어지면 입력 간격이 서버의 250ms 입력 만료 기준을 넘을 수 있었습니다. 기존 개발 서버 실측에서도 첫 이동 시 입력 공백과 이동키를 누르는 중 `moving=false`가 관측됐습니다. FE의 긴 프레임 작업도 함께 관측돼 BE 단독 원인으로 확정하지는 않았습니다.

**FE에서 진행한 작업**

응답을 기다리는 구조를 제거하고 기존 60ms 입력 간격을 응답 시간과 독립적으로 유지하도록 수정했습니다. 기존 입력 형식과 서버 승인 좌표 기반 표시를 유지했습니다. 좌표 보간은 실측 재생에서 안정적이었던 프로토타입 방식을 유지합니다. 첫 이동의 긴 프레임 작업 원인 분석은 FE 후속 작업으로 남아 있습니다.

**BE 요청**

실제 개발 서버의 입력 최소 간격 50ms·입력 만료 250ms·물리 30Hz·변화 시 약 100ms 방송 설정을 확인해주세요. 이동 중지가 입력 만료·충돌·처리 지연 중 무엇인지 판단할 수 있도록 입력 seq/수락·만료 시각, 정지 사유, 물리 처리·방송 지연을 확인 부탁드립니다. 승인 좌표의 생성 시각 또는 물리 tick을 제공할 수 있는지도 협의 부탁드립니다.

기존 로그 확인 대상은 **2026-10-26 15:44:43~15:44:48 KST**, 검수 계정 `test`입니다. 로그가 남아 있지 않다면 FE 반영본 배포 후 재현·수집하면 됩니다. 제한/만료 시간을 우선 늘려달라는 요청은 아닙니다.

## 3. 스페이스를 눌러도 점프가 바로 반응하지 않는 문제

**기존 문제**

스페이스 입력이 FE의 다음 60ms 입력 수집 주기를 기다렸고, 전송 대기 중 이동키를 놓으면 대기 점프가 지워질 수 있었습니다. BE는 입력 수신과 실제 점프 실행 시 접지 여부를 확인하므로, 접지가 불안정하거나 착지 직전인 경우의 누락 가능성도 별도 확인이 필요합니다. BE에서 실제로 누락됐다는 실서버 검증 결과는 아직 없습니다.

**FE에서 진행한 작업**

스페이스를 누른 즉시 입력을 전송 큐에 등록하고, 방향키를 놓아도 대기 점프 한 번이 유지되도록 수정했습니다. 기존 60ms 전송 간격은 지키며, 창 전환·시설 이용·연결 변경 시에는 대기 입력을 취소합니다. 점프 물리나 서버 승인 좌표를 FE에서 변경하지 않았습니다.

**BE 요청**

평지 정지/걷기/달리기, 경사·이음새·난간, 착지 직전/직후에서 `onGround()` 판정으로 점프 입력이 폐기되는지 확인해주세요. 접지가 불안정하다면 프로토타입의 하향 접지 프로브·발밑 지지면 확인 목적을 현 Minie/Bullet 엔진에 맞게 적용할지 검토 부탁드립니다.

추가로 발판 이탈 직후 점프를 허용하는 **코요테 타임**, 착지 직전 입력을 잠시 보관하는 **점프 버퍼**의 도입 여부와 허용 시간을 협의 부탁드립니다. 두 기법은 저장된 프로토타입에서 확인된 기존 기능이 아니라 개선 제안입니다. 한 입력 한 번 실행, 이중 점프 방지, 시설·수영·연결 전환 시 초기화 조건이 필요합니다. 점프 등록·소비·폐기 이유를 KST 시각·seq·물리 tick과 연결해 확인할 수 있으면 좋겠습니다.

## 4. 프로토타입과 달라진 수영 모션

**기존 문제**

프로토타입의 이동 중 수영 동작 일부가 이관 과정에서 빠져 팔꿈치·무릎 동작과 동작 주기가 다르게 표현됐습니다.

**FE에서 진행한 작업**

이동 중 수영에도 프로토타입의 이동 blend/phase를 적용해 팔꿈치·무릎 동작과 주기를 복원했습니다. 서버의 수영 속도·부력·충돌 계산은 변경하지 않았습니다.

**BE 요청**

배포 후 입수/출수, 정지/일반/달리기 수영, 징검다리·점프 전환에서 서버의 swimming/moving/running 상태와 수면 높이·부력·충돌을 함께 확인 부탁드립니다. 추가 수영 모션 구현 요청은 아닙니다.

- 새 공원 맵 선택/확인 계약은 BE에 이미 구현된 것으로 확인했습니다. 해당 기능을 중복 개발 요청하는 내용은 포함하지 않았습니다.
