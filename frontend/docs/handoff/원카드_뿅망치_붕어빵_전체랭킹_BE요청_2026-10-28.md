# 원카드 뿅망치 방어 · 붕어빵 전체 랭킹 BE 요청

## 범위와 현재 상태

2026-10-28 추가 요청입니다. FE 화면·조작과 아래 **제안 계약의 어댑터**를 구현했습니다. 서버 구현·DB 변경은 포함하지 않습니다. 실제 개발 서버에서 차단이나 전체 랭킹이 동작한다고 확인한 문서가 아닙니다.

- 원카드 덱 클릭·위로 드래그 내기는 기존 `GAME_ACTION_SEND`의 draw/play/accept-attack을 그대로 사용합니다. 새 API가 필요 없습니다.
- 원카드 버튼을 베이지·회색·검정으로 변경하고, 손패 정리 옆에 뿅망치 들기를 추가했습니다. 첨부 디자인의 뿅망치와 반투명 손은 이용자 자신의 화면에만 보이는 FE 연출입니다.
- **다른 관전자의 방해 차단과 두 단계 손 뻗기 판정은 BE가 필요합니다.** 서버 승인 전에는 차단됐다고 표시하지 않습니다.
- 붕어빵 결과에 전체 랭킹 요약·상세·페이지 탐색·오류/재조회 화면을 추가했습니다. 서버가 주지 않은 순위·인원·참여자를 만들지 않습니다.

기본 서비스에서는 `VITE_ONECARD_PRANK_DEFENSE`, `VITE_BUNGEOPPANG_RANKINGS`를 켜지 않습니다. 기존 `VITE_ONECARD_PRANKS`도 기존 배포 설정을 유지합니다. 아래 계약 합의·구현·배포·통합 검수 후 활성화해 주세요.

## 1. 원카드: 손 뻗기 → 뿅망치 → 뒤집기/차단

### 기본안

- 승인 관전자가 현재 차례의 플레이어에게만 손을 뻗습니다. 카드 뒷면을 누르는 FE 조작이며 상대의 카드 ID·내용은 전송하거나 공개하지 않습니다.
- 서버가 시도를 발급하고 당사자에게 알립니다. FE는 시도한 관전자의 반투명 손을 대상 플레이어에게 표시합니다.
- **방어 시간 기본안 1.4초, 차단 시간 기본안 3초**입니다. FE 허용 범위는 손 뻗기 잔여 0초 초과~1.5초, 차단 잔여 0초 초과~3초입니다. 이 값을 변경하려면 FE 계약도 함께 조정해 주세요.
- 방어가 승인되면 **그 관전자 → 그 플레이어** 조합만 해당 경기에서 3초 차단합니다. 다른 관전자를 일괄 차단하거나 게임 진행·카드 효과를 정지시키지 않습니다.
- 방어하지 않은 시도는 서버가 마감 시각에 확정하고 기존 손패 뒤집기 이벤트를 발행합니다. 선택/제출 카드 보호, 최대 2장, 전체 손패 정리 및 복구 면역은 기존 계약을 유지합니다.
- 기존 한 차례 한 번 제한은 관전자·대상·turnCount로 관리합니다. 3초가 지나도 같은 차례에서 소모한 시도를 재사용하지 않습니다.

### 제안 Raw WebSocket 계약

모든 사용자 식별자는 문자열입니다. `eventId`는 클라이언트 생성 UUID로 멱등 키, `attemptId`는 서버 발급 UUID입니다. 시간은 신뢰 가능한 서버의 epoch milliseconds입니다.

관전자 요청:

```json
{"type":"ONECARD_PRANK_REACH_SEND","requestId":"...","payload":{"gameId":"...","eventId":"<uuid>","targetUserId":"101","turnCount":2}}
```

승인 ACK 및 같은 경기의 필요한 당사자에게 방송:

```json
{"type":"ONECARD_PRANK_REACH_STARTED","requestId":"... 또는 null","payload":{"gameId":"...","eventId":"<요청 eventId>","attemptId":"<서버 uuid>","actorUserId":"505","targetUserId":"101","turnCount":2,"serverNow":10000,"resolveAt":11400}}
```

대상 플레이어가 손을 때리는 요청:

```json
{"type":"ONECARD_PRANK_HIT_SEND","requestId":"...","payload":{"gameId":"...","eventId":"<uuid>","attemptId":"<서버 uuid>"}}
```

차단 승인 ACK 및 당사자 방송:

```json
{"type":"ONECARD_PRANK_BLOCKED","requestId":"... 또는 null","payload":{"gameId":"...","eventId":"<방어 요청 eventId>","attemptId":"<서버 uuid>","actorUserId":"505","targetUserId":"101","turnCount":2,"serverNow":10800,"blockedUntil":13800}}
```

방어하지 않았거나 취소된 시도 종료:

```json
{"type":"ONECARD_PRANK_REACH_RESOLVED","requestId":null,"payload":{"gameId":"...","eventId":"<서버 uuid>","attemptId":"<서버 uuid>","actorUserId":"505","targetUserId":"101","turnCount":2,"serverNow":11400,"outcome":"FLIPPED"}}
```

outcome은 `FLIPPED | BLOCKED | CANCELLED`입니다. FLIPPED인 경우 서버가 별도로 기존 `ONECARD_HAND_FLIPPED`를 발행합니다. FE는 REACH_RESOLVED만으로 카드를 뒤집지 않습니다. 기존 `ONECARD_HAND_RESTORE_SEND`/`ONECARD_HAND_RESTORED`는 유지합니다.

### 서버 권한·동시성·재접속

1. actor는 요청 본문이 아니라 인증 세션에서 결정합니다. 같은 경기의 승인 관전자·현재 대상·정상 차례·빈 관전 좌석이 아닌 실제 관전 권한을 검사합니다. 플레이어는 타인의 attempt를 때릴 수 없습니다.
2. 시도 발급·한 차례 사용 소모·차단 조회를 서버에서 원자적으로 처리합니다. 마감 타이머가 진행되고 관전자 창이 닫혀도 서버가 최종 판정합니다.
3. hit와 마감 판정은 같은 attempt에 대해 직렬화/CAS합니다. `PENDING → BLOCKED`와 `PENDING → FLIPPED`가 동시에 성공하면 안 됩니다. 차단된 시도에서 뒤집기 방송을 발행하지 않습니다.
4. UUID 재전송은 같은 영수증을 반환하고 시간을 연장하지 않습니다. 재접속해도 이미 끝난 손 연출을 재생하지 않으며, 아직 유효한 차단은 서버에서 계속 검사합니다. 초기 복구 스냅샷 계약이 필요하면 별도로 합의해 주세요.
5. 차례 변경·기권·종료·관전 해제·채널 변경 시 미완료 attempt를 취소합니다. 잔여 차단은 최대 3초, 해당 경기 범위로 제한합니다.
6. 최대 동시 시도·요청 속도 제한을 서버에서 검사합니다. FE는 대상 화면에서 최대 4개 손 연출만 표시합니다. 화면 좌표나 커서 이동을 월드 전체에 방송할 필요가 없습니다.
7. 새 방식이 켜진 서버에서는 기존 즉시 `ONECARD_HAND_FLIP_SEND`로 방어 시간을 우회할 수 없도록 처리합니다. 기능 협상·기존 클라이언트 호환 정책을 확정해 주세요.

제안 오류: `ONECARD_DEFENSE_NOT_CONFIGURED`, `ONECARD_PRANK_ACCESS_DENIED`, `ONECARD_PRANK_TOO_LATE`, `ONECARD_PRANK_BLOCKED`, `ONECARD_PRANK_ALREADY_USED`. 기존 ERROR envelope 사용. 네트워크 오류나 기한 초과에서 FE는 자동 재전송·임의 차단을 하지 않습니다.

## 2. 붕어빵: 전체 기간 · 개인별 최고 기록

시안의 ‘이번 주’ 대신 사용자 요청대로 **전체 랭킹**입니다. 같은 이용자는 최고 기록 1개만 나옵니다. v4 1분과 v5 3분 기록은 비교하지 않고 `rulesVersion`별 전체 기간 집계로 분리합니다. 개인 최고 기준과 아래 순위 표기 방식은 FE 기본안이므로 최종 확인 부탁드립니다.

정렬/최고 기록 선택:

1. 서버 확정 완성 개수 `made` 내림차순
2. 서버 확정 실수 횟수 `failed` 오름차순
3. 두 값이 같으면 **같은 순위**, 서버 `completedAt`이 빠른 기록 우선
4. 완료 시각까지 같으면 문자열 BIGINT userId의 숫자 순서로 안정 정렬

순위는 경쟁 순위 `1, 1, 3` 방식입니다. 동점이 나중에 완료됐다는 이유로 2위로 바뀌지 않습니다. 같은 사용자의 동일한 기록 재도전은 더 이른 최고 기록 완료 시각을 보존해 주세요.

### 제안 조회 API

```http
GET /api/v1/minigames/bungeoppang/rankings?period=ALL_TIME&rulesVersion=v5&limit=20
GET /api/v1/minigames/bungeoppang/rankings?period=ALL_TIME&rulesVersion=v5&limit=20&cursor=<opaque-cursor>
Cache-Control: no-store
```

```json
{
  "rulesVersion":"v5",
  "period":"ALL_TIME",
  "basis":"PERSONAL_BEST",
  "snapshotId":"ranking-snapshot-id",
  "updatedAt":"2026-10-28T10:00:00Z",
  "totalParticipants":152,
  "items":[
    {"rank":1,"userId":"102","nickname":"달인","made":12,"failed":1,"completedAt":"2026-10-28T08:00:00Z"},
    {"rank":1,"userId":"103","nickname":"장인","made":12,"failed":1,"completedAt":"2026-10-28T09:00:00Z"}
  ],
  "me":{"rank":12,"userId":"101","nickname":"나","made":8,"failed":2,"completedAt":"2026-10-28T09:30:00Z"},
  "nextCursor":"opaque-next-cursor"
}
```

- 마지막 페이지는 `nextCursor:null`. 내 최고 기록이 없으면 `me:null`. 아무 기록도 없으면 totalParticipants 0, items [], me null, nextCursor null입니다.
- me는 인증된 요청자만 반환하며 클라이언트가 타인의 userId를 지정하지 않습니다. 공개 정보는 닉네임·완성·실수·순위·완료 시각만 있으면 됩니다. 개인정보·개인 보상 내역은 넣지 않습니다.
- 동일 snapshotId에서 중복 이용자·순위 역전이 없어야 합니다. 커서는 스냅샷과 안정 정렬 경계를 포함하고 만료되면 `409 RANKING_SNAPSHOT_EXPIRED` 등 명확한 오류를 반환합니다. FE는 처음부터 다시 조회할 수 있습니다.
- 점수·완성·실수·완료 시각을 FE가 POST해서 랭킹에 등록하지 않습니다. **실제 완료 검증·정산 커밋 후** DB의 확정 통계에서 등록/개인 최고 갱신합니다.
- 포기·만료·검증 실패·로컬 미리보기는 제외합니다. 일일 엽전 한도로 지급이 0인 정상 완료 기록을 랭킹에 포함하는 것을 기본안으로 합니다.
- complete 재시도/복구로 중복 등록·참여자 증가·completedAt 변경이 생기면 안 됩니다. complete/COMPLETED 응답 직후 GET이 확정 기록을 읽도록 커밋 순서를 보장해 주세요.

## 통합 검수와 전달 요청

BE에서 구현 브랜치/MR, 최종 이벤트·API 예시, 기능 플래그 적용 방식, 배포 시점을 공유해 주세요. FE에서 실제 개발 서버의 두 계정으로 손 뻗기·차단·실패·재접속·기존 패 복구를 확인하고, 확정 게임 완료 → 결과 랭킹 → 상세 → 다음 페이지 → 동점 순서까지 대조하겠습니다. 현재 로컬 테스트는 명시적 계약 fixture이며 실제 서버 완료 검증을 대신하지 않습니다.

### 전달할 글

원카드·붕어빵 추가 FE 작업과 BE 요청 문서를 공유드립니다. 원카드의 덱 클릭·드래그 내기는 기존 API를 사용합니다. 새로 필요한 부분은 관전자가 손을 뻗으면 대상 플레이어에게 알리고, 뿅망치 방어 성공 시 그 관전자의 해당 대상 방해를 3초 차단하는 서버 판정입니다. 화면에만 차단 표시를 하는 방식으로는 다른 사용자의 동작을 막을 수 없어 두 단계 이벤트와 최종 판정을 요청드립니다.

붕어빵은 결과 화면에 전체 랭킹 요약과 상세 화면을 추가했습니다. 전체 기간·개인 최고 기록을 완성 개수 많은 순, 실수 적은 순으로 집계하고 두 값이 같으면 같은 순위에서 먼저 완료한 기록부터 표시하려고 합니다. v4/v5 기록은 구분하고, 정상 완료 검증·정산 후 서버 통계로 반영되는 조회 API를 부탁드립니다. 문서의 JSON은 제안이므로 확정 응답과 배포 일정을 주시면 실제 연동을 검수하겠습니다.
