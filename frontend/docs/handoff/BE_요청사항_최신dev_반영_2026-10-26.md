## BE에 요청할 사항

### 1. 사용자마다 같은 낮밤을 표시할 서버 시간 계약

- 서버 현재 시각, 공통 epoch, 낮밤 주기와 초기/재접속/탭 복귀 재동기화 방식을 확정해주세요. 실제 필드명과 메시지는 협의 후 FE에 연결합니다.
- 기준은 **Asia/Seoul**, epoch **2026-01-01T00:00:00+09:00 = 1767193200000 Unix ms**, 기존 낮밤 한 주기는 **30분**입니다.
- 전송·계산은 Unix ms이며 9시간을 중복 가산하지 않습니다. 기기 시계가 틀린 사용자도 같은 위상을 표시하는 것이 서버 동기화의 목표입니다.
- 서버 재시작·채널/인스턴스 간 동일 설정을 유지하고, 시계 보정 허용 오차는 공동 검수 전에 합의해주세요.

### 2. 이동 중지 원인과 좌표 생성 시점 확인

- 소스 기본값인 입력 최소 50ms·입력 만료 250ms·물리 30Hz·변화 시 약 100ms 방송이 실제 개발 배포에도 적용됐는지 공유해주세요. 기본값을 무조건 늘리는 요청은 아닙니다.
- **2026-10-26 15:44:43~15:44:48 KST**, 당시 검수 계정 `test`의 입력 seq/수락·만료 시각, 정지 사유, 물리 step·방송 지연 로그가 남아 있다면 확인해주세요. 로그가 없다면 최신 FE 반영본으로 같은 상황을 재현해 수집해주세요.
- 기존 실측 6회/273개 입력 중 첫 이동에서 프레임 공백 최대 358.2ms, FE Long Task 340ms, 입력 공백 432.4ms와 이동키 유지 중 `moving=false`가 관측됐습니다. 최대 RTT 299.2ms를 BE 단독 지연으로 해석하지 않습니다. 당시 `MOVE_TOO_FREQUENT`는 0건이었습니다.
- WORLD_STATE의 좌표 생성 시각 또는 물리 tick 제공 가능 여부와 의미를 협의해주세요. `lastInputSeq`는 수락 순번이므로 물리 계산 완료 번호로 간주하지 않습니다.

### 3. 점프 접지 판정과 입력 유예 정책 검토

- 평지 정지/걷기/달리기, 경사·이음새·난간, 착지 직전/직후에서 수신/실행 시의 `onGround()` 때문에 입력이 폐기되는지 확인해주세요. 실제 점프 누락의 BE 원인으로 아직 확정한 것은 아닙니다.
- 접지가 불안정하다면 프로토타입의 하향 접지 프로브·실제 발밑 지지면 확인 목적을 Minie/Bullet에 맞춰 검토해주세요. Rapier 수치를 그대로 이식하는 요청은 아닙니다.
- 코요테 타임과 착지 전 점프 버퍼는 **추가 개선 제안**입니다. 채택 여부·허용 시간·소비/취소 조건을 협의해주세요. 한 입력 한 번 실행과 이중 점프 방지, 시설·수영·재접속·채널 전환 초기화 조건이 필요합니다.
- KST 시각·seq·물리 tick, 접지 상태, 점프 큐 등록·소비·폐기 이유를 연결할 수 있게 확인해주세요.

### 4. 수영 상태 공동 확인

FE 모션 복원은 완료됐습니다. BE에 새 모션 구현을 요청하는 것은 아닙니다. 실제 서버에서 입출수·정지/일반/달리기 수영·징검다리·점프 전환 시 승인 swimming/moving/running, 수면 높이·부력·충돌을 함께 확인해주세요.

회신 요청: 확인한 원인/재현 결과, 시간·스냅샷 계약, 점프 정책 결정사항, 실제 맵 모드·배포 설정, 반영 커밋 및 배포 시각(KST).
