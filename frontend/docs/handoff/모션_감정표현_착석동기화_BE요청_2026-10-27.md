# 감정표현·테이블 착석 동기화: BE 작업 요청

작성일: 2026-10-27 (KST)
FE 보존 브랜치: `wip/frontend-emote-seat-be-pending`
상태: **BE 계약 확정·구현·공동 검수 대기. dev 머지·배포 보류.**

이번 요청은 아래 세 가지입니다. FE 시안과 관련 테스트는 별도 브랜치에 준비했으며, BE 코드는 변경하지 않았습니다. BE 구현 후 최신 dev를 반영하고 실제 두 계정으로 함께 확인한 뒤 통합할 예정입니다.

| 항목 | 사용자에게 필요한 동작 | BE 요청 |
| --- | --- | --- |
| 이동 중 방귀 유지 | 이미 시작한 방귀는 이동해도 끝까지 재생 | FART의 이동 취소 예외 |
| 취소 후 즉시 다른 감정표현 사용 | 손 인사 취소 → 멈춤 → 바로 박수 사용 | 유효한 취소 후 이전 표현의 재사용 제한 해제 |
| 주변 사용자에게 착석 표시 | 테이블에 참여하지 않은 사람도 앉은 모습을 봄 | 채널 전체에 사용자별 테이블·좌석 상태 제공 |

## 1. 이미 시작한 방귀는 이동해도 유지해주세요

**현재 원인**

기준 소스의 `TableHub`는 이동 요청 처리와 물리 갱신에서 `cancelEmote(userId, "MOVEMENT")`를 호출합니다. `WorldEmoteService.cancel()`은 표현 종류와 무관하게 마지막 이벤트를 제거하고 취소 이벤트를 만듭니다. 따라서 FE에서 이동 취소를 해제해도 서버의 `WORLD_EMOTE_CANCELLED`를 받으면 다시 끊깁니다.

**요청 작업**

- 현재 승인된 표현이 `FART`이고 사유가 `MOVEMENT`이면 이벤트를 유지하고 취소 이벤트를 방송하지 말아주세요.
- 이동 요청 경로와 물리 갱신 경로 양쪽에 적용해주세요. 공통 취소 정책에서 처리하면 경로별 차이를 줄일 수 있습니다.
- 다른 감정표현의 이동 취소와 시설 이용 시작·채널 이탈·접속 종료에 따른 취소는 기존대로 유지합니다.
- 이미 시작한 동작을 끝까지 재생하는 요청입니다. 이동 중 새 표현 시작이나 무한 재생 기능 추가는 포함하지 않습니다.

**FE 준비 / 완료 기준**

FE는 이동 입력과 좌표 수신 중 방귀를 지우지 않고 기존 `sentAt`을 유지합니다. 같은 채널의 A/B 화면에서 A가 방귀를 시작한 뒤 걷기·달리기·점프해도 재시작하거나 끊기지 않고 정상 종료되어야 합니다.

## 2. 유효하게 취소한 표현의 대기시간을 해제해주세요

**현재 원인**

`WorldEmoteService.create()`는 `lastSent`에 `max(minimumInterval, 표현별 cooldown)`을 기록하지만 `cancel()`에서는 이 제한을 유지합니다. 기준 소스상 최소 간격은 기본 1초, WAVE·CLAP의 쿨다운은 5초입니다. 실제 적용값은 서버 설정 확인이 필요합니다. FE에서 바로 선택할 수 있게 해도 서버가 `EMOTE_TOO_FREQUENT`로 거절할 수 있습니다.

**요청 작업**

- 재생 중인 표현이 유효하게 취소되면, 이전 표현의 5초/1.8초 대기가 다음 표현을 막지 않도록 해주세요.
- 기존 최소 전송 간격도 즉시 사용을 막을 수 있습니다. **유효한 취소 직후 다음 표현은 승인**되도록 하고, 과다 요청 제한은 별도 정책으로 정리해주세요. 적용할 정책과 값을 회신 부탁드립니다.
- 현재 이벤트 ID와 재생 유효 기간을 확인해주세요. 만료된 표현에 대한 이동이나 오래된 취소가 새 표현의 제한을 해제해서는 안 됩니다.
- 정상 재생 완료 후의 쿨다운과 시설 이용 등 표현을 시작할 수 없는 상태 제한은 유지합니다.
- 기존 `WORLD_EMOTE_CANCELLED`의 `emoteEventId`, `reason`, `sentAt` 계약은 유지해주세요.

**FE 준비 / 완료 기준**

FE는 실제 취소 시 쿨다운과 요청 잠금을 해제하고, 이전 요청의 늦은 승인·거절·종료가 새 표현을 덮어쓰지 않도록 처리했습니다. 정상 종료한 표현의 쿨다운은 유지합니다.

A가 손 인사를 하다가 이동해 취소한 뒤 멈추고 즉시 박수를 선택하면, 서버가 새 요청을 승인하고 A/B 화면 모두 박수를 표시해야 합니다. 기존 쿨다운이나 이전 응답 때문에 새 동작이 막히면 안 됩니다.

이번 FE에는 별도 수동 취소 요청 API를 추가하지 않았습니다. 이동 등 기존 취소 경로 기준의 요청이며, 취소 버튼까지 필요하면 요청 계약을 별도로 합의해야 합니다.

## 3. 일반 주변 사용자에게도 테이블 착석 상태를 보내주세요

**재현 / 현재 원인**

A만 테이블에 앉으면 자기 화면에서는 앉아 있지만 주변 B에게는 서 있는 것으로 보입니다. B도 같은 테이블에 앉으면 둘 다 앉은 모습으로 보입니다.

기준 소스의 `TableHub.publish()`는 참가자에게 `TABLE_STATE`, 관전자에게 `TABLE_WATCH_STATE`를 보냅니다. 일반 주변 사용자는 대상이 아니며, 현재 월드 아바타 데이터에도 사용자별 테이블·좌석 정보가 없습니다. 인원수만으로는 누가 어느 자리에 앉았는지 판단할 수 없습니다.

**제안 계약 — BE 확정 필요**

기존 `WORLD_STATE.payload.avatars[]`의 각 아바타에 `tableSeat`를 추가하는 안으로 FE 수신 처리를 준비했습니다. **아직 BE에 구현된 확정 계약이 아닙니다.** 다른 형식을 선택하면 합의한 명세에 맞춰 FE를 조정하겠습니다.

앉아 있는 아바타의 추가 필드:

```json
{
  "tableSeat": {
    "tableId": "실제-서버-tableId",
    "seatNumber": 1
  }
}
```

서 있는 아바타의 추가 필드:

```json
{
  "tableSeat": null
}
```

기존 `userId`, 좌표, 프로필, 장비 등 아바타 필드는 그대로 유지합니다.

| 필드 | 의미 |
| --- | --- |
| `tableId` | 해당 채널의 실제 서버 테이블 ID. FE 기존 매핑과 연결 |
| `seatNumber` | 기존 TABLE_STATE와 같은 1-based 정수, 1~4 범위의 실제 배정 좌석 |
| `tableSeat: null` | 테이블에 앉아 있지 않음. 이전 착석 표시 해제 |
| 필드 생략 | 이전 BE 호환용이며 주변 사용자 착석 문제는 해결되지 않음 |

**요청 작업**

1. 서버의 실제 `seating`과 `TableRoom` 좌석에서 공개 착석 상태를 구성해주세요.
2. 참가·관전 여부와 무관하게 같은 채널의 일반 사용자도 받는 월드 스냅샷에 포함해주세요. 새 계약 적용 후에는 비착석 사용자에게도 반드시 `tableSeat:null`을 보내주세요.
3. 착석·일어나기·강제 퇴장·접속 종료 등 좌석 변경 시 월드 버전과 방송을 갱신해주세요. 좌표가 그대로여도 좌석 상태만 바뀌면 전송되어야 합니다.
4. 최초 입장·재접속 초기 스냅샷에도 이미 앉은 사용자의 좌석 정보를 넣어주세요.
5. 같은 좌석 중복이나 시설/테이블 동시 사용처럼 모순된 상태가 없도록 일관된 시점의 값을 구성해주세요.
6. 공개 정보는 테이블·좌석 표시용으로 한정해주세요. 참가 권한·준비·배팅·비공개 게임 정보는 기존 계약을 유지합니다.

**FE 준비 / 완료 기준**

FE는 제안 필드를 검증하고 기존 테이블 매핑으로 위치·방향·앉은 모션을 적용합니다. 모르는 테이블 ID를 거리나 목록 순서로 추측하지 않습니다. 공개 정보는 다른 사람의 표시용이며, 내 참가 권한과 버튼 상태는 기존 `TABLE_STATE`로 결정합니다.

- B가 참가·관전하지 않아도 A가 실제 좌석에서 앉은 모습으로 보여야 합니다.
- A가 앉은 뒤 입장한 C와 재접속한 B도 초기 화면부터 같은 모습을 봐야 합니다.
- A가 일어나거나 퇴장/접속 종료하면 앉은 잔상이 남지 않아야 합니다.
- 다른 채널·오래된 월드 버전·이전 감정표현의 취소 이벤트가 현재 표시를 덮어쓰지 않아야 합니다.

## 그대로 전달할 글

> 감정표현과 테이블 착석 동기화 관련 BE 작업 세 가지를 부탁드립니다. FE 시안과 수신 처리는 `wip/frontend-emote-seat-be-pending`에 준비했으며, BE 연동 전까지 dev 머지·배포를 보류하고 있습니다.
>
> 1. 이미 시작한 FART는 걷기·달리기·점프 때문에 취소되지 않도록 이동 요청/물리 갱신의 MOVEMENT 취소에서 제외해주세요.
> 2. 재생 중인 감정표현을 취소한 뒤 멈추고 다른 표현을 바로 선택하면 승인되도록 이전 쿨다운과 최소 전송 간격 정책을 조정해주세요. 정상 완료 후 쿨다운과 과다 요청 제한은 유지해야 합니다.
> 3. 테이블에 참여하지 않은 주변 사용자에게도 사용자별 테이블·좌석 상태를 보내주세요. FE는 WORLD_STATE.avatars[].tableSeat에 {tableId, seatNumber} 또는 null을 추가하는 안으로 준비했습니다. 신규 제안이므로 필드와 방송 방식을 먼저 확정 부탁드립니다. 최초 입장·재접속·착석·퇴장에도 빠짐없이 반영되어야 합니다.
>
> 각 항목의 적용 방식과 검수 가능한 시점을 공유해주시면, 실제 두 계정으로 함께 확인한 뒤 FE를 통합하겠습니다.
