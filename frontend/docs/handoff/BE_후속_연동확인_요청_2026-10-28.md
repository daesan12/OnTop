# 게임 QA 통합 후 BE 연동 확인 요청

작성일: 2026-10-28 KST. 최신 dev 통합 기준: `6bc51ddc3862bf3d39af6e5b104876712c34f904`(붕어빵 v5 FE 포함). 오목 BE 확인 기준: `0093398`에 포함된 `12a0a25`.

## 현재 반영 범위

FE는 결과 화면 잔류/재접속 시 재표시 방지, 오목 Enter 채팅·분산 표시·반투명 핑 이름, 게임 중 지도/옷장 차단, 바둑판 조명 번짐 제거, 정산 후 자동 잔액 갱신, 원카드 확대/트럼프 아트/설명 분리, 붕어빵 결과 팝업을 반영했다.

최신 dev의 BE 커밋 `12a0a25`에는 플레이어 채팅과 퇴장 후 종료 복구 경계 보완이 이미 들어 있다. 확정 명세 `docs/websocket-api/10-game-spectator-events.md`를 확인하고 FE 플레이어 채팅도 활성화했다. 현재 착석한 본인 경기의 인증된 플레이어만 채팅하며, 관전 핑은 계속 관전자만 전송한다. **같은 기능을 새로 구현해 달라는 요청이 아니라 배포 반영과 실제 계정 간 통합 QA 요청이다.**

이번 FE 작업에서 BE 코드·DB·배포 설정을 새로 수정하지 않았다. 작업 브랜치에 포함된 BE 변경은 최신 dev 병합으로 가져온 기존 변경이다.

## BE 담당자에게 요청할 사항

### 1. 개발 서버 반영 및 오목 경기 채팅 공동 검수

- MR 머지 후 dev를 pull하고, BE의 플레이어 채팅·종료 복구 보완이 실제 개발 서버에 반영되는지 확인해 주세요. Git 머지만으로 배포 완료를 판단하지 않습니다.
- 흑·백 두 플레이어와 승인된 관전자로 같은 경기에 접속해 양방향 채팅을 확인해 주세요. 플레이어는 내 차례/상대 차례 모두 전송하고, 관전자도 Enter로 입력·전송할 수 있어야 합니다.
- 메시지는 기존 `GAME_SPECTATOR_CHAT_SEND` → `GAME_SPECTATOR_CHAT_MESSAGE` 계약을 사용합니다. 광장 채팅(`WORLD_CHAT_*`) 및 다른 게임/다른 경기와 섞이면 안 됩니다. 오목 경기 안에서만 동작합니다.
- 플레이어의 `OMOK_SPECTATOR_PING_SEND`는 계속 거절해야 합니다. 복구 전·퇴장 후·다른 경기·이전 연결의 전송도 거절해야 합니다.
- 원래 requestId의 발신자 ACK, 나머지 수신자의 requestId=null, UUID 중복 방지·1초 간격·채팅 TTL 3초·비필수 이벤트 폐기 정책은 기존 계약을 유지합니다. ACK는 모든 수신자 화면 도착 보장이 아니라 서버 승인 및 전달 시도 완료입니다.

### 2. 종료·정산·퇴장·재접속 경계 확인

- 경기 종료 → 정산 완료 → 테이블에서 일어나기 → 새로고침/재로그인을 재현해 과거 결과나 종료 경기 복구가 활성 화면을 다시 열지 않는지 확인해 주세요.
- 기존 보완의 좌석/복구 슬롯/자동 결과 전달 범위가 배포 서버에서도 일치하는지 확인해 주세요. 기록 삭제 요청은 아닙니다.
- 진행 중 경기의 재접속 복구, 정산 대기 중 결과 확인, 본인 기권 영수증과 명시적 결과 이력 조회는 유지되어야 합니다.
- 문제가 재현되면 연결별 `TABLE_LEFT`, `TABLE_STATE`, `GAME_START_STATE`, `GAME_CONNECTION_STATE`, `GAME_RESULT`의 경기/사용자/테이블 ID와 전달 순서를 공유해 주세요. 토큰 등 인증 정보는 제외합니다.

### 3. 게임 완료 직후 지갑 조회의 일관성 확인

- 오목·주사위·원카드·거짓말 다리: 지갑 정산 트랜잭션 커밋 후 본인 `GAME_RESULT(settlementStatus: SETTLED)`가 도착해야 합니다. FE는 이때 `GET /api/v1/wallets/me`를 자동 조회해 `balance`를 표시합니다.
- `PENDING`만 도착하고 확정 이벤트가 누락되는 경로가 있는지, 테이블에서 먼저 나온 사용자도 본인 정산 확정을 받을 수 있는지 확인해 주세요. 정상 종료·기권·무효 환급을 포함합니다.
- 붕어빵: `/complete` 성공 또는 `COMPLETED` 복구 응답 직후 지갑 GET에 보상이 반영되어야 합니다. 동일 키 재시도로 보상이 중복 지급되면 안 됩니다.
- 브라우저·프록시 캐시로 이전 잔액이 반환되지 않는지 확인해 주세요. FE는 `cache: no-store`로 조회하고, 예상 보상이나 결과 delta를 로컬 잔액에 임의로 더하지 않습니다.
- 새 API나 지갑 이벤트 타입은 요청하지 않습니다. 기존 확정 응답·이벤트와 지갑 GET의 순서/일관성 확인이며, 문제가 확인되면 해당 경로만 보완해 주세요.

## FE 검증과 한계

최신 dev를 통합한 상태에서 타입 검사·단위 테스트·빌드와 관련 Edge/Playwright 계약 브라우저 QA를 진행한다. 실제 개발 서버의 인증 계정 간 전달, DB 커밋 시점, 프록시 캐시, 배포 반영 여부는 계약 fixture로 확정할 수 없으므로 위 통합 확인이 필요하다. Git 머지와 서비스 배포는 별개다.

### 함께 반영된 붕어빵 v5 FE 작업과의 구분

통합 중 dev에 이미 머지된 붕어빵 v5 FE 작업도 보존했다. 이번 결과 화면은 v4와 v5 공통으로 사용하며, v5 미리보기의 **실제 엽전 지급 없음** 표시와 보상 계산을 유지했다. 기본 실행은 기존 v4이며, BE 최종 계약 수락·배포 전에는 `VITE_BUNGEOPPANG_RULES_VERSION=v5`로 전환하지 않는다.

v5의 180초·주문/재고·소 투입(FILL) 가열·복구 등의 별도 BE 연동 요청은 이미 전달된 [붕어빵 v5 BE 전달 요약](../../../docs/bungeoppang-v5/BE_전달_요약_2026-10-28.md)을 따른다. 이번 QA에서 새로 요청하거나 완료로 간주하는 항목이 아니며, 기존 담당자의 최종 계약·배포 확인과 함께 대조한다.

## 전달용 요청 글

FE 게임 QA 변경을 dev에 통합했습니다. dev를 pull해서 진행 부탁드립니다. 최신 dev에 플레이어 채팅 허용과 퇴장 후 종료 복구 보완이 이미 반영된 것을 확인했고, FE도 확정 명세에 맞춰 오목 플레이어 채팅을 활성화했습니다. 핑은 관전자 전용으로 유지했습니다.

추가로 같은 기능의 신규 구현을 요청드리는 것은 아니며, 개발 서버 배포 반영과 실제 계정 기준으로 ① 오목 플레이어↔관전자 채팅, ② 정산·퇴장·재접속 후 과거 결과 미표시, ③ 게임 종료 직후 새로고침 없는 잔액 갱신을 함께 확인 부탁드립니다. 특히 `SETTLED` 이벤트 및 붕어빵 완료 응답 직후 지갑 GET이 변경된 금액을 반환하는지 확인해 주세요. 상세 계약과 재현 순서는 이 문서에 정리했습니다.
