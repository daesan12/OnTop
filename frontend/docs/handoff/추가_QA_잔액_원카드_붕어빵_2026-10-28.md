# 추가 게임 QA — 잔액 자동 갱신 및 결과 화면

## FE 반영

- 오목·주사위·원카드·거짓말 다리의 본인 `GAME_RESULT`가 `SETTLED`이면 `GET /api/v1/wallets/me`를 자동 재조회한다. 게임 결과창을 열거나 새로고침할 필요가 없다.
- 이미 테이블을 떠난 뒤 도착한 본인 정산도 잔액에 반영한다. 종료한 경기 화면은 다시 열지 않는다.
- 붕어빵 완료 응답 및 완료 상태 복구가 확정되면 공원 지갑도 재조회한다. 결과창에서 공원으로 돌아가더라도 지갑 조회는 별도로 유지한다.
- 지갑 요청은 캐시를 사용하지 않는다. 예상 보상이나 `myCoinDelta`를 현재 잔액에 임의로 더하지 않고, 서버가 반환한 `balance`를 표시한다.
- 대기 중인 결과·다른 사용자의 결과·잘못된 응답은 지갑 갱신을 발생시키지 않는다. 동일 정산의 재수신은 중복 조회를 막는다. 조회 실패 시 마지막 확인 잔액과 재조회 기능을 유지한다.
- 원카드 손패를 확대하고 실제 트럼프 형태의 숫자·무늬·인물 카드로 변경했다. 효과 설명은 카드 아래 안내 영역으로 분리했다. 공개 바닥 카드와 상대 손패 뒷면도 같은 카드 아트를 사용한다. 상대의 비공개 앞면은 만들지 않는다.
- 붕어빵 결과를 첨부 시안에 맞춘 아이보리 팝업으로 변경했다. 붕어빵 그림, 완성/실수, 보상 대기/확정/오류, 다시 도전·공원으로·설명서를 배치한다. 시안의 예시 수치나 상태 예시 영역은 제품에 고정하지 않았다.

## BE 전달 — 기존 계약 확인 및 통합 QA

이번 변경에 새로운 API나 필수 BE 구현은 없다. 아래 기존 계약이 배포 서버에서도 유지되는지 확인을 요청한다.

1. 보드게임 정산의 지갑 트랜잭션이 커밋된 뒤 본인에게 `GAME_RESULT(settlementStatus: SETTLED)`가 전달되어야 한다. 그 직후 지갑 GET이 변경된 `balance`를 반환해야 한다. `PENDING`만 전달되고 확정 이벤트가 오지 않는 경로가 있다면 수정하거나 FE에 알려 주세요.
2. 정상 종료, 기권, 무효 경기의 환불, 연결 복구 및 테이블 퇴장과 정산이 겹치는 경우에도 해당 계정의 확정 결과 조회/전달이 가능한지 확인해 주세요. FE는 본인이 참가자로 포함된 정산만 사용합니다.
3. 붕어빵 `/complete` 성공 응답 및 `COMPLETED` 복구 응답 직후 지갑 GET이 지급된 보상을 포함해야 합니다. 동일 키 재시도에서 보상을 중복 지급하면 안 됩니다.
4. 지갑 GET이 브라우저·프록시 캐시에 이전 잔액을 남기지 않는지 확인해 주세요. FE 요청은 `cache: no-store`를 사용합니다.

현재 소스의 붕어빵 `MinigameService.complete()`는 `TransactionTemplate.execute()`가 끝난 뒤 결과를 반환하는 구조다. BE 코드는 수정하지 않았다. 실제 배포 환경의 이벤트 발행 순서·DB 커밋·캐시 동작은 FE 계약 fixture만으로 확정할 수 없어 통합 검증이 필요하다.

## 통합 확인 방법

1. 각 게임 시작 전 잔액을 확인한다.
2. 게임 종료 후 새로고침·재접속·수동 재조회 없이 잔액이 지갑 API 값으로 바뀌는지 확인한다.
3. 테이블에서 먼저 퇴장한 뒤 정산되더라도 잔액은 갱신되고 이전 게임 결과는 다시 뜨지 않아야 한다.
4. 붕어빵 결과 대기 → 확정, 통신 오류 → 같은 결과 재확인, 일일 한도 도달, 공원 복귀에서 동일하게 확인한다.

기존 오목 플레이어 채팅 BE 요청은 `게임_QA_FE수정_BE요청_2026-10-28.md`를 따른다.
