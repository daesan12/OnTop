# 서버 시간·충돌 맵 FE 연동 결과와 남은 BE 요청

작성: 2026-10-27 KST. 기준 dev: `36c0ba73e3e072a295e4f06b0186fcc64328bbd5`.
작업 브랜치: `fix/frontend-motion-clock`. 최신 dev를 `fc335fa`에서 충돌 없이 병합했다.
이번에 직접 수정한 범위는 `frontend/`뿐이며, BE·DB·인프라 구현과 배포 설정은 변경하지 않았다.

이 문서를 최신 전달본으로 사용한다. 10월 26일 요청 중 서버 시간 API 구현·진단 로그 추가·충돌 보정은 BE에 반영됐으므로 같은 구현을 다시 요청하지 않는다. 아래는 FE 연결 결과와 실제 남은 요청이다.

## FE에서 완료한 작업

### 1. 서버 시간 API 연결

기존에는 FE의 공통 KST 기준을 사용해도 기기 시계 오차가 남았다. 이제 인증된 기존 SharedSocket으로 아래 계약을 연결했다.

- `CONNECTED.payload.time`: 최초 서버 시간 적용.
- `WORLD_TIME_CHECK {}` → `WORLD_TIME_STATE`: 요청 전후 `performance.now()`로 RTT를 재고 서버 시각 + RTT/2를 수신 시점 추정값으로 적용.
- 접속·재접속·탭 복귀 시 조회하고, 보이는 탭에서는 30초마다 재보정. 기존 WebSocket heartbeat는 변경하지 않는다.
- `serverNow/cycleEpochMs/cycleDurationMs/timeZone`을 검증해 환경 시계·주기에 반영. 한국 시간 `Asia/Seoul`, 한국 자정 epoch와 30분 주기 계약을 사용하며 Unix ms에 9시간을 중복 가산하지 않는다.
- 연결 종료·로그인 종료·재연결 때 시간 요청/이벤트 리스너/타이머를 정리. 이전 연결이나 숨김 탭을 가로질러 도착한 응답은 적용하지 않는다. 잘못된 응답과 지연 outlier도 정상 시계를 덮어쓰지 않는다.
- 조회 실패 시 마지막 유효 시간 또는 기존 KST fallback을 유지한다. 시간 요청 실패가 이동·인증 성공으로 오인되거나 이동을 막지 않으며, 내부 오류 정보는 시간 클라이언트에 남긴다. 네트워크 비대칭에 의한 RTT/2 추정 오차는 남는다.

### 2. FE 충돌 정의와 BE 데이터 정합성 확인

BE 전달본의 기준 커밋 `a1403c7fec82b520ee9713c6963e25f418e77ff8`을 현재 FE와 비교해 두 설정 차이를 반영했다.

- 분수의 이전 사각 충돌 1개를 반경 5.4m 원형 범위의 48개 구간으로 변경. FE `ParkFountain`의 바닥 원형 형상과 같은 기준이다.
- `TableShell`에 표시되던 야외 돌 의자 16개의 충돌 정의를 추가하고 picnic 의자 12개의 이동 충돌 높이를 BE와 같은 2.5m 기준으로 맞춤. 이 높이는 이동 차단 정책이며 시각 의자 높이를 늘린 것이 아니다.
- 전체 이동 충돌 박스 **1,205개**를 BE `park.json`과 하나씩 비교해 ID·중심·크기·회전이 일치함을 확인.
- 지형/계단/탑/울타리 메시 **4개**, 정자 hull **9개**, 이동 설정·스폰·물·탑·징검다리·테이블 배치도 전체 비교.
- BE의 시설 bake 도구를 읽기 전용으로 실행해 결과를 저장소 밖 QA 폴더에 생성. 시설 **94개**, 제외 **0개**이며 좌석·출구·상호작용/조준 등 모든 운영 필드가 기존 BE 카탈로그와 일치함을 확인했다. 출력의 `configSha256`은 현재 FE 소스 변경 때문에 달라지지만 운영 데이터와 맵 버전은 동일하다. BE 파일을 재생성/덮어쓰기하지 않았다.

위 검증 뒤 FE 기대 맵 버전을 아래 BE 충돌 맵 식별값으로 맞췄다.

```text
mapId: park
schemaVersion: 1
mapVersion: ae833248d2dd356c6603af72b2b865f9051a866e9cfa7d2b9c9abe890579944d
```

이 값은 BE 기준 source-manifest 원시 바이트의 SHA-256임을 검사한다. 현재 FE 전체 소스를 다시 해싱한 값이나 생성 JSON 파일 자체 해시라고 설명하지 않는다. 시간 코드 등 비충돌 설정 변경이 있어도 승인된 충돌 스냅샷과 실제 운영 데이터의 일치를 별도로 확인한다. 새 180m 생성 맵 전환은 이번 범위에 포함하지 않았다.

### 3. 맵 확인 후 채널 입장

- `CONNECTED`의 맵 식별 정보를 FE 자체 식별값과 비교한다. 서버 값을 FE의 기대 버전으로 자동 복사하지 않는다.
- 서버가 `mapVerificationRequired=true`이면 `WORLD_MAP_CONFIRM`에 FE 식별값을 보내고, 일치하는 `WORLD_MAP_STATE`와 `verified=true` 확인 뒤 채널에 입장한다.
- 다른 맵·거절·잘못된 확인 응답이면 입장/이동을 차단한다. 기존 WORLD_STATE와 시설 카탈로그 버전 검사도 유지한다.
- 맵 메타데이터가 없는 이전 서버는 기존 WORLD_STATE 검사로 호환하되, 실제 승인 좌표 버전이 다르면 이동하지 않는다.

## 검증

- 단위 테스트 **62개 파일 / 621개 통과**. 서버 시간 파싱·기기 시계 오차·단조 시계 RTT·숨김 탭 응답 폐기·재접속·실패/outlier와 맵 전수 정합성 회귀를 포함한다.

## BE에 남은 확인·요청

1. **배포 버전·실제 환경 확인:** 서버 시간 API와 위 `ae8332…` legacy 충돌 맵이 반영된 BE commit, 실제 맵 모드/버전, 개발 배포 시각(KST)을 공유해주세요. FE도 같은 기준으로 배포한 뒤 공동 검수해야 합니다. 새 FE를 이전 `544bc6…` 서버와 연결하면 의도적으로 맵 불일치가 차단됩니다.
2. **이동 진단 로그로 원인 확인:** 추가된 DEBUG 로그를 진단 환경에서 선택 활성화하고, 입력 만료·점프 판정·물리/방송 지연을 실제 재현 실행에서 확인해주세요. 기본값 50ms 제한·250ms 만료·30Hz·100ms 방송의 실제 배포 설정도 공유해주세요. 로그 코드 추가와 문제 원인 확인/성능 해결 완료는 구분합니다. 계정 식별 정보가 없는 로그에서 재현 대상을 구별할 안전한 방법과 KST 시각·seq·tick 대조 방법도 합의가 필요합니다.
3. **점프 유예 정책 결정:** 코요테 타임·착지 전 점프 버퍼는 BE 문서상 미확정·미구현입니다. 실제 접지 거절 재현을 확인한 뒤 도입 여부, 허용 시간, 한 번 소비/이중 점프 방지, 시설·수영·연결 변경 시 초기화 조건을 결정해주세요. 프로토타입에 있었던 기존 기능으로 단정하지 않습니다.
4. **좌표 생성 시점 공개 계약 협의:** 좌표 생성 시각 또는 물리 tick은 아직 공개 WORLD_STATE 필드에 없습니다. 서버 내부 진단 tick과 `lastInputSeq`를 대신 사용하지 않습니다. 후속 보간 개선이 필요하면 필드 제공 여부·의미·갱신 규칙을 협의해주세요. 이번 FE 연결의 필수 선행조건은 아닙니다.
5. **공동 검수:** 두 계정의 낮밤, 탭 복귀/재접속, 걷기·달리기·점프·수영·입출수, 분수 대각선 통과·돌 의자 충돌·정상 낙하/복구를 실제 승인 좌표와 화면으로 확인해주세요.

## 바로 전달할 문구

안녕하세요. 최신 dev의 BE 서버 시간 API와 충돌 보정 데이터를 확인해 FE 연결을 완료했습니다. 기존 소켓에서 접속·재접속·탭 복귀 시간 동기화를 연결했고, 분수/돌 의자 충돌 정의를 반영한 뒤 전체 맵과 시설 데이터를 대조해 `ae8332…` 버전으로 맞췄습니다. 서버가 맵 확인을 요구하면 승인 후 채널에 입장하도록 처리했습니다.

BE에서는 해당 API/맵의 실제 개발 배포 commit·버전·시각과 입력 제한/만료 설정을 공유 부탁드립니다. 추가된 진단 로그로 실제 이동 중지·점프 접지 거절 원인을 확인하고, 아직 미확정인 코요테 타임/점프 버퍼 도입 여부를 결정해주세요. 좌표 생성 시각/tick 공개 필드는 필요 시 후속 협의하면 됩니다. FE 배포 후 두 계정의 낮밤과 이동·점프·수영·분수/의자 충돌을 함께 검수하겠습니다. 첫 이동 프레임 지연은 FE에서도 별도로 분석하겠습니다.
