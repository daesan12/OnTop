## BE 전달용 요약

점프 입력 지연 관련 FE 수정과 로컬 검증이 완료됐습니다. Space를 누르는 즉시 전송 큐에 등록하며, 방향키를 놓아도 대기 점프 한 번이 보존됩니다. 입력 간격 60ms와 기존 `seq,dx,dz,run,jump` 계약은 유지합니다. 창 전환·시설 이용 등 입력 취소 시에는 대기 점프를 폐기합니다. 단위 테스트 534개, 로컬 브라우저 테스트 3개, 타입 검사·빌드가 통과했으며 개발 서버에는 아직 배포하지 않았습니다.

BE에는 다음 확인을 요청드립니다.

1. **우선 확인 — 접지 판정과 점프 누락 사유:** `WorldPhysics.java`에서 입력 수신 시와 실행 시의 `onGround()` 판정 때문에 유효한 입력이 누락되는지 확인해주세요. 평지 정지·걷기·달리기, 경사·이음새·난간, 착지 직전/직후를 비교해주세요. 현재 서버 장애 원인으로 확정한 내용은 아니므로 로그와 재현 결과로 판정이 필요합니다.
2. **수정 검토 — 접지 보정:** 프로토타입에는 작은 하향 접지 프로브와 발밑 9개 지지면 광선 검사가 있었습니다. 접지가 불안정하다면 같은 목적의 보정을 Minie/Bullet에 맞게 검토해주세요. Rapier 구현 수치를 그대로 적용하는 요청은 아닙니다.
3. **정책 협의 — 점프 입력 유예:** 발판 이탈 직후 점프를 허용하는 코요테 타임과 착지 직전 입력을 보관하는 점프 버퍼 도입 여부·허용 시간을 회신해주세요. 두 기법은 저장된 프로토타입에서 확인된 기존 기능이 아니라 추가 개선 제안입니다. 한 입력 한 번 소비, 이중 점프 방지, 시설·수영·연결 전환 시 초기화 조건을 함께 정의해주세요.
4. **로그와 재검수:** KST 시각·입력 seq·물리 tick, 수신/실행 시 접지, 점프 등록·소비·폐기 사유를 연결해 확인할 수 있게 해주세요. FE 반영본과 BE 수정/정책 적용 후 실제 개발 서버에서 누락·중복 점프가 없는지 함께 재검수해야 합니다.

회신 요청: 재현 결과와 원인, 접지 보정 필요 여부, 입력 유예 채택 여부 및 시간/초기화 정책, 반영 커밋·개발 서버 배포 시각(KST). FE에서 점프 물리나 서버 좌표 권한을 변경한 사항은 없습니다.

## 확인한 원인과 적용한 FE 수정

1. 기존 `frontend/src/world/input.ts`는 Space를 눌러도 `jump=true`만 저장하고 다음 60ms 입력 수집 주기를 기다렸다. 전송 버퍼의 전송 간격 대기까지 겹칠 수 있었다. 이제 유효한 Space keydown에서 현재 방향·카메라 회전을 반영한 입력을 즉시 전송 버퍼에 넣는다. 이미 다른 입력을 보냈다면 기존 60ms 전송 간격의 남은 시간은 지킨다. 서버의 입력 간격 제한을 우회하는 무조건 즉시 전송은 아니다.
2. 전송 대기 중인 점프가 방향키 해제에 따른 `dx=0,dz=0,jump=false` 입력으로 지워질 수 있었다. 일반 방향 갱신은 대기 점프 한 번을 유지하고 최신 방향으로 합친다. 전송 후 점프를 자동 재전송하지 않는다.
3. 방향키 해제와 입력 소유권 상실을 구분했다. FE 명령 포트에 `stopMovement()`를 추가해 창 이탈·포커스 변경·시설/테이블/메모/피드백 진입·감정표현에서 미전송 점프를 취소한다. 취소 후 정지 입력도 기존 전송 간격을 지킨다. 재접속·채널 전환 때의 입력 폐기는 유지한다.

기존 `seq,dx,dz,run,jump` 프로토콜을 유지한다. 점프 높이·중력·착지·접지·수영 상태는 서버가 결정하며, FE에서 좌표를 예측하거나 가짜 점프를 표시하지 않는다. 이전 이동 수정의 응답 대기 제거도 함께 유지한다.

## BE 요청사항 — 미구현

현재 저장소 `backend/src/main/java/com/ssafy/ontop/world/movement/WorldPhysics.java`는 `inputNow`에서 `onGround() || swimming`일 때만 `jumpQueued`를 설정한다(150행). 물리 처리에서 다시 `onGround()`를 검사하고(270행) 매 처리 때 큐를 비운다(278행). 따라서 입력 수신 시점이나 실행 시점의 접지가 잠깐 false이거나 착지 직전이면 그 점프는 실행되지 않을 수 있다. 실제 개발 서버에서 발생한 점프 누락 원인으로 확정한 것은 아니다.

1. **접지 신뢰성 비교:** 평지·경사·이음새·난간·빠른 이동에서 Minie/Bullet의 `onGround()`가 불안정해지는지 확인한다. 프로토타입의 접촉 틈 보정과 실제 발밑 지지면 검증 목적을 현 엔진에 맞춰 적용할지 검토한다. Rapier의 수치·이동 코드를 그대로 복사하지 않는다.
2. **입력 허용 유예 검토:** 접지 경계에서의 조작감을 개선하려면 서버에 코요테 타임과 착지 전 점프 버퍼를 검토한다. 허용 시간·소비 조건은 서버에서 결정한다. 한 번의 입력은 한 번만 소비하고 이중 점프·지속 자동 점프·난간 재충전이 생기지 않아야 한다. 좌석·시설·수영·재접속·채널 전환의 초기화 조건도 정의한다.
3. **원인 식별 로그:** 입력 seq와 KST 기준 시각, 수신 시/물리 처리 시 접지, jumpQueued 등록·소비·폐기 이유, 입력 만료, 실제 점프 실행과 해당 tick을 연결할 수 있게 한다. 인증 정보는 수집하지 않는다.
4. **승인 기준:** 평지 정지/걷기/달리기에서 한 번 누르면 한 번 점프한다. 착지 전/발판 이탈 직후는 합의한 유예 정책대로 동작한다. 난간·경사·시설 전환·재접속에서 추가 점프나 지연 재생이 없다. 기존 입력 빈도 제한을 유지한다.
