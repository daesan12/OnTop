## BE 요청 1 — 오목 플레이어의 경기 채팅 허용 (필수)

현재 `backend/src/main/java/com/ssafy/ontop/table/service/TableHub.java`의 `sendSpectatorEvent`는
`approvedSpectator` 승인 여부와 `canControlGame`을 검사해 플레이어의 `GAME_SPECTATOR_CHAT_SEND`를
`GAME_SPECTATOR_ACCESS_DENIED`로 거절한다.
`backend/src/test/java/com/ssafy/ontop/table/OmokSpectatorEventFlowTests.java`에도 플레이어 채팅 거절을 기대하는 테스트가 있다.
따라서 FE의 입력창만 활성화해서는 플레이어 채팅을 완료할 수 없다.

BE 담당자 요청 내용:

1. 오목 `PLAYING` 경기의 인증된 플레이어와 승인된 관전자가 같은 경기 채팅을 주고받도록 허용해 주세요.
2. 기존 `GAME_SPECTATOR_CHAT_SEND`를 플레이어에게도 허용할지, 별도 경기 공통 전송 타입을 제공할지 확정하고 명세에 반영해 주세요. 아래는 기존 타입을 유지하는 최소 변경안입니다.

   ```json
   { "type": "GAME_SPECTATOR_CHAT_SEND", "requestId": "요청 ID", "payload": {
     "gameId": "현재 승인된 경기 ID", "eventId": "UUID", "text": "메시지"
   } }
   ```

   응답·브로드캐스트 `GAME_SPECTATOR_CHAT_MESSAGE`의 `gameId`, `eventId`, `senderUserId`, `text`,
   `sentAt`, `expiresAt`, `serverNow` 필드와 Unix 밀리초 표현은 유지해 주세요.
3. 플레이어는 해당 계정의 현재 소켓이 실제로 그 경기의 조작 권한을 갖는지 서버에서 검증해 주세요. 관전자는 기존 채널·거리·관전 승인을 검증해 주세요.
4. 전송자는 ACK를 받고, 동일 경기의 플레이어 및 승인 관전자가 메시지를 받아야 합니다. 중복 전송 방지, 1초 간격 제한, 1~200자 검증, 3초 표시 만료 계약은 유지해 주세요.
5. 위치 추천 `OMOK_SPECTATOR_PING_SEND`는 계속 관전자에게만 허용해 주세요. 플레이어의 채팅 권한이 착수·핑 권한으로 확대되면 안 됩니다.
6. 종료 경기, 타인 경기, 이전 연결, 퇴장 후 전송은 거절하고 판·턴·타이머·결과·정산은 변경하지 않아야 합니다.
7. 기존 플레이어 채팅 거절 테스트를 새 정책으로 수정하고, 플레이어↔관전자 전달 및 플레이어 핑 거절 테스트를 추가해 주세요.

## BE 요청 2 — 퇴장 뒤 종료 경기 복구 전달 여부 확인

FE 표시 잔류는 위와 같이 방어했다. 실제 사용자가 재접속해도 반복했다고 보고했으므로
서버의 저장된 경기·복구 슬롯·좌석 상태도 아래 순서로 확인해 주세요. 서버 원인으로 확정한 사항은 아니다.

1. 실제 서버에서 경기 종료 → 정산 완료 → 대기 전환 → `TABLE_LEAVE` 승인 → 새로고침/재로그인을 재현한다.
2. `TABLE_LEFT`, `TABLE_STATE`, `GAME_START_STATE`, `GAME_CONNECTION_STATE`, `GAME_RESULT`를 연결별로 수집한다. 사용자·경기·테이블 ID와 전달 순서를 함께 확인한다.
3. `GameReconnectService`의 복구 슬롯이 이미 퇴장한 종료 경기를 활성 경기처럼 다시 안내하는지 확인한다. 미착석 로비는 `LOBBY` 또는 `NOT_SEATED` 계약으로 일관되게 구분해 주세요.
4. `TableHub.activateConnection`의 결과/복구 전달과 `TABLE_LEAVE` 이후 좌석 제거가 일치하는지 확인한다. 종료 내역·정산 기록은 보존하면서 현재 활성 경기 권한만 종료해 주세요.
5. 실제 진행 중 연결이 끊긴 경기의 재접속 복구, 기권 후 다른 참가자가 진행 중인 경기, 정산 대기 중인 착석 사용자의 결과 조회는 계속 가능해야 합니다.

전달용 확인 글:

> 경기 종료 후 테이블에서 일어나도 결과 화면이 남고 재접속 후에도 반복됐다는 QA가 있습니다. FE에서는 미착석 결과 표시·종료 경기 복구 재표시를 차단했습니다. 서버에서도 `TABLE_LEAVE` 이후 좌석과 활성 경기 복구 슬롯이 해제되는지, 재접속 때 과거 종료 경기 결과/복구를 어떤 순서로 전달하는지 확인 부탁드립니다. 경기·정산 이력 삭제가 아니라 현재 좌석 및 활성 복구 상태의 정합성 확인 요청입니다.
