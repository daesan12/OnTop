# 공원 진입 추가 최적화 결과

2026-10-26. 브랜치 `fix/park-entry-performance`. 비교 기준은 이전 최적화 커밋 `ea13191`의 배포 빌드다.

## 결과

같은 PC의 Edge headless / 1440×900 / 로컬 Vite 배포 빌드에서 기준 버전과 수정 버전을 번갈아 5회씩 실행했다. 매번 새 브라우저 컨텍스트를 만들고, 탐색 시작부터 첫 3D 프레임을 그린 뒤 로딩 표시가 사라지는 시각까지 측정했다.

| 공원 진입 | 이전 수정본 | 추가 최적화 |
|---|---:|---:|
| 중앙값 | 4,609ms | 2,945ms |
| 최솟값 | 4,413ms | 2,928ms |
| 최댓값 | 5,077ms | 3,101ms |

**중앙값 기준 1,664ms, 약 36.1% 단축**됐다. 이전 문서의 4.8초는 단일 측정이었으며, 위 수치는 이번 동일 조건 반복 비교 결과다. 별도 초기 실험에서도 4,072ms → 2,770ms로 같은 방향의 개선을 확인했다.

HTTP·RawWS는 테스트 fixture를 사용했다. 실제 OAuth 공급자, 서비스 백엔드·DB, 실사용자의 네트워크와 GPU 차이는 포함하지 않으며 GPU 드라이버 캐시를 강제로 초기화한 시험도 아니다. FE 머지·배포 후 실제 서비스에서 재확인이 필요하다.

## 무엇을 어떻게 바꿨나

### 1. 모델의 중복 꼭짓점 병합 비용 감소

소품과 건물 표면을 생성하는 `PropBuilder.finish()`와 `mergeSurfaceParts()`는 `mergeVertices()`로 같은 꼭짓점을 합쳤다. 기존 함수는 꼭짓점마다 위치·법선·UV·색상·표면 설정을 긴 숫자 문자열로 변환해 비교했다. 공원 진입 시 많은 정점에서 이 변환과 문자열 할당이 반복됐다.

새 `weldStaticVertices()`는 같은 반올림 규칙으로 숫자를 만들고 숫자 해시로 후보를 찾는다. 후보가 있으면 모든 정점 속성을 다시 비교한다. 해시 값이 같아도 실제 속성이 다르면 합치지 않으므로 위치만 같은 색상·UV·법선 경계도 유지한다. 첫 등장 순서와 삼각형 인덱스 순서도 유지한다.

이 경로는 공원 정적 모델의 Float32 속성에 적용한다. 정규화 속성, 모프·인터리브 등 다른 형식이나 비정상 수치는 기존 Three 유틸리티로 처리한다.

### 2. 정점별 임시 배열 생성 감소

`propGeometry.ts`의 색상과 `staticSurface.ts`의 UV·표면 설정을 기록할 때 정점마다 임시 배열을 만들어 `TypedArray.set()`에 넘기던 코드를 직접 인덱스 대입으로 바꿨다. 생성되는 모델 데이터는 같고, 초기화 중 임시 객체와 메모리 정리 부담을 줄인다.

### 계산 단독 비교

28,800개 삼각형을 가진 고정 입력을 사용하고 첫 실행을 제외해 5회 측정했다. 병합 계산 중앙값은 **86.9ms → 10.85ms**로 약 87.5% 줄었다. 두 방식의 결과는 모두 18,500개 정점이었다. 이 수치는 특정 계산의 벤치마크이며 공원 전체가 같은 비율로 빨라진다는 의미는 아니다.

## 동일성·회귀 검증

- 경계값·음수·큰 좌표의 해시 충돌, 인덱스가 있는 입력, 다양한 반올림 허용오차, 비정상 수치, 16/32비트 인덱스, 정규화·모프 속성을 검사했다.
- 실제 붕어빵 카트·우체통·랜드마크·망원경·등·벤치·거리 소품·정자 등의 생성 과정에서 기존 함수와 새 함수의 **정점 속성·인덱스 원시 바이트 SHA-256**을 비교했다. 30개 초과 배치와 10만 개 초과 입력 정점에서 동일성을 확인했다.
- 단위 테스트 **60개 파일 / 566개 통과**. 앱·테스트 TypeScript 검사, 규칙서 게시, 프로덕션 빌드 통과.
- 배포 빌드 성능 비교의 10회 입장에서 첫 이동 입력 전송, 공원 표시, 오류 오버레이·페이지 예외 없음도 확인했다.
- 진입 직후 60프레임을 기록한 최종 비교에서 프레임 중앙값은 두 버전 모두 약 8.2~8.5ms였다. p95는 기준 9.7~10.9ms, 수정 9.3~9.9ms였다. 단발성 긴 프레임은 기준 최대 34.8ms, 수정 최대 35.8ms로 남아 있다.
- 추가 브라우저 회귀 **6개 시나리오 통과**: 인증 대기 중 리소스 준비, 설정 대기 중 접속권 발급·단일 소켓, 반복 미니게임 진입/종료와 이동, 채팅·이동·착석, 테이블 포인터 선택·착석 표시·LOD·품질 변경, 재접속.

## QA 환경과 증거

Browser 플러그인이 제공되지 않아 기존 Playwright와 설치된 Edge를 사용했다. 성능 비교는 `http://127.0.0.1:52984`의 기준 빌드와 `http://127.0.0.1:52985`의 수정 빌드, 회귀 검사는 전용 개발 서버 `http://127.0.0.1:52983`을 사용했다.

화면·JSON·임시 측정 스크립트는 저장소 밖 QA 폴더에 저장했다.

- `entry-v2-performance.json`: 각 5회 원본 측정과 프레임 통계.
- `entry-v2-baseline.png`, `entry-v2-optimized.png`: 첫 입장 후 공원 화면.
- `park-return-desktop.png`, `park-return-narrow.png`: 반복 미니게임 복귀 화면.

이번 변경은 FE의 모델 생성 계산에 적용했다. 서버 이동 물리·충돌 맵, 캐릭터·소품 형상, 재질, 시야 거리, 해상도와 전체 셰이더 사전 준비 방식은 그대로 유지했다.
