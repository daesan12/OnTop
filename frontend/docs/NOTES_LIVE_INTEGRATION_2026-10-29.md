# 익명 메모 주제·작성 알림 FE 연동

> 2026-10-30: 최신 dev의 새 공원 맵 통합을 반영했습니다. 현재 배치·빌드 경로·검증과 BE 전달 내용은 [새 맵 연동 기록](./NOTES_NEW_PARK_INTEGRATION_2026-10-30.md)을 참고하세요. 아래 좌표·충돌 요청은 구맵 당시 기록입니다.

## FE 적용 내용

BE `3228c1c`가 포함된 dev `a6b06d6`의 계약을 기준으로 구현했습니다. BE 코드·DB·물리 리소스·인프라는 수정하지 않습니다.

- 메모 주제 5종(daily/cheer/worry/recommend/free)을 기본 활성화합니다. 본문은 UTF-16 300자 그대로 유지합니다. 주제를 포함한 POST 성공 응답이 요청과 일치해야 접기·부착 성공 연출을 시작합니다.
- `VITE_NOTES_CATEGORIES=false`를 명시하면 구버전 서버 호환 모드로 돌아갑니다. 이 값은 FE 빌드 시 반영되므로 배포 환경에서 이전 false 값이 남아 있으면 제거하거나 true로 바꾸고 다시 빌드해야 합니다.
- 기존 `/ws/tables` 소켓의 `NOTES_CHANGED`만 수신합니다. 새로운 소켓이나 구독 명령은 추가하지 않습니다. payload는 양수 BIGINT의 십진 문자열 `revision` 하나이며 숫자로 변환해 정밀도를 잃지 않습니다. 같은 번호·오래된 번호·잘못된 알림은 무시합니다.
- 메모창이 열린 방문만 알림을 구독합니다. 본문이나 작성자 정보를 소켓으로 전송하지 않습니다. 본인 글은 POST ACK로 바로 합치며, 수신한 작성 알림은 필요한 REST 조회로 합칩니다. 작성 요청 도중의 알림도 작성 종료 후 처리하므로 동시에 올라온 다른 사람의 글을 놓치지 않습니다.
- 정기 GET은 없습니다. 조회 중 새 알림이 오면 후속 조회 한 번으로 합치고, 로컬 1초 간격과 서버 nextAllowedAt를 지킵니다. 알림 때문에 시작한 조회가 429이면 해당 알림에 대해 한 번만 재시도합니다. 수동 조회나 다른 오류는 자동 반복하지 않습니다.
- 조회 중 기존 목록을 유지하고, 작성 화면의 원문·선택 주제·포커스·선택 범위를 보존합니다. 창 닫기·거리/활동 이탈·단절·로그아웃에는 구독과 대기 조회를 정리합니다. 재접속은 전체 목록부터 다시 읽고 revision 비교도 새 연결 기준으로 시작합니다.
- 서버의 NOTES_CATEGORY_INVALID에는 주제를 다시 고르라는 안내를 표시하며 원문·재시도 정책은 유지합니다.

## 로컬 검증

FE production build, FE/테스트 타입 검사, 전체 FE 단위 1,150개(122개 파일), 메모 REST·에셋·실시간 연동 브라우저 13개 시나리오와 FE 경계 검사가 통과했습니다. 두 세션 시나리오는 테스트 사용자 위치와 300자 trim 데이터를 바로잡은 뒤 선택 재실행해 통과했습니다. 브라우저 검증은 독립된 두 세션이 공유 HTTP/WS fixture를 사용합니다. 실제 개발 DB 저장이나 배포 성공을 의미하지 않습니다.

기본 검증 명령은 `pnpm build`, `pnpm test`, `pnpm typecheck:tests`, `pnpm check:migration`, `pnpm exec playwright test notes-live.spec.ts notes-rest.spec.ts live-notes-art.spec.ts`입니다. 이번 실행은 다른 작업의 5197 포트를 건드리지 않도록 독립 포트 5231과 별도 Vite 캐시를 사용했습니다.

검증 항목: 주제 300자 작성과 응답 확인, 다른 세션의 작성 알림 갱신, 작성 중 textarea와 커서 유지, 유휴 GET 없음, BIGINT 중복/역순 알림, 느린 조회 동안 알림 합치기, 닫힌 방문 정리, 재접속 후 새 목록과 revision, 실패 시 같은 키로 재시도, 월드 에셋의 실제 메모 최대 6장.

## BE 담당자께 남은 확인 요청

메모 주제와 작성 알림의 FE 연결을 마쳤습니다. 실제 환경에서는 V129가 적용된 DB와 NOTES_ENABLED/기존 privacy-secret 설정을 사용하는 새 BE가 배포됐는지 확인해주세요. 배포 커밋과 적용 환경을 공유해주시면, 실제 두 사용자로 주제 저장·재조회·작성 알림을 공동 검수할 수 있습니다. 비밀키 값을 전달하실 필요는 없습니다.

확대된 메모함의 충돌 범위는 기존 요청대로 별도 검토가 필요합니다. FE 표시 배율은 2지만 FE/BE의 tower-notes-box 반폭은 기존 `[0.65,0.86,0.48]`입니다. BE에서 활성 맵의 최종 충돌 형상과 mapVersion을 확정해 공유해주세요. FE 충돌·버전은 합의 없이 임의 변경하지 않았습니다. 상세 조건은 [메모함 확대 BE 요청](./handoff/NOTES_BOARD_SCALE_BE_REQUEST_2026-10-29.md)에 있습니다.

소리함의 기존 비공개 의견 API와 600자 정책은 유지합니다. 실제 저장·관리자 조회와 일반 사용자 비공개 여부는 실제 인증 세션으로 검수해야 합니다.
