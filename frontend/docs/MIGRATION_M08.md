  닫기·거리/높이 이탈·시설/테이블/수영·단절·채널 변경·인증 종료 시 기존 수명 취소와 함께 타이머를 정리한다.
  다시 열기·재접속은 새 목록 조회부터 시작한다. 중복 watcher와 지난 방문의 늦은 응답도 차단한다.
- ISO 시각을 FE ms로 변환하고 공개 목록에는 `id/text/createdAt`만 담는다. 중복 ID를 표시하지 않고
  `createdAt DESC, id DESC` 정렬·최근 120장 제한을 유지한다. 큰 정수 ID도 정밀도 손실 없이 정렬한다.
- `NOTES_READ_COOLDOWN`과 `NOTES_WRITE_COOLDOWN`의 서버 `nextAllowedAt`을 각각 적용한다.
  `403 NOTES_OUT_OF_RANGE`만 업무 거절로 처리하며, 그 밖의 권한 거절과 기존 M07·다른 REST 인증 종료는 유지한다.
- `410 NOTE_REMOVED/NOTES_REQUEST_EXPIRED`에는 원문·키를 보존하고 같은 요청의 재게시를 차단한다.
  사용자가 내용을 바꿔 새 글을 작성하기 전에는 새 키를 자동 발급하거나 다시 올리지 않는다.
- 기존 메모 UI·한글 입력·포커스·F1·카메라·닫은 뒤 이동 복구를 유지한다. WS 본문 방송·작성자 표시·
  브라우저 영구 저장·관리자 API·BE/DB/Flyway/인프라 변경은 추가하지 않는다.

### 개발 서버 확인

2026-10-25 13:59 KST, 실제 로그인·채널 입장 후 기존 개발 FE의 API 경로로 조회했다.
`GET https://dev.on-top.world/api/v1/notes?channelId=channel-1`은 **404**를 반환했다.
비인증 요청의 401과 구분해 확인했으며, 메모 목록 또는 DB 저장 성공 응답은 받지 못했다.
직접 DB 적용 이력을 조회할 관리 수단은 없어 V121 적용 여부는 확정할 수 없다.

BE 확인 필요: 실행 버전·메모 경로 등록/프록시, `NOTES_ENABLED=true`, 32자 이상의 공유
`NOTES_PRIVACY_SECRET`, 기존 Flyway 경로에 합의된 `classpath:db/notes` 추가 및 V121 적용 이력.
FE에서 설정이나 DB를 변경하지 않는다. 404만으로 DB 미적용·비밀키 누락 등을 특정 원인으로 단정하지 않는다.
API가 활성화된 뒤 실제 작성→재조회·새 접속 조회·동일 키 재시도의 DB 검수가 남아 있다.

## 기존 맵과 화면 연결

기존 `PlannedLandmarks`의 `tower-notes-mailbox` 모델과 `config/notes.ts`의 `NOTES_BOX`를 재사용한다. 새 모델·자산·좌표·맵 버전을 만들지 않는다. 정상 높이 `NOTES_BOX.y + 0.8`에서 수직 오차 0.7m 미만·반경 2.6m 이내를 검사하고 기존 공통 E 선정/버튼에 연결한다. 지상/원거리 직접 호출도 FE 포트에서 거절하며 실제 서버 권한 검증을 대신하지 않는다.

원본 `AnonymousNotes.tsx`의 목록·빈 상태·익명 쪽지·1~300자 작성·최근 120장 정책을 현재 UI와 입력 경계에 맞춰 이식한다. NFC·제어/서식 문자 제거·trim 정책은 기존 `parseAnonymousNote`를 사용한다. 길이는 JavaScript 문자열 길이이며 원문 300자 상한을 먼저 적용한다. 닉네임·작성자 ID를 메모에 표시하지 않으며 HTML 문자열을 실행하지 않는다.

조회 대기/실패를 빈 목록과 구분하고 새로고침을 제공한다. 조회는 최소 1초 간격으로 제한한다. 성공한 메모는 목록에 한 번 추가하며, 열려 있는 목록은 목업 변경 알림 후 다시 읽는다. 닫았다 열면 새로 조회한다. 15초 작성 간격·최근 120장은 개발 목업의 참조 정책이며 최종 운영 정책 확정이 아니다.

## 작성·입력·연결 수명

- 작성창이 입력을 소유하는 동안 이동·점프·E·G·채팅 Enter·카메라 드래그/휠 입력을 차단한다. 한글 입력·줄바꿈·Tab 포커스 순환·Esc/×/바깥 클릭 닫기를 제공한다. 카메라·실제 위치·아바타 자세를 바꾸지 않는다.
- 제출 중 중복 클릭과 편집을 막고 승인 후에만 입력을 비운다. 실패·형식 오류·10초 타임아웃에는 원문과 재시도 키를 유지한다. 같은 정규화 본문은 같은 키로 재시도하고 본문 변경은 새 키를 만든다.
- 응답 유실 시 목록을 먼저 확인하도록 안내한다. 목업에서는 같은 요청이 같은 메모 번호를 반환해 중복 표시를 막는다. 이 FE 포트 의미가 운영 BE의 멱등성 계약을 확정하지 않는다.
- 닫기·단절·원거리/높이 변화·시설 상태 변화·맵 불일치 시 창/목록/대기·구독·타이머를 정리하고 이전 방문의 늦은 응답을 폐기한다.
- 같은 사용자·같은 채널 자동 재접속에서는 작성 중 원문과 재시도 키만 유지한다. 목록은 재조회한다. 명시적 채널 변경·공원 종료·인증 종료·다른 사용자 연결에서는 삭제한다. 새로고침/브라우저 종료 후 복구는 제공하지 않는다.

## API와 목업 분리

확인한 Java BE에는 전망대 메모 조회·작성 API가 없다. 기존 로그인·프로필·월드/이동·채팅·테이블·오목 연결은 그대로 사용하며 새 REST 경로·WS 명령·wire DTO를 추정하지 않는다.

`features/notes/contracts.ts`는 FE 내부 포트다. 근접 검사에 쓰는 현재 세션 문맥과 공개 메모 모델을 분리한다. 목록/접수 응답에서 상태로 저장하는 메모 필드는 `id`, `text`, `createdAt`뿐이며 여분의 작성자 필드는 복사하지 않는다. 공개 월드·아바타·일반 채팅에 본문을 넣지 않는다. 이 처리가 운영 저장소/로그의 익명성까지 보장하는 것은 아니다.

일반 개발/운영에서는 작성 UI와 서버 연결 준비 안내를 표시하고 조회·게시 버튼을 비활성화한다. 미연결 상태를 가짜 빈 목록/게시 성공으로 표시하지 않는다. `pnpm dev:facilities`의 `facility-preview`에서만 `MockNotesService`를 사용한다. 페이지 안에서 공유되는 메모 목록과 변경 알림을 제공하며 실제 다른 탭·계정 간 전송·파일/DB 저장은 없다. 새로고침하면 목업 게시판도 초기화된다.

목업 메모에는 작성자·닉네임·접속 ID·주소를 저장하지 않는다. 요청 간격을 시연하기 위한 일시적 사용자별 시각과 임의 요청 키의 재시도 확인 정보는 별도 메모리에 있다. 실제 익명성 정책과 영구 저장·접속 로그 정책은 BE 공동 검수 대상이다. 운영 빌드에서 목업 구현을 제외하고 경계 스크립트로 검사한다.

BE 담당자와 합의할 항목은 읽기/쓰기 모두의 서버 근접·높이·활동 상태 권한, 전체/채널별 게시판 범위, 최신 120장/보존 정책, 익명 저장·조회 필드, 작성/조회 제한, 저장 승인·실패/응답 유실·중복 처리, 근처 조회자 갱신, 동시 작성/다중 서버/재시작 보존이다. 신고·삭제·필터는 미구현이며 이번에 임의 도입하지 않는다.

## 변경 범위와 검증

`features/notes/`에 UI·상태·요청 수명·검증·FE 서비스·목업을 추가한다. 공통 E 선정·공원 화면·입력 플래그·감정표현 가드 및 월드/런타임에는 메모 수명 훅만 추가한다. M01~M07 기능·HTTP/RawWS·M02 이동·M04 매핑·기존 인증/API 오류 처리와 BE·인프라·설정/맵·자산·의존성은 보존한다.

Browser plugin not available. 기존 Playwright/Edge와 테스트 전용 HTTP/RawWS 계약 대역을 사용한다. 검수 흐름은 기존 공원 → 정상 메모함 E → 목록/빈 상태 → 작성/입력 격리 → 실패/재시도 → 승인 후 목록 갱신 → 닫기/이동 복구다. 지상 직접 읽기/쓰기 거부, 목업 내 다른 작성자의 목록 갱신, 응답 유실/동일 키·접수 번호 재사용, 단절/인증 종료·390×844 조작부도 검증한다.
