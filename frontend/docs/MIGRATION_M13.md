# M13 거짓말 다리 건너기 이관

2026-10-24 원본 시각 보완: 아래 초기 기본 도형 대신 원본 최적화 GLB 보드·말·좌표·LOD를 적용했다. 실제 BE/비밀 눈/순차 판단 계약은 유지하며 변경·검수는 [M13 시각 보완](M13_VISUAL.md)을 따른다.

기준: 2026-10-24, M12 커밋 `2ea425d` 위의 FE 작업. 같은 `feat/frontend-m09-table-lobby` 브랜치에서 로그인·인증·기존 Spring HTTP/RawWS·월드/이동·오목·Farkle·원카드·M09 공통 로비/관전/결과를 유지한다. BE·인프라·맵·에셋 파일·의존성/잠금 파일은 수정하지 않으며 M14는 진행하지 않는다.

## 이관 범위

- 공통 로비에서 LIAR_BRIDGE 선택·준비 활성화. 2~4인·각 말7개·색상·현재 말 위치·예비/골인/추락/기권/제거 말·점수·현재 선언자와 판단자를 표시한다.
- 본인 비공개 주사위·1~4 선언·현재 판단자의 믿기/다우트·순차 응답·단계 마감·기권 예정·원자 판정·공동 승리/종료 사유·기존 정산/다음 판 흐름을 연결한다.
- 모두 믿으면 실제 눈을 계속 숨긴다. 다우트가 있는 서버 승인 판정에서만 actualFace·도전자·거짓말 여부를 표시한다. 현재 개인 눈과 이전 공개 다우트 결과를 구분한다.
- 공개 판과 개인 상태를 같은 버전 응답으로 검사한다. ACK만 먼저 오면 다음 상태를 추측하지 않고 입력을 막는다. 복구/응답 불명/연결 단절·마감·RESOLVING·FINISHED·기권 예정/확정 시 행동을 차단하며 자동 재전송하지 않는다.
- 관전자는 공개 판·말·슬롯·승자만 보며 비공개 눈·행동·개인 정산 권한을 얻지 않는다. 기존 M09 관전 시점을 그대로 사용한다.

프로토타입 `BridgePanel`, `BridgeBoard`, `TableClock`, `motion`, `presentation`의 표시/연출 구조를 참고해 현 React/RawWS 모델에 맞게 옮겼다. 원본 Colyseus·matchId/expectedRevision/phaseVersion 타입이나 서버 규칙 코드는 복사하지 않는다.

## 실제 BE 계약

현재 프로젝트 `docs/bridge.md`, `BridgeEngine`, `BridgeMatch`를 기준으로 한다. 기존 인증 소켓 하나의 `GAME_ACTION_SEND {gameId,actionId,expectedVersion,input}`를 사용한다.

| 기능 | input | FE 제한 |
| --- | --- | --- |
| 비밀 굴림 | `{kind:'roll'}` | AWAITING_ROLL의 본인 차례 |
| 숫자 선언 | `{kind:'declare',value:1~4}` | DECLARING의 본인 차례·해당 turnId의 본인 비밀 눈 수신 후 |
| 믿기 | `{kind:'trust'}` | RESPONDING의 현재 responderUserId만 |
| 다우트 | `{kind:'doubt'}` | 같은 현재 판단자만 |

입력에는 실제 눈·점수·승자·클라이언트 계산 위치·별도 프로토타입 단계 버전을 보내지 않는다. 난수·성공/실패·벌칙·이동·골인 발급·기권·종료·지급은 서버가 결정한다.

GAME_STATE의 publicState와 privateState는 하나의 version을 공유한다. 개인 상태는 `{userId,turnId,die}`이며 현재 차례의 본인에게 DECLARING/RESPONDING에서만 허용한다. 타인/관전자·다른 차례·기권 예정·굴림 전/판정 후에는 빈 객체만 허용한다. 개인 눈이 누락되거나 소유자/turnId/눈 형식이 맞지 않으면 입력을 중단한다. 공개 판에 임의의 die/face/actualFace를 수용하지 않는다.

`resolution.challenged === false`일 때는 actualFace/challengerUserId/wasBluff 키가 없어야 하며 null이어도 거절한다. challenged=true일 때만 검증 후 복사한다. 알려진 공개/개인 필드만 보관하며 개인 눈을 아바타·공개 장면·3D 재질/텍스처로 전달하지 않는다.

GAME_CONNECTION_STATE는 원카드와 같은 `{publicState,privateState}` 래퍼를 파싱한다. 같은 비밀 눈·차례·원래 마감을 복구하며 재굴림하지 않는다. 기존 복구 게이트가 PENDING이면 “경기 복구 다시 확인”으로 승인 상태를 확인한다. 공통 월드 채널의 자동 재입장 전체를 이번 범위에서 보장하지 않는다.

## 현재 서버 규칙과 원본 초안 차이

- 초안의 굴림5초/선언12초/판단7초 대신 **현 BE의 모든 단계30초**를 따른다. 굴림/선언 만료는 자동 굴림·선언 없이 차례 넘김, 판단 만료는 믿기다. FE가 자동 행동 요청을 보내지 않는다.
- 판정 연출은 서버 기준1.5초이며 입력을 막는다. 타이머는 참고 표시, 마감 정각/지연/승패는 서버 최종 판정이다. 조회·거절·재접속으로 마감을 연장하지 않는다.
- 상대 모두가 동시에 판단하지 않는다. responseOrder/acceptedBy/responderUserId를 그대로 표시한다. 활성 말이 없고 골인 말만 있는 판단자도 응답할 수 있다.
- 골인 슬롯1~8은 고정 위치다. OCCUPIED는 현재 소유 점수, VACATED는 사용 완료로 표시하고 번호/발급 이력을 보존한다. 점수는 현재 점유 슬롯 합이며 nextGoalSlot을 임의로 되돌리거나 빈 슬롯을 채우지 않는다.
- pendingForfeit는 확정 기권과 구분해 표시한다. FE에서 말을 먼저 제거하지 않으며 다음 서버 원자 판정을 따른다. THREE_GOALS/최종 생존/슬롯 소진/이동 말 소진/승자 없는 종료와 공동 승리를 서버 결과 그대로 표시한다.

## 렌더링과 연출

현 맵에 맞는 기본 도형·공유 재질로 8칸 판과 말을 구성했다. 이번 단계에서 프로토타입의 authored GLB 시각 자산을 복사한 것은 아니다. 기존 공원 에셋은 변경하지 않는다. 새 다운로드/텍스처·별도 모델 로더·캐시를 추가하지 않는다.

최대28개 말,8개 발판,8개 골인 표시,사용 완료 ×를 각각 인스턴싱한다. 승자·말의 최종 위치/점수는 전체 서버 스냅샷이 기준이다. MOVE/SCORE/SPAWN/FALL/VACATE/FORFEIT 연산은 시각 연출에만 사용한다. 첫 스냅샷·재접속·늦은 과거 판정은 재연출하지 않고 최종 상태로 맞춘다. 같은 turnId의 중복 판정도 다시 시작하지 않는다. reduced-motion/비활성 탭에서는 최종 표시를 우선하며 연출 완료가 게임 상태를 바꾸지 않는다.

위치/행렬 갱신은 ref와 scratch 객체를 사용하며 매 프레임 React 상태를 만들지 않는다. 장면 종료 시4개 개별 인스턴스 GPU 자원만 해제하고 공용 geometry/material은 페이지 수명 동안 공유한다. 정적 기본 도형과 저면수 말이므로 별도 LOD·KTX2·Meshopt 파일 변환은 적용하지 않았다. 이를 전체 장비 최적화 완료나 FPS 개선 주장으로 해석하지 않는다.

## BE 미구현과 목업 경계

원카드와 마찬가지로 **M13 게임 엔진/가짜 난수/가짜 승패·정산 목업은 추가하지 않는다.** 굴림·선언·순차 판단·비밀 눈·공개 판·복구·결과는 기존 API에 연결한다.

- 공개 수동 기권 API는 아직 없으므로 M10 공통 의사 확인 포트를 재사용한다. 전용 `DEV && MODE === 'facility-preview'`에서만 목업 의사 확인이며 경기/좌석/지급을 바꾸지 않는다. 일반 개발/운영에서는 비활성 안내다. BE 내부 graceExpired 명령을 제품에 연결하지 않는다.
- 공개 gameId 공급은 M09의 기존 전용 미리보기 포트만 목업이다. GAME_WATCH의 실제 권한·20m/채널 검사·공개 상태를 우회하지 않는다. 개발 서버 테이블 관전 거리 오류 조사는 보류 범위 그대로다.
- 정식 엔진 활성 설정(`ontop.games.bridge.enabled`), 참가 차감·DB 정산·운영 영속성·배포는 환경/BE 범위다. 소스에 API가 있다고 현재 개발 서버 활성/지급까지 완료됐다는 의미는 아니다.
