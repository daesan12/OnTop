# 붕어빵 v4 실제 DEV 납품·정산·중복 지급 검증

검증일: 2026-10-27 16:05~16:08 KST

## 결과

**실제 DEV API에서 2판을 완료했고, 각각 20점·1냥으로 정산됐다. 지갑은 100 → 101 → 102냥,
오늘 획득량은 0 → 2냥이다. 같은 완료 요청의 병렬 재전송과 늦은 납품 재전송에서 추가 지급은 없었다.**

이전 12:10의 지갑409/미니게임503 이후 BE의 지갑 수정 완료 안내를 받아 재검증했다.
이번에는 지갑 조회와 v4 로비 조회가 모두 200이며, 시작 전 활성 판은 없었다.
지갑·회원·DB 데이터를 직접 수정하거나 초기화하지 않았다.

예약 잔액은 시작부터 끝까지 0냥으로 유지됐다. 최종 일일 획득량은 2/100냥이다.

## 환경과 실제 연결 범위

- 최신 로컬 FE: `e3bf6ddfe6a43db7c21128389ad0363397a5a4d3`, `http://127.0.0.1:5201`.
- 실제 서버: `https://dev-api.on-top.world`. 사용자가 `https://dev.on-top.world`에서 실제 로그인한 회원 JWT를 메모리에서 사용했다.
- Windows / Edge / WebGL2 / 1280×720. Browser plugin not available로 기존 Playwright를 사용했다.
- 공원 위치·이동·주변 아바타와 로컬 인증 화면 진입은 기존 계약 fixture로 고정했다.
- **미니게임 시작·판 GET·납품·완료·지갑은 실제 DEV로 전달했으며 응답을 만들어 대체하지 않았다.**
- 로컬 요청의 인증 헤더를 실제 회원 JWT로 바꾸어 서버로 전달했다. 실제 OAuth 로그인은 수행했지만,
  로컬 화면에서 DEV까지의 브라우저 CORS/배포 프록시와 공개 월드 전체 동작을 검증한 것은 아니다.
- 프로덕션 환경, DB 원장 직접 조회, 부하·다중 기기·자정·상한 도달 검증은 포함하지 않는다.

## 확인한 동작

1. 지갑과 v4 로비 200, v4 지원, 일일 남은 한도와 활성 판 없음 확인 후 시작했다.
2. 실제 시작 POST와 판 GET의 서버 시각을 사용해 카운트다운 후 진행했다. 게임/서버 시각을 앞당기지 않고 실제 60초를 기다렸다.
3. 키 입력으로 팥2개를 양면 PERFECT로 조리해 쟁반에 보관했다.
4. 첫 판 납품은 실제 deliveries 200, scoreDelta20, consumedBreadIds와 다음 주문을 확인했다.
   납품 직후에도 지갑은 100냥이었다. 같은 납품 키·본문을 재전송하면 최초 영수증과 같았다.
5. 첫 판 완료는 서버 점수20·지급1, 지갑101냥을 확인했다. 같은 완료 키·본문을 동시에3회 보냈고
   모두 최초 완료 JSON과 같았다. 결과 GET도 같고 잔액은101냥이었다.
6. 두 번째 판은 t=59631에 납품했으며, 이 납품 요청의 서버 도달을 잠시 보류했다.
   60초 종료의 complete가 먼저 서버에 도달해 같은 deliveryKey의 마지막 납품까지 검증했다.
7. 두 번째 complete는 실제 서버에서200으로 성공한 뒤, FE로 가는 응답만 유실시켰다.
   FE는 판 GET의 확정 결과를 복구해 점수20·지급1을 표시했다. 지갑은102냥이었다.
8. 두 번째 완료도 같은 키·본문으로 동시에3회 재전송했다. 원래 결과가 반환되고 지급은 늘지 않았다.
9. 보류했던 납품을 완료 뒤 같은 키·본문으로 보냈다. complete가 만든 승인 영수증이200으로 재생됐고,
   늦은 응답을 FE에 전달해도 결과 화면과 잔액이 바뀌지 않았다.
10. 마지막 지갑 GET과 로비 GET에서 잔액102·일일 획득2를 대조했다. pageerror는0건이다.

전체 HTTP 확인은38건이며 서버 응답4xx/5xx는 없었다. 의도적으로 유실시킨 FE 완료 응답은1회다.
동일 요청 재생의 응답 JSON·최종 세션 결과·잔액 증가량을 함께 대조했다.
이 결과는 **HTTP와 지갑 잔액 기준으로 검증한 지급 멱등성**이며, DB 원장 UNIQUE 행 개수를 직접 센 결과는 아니다.
기존 Three.Clock 경고는 남고 오류 오버레이/앱 런타임 오류는 없었다.
