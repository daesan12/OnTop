# M05 — 운동기구 이용·표시 분리

2026-10-24. M00~M04가 머지된 최신 dev `635ab92`를 기준으로 M05 프론트 변경만 같은 작업 브랜치에 추가한다. 원본 작업본의 변경 파일 144개를 보존한다. 이번 단계에서는 원격 dev 머지·배포와 M06 진행을 하지 않는다.

## 이용 흐름

기존 11종/12대의 안정적인 시설 ID·배치·방향·충돌체를 유지한다. 공중걷기 2대, 허리돌리기·팔돌리기·파도타기·타원 달리기·노젓기·윗몸일으키기·거꾸로 매달리기·등허리지압·오금펴기·역기내리기를 대상으로 한다.

- 기존 E 선택과 안내 패널에 운동기구를 추가한다. 거리·높이·시선을 확인하고 E/버튼으로 같은 대상을 이용한다.
- 승인 전에는 이용 표시를 바꾸지 않는다. 승인 뒤 현재 세션·채널·맵·실제 접근 위치와 다른 시설 상태를 다시 확인한다.
- 이용 중 설명·목업 라벨·내려오기 버튼을 제공한다. 버튼 또는 WASD/방향키로 반납하고 승인 후 기존 이동을 재개한다. Shift/Space만으로 하차·점프하지 않는다.
- 이용/대기 중 일반 이동·채널 변경·테이블/벤치 중복 이용·감정표현을 제한한다. 정지 메시지와 기존 채팅은 유지한다.
- 채팅·G 휠 등 기존 입력 소유권을 존중한다. 단절·채널/맵 변경·본인 제거 시 이전 요청을 취소하고 원격 이용자 퇴장 시 해당 점유만 해제한다. 반납 실패는 이용 상태를 보존한다.

## 실제 BE와 목업의 경계

기준 dev의 Java 소스와 기존 메시지 처리에는 운동기구 이용·반납·점유 동기화 API가 없다. 정적 시설/충돌 정보와 일반 이동 물리는 이용 API로 간주하지 않는다. `FitnessService`와 `FitnessLease`는 FE 내부 포트이며 REST 경로·WS 명령·서버 DTO를 임의로 추가하지 않는다.

`DEV && MODE === facility-preview`에서만 `MockFitnessService`를 사용한다. `pnpm dev:facilities`도 기존 로그인·실제 BE 입장을 사용한다. 일반 개발/운영 빌드에서는 서비스가 미연결이며 이용 버튼을 비활성화한다. 운영 산출물에서 목업 구현이 제거되는지 `check:migration`으로 검사한다.

목업 점유는 현재 페이지 메모리에만 존재한다. 채널/기구별 1명 점유, 중복 요청·취소·반납을 검사하지만 실제 두 계정 간 점유 방송·서버 동시성·재접속 복구를 제공하지 않는다.

승인 위치는 표시 모델에만 합성한다. 실제 서버의 `authoritativePose`와 기존 `WORLD_MOVE {seq,dx,dz,run,jump}` 형식은 유지한다. 하차 시 최신 서버 접근 위치로 복원한다. 출구 앵커는 후속 BE 계약용이며 실제 서버 사용자를 클라이언트가 순간이동시키지 않는다. 운동 보상·능력치·지갑 지급은 추가하지 않는다.

BE 연결에는 시설 ID, 채널별 원자적 점유·반납·단절 해제, 근접/높이 검사, 승인 위치·방향·시작 시각, 공개 이용 상태, 안전 하차 위치와 취소/늦은 응답·재접속 정책이 필요하다.

## 기구와 캐릭터

승인 `startedAt`과 기존 2.4초 샘플러를 기구·아바타가 공유한다. 기존 가동 부품·인스턴싱·공유 재질·LOD와 개인 리그 수명을 유지하며 프레임별 React 상태 갱신이나 본/부품 변환 전송을 추가하지 않는다.

M05 원본의 손잡이 거리·간격, 팔돌리기 왕복 범위, 운동 자세의 좌우 대응과 골반 높이, 실제 모델 좌표의 두 본 손 IK를 이관한다. 기본 감정표현의 손 보정 경로는 유지한다. 기존 남녀 GLB·스킨·스케일·텍스처와 맵 충돌체는 변경하지 않는다.

실제 남녀 GLB의 9개 주기 표본에서 손목 목표 오차 8.5cm 이내, 착석 골반 높이와 좌우 부품 대응을 검사한다. 손가락/천 충돌 해결이나 FPS 개선·지원 GPU 성능 보장을 의미하지 않는다. 성능 비교는 후속 자산/성능 검수 범위다.

## 다른 변경과 분리

M06 망원경·M07 소리함의 상태/서비스/입력/카메라·패널은 가져오지 않는다. 원본에 섞인 인증/API 오류·지갑·미니게임·로컬 플레이·맵 생성 변경도 제외한다. M04의 손 인사/박수 목업 금지, 코드 매핑·서버 거절 처리와 기존 M02 본인 제거 입력 보호를 유지한다.

백엔드·인프라·맵/버전·자산·의존성/잠금파일·Vite 설정·실제 배포 JSON은 변경하지 않는다. 기존 로그인·HTTP/RawWS·테이블·오목·벤치 연결은 운동 이용 중 중복 방지 훅을 제외하고 유지한다.

## 검증

```sh
pnpm typecheck:tests
pnpm test
pnpm build
pnpm check:migration
pnpm test:e2e:facilities
pnpm exec playwright test tests/e2e/park.spec.ts tests/e2e/omok.spec.ts tests/e2e/fitness-boundary.spec.ts
```

Browser plugin not available. 기존 Playwright/Edge와 테스트 전용 HTTP/RawWS 계약 대역을 사용한다. 기존 실행 서버를 유지하고 facility-preview는 `127.0.0.1:5196`, 일반 모드 회귀는 별도 QA 설정의 `127.0.0.1:5198`에서 실행한다. 화면은 저장소 밖 QA 폴더에 저장한다.

검수 흐름은 기존 로그인/공원 → 12대 E 이용·기구별 동작·버튼 반납 → 원격 점유 표시·퇴장 → 채팅/G 입력 보호 → WASD 하차 후 기존 이동 → 단절 정리다. 1920×1080과 운동 조작부 390×844를 검사한다. 일반 모드에서는 이용 비활성화 상태에서도 기존 채팅이 작동하는지 확인한다.

이 검증은 FE 계약 대역과 페이지 내부 목업을 이용한다. 실제 Java 서버의 다중 사용자 점유·출구 충돌·정식 방송·개발 서버 배포 완료를 선언하지 않는다. 기존 Three.Clock/ANGLE·큰 3D 청크 경고는 남아 있다.
