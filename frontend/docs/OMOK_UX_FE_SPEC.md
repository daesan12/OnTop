# 오목 UX 후속 FE 작업 명세

작성: 2026-10-27 KST. 상태: BE 최종 계약 반영 / FE 로컬 구현 완료. 개발 서버 다중 계정 공동 검수는 별도다. [기획](../../docs/omok-ux-plan.md)과 [BE 확정 계약](../../docs/websocket-api/10-game-spectator-events.md)을 함께 사용한다.

## 확정 계약 반영

- sentAt/expiresAt/serverNow는 Unix milliseconds 숫자다. 잔여 수명은 expiresAt-serverNow, 이후 소멸은 브라우저 단조 시간으로 처리한다.
- 채팅 TTL 3000ms·핑 TTL 2000ms, 종류별 사용자 간격 1000ms, 경기 전체 채팅 3건/3초·핑 5건/2초다.
- 채팅·핑 모두 두 플레이어와 승인 관전자 전체가 받는다. 발신자 ACK도 한 번만 표시한다. 승인 응답은 모든 화면 도착 보장이 아니며 자동 재시도하지 않는다.
- GAME_WATCH 승인 후 첫 GAME_STATE를 받은 인증 관전자만 발신한다. 플레이어·향후 게스트는 수신만 한다.
- 핑은 현재 표시 version과 일치할 때만 표시한다. 높은 버전은 만료까지 제한적으로 보관하고 낮은 버전·다른 경기·중복·만료 이벤트는 폐기한다.

## 선행 의존성과 적용 범위

게임 선택·준비·수동 시작 선행 작업의 승인 상태와 태블릿 전환을 사용한다. 충돌하면 이 후속 구현을 선행 작업에 맞춘다. 시작 버튼 클릭만으로 경기를 생성하거나 카메라를 바꾸지 않는다. [선택 후 에셋 표시](BOARDGAME_PRESENTATION_PLAN.md)를 함께 반영한다.

`OMOK + role=PLAYER + 서버 경기 PLAYING`에서 집중 화면을 활성화한다. 복구 중 기존 경기를 보여줄 수 있으면 같은 카메라를 유지하되 입력은 기존 복구 조건으로 차단한다. 종료·경기 해제·채널 변경에는 핸들러와 오버레이를 정리하고 선행 결과/공원 흐름으로 복귀한다. 플레이어 전용 메뉴 숨김을 관전자에게 일괄 적용하지 않는다.

## FE-01: 고정 카메라와 보드 좌표

대상: `src/world/CameraRig.tsx`, `src/world/omokCamera.ts`, `src/game/OmokBoard.tsx`, `src/game/cameraState.ts`.

- 경기 중 두 플레이어 모두 확대 탑뷰를 사용한다. 본인 차례 조건은 카메라·화각·판 전용 레이어·판 배경 조건에서 제거하고 착수 권한 검사에만 남긴다.
- 기존 확대 화각 42도와 좌석별 up 방향을 출발점으로 사용한다. HUD 안전 영역을 제외한 사각형 안에 15×15 판 전체가 들어오게 확대 높이를 계산한다. 턴마다 시점을 재설정하지 않는다.
- 초기 진입·종료 및 창 크기 변경에 필요한 보정만 허용한다. 턴 변경·채팅·핑·F1 열기/닫기로 위치·회전·화각이 바뀌지 않는다.
- 집중 화면의 주변 둘러보기 버튼·카메라 전환 단축키는 비활성화한다. F1·기권·복구 경로는 유지한다.
- 핑 링도 판 전용 레이어에서 표시한다. 관전 참여 때문에 공원 아바타·이름표·말풍선 전체를 다시 표시하지 않는다.
- 시점 정착과 `canPlace`의 본인 턴·마감·복구·버전 검사는 유지한다. 고정 시점이 상대 턴 착수 권한을 부여하지 않는다.
- 양쪽 좌석 모두 `x=열`, `y=행`, `board[y][x]`를 유지한다. 클릭 좌표는 레이캐스트로 교차점에 변환한다.

## FE-02: 경기 정보·메뉴·F1

대상: `src/game/OmokPanel.tsx`, `src/game/prototypeTable.css`, `src/game/game.css`, `src/park/ParkPage.tsx`, `src/features/parkMenus/`, `src/features/manual/ManualHost.tsx`.

- 판 밖 상단에 내 닉네임·흑/백, 상대 닉네임·흑/백, 현재 차례와 한 수 남은 시간을 배치한다. 돌 색은 흑/백 텍스트를 병기한다. 정보가 교차점을 가리지 않게 한다.
- 수순·마지막 수·착수 안내·기권·접근성 키보드 격자·복구 안내도 판과 겹치지 않게 배치한다. 복구/요청 상태는 필요한 상황에 표시한다.
- 오른쪽 공통 메뉴 열과 해당 옷장·지도·감정표현 단축키를 플레이어 경기 중 숨김/차단한다. 독립 `게임 설명 · F1` 버튼을 제공한다.
- `ManualHost`를 언마운트하지 않는다. 오목 설명서로 열고 시간 진행 문구를 유지한다. 설명서가 열린 동안 보드 입력은 막되 서버 상태 수신과 타이머는 계속 갱신한다.
- `ParkTools`를 포함한 상위 공원 영역 전체를 숨겨서 `GamePanel`과 필수 연결 안내까지 제거하지 않는다. 경기 UI와 공원 런처 표시 조건을 분리한다.

## FE-03: 플레이어 채팅창 제거·관전 채팅 오버레이

대상: `src/features/chat/ParkChat.tsx`, `src/park/ParkPage.tsx`, `src/world/inputOwnership.ts`, 런타임·네트워크 계약 및 새 오목 전용 오버레이 모듈.

- 플레이어 경기 중 좌하단 `ParkChat` 기록·입력창을 제거한다. Enter/Z 안내·리스너도 해제하여 숨겨진 입력창·포커스·이동 잠금이 남지 않게 한다. 다른 게임·공원 채팅은 유지한다.
- 플레이어는 채팅을 전송하지 않는다. 승인된 오목 관전자에게 해당 경기 채팅 입력 경로를 제공하고, `WORLD_CHAT_SEND`와 경기별 관전 채팅 요청을 구분한다. IME 조합 중 Enter를 전송으로 오인하지 않는다.
- BE가 승인하여 전달한 같은 gameId의 관전 채팅만 표시한다. 일반 근거리 채팅이나 FE가 추측한 관전자 목록을 사용하지 않는다.
- 적용: 잔여 수명 최대 3초/동시 3개, 메시지별 고정 위치·반투명 글자·짧은 페이드아웃. 화면 여러 슬롯 중 HUD·필수 버튼·기존 메시지와 겹치지 않는 곳을 선택한다. 판 위에도 배치할 수 있으나 큰 배경 패널을 만들지 않는다.
- `pointer-events: none`으로 착수 클릭을 통과시킨다. 닉네임은 프로필과 연결하되 없으면 일반 관전자 이름을 사용한다. 일반 텍스트 렌더링, 최대 2줄·긴 글 생략 표시를 사용한다.
- eventId 중복, 다른 gameId·구독 세대, 만료 이벤트를 폐기한다. 긴 대기열이나 재접속 후 과거 이벤트 재생을 하지 않는다.
- F1이 열린 동안 설명서 위에 오버레이를 띄우지 않는다. 유효 시간을 연장하거나 닫은 뒤 만료 내용을 재생하지 않는다.

## FE-04: 관전자 판 클릭·핑

대상: `src/game/OmokBoard.tsx`, `src/game/omokPresentation.ts`, 관전 UI, 런타임·프로토콜 및 새 핑 표시 모듈.

- 승인된 `SPECTATOR`가 관전 중인 판을 클릭하면 교차점을 계산해 핑 요청을 보낸다. 참가자는 기존 착수 경로를 사용한다. 관전자 요청을 `placeOmok`/`GAME_ACTION_SEND`로 보내지 않는다.
- 실제 판이 보이고 레이캐스트가 준비됐을 때만 전송한다. 카메라 이동·UI 클릭·드래그 해제·F1·연결 복구 중 클릭을 핑으로 오인하지 않게 한다. 별도 훈수 모드 전환은 만들지 않는다.
- 두 플레이어와 해당 경기 전체 관전자가 승인 이벤트를 받아 같은 좌표에 링을 표시한다. 발신자도 서버 이벤트 수신 후 표시하고 중복을 제거한다.
- 적용: 잔여 수명 최대 2초/전체 5개/발신자별 최신 1개. 돌이 있는 교차점에도 돌을 가리지 않는 링을 표시할 수 있다. 마지막 수·착수 미리보기와 구별하고 핑 레이어는 raycast에서 제외한다.
- `basedOnVersion`은 발신 시 공개 판 버전이다. 낮은 버전의 핑은 폐기하고 판 버전이 바뀌면 기존 핑을 제거한다. 미래 버전 이벤트는 짧고 제한된 버퍼로 같은 상태가 도착할 때만 표시하며 만료 후 폐기한다.

## FE-05: 통신·수명·정리

- 채팅·핑은 일회성 이벤트 저장소로 관리한다. `useGame`의 판·차례·version을 가짜 갱신하지 않는다.
- 기존 인증 소켓과 runtime 어댑터를 확장한다. UI에서 별도 소켓을 열지 않는다. BE 확정 메시지명·필드를 사용하고 NOT_CONFIGURED 등 미지원 오류에는 관전 입력을 비활성화한다.
- 서버 시각 계약으로 이벤트 잔여 수명을 계산하고 로컬 단조 시간으로 소멸시킨다. 수신 시마다 TTL 전체를 다시 주거나 PC 시계 변경으로 오래된 핑을 살리지 않는다.
- 종료·기권 후 역할 변경·관전 종료·거리 이탈·채널 변경·재접속에 범위 키와 이벤트를 정리한다. 늦은 이벤트가 다음 경기에서 보이지 않아야 한다.
- F1·채팅 입력 잠금, 판 레이어 복귀, 타이머·리스너·핑 자원 해제를 검수한다. 동작 줄이기 설정은 정적 표시로 대체하며 공유 모델·텍스처는 임의 해제하지 않는다.

## 로컬 구현 및 확인 범위

- 브랜치 `feat/frontend-omok-ux`, 폴더 `frontend-omok-ux`. 태블릿 선행 커밋 `698a404`와 최신 dev `dcf8901`을 합친 기준에서 구현했으며, 다른 작업 폴더의 미커밋 변경은 유지했다.
- `src/game/omok/spectatorEvents.ts`: 확정 payload 검증, 승인 관전자 발신, ACK/오류 소유권, 단조 시계 만료, 중복·버전·구독 범위 정리. `OmokFeedback.tsx`/`omokFocus.css`: 채팅·핑 연출과 관전자 입력. 기존 보드·카메라·HUD·런타임과 연결했다.
- 단위 검사 71개 파일/688건 통과. 소스·테스트 TypeScript 검사, 기본·tablet 빌드, 마이그레이션 경계 검사 통과.
- Edge에서 계약 fixture 기반 브라우저 시나리오 21건 통과: 양쪽 좌석 고정 시점·3가지 화면 크기·같은 좌표 착수, 승인 관전자 채팅/핑, F1 수명, 오목 금수·응답 유실·복구·시간 만료·기권·정산·다음 판, 4개 게임의 F1과 태블릿 수동 시작. Browser plugin이 제공되지 않아 기존 Playwright/Edge 경로를 사용했다.
- 화면 크기는 1920×1080, 1280×720, 1000×1400을 확인했다. 페이지 제목·의미 있는 화면·Vite 오류 오버레이·브라우저 오류 로그·스크린샷·실제 UI 상호작용을 확인했다. 기존 Three.Clock 폐기 예정 안내와 셰이더 정밀도/빌드 청크 크기 경고는 남아 있다.
- 실제 개발 서버의 인증 계정 4개 이상 동시 접속, 수신자 큐 포화·실제 네트워크 지연·배포 환경은 이번 FE fixture 검증에 포함하지 않았다. BE 담당자 완료 회신 및 서버 통합 검사와 구분하며 최종 WebSocket 문서의 공동 검수 절차를 따른다.
