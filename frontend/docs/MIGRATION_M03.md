## 재사용한 자산과 연결

기존 남녀 GLB `/art/characters/man.glb?rig=6`, `girl.glb?rig=6`과 로더·manifest를 그대로 사용한다. 49본·두 LOD·스킨·여자 모델의 `seatedCloth` 모프를 유지한다. 새 캐릭터·메시·텍스처·별도 VisitorModel/ClapRig를 가져오지 않는다. 자산 출처·해시는 기존 manifest·크레딧·단위 검사를 따른다.

본인 외형은 기존 `/api/v1/users/me`의 `characterGender`와 프로필 어댑터를 유지한다. 위치·moving/running/swimming과 테이블 착석은 기존 서버 승인 상태를 사용한다. 타인 외형 메타데이터가 없는 경우 기존 기본 표시를 유지하며, 테스트 프로필을 실제 외형 동기화라고 표시하지 않는다. M00~M02의 로그인·HTTP/RawWS·이동·벤치 서비스 코드는 변경하지 않는다.

정교한 점프/착지 클립이나 접지·물리 판정은 추가하지 않는다. M02의 승인 높이 보간을 유지한다. 의상·손 관통의 기존 한계를 천/손가락 충돌 해결로 설명하지 않는다.

## 다른 M·목업과의 경계

기존 코드에 있던 기구·망원경·주요 표현의 자세 계산만 정리한다. **M04 G 휠·감정표현 요청/승인·이벤트 매핑·쿨다운**, **M05 시설 이용·손잡이 IK·골반 높이/좌우 보정·기구 동기**, **M06 접안 카메라·본인 숨김 확장**, M07 소리함은 포함하지 않는다. `CharacterRig.ts`의 M05용 `reachFitnessHand` 변경과 `fitnessGrip.ts`도 가져오지 않는다.

BE가 아직 제공하지 않는 시설/표현의 자세 확인 데이터는 `tests/e2e/sceneProbe.ts`의 `fixtureCharacterPose`/`fixtureExercise`와 `tests/fixtures/characterRig.ts`에만 둔다. 앱 진입 코드에서는 import하지 않는다. 운영용 가짜 계정·잔액·월드 필드·승인 API를 추가하지 않는다. M01 개발용 벤치 목업은 그대로 유지한다.

운동·박수 캡처는 테스트 데이터에 의한 자세 검수이며 실제 시설 승차·손잡이 접촉·서버 승인 표현이나 다른 M 완료의 증빙이 아니다.

백엔드·인프라·맵·프로토콜·이동/런타임·리그 구현·설정·에셋·의존성·잠금파일·인증 오류 처리·지갑·미니게임·로컬 플레이 변경도 제외한다.

새 캐릭터 단위 검사는 실제 배포 GLB를 로컬 Meshopt 디코더로 읽는다. Node CPU 검사에서는 이미지/재질을 제외하고 geometry·skin·bind·본·모프를 사용한다. 남녀별 본/스켈레톤 분리·불변 자원 참조 공유·LOD 자세 유지·개인 bone texture 해제를 검사한다. 실제 화면 검증은 원래 GLB의 재질·텍스처를 사용한다.

브라우저 흐름은 기존 공원 → 테스트 남녀 프로필 → 승인 이동/달리기 → 격리된 수영·11종/12대 운동·박수 자세 → 본인 착석 숨김/원격 전신 → 정지 복귀다. 별도 시나리오에서 원거리 LOD 후 복귀, 원격 사용자 퇴장/재입장 3회의 개인 텍스처 dispose·공유 자원 유지·준비된 GPU 메모리 수를 비교한다. 광고 회전으로 인한 별도 업로드가 비교에 섞이지 않도록 테스트 전용 시계만 고정한다. 운영 광고 코드는 변경하지 않는다.

Browser plugin not available. 기존 Playwright/Edge와 HTTP/RawWS 계약 대역을 사용하고 기존 실행 서버와 분리한 `http://127.0.0.1:5198`에서 검증한다. M03은 1920×1080, 기존 오목은 1280×720도 확인하며 로그인 390×844 회귀를 유지한다. 화면은 저장소 외부 QA 폴더에 저장한다.
