- 문서 버전: 1.6

- 상태: 핵심 규칙 확정, 밸런스 수치는 초기 기준, 일부 세부 운영 규칙 추가 확정 필요
- 이 문서는 대화에서 정한 기획을 정리한 것이다. 기획 확정과 실제 구현 완료는 구분한다.

### 1.6 치즈·베이컨 독립 큐브 (2026-11-02)

- 늘이기·감싸기·앞끝/뒤끝 규칙을 폐기한다. 치즈는 노란 큐브, 베이컨은 지방 줄무늬가 있는 분홍 큐브다.
- 한 꼬치에 치즈·베이컨은 각각 최대 2개, 토마토·피망·새우·고기는 각각 최대 1개다. 큐브 하나만 포함한 조합도 유효하다.
- 주문은 재료의 종류·개수·순서로 판정한다. 전체 역방향 정답과 마지막 재료부터 빼기는 유지한다.
- 기존 협동 주문 여섯 개의 배열·점수·서버 메시지는 유지한다. 각 배열 항목이 이제 독립된 음식 한 조각을 뜻한다.
- 주문표·손님 말풍선·완성 접시·PC/VR 음식 모델과 아이콘을 동일한 조합으로 갱신한다.

### 1.5 보상·랭킹·결과 코드 연결

- 서버의 팀 점수 20점당 두 사람에게 각각 1냥을 환산하고, 기존 원장의 모든 미니게임 보상을 합쳐 개인별 한국 시간 하루 500냥 상한을 적용한다.
- 개인별 영수증과 공동 결과·지갑·원장을 한 트랜잭션에서 확정한다. 재조회·재시도는 중복 지급하지 않는다.
- 정상 종료한 240초 VR 경기만 전체 기간 팀 최고 기록에 등록한다. 같은 두 사람은 역할을 바꾸어도 같은 팀이며 동점은 공동 순위다. 이는 상세 미정 항목에 적용한 초기 랭킹 정책이다.
- 두 역할의 공통 종이 결과 화면과 VR 공간 결과판에서 점수·개인 보상·오늘 남은 한도·랭킹 상태를 표시한다. DB 없는 독립 프리뷰는 실제 지급을 표시하지 않는다.
- 저장 migration은 사용자 번호 재지정에 따라 **V145**을 사용한다. V138은 공원 랭킹, V139는 판돈 0 허용, V140은 주간 복권 테이블이다. V145는 2026-11-04 팀 조율 후 사용자가 꼬치왕에 지정한 번호다. 로컬 DB 검증과 공유 서버 적용·두 기기/Quest 검수는 구분하며 자세한 계약·실행·한계는 [SKEWER_COOP_SETTLEMENT.md](SKEWER_COOP_SETTLEMENT.md)를 따른다.

### 1.1 개정 내용

- 테이블 정리 후 수거한 더러운 식기를 자동 식기세척기에 넣는 흐름을 추가했다.
- 꼬치·사케와 더러운 식기를 동시에 운반할 수 없다.
- 더러운 식기 운반 중에는 주문 접수·주방 전달도 할 수 없다. 이미 받은 주문표는 유지한다.
- 테이블은 정리·식기 수거 완료 시 다시 사용할 수 있다. 세척 완료를 기다리지 않는다.
- 식기 운반·세척기 용량은 각각 2테이블분, 세척은 8초다. 2026-11-02 점수는 정리 2점·수거 2점·투입 3점으로 정했다.

### 1.2 로컬 구현 반영

- 1.1의 식기 수거·운반 제한·자동 식기세척기와 관련 HUD를 독립 서빙 프리뷰에 구현했다.
- 로컬 테스트에서는 식기 최대 2테이블분, 세척기 한 번에 최대 2테이블분, 자동 세척 8초를 사용한다. 세척 중 추가 투입은 받지 않는다. 이는 확정 밸런스나 서버 계약이 아니다.
- 세척기에 투입하면 즉시 주문·음식 업무를 재개할 수 있다. 중복 입력으로 세척이 다시 시작되거나 식기가 복제되지 않는다.
- 실제 2인 서버 연결·점수/보상·서버 권한 검증은 여전히 미완료다.

### 1.3 반납·임시 보관으로 운반 막힘 해소

- 남은 사케는 냉장고에 반납하고, 꼬치는 전용 임시 보관대에 맡겼다가 원하는 접시를 다시 수령한다.
- 음식과 식기의 동시 운반 금지, 식기 운반 중 주문 접수·전달 금지는 유지한다. 손을 비운 뒤 식기를 수거할 수 있다.
- 임시 보관대는 요리사의 완성 접시 전달대와 분리한다. 전달대가 가득 차도 이미 들고 있는 꼬치를 내려놓을 수 있다.
- 로컬 서빙 프리뷰에 반납·보관·그림 선택·재수령을 구현했다. 실제 서버 동기화와 보상은 연결 전이다.

## 1. 게임 개요

### 1.4 실제 2인 연결 구현

- 각자의 컴퓨터/계정으로 같은 공원에 접속해 VR 입구에서 협동 방을 생성·참가하고 역할을 선택한다. 기존 판돈 테이블이나 한 컴퓨터의 화면 분할을 사용하지 않는다.
- 무료 협동 엔진 `SKEWER_COOP`와 기존 공통 WebSocket·인증·경기 복구를 연결했다. 두 사람의 준비 후 서버 기준 카운트다운·영업을 진행한다.
- 주문 접수·주방 전달·요리사의 앞면 두 장·조립/제출·수령·서빙과 사케 반납·꼬치 보관/재수령·식기 수거/세척을 서버 상태로 관리한다. 미전달 주문은 요리사에게 전송하지 않는다.
- 공통 시간·점수·두 번의 인사·단절 시 공동 정지·30초 복귀 대기와 공동 종료를 구현했다. 요리사의 VR 연결 해제 시 랭킹 제외 자격은 복구하지 않는다.
- 실제 회원 DB의 엽전 지급·하루 합산 한도 정산·랭킹 저장·개발 서버 배포·실기기 검수 완료를 뜻하지 않는다. 실행과 연결 계약은 `SKEWER_COOP_NETWORK.md`에 별도로 기록한다.

서로 다른 컴퓨터에서 접속한 두 플레이어가 이자카야를 함께 운영하는 협동 게임이다. 요리사는 전달받은 주문의 꼬치를 만들고, 서빙 담당은 홀을 이동하며 주문 접수·주방 전달·음식 운반·사케 준비·서빙·테이블 정리·식기 수거와 세척기 투입을 담당한다.

협동의 중심은 **주문표와 완성 접시를 정확하게 인계하고, 각 역할의 작업 순서와 동선을 맞추는 것**이다. 제한 시간 동안 더 많은 주문을 완료해 팀 점수를 높인다.

| 항목 | 기획 기준 |
| --- | --- |
| 인원 | 정확히 2명, 서로 다른 컴퓨터에서 접속 |
| 역할 | 요리사 1명 + 서빙 담당 1명 |
| 기본 조작 | 요리사: VR 또는 키보드·마우스 / 서빙 담당: 키보드·마우스 |
| 분위기 | 따뜻한 조명의 이자카야, 둥글고 단순한 3D 형태 |
| 승부 방식 | 두 플레이어가 하나의 팀 점수를 쌓는 협동 방식 |
| 종료 | 영업 제한 시간 종료 |
| 영업 시간 | 초기 기준 4분 |
| 손님 수 | 제한 시간 내 가능한 한 많이 응대. 고정 10명 종료 방식은 사용하지 않음 |
| 특별 행동 | 한 경기 인사 이벤트 2회 |

| 랭킹 | 요리사가 VR로 진행한 경기만 팀 랭킹 대상 |

## 2. 역할과 정보의 비대칭

### 2.1 서빙 담당 — PC

- 높은 고정 시점에서 가게 전체를 본다.
- 손님의 그림 말풍선과 테이블 상태를 확인한다.
- 손님에게 다가가 `E`로 주문표를 받는다.
- 주문 전달대에서 요리사에게 주문표를 넘긴다.
- 완성 접시를 수령하고, 냉장고에서 사케를 꺼내 해당 테이블에 전달한다.
- 손님이 나간 자리를 청소해 다음 손님을 받을 수 있게 한다.
- 치운 식기를 모아 자동 식기세척기에 넣는다. 식기를 들고 있을 때는 주문 업무와 음식 운반을 할 수 없다.
- 여러 테이블·주방·냉장고·입구를 잇는 이동 순서가 전략이 된다.

### 2.2 요리사 — VR 또는 PC

- 주방 중심의 조리 시점으로 플레이한다.
- **서빙 담당이 주방에 전달하기 전에는 해당 주문을 알 수 없다.**
- 전달받은 주문을 꼬치 그림으로 확인한다.
- 재료 종류·개수·순서를 맞춰 꼬치를 만든다.
- 완성 접시를 제출하면 서빙 담당이 수령할 수 있다.
- 사케 준비와 홀 청소는 서빙 담당이 처리한다.

### 2.3 정보 공개 원칙

| 정보 | 서빙 담당 | 요리사 |
| --- | --- | --- |
| 손님의 그림 말풍선 | 볼 수 있음 | 볼 수 없음 |
| 아직 접수하지 않은 주문 내용 | 말풍선으로 확인 | 공개하지 않음 |
| 접수했지만 주방에 넘기지 않은 주문표 | 볼 수 있음 | 공개하지 않음 |
| 주방에 전달된 주문 | 접수/조리 상태 확인 | 앞면으로 공개된 꼬치 작업 2개 확인 |
| 뒤에서 기다리는 요리사 작업 | 진행 수량 등 필요한 상태만 확인 | 내용은 가리고 대기 상태 표시 |
| 완성 접시 | 메뉴 모양·테이블 번호 확인 | 자신이 제출한 작업과 전달대 상태 확인 |
| 남은 영업 시간·팀 점수·인사·연결 상태 | 공동 상태 | 공동 상태 |

요리사 시점에서 홀을 볼 수 있더라도 미전달 주문 그림이 노출되면 안 된다. 단순히 화면에서 숨기는 것과 별개로, 실제 서버 연결 시 역할별 상태를 분리해야 한다.

## 3. 진입·역할 선택·경기 흐름

### 3.1 진입과 준비

1. 공원 VR 존에서 `E`로 게임 선택 화면을 연다.
2. 온탑 꼬치왕을 선택하고 2인 플레이를 준비한다.
3. 두 사용자가 요리사와 서빙 담당을 각각 선택한다.
4. 요리사는 VR 또는 키보드·마우스 입력 방식을 선택한다.
5. 역할별 설명서를 확인한다.
6. 두 플레이어가 준비하면 `3 → 2 → 1 → 시작` 연출 후 영업을 시작한다.

게임 선택 화면은 온탑 꼬치왕과 이후 추가 게임을 위한 총 3칸 구성을 유지한다. 실제 방 생성·입장·매칭의 세부 UI는 후속 확정 대상이다.

### 3.2 기본 순환

```text
깨끗한 자리 발생
  → 입구 손님 자동 입장·착석
  → 그림 말풍선으로 주문 요구 표시 — PC 전용
  → 서빙 담당이 E로 주문표 접수
  → 주방 전달대에서 주문표 인계
  → 요리사에게 꼬치 그림 공개
  → 요리사가 조립·완성 접시 제출
  → 서빙 담당이 접시 수령
  → 해당 테이블에 음식·사케 전달
  → 손님 식사·퇴장
  → 더러워진 자리를 E 유지로 정리·식기 수거
  → 다음 손님 착석 가능
```

수거한 식기는 별도 흐름으로 처리한다.

```text
더러운 식기 운반
  → 필요하면 다른 테이블 식기 추가 수거 — 최대 2테이블분, 초기 기준
  → 자동 식기세척기에 E로 투입
  → 빈손으로 주문·음식 업무 재개
  → 세척기는 자동으로 세척 진행
```

사케는 서빙 담당이 냉장고에서 별도로 준비한다. 주문·음식 업무와 식기 수거 업무를 어떤 순서로 묶을지 판단하는 것이 홀의 핵심 플레이다. 더러운 식기를 든 뒤에는 세척기에 비우기 전까지 주문을 접수하거나 주방에 전달할 수 없다.

### 3.3 종료 흐름

```text
영업 제한 시간 종료
  → 추가 행동 종료
  → 완료 연출
  → 팀 결과와 각자의 보상·랭킹 상태 표시
  → 공원 복귀
```

준비·카운트다운·완료·결과 전환은 기존 붕어빵 미니게임과 어울리는 흐름을 사용하되, 이 게임의 역할과 협동 정보를 담는다.

## 4. 매장·테이블·이동

### 4.1 매장 구성

- 테이블 총 6개: 1인석 3개, 2인석 3개.
- 총 좌석 수 9개.
- 손님 입구와 대기 공간.
- 주방 주문 전달대.
- 완성 접시 수령대.
- 사케 냉장고.
- 자동 식기세척기와 투입 공간.
- 뒤쪽 요리 공간.

현재 독립 프리뷰는 위쪽 01~03번 원형 1인석, 아래쪽 04~06번 사각 2인 테이블로 구성한다. 매장 크기는 24×15의 게임 내 좌표 단위이며 실제 미터를 뜻하지 않는다. 이 배치 수치는 플레이 검증에 따라 조정할 수 있다.

식기세척기는 홀에서 접근하기 쉬운 주방 가장자리에 배치하고, 픽업대를 이용하는 동선을 막지 않도록 한다. 세척기는 현재 홀 왼쪽 주방 가장자리의 상호작용 지점에 구현되어 있다.

### 4.2 이동과 상호작용

- 기본 이동: `WASD` 또는 방향키.
- 가까운 대상과 상호작용: `E`.
- 테이블 정리·식기 수거: `E`를 약 1.5초 유지. 꼬치·사케를 들고 있으면 시작할 수 없다.
- 자동 식기세척기 투입: 가까이에서 `E` 한 번.
- 더러운 식기 운반 중 행동 제한은 7.3절의 운반 상태별 규칙을 따른다.
- 테이블·의자·시설 등 가구에는 충돌이 있다.
- 이동하는 손님과는 통과 가능하게 해 동선이 막히지 않게 한다.
- 한 방향으로만 돌아가야 하는 불편을 줄이도록 접근 가능한 면에서 상호작용한다.

현재 프리뷰에서는 1인석 앞/양옆, 2인석 앞/뒤 접근과 클릭 이동을 지원한다. 클릭하면 실제 이동 경로가 짧은 접근 면으로 간다. 클릭 이동은 키보드 조작을 보완하는 기능이다.

## 5. 손님 입장·착석·주문

### 5.1 착석과 대기

- 청소가 끝난 알맞은 자리가 생기면 손님이 자동으로 입장해 앉는다.
- 1명 손님은 1인석을 우선 사용한다.
- 2명 손님은 2인 테이블을 사용한다.
- 1인석이 없고 대기 중인 2인 손님도 없으면, 1명 손님이 2인 테이블을 사용할 수 있다.
- 자리가 없으면 입구에서 기다린다.
- 좌석 조건에 맞는 대기 손님 중 먼저 온 팀을 우선한다.
- 입구 대기 최대 3팀을 초기 기준으로 둔다. 가득 차면 새 손님 생성을 멈춘다.
- 손님 입장 간격의 초기 기준은 12초다.

### 5.2 테이블당 주문

| 손님 규모 | 꼬치 | 사케 |
| --- | --- | --- |
| 1명 | 1개 | 0~1병 |
| 2명 | 2개 | 0~2병 |

주문량은 실제 손님 인원 기준이다. 1명 손님이 2인 테이블에 앉았다고 2명분을 주문하지 않는다.

- 테이블당 주문표는 한 장이다.
- 서빙 담당이 접수해야 주방에 전달할 수 있다.
- 꼬치는 요리사 작업으로, 사케는 서빙 담당 작업으로 나뉜다.
- 손님은 오래 기다려도 떠나지 않는다.
- 압박은 제한 시간과 빠른 서빙 보너스로 만든다.

### 5.3 서빙 담당의 상태 표시

```text
주문 미접수 → 주방 전달 대기 → 조리 중 → 픽업 가능 → 전달 완료
  → 식사 중 → 청소 필요 → 빈자리
```

2인 주문은 일부 메뉴만 완료될 수 있다. 테이블 요약 상태와 함께 접시·사케의 필요 수량과 전달 수량을 확인할 수 있어야 한다. ‘전달 완료’는 해당 테이블의 요청 메뉴 전체를 전달한 상태다.

## 6. 꼬치 재료·조립·주문 그림

### 6.1 사용할 수 있는 재료

| 구분 | 재료 | 수량·표현 규칙 |
| --- | --- | --- |
| 고형 재료 | 토마토, 피망, 새우, 고기 | 꼬치 하나에서 종류별 최대 1개 |
| 큐브 재료 | 치즈, 베이컨 | 종류별 최대 2개. 각각 독립된 한 조각 |

버섯 등 게임에 없는 재료는 주문 그림·메뉴·완성 접시에 등장시키지 않는다. 현재 검증용 메뉴는 고형 재료 네 종류를 각 한 개씩 사용하며, 큐브 위치와 개수가 다른 여섯 조합을 사용한다. 정식 메뉴별 난도 배정은 추가로 정리한다.

### 6.2 조립 규칙

- 주문의 재료 종류·순서·개수를 모두 맞춘다.
- 치즈·베이컨은 각각 최대 2개의 큐브를 한 조각씩 꽂는다.
- 같은 종류의 큐브 두 개를 연속으로 꽂거나 떨어진 위치에 꽂을 수 있다.
- 꼬치 전체를 반대 방향으로 조립해도 정답이다.
- 수정은 마지막에 꽂은 재료부터 하나씩 빼는 방식이다.
- 제출 실패 시 조립 상태를 유지해 수정할 수 있게 한다.
- 성공한 꼬치는 완성 접시로 넘기고 다음 작업을 진행한다.

예시:

```text
조립 순서:
토마토 → 치즈 큐브 → 피망 → 새우 → 치즈 큐브 → 고기

완성 그림:
토마토 — 치즈 — 피망 — 새우 — 치즈 — 고기
```

### 6.3 요리사의 주문 큐

- 테이블 주문표가 주방에 전달되면 꼬치별 작업으로 나눈다.
- 2인 테이블의 꼬치 두 개는 각각 하나의 조리 작업이다.
- 동시에 확인할 수 있는 앞면 주문은 2개다.
- 나머지 작업은 뒷면으로 가려 대기시킨다.
- 앞면 작업 중 하나를 선택해 조립한다.
- 올바르게 제출하면 해당 작업이 제거되고 다음 대기 주문이 자동으로 공개된다.
- 완성 접시 전달대가 가득 차면 조립 상태를 보존하고 수령을 기다리게 한다.

### 6.4 그림 주문서의 기준

1. 손님 말풍선에는 대화 문장 대신 음식 그림으로 요구사항을 표시한다.
2. 서빙 담당이 전달한 주문은 요리사에게도 같은 레시피의 그림으로 표시한다.
3. 그림은 실제 재료 목록·순서·개수를 따라야 한다.
4. 각 조각이 서로 가려지지 않도록 충분한 간격을 둔다.
5. 치즈의 노란색과 기공, 베이컨의 분홍색과 지방 줄무늬로 두 큐브를 구분한다.
6. 요리사는 테이블 번호와 그림을 함께 확인한다.

현재 화면 기준:

- 손님 말풍선: 간결한 꼬치 그림과 사케 수량.
- PC 요리사: 앞면 그림 2장, 선택한 주문의 큐브 개수, 큰 그림·번호·조각 순서를 보는 상세 안내.
- VR 요리사: 공간 주문판의 그림 2장과 선택한 주문의 큰 조립 순서 안내.
- 완성 접시: 실제 조합의 음식 형태와 테이블 번호.

## 7. 주문표·음식·더러운 식기 운반

### 7.1 용량

| 대상 | 최대 용량 |
| --- | --- |
| PC가 들고 있는 주문표 | 2장 |
| 주방의 완성 접시 전달대 | 꼬치 접시 2개 |
| PC가 운반하는 꼬치 접시 | 2개 |
| PC가 운반하는 사케 | 2병 |
| PC가 운반하는 더러운 식기 | 최대 2테이블분 — 초기 테스트 기준 |

꼬치 접시 2개와 사케 2병은 함께 운반할 수 있다. **꼬치·사케와 더러운 식기는 동시에 운반할 수 없다.** 꼬치나 사케를 하나라도 들고 있으면 테이블 정리·식기 수거를 시작할 수 없다.

더러운 식기는 낱그릇 개수 대신 한 테이블에서 수거한 묶음을 단위로 센다. 1인석과 2인석의 식기는 모두 한 테이블분이며, 그릇 더미의 모양으로 실제 인원 차이를 표현한다. 식기 2테이블분 제한은 플레이테스트 후 조정할 수 있다.

### 7.2 처리 기준

- 주방에서 접수한 주문표를 넘기면 요리사 작업 큐에 등록된다.
- 수령대에서는 먼저 완성된 접시부터 한 번의 상호작용에 하나씩 수령하는 것을 초기 기준으로 둔다.
- 냉장고에서는 한 번의 상호작용에 사케 한 병씩 준비한다.
- 테이블에서는 들고 있는 음식 중 해당 주문에 맞는 접시와 필요한 사케를 전달한다.
- 한 번의 테이블 상호작용으로 현재 전달 가능한 일치 메뉴를 함께 전달하는 것을 초기 기준으로 둔다.
- 다른 테이블의 접시와 아직 필요하지 않은 사케는 운반 상태에 남긴다.
- 동일한 메뉴를 반복 전달해 점수를 중복 획득할 수 없어야 한다.
- 위 주문·음식 작업은 더러운 식기를 운반하지 않을 때만 할 수 있다.

### 7.3 운반 상태별 행동 제한

| 운반 상태 | 가능한 홀 작업 | 할 수 없는 홀 작업 |
| --- | --- | --- |
| 빈손 — 주문표 소지 여부와 무관 | 주문 접수·전달, 음식·사케 수령, 보관 꼬치 수령, 테이블 정리·식기 수거 | 용량·거리 등 다른 조건에 맞지 않는 작업 |
| 꼬치 또는 사케 운반 중 | 주문 접수·전달, 용량 내 추가 음식·사케 수령, 해당 테이블 서빙, 사케 반납·꼬치 보관·용량 내 재수령 | 테이블 정리·더러운 식기 수거 |
| 더러운 식기 운반 중 | 용량 내 다른 테이블 식기 추가 수거, 세척기 투입 | 주문 접수·주방 전달, 꼬치·사케 수령과 서빙, 보관 꼬치 수령 |

- 이동은 모든 운반 상태에서 가능하다.
- 더러운 식기를 수거하기 전에 받은 주문표는 버리거나 자동 전달하지 않고 그대로 소지한다. 세척기에 식기를 넣은 뒤 전달할 수 있다.
- 더러운 식기가 2테이블분이면 추가 테이블 정리·수거를 시작할 수 없다. 세척기에 비워야 한다.
- 인사 카드 응답·공동 일시정지·연결 복구 같은 공통 기능은 운반 제한으로 막지 않는다.
- 행동 제한은 버튼 표시와 서버 판정에 함께 적용한다. 막힌 행동으로 소지품이나 주문 상태가 바뀌면 안 된다.

### 7.4 동선 판단의 예

팀이 판단할 동선의 예:

> 두 테이블의 주문표 접수 → 주방에 함께 전달 → 완성 접시 두 개와 사케 수령 → 들고 있는 음식을 모두 서빙 → 더러운 테이블 두 곳 정리·식기 수거 → 세척기에 투입 → 새 주문 접수.

식기를 들기 전에 주문표부터 받아둘지, 식기를 한 테이블분만 들고 바로 비울지 두 테이블분을 모아서 갈지 선택하게 한다.

### 7.5 사케 반납과 꼬치 임시 보관

| 장소 | 조작 | 처리 |
| --- | --- | --- |
| 사케 냉장고 | E | 용량 내에서 사케 1병 수령 |
| 사케 냉장고 | R 또는 반납 버튼 | 들고 있는 사케 전부 반납. 꼬치 접시는 유지 |
| 꼬치 임시 보관대 | 접시를 들고 E | 들고 있는 꼬치 접시 전부 맡기기. 사케는 유지 |
| 꼬치 임시 보관대 | 빈손일 때 E, 또는 R/받기 버튼 | 보관 접시 목록 열기. 테이블 번호와 실제 꼬치 조합 그림을 보고 원하는 1접시 선택 |

- 재수령 후에도 꼬치 운반 한도는 2접시다. 1접시를 든 상태에서는 R로 목록을 열어 다른 1접시를 받을 수 있다.
- 보관은 기존 접시의 소유 위치만 바꾼다. 접시 ID·테이블/주문 연결·레시피·완성 상태를 유지하며, 새 접시를 생성하거나 요리사에게 재제작을 요청하지 않는다.
- 보관 공간은 현재 발행된 미전달 접시를 모두 내려놓을 수 있게 확보한다. 요리사의 2접시 전달대와 용량을 공유하거나, 보관대가 가득 차 손을 비울 수 없게 만들지 않는다. 현재 9석의 정상 주문은 최대 9접시다.
- 보관한 접시의 수량과 실제 접시를 홀에 표시한다. 목록에서는 같은 테이블의 서로 다른 메뉴도 그림으로 구분한다.
- 더러운 식기를 든 동안 보관 꼬치를 받을 수 없다. 식기를 세척기에 넣은 뒤 재수령한다. 주문표는 반납·보관 과정에서도 유지한다.
- 접시를 고르는 동안 이동과 다른 업무 입력은 막고, 영업·손님·세척 시간은 계속 진행한다. 목록 취소·닫기로 접시가 사라지지 않는다.
- 반납·보관·재수령에는 점수를 주거나 빼지 않는다. 손님에게 정확히 전달했을 때만 기존 메뉴 점수를 확정한다. 종료 시 보관 접시는 자동 서빙되지 않는다.
- 영업 종료 후 새 반납·보관·재수령은 막는다. 중복 요청이나 거리 밖 요청으로 접시·사케가 복제되거나 소실되지 않아야 한다.

운반 중인 음식이 모든 청소를 막는 경우, **사케 반납 → 꼬치 보관 → 테이블 정리·세척기 투입 → 필요한 꼬치 재수령**으로 업무를 전환한다.

## 8. 식사·퇴장·테이블 정리·자동 식기세척

### 8.1 식사와 퇴장

- 전체 주문이 전달되면 손님이 식사한다.
- 식사가 끝나면 손님이 퇴장하고 테이블이 더러워진다.
- 더러운 자리에는 다음 손님이 앉을 수 없다.

정식 식사 시간과 별도의 퇴장 이동 시간은 밸런스 확정이 필요하다. 프리뷰에 사용한 식사 시간은 화면 검증용이며 최종 기획 수치로 고정하지 않는다.

### 8.2 테이블 정리와 식기 수거

1. 꼬치·사케를 들고 있지 않고 식기 운반량에 여유가 있을 때, PC가 더러운 테이블에 접근한다.
2. `E`를 약 1.5초 유지한다.
3. 완료 시 테이블을 정리하고 그 테이블의 더러운 식기 한 묶음을 수거한다.
4. 정리된 테이블에는 다음 손님이 바로 배정될 수 있다.
5. PC는 수거한 식기를 세척기로 운반한다. 남은 용량이 있으면 다른 테이블 식기도 추가로 수거할 수 있다.

- 도중에 이동하거나 키를 놓으면 정리가 취소되고 진행도가 초기화된다.
- 취소 시 테이블 상태와 식기 운반량은 바뀌지 않는다.
- 테이블 정리와 해당 식기 수거는 한 번에 완료된다. 식기를 수거하지 않은 채 자리만 비우는 처리는 하지 않는다.
- **새 손님 착석은 세척 완료를 기다리지 않는다.** 테이블 정리·식기 수거 완료를 기준으로 한다.

### 8.3 자동 식기세척기

- 가까이에서 `E` 한 번으로 들고 있는 더러운 식기를 함께 투입한다.
- 투입이 정상 처리되면 더러운 식기 운반량이 비워지고 주문·음식 업무를 다시 할 수 있다.
- 식기세척기는 자동으로 세척을 진행한다. PC가 옆에 머물거나 세척 완료 버튼을 누를 필요가 없다.
- 깨끗한 식기를 다시 수령·운반하는 작업은 이번 범위에 넣지 않는다.
- 세제 보충·기계 고장·별도 타이밍 판정은 이번 범위에 넣지 않는다.
- 세척 시간, 기계의 투입/대기 용량, 세척 중 추가 투입 가능 여부와 일괄 처리 방식은 추가 확정 대상이다. 아직 특정 시간이나 무제한 투입을 확정하지 않는다.
- 기계가 투입을 받을 수 없다면 식기는 계속 PC가 소지한다. 실제로 받지 않은 식기를 비운 것으로 처리하지 않는다.

현재 로컬 프리뷰만의 시험 설정은 **한 번에 최대 2테이블분, 자동 세척 8초, 세척 중 추가 투입 불가**다. 세척 중에는 남은 시간과 진행도를 보여주며, 식기를 든 사용자가 다시 투입하면 기존 세척과 운반 식기를 보존한다. 정식 밸런스는 실제 2인 테스트 후 확정한다.

### 8.4 안내와 동선

- HUD에 현재 운반 모드와 더러운 식기 적재량을 표시한다. 예: `식기 운반 중 · 1/2테이블분 · 주문 업무 불가`.
- 음식을 든 상태에서 테이블 정리를 시도하면 `음식을 먼저 서빙해 주세요`를 표시한다.
- 식기를 든 상태에서 주문·음식 작업을 시도하면 `식기를 세척기에 넣어 주세요`를 표시한다.
- 식기 적재량이 가득 찼으면 `식기가 가득 찼어요 · 세척기에 비워 주세요`를 표시한다.
- 꼬치·사케를 든 자세와 더러운 식기를 든 자세를 구분한다. 색상 외에도 그릇 모양과 아이콘·문구로 상태를 알린다.
- 세척기는 주방 가장자리에서 접근하기 쉽게 배치하고, 식기 반납을 위해 지나치게 긴 왕복을 요구하지 않도록 검증한다.

### 8.5 청소·식기 처리 점수

- 테이블 한 이용 회차당 정리 2점, 수거 2점, 세척기 투입 3점: 합계 7점이다. 1인석·2인석 모두 같다.
- 정리와 수거는 E를 1.5초 유지한 완료 시점에 함께 확정한다. 별도의 추가 버튼은 없다. 중간 취소·이동·종료는 0점이다.
- 식기 묶음이 세척기로 실제 이동할 때 묶음당 3점을 확정한다. 2테이블분을 한 번에 넣으면 6점이다.
- 자동 세척 완료에는 추가 점수가 없다. 세척 중 종료되어도 이미 확정한 투입 점수는 유지한다.
- 같은 묶음을 반복 수거/투입할 수 없고, 잘못된 입력·음식 반납·보관은 점수를 주지 않는다.
- 운반 중 종료되면 정리·수거 4점만 유지한다. 종료 후 남은 작업을 자동 완료하거나 추가 지급하지 않는다.

## 9. 인사 이벤트

- 한 경기에 총 2회 발생한다.
- 초반·후반의 서로 다른 구간에 배치하고, 구간 안의 발생 시점을 무작위로 정한다.
- 두 플레이어에게 인사 카드를 표시한다.
- 각자 빠르게 카드를 선택할수록 더 높은 보너스를 받는다.
- 두 사람 중 느린 응답을 기준으로 팀 보너스를 계산하는 것을 초기 기준으로 둔다.
- 응답 시간의 초기 상한은 6초, 이벤트당 보너스는 0~50점이다.
- 선택하면 두 캐릭터가 **“어서오십쇼!!”** 하고 말하는 말풍선 연출을 보여준다.
- 실제 마이크 발화를 요구하지 않는다.
- 인사 중에도 영업 제한시간과 인사 응답 시계(최대 5초)는 계속 진행한다. 영업시간 0초에서는 경기 종료가 우선한다. 손님 입장·식사·청소·세척과 서빙 속도 측정은 인사 구간을 제외한다. (2026-11-03 변경)
- 자동 세척과 진행 중인 테이블 정리도 함께 정지한다. 식기 운반 중이어도 인사 카드에는 응답할 수 있다.
- 이벤트 종료 후 중단한 영업 흐름을 이어간다.
- 피버타임이나 피버 배율은 사용하지 않는다.

정확한 발생 구간, 응답 속도별 보너스 함수, 한쪽이 미응답했을 때의 처리와 일반 조작 허용 범위는 추가 확정 대상이다.

## 10. 점수와 확정 시점

### 10.1 초기 점수표

| 행동 | 팀 점수 | 점수 확정 시점 |
| --- | ---: | --- |
| 쉬운 꼬치 | 100점 | 손님에게 올바르게 전달했을 때 |
| 보통 꼬치 | 160점 | 손님에게 올바르게 전달했을 때 |
| 어려운 꼬치 | 240점 | 손님에게 올바르게 전달했을 때 |
| 요청한 사케 | 1병당 30점 | 손님에게 올바르게 전달했을 때 |
| 빠른 서빙 | 테이블당 0~30점 | 테이블 주문 전체 전달 시 |
| 테이블 정리·식기 처리 | 정리 2 + 수거 2 + 투입 3 = 7점 | 각 완료 단계에서 확정. 자동 세척 완료는 추가 점수 없음 — 8.5절 |
| 인사 | 이벤트당 0~50점, 한 경기 2회 | 해당 이벤트 판정 시 |

쉬움·보통·어려움 주문의 구성 비율은 비슷하게 유지하고, 등장 순서를 무작위로 만든다. 높은 난도의 주문일수록 기본 점수를 높게 준다.

### 10.2 빠른 서빙 보너스

- 손님 착석부터 그 테이블의 주문 전체 전달까지 걸린 시간을 측정한다.
- 인사 이벤트·공동 일시정지 구간은 측정 시간에서 제외한다.
- 초기 기준 시간은 꼬치 난도별 쉬움 45초, 보통 60초, 어려움 80초다.
- 2인 테이블은 해당 꼬치들의 기준 시간을 합산한다.
- 예: 쉬움 + 어려움 주문의 초기 기준 시간은 45 + 80 = 125초다.
- 테이블 전체 주문을 완료한 순간 빠른 서빙 보너스를 한 번 확정한다.

시간을 0~30점으로 환산하는 함수, 반올림 방식, 사케 주문에 대한 추가 시간 가산은 아직 세부 확정이 필요하다.

### 10.3 영업 종료 경계

| 종료 시 상태 | 처리 |
| --- | --- |
| 이미 손님에게 정확히 전달한 메뉴 | 해당 메뉴 점수 유지 |
| 일부 메뉴만 전달한 테이블 | 전달한 메뉴 점수 유지, 전체 완료 보너스는 없음 |
| 요리사가 만들었지만 수령대에 있는 접시 | 서빙 점수 없음 |
| 임시 보관대에 맡긴 접시 | 서빙 점수 없음. 종료 시 자동 전달·추가 지급 없음 |
| PC가 들고 있지만 손님에게 전달하지 않은 접시·사케 | 서빙 점수 없음 |
| 테이블 정리 중이지만 아직 완료하지 않은 자리 | 해당 미완료 단계 점수 없음 |
| 정리했지만 운반 중인 더러운 식기 | 이미 확정된 단계 점수만 유지. 미완료 식기 처리 점수 없음 |
| 세척기에 투입했지만 자동 세척 중인 식기 | 확정된 단계 점수만 유지. 종료 후 세척 시간 연장·추가 지급 없음 |
| 조리 중인 꼬치·대기 주문 | 완료 메뉴 점수 없음 |

조립 성공이나 주방 제출 자체를 손님에게 서빙한 것으로 계산하지 않는다.

## 11. 엽전 보상과 일일 상한

### 11.1 입장과 기본 환산

- 무료로 플레이한다. 시작 시 엽전을 지불하지 않는다.
- 팀 점수를 기준으로 **20점당 1냥**, 소수점은 버림 처리한다.
- 계산한 기본 보상을 두 사람에게 각각 적용한다. 팀 보상을 절반으로 나누는 방식이 아니다.
- 각 플레이어의 실제 지급액은 자신의 남은 일일 한도를 넘을 수 없다.

```text
개인 기본 보상 = floor(팀 점수 / 20)

개인 남은 한도 = max(0, 500 - 오늘 모든 미니게임에서 이미 받은 엽전)

개인 실제 지급액 = min(개인 기본 보상, 개인 남은 한도)
```

### 11.2 공유 상한

일일 500냥은 꼬치왕만의 상한이 아니라 **모든 미니게임이 공유하는 개인별 하루 상한**이다. 두 사람의 한도도 각각 다르게 계산한다.

예시:

- 팀 점수 2,400점 → 기본 보상은 각자 120냥.
- A가 오늘 다른 미니게임 등에서 460냥을 받았다면, 남은 한도 40냥만 지급.
- B가 오늘 200냥을 받았다면, 남은 한도 300냥 중 120냥 지급.

하루 한도는 엽전 보상과 연결되는 값이다. 한도 도달 후 플레이 안내, 하루의 기준 시각과 초기화 처리는 기존 공통 미니게임 정책에 맞춰 최종 확인한다.

### 11.3 서버 확정

- 최종 점수와 보상은 서버 판정 결과를 따른다.
- 결과창 재열기·중복 종료 요청·재접속으로 보상이 중복 지급되지 않아야 한다.
- 결과 화면에서 팀 점수, 개인 기본 보상, 한도 적용 후 실제 지급액을 구분한다.

## 12. VR 사용과 팀 랭킹 자격

| 요리사 입력 상태 | 플레이 | 엽전 보상 | 팀 랭킹 |
| --- | --- | --- | --- |
| VR로 진행 | 가능 | 일일 잔여 한도 내 지급 | 대상 |
| 처음부터 키보드·마우스로 진행 | 가능 | 같은 환산·한도 적용 | 제외 |
| 경기 중 VR에서 키보드·마우스로 전환 | 계속 진행 가능 | 같은 환산·한도 적용 | 해당 경기 계속 제외 |
| 전환 후 VR 재연결 | 계속 진행 가능 | 같은 환산·한도 적용 | 해당 경기 자격 복구 안 됨 |

- 준비 화면에서 요리사의 입력 방식을 선택하고 팀 랭킹 자격을 두 사람 모두에게 명확히 표시한다.
- 비VR 경기는 “랭킹 제외 · 일일 한도 내 엽전 보상 가능”처럼 직관적으로 안내한다.
- 실제 VR 사용 여부와 일반 브라우저의 VR 시점 미리보기를 구분한다.
- 기권 또는 재접속 시간 초과로 끝난 경기는 팀 랭킹에서 제외한다.
- 랭킹의 상세 집계 기간·동점 처리·표시 방식은 후속 확정 대상이다.

## 13. 일시정지·이탈·재접속

### 13.1 공동 일시정지

- 수동 일시정지는 두 사람의 게임을 함께 멈춘다.
- 영업과 손님 관련 진행 시간을 함께 정지한다.
- 테이블 정리 진행과 자동 세척도 함께 정지한다.
- 두 사람 모두 준비하면 재개한다.
- 설명서·팝업 사용 중에는 뒤의 게임 조작이 함께 실행되지 않게 한다.

### 13.2 연결 끊김

1. 한쪽의 연결이 끊기면 공동 일시정지한다.
2. 30초 동안 재접속을 기다린다.
3. 제한 시간 안에 돌아오면 서버의 현재 상태를 복원해 이어간다.
4. 30초 동안 돌아오지 않으면 경기 완료 처리한다.
5. 종료 전에 확정한 점수만 정산하고 팀 랭킹에서는 제외한다.

재접속 시 역할·테이블·주문 큐·조립 상태·운반 상태·전달 완료 여부·중단한 시간·랭킹 제외 상태가 일치해야 한다. 운반 상태에는 음식과 더러운 식기의 배타적 구분·식기 묶음 수·기존 주문표를 포함하고, 세척기의 투입/대기 상태와 남은 세척 시간도 함께 복원한다.

명시적으로 기권한 경우에는 즉시 종료한다. 서버 프로세스 재시작 후 복구는 별도의 구현·검증 대상이며 현재 보장하지 않는다.

## 14. 화면·아트·가독성

### 14.1 서빙 화면

- 가게 전체와 통로를 한눈에 볼 수 있는 높은 고정 시점을 사용한다.
- 오버쿡드에서 참고하는 핵심은 전체 매장 구도와 동선 판단이다.
- 둥근 캐릭터·두꺼운 가구·큰 색 영역·명확한 접지 그림자로 형태를 통일한다.
- 이자카야의 목재, 남색 노렌, 붉은 등롱과 따뜻한 조명을 사용한다.
- 장식은 벽·주방 뒤·외곽에 두어 길과 작업 대상을 가리지 않게 한다.
- 그림 말풍선, 테이블 번호, 상태 아이콘, 가까운 대상의 `E` 안내를 보여준다.
- 주문표 2장·접시 2개·사케 2병의 보유 상태를 가장자리 HUD에서 확인한다.
- 더러운 식기 운반 모드와 0~2테이블분 적재량을 표시하고, 할 수 없는 주문·음식 행동의 이유를 안내한다.

### 14.2 요리사 화면

- 음식과 꼬치를 직접 조작하는 주방 시점이다.

- VR 실기기에서 시야·글자 크기·거리·컨트롤러 조작을 별도로 검증한다.

### 14.3 준비·결과 화면

### 2026-11-03 오배송 규칙 추가

- 주문을 받은 뒤 음식 대기 중인 테이블(주방 전달 대기/조리 중/픽업 가능)에 E로 서빙할 수 있다. 트레이에서 해당 테이블의 미전달 꼬치와 아직 필요한 사케를 전달한다.

- PC 화면은 큰 꼬치 그림이 있는 영수증 두 장과 중앙 상단 남은 시간·팀 점수·요리 완료 수를 표시한다. 요리 완료는 정확도와 무관하게 전달대 제출에 성공한 꼬치 수다.
- 좌상단 제목, PC/VR 전환 탭, 오른쪽 시간·전달대 패널, 하단 재료·순서·제출 바는 PC에서 제거한다. 간단한 키 안내와 오류/행동 메시지만 남긴다.
- 숫자 1~6은 왼쪽부터 현재 재료 위치에 대응한다. Space로 꽂고 Backspace로 끝 재료를 뺀다. **R로 완성 및 즉시 전달대 제출**, Enter는 사용하지 않는다.
- PC 제출 성공마다 재료·이름표·클릭 영역을 함께 재배치한다. 같은 순서가 반복되지 않게 하며 실제 헤드셋 요리 중에는 배치를 섞지 않는다. 수량 초과·잘못된 큐브 간격·빈 꼬치·전달대 가득 참으로 거절되면 제작 수와 배치는 유지된다.
- 치즈·베이컨은 종류별 0개 또는 2~3개. 같은 큐브의 각 인접한 출현 사이에는 다른 재료가 정확히 한 개 있어야 한다. 치즈–피망–치즈는 가능, 치즈–치즈와 치즈–피망–새우–치즈는 불가능하다. 조립 중 단일 큐브는 허용하지만 그 상태로 제출할 수 없다.
- 여섯 주문 레시피를 FE/BE에서 동일하게 수정했고, 실제 레시피로 960×340 주문 그림을 다시 렌더링했다. 손님 말풍선·요리사 주문서·접시에서 같은 recipe 키를 사용한다.
- 레시피와 다르게 만든 꼬치도 조립 규칙을 충족하면 제출할 수 있다. 전달대·서빙 트레이에는 실제 제작 재료를 표시한다. 손님에게 전달했을 때 잘못된 꼬치는 소모하고 접시당 10점 감점(0점 하한), 원래 주문을 주방에 다시 보낸다. 단순 다른 테이블 오배송의 기존 음식 보존 규칙은 유지한다.
- 서버 privateState.chef에 pantry(현재 슬롯 순서), completed(제작 완료 수)를 추가한다. SUBMIT 액션과 기존 actionId/expectedVersion 처리를 재사용한다. 원본 주문과 실제 제작 접시를 분리해 올바른 음식만 점수를 받는다.
