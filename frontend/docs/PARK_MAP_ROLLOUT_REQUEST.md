# 새 공원 맵 전환 요청서 — BE·인프라 공동 전달용

확정일: 2026-10-29  
기준: `feat/park-180-layout-preview`의 FE 확정 전달본. 기능 기준은 원격 `dev`의 `94421c9ce7422d0868f51ae92e955ba5d9555a4d`이며 새 맵의 실제 전환은 BE·인프라 검증 후 별도로 진행합니다.

## 1. 이번 요청의 목적과 현재 상태

2026-10-29 기능 보강 기준은 원격 `dev`의 `94421c9c`이다. 본인 이동 예측·서버 위치 보정까지 반영했으며 motion 없는 서버에서는 기존 표시를 사용한다. 새 맵의 배치·모델·광고 제거 상태와 아래 JSON 버전은 유지하고 FE 기능만 동기화했다. 상세 보존 규칙·좌표 어댑터·검증 범위는 `frontend/docs/PARK_FE_INTEGRATION.md`의 「기능 기준과 맵 보존 규칙」을 참고한다. 이 작업으로 BE·인프라 소스를 변경하거나 서비스 맵을 배포하지 않았다.

180×180m 공원 맵을 실제 서비스의 `/park`에 적용하려고 합니다. 공원 내부만 이동하고 도로·외곽 건물은 배경으로 사용합니다. 기존 시설 ID·서버 테이블 ID와 Java 이동·충돌 판정을 유지합니다.

FE의 공통 설정, 서버 JSON·버전 생성, 새 맵 화면과 상호작용 연결은 구현했습니다. 최신 `dev`의 BE 생성 맵 로더·실행 선택 코드도 확인했습니다. **BE 로더를 처음부터 다시 구현해 달라는 요청이 아니라, 최신 생성물로 검증하고 실행·배포 환경을 함께 연결해 달라는 요청입니다.**

| 구분 | 현재 확인 상태 |
| --- | --- |
| FE 공통 설정·JSON·버전 생성 | 구현 및 자체 검증 완료 |
| FE 새 맵 `/park` | `park-integration` 모드에서 구현 및 계약 fixture 검증 완료 |
| 기본 FE 빌드 | 여전히 기존 맵 사용. 일반 `pnpm build`만 실행하면 새 맵으로 전환되지 않음 |
| BE 로더·테이블/시설 조립·실행 선택 | 최신 코드에 있음. BE 담당자는 이전 전달본의 로컬 자동 검증 완료를 회신함 |
| 최신 전달본의 BE 검증·실제 접속 환경 | 이번 버전 기준 확인 및 접속 정보 회신 요청 |
| 실제 로그인·Java 물리와 FE 화면 공동 검수 | 미완료 |
| 새 맵 CI·개발/운영 전환 | 담당자 확인 및 연결 필요 |

전달 시에는 **이 문서와 생성물을 포함한 MR의 머지 커밋**을 기준으로 체크아웃해 주세요. 브랜치 이름만으로 이전 전달본과 혼용하지 않습니다. 이 MR의 머지는 기본 서비스 맵을 새 맵으로 전환하는 작업이 아닙니다. 파일로 전달하거나, FE 담당자가 팀에서 합의한 브랜치·MR 절차로 게시한 뒤 정확한 커밋을 공유하겠습니다. 이 문서 자체는 배포 실행 요청이나 브랜치 보호 해제 요청이 아닙니다.

경로는 모두 저장소 루트 기준입니다.

최신 dev 병합 이후 원형 광장·네 방향 테이블·잔디 위 부스·식재·카트 연결길을 변경해 데이터와 맵 버전이 다시 바뀌었습니다. 이번 값은 사용자 확인을 마친 FE 확정 전달본입니다. **이전 직사각형 광장 JSON과 새 FE 번들을 섞으면 안 됩니다.** 이후 재생성하면 해당 파일과 manifest의 실제 값이 기준입니다.

이번 보강에는 분수 진입 경계의 높이 보정도 포함됩니다. 지형 메시의 경계 높이와 맵 버전이 갱신됐으며 기존 시설·테이블·벤치 ID와 좌석·퇴장 좌표는 유지합니다. BE 코드 수정은 수행하지 않았습니다. 서비스 전환 시 위 새 생성 세트로 로딩·접속 검증이 필요합니다.

두 JSON은 같은 생성 세트로 전달하고 원본 바이트를 유지합니다. JSON을 다시 포맷하거나 줄바꿈을 바꾸면 파일 체크섬 검사가 실패할 수 있습니다. 맵 버전은 파일 SHA-256과 다른 값입니다.

광고 제거 반영(2026-10-29): 새 FE 맵의 외곽 광고 화면·프레임과 공원 A형 광고판 3개·에어벌룬을 제거했습니다. 생성 데이터에서도 `advertising-balloon` 시설과 A형 광고판의 2D 장애물 3개를 제거해 facilities 12개·미리보기 장애물 550개가 됐습니다. 게임 테이블·벤치·소리함·메모함·기타 이용/퇴장 좌표 및 3D 물리 데이터는 직전 전달본과 동일합니다. 광고가 없는 이번 버전을 새 manifest와 함께 사용합니다.

## 3. BE 담당자 요청

### 3.1 최신 생성물로 기존 구현 검증

다음 기존 코드에 최신 파일을 연결해 검증 부탁드립니다.

- `backend/src/main/java/com/ssafy/ontop/world/map/GeneratedParkMapLoader.java`
- `backend/src/main/java/com/ssafy/ontop/world/map/PreparedParkMap.java`
- `backend/src/main/java/com/ssafy/ontop/world/map/WorldMapRuntime.java`
- `backend/src/main/java/com/ssafy/ontop/world/config/WorldMapProperties.java`
- `backend/src/main/resources/application.yml`

확인할 계약은 다음과 같습니다.

1. 서버 물리는 `data.physics.boxes/meshes/hulls`를 사용합니다. 여유 폭이 반영된 미리보기용 `data.collision`을 더하지 않습니다. 기존 캐릭터 캡슐·margin 처리를 유지합니다.
2. `table-1`~`table-18`을 모두 실제 게임 테이블로 사용합니다. 기존 16개 매핑은 유지하며, 신규 VR 테이블 `table-17/18`의 실제 서버 ID는 BE에서 발급·추가해주세요. 기존 서버 ID와 명시적 `channelId/tableId/anchorId` 매핑을 유지하고 좌표·맵 버전으로 ID를 다시 만들지 않습니다. 좌석은 테이블 기준 로컬 좌표입니다.
3. 벤치·운동기구·망원경의 생성 ID, 이용/퇴장 Pose·반경·높이 기준을 적용합니다. 소리함 `mailbox`와 익명 메모함 `notes`는 별개입니다.
4. `physics.spawn.position`은 높이를 포함한 캡슐 중심입니다. 시설 use/exit와 notes.reachPosition에 높이 보정을 중복 적용하지 않습니다.
5. 호수 수영, 계단·다리, 전망대 나선 이동, 디딤돌 보조 이동 정보를 같은 세트로 사용합니다. `steppingStones`를 원래 hull 위에 별도 충돌체로 중복 생성하지 않습니다.
6. 관전 허용 거리는 기존 **20m**를 유지합니다.

형식의 상세 설명은 [PARK_BE_HANDOFF.md](PARK_BE_HANDOFF.md), notes·전망대·디딤돌 기준은 [PARK_BACKEND_CONFIRMATION.md](PARK_BACKEND_CONFIRMATION.md)를 참고해 주세요. 과거 문서에 기록된 버전·개발 매핑 상태는 당시 이력이므로 이번 요청서와 실제 생성 파일을 우선합니다.

### 3.2 버전 확인 계약 유지

```text
CONNECTED.payload.map = 서버가 실제 로딩한 identity
  → WORLD_MAP_CONFIRM = FE 번들 자체 identity
  → WORLD_MAP_STATE.payload.map 일치 + verified:true + 요청 ID 일치
  → 채널 입장 / 기존 경기 복구
```

- 오류는 `MAP_VERSION_MISMATCH`·`MAP_VERSION_REQUIRED`, 서버 맵 정보는 `payload.serverMap`을 유지합니다.
- `CHANNEL_JOIN`은 `{channelId}`, `GAME_RECONNECT_CHECK`는 기존 payload를 유지합니다.
- 새 맵은 확인 전 입장·복구를 막고 재접속마다 다시 확인합니다. FE는 새로고침·수동 재접속을 안내합니다.
- 내부 물리 변환에 schemaVersion 1 구조를 쓰더라도 외부 identity는 원본 생성 파일의 **2**입니다.

### 3.3 접속 정보와 검증 결과 회신

다음 내용을 전달 부탁드립니다.

- 최신 전달본 로딩 성공 여부와 실제 `mapId/schemaVersion/mapVersion`.
- 실제 접속 가능한 FE/REST/WS 주소·경로, 로그인 방법·OAuth 콜백과 허용 Origin. 로컬 FE 사용 시 기본 Origin은 `http://localhost:5202`입니다.
- 활성 채널 목록과 채널별 18개 실제 서버 ID 매핑(기존 16개 유지 + 신규 2개 추가). 개발 `channel-1`은 전달된 dev 매핑과 일치하는지 확인 부탁드립니다.
- 최신 파일로 실행한 전달본·물리·WebSocket 테스트 결과. 미실행/스킵 항목도 구분해 주세요.
- 실제 FE와 함께 검수할 수 있는 시점 및 담당자.

테스트용 인증 fixture 통과와 실제 로그인·DB·서비스 실행 성공은 구분합니다. 비밀번호·키를 전달 문서나 채팅에 넣을 필요는 없습니다.

## 4. 인프라 담당자 요청

### 4.1 서버 파일 제공과 실행 환경

현재 `backend/Dockerfile`은 backend 경로로 JAR를 빌드하고, 확인한 `infra/app/compose.dev.yaml`에는 생성 맵 파일 마운트가 없습니다. 파일을 저장소에 추가하는 것만으로 컨테이너에 전달되지 않습니다.

동일 릴리스의 JSON 두 파일을 서버가 읽을 수 있도록 이미지 포함 또는 읽기 전용 볼륨 중 기존 배포 방식에 맞춰 연결 부탁드립니다. 현재 로더는 **파일 시스템 경로**를 받으며 URL/classpath 경로를 받지 않습니다.

예시 서버 환경변수입니다. 경로는 실제 마운트 위치로 확정해 주세요.

```dotenv
WORLD_MAP_SOURCE=generated
WORLD_MAP_JSON_PATH=/opt/ontop/maps/server-map.json
WORLD_MAP_MANIFEST_PATH=/opt/ontop/maps/manifest.json
WORLD_MAP_REQUIRE_MATCH=true
```

- 서버 프로세스 사용자에게 파일 읽기 권한이 있어야 합니다.
- source 기본값은 `legacy`이므로 경로만 지정하면 전환되지 않습니다.
- 파일 누락·체크섬·버전 오류는 시작 실패로 처리하고 구형 맵으로 조용히 대체하지 않습니다.
- 로딩은 서버 시작 시 한 번입니다. 파일만 교체해도 실행 중 충돌·좌표가 갱신되는 구조가 아니며 재시작/재배포가 필요합니다.

### 4.2 FE 빌드와 환경별 매핑

개발 `channel-1` 기준의 새 맵 빌드 예시입니다.

```sh
# frontend 디렉터리, 빌드 환경변수로 설정
VITE_PARK_BINDINGS_URL=/park-bindings.generated.dev.json pnpm build:park
```

- 배포 산출물은 **`frontend/dist-park/`**입니다. 일반 `dist/`와 혼동하지 않도록 빌드 명령·출력 디렉터리를 함께 지정합니다.
- `build:park`는 `park-integration` 모드로 새 장면과 생성 identity를 선택합니다. `pnpm build`는 기존 맵이므로 새 맵 배포 명령으로 사용하지 않습니다.
- `VITE_PARK_BINDINGS_URL`은 빌드 시 적용됩니다. 브라우저 배포 후 서버 환경변수만 바꿔도 번들이 변경되지는 않습니다.
- 새 맵 기본 매핑은 로컬 연동용 두 채널 파일입니다. 실제 개발 환경은 dev 파일을 명시하고 운영은 확정된 운영 채널 매핑을 FE에서 준비한 뒤 선택합니다.
- 매핑 JSON은 정적 파일로 접근 가능해야 하며 SPA HTML로 대체되면 안 됩니다.
- FE REST rewrite·WS 주소·인증 콜백은 실제 새 맵 BE를 향하도록 확인합니다. 기존 코드의 `dev.on-top.world`/`www.on-top.world` WS 호스트 처리를 재사용할 수 있는지 확인하고, 별도 호스트가 필요하면 주소를 먼저 공유해 주세요.
- 화면 갱신 후 구버전 HTML·번들이 계속 제공되지 않는지 확인합니다. 오래된 FE는 버전 오류 안내로 차단되어야 합니다.

### 4.3 CI 검사와 전달본 테스트

현재 체크아웃에는 루트 `.gitlab-ci.yml`이 없어 공용 파이프라인의 실제 위치·외부 include·배포 프로젝트 설정은 확인하지 못했습니다. 담당자가 사용 중인 설정 위치와 변경 범위를 먼저 확인해 주세요.

요청할 검사 순서는 다음과 같습니다.

1. 동일 커밋을 체크아웃하고 FE 의존성을 잠금 파일 기준으로 설치합니다. 현재 FE 요구 버전은 Node 24, pnpm 11.25.0입니다.
2. `frontend`에서 **`pnpm map:check`를 build보다 먼저** 실행합니다. build는 자동 생성하므로 순서를 바꾸면 오래된 커밋 생성물을 가릴 수 있습니다.
3. FE 타입·단위 검사와 새 맵 빌드를 실행하고 JSON·manifest·FE 빌드·매핑을 같은 릴리스 아티팩트로 묶습니다.
4. BE 테스트용 폴더에 아래 네 파일을 준비하고 `TEST_GENERATED_MAP_DIR`에 그 폴더의 절대 경로를 지정합니다.

```text
server-map.json
manifest.json
park-bindings.dev.json
park-bindings.frontend-test.json
```

5. 기존 전체 BE 검사에 더해 다음 전달본 검사를 필수로 실행합니다. 현재 일부 테스트는 해당 환경변수가 없으면 스킵되므로 **환경변수 미지정·테스트 스킵을 성공으로 처리하지 않도록** 확인해 주세요.

```text
GeneratedParkMapHandoffTests
PreparedParkMapHandoffTests
PreparedParkMovementTests
PreparedParkSocketTests
GeneratedWorldMapRuntimeTests
WorldMapSelectionWebSocketTests
```

6. 공통 소스·참조 설정·생성물·BE 로더 변경이 검사에서 빠지지 않도록 변경 감지 규칙을 연결합니다. `manifest.sources`가 실제 입력 목록의 기준입니다.
7. 이미지 빌드·배포에서 같은 검증 파일이 사용됐는지 확인합니다. 현재 Dockerfile의 `bootJar -x test`는 별도 CI 테스트 단계를 대신하지 못합니다.

CI와 Docker·Compose는 이번 FE 작업에서 수정하지 않았습니다. 기존 인프라 검토·배포 절차에 맞춰 담당자 쪽에서 진행 부탁드립니다.

## 5. FE 담당자가 남겨 둔 작업

FE의 **구현·자체 검증은 완료**, 실제 서비스 전환까지 모두 끝난 상태는 아닙니다.

| 남은 FE 작업 | 진행 조건 |
| --- | --- |
| 전달본 게시 및 정확한 커밋 공유 | 팀의 브랜치 보호·MR 절차 합의 |
| 실제 환경의 채널 매핑·REST/WS·로그인 설정 확정 | BE·인프라 접속 정보 수령 |
| 새 맵 빌드 선택 또는 기본 서비스 모드 전환 | BE와 같은 생성 세트·동시 전환 일정 확정 |
| 실제 서버와 좌석·시설·충돌·수영·재접속 검수 및 발견된 FE 문제 수정 | 새 맵 BE 접속 환경 준비 |
| preview/pending 메타데이터의 출시 표기 정리 | 공동 검증 완료 및 최종 릴리스 확정 |

현재 `metadata.stage: preview`, `semantics.scope: park-preview`, manifest의 `backendIntegration: pending`은 의도적으로 유지했습니다. 출시 표기를 변경하면 재생성으로 버전이 달라질 수 있으므로 **표기 정리 후 최종 JSON·FE 버전을 다시 맞춰야 합니다.** 검증 전 완료 표기만 먼저 바꾸지 않습니다.

배치 미리보기의 점프맵 체험·HUD는 서비스 게임 기능으로 이관된 범위가 아닙니다. 이를 `/park`의 실제 게임으로 제공하려면 별도 FE·BE 기획/연동 작업이 필요합니다. 메인 광장의 추가 디자인 수정도 후속 범위입니다.

2026-10-28 자체 검증 이력: 앱·테스트 타입 검사, 생성물 일치 검사, 단위 93개 파일·881개 테스트, 기본/새 맵 빌드, 새 맵 브라우저 3개·기본 맵 회귀 브라우저 10개 통과. 브라우저 검사는 테스트 REST/WS fixture를 사용했으며 실제 BE 물리·로그인 공동 검증 결과가 아닙니다.

## 6. 공동 전환 순서와 완료 기준

1. **전달본 고정:** FE가 최신 커밋·JSON 세트·매핑을 공유하고 BE가 동일 identity 로딩을 확인합니다.
2. **접속 환경 준비:** BE·인프라가 새 맵 실행 주소·인증·채널·파일 공급·빌드 선택을 맞춥니다.
3. **기준 배치 공동 검수:** 실제 로그인 후 공원 경계·스폰 높이, 길/울타리/계단, 양쪽 호수 횡단·수영·낚시 구역, 전망대 정상·메모함, 18개 테이블 좌석, 벤치·운동기구·망원경 이용/퇴장, 관전 20m, 따라가기·게임 복구를 확인합니다.
4. **작은 변경 검수:** 별도 검증용 변경에서 테이블 하나와 장애물 하나만 이동합니다. 재생성 → 양쪽 재빌드 → BE 재시작 후 화면·좌석·충돌·관전 기준점·버전이 함께 바뀌는지 확인합니다. ID와 관전 반경 20m는 유지합니다.
5. **확정 배치 복원:** 임시 이동을 원복하고 다시 생성·검사합니다. 출시 메타데이터와 매핑을 확정한 뒤 최종 파일 세트를 다시 고정합니다.
6. **같은 릴리스로 전환:** 인프라 담당자가 FE·BE 전환을 조율합니다. 배포 시간차의 구버전 접속 차단과 새로고침·재접속을 확인합니다.
7. **복구 준비:** 문제 시 직전 FE 빌드·BE 이미지·맵 JSON/manifest·채널 매핑·환경 설정을 호환되는 세트로 되돌립니다. 구형 JSON만 단독 교체하지 않습니다.

완료는 동일 버전의 실제 FE 화면과 실제 Java 판정이 함께 검증되고, CI·파일 공급·재배포 절차가 연결됐을 때로 판단합니다. 이후에도 설정 저장만으로 실행 중 BE 좌표가 즉시 바뀌지는 않습니다. **공통 설정 수정 → 생성 → 검사 → 양쪽 빌드·배포/BE 재시작**까지가 자동화 연결의 전체 흐름입니다.

## 8. 함께 보낼 채팅 문구

> 새 공원 맵 전환 요청서를 전달드립니다. FE는 공통 설정·서버 JSON 생성·버전 확인·새 맵 모드 연결과 자체 검증까지 완료했습니다. 최신 dev에 있는 BE 로더·실행 선택 코드를 기준으로, 이번 JSON/manifest의 로딩 검증과 실제 접속 환경 준비를 부탁드립니다. 테이블 18개·기존 서버 ID·Java 판정·관전 20m·WORLD_MAP_CONFIRM 계약은 유지합니다. 인프라 쪽에서는 동일 생성물의 파일 공급, CI 검사, FE build:park/dist-park 선택, BE generated 실행 및 동시 전환·복구 절차 연결을 부탁드립니다. 최신 로컬 커밋과 생성 버전은 문서에 적었으며, 원격 게시 경로를 확정해 공유하겠습니다. 실제 서버 공동 검수 후 최종 버전을 고정하고 함께 전환하면 됩니다. 문서 마지막 회신 양식에 맞춰 담당 범위와 준비 시점을 알려주시면 FE의 환경 설정·공동 검수를 이어가겠습니다.

추가 배치 보정: 소리함 좌표 (-18, 18)는 유지하고 나무의 본체·이용 공간 침범을 제거했습니다. 북동쪽 table-15 세트는 (48, -72)에서 (48, -70.5)로 남쪽 1.5m 옮겼습니다. 테이블 ID·로컬 좌석 오프셋은 유지하며, 생성된 테이블 위치·물리 프록시·맵 버전은 함께 갱신했습니다. BE는 위 최신 생성물과 기존 매핑 파일을 사용해야 합니다.
