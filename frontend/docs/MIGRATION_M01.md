# M01 — 공통 E 상호작용·벤치 분리

2026-10-24. M00 커밋 `f61f496` 위에 M01만 추가한다. 기준 GitLab dev는 `69a9d19`이며 원본 작업본의 미커밋 변경은 그대로 보존한다. 같은 브랜치에 단계를 쌓고 이번에는 병합·배포하지 않는다.

## 포함한 기능

- 벤치·테이블을 거리·높이·시선으로 선정한다. 화면 E 안내와 E/버튼 실행이 같은 선정 함수를 사용한다.
- 기존 맵 벤치 ID·방향·두 좌석·높이·접근 범위·하차 앵커를 FE 내부 데이터로 정의한다. 맵·에셋은 바꾸지 않는다.
- 벤치 승인 대기·중복 방지·거절 안내·일어서기를 처리한다. 승인 전에 착석 표시를 바꾸지 않는다.
- 승인 이후에도 실제 서버 위치·채널·사용자·맵·경기 상태를 다시 검사한다. 단절·이탈·월드 사용자 삭제 시 요청과 점유를 취소한다.
- 착석 위치를 표시용으로 합성하고 실제 서버 위치는 보존한다. 착석 중 월드 스냅샷이 와도 표시를 유지하고, 하차하면 최신 서버 위치를 사용한다.
- 본인 착석은 1인칭으로 표시하고 본인 모델만 숨긴다. 원격 모델에는 기존 앉는 자세를 재사용한다. 하차·퇴장 시 카메라 설정을 복원한다.
- 이동키로 하차하고 승인 후 이동을 재개한다. 채팅·텍스트창·대화창 입력, blur·탭 전환·컴포넌트 해제 시 입력을 정리한다. 향후 패널용 입력 소유권 플래그만 제공한다.
- 벤치 이용/대기 중 테이블 입장·채널 변경·일반 이동을 차단한다. 기존 이동 정지 메시지는 허용한다.

## 실제 BE와 목업의 경계

기존 로그인·OAuth·세션 복원·채널·이동·채팅·테이블·오목의 HTTP/RawWS 연결은 유지한다. 별도 가짜 입장 화면·계정·잔액·공원 대체 런타임을 추가하지 않는다.

최신 dev의 `backend/src/main/java/com/ssafy/ontop/table/dto/TableProtocol.java`와 `table/service/TableHub.java`에는 벤치 착석·반납 명령이 없다. 따라서 `BenchService`는 FE 내부 인터페이스로 두고, `import.meta.env.DEV`에서만 `MockBenchService`를 사용한다. 운영 빌드에서는 미연결 어댑터를 사용하고 벤치 이용 버튼을 비활성화한다. 목업 클래스·식별자가 운영 산출물에 없는지 `check:migration`으로 검사한다.

목업 점유는 현재 탭의 메모리에만 있다. 다른 실제 사용자와의 점유 동기화·서버 근접 재검사·안전 하차 위치로의 서버 이동은 아직 검증하거나 구현하지 않았다. 브라우저 테스트의 원격 착석은 테스트 전용 대역이다.

BE 연결 시 확정할 계약은 채널/벤치/좌석 ID, 원자적 점유·반납, 근접/높이 검사, 승인 위치와 하차 위치, 공개 점유 스냅샷·변경·삭제, 단절 정리·오류·재시도 규칙이다. REST 경로·WS 명령·DTO를 FE에서 임의로 만들지 않았다.

## 제외한 변경

M02 이동 버퍼·보간·카메라 충돌, M03 리그·보행 모션, M04 G 휠·감정표현, M05 운동기구, M06 망원경, M07 소리함과 그 목업은 포함하지 않는다. 기존 코드에 이미 있던 표시 필드·정적 모델은 유지한다.

인증/API 오류 처리 개선·지갑·미니게임·로컬 플레이·맵 버전·맵 생성·백엔드·인프라·Vite 설정·의존성·잠금파일도 변경하지 않는다. `world/input.ts`의 이동 방향 계산과 60ms 전송 주기, `worldClient.ts`의 보간 함수는 M00 상태를 유지한다.

## 실행·검증

```sh
pnpm dev:facilities
pnpm typecheck:tests
pnpm test
pnpm build
pnpm check:migration
pnpm exec playwright test tests/e2e/m01.spec.ts tests/e2e/park.spec.ts tests/e2e/omok.spec.ts
```

`dev:facilities`는 기존 로그인·BE 연결을 사용하는 Vite 개발 모드다. 실제 입장에는 기존 BE/OAuth 설정이 필요하다. 기존 `pnpm dev`에서도 개발 벤치 목업을 사용할 수 있다.

Browser plugin not available. 저장소의 Playwright/Edge와 테스트 전용 HTTP/WS 응답을 사용하고, 기존 실행 서버와 격리한 `127.0.0.1:5198`에서 검증한다. 테스트는 운영 코드에 없는 별도 벤치 WS 명령이 전송되지 않는지 확인한다. 화면 증빙은 저장소 외부 QA 폴더에 둔다.
