## 구현한 동작

이미지 한 장을 배경으로 놓은 화면이 아니다. 가구·음식·꼬치·식기·전달대·VR 주문판/조작판을 실제 Three.js geometry로 구성했다. 음식 조합 그림은 같은 FoodModels를 렌더한 이미지여서 조립 결과와 주문 재료가 대응한다.

- PC: 현재 배치 기준 숫자 1–6 또는 재료 트레이 클릭으로 선택, Space/꼬치 끝 클릭으로 꽂기, Backspace로 끝 재료 제거, R로 완성·전달대 제출.
- 주문표는 앞의 두 장만 공개한다. 선택한 주문의 테이블 번호와 실제 조합을 판정한다. 독립된 음식 조각의 종류·개수·순서와 전체 반대 방향 정답을 판정한다.
- 제출 실패 시 조립 상태를 유지한다. 성공 시 테이블 번호가 달린 실제 완성 접시를 전달대에 추가하고 해당 작업을 제거한 뒤 다음 앞면 주문을 공개한다.
- 전달대 용량 2개. 가득 차면 조립 결과를 보존하며 제출을 거절한다. 프리뷰 안내창의 ‘서빙 담당 수령 (샘플)’으로 하나씩 비울 수 있다.
- 처음은 샘플 전달 주문 4개(01,04 공개 / 뒤 2개 비공개). 안내창에서 주문 없는 상태 → 샘플 주문 받기로 전환할 수 있다. 미전달 상태에서는 조립이 차단되고 요구 그림을 표시하지 않는다.

## VR 코드와 검증 경계

‘VR 시점’은 일반 브라우저에서도 확인할 수 있는 1인칭 카메라다. 이것을 실제 헤드셋 세션이라고 표시하지 않는다. 지원 여부를 확인하고 미연결 상태를 명시하며, 지원 기기에서만 VR 시작 버튼이 활성화된다.

실제 WebXR 입력 경로:

1. 보안 컨텍스트에서 사용자 클릭으로 `immersive-vr` 세션 요청, `local-floor` 기준 사용.
2. 실제 target-ray/grip 추적에 컨트롤러 모델을 연결. 트리거로 재료를 ray-pick해 잡고, 꼬치 끝에서 방향/거리 조건을 만족할 때 놓으면 삽입한다.
3. 그립으로 꼬치를 잡고, 놓으면 조리대 받침으로 복귀. 주문표 선택/끝 재료 제거/완성 접시 제출은 공간 조작판을 ray-pick한다.
4. 실제 XR에서는 데스크톱용 AO/postprocessing 대신 직접 렌더한다. 컨트롤러/카메라는 실제 미터 좌표를 사용하고 주방은 별도 그룹에서 스케일링한다. 상판 높이 약 1m, 꼬치 약 1m, 레이로 잡은 손에 손잡이를 붙여 과도하게 먼 오프셋을 없앴다.
5. 세션 종료/요청 실패/컴포넌트 해제 시 세션과 들고 있던 물체/카메라/주방 스케일/이벤트 리스너를 정리한다.

**Quest 2가 연결되지 않아 위 하드웨어 경로의 실제 포즈·삽입 감도·그립·세션 재진입·프레임 성능은 미검증이다.** 브라우저 VR 카메라 확인, 삽입 거리/방향 수식 단위 테스트, 타입/빌드 성공을 실기기 성공과 혼동하지 않는다. 별도 WebXR 가상 하드웨어 테스트로 보장했다고 주장하지 않는다.

기기 테스트 시 이 프리뷰는 localhost 또는 정상 HTTPS로 접근해야 한다. 사용자 PC에 adb가 준비되고 Quest USB 디버깅이 승인된 경우 포트 5240을 reverse하고 Quest 브라우저에서 localhost:5240으로 접속하는 기존 방식을 사용할 수 있다. 이번 작업에서는 기기 연결이나 adb 조작을 실행하지 않았다.
