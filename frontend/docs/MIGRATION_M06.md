# M06 — 전망대 망원경 이용·접안 표시 분리

2026-10-24. M05 `31556f6` 위에 M06 프론트 변경만 추가한다. 원격 dev는 M00~M04가 머지된 `635ab92`이며 M05와 M06은 같은 작업 브랜치에 독립 커밋으로 쌓는다. 원본 작업본의 변경 파일 144개를 보존하고, 이번 단계에서 dev 머지·배포·M07 진행은 하지 않는다.

## 이용·카메라·입력

- 기존 두 망원경 ID·정상 배치·충돌체·모델과 아바타 자세를 재사용한다. 같은 높이·2m 이내의 공통 E 선택으로 접근하며 지상의 같은 x/z에서는 이용하지 못한다.
- 승인 전에는 대기와 중복 방지를 표시한다. 승인 후 세션·채널·맵·다른 시설 상태와 실제 서버 접근 위치를 다시 검사한다.
- 승인 뒤 접안 카메라와 화면 중심의 원형 뷰파인더를 표시한다. 본인 아바타/본인 이용 기구만 숨기고 원격 이용자는 승인 방향과 전신으로 표시한다.
- 드래그로 조준하고 휠/버튼으로 2~8배 확대한다. 기본은 3배이며 확대/FOV는 로컬 값이다. 카메라는 즉시 반응하고 표시 모델의 yaw/pitch는 서비스 승인을 따른다. 방향은 최대 100ms 간격으로 요청하고 동시/미변경 요청을 막는다.
- 이용/대기 중 이동·점프·다른 시설과 경기 입장을 제한한다. 기존 채팅과 정지 의도는 유지한다. E/Esc/버튼의 반납 승인 뒤 기존 로밍 방향·거리·피치·FOV와 실제 서버 접근 위치로 복귀한다.
- 단절·채널/맵 변경·본인 제거에서 요청·점유·뷰 상태를 정리한다. 늦은 방향 응답은 이용을 복구하지 못하고, 반납 실패는 점유·카메라를 유지하며 재시도한다. 카메라 언마운트에서도 저장 FOV와 시점을 복구한다.
- 이용 중 F1/버튼으로 망원경 조작 설명을 연다. 설명서에서는 조준·휠·E가 새지 않으며 Esc/F1은 설명서만 닫는다. 기존 채팅·map/manual/emote/minigame 입력 소유권을 유지한다. 전체 설명서 호스트를 추가하는 작업은 아니다.

## 실제 BE와 목업 경계

기준 Java 소스와 기존 메시지 처리에는 망원경 이용·반납·방향 동기화 API가 없다. 정적 배치·전망대 물리는 이용 API로 간주하지 않는다. `TelescopeService`·`TelescopeLease`는 FE 내부 포트이며 Spring 경로·WS 명령·wire DTO를 임의로 추가하지 않는다.

`DEV && MODE === facility-preview`에서만 `MockTelescopeService`를 사용한다. `pnpm dev:facilities`도 기존 로그인·실제 월드 연결이 필요하다. 일반 개발/운영에서는 미연결 안내와 비활성 버튼을 표시하고 `check:migration`으로 운영 산출물의 목업 구현 제외를 확인한다.

목업은 현재 페이지 메모리에서 채널/기구별 독립 점유·동시 요청 거절·소유 검증·승인 방향·반납/취소를 처리한다. 실제 두 계정 간 점유·방향 방송, 서버 동시성·재접속 복구를 제공하지 않는다. 확대는 서비스 payload로 보내지 않으며 사용료·보상·지갑 지급도 추가하지 않는다.

승인 위치는 표시 아바타에만 합성한다. 실제 `authoritativePose`와 기존 `WORLD_MOVE {seq,dx,dz,run,jump}`는 유지하고 이용/대기 중에는 정지 의도만 보낸다. 반납 시 실제 서버의 최신 접근 위치로 복원한다. 출구 앵커로 서버 사용자를 클라이언트가 순간이동시키지 않는다.

BE 연결에는 채널/기구별 원자적 소유권, 정상 높이·근접·다른 시설/경기 상태 검사, 승인/취소/늦은 응답 상관관계, 소유자만 방향 변경·반납, 승인 yaw/pitch 범위·빈도·순서, 단절 해제와 안전 하차 위치 정책이 필요하다.

## 다른 작업과의 분리

M07 소리함 상태·서비스·패널·입력과 지갑·인증/API 오류·미니게임·로컬 플레이는 가져오지 않는다. M05 운동기구 모델/리그/손잡이·설정·기존 이용 흐름도 그대로이며, 망원경과의 중복 이용 방지 훅만 추가한다.

M02 본인 제거 시 입력 차단, 이동 형식/주기/보간과 M04 감정표현 매핑·손 인사/박수 목업 금지·서버 거절 처리를 유지한다. 기존 로그인·HTTP/RawWS·테이블·오목·벤치를 망원경 중복 방지 훅 이외에는 변경하지 않는다.

백엔드·인프라·맵/버전·모델/텍스처·의존성/잠금파일·Vite·실제 배포 JSON은 수정하지 않는다. 기존 `telescopeView`·배치/방향/FOV 설정은 그대로 사용한다. 정밀 접안 자세, FPS/GPU/메모리 성능 비교와 전체 모바일 HUD 재배치는 이번 범위에 포함하지 않는다.

## 검증

```sh
pnpm typecheck:tests
pnpm test
pnpm build
pnpm check:migration
pnpm test:e2e:facilities
pnpm exec playwright test tests/e2e/park.spec.ts tests/e2e/omok.spec.ts tests/e2e/fitness-boundary.spec.ts tests/e2e/telescope-boundary.spec.ts
```

Browser plugin not available. 기존 Playwright/Edge와 테스트 전용 HTTP/RawWS 계약 대역을 사용한다. 기존 실행 서버를 유지하고 facility-preview는 `127.0.0.1:5196`, 일반 모드 회귀는 별도 QA 설정의 `127.0.0.1:5198`에서 실행한다. 화면은 저장소 밖 `m06-isolated/`에 저장한다.

검수 흐름은 기존 로그인/공원 → 지상 진입 거부 → 정상 E 이용 → 드래그·확대 → F1 입력 차단/닫기 → E/Esc/버튼 반납 → 카메라/FOV·이동 복원 → 원격 방향·두 기구 독립 점유 → 단절/퇴장 정리다. 데스크톱 1920×1080과 조작부 390×844를 검사하며 일반 모드의 미연결 비활성화와 기존 공원·오목도 회귀 검증한다.

이 검증은 페이지 내부 목업·FE 계약 대역 검사다. 실제 Java 서버의 다중 사용자 점유·방향 방송·출구 물리·개발 서버 배포 완료를 뜻하지 않는다. 기존 Three.Clock/ANGLE·큰 3D 청크 경고는 남아 있다.
