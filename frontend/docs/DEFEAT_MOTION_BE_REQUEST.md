# 기권·패배 연출 WS 연동 요청

작성일: 2026-10-26 · 확인 기준 dev: `2310dae` · FE 브랜치: `feat/frontend-defeat-motion`

안녕하세요. 기권·패배 연출의 FE 작업은 완료했고, 모든 대상 화면에서 서버 확정 기준으로 같은 연출을 보여주기 위해 BE 연동을 요청드립니다. 이전에 답변 주신 정책을 기준으로 문제점, FE 완료 내용, BE 요청 사항을 정리했습니다.

## 1. 기존에 어떤 문제가 있었는지

현재 FE는 전달받은 경기 상태의 이전 값과 다음 값을 비교해서 기권·패배 모션을 재생합니다. 이 방식에는 다음 한계가 있습니다.

- 해당 경기를 구독하지 않는 주변 사용자는 경기 상태를 받지 못해 같은 패배 연출을 볼 수 없습니다.
- 중간 상태를 놓치면 기권·패배 직전의 잔여 참가자 수를 정확히 확인하기 어렵습니다. FE는 잘못된 판 엎기를 방지하기 위해 이때 연출을 생략하고 있습니다.
- 다인전 중도 기권에는 현재 공개 상태만으로 확정 시각을 알 수 없어 화면별 수신 시각으로 재생합니다. 여러 사용자 화면의 재생 시점을 정확히 맞추려면 서버의 사건 식별 정보와 확정 시각이 필요합니다.

따라서 서버가 기권·패배를 확정한 시점에 연출 전용 WS 이벤트를 전달하는 방식이 필요합니다.

별도로 결과 화면의 큰 3D 결과판이 테이블과 캐릭터를 가리던 문제는 FE에서 해결했습니다.

## 2. FE에서 완료한 작업

- 남녀 캐릭터 모두 양손으로 머리를 감싼 뒤 원래 착석 자세로 돌아오는 패배 모션을 제작했습니다.
- **기권·패배 직전 잔여 참가자가 2명이면 판 엎기, 그 외에는 머리 감싸기**로 분기했습니다. 시작 인원이 4명이더라도 2명만 남은 상태라면 판 엎기 대상입니다.
- 기존 경기 상태를 받은 참가자·공개 관전자 화면에 연출을 연결하고 중복 재생과 이동·퇴장 후 재생을 방지했습니다.
- 테이블 위 3D 결과판을 제거하고 결과를 화면 가장자리와 상세 화면에서 확인하도록 바꿨습니다. 정산 확인·다음 판 준비·기존 카메라는 유지했습니다.
- 최신 dev의 무효 경기·정산 복구 처리를 유지하고, 무효 결과에서 패배 연출이 나오지 않는 것을 검증했습니다.

FE 변경만 진행했으며 BE 소스·DB·배포 설정을 직접 수정하지 않았습니다.

## 3. BE 담당자에게 부탁드리는 작업

아래는 이전 답변으로 합의한 연출 WS 정책입니다. 해당 방향으로 구현·검증을 진행 부탁드립니다.

1. **서버 확정 시점에 연출용 WS 이벤트를 생성해주세요.** 사건 ID, 경기·테이블·채널 ID, 대상 사용자, 기권/패배 구분, 직전 잔여 참가자 수, 확정 시각을 전달해주세요. 실제 이벤트명과 필드명·타입은 BE 명세에 맞춰 FE에서 연결하겠습니다.
2. **참가자·관전자와 같은 채널의 테이블 주변 20m 사용자에게 전달해주세요.** 주변 사용자가 해당 경기를 구독하지 않아도 수신할 수 있어야 합니다. 비공개 손패·주사위·개인 정산 정보는 포함하지 않습니다.
3. **다리는 `pendingForfeit` 최초 확정을 기준으로 처리해주세요.** 이후 실제 말 제거 때 같은 기권을 새 사건으로 다시 만들지 않도록 부탁드립니다.
4. **같은 사건에는 동일한 사건 ID를 유지하고, 재접속·신규 관전에는 과거 연출을 재전송하지 않는 정책을 적용해주세요.** FE는 사건 ID로 중복 재생을 막겠습니다. 무효/중단 경기의 연출 대상 여부도 명세에서 확인할 수 있게 부탁드립니다.

구현·검증 완료 후 아래 자료를 공유해주세요.

- 이벤트 이름과 메시지 구조, 필드명·타입·열거값·시각 형식이 포함된 명세
- 1대1 기권, 다인전 중도 기권, 일반 패배의 실제 JSON 예시 — 다인전에서 2명만 남은 경우 포함
- 적용 브랜치/커밋, 배포 완료 여부, FE가 실제 계정으로 연결할 수 있는 개발 환경
- 참가자·관전자·주변 20m 전달, 중복 처리, 과거 사건 미재전송 검증 결과

## 4. BE 작업 이후 FE가 진행할 작업

자료를 받으면 현재 경기 상태 비교 방식에서 **서버 확정 이벤트 기반 재생**으로 전환하겠습니다. 기존 WS 수신 경로를 사용하고, 두 방식이 동시에 동작해 중복 재생되지 않도록 정리하겠습니다.

이후 사건 ID로 중복을 막고 확정 시각으로 재생을 맞추며, 비구독 주변 사용자에게도 같은 모션이 보이도록 연결하겠습니다. 마지막으로 실제 계정에서 1대1·다인전·다인전→2인, 다리 기권 예정, 참가자·관전자·주변 사용자, 재접속·중복 수신을 함께 검증하겠습니다.

**지금 다음 단계는 BE의 연출 WS 구현·검증과 명세·JSON 예시·연동 환경 공유입니다. FE는 해당 자료를 받은 뒤 이벤트 연결과 실제 서버 검증을 진행하면 됩니다.**

## 5. 현재 FE 검증 결과

- 단위 검사 57개 파일·564개 통과, 타입 검사·이관 경계 검사·프로덕션 빌드 통과.
- Edge 브라우저 회귀 18개 통과: 패배 모션 9개, 4종 게임 결과 4개, 무효 결과·정산 복구 1개, 팔각정 1280×720·1000×700 결과 조작 2개, 기존 옷장 2개.
- 검증은 HTTP/RawWS 계약 fixture 기반입니다. 실제 BE 연출 WS와 여러 실제 계정의 통합 검증은 위 자료 수령 후 진행합니다.
- 이전에 후속 작업으로 안내했던 기권·주사위 E2E 참가비 입력 보완은 최신 dev에서 완료됐습니다.

## 채팅 전달용 요약

> 현재 FE는 경기 상태를 비교해 패배 연출을 재생하고 있어, 비구독 주변 사용자에게 연출을 보여주거나 중간 상태 누락 시 직전 잔여 인원·확정 시각을 정확히 맞추는 데 한계가 있습니다. FE에서는 남녀 머리 감싸기 모션, 잔여 2명일 때 판 엎기 분기, 참가자·관전자 화면 연결과 결과판 가림 문제를 해결했습니다.
>
> BE에서는 합의한 서버 확정 연출 WS 이벤트를 구현·검증 부탁드립니다. 사건 ID·경기/테이블/채널 ID·대상자·기권/패배 구분·직전 잔여 인원·확정 시각을 담아 참가자·관전자와 같은 채널의 테이블 주변 20m 사용자에게 전달해주세요. 다리는 pendingForfeit 최초 확정을 기준으로 하고, 과거 사건 미재전송과 동일 사건 ID 유지 정책도 적용 부탁드립니다.
>
> 완료 후 명세·실제 JSON 예시·적용 커밋과 배포 환경을 공유해주시면, FE에서 서버 이벤트 기반 재생·중복 방지·시각 동기화를 연결하고 실제 계정으로 함께 검증하겠습니다.
