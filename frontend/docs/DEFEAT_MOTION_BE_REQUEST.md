# 패배 연출·결과 화면 — FE 현황 및 BE 연동 인계

기준: 2026-10-26, 최신 dev `2310dae`, 작업 브랜치 `feat/frontend-defeat-motion`.

**FE 모션·결과 화면은 구현되어 있다. 다음 연동은 BE가 합의한 연출용 WS 이벤트를 구현·검증한 뒤 명세·JSON 예시·접속 가능한 환경을 공유받아 진행한다. 확인한 최신 dev에서는 해당 연출 WS 명세·구현을 확인하지 못했으며 실제 배포 여부도 검증하지 않았다.**

## 현재 FE에서 완료한 내용

- 남녀 캐릭터의 3.6초 머리 감싸기: 양손 올리기 → 머리 숙이기 → 원래 착석 자세로 복귀.
- 시작 인원과 관계없이 기권·패배 확정 직전 잔여 참가자가 2명이면 기존 2.8초 판 엎기, 그 외에는 머리 감싸기.
- 서버가 승인한 연속 경기 상태에서 새 패배자를 확인해 한 번 재생. 요청/승인 영수증만으로 승패를 추정하지 않는다.
- 초기 관전·재접속의 과거 결과와 누락 버전 사이는 재생하지 않는다. 현재 재생 범위는 해당 경기 참가자·공개 관전자이다.
- 이동·퇴장·채널 변경·연결 종료·관전 종료 시 취소. 기존 카메라와 착석 하체를 유지한다.
- 테이블 위 3D 결과판을 제거하고 화면 가장자리 HUD와 결과 상세를 사용. 결과 버튼·채팅·빠른 메뉴의 겹침을 보완했다.

새 소켓·일반 감정표현 명령·모델 자산·의존성은 추가하지 않았다. 승패·게임 입력·지갑·정산을 변경하지 않는다.

## 최신 dev에서 확인한 변경

- 경기 이탈·무효 반환·결과 재전달/복구와 관련 FE 표시가 dev에 반영되어 있다. 저장된 서버 결과를 우선 표시하고 무효 경기를 승리/무승부로 추정하지 않는 처리를 유지했다.
- 이전에 후속 작업으로 안내했던 기권·주사위 E2E의 참가비 입력 보완은 이미 dev에 반영됐다. 같은 수정을 다시 진행할 필요가 없다.
- 추가된 REST/WS API 명세 보완(`2310dae`)도 그대로 반영했다. 이 추가분에는 FE 변경이 없으며, 합의한 패배 연출 WS의 구현·명세는 아직 확인되지 않았다.
- `tests/unit/tableGathering.test.ts`에서 3D 결과판 UV 테스트 제거와 dev의 새 무효/정산 테스트가 충돌했다. 새 정산 테스트와 필요한 fixture import를 유지하고, 제거된 3D 결과판의 import만 제외했다.
- 자동 병합된 무효 경기 E2E도 결과판이 생성되지 않는 기대값으로 맞추고, 무효 결과에서 패배 모션이 발생하지 않음을 확인한다.
- 이번 충돌 해결·문서 갱신은 FE 범위이며 BE 코드는 최신 dev 그대로 반영한다.

## BE 답변으로 확정된 사항

1. 서버 확정 연출용 WS 이벤트에 사건 ID, 경기·테이블·채널 ID, 대상자, 기권/패배 구분, 직전 잔여 참가자 수, 확정 시각을 담는다.
2. 경기 참가자·관전자와 같은 채널의 테이블 주변 20m 사용자에게 전달하고, 비공개 게임 정보는 제외한다.
3. 다리는 `pendingForfeit` 최초 확정을 연출 기준 시점으로 사용한다. 이후 실제 말 제거 시 같은 기권을 다시 재생하지 않는다.
4. 재접속·신규 관전에는 과거 연출을 재전송하지 않는다. 같은 사건은 중복 재생하지 않는다.

위 정책은 합의됐다. 아래 항목은 구현·배포 완료 후 FE 연결을 위해 받을 자료다. 새 필드명·이벤트명·운영 계약을 FE에서 임의로 정하지 않는다.

## BE에 지금 요청할 자료

- 구현·검증 완료 후 **이벤트 이름, 메시지 구조, 정확한 필드명·타입·열거값·시각 형식**이 포함된 명세를 공유해주세요.
- 1대1 기권, 다인전 중도 기권, 일반 패배의 실제 JSON 예시를 공유해주세요. 다인전에서 2명만 남은 사례도 포함하면 FE 분기를 확인할 수 있습니다.
- 적용 브랜치/커밋, 배포 완료 여부, 연동 가능한 개발 환경과 적용된 맵/테이블 연결 정보를 알려주세요.
- 참가자·관전자·주변 20m 수신과 중복 방지·과거 사건 미재전송 검증 결과를 공유해주세요. 무효/중단 경기는 패배로 연출하지 않는 경계도 명세에 밝혀주세요.

## 자료를 받은 뒤 FE가 진행할 순서

1. 기존 단일 WS 수신 경로에 명세대로 이벤트를 연결하고 채널·테이블·대상자·시각을 검증한다.
2. 현재 `GAME_STATE` 비교로 재생하는 경로를 서버 확정 이벤트 기반으로 전환해 이중 재생을 막는다.
3. 사건 ID로 중복을 막고 서버 확정 시각으로 모션을 맞춘다. 직전 잔여 인원 2명은 판 엎기, 그 외에는 머리 감싸기를 적용한다.
4. 경기 비구독 주변 사용자도 모션을 볼 수 있게 연결한다. 재접속·관전 진입의 과거 사건은 재생하지 않는다.
5. 실제 계정으로 참가자·관전자·주변 사용자, 1대1/다인전/다인전→2인, 다리 기권 예정, 중복·지연·연결 종료를 함께 검증한다.

명세를 받기 전에는 이벤트 이름·JSON을 추측해 연결하지 않는다. 최신 dev의 참가비 E2E 보완은 완료되어 추가 대기 작업으로 제안하지 않는다.

## 검증

- 최신 dev 반영 및 FE 충돌 해결 후 `pnpm test`: 57개 파일, 564개 단위 검사 통과.
- 위 검사 이후 반영한 API 명세 보완에는 FE 변경이 없어 검증한 FE 소스는 동일하다.
- `pnpm typecheck:tests`, `pnpm check:migration`, `pnpm build` 통과.
- Edge 브라우저 회귀 18개 통과: 패배 모션 9개, 4종 게임 결과 4개, 무효 결과 우선 표시·정산 복구 1개, 팔각정 1280×720·1000×700 결과 조작 2개, 기존 옷장 2개. 페이지·화면·콘솔 오류·조작을 확인했다.
- `git diff --check` 통과. 충돌 파일은 모두 해소했으며 최신 dev 대비 이번 변경은 `frontend/` 아래에만 있다.
- 브라우저 검증은 HTTP/RawWS 계약 fixture 기반이다. 실제 BE 연출 WS 및 다중 계정 통합 검증은 명세·환경 수령 후 진행한다.

## BE 채팅 전달용

> 답변 주신 연출 WS 정책 확인했습니다. FE 모션·1대1 분기·결과 화면은 준비되어 있습니다. 합의한 방향대로 구현·검증을 진행해주시고, 완료되면 이벤트 명세·실제 JSON 예시·적용 커밋과 배포 환경을 공유 부탁드립니다. 받는 대로 FE를 서버 이벤트 기반으로 전환해 참가자·관전자·주변 20m 표시와 중복/시각 처리를 연결하겠습니다. 다리는 pendingForfeit 최초 확정 기준으로 진행하겠습니다.
