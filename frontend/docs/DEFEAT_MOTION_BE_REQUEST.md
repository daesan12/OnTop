# 기권·패배 서버 연출 FE 연동 및 공동 검수

작성일: 2026-10-27 · 반영한 dev: `c4010b8` · FE 브랜치: `feat/frontend-defeat-motion`

## 기존 문제와 해결 방향

기존 FE는 연속된 경기 상태를 비교해 기권·패배를 추정했습니다. 경기 비구독 주변 사용자는 경기 상태를 받지 못했고, 중간 상태가 누락되면 직전 잔여 인원·확정 시각을 정확히 알 수 없었습니다.

BE가 추가한 `WORLD_GAME_REACTION`을 기존 `/ws/tables` 수신 경로에 연결했습니다. 이제 경기 상태·기권 영수증·정산 결과만으로 모션을 만들지 않으며, 서버가 확정한 사건의 모션·시각으로만 재생합니다. 서버 명세는 [기권·패배 공개 연출](../../docs/world-game-reaction-api.md), 시각 계약은 [월드 시간 진단](../../docs/world-time-diagnostics-api.md)을 따릅니다.

## FE 완료 내용

- 서버의 `eventId`, 경기·테이블·채널·대상자, 게임 코드, 버전, 직전 잔여 인원, 모션·지속 시간·확정 시각을 검증합니다.
- 기권·패배 직전 2명이면 기존 판 엎기 2.8초, 나머지는 남녀 머리 감싸기 3.6초를 재생합니다. 다인전에서 2명만 남은 경우도 동일합니다. 다리 `pendingForfeit`도 서버가 보낸 최초 확정 사건을 사용합니다.
- 사건 ID와 `(채널, 경기, 대상자)`로 중복을 막습니다. 이동·퇴장·채널 변경·재접속으로 재생을 취소해도 같은 사건을 다시 시작하지 않습니다. 캐시는 크기와 보존 시간을 제한하며, 지속 시간이 지난 사건도 재생하지 않습니다.
- `CONNECTED.payload.time.serverNow`의 UTC와 단조 증가 시계를 사용합니다. 기기 시계가 바뀌어도 진행 중 모션을 되감지 않고, 늦게 도착한 사건은 남은 구간만 재생합니다. 맵의 한국 시간·낮밤 주기는 유지합니다. 이 초기 시각 보정이 네트워크 지연까지 없애거나 프레임 단위 동시 재생을 보장하지는 않습니다.
- 같은 채널의 확인된 테이블 매핑을 사용합니다. 경기 참가자는 거리와 관계없이, 나머지는 테이블 중심의 XZ 거리 **20m 이내(경계 포함)**에서 서버가 보낸 연출을 표시합니다. 20.01m와 다른 채널·불일치 맵·대상 미확인·다른 활동 중인 아바타는 제외합니다.
- 비구독 주변 사용자에게 `TABLE_WATCH`·`GAME_WATCH`나 새 소켓을 만들지 않습니다. 공개 월드에 좌석 정보가 없는 경우 기존 몸 자세 위에 상체 모션만 덧씌우고, 좌석·위치·승패·정산·상호작용 권한을 추정하거나 수정하지 않습니다.
- 기존 큰 3D 결과판 제거, 가장자리 결과 HUD·결과 상세·정산·다음 판·기존 카메라를 유지했습니다. 최신 dev의 수영·착석·닉네임 위치·이동·성능·충돌 맵 보정도 함께 유지했습니다.

수정 범위는 `frontend/`입니다. BE·DB·배포 설정은 변경하지 않았습니다. dev를 이 기능 브랜치에 반영했으며 dev로 머지하지 않았습니다.

## 검증

- 최신 dev 반영 후 단위 테스트 **66개 파일·658개 통과**.
- 앱·테스트 타입 검사, 이관 경계 검사, 프로덕션 빌드 통과. 기존 번들 크기 경고는 남아 있습니다.
- Edge 브라우저 **26개 시나리오 통과**: 서버 연출 15개와 기존 기능 회귀 11개. 서버 연출은 4종 게임, 남녀 리그, 다인전→2인, 관전자·비구독 주변 6m/20m/20.01m, 기기 시계 10분 오차, 사건/상태 도착 순서, 중복·이동·재접속·지난 사건을 검사했습니다. 회귀는 4종 게임 결과, 무효 결과·정산 복구, 팔각정 1280×720·1000×700 HUD 조작, 옷장 2개, 우클릭 따라가기와 감정표현 취소를 확인했습니다. 앱 예외·console error·Vite 오류 overlay는 없었습니다.
- 검증은 HTTP/RawWS 계약 fixture와 실제 배포 남녀 캐릭터 리그를 사용했습니다. 실제 개발 BE 배포·실제 계정 간 전달 검증과 구분합니다.
- 반영 전 dev에서 발견한 시설 맵 버전 불일치는 최신 `04f19c2`의 기존 FE 충돌 맵 보정으로 해소됐습니다. 해당 담당자의 설정을 유지했고 관련 기존 단위 검사도 통과했습니다.

## BE 담당자에게 부탁드리는 남은 내용

연출 이벤트 추가 구현을 다시 요청하는 단계는 아닙니다. 아래 배포 확인과 공동 검수가 남았습니다.

1. `WORLD_GAME_REACTION`과 `CONNECTED.payload.time.serverNow`가 개발 환경에 배포됐는지, 적용 커밋과 접속 환경을 공유해주세요. 저장소 명세의 “로컬 검증·미배포” 문구만으로 현재 배포 완료를 판단하지 않았습니다.
2. 참가자·공개 관전자·경기 비구독 주변 사용자 계정으로 같은 사건 ID·확정 시각을 받는지 공동 확인해주세요. 20m 경계 포함, 20.01m 제외, 다른 채널 제외도 확인 대상입니다.
3. 1대1 기권·일반 패배, 다인전 중도 기권·다인전→2인, 다리 `pendingForfeit` 최초 확정, 중복 알림·재접속·신규 관전 미재전송, 무승부·무효 경기 연출 제외를 함께 확인해주세요.
4. 실제 서버의 맵 버전과 FE 배포본을 일치시켜주세요. 이번 FE 기준은 기존 충돌 맵 `ae833248d2dd356c6603af72b2b865f9051a866e9cfa7d2b9c9abe890579944d`입니다. 전체 테이블 매핑·새 맵 활성화는 별도 담당 작업을 따릅니다.

## 채팅 전달용 요약

> 기존 FE는 경기 상태를 비교해 패배를 추정해 비구독 주변 사용자와 정확한 확정 시각을 맞추기 어려웠습니다. 추가해주신 WORLD_GAME_REACTION에 FE를 연결했고, 서버 확정 모션·시각 사용, 사건/경기·대상자 중복 방지, 참가자·관전자·주변 20m 표시와 이동·재접속 취소를 처리했습니다. 기존 결과 HUD·카메라와 최신 dev의 아바타·맵 개선은 유지했습니다.
>
> BE 추가 구현을 다시 요청하는 것은 아니며, 개발 환경 배포 여부·적용 커밋·검수 환경을 공유 부탁드립니다. 배포된 환경에서 참가자·관전자·비구독 주변 사용자로 20m 경계, 다인전→2인, 다리 최초 기권 확정, 중복·재접속 미재전송을 함께 확인하면 됩니다. FE/BE 배포 맵 버전도 동일하게 맞춰주세요.
