# 기권·패배 캐릭터 연출 · FE 구현 및 BE 요청

기준: 2026-10-26, dev `5732745`, 작업 브랜치 `feat/frontend-defeat-motion`. 최신 dev를 작업 기준에 반영했으며, 추가된 BE 테스트 변경과 이번 FE 변경은 겹치지 않았다. 사용자 확정: 시작 인원과 관계없이 **기권·패배가 확정되기 직전 남은 참가자가 2명이면 판 엎기**, 그 외에는 양손으로 머리를 감싸는 모션이다. 판·카드·주사위·말·점수·승패·정산은 바꾸지 않는다.

## FE 구현 범위

- 기존 남녀 캐릭터 리그와 IK를 사용한 3.6초 머리 감싸기: 양손 올리기 → 머리를 숙여 감싸기 → 손 내리고 원래 착석 자세로 복귀. 하체·착석 위치와 게임 오브젝트는 유지한다. 기존 2.8초 판 엎기 클립은 1대1 분기에서 재사용한다.
- 이미 검증되어 표시 스토어에 반영된 같은 경기의 연속 버전 `GAME_STATE` 변화를 관찰한다. ONE_CARD의 active, LIAR_BRIDGE의 forfeited/pendingForfeit, 종료 승자를 사용한다. 남은 인원은 말 개수가 아니며, 다리에서 말이 없어도 서버가 참가 자격을 유지하는 사용자는 포함한다.
- 다인전 기권 확정/기권 예정 전환과 종료 시 새 패배자만 재생한다. 앞서 기권한 사람, 승자, 무승부에는 일반 패배 연출을 추가하지 않는다. 기권 요청·확인창·승인 영수증만으로 재생하지 않는다.
- 같은 경기·사용자는 한 번만 재생한다. 초기 관전·재접속 시 이미 종료된 상태, 과거/동일 버전, 누락된 버전 사이의 전환은 재생하지 않는다. 관측하지 못한 중간 탈락이나 1대1 전환을 추정하지 않는다.
- 현재 참가자/공개 관전자 화면에서 해당 테이블에 실제 착석한 캐릭터만 표시한다. 이동·퇴장·채널 변경·연결 종료·새 경기·관전 종료 시 취소한다. 경기 중 본인 1인칭 모델 숨김과 기존 카메라는 유지하며, 종료 결과의 함께 보는 시점에서는 본인 모션이 보인다.
- 결과 화면은 테이블을 가리던 3D 결과판을 제거하고 화면 가장자리 HUD 및 기존 결과 상세 화면을 사용한다. 결과 버튼은 오른쪽 빠른 메뉴와 겹치지 않게 배치하고, 901~1200px 화면에서는 채팅창을 위한 폭도 확보한다. 결과 카메라·승패·정산 확인·다음 판 준비는 유지한다. 이 배치 수정에 추가 BE 작업은 필요하지 않다.
- 일반 감정표현 코드/버튼·쿨다운을 추가하거나 WORLD_EMOTE_SEND를 보내지 않는다. 기존 소켓·공개 경기 상태만 사용한다. 시각 표시 전용이며 새 BE DTO/엔드포인트를 임의로 만들지 않는다.

구현: `src/game/presentation/defeat.ts`, `src/world/gameReactions.ts`, `src/world/art/defeatMotion.ts`. 기존 `Avatars.tsx`와 `avatarMotion.ts`에는 표시 연출 연결만 추가한다. 새 GLB·형상·재질·텍스처·의존성은 없다. 매 프레임 React 상태를 갱신하지 않으며 기존 포즈 cadence와 리그/geometry 공유를 유지한다.

## BE에 전달할 요청

**이 문서는 협의 요청이며 새 운영 메시지/필드의 확정 명세가 아니다. BE 소스·DB·설정은 수정하지 않았다.**

1. 기권·패배 확정 직전의 **서버 기준 잔여 참가자 수**와 해당 연출 대상자를 일관되게 확인할 전달 경로를 합의해주세요. 3·4인 시작 후 2명만 남은 경우도 판 엎기이며, 동시에 여러 사람이 이탈하거나 클라이언트가 중간 상태를 놓친 경우에는 클라이언트가 수를 추정하지 않아야 합니다.
2. 현재는 해당 경기 참가자와 GAME_WATCH 공개 관전자만 연출을 볼 수 있습니다. **경기를 구독하지 않는 주변 공원 사용자**에게도 같은 연출이 필요하면, 서버가 확정한 사건을 공개 월드 표시로 전달해주세요. 기존 상태/이벤트를 재사용할지 서버 측에서 결정해주세요. 손패·비공개 눈·개인 정산/지갑 정보는 포함하지 않습니다.
3. 사건 구분·중복 방지에 필요한 식별 정보, 경기/채널·대상 사용자, 확정 시각 및 기권/패배 구분의 의미를 정해주세요. 종료는 기존 endedAt을 사용하지만 다인전 중도 기권은 현재 공개 상태에 확정 시각이 없어 각 화면의 수신 시각으로 시작합니다. 정확히 맞는 동시 재생에는 서버 시각/사건 정보가 필요합니다.
4. 다리 pendingForfeit를 연출 확정 시점으로 삼을지 확인해주세요. 현재 FE는 서버가 pendingForfeit=true로 입력 자격 상실을 확정한 첫 상태에서 한 번 재생하고, 이후 말 제거/forfeited 전환 때 반복하지 않습니다. 재접속·관전 진입 시 과거 사건을 다시 방송/재생하지 않는 정책도 함께 확인해주세요.

### 채팅 전달용 요약

> FE에서 머리 감싸기 모션과 기존 판 엎기의 조건 분기를 연결했습니다. 기권·패배 직전 잔여 참가자가 2명이면 판 엎기, 그 외에는 머리 감싸기입니다. 현재는 연속된 공개 경기 상태를 받은 참가자·관전자만 표시할 수 있습니다. 일반 주변 사용자까지 동일하게 보여주려면 서버 확정 대상자·직전 잔여 인원·사건 식별 정보·시각의 공개 전달 방식을 합의해주세요. 특히 다리 pendingForfeit의 최초 확정을 연출 시점으로 사용해도 되는지 확인 부탁드립니다. FE에서는 새 서버 메시지를 추정하거나 승패·정산을 변경하지 않았습니다.
