# 팔각정 숨은 의자 충돌 분석 및 FE/BE 인계

## 후속 반영 상태 (2026-10-29)

BE MR !192(`a6b06d6`)에서 채널별 의자 충돌 제어와 `WORLD_STATE.tables[].chairCount`가 머지됐다. FE도 새 공개 수를 실시간 모델에 연결했다. 상세 내용과 실제 서버 검증의 구분은 [PUBLIC_CHAIRS_FE_INTEGRATION.md](./PUBLIC_CHAIRS_FE_INTEGRATION.md)를 참고한다. 아래는 BE 구현 전 최초 인계 당시의 원인·요청 기록이다.

## 최초 인계 상태 (2026-10-28)

- 범위: FE 소스·테스트·문서만 변경. BE 소스, 충돌 맵 JSON, 맵 생성 스크립트는 수정하지 않았다.
- FE 보완 완료: 테이블에 앉거나 관전하지 않은 사용자도 **이미 수신한 공개 테이블 목록**의 승인 인원수를 의자 표시에 사용한다.
- 실제 보행 막힘: **미해결 — BE의 물리 충돌 변경이 필요하다.** 이번 FE 변경만으로 통과 가능해졌다고 판단하면 안 된다.
- 공개 목록은 채널 입장/테이블 조회 시 수신한다. 현재 계약에는 모든 산책자에게 설정 변경을 즉시 전달하는 의자 상태 스트림이 없다. 공개 목록이 갱신되기 전까지 주변 사용자에게 실시간 동기화됐다고 보장하지 않는다.

## 재현

1. 일반 태블릿 모드로 공원에 입장한다.
2. 중앙 팔각정의 게임이 선택되지 않은 테이블을 확인한다. 앞뒤 의자 두 개만 보인다.
3. 좌우의 비어 보이는 세 번째·네 번째 의자 위치로 걷는다.
4. 그 위치에 의자 모델은 없어도 서버 위치가 진행하지 않는다.
5. 3인 또는 4인 설정을 승인하면 그 위치에 의자가 나타난다.

## 정적 코드에서 확인한 원인

| 경로 | 동작 |
| --- | --- |
| `src/features/tableLobby/useTablePresentation.ts` | 승인 상태로 표시할 의자 수를 결정한다. 기본은 2개다. |
| `src/features/tables/TableShell.tsx` | 그 수를 실제 테이블·의자 모델에 전달한다. |
| `src/world/art/PavilionSeating.tsx` | 중앙 팔각정 의자 모델을 지정 수만큼만 렌더링한다. |
| `src/config/world.ts` | 팔각정마다 `tableSeats(t).map(...)`으로 네 의자 충돌 박스를 항상 만든다. |
| `../backend/src/main/resources/world/park.json` | 네 의자의 이동 충돌 박스를 정적 맵에 포함한다. 읽기만 했다. |
| `../backend/src/main/java/com/ssafy/ontop/world/movement/ParkScene.java` | 맵의 모든 박스를 상태 조건 없이 물리 shape으로 만든다. 읽기만 했다. |
| `../backend/src/main/java/com/ssafy/ontop/world/movement/WorldPhysics.java` | 모든 정적 shape을 채널 물리 공간에 등록한다. 읽기만 했다. |
| `src/park/runtime/SpringParkRuntime.ts`, `src/world/movementPresentation.ts` | FE는 이동 의도를 전송하고 승인된 서버 위치를 보간한다. FE가 독립적으로 캐릭터를 충돌 영역 밖으로 이동시키지 않는다. |

중앙 팔각정 P0의 시각 anchor는 `table-5`이며 바닥 높이는 2m, 중심 X/Z는 `(0, 6)`이다. 좌우 선택 의자의 시각 anchor는 `(-2.61, 6)`, `(2.61, 6)`이다. FE 박스 ID는 `table-5-chair-2`, `table-5-chair-3`이다. **박스 접미사는 0-based, 공개 좌석 번호는 1-based**다. 이 값은 현재 맵의 사례이며 wire tableId를 이 문자열로 추정하면 안 된다. 채널의 명시적 table/anchor binding을 사용해야 한다.

## 이번 FE 변경

1. `presentedChairCount`에 공개 `TableSummary` fallback을 추가했다.
2. 상세 `TABLE_STATE`/관전 상태가 있으면 그 승인 좌석 정보를 우선한다. 이미 승인된 상위 좌석의 사용자를 가리지 않는다.
3. 상세 상태가 없으면 기존 GET `/api/v1/tables?channelId=...` 응답의 `startMode`, `selectedPlayers`, `capacity`, `gameCode`, `occupiedSeats`로 표시 수를 결정한다.
4. 채널과 anchor binding이 맞는 테이블만 참조한다. 미승인 UI 선택이나 다른 채널 설정은 사용하지 않는다.
5. `TableShell.userData.chairCount`에서 현재 렌더링 수를 확인할 수 있다.

새 API나 임의의 WS 메시지를 추가하지 않았다. 정적 `WORLD_COLLIDERS`, `EXPECTED_MAP_VERSION`, FE/BE 맵 일치 검사도 변경하지 않았다. 서버가 여전히 네 의자를 막고 있는 동안 FE 길 안내만 그 위치를 통과하도록 바꾸면 실제로 막히는 경로를 안내하게 되므로 현재 정적 경로 판정은 유지한다.

## BE 요청 사항 — 구현은 BE 담당 범위

### 채널별 의자 충돌 활성화

- 기본 2인/게임 미선택: 좌석 1·2만 활성화하고 좌석 3·4의 충돌은 해제한다.
- 서버 승인 3인: 좌석 3만 추가 활성화한다.
- 서버 승인 4인: 좌석 3·4를 추가 활성화한다.
- 필요한 의자 수는 서버 승인 인원수와 점유된 가장 큰 좌석 번호 중 큰 값으로 하되 2~4 범위로 유지한다. 점유 중인 좌석의 충돌/표시를 임의로 제거하지 않는다.
- 설정 취소/초기화/마지막 퇴장 등으로 승인 상태가 바뀌면 같은 규칙으로 갱신한다. 참가자 수만 보고 이미 승인된 4인 설정을 2인으로 축소하면 안 된다.
- 팔각정 의자 박스를 무조건 정적 등록하는 경로를 분리하거나, 의자 ID를 보존한 채 채널별 물리 공간에서 활성/비활성을 관리한다. 숨은 의자를 정적 박스와 동적 박스로 중복 등록하지 않는다.
- 다른 채널/테이블의 설정에 영향을 주지 않아야 한다. 기본 의자·테이블·기둥·난간·바닥 충돌은 유지한다.
- 의자를 추가할 자리에 산책자가 이미 서 있을 때 관통/튕김/고립이 생기지 않도록 서버의 안전한 위치 해결 정책을 정하고 검증한다.

### 공개 표시 상태 전달

- 기존 공개 목록의 `startMode`/`selectedPlayers`/`capacity`를 참가자에게 승인한 상태와 일치시킨다.
- 채널 내 산책자와 늦게 입장한 사용자도 현재 의자 수를 알 수 있도록 공개 상태 갱신 방식을 합의한다. 기존 전체 좌석 비공개 정보를 무조건 방송하는 방식은 요구하지 않는다.
- 실시간 공개 갱신이 새 메시지/필드를 필요로 한다면 channelId, tableId, 승인 버전/순서, 선택 인원수, 초기화 규칙을 명시해 FE와 계약을 확정한다. 이번 FE 변경은 제안 단계의 wire 메시지를 추정해 파싱하지 않는다.
- 정적 맵 구조/지문 변경이 필요하면 FE 상수·검증 데이터·BE 메타데이터를 함께 갱신할 인계 자료를 제공한다. 현재 맵 버전 검사를 우회하지 않는다.

### 수용 조건

| 상태 | 보여야 하는 의자 | 통과 가능해야 하는 자리 |
| --- | --- | --- |
| 미설정 / 승인 2인 | 1·2 | 3·4 |
| 승인 3인 | 1·2·3 | 4 |
| 승인 4인 | 1·2·3·4 | 없음 — 표시된 의자는 계속 충돌 |

추가 검증: 2→3→4→2 전환, 게임 종료/설정 초기화/퇴장, 좌석 4 점유 상태, 두 채널 독립성, 중앙·일반 팔각정, 늦은 입장, 오래된 메시지, 의자 생성 자리에 서 있는 산책자, 맵 버전 일치, 기존 테이블/기둥 충돌 유지. 피크닉/야외 테이블에도 같은 모델 숨김 규칙이 적용되므로 후속 점검 대상이다.

## FE 검증 범위

단위 테스트는 공개 목록만 있는 산책자의 2/3/4인 표시, 상세 승인 우선, 4번 좌석 점유 보호를 검증한다. 브라우저 테스트는 실제 장면의 의자 개수 갱신과 기존 태블릿 동작을 확인한다. 모의 WS/HTTP를 사용하는 브라우저 테스트는 실제 BE 물리 통과를 검증하지 못한다. 물리 수용 조건은 BE 수정 후 실제 서버 환경에서 별도 검증해야 한다.

2026-10-28 검증 결과:

- `pnpm exec vitest run tests/unit/tabletLobby.test.ts tests/unit/worldMapParity.test.ts`: 9개 통과. 기존 정적 FE/BE 맵 일치도 유지.
- `pnpm typecheck:tests`, `pnpm build`: 통과.
- Playwright / Edge, `http://127.0.0.1:5278`, 1920×1080: 새 공개 의자 표시 테스트와 기존 ONE_CARD 3인 / LIAR_BRIDGE 4인 태블릿 테스트, 총 3개 통과.
- 장면 인스턴스 개수가 승인 수에 따라 3→4→2개 의자 분량으로 변함을 확인하고 캡처를 육안 점검. 새 테스트에서 테이블 참가/관전 요청이 발생하지 않음을 확인.
- 관련 브라우저 오류 및 Vite 오류 오버레이 없음. 기존 Three.js 경고는 유지됨.
- Browser 플러그인이 제공되지 않아 프로젝트의 Playwright 검증 경로 사용. 실제 BE 충돌 공간에서의 통과 검증은 수행하지 않음.
