# 공원 진입·붕어빵 종료 최적화 검토

2026-10-26. 브랜치 `fix/park-entry-performance`, 기준 `a1403c7`.

## 변경

- `/park` 인증 확인, OAuth callback, 온보딩 단계에서 공원 캐릭터·텍스처를 미리 요청한다. 정적 공원 모델의 무거운 모듈 초기화보다 앞서 다운로드를 시작한다. 일반 로그인 첫 화면에서 불필요하게 공원 전체를 생성하지 않는다.
- 공원 채널·배치·프로필 조회와 접속권 발급을 함께 시작한다. 소켓은 설정 검증이 끝난 후에만 열며 이전 연결 종료, 세대 취소, 접속권 유효기간 확인을 유지한다.
- 붕어빵에서 나가면 즉시 HUD·입력 소유권을 반환한다. 시점만 240ms 동안 복귀한다. 종료 후 다시 진입했을 때 이전 타이머가 새 방문을 닫지 않는다.
- 진행 중 판 포기 요청은 서버 응답을 기다리며, 실패 시 확인창과 재시도를 유지한다.

## 로컬 성능 확인

Windows / Edge headless / 1440×900 / 배포용 Vite 빌드 / 로컬 HTTP·RawWS fixture. 새 브라우저 컨텍스트에서 공원 화면이 나타난 후 로딩 표시가 사라질 때까지 측정했다. OAuth·실서비스 백엔드·실사용 네트워크는 포함하지 않는다.

| 항목 | 기준 버전 | 수정 버전 | 해석 |
|---|---:|---:|---|
| 첫 공원 준비 완료 | 5,118ms | 4,820ms | 단일 비교 약 6% 단축. 큰 폭의 개선으로 일반화할 수 없음 |
| 붕어빵 시작 화면에서 나가기 | 918ms | 49ms | 의도적으로 대기하던 800ms 입력 잠금 제거 |
| 캐릭터·텍스처 요청 시작 | 탐색 후 약 2,114ms | 약 190ms | 무거운 월드 모듈 초기화보다 먼저 요청 |

3D 정적 형상 생성과 GPU 첫 사용 비용이 남아 있어 공원 진입 지연이 완전히 해결됐다고 볼 수 없다. 기존 전체 셰이더 준비와 오류 진단을 유지한다.

## 검증

- 단위 테스트, 앱 및 테스트 TypeScript 검사, 프로덕션 빌드.
- 새 회귀 테스트: 인증 대기 중 리소스 요청, 설정 대기 중 접속권 발급 및 소켓 생성 지연, 반복 붕어빵 진입·즉시 종료·이동·동일 Canvas 유지.
- 기존 회귀 테스트: 실제 60초 붕어빵 조작·정산·포기 재시도, 공원 입장·채팅·이동·착석, 재접속 시 단일 소켓, 로그인.
- Browser 플러그인이 제공되지 않아 프로젝트의 Playwright/Edge로 검증한다. 스크린샷·측정 스크립트·실행 산출물은 저장소 밖에 둔다.

### 확정 결과

- 단위 테스트 **58개 파일 / 554개 통과**.
- 앱·테스트 TypeScript 검사, 규칙서 게시 스크립트, Vite 프로덕션 빌드 통과. 기존의 큰 JS 청크 경고는 남아 있다.
- 선택한 브라우저 회귀 **12개 시나리오 통과**. 첫 실행에서 9개 통과 후 검사 조건을 수정한 3개를 재실행해 통과했다. 콘솔 검증을 추가한 반복 종료 시나리오도 다시 통과했다.
- 실행 환경: `http://127.0.0.1:52983`, Edge headless, 데스크톱 1440×900 / 좁은 화면 740×900. Browser 플러그인 미제공으로 Playwright 사용.

| 화면 검사 | 결과 |
|---|---|
| 페이지 식별 | `/park`, 제목 `OnTop` 확인 |
| 빈 화면 | 공원 기본 화면·Canvas·HUD 표시 |
| 프레임워크 오류 | Vite 오류 오버레이 없음 |
| 콘솔 | 반복 종료에서 console error·pageerror 없음. 기존 THREE.Clock 폐기 예정 경고와 GPU 정밀도 경고 확인 |
| 화면 증거 | 종료 후 캐릭터·카트·HUD 복귀 확인 |
| 상호작용 | E 진입 → 나가기 3회 → 즉시 입력 잠금 해제 → S 이동 메시지 전송, 동일 Canvas·단일 채널 입장 유지 |

화면 증거는 저장소 밖 QA 폴더의 `park-return-desktop.png`, `park-return-narrow.png`에 저장했다. 740px 화면에서는 기존 하단 조작 안내 일부가 채팅 영역에 가려지는 레이아웃도 확인했으며 성능 수정 범위에 포함하지 않았다.

검증 명령은 설치된 프로젝트 바이너리로 `vitest run`, `tsc --noEmit`, `tsc --project tsconfig.tests.json --noEmit`, `publish-rulebooks.mjs`, `vite build`, `playwright test`를 실행했다. 격리 폴더에서는 pnpm의 의존성 재설치 동작을 피하기 위해 Node로 설치된 CLI를 직접 호출했다.
