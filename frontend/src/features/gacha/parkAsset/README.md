## 로컬 섞기·단일 배출 연출 — 2026-11-08

### 앞 레버 아래로 당기기 추가

사용자 확인에 따라 정면 금색 손잡이를 움직인다. `gachaLever.ts`가 0~330ms에 약 105도 아래로 당기고, 600ms까지 유지한 뒤 1000ms에 원위치로 돌린다. 기존 혼합 시작 450ms와 총 3650ms 시간표는 유지한다. 공원 기계와 로컬 패널이 같은 연출 시각/각도 함수를 사용하며 패널의 기존 연속 회전은 제거했다.

`gachaMachineGeometry.ts`는 레버 모양/색/위치를 유지하면서 기존 금장 배치 끝에 레버 정점 범위를 둔다. `createLeverDriver`는 해당 범위의 위치·법선만 원본에서 회전해 부분 버퍼를 갱신한다. 별도 메시/재질/셰이더/드로콜 없이 동작하고 같은 각도/대기/복귀 완료 시 갱신을 생략한다. 건너뛰기·닫기·모션 감소의 최종 시각은 자동으로 원위치 각도 0을 사용한다. CPU 레버 원본 배열을 소량 보관하며 기존 캡슐 인스턴싱과 클립은 유지한다.

동일 조건의 대기 이미지가 이전 이미지와 모든 픽셀에서 일치했다. 레버가 내려간 상태까지 기계 8 calls/99,436 triangles/기하 버퍼 2,962,468 bytes로 같았다. 저장소 밖 `gacha-lever-animation.gif`/`gacha-lever-pulled.png`/`gacha-lever-metrics.json`에 연출과 수치를 보관한다. 대기 동일 이미지는 현 카메라·조명에서의 검증이며 전체 기기 FPS 측정은 아니다.

- 현재 로컬 화면은 기존 `Machine3D` 대신 `preview/LocalMachineScene.tsx`를 사용한다. 공원 기계와 화면이 동일한 18개 인스턴스/클립/단조 시간 시계를 공유하며, 화면 아트의 유리통·배출구에 맞추는 좌표 투영만 다르다. 실제 서비스의 `CapsuleScene`/`GachaPanel`/서버 계약은 변경하지 않았다.
- `gachaMixCue.ts`: 유효한 로컬 영수증을 먼저 확정한 후 연출을 시작한다. 연출에서 보상을 다시 추첨하지 않는다. 0~450ms 손잡이 준비 → 450~2100ms 섞기 → 2100~2300ms 캡슐 흡입 → 2300~2500ms 가려진 내부 통로 → 2500~2950ms 열린 아치에서 배출 → 3650ms까지 안착/공개. 엽전 보상은 같은 캡슐을 금색으로 표시하고 기존 결과 화면이 엽전을 공개한다.
- 배출할 캡슐도 기존 18개 중 하나를 사용한다. 별도 배출 메시/물리 엔진을 추가하지 않는다. 완료 시 17개는 바닥 또는 아래 캡슐에 지지되고 1개는 붉은 받침에 남는다. 내부 장식은 매 뽑기마다 18개 템플릿으로 시작하며 실제 보상 재고 수량과 같은 개수를 표현하는 것은 아니다.
- `tools/bakeCapsuleMix.mjs`는 개발 시에만 접촉 계산을 수행한다. `capsuleMixClip.json`의 혼합 64프레임과 배출 대상별 정착 48프레임을 미리 생성한다. 재생 중에는 재사용하는 배열/행렬로 18개 포즈를 보간하고 두 InstancedMesh의 행렬을 갱신한다. 완료 후 갱신을 중지한다. 클립 원문 110,047 bytes, gzip 39,161 bytes이며 기하 버퍼와 별도인 추가 동작 데이터다. 재생성: frontend에서 `node src/features/gacha/parkAsset/tools/bakeCapsuleMix.mjs`.
- 모션 감소 설정은 즉시 최종 상태/결과로 전환하며 재생 중 설정 변경도 처리한다. 건너뛰기·도중 닫기·중복 입력·오래된 완료 콜백을 방어한다. 뽑기권은 영수증 확정 시 한 번만 사용한다. 외관 확인 전용 `섞기·배출 연출 보기`는 지갑을 변경하지 않는다.
- 720×810/DPR1/고정 카메라/동일 재질·조명/그림자 끔의 실제 Three.js 카운터는 대기·혼합·배출·완료 모두 **8 draw calls / 99,436 triangles / 기하 버퍼 2,962,468 bytes**로 동일하다. 화면 내부 캡슐/손잡이는 별도 캔버스의 5 calls다. 이는 기계 단독 기하·렌더 비용이며 실제 게임 전체 FPS/CPU·GPU 프레임 시간 측정은 아니다.
- 외관 원본 `gachaRoof`/`gachaGlass`/`gachaMachineGeometry`/`gachaMaterials`/`capsuleBatchGeometry` 및 다른 확정 에셋의 SHA-256을 유지했다. 처음의 정적 배치와 180×180 맵/충돌은 동일하다.
- 실행: `http://127.0.0.1:5233/layout-preview.html` → 의상 뽑기 기계 → 의상 뽑기 체험 → 캡슐 뽑기. 외관만 볼 때 시설 패널의 섞기·배출 연출 보기를 사용한다. Browser plugin not available: 설치된 Edge/Playwright를 사용했다. 실서버 지갑·다른 이용자에게 전파·헤드셋·모바일 실기기 FPS는 이번 로컬 연출 범위 밖이다.

## 유리통·처마 보완 — 2026-11-08

유리통은 gachaGlass.ts의 매끄러운 회전 곡면과 가장자리 반사/Fresnel·하늘 반사·곡면 하이라이트로 표현한다. 금장 고리와 닿는 끝 위치는 유지하고 가운데 윤곽을 조금 부풀렸다. 굴절용 추가 렌더 패스/환경 이미지 다운로드 없이 한 번의 투명 렌더로 캡슐을 읽을 수 있게 한다. 지붕은 기와 끝을 둥글게 닫고, 목재 아랫면과 닫힌 곡선의 처마 띠를 추가해 모서리/끝단 틈을 보완했다. 캡슐 10개, 몸체/손잡이/등롱, 좌표/충돌/상호작용/뽑기 화면과 로컬 테스트 보상은 유지했다.


## 확대·겹침 정리·기와 재구성 — 2026-11-08

## 새 중앙 기계 레퍼런스 반영 — 2026-11-08

새 레퍼런스의 중앙 기계를 기준으로 형태/재질을 재구성했다. gachaRoof.ts는 넓고 오목한 암키와, 작은 볼록 덮개 기와, 겹이음과 물결 처마를 만든다. 원형 막새가 타일 입술과 교차하지 않도록 짧은 연결부 뒤에 배치한다. 전면 지지대를 없애고 뒤쪽 2개만 유지했다. ParkCapsules.tsx의 장식 캡슐은 단순한 둥근 몸체/금색 띠/작은 꼭지 18개를 겹치지 않게 모았다. 별도 뽑기 화면의 캡슐/보상 상태는 그대로다.

사각 종이 등롱에는 목재 프레임·금장 테두리·꽃 문양·연결 고리·녹색 술을 추가했다. 꽃 메달은 녹색 대신 금색 계열로 바꾸고 몸통에 구름 장식/손잡이 리벳을 넣었다. 배출구에는 금장 곡면 레일과 붉은 둥근 받침을 넣어 하단 금장 띠 위에서 충분히 보이게 했다.

gachaMaterials.ts는 이 에셋 전용 PBR 목재·도자기·금속·종이 발광을 제공한다. 목재 결은 셰이더, 반사용 환경은 메모리에서 만드는 128×64 텍스처이며 외부 요청/공통 장면 환경 변경은 없다. 공유 PropModel/다른 확정 에셋을 변경하지 않는다. 몸체 크기·공원 배치/충돌·기존 상호작용과 테스트 지갑은 유지한다. 아직 사용자 검토안이며 승인 카탈로그에는 미등록이다.


## 캡슐 바닥 적층 — 2026-11-08

PARK_CAPSULES의 장식 18개만 바닥에서부터 정착한 정적 배열로 재배치했다. 금장 바닥 상단 Y2.12/구체 반경 .315를 기준으로 아래 캡슐은 바닥에 놓이고 위 캡슐은 하부 캡슐에 기대도록 했다. 중심 높이는 2.43493~2.98592이며 규칙적인 공중 3단 행을 없앴다. 방향은 작은 기울기만 허용해 꼭지가 바닥을 뚫지 않게 했다. 크기·색·개수·기계·재질·UI·맵/충돌은 유지하며 런타임 물리나 새로운 애니메이션은 추가하지 않았다. 단위 검사로 바닥 또는 지지 캡슐로 이어지는 경로 및 구체 겹침 없음을 확인한다.

지붕 폭/깊이·최대 높이·전체 구성은 유지하고 gachaRoof.ts만 다듬었다. 암키와와 볼록한 덮개 기와를 각각 네 마디로 나누어 실제로 겹치게 만들고 작은 두께/색 차이를 줬다. 앞쪽 U자 단면 깊이는 절반으로 줄였으며 굵은 줄처럼 보이던 곡면 관을 얇고 닫힌 타일 입술로 교체했다. 원형 막새는 짧은 연결부와 둥글게 모따기한 회전 곡면으로 이어 붙였다. 처마 모서리는 끝에서 기울기가 튀지 않는 부드러운 보간으로 바꿨다. 바닥에 쌓인 캡슐 18개, 몸통·유리·등롱·재질·클릭 UI는 그대로다.

## 외관 보존 경량화 — 2026-11-08

- ParkCapsules.tsx는 18개 × 3개 메시 대신 구체/금장 두 InstancedMesh를 사용한다. capsuleBatchGeometry.ts가 이전과 동일한 위치·회전·.315 크기 행렬을 만들고, 구체 색상은 기존 네 색을 instanceColor로 전달한다. 금장 띠와 꼭지는 한 형상으로 합쳤다. 인스턴스 경계 구를 갱신하고 해제 시 인스턴스 버퍼를 정리한다.
- 기와 네 마디/끝마감/처마 형상·목재/금장 장식·원형 유리·붉은 받침을 유지하고 분할 수만 줄였다. 직선 목재 이음선은 길이 방향 한 구간으로 만들고, 꽃/리벳/기와/유리/캡슐의 곡면을 현재 시점에서 식별이 어려운 수준으로 낮췄다. 위치/배치/외형 크기/재질 값과 게임·지갑·뽑기 UI 계약은 유지한다.
